# Twitter AI Agent - 2026-07-10

## 1. 人们在讨论什么

### 1.1 Codex 发布后的余波，让模型选择变成了路由与 UX 问题 🡕

7 月 10 日声量最大的一组讨论，来自 OpenAI 将 Codex 并入 ChatGPT 后的次日反馈。讨论的焦点不只是 GPT-5.6 Sol 好不好，而是默认设置、滑块、用量配额，以及用户是否应该自己知道何时该把任务路由到 Sol、Terra、Luna 或其他厂商。以下 4 条内容从不同角度提供了证据。

[@danshipper](https://x.com/danshipper) [认为](https://x.com/danshipper/status/2075263920613277809)（737 个赞、46 条回复、121,730 次浏览、464 次收藏）表示，GPT-5.6 Sol 速度快、成本低，能力也足以跑完整个知识工作闭环，但在他的 Senior Engineer 基准测试中只拿到 56/100，而 Claude Fable 5 为 91/100。其独特之处不在意识形态，而在操作层面：他建议把 Sol 作为 Fable 的子代理，把合并后的 ChatGPT Codex 应用视为一个工作流界面，并将真正的选择表述为：哪些任务交给 Sol，哪些任务留给更强但也更挑剔的模型。

[@thsottiaux](https://x.com/thsottiaux) [表示](https://x.com/thsottiaux/status/2075641131002700120)（1,672 个赞、356 条回复、32,372 次浏览、112 次收藏）表示，OpenAI 让用户太容易触发最高算力设置，在桌面布局里把熟悉的聊天和项目藏得太深，还让一些多代理工作流出现了回归问题。他承诺会在当天重置用量，给模型选择器加入更便宜的默认项，修复插件问题，并在下一周带来更熟悉的侧边栏和更清晰的用量可见性。

[@btibor91](https://x.com/btibor91) [总结](https://x.com/btibor91/status/2075670159264461255)（153 个赞、12 条回复、12,881 次浏览、89 次收藏）总结了公开的 Codex AMA：大多数工作用 Sol Medium，快速的非编码任务用 Terra，子代理用 Luna，目前还没有真正的 “Auto” 模型。他的帖子还记录了团队对困难任务的建议：面对模糊 bug 和迁移任务时提高推理强度；对于高度依赖 MCP 的工作流，降低推理强度或使用 CLI 封装；同时把目标设定得更有边界，避免 Codex 过早放弃。

[@nikesharora](https://x.com/nikesharora) [认为](https://x.com/nikesharora/status/2075631728027484462)（132 个赞、29 条回复、11,058 次浏览、164 次收藏）认为，企业最终仍会被卡在单一模型栈上，因为 harness 调优、评测、程序性记忆以及缓存定价都无法在不同提供方之间平滑迁移。他的独特观点是，真正的切换成本不是数据迁移，而是重新验证；这让浅层路由层适合简单任务，却很难支撑长链路代理。

**讨论洞察：** 回复基本都很务实：重置时间、Windows 资源占用、命名混乱，以及路由是否应该自动学会，而不是推给操作员自己处理。

**与前一天的对比：** 7 月 9 日讨论的是 harness 经济学。到 7 月 10 日，同一场争论已经变成了围绕默认设置、模型选择器，以及产品究竟该替用户吸收多少路由工作量的拉锯。

发帖者不再把 harness 工程当作圈内黑话，而是把它变成图示、循环分类、公开课程和具体的仓库模式。共同做法是，把可持续的知识从一次性提示词里拿出来，沉淀进文件、停止条件和可复用脚手架中。

### 1.4 可审计、面向领域的评测离生产更近了一步 🡕

关于验证的讨论，已经从泛泛的“用评测”建议，转向了具体领域和契约层。基准测试越来越像生产验收测试：有领域任务、明确的答案契约，以及公开的通过/失败分布。

[@kenbwork](https://x.com/kenbwork) [介绍了](https://x.com/kenbwork/status/2075263946106540197)（28 个赞、3 条回复、3,736 次浏览、16 次收藏）介绍了 BioSecBench-Surveillance：一个覆盖 7 类任务、6 种样本类型，并同时包含短读长与长读长测序的基准，共 100 个评估。配图之所以重要，是因为它把能力上限直接摆了出来：最佳 endpoint 通过率约 50%，大多数前沿配置都低于这一水平，异常检测只有 20% 左右，长读长数据集也比短读长更难。

![BioSecBench-Surveillance 图表，展示了按模型-harness 配对划分的运行结果分解和端点通过率，最佳结果接近 50%](https://pbs.twimg.com/media/HMzQefpbEAAkk_V.jpg)

[@SciFi](https://x.com/SciFi) [分享了](https://x.com/SciFi/status/2075616554553577708)（1 个赞、110 次浏览、3 次收藏）介绍了论文 [From Prompts to Contracts](https://arxiv.org/abs/2607.08028) 及其 [配套仓库](https://github.com/hammerbaki/enterprise-llm-agent-harness)。摘要异常具体：主张源边界、实体路由、答案契约和可复现轨迹，并报告了 3 个托管模型上的 270 次组合边界运行；消融实验还显示，由代码内建的约束机制保住了 120/120 的效用，而外部 guardrail 则把效用降到了 88/120。

**与前一天的对比：** 7 月 9 日聚焦外部验证器和重写循环。到 7 月 10 日，这些想法已经被推进到基因组监测、企业答案契约和本地 MCP 工具调用实验中。

## 2. 人们因为什么而感到挫败

### 用户仍然得自己充当模型与推理路由器

高严重度。[@thsottiaux](https://x.com/thsottiaux) [承认](https://x.com/thsottiaux/status/2075641131002700120)（1,672 个赞、356 条回复、32,372 次浏览、112 次收藏）表示，OpenAI 让最高算力设置过于容易被触发，却又弱化了其对用量限制的影响；与此同时，[@btibor91](https://x.com/btibor91) [记录了](https://x.com/btibor91/status/2075670159264461255)（153 个赞、12 条回复、12,881 次浏览、89 次收藏）提到的一场 AMA 中，仍然没有真正的 Auto 模型，用户必须根据任务在 Sol、Terra、Luna 和不同推理等级之间自行选择。[@danshipper](https://x.com/danshipper) [展示了](https://x.com/danshipper/status/2075263920613277809)（737 个赞、46 条回复、121,730 次浏览、464 次收藏）说明了这为什么重要：Sol 足以胜任很多循环，但在他的基准测试里，Fable 在最难的编码工作上仍然明显领先。人们目前的应对方式，是用子代理模式、面向 MCP 密集型流程的低推理封装，以及大量手动试验。之所以值得围绕这一点构建产品，是因为同样的路由痛点，同时出现在厂商道歉、公开 AMA 和独立实践者测试里。

### Harness 可移植性与切换成本依旧脆弱

高严重度。[@nikesharora](https://x.com/nikesharora) [认为](https://x.com/nikesharora/status/2075631728027484462)（132 个赞、29 条回复、11,058 次浏览、164 次收藏）认为，真正形成锁定的不是模型权重，而是 harness、评测、程序性记忆，以及不同提供方各自的缓存定价。[@dr_cintas](https://x.com/dr_cintas) [展示了](https://x.com/dr_cintas/status/2075630574069592251)（337 个赞、30 条回复、30,943 次浏览、495 次收藏）提供了一个折中办法：把规划和审查放在 Claude Fable 5 上，把实现量压给 Grok 4.5。[@KBlueleaf](https://x.com/KBlueleaf) [声称](https://x.com/KBlueleaf/status/2075560167438188582)（8 个赞、1 条回复、531 次浏览）则表示，在相近 token 总量下，他自己的框架只消耗了 Codex 周额度的大约二分之一到三分之一，这再次说明底层基座开销很重要。团队现在的应对方式包括自定义路由、按模型定制技能，以及手动重新验证。之所以值得围绕这一点构建产品，是因为切换成本在表现为模型质量问题之前，首先已经表现为 harness 问题。

### 高判断负载的领域工作仍会让代理失灵

高严重度。[@kenbwork](https://x.com/kenbwork) [报道](https://x.com/kenbwork/status/2075263946106540197)（28 个赞、3 条回复、3,736 次浏览、16 次收藏）指出，在不同模型—harness 组合中，BioSecBench-Surveillance 的通过率大约在 14% 到 50% 之间；异常检测约为 20%，长读长数据集为 26%，而短读长为 41%。失败模式不只是找不到工具，而是卡在对阈值、参考、归一化和结果解释的科学判断上。[@goose_oss](https://x.com/goose_oss) [转发了](https://x.com/goose_oss/status/2075616723202343276)（5 个赞、1 条回复、504 次浏览）还提到一项本地测试：一个 7B 函数调用模型没能执行一个 MCP 工作流，而 4B 模型却完成了。人们目前的应对方式，是缩小范围、加强验证器，以及采用工具优先架构。之所以值得围绕这一点构建产品，是因为“能调用工具”和“能做出正确判断”之间，依然有很大鸿沟。

### 仓库原生结构仍主要靠手工搭建

中等严重度，且在上升。[@mattpocockuk](https://x.com/mattpocockuk) [分享了](https://x.com/mattpocockuk/status/2075505624096350655)（83 个赞、11 条回复、8,306 次浏览、64 次收藏）介绍了一项深层模块技能，专门用于在 TypeScript 仓库中强制维持清晰边界；[@Divyyanshishrma](https://x.com/Divyyanshishrma) [指出](https://x.com/Divyyanshishrma/status/2075541537266769962)（72 个赞、6 条回复、1,549 次浏览）则指向一整套公开的 harness 工程课程；[@LearnWithBrij](https://x.com/LearnWithBrij) [认为](https://x.com/LearnWithBrij/status/2075633837292552289)（6 个赞、101 次浏览）说明，编码代理仓库需要在高风险模块附近配好 CLAUDE.md、技能、钩子、文档和本地规则。今天的应对策略，仍是手工围绕模型搭项目记忆和护栏。之所以值得围绕这一点构建产品，是因为需求是真实的，但现在的搭建方式依然像定制化的仓库木工活。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |

总体来看，满意度跨度最大的，不是单个工具，而是模型与 harness 的组合。GPT-5.6 Sol 因速度和价格收获好评，但 Fable 依旧占据最难编码工作的“声望位”，这也是为什么混合式规划者—执行者配置不断出现。同样的模式也出现在本地栈讨论中：当工具调用更匹配时，较小的本地模型也能胜过较大的模型。

最常见的变通办法，是把逻辑从提示词挪进结构。技能、钩子、本地规则、Decision Trace、API 或 MCP 部署，以及分阶段发布控制，本质上都在做同一件事：降低系统对某一次完美补全的依赖。因此，迁移压力流动的方向，也不再主要是从一个模型厂商切到另一个厂商，而是从临时拼凑的聊天式工作流，转向把路由、验证、治理和可复用上下文做成一等能力的产品。

## 6. 新内容与值得关注的事项

### BioSecBench-Surveillance 让科学代理的能力上限变得可见

它之所以值得关注，不只是因为又多了一个基准，而是因为它揭示了失败的形状。[@kenbwork](https://x.com/kenbwork) [发布了](https://x.com/kenbwork/status/2075263946106540197)（28 个赞、3 条回复、3,736 次浏览、16 次收藏）介绍了一个监测基准：当前模型—harness 组合的 endpoint 通过率上限约为 50%，尤其在异常检测和长读长数据上吃力。这为代理讨论提供了一项特定领域的压力测试，而不是又一个通用编码分数。

### “从提示词到契约”的论文把可审计性落成了具体架构

[@SciFi](https://x.com/SciFi) [提到](https://x.com/SciFi/status/2075616554553577708)（1 个赞、110 次浏览、3 次收藏）介绍了 [From Prompts to Contracts](https://arxiv.org/abs/2607.08028)。它之所以重要，在于它把 harness 这套主张变成了可测量的内容：源边界、实体路由、答案契约、可复现轨迹、270 次组合边界运行，以及 harness 与外部 guardrail 之间明确的效用对比。这是本数据集中最清晰的公开尝试之一：把可审计性从愿景，落到有名字的产物和验收测试上。

### 本地优先研究与 MCP 工作台拿出了具体的公开证据

本地优先这条支线的生态，比平时更强。[Open Science Desktop](https://github.com/ai4s-research/open-science) 的 README 表示，它在 ResearchClawBench 上排名第 1，同时把探索、实验、来源和写作打包进一个桌面闭环；[@goose_oss](https://x.com/goose_oss) [转发了](https://x.com/goose_oss/status/2075616723202343276)（5 个赞、1 条回复、504 次浏览）则提到一项测试：较小的本地模型在一个真实 MCP 任务上胜过了更大的模型。这里值得注意的信号是，本地优先构建者现在拿出来的是基准排名和具体工具调用结果，而不只是隐私口号。

## 7. 机会在哪里

**[+++］ 自动路由与使用治理层** — ［@thsottiaux](https://x.com/thsottiaux/status/2075641131002700120)、[@btibor91](https://x.com/btibor91/status/2075670159264461255)、[@danshipper](https://x.com/danshipper/status/2075263920613277809) 和 [@nikesharora](https://x.com/nikesharora/status/2075631728027484462) 都指向同一个缺失层：自动决定模型档位、推理深度和停止条件，同时把支出展示得足够清楚，让用户愿意信任默认设置。这是一个强机会，因为同一天里，厂商沟通、实践者基准和用户回复都出现了同样的痛点。

## 8. 要点

1. **发布日的 UX 问题，如今是路由问题，而不是原始智能问题。** OpenAI 自己的后续说明也承认，默认设置和用量可见性把用户推向了昂贵选项，而公开 AMA 仍要求用户按任务自己选择模型档位和推理等级。（[来源](https://x.com/thsottiaux/status/2075641131002700120)）
2. **Harness 工程正借助图示、循环设计和课程，变成一门正式学科。** 当天最有力的教育材料，不是泛泛的提示词技巧，而是明确的“收集—执行—验证—重试”图、循环分类和公开 harness 课程。（[来源](https://x.com/David_TornAI/status/2075265726080774424)）
3. **真正吸引注意力的产品，是围绕代理构建的控制界面，而不只是代理本身。** Langflow、Hands、Mission Control、Zero 和 CoinMarketCap Agent Hub 所卖的，更多是受治理的执行、部署或数据接入，而不是抽象的自主性。（[来源](https://x.com/CoinMarketCap/status/2075564007402991872)）
4. **面向具体领域的评测，仍在暴露巨大的判断鸿沟。** 在 BioSecBench-Surveillance 中，前沿代理栈的 endpoint 通过率往往低于 50%，在开放式科学判断上尤其吃力。（[来源](https://x.com/kenbwork/status/2075263946106540197)）
5. **可审计契约与本地优先栈，是目前建立信任最清晰的两种回答。** 一条讨论把答案契约、轨迹和模型替换验证推进为代码持有的产物，另一条则显示：因为工具调用更匹配，一个较小模型也能成功跑通完整的本地 MCP 闭环。（[来源](https://x.com/SciFi/status/2075616554553577708)）
