### 1.2 Anthropic 的智能体对智能体商业实验持续受到审视 🡒

Anthropic 的 Project Deal 实验进入第二天，继续引发讨论。[@Pirat_Nation](https://x.com/Pirat_Nation) [总结了](https://x.com/Pirat_Nation/status/2048416817983733935)（373 个赞、29,920 次浏览）：“Anthropic 测试了一个用于智能体对智能体商业交易的市场，给 69 名员工每人 100 美元，让 AI 智能体完成所有买卖。这些智能体达成了 186 笔真实交易，总额超过 4,000 美元。能力更强的 AI 模型拿到了更好的价格，也促成了更多交易。甚至有一个智能体给它的主人买了 19 个乒乓球，算是送给主人的一份自作主张的礼物。” [@TechCrunch](https://x.com/TechCrunch) [报道了](https://x.com/TechCrunch/status/2048156238614274272)（28 个赞、11,275 次浏览）分析了该实验，并指出 Anthropic 运行了四个采用不同模型的独立市场，发现“当用户由更先进的模型代表时，他们会获得客观上更好的结果”——但用户并没有察觉这种差异。

回复开始转向更实际的担忧。[@PointWake25](https://x.com/PointWake25) 指出：“服务型业务版本规模更小，也会更早到来。一个智能体负责预约暖通空调技师，另一个确认可用性和报价。信任应建立在受限交易逐步扩展的基础上，而不是从开放市场开始。” [@micahrmiller13](https://x.com/micahrmiller13) 提醒道：“涉及资金的部分很吓人，因为权限边界并不清晰。智能体应从受限预算和枯燥、可重复的决策开始，而不是开放式购物。”

**讨论洞察：** 讨论已从 4 月 25 日对不平等的关注，转向实际部署约束：预算上限、受限的交易类型，以及先从服务型业务场景切入，而非直接进入开放市场。

**与前一天的对比：** 4 月 25 日浮现的是模型层级不平等的角度（“如果你的房东运行 gpt7，而你运行 budget-mini”）。4 月 26 日则补充了实际部署路径：先做受限的服务交易，再走向开放商业。

### 1.7 上下文工程与 Token 优化开始受到关注 🡕

上下文管理开始成为一个独立议题。[@mksglu](https://x.com/mksglu) [宣布](https://x.com/mksglu/status/2048295938096082978)（14 个赞）context-mode v1.0.90 已获 10K+ GitHub stars 和 82K npm 下载量：“你的 AI 编程智能体会把已经处理过的工具输出反复塞回上下文窗口，占据其中大部分空间。context-mode 会拦截这些输出，将其索引到本地 FTS5 数据库中，然后只给智能体提供一份 1KB 摘要。”真实会话结果：token 减少 86.5%（从 29.6 MB 降至 4.0 MB），节省 6.7M token。该工具现已支持 14 个平台，其中包括 Qwen Code 和 JetBrains Copilot。

[@PawelHuryn](https://x.com/PawelHuryn) [引用了](https://x.com/PawelHuryn/status/2048425890208465389)（10 个赞，12 次收藏）Anthropic 工程博客：“使用 LLM 正逐渐不再是寻找正确的词句，而更多取决于你给模型配备了怎样的上下文、记忆和工具。”[@HanchungLee](https://x.com/HanchungLee) [分享了](https://x.com/HanchungLee/status/2048477527275143513) 关于“面向年轻一代的上下文工程与智能体记忆”的幻灯片。

**讨论洞察：** 从“提示词工程”到“上下文工程”的重新定义正在加速。context-mode 的 82K 下载量和 86.5% token 降幅表明，在工具层面，上下文管理已经基本被解决——真正的缺口在于，智能体框架还没有原生集成这些优化。

**与前一天的对比：** 4 月 25 日讨论的是持久化智能体记忆这一未被满足的需求（Obsidian 第二大脑、Markdown 提炼）。而 4 月 26 日，context-mode 展示了可规模化、可量化的 token 节省，话题重心也从记忆持久化转向上下文效率。

## 2. 什么让人们感到挫败

### 智能体定制成了拖延行为 —— 严重程度：高

[@thdxr](https://x.com/thdxr) [记录了](https://x.com/thdxr/status/2048388289112006988)（735 个赞）指出了当天最突出的挫败感：开发者花上数周构建“高度定制、但肯定还不如默认版的编程智能体工作流”。这条帖子之所以引发共鸣，是因为它点破了人人都熟悉的一种行为。64 条回复和 9 条引用表明，这不是理论上的担忧，而是切身存在的现实。背后的核心张力在于：skills 和 harness 生态鼓励定制，但没有办法衡量一套定制配置是否真的优于默认设置。

普遍程度：广泛存在 —— 这是当天互动量最高的帖子，也是一个文化拐点。

### 代码解释器依然不好用，而本地智能体正在崛起 —— 严重程度：中

[@willdepue](https://x.com/willdepue) [报道了](https://x.com/willdepue/status/2048192238870839346)（50 个赞）：“今天试了下：不能下载包，会挂掉并把自己清空，全是报错。”[@jercarin](https://x.com/jercarin) 对比称：“Anthropic 在这方面明显做得更好。Claude web 通过代理拥有完整网络访问能力，而 GPT 只能访问获批准的包管理器。”这种挫败感是结构性的：OpenAI 的沙箱代码解释器落后于本地智能体，也落后于 Anthropic 的方案。

普遍程度：反复出现 —— 围绕代码解释器的抱怨已经持续多天。

### 没有个人智能体能满足所有要求 —— 严重程度：中

[@petergyang](https://x.com/petergyang) [列出了](https://x.com/petergyang/status/2048433179338633627)（109 个赞，113 次收藏）列出了个人智能体的七项要求（跨应用、主动运行、记忆、多模态、多平台、消息能力、个性），并得出结论：“没有一个能同时满足这些条件。”具体缺口包括：Claude Code 在移动端每次都需要 `/remote-control`，而且例行任务失败时不会通知；Codex 完全没有移动端；OpenClaw 不够稳定，“重度用户不得不定期让 Codex/Claude Code 来帮它修修补补”。

普遍程度：活跃 —— 单项能力在提升，但整合仍然碎片化，个人智能体的缺口反而在扩大。

## 3. 人们希望出现什么

### 编程智能体定制基准测试

[@thdxr](https://x.com/thdxr/status/2048388289112006988) 所说的“还不如默认版”批评，与 harness 工程社区量化出的优势（比 ReAct 高 15.7 分）之间的张力，暴露出一个缺口：个人开发者没有标准方法来衡量，自己的定制智能体配置是否真的在特定工作流中优于默认设置。ClawEnvKit 这类基准测试已存在于研究领域，但还没有面向个人生产力评估的版本。

## 7. 机会在哪里

**[+++］** **统一的个人智能体平台** -- ［@petergyang](https://x.com/petergyang/status/2048433179338633627)提出了七项要求（跨应用工作、主动行为、持久记忆、多模态输入、多平台、消息可达性、个性），并发现没有任何产品能全部满足。113 次收藏表明，开发者正把这当作一份产品规格来对待。Claude Code、Codex 和 OpenClaw 各自覆盖了其中不同的子集。谁能把这些能力整合成连贯的跨设备体验，谁就有机会拿下个人 agent 市场。

**[++］** **智能体定制化衡量** -- ［@thdxr 之间的张力](https://x.com/thdxr/status/2048388289112006988)那条获得 735 个赞的“比原生方案更差”批评，以及 ClawEnvKit 在 harness 上 15.7 分的优势，揭示出一个空白：目前没有标准基准，能让个人开发者衡量自己的定制配置是否真的有帮助。一个面向 coding agent 的个人生产力基准（而不只是研究基准）将能用数据来解决“定制化还是尽快交付”的争论。来源：[@thdxr](https://x.com/thdxr/status/2048388289112006988)、[@daniel_mac8](https://x.com/daniel_mac8/status/2048049449289527797)。

**[++］** **垂直领域智能体技能包** -- finance-skills (himself65) 表明，将领域专长封装为智能体技能能够立刻创造价值。法律、医疗、DevOps 和营销等垂直领域还缺乏同等标准化的技能包。Agent Skills 开放标准和 `npx skills add` 分发模式让创建和采用的门槛都很低。来源：［@tom_doerr](https://x.com/tom_doerr/status/2048178965966164047)、[@RhysSullivan](https://x.com/RhysSullivan/status/2048431538862461169)。

**[++］** **智能体到智能体的商业基础设施** -- Anthropic 的 Project Deal（186 笔交易，$4,000+）证明了智能体商业是可行的。目前还没有用于智能体协商、结算或争议解决的标准协议。更现实的切入点是受限的服务交易（预订、价格确认），而不是开放式市场。来源：［@Pirat_Nation](https://x.com/Pirat_Nation/status/2048416817983733935)，[@TechCrunch](https://x.com/TechCrunch/status/2048156238614274272).

**[+］** **智能体框架中的原生上下文优化** -- context-mode 的 82K npm 下载量和 86.5% 的 token 降幅证明了需求的存在。目前还没有主流智能体框架原生集成上下文拦截与压缩。这个工具目前以外部 MCP server 的形式覆盖 14 个平台；机会在于将其内建到框架核心中，让开发者默认就能获得 token 节省。来源：［@mksglu](https://x.com/mksglu/status/2048295938096082978).

## 8. 要点

1. **Anthropic 的四层生产级智能体框架在 4 月 26 日的话题中占据主导，多个帖子合计获得超过 2,700 个赞和 500 次收藏，但也招致了尖锐质疑：架构蓝图是否真能转化为生产环境中的可靠性。** 社区想看的是失败日志，而不是分层示意图。（[来源](https://x.com/cyrilXBT/status/2048262079925154192)、[来源](https://x.com/RoundtableSpace/status/2048239392322719805)）

4. **智能体技能分成两类：编程实践类技能（TypeScript conventions 项目获得 22,800 stars）和垂直领域类技能（通过 Agent Skills standard 进行金融分析）。两者都以可安装的 Markdown 文件形式分发，让智能体知识从字面意义上成为开源。**（[来源](https://x.com/RhysSullivan/status/2048431538862461169)、[来源](https://x.com/tom_doerr/status/2048178965966164047)）

5. **围绕 Anthropic Project Deal 的讨论，已从“不平等”框架走向实际部署：把受约束的服务交易（如 HVAC 预约、价格确认）作为智能体商业的切入点，而不是开放式市场。**（[来源](https://x.com/Pirat_Nation/status/2048416817983733935)、[来源](https://x.com/TechCrunch/status/2048156238614274272)）

6. **Stanford 开源了 Meta-Harness：这是一个让编码智能体在每次尝试中读取中位数 82 个文件、从而自动优化模型脚手架的框架，而 ClawEnvKit 的量化结果显示，在 1,040 个生成环境中，最佳 harness 的表现比原始 ReAct 高出 15.7 个百分点。** ([来源](https://x.com/AlphaSignalAI/status/2048371802343149600), [来源](https://x.com/daniel_mac8/status/2048049449289527797))

7. **context-mode 在 GitHub 上达到 10K stars、npm 下载量 82K，并在 14 个平台上实现了 86.5% 的 token 减少，表明上下文优化在工具层面已是一个已被解决的问题——但目前还没有任何主流框架原生集成这一能力。** ([来源](https://x.com/mksglu/status/2048295938096082978))

8. **没有任何个人代理产品同时满足 @petergyang 定义的七项标准（113 个书签）：跨应用、主动性、记忆、多模态、多平台、消息传递和个性。** Claude Code、Codex 和 OpenClaw 都在不同维度上存在缺失。统一型个人代理仍是最大的尚未被占据的产品机会。 ([来源](https://x.com/petergyang/status/2048433179338633627))
