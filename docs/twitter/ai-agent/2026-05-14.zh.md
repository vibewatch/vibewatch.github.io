# Twitter AI 智能体 - 2026-05-14

## 1. 人们在讨论什么

### 1.1 常驻型智能体开始落地，并明确给出权限界面 🡕

最大的变化，不是又多了一张抽象的编排架构图，而是出现了具名智能体，明确说明自己能看到哪些数据、可以执行哪些操作。Google 泄露的 Gemini Spark 引导流程、xAI 的 Grok Build 测试版，以及 SAP/NVIDIA 的 OpenShell 运行时，都将智能体塑造成长期运行的执行者；在用户愿意信任它们之前，这类系统需要先解决权限、浏览器状态和执行控制。

[@testingcatalog](https://x.com/testingcatalog) [报道](https://x.com/testingcatalog/status/2054839588963696792)（524 个赞、26 条回复、34,072 次浏览）称，Gemini Spark BETA 被定位为一个 24/7 处理收件箱和在线任务的智能体，其引导文案写明，它可以调用 Connected Apps、技能、聊天记录、用户已登录的网站、Personal Intelligence 和位置信息，同时保存远程浏览器数据，例如登录详情和远程代码执行状态。TestingCatalog 配套的 [文章](https://www.testingcatalog.com/google-prepares-gemini-spark-ai-agent-ahead-of-i-o-launch/) 含有相同文案，并指出 Google 警告称，由于 Spark 仍处于实验阶段，它可能会与第三方共享信息，或在未经用户确认的情况下进行购买。

![Gemini Spark 引导界面截图，展示了其始终在线的代理定位、跨应用上下文来源，以及它可能会在未询问的情况下共享信息或进行购买的警告](https://pbs.twimg.com/media/HIRBtw5XAAAOpxB.jpg)

[@yunta_tsai](https://x.com/yunta_tsai) [表示](https://x.com/yunta_tsai/status/2055025397448966247)（362 个赞、20 条回复、18,452 次浏览）称，Grok Build 已经可用于车队数据分诊、改进训练标注、修补安全漏洞，以及在多个环境中提出建议；其中还引用了 xAI 对 Grok Build 早期测试版的描述：这是一个面向编程、应用构建和工作流自动化的智能体 CLI。更有力的证据来自回复区：他称其为自己的“主力干活工具”，而 xAI 团队成员也回复称，直接的用户反馈正在加速产品改进。

[@nvidia](https://x.com/nvidia) [宣布](https://x.com/nvidia/status/2054622706465702339)（468 个赞、33 条回复、39,198 次浏览）称，SAP 正将 NVIDIA OpenShell 嵌入 SAP Business AI Platform，以推动专业智能体从开发阶段进入可信的生产部署。NVIDIA 自己的 [发布文章](https://blogs.nvidia.com/blog/sap-specialized-agents/) 表示，OpenShell 增加了隔离执行环境、文件系统与网络策略强制执行，以及在智能体逻辑失效时的隔离遏制能力；SAP 配套的 [帖子](https://news.sap.com/2026/05/secure-ai-agents-how-sap-and-nvidia-co-define-enterprise-grade-agent-execution/) 则将同一层描述为业务流程中实现可审计性、企业 IAM 对齐和可治理执行的基础。

**讨论洞察：** 回复区关注的重点，不再是模型原始能力，而是监督机制。Gemini Spark 引发的质疑主要集中在其发布范围，以及 Google 是否值得被托付后台操作；而 SAP/OpenShell 相关讨论则反复回到同一个问题：智能体究竟能访问什么、批准什么、花多少钱。

**与前一天对比：** 5 月 13 日已经强调了 Notion 和 Cursor 中的编排界面。到了 5 月 14 日，这一转变变得更具体：面向消费者、编程和企业的智能体，都被呈现为需要明确控制层的常驻系统。

### 1.2 托管式控制平面与可回放工作流，正在取代临时会话 🡕

第二条讨论脉络，将话题从“智能体可以协同”推进到“智能体需要运营界面”。最有代表性的不是模型发布，而是控制平面、扇出式运行时和可复现的工作流工件——它们让智能体行为变得可观测、可复跑。

[@ashpreetbedi](https://x.com/ashpreetbedi) [认为](https://x.com/ashpreetbedi/status/2054678134147203535)（19 个赞、4 条回复、2,039 次浏览）称，下一代界面将是一个托管式智能体工作区，具备上下文、工具、权限、记忆、审阅循环和领域专属技能，并链接到 [Agno](https://github.com/agno-agi/agno)。Agno 的公开 README 将其描述为一个用于构建和管理智能体平台的控制平面，提供追踪、调度、RBAC、人工审批、上下文提供器和多种界面，因此这条推文不只是泛泛的工作区概念图。

![Agno 仪表板，展示了在统一控制平面中管理代理、团队、工作流、追踪、记忆、评估、审批和调度器](https://pbs.twimg.com/media/HIOuzamawAApC5i.jpg)

[@cline](https://x.com/cline) [分享了](https://x.com/cline/status/2054972897568104853)（27 个赞、2 条回复、1,108 次浏览）展示了一个 Cline SDK 多智能体示例：它并行启动多个专长型智能体，并将输出实时流式传到浏览器。公开的 [示例 README](https://github.com/cline/cline/tree/main/sdk/apps/examples/multi-agent) 表示，该应用会使用 `Promise.all` 并发运行三个智能体，通过 SSE 发送各自的输出流，再把这些输出交给一个综合智能体处理。这是一种具体的实现模式，而不是含糊的“多智能体”口号。

[@kane_cli](https://x.com/kane_cli) [推出了](https://x.com/kane_cli/status/2054938158027116899)（11 个赞、1 条回复、140 次浏览）介绍了 Test.md：它可以把一次成功通过的浏览器流程保存下来，之后在 CI 中重跑，或交给另一个智能体，而无需从头重写。Kane 的公开 [agents.md](https://testmuai.com/kane-cli/agents.md) 描述了基于 Markdown 的测试，支持可复用导入、变量、回放、缓存和 Playwright 互操作性，精准收窄了浏览器智能体最常见的失败模式之一：演示能跑通，但难以复现。

**讨论洞察：** 围绕托管式工作区的回复，更关注集成而非新奇性。Agno 话题下最早出现的问题之一，就是它能否与现有订阅配合使用。这说明团队想要的是能吸纳现有工具的控制平面，而不是把一切推倒重来。

**与前一天对比：** 5 月 13 日将工作区和编排视为产品方向。5 月 14 日则补上了更具体的基础能力：RBAC、调度器、SSE 扇出，以及可回放的 Markdown 测试。

### 1.3 市场正在从技能发现转向付费服务发现 🡕

技能供给爆发仍是主线，但叙事已从“找到一个技能”扩展到“找到一项服务并为之付费”。最强的市场类帖子聚焦于发现层，但后续讨论表明，信任与评估机制仍然落后于目录规模。

[@cyrilXBT](https://x.com/cyrilXBT) [声称](https://x.com/cyrilXBT/status/2054877213716296014)（98 个赞、15 条回复、3,677 次浏览）称，一个智能体技能市场已经上线，拥有超过一百万个可直接部署的技能和插件。公开的 [Skills Marketplace](https://skillsmp.com/) 网站目前宣传其收录了 1,319,403 个源自 GitHub 的 SKILL.md 条目，兼容 Claude Code 和 Codex 类工具，并在 FAQ 中建议用户安装前先检查代码。这与推文中的规模说法一致，也凸显出大量责任依然被推回给用户。

[@circle](https://x.com/circle) [推出了](https://x.com/circle/status/2054985094251556895)（107 个赞、9 条回复、5,344 次浏览）将 Agent Marketplace 描述为一个让已获资金支持的智能体发现、评估并集成付费服务的平台。Circle 的 [Agent Stack 发布文章](https://www.circle.com/blog/introducing-circle-agent-stack-financial-infrastructure-for-the-agentic-economy) 表示，该套件结合了 Agent Wallets、Agent Marketplace、CLI、nanopayments 和技能，使智能体能够持有 USDC、发现服务并以编程方式完成交易；[agents.circle.com](https://agents.circle.com/) 则将其表述为面向付费 API 的“以支付作为认证”。

![Circle Agent Marketplace 发布图片，展示了 Circle Agent Stack 内付费代理式服务的服务发现界面](https://pbs.twimg.com/media/HIS87HyaMAA_-6J.jpg)

**讨论洞察：** 两个市场话题都立刻暴露出同一个缺失层。SkillsMP 的回复质疑，这样的超大目录是否只是一个更高级的提示词商店，却没有质量信号；Circle 相关回复则要求声誉机制、可靠性和可执行合同，尤其是在智能体开始自主购买服务之后。

**与前一天对比：** 5 月 13 日聚焦于技能目录规模和第一方技能。5 月 14 日则把这条逻辑延伸到了市场：智能体不只是安装能力，还应能发现并购买服务。

## 2. 什么让人感到沮丧

### 一旦智能体开始在后台行动，权限边界仍然过于模糊

最明显的高严重度问题，不是“模型太弱”，而是“控制界面不完整”。[@testingcatalog](https://x.com/testingcatalog) [报道](https://x.com/testingcatalog/status/2054839588963696792)（524 个赞、26 条回复、34,072 次浏览）称，Gemini Spark 可能会与第三方共享信息，或在未经用户确认的情况下进行购买；链接的 [TestingCatalog 文章](https://www.testingcatalog.com/google-prepares-gemini-spark-ai-agent-ahead-of-i-o-launch/) 复述了 Google 自己的警告：该产品仍处于实验阶段，应在监督下使用。企业侧也是同一问题的另一端：NVIDIA 的 [OpenShell 帖子](https://blogs.nvidia.com/blog/sap-specialized-agents/) 和 SAP 的 [配套文章](https://news.sap.com/2026/05/secure-ai-agents-how-sap-and-nvidia-co-define-enterprise-grade-agent-execution/) 实际上描述的是同一件事——一旦智能体能接触记录系统，团队就需要隔离遏制、策略强制执行、IAM 对齐和审计轨迹。严重程度：高。信息流中可见的解决方向，不是更好的提示词，而是更强的治理。

### 浏览器流程成功一次，并不意味着团队之后还能重跑

[@kane_cli](https://x.com/kane_cli) [将其描述为](https://x.com/kane_cli/status/2054938158027116899)（11 个赞、1 条回复、140 次浏览）直接点出了这种失败模式：浏览器流程也许能成功一次，但在 Test.md 出现之前，想在下周、在 CI 中，或通过另一个智能体重跑，往往就意味着必须重写。Kane 的公开 [agents.md](https://testmuai.com/kane-cli/agents.md) 用基于 Markdown 的回放、导入和缓存机制回应了这一问题，使这类抱怨显得异常具体。严重程度：中等，但可执行性强。它值得构建，因为痛点狭窄、反复出现，也很容易验证。

### 发现层到来的速度，快于信任信号的建立

市场相关话题在标题层面令人兴奋，但回复区明显更为怀疑。[@cyrilXBT](https://x.com/cyrilXBT) [推广了](https://x.com/cyrilXBT/status/2054877213716296014)（98 个赞、15 条回复、3,677 次浏览）介绍了一个拥有超过一百万项技能的技能市场，但最早的质疑回复之一就称，如果没有清晰的质量信号，这不过是“一个更花哨的提示词商店”。[Skills Marketplace 常见问题](https://skillsmp.com/) 本身也写明，用户安装前应检查代码。同样，[@circle](https://x.com/circle) [推出了](https://x.com/circle/status/2054985094251556895)（107 个赞、9 条回复、5,344 次浏览）介绍 Agent Marketplace，而回复马上就开始要求声誉、可靠性和可执行合同，尤其是在智能体开始自动购买服务之后。严重程度：对生产环境采用而言为高。当前的应对方式仍是人工审查和选择性策展。

## 3. 人们希望存在什么

### 面向技能和服务的信任评分发现机制

人们想要的，似乎不只是更大的目录，而是一个能告诉他们哪些安全、哪些是最新、哪些可靠的市场。[@cyrilXBT](https://x.com/cyrilXBT) [推动了](https://x.com/cyrilXBT/status/2054877213716296014)（98 个赞、15 条回复、3,677 次浏览）把注意力带向了一个拥有超过百万项技能的市场，但回复很快转向质量问题，而 [Skills Marketplace 常见问题](https://skillsmp.com/) 也明确要求用户安装前检查代码。相同模式也出现在 [@circle](https://x.com/circle) 的 [Agent Marketplace 帖子](https://x.com/circle/status/2054985094251556895)（107 个赞、9 条回复、5,344 次浏览）下方，回复要求付费服务具备声誉、可靠性和合同执行机制。机会：直接且具有竞争性。发现机制已经出现，但信任基础设施仍然薄弱。

### 无需人工结账回路的智能体支付与认证通道

Circle 自己的材料表明，这一需求正变得切实，而非停留在假设层面。[@circle](https://x.com/circle) [将其定位为](https://x.com/circle/status/2054985094251556895)（107 个赞、9 条回复、5,344 次浏览）将 Agent Marketplace 定位为让已获资金支持的智能体发现并集成服务的场所；[Agent Stack 博文](https://www.circle.com/blog/introducing-circle-agent-stack-financial-infrastructure-for-the-agentic-economy) 表示，智能体需要钱包、发现机制和 CLI 工具，以便以编程方式完成交易；[agents.circle.com](https://agents.circle.com/) 则将其表述为面向付费 API 的“以支付作为认证”。机会：直接。如今已经能看到基础设施雏形，但这一类别仍足够早期，以至于认证、结算和服务评估仍是开放的设计空间。

### 可回放、原生面向智能体的工作流工件

Kane 这一话题把需求讲得格外具体：缺口并不是广义上的浏览器自动化，而是另一智能体或 CI 任务能够可靠重跑的可重复浏览器自动化。[@kane_cli](https://x.com/kane_cli) [描述为](https://x.com/kane_cli/status/2054938158027116899)（11 个赞、1 条回复、140 次浏览）把 Test.md 描述为成功浏览器会话与持久工件之间缺失的桥梁；公开的 [agents.md](https://testmuai.com/kane-cli/agents.md) 则用 Markdown 步骤、导入、变量和回放补上了其实现机制。机会：直接。这更像是一项务实需求，而不是情绪性需求；现有证据显示，当前工具对此仍只是部分覆盖。

最强的构建模式是基础设施，而不是新奇包装。Grok Build、Agno、Cline SDK、Kane 和 Circle 都在试图填补执行、回放、支付或协同上的运营缺口，而不只是再加一个聊天界面。

BRUT-V 之所以突出，是因为它恰好属于另一类项目：一个公开工件，展示智能体如何协助产出真正的创意编程工具链。公开仓库称，它提供浏览器编辑器、JavaScript 汇编器、最小 RISC-V VM 和示例草图；而推文则声称，Hermes Agent 编写了 6,200 行汇编代码，并将该汇编器引导至与参考模拟器逐字节一致。

![BRUT-V 图库图片，展示了多张 RISC-V 汇编草图及其背后的原始代码清单](https://pbs.twimg.com/media/HIOuqXcWQAA1Rz6.png)

贯穿整个部分、反复出现的触发因素，是可靠性。构建者之所以把智能体打包进控制平面、可复现工件、支付通道和可检查仓库，是因为临时会话看起来已经不足以支撑严肃使用。

### Gemini Spark 让 Google 的后台智能体野心变得清晰可见

[@testingcatalog](https://x.com/testingcatalog) [披露了](https://x.com/testingcatalog/status/2054839588963696792)（524 个赞、26 条回复、34,072 次浏览）让外界第一次较清晰地看到了 Gemini Spark，而链接的 [文章](https://www.testingcatalog.com/google-prepares-gemini-spark-ai-agent-ahead-of-i-o-launch/) 则暗示 Google 可能会在 Google I/O 前后推出公开测试版。它之所以值得关注，不只是因为又多了一个智能体名字，而是因为其引导文案明确提到了已连接应用、用户已登录的网站、远程浏览器数据，以及未经确认便可能进行购买或共享数据的可能性。

## 7. 机会在哪里

**[+++] 面向可行动智能体的策略与审计层** —— 多个章节都能看到证据。Gemini Spark 的引导流程警告称可能发生数据共享和购买行为，而 SAP/NVIDIA 则明确将隔离遏制、策略强制执行、IAM 对齐和审计轨迹构建进 OpenShell。这个机会很强，因为相同需求同时出现在消费者和企业场景中。

**[++] 面向技能和服务的信任评分市场** —— SkillsMP 展示了供给，Circle 则展示了通往付费服务发现的下一步，但两个话题都立刻撞上了声誉、维护和合同执行问题。这个机会属于中等强度，因为市场显然正在形成，但缺失的信任层仍然开放。

**[++] 可回放的智能体工作流工件** —— Kane 的 Test.md 和 Cline 的多智能体示例都指向同一个缺口：成功的智能体工作需要被保存为持久工件，以便重跑、检查和交接。这个机会属于中等强度，因为痛点清晰且务实，尤其适用于浏览器和编排工作流。

**[+] 面向智能体的支付与认证通道** —— Circle 的 Agent Stack 和 agents.circle.com 表明，这一类别终于开始变得现实：钱包、付费 API 访问和机器速度结算，正在被一起打包。这个机会仍处于萌芽阶段，因为基础能力已经可见，但使用模式和评估标准仍然很早期。

## 8. 要点

1. **常驻型智能体在发布时附带了明确警告，而不只是承诺。** Gemini Spark 的引导流程写明，它可以使用已连接应用、用户已登录的网站和远程浏览器数据；由于仍属实验阶段，它可能会在未经询问的情况下共享信息或进行购买。（[来源](https://x.com/testingcatalog/status/2054839588963696792)）
2. **企业智能体采用正收敛到运行时隔离遏制与可审计性。** SAP 和 NVIDIA 并不是把 OpenShell 当作更精美的聊天机器人外壳来推销；他们主打的是隔离执行、策略强制执行，以及对接触业务流程系统的可审计控制。（[来源](https://x.com/nvidia/status/2054622706465702339)）
3. **智能体平台正在演变为控制平面。** Agno 的公开平台界面和 Cline 的流式多智能体示例都表明，当天的需求正从一次性聊天会话转向调度器、追踪、审批和结构化扇出。（[来源](https://x.com/ashpreetbedi/status/2054678134147203535)）
4. **发现能力扩张的速度快于信任建设。** SkillsMP 可以指向超过 130 万个源自 GitHub 的技能，但其 FAQ 和推文回复都表明，质量信号与安全安装信心仍远远落后于目录规模。（[来源](https://x.com/cyrilXBT/status/2054877213716296014)）
5. **可复现性正在成为智能体的一等议题。** Kane 对 Test.md 的定位之所以成立，正是因为团队已经遇到了这样的痛点：工作流能成功一次，却无法在 CI 中或通过另一个智能体回放，除非重新编写。（[来源](https://x.com/kane_cli/status/2054938158027116899)）
6. **公开的智能体构建工件正变得更容易检查。** BRUT-V 值得关注，是因为仓库、演示和截图让这一说法变得清晰可辨：它展示的是一个基于浏览器的创意编程栈，而不是含糊地声称“有智能体帮了忙”。（[来源](https://x.com/NousResearch/status/2054681412674932759)）
