# Twitter AI Agent - 2026-10-19

## 1. What People Are Talking About

### 1.1 Evaluation beyond prompt craft 🡕

Two practitioner posts focused on whether agent instructions work in practice, rather than on prompt-writing alone. [@sermakarevich](https://x.com/sermakarevich) [asked](https://x.com/sermakarevich/status/2112198653469241856) (57 likes, 11 replies, 3,628 views, 126 bookmarks) how to test whether an external skill helps, saying that many available skills are untested and written without a clear evaluation method. [@JFPuget](https://x.com/JFPuget) [reported](https://x.com/JFPuget/status/2112118534129987833) (96 likes, 51 replies, 4,476 views, 17 bookmarks) using agents for training experiments, while still needing to remove over-engineered changes, dead compatibility code, and unnecessary token use.

**Discussion insight:** A reply to JFPuget [suggested](https://x.com/laozhang_ai/status/2112131222382284809) (3 likes, 1 reply, 134 views, 2 bookmarks) explicitly labeling throwaway research repositories and checking diffs to catch unrequested compatibility work. In the skills discussion, one commenter questioned whether benchmark-task selection simply replaces one person's subjective judgment with another's; the author agreed that this is a real evaluation risk.

**Comparison to prior day:** On October 18, [@rakyll](https://x.com/rakyll) [argued](https://x.com/rakyll/status/2111842823989539153) (201 likes, 30 replies, 14,874 views, 46 bookmarks) that open-source software around agents may be hard to defend unless it improves model quality. Today's posts shift the focus from defensibility to whether skills and generated code can be tested and kept maintainable.

## 2. What Frustrates People

### Agent overreach and unverified skills

JFPuget [described](https://x.com/JFPuget/status/2112118534129987833) (96 likes, 51 replies, 4,476 views, 17 bookmarks) coding agents adding work he did not request, retaining dead compatibility paths, and increasing token use without benefit. He says the agent still needs a human driver. The skill-evaluation post [raises](https://x.com/sermakarevich/status/2112198653469241856) (57 likes, 11 replies, 3,628 views, 126 bookmarks) a related reliability concern: an instruction bundle can look useful without having been tested on representative tasks. The evidence is limited to these practitioner posts, but both identify review and evaluation as practical work rather than solved problems.

## 3. What People Wish Existed

### A repeatable way to evaluate skills

The clearest request is for a way to determine whether an external skill improves outcomes, expressed by [@sermakarevich](https://x.com/sermakarevich) [here](https://x.com/sermakarevich/status/2112198653469241856) (57 likes, 11 replies, 3,628 views, 126 bookmarks). The discussion points to fixed tasks or a rubric, while also warning that benchmark choice can be subjective. **Opportunity: direct and emerging**; the post asks for an evaluation method, and no existing approach is described as sufficient.
