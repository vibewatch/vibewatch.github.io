# Twitter AI Agent - 2026-10-20

## 1. What People Are Talking About

### 1.1 Agents are being paired with deterministic code checks 🡕

Uber's AutoClean post reports removing more than one million lines of dead code and cleaning up 16,000+ stale feature flags with agents, deterministic transformations, and validation. [@UberEng](https://x.com/UberEng) [described](https://x.com/UberEng/status/2112604623454470476) (177 likes, 11 replies, 10,849 views, 229 bookmarks) the system, while a reply highlighted restricting automated test-fixing to test files so an agent cannot make a failing test pass by changing production code. A separate merge-risk skill scores proposed changes across alignment, impact, verification, rollback cost, and error detection.

### 1.2 The company harness includes identity, memory, and scheduling 🡕

LangChain's account describes building shared infrastructure after internal agents across marketing, sales, and engineering exposed common needs. [@caspar_br](https://x.com/caspar_br) [outlined](https://x.com/caspar_br/status/2112644945697976630) (26 likes, 1 reply, 4,190 views, 40 bookmarks) Slack-based access, user-scoped identity and memory, a sandbox for code and authenticated tools, and scheduled runs; its Managed Deep Agents documentation describes the product runtime.

**Discussion insight:** In a separate overnight-run post, [@obie](https://x.com/obie) [asked](https://x.com/obie/status/2112592132099711365) (53 likes, 18 replies, 2,906 views, 61 bookmarks) what decisions an agent made while it continued through reviews, merges, and deployments. A reply questioned allowing overnight merges and deploys, and Obie said staging was an option.

## 2. What Frustrates People

### Trusting agent-generated changes

The merge-risk post frames review as a bottleneck: teams need to assess scope, verification, rollback cost, and error detection before trusting an agent-produced change. [@BHolmesDev](https://x.com/BHolmesDev) [outlined](https://x.com/BHolmesDev/status/2112653011369807971) (99 likes, 6 replies, 4,058 views, 143 bookmarks) five dimensions for that assessment. Uber's post also emphasizes deterministic transformations and validation rather than unbounded code edits.

### Understanding long-running work

The overnight-run post asks what an agent decided while it continued through reviews, merges, and deployments. Its replies include concern about letting changes ship unattended, pointing to a visibility and control problem rather than a demonstrated failure.

---

## 3. What People Wish Existed

### Risk-based review with visible evidence

The merge-risk skill is a concrete attempt to make trust decisions explicit, scoring alignment, impact, verification, rollback cost, and error detection. Its author [describes](https://x.com/BHolmesDev/status/2112653011369807971) (99 likes, 6 replies, 4,058 views, 143 bookmarks) a path toward more reviewable, lower-risk changes. The post evidences a proposed tool and a stated bottleneck, not broad user demand.
