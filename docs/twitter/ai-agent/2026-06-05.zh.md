# Twitter AI Agent - 2026-06-05

## 1. 人们在讨论什么

### 1.1 Agent 的价值被重新定义为模型之上的脚手架、上下文与编排 🡕

6 月 5 日最清晰的 AI Agent 主题是：模型本身越来越不构成差异化，真正拉开差距的是包裹在模型外部的系统。共有五条入选内容支撑了这一主题。

[@RihardJarc](https://x.com/RihardJarc) [报道](https://x.com/RihardJarc/status/2062889341643350082)（61 个赞、5 条回复、5,352 次浏览、54 次收藏）是一段对 Microsoft 员工的采访。对方认为，模型正在成为 SaaS 层，而真正的价值存在于 Microsoft 所说的“脚手架”中：AI 如何连接企业数据、接收什么上下文、如何观测 token 开销，以及如何处理权限与安全。随附的采访截图把这一点说得很具体，明确写到真正的魔力已不再只存在于基础模型本身，而在于其上方那一层。

![文字记录截图，重点标出 Microsoft 关于模型正在成为 SaaS 层、其上的脚手架会创造价值的说法](https://pbs.twimg.com/media/HKDa24UW0AAhW_3.png)

[@GoogleResearch](https://x.com/GoogleResearch) [宣布](https://x.com/GoogleResearch/status/2062982001850974257)（238 个赞、5 条回复、15,507 次浏览、202 次收藏）介绍了一套面向企业问题的新型多 Agent RAG 工作流。Google 随附的 [博客文章](https://research.google/blog/unlocking-dependable-responses-with-gemini-enterprise-agent-platforms-agentic-rag/) 表示，该系统使用规划器、查询重写和充分上下文检查，在 824 个 FramesQA 查询和 2,676 份 PDF 上回答多跳问题；在跨语料库场景下准确率达到 90.1%，同时将延迟控制在单语料库版本的 3% 以内。

[@mattpocockuk](https://x.com/mattpocockuk) [认为](https://x.com/mattpocockuk/status/2062825992486269441)（114 个赞、16 条回复、5,107 次浏览、44 次收藏）认为，上下文工程本质上是在加载代码、转录等一手来源，与加载摘要、文档等二手来源之间做权衡。这一框架与当天其他讨论高度一致：人们关注的不再是模型的“个性”，而是哪几层上下文值得为之付费。

[@tenobrus](https://x.com/tenobrus) [表示](https://x.com/tenobrus/status/2062729311233454363)（224 个赞、18 条回复、9,927 次浏览、104 次收藏）认为，Claude Code 的动态工作流才是合理版本的 Agent 编排；他随后又在回复中给出更具体的用法：已经将其用于大型重构、数据处理、临时评测、系统化找 Bug 和安全任务。一条回复进一步提炼出操作层面的经验：单独保留一个范围受限的探索窗口，避免过时假设泄漏到真实构建过程中。

**讨论洞察：** 回复不断把抽象的“编排”讨论翻译成具体的操作问题：独立的限定范围窗口、数据集成、token 可观测性、语料库路由，以及足以可靠回答问题的充足上下文。

**与前一天的对比：** 6 月 4 日强调 harness 是关键层；到了 6 月 5 日，讨论又往前走了一步，把模型之上的脚手架、上下文纪律和编排直接视为真正的产品护城河。

### 1.2 共享运行时与技能层看起来将成为下一场 Agent 平台争夺战 🡕

第二个讨论簇围绕 Agent 的共享基础设施展开：可复用的运行时、注册表和编排器，而不是每个团队都重复搭建同样的胶水代码。共有四条入选内容支撑了这一主题。

[@pvncher](https://x.com/pvncher) [宣布](https://x.com/pvncher/status/2062866814695092511)（282 个赞、31 条回复、11,880 次浏览、101 次收藏）介绍了 GitHub 上的 RepoPrompt Community Edition，并将其描述为一款多 Agent 编排工具：它反转了 harness 的设计方式，让 MCP 服务器成为主 Agent，而底层 CLI harness 则可自由替换。公开的 [RepoPrompt CE 仓库](https://github.com/repoprompt/repoprompt-ce) 将其描述为一款免费的 macOS 上下文工程应用：从文件、CodeMaps、代码仓库结构和 Git diff 组装出可审阅的上下文，再通过原生界面协调由 CLI 驱动的 Agent。

[@rauchg](https://x.com/rauchg) [将其描述为](https://x.com/rauchg/status/2062951924677128455)（61 个赞、13 条回复、6,855 次浏览、20 次收藏）将 Skills API 称为“Agent 能力与可扩展性的 npm 注册表”。公开的 [skills.sh](https://www.skills.sh/) 首页通过“单命令安装”来描述一个开放的 Agent 技能生态，这基本印证了帖文主旨；但一条回复立刻让 npm 类比的另一面浮出水面：需要警惕拼写劫持和供应链攻击，技能安装必须配套版本锁定、审查和评测。

[@OpenCovenant](https://x.com/OpenCovenant) [认为](https://x.com/OpenCovenant/status/2062872216736354574)（38 个赞、23 条回复、389 次浏览）指出，各类 Agent 框架都在重复造权限、记忆、日志和身份这套轮子。公开的 [Covenant 仓库](https://github.com/open-covenant/covenant) 把这一点说得很具体：它将自身定位为一个 Rust 守护进程和本地控制平面，提供运行时分发、基于 SQLite 的记忆、签名能力、追加式审计、MCP 与 A2A 适配器，以及 Next.js 操作控制台。

[@TheAhmadOsman](https://x.com/TheAhmadOsman) [分享](https://x.com/TheAhmadOsman/status/2062702020612472990)（43 个赞、4 条回复、1,602 次浏览、39 次收藏）介绍了一层围绕多 Agent 委派、增强记忆、更完善的产物、AGENTS.md 上下文化和可选运行时指标构建的 Codex CLI 增强层。回复也说明了它为何重要：人们第一时间就追问，记忆如何跨委派保留，以及如何避免子 Agent 上下文失控膨胀。

**讨论洞察：** 真正有意思的分歧不在于 Agent 是否需要可复用能力，而在于这些能力应当落在哪里：运行时、技能注册表，还是包在现有 Agent 外层的编排 shell。

**与前一天的对比：** 6 月 4 日更强调可安装技能和公开的操作员工具；到了 6 月 5 日，讨论更明显地转向共享操作层，以及多个 Agent 产品都能建立其上的开放注册表。

### 1.3 安全与验证成为 Agent 的一等工作，而不再只是收尾 🡕

安全讨论从泛泛警告转向了关于可审计性、失败边界，以及不加固 Agent 技术栈代价的具体案例。共有四条入选内容支撑了这一主题。

[@P3b7_](https://x.com/P3b7_) [解释](https://x.com/P3b7_/status/2062807526463205876)（254 个赞、69 条回复、36,481 次浏览、106 次收藏）称，一次由 AI 驱动、运行 Opus 4.8 的审计发现了一个 Zcash Orchard 漏洞，而此前审计以及 Opus 4.7 都未能发现。其线程称，该 Agent 在约 6 小时内生成了一个可运行的 RPC 级 PoC，并认为持续性的 AI 辅助审计再加上更强的形式化验证，如今已成为高风险系统新的防御基线的一部分。

![技术截图，解释了 Orchard 电路中缺失的约束如何让证明者绕过 nullifier 完整性检查](https://pbs.twimg.com/media/HKCPArbWMAAT2O-.png)

[@RoundtableSpace](https://x.com/RoundtableSpace) [发布](https://x.com/RoundtableSpace/status/2062765105729933684)（44 个赞、15 条回复、26,993 次浏览）介绍了一项故意保持简单的提示注入测试：要求 Agent 忽略先前指令并泄露其隐藏的系统提示。回复很快把讨论推进到一次性测试之外，认为真实系统需要的是分层的指令边界、输出过滤和红队测试，而不是依赖某一个脆弱的单点防线。

[@asmah2107](https://x.com/asmah2107) [分享](https://x.com/asmah2107/status/2062870047903605109)（60 个赞、1 条回复、1,650 次浏览、112 次收藏）给出了一份 Agent 架构阅读清单，混合了 CAP 定理、Hystrix、Saga 模式、Google SRE 一书、OWASP LLM Top 10、LangGraph、AutoGen，以及《欧盟 AI 法案》中的人工监督规则。这个组合之所以重要，在于它把监督和攻击面视为核心架构知识的一部分，而不是事后补充。

**讨论洞察：** 当天的安全语气非常偏操作层。人们的诉求是：锁定技能版本、限定权限范围、记录操作、当前沿模型变化时重新跑审计，并明确界定 Agent 不应被允许泄露什么。

**与前一天的对比：** 6 月 4 日聚焦恶意输入和委派策略；6 月 5 日则增加了一个具体且高影响力的审计案例，以及更明显的运行时治理回应。

## 2. 人们感到挫败的地方

### 团队仍把 Agent 当成单条提示词，而不是系统

严重程度：高。[@sjsandeep_jain](https://x.com/sjsandeep_jain/status/2062720562758050289)（32 个赞、10 条回复）明确将 Agent 构建拆分为提示设计、记忆、编排、UI 和评测，因为仍有太多团队只是把一个模型接到一条提示词上就停下了。[@tenobrus](https://x.com/tenobrus/status/2062729311233454363)（224 个赞、18 条回复、104 次收藏）指出，动态工作流只有在范围被谨慎管理时才有效；一条回复还描述了如何把探索窗口与真实构建分开，以避免过时上下文渗漏。[@GoogleResearch](https://x.com/GoogleResearch/status/2062982001850974257)（238 个赞、5 条回复、202 次收藏）则几乎展示了这个问题的企业版：想得到可靠答案，需要规划 Agent、查询重写和充分上下文检查，而不是普通检索。人们正在通过绘制蓝图、构建多 Agent 检索循环和文档化工作流来应对，但根本挫败感在于，太多 Agent 部署仍停留在 demo 层。这值得投入，因为整条信息流反复指向的都是脚手架缺失，而不是模型智能不足。

### 信任与安全在运行时仍然太容易失守

严重程度：高。[@P3b7_](https://x.com/P3b7_/status/2062807526463205876)（254 个赞、69 条回复、36,481 次浏览）描述了一个已有 4 年历史的 Zcash bug 被 Opus 4.8 驱动的审计抓到，这把 Agent 安全重新定义成了一场比拼谁先获得更强自动化审计能力的竞赛。[@RoundtableSpace](https://x.com/RoundtableSpace/status/2062765105729933684)（44 个赞、15 条回复、26,993 次浏览）则用一次直白的提示注入测试把问题压缩呈现出来，而回复立刻主张更强的边界、输出过滤和红队测试。[@OpenCovenant](https://x.com/OpenCovenant/status/2062872216736354574)（38 个赞、23 条回复）从基础设施侧瞄准了同一缺口，试图集中管理权限、记忆和审计。人们正在用运行时层、审计和显式策略来应对，但现有证据仍显示，Agent 技术栈太容易把信任责任泄漏到应用层。这值得投入，因为这里的失败模式不只是浪费时间，而是不可信执行。

### 技能与可复用能力更容易共享，却更难治理

严重程度：中高。[@rauchg](https://x.com/rauchg/status/2062951924677128455)（61 个赞、13 条回复、6,855 次浏览）称赞了一种注册表式的 Agent 技能模型，但一条回复立刻点出注册表的负面一面：如果技能成为 Agent 的 npm 层，那么拼写劫持和供应链攻击也会一起成为 Agent 问题。[@pvncher](https://x.com/pvncher/status/2062866814695092511)（282 个赞、31 条回复、101 次收藏）和 [@OpenCovenant](https://x.com/OpenCovenant/status/2062872216736354574)（38 个赞、23 条回复）则分别从不同方向给出了对这一治理问题的回应：前者是面向用户的编排器，后者是更底层的运行时。人们正通过集中化的上下文审查、权限和审计来应对，但安装、版本管理和评测看起来仍高度依赖人工。这值得投入，因为生态显然正在走向可复用 Agent 能力，但其信任模型仍未定型。

### 操作层知识仍然需要从帖子、仓库和阅读清单中拼凑

严重程度：中。[@sairahul1](https://x.com/sairahul1/status/2062810319920209933)（427 个赞、28 条回复、1,012 次收藏）将 harness 工程和记忆架构描述为最有价值、却仍未被正规教育充分教授的技能。[@asmah2107](https://x.com/asmah2107/status/2062870047903605109)（60 个赞、112 次收藏）给出了一份横跨分布式系统、安全与监管的阅读清单，[@DanKornas](https://x.com/DanKornas/status/2062972973435269324)（18 个赞、19 次收藏）则提供了一个按章节组织的公开仓库。人们正在通过公开材料自行拼装课程体系。这值得投入，因为结构化、重实践的教育需求已经非常明显，但现有结构仍然碎片化。

## 3. 人们希望存在什么

### 内置的上下文、可观测性与权限脚手架

这是数据集中最务实的需求。[@RihardJarc](https://x.com/RihardJarc/status/2062889341643350082)（61 个赞、5 条回复、54 次收藏）概括了 Microsoft 的一种看法：如今价值位于模型之上的脚手架，尤其是数据访问、可观测性和权限。[@sjsandeep_jain](https://x.com/sjsandeep_jain/status/2062720562758050289)（32 个赞、10 条回复）把同一个问题呈现为一份整套系统蓝图，[@OpenCovenant](https://x.com/OpenCovenant/status/2062872216736354574)（38 个赞、23 条回复）则给出了一个运行时层面的答案，围绕记忆、日志、身份和授权展开。机会：直接。虽然已经有部分答案，但信息流反复显示，团队仍在手工拼装这套栈。

### 默认具备安全的技能分发与运行时信任

这是一个务实且紧迫的需求。[@rauchg](https://x.com/rauchg/status/2062951924677128455)（61 个赞、13 条回复、6,855 次浏览）推动开放技能生态，但回复立刻要求提供类似包管理器的安全机制：在 Agent 摄入新指令前，先完成版本锁定、审查和评测。[@RoundtableSpace](https://x.com/RoundtableSpace/status/2062765105729933684)（44 个赞、15 条回复）通过一次简单的泄露测试让运行时信任问题变得可见，[@P3b7_](https://x.com/P3b7_/status/2062807526463205876)（254 个赞、69 条回复）则展示了当前沿模型成为更强审计员后，攻防双方会如何同步加速。机会：直接且竞争激烈。

### 一条从 ReAct 演示走向生产级 Agent 系统的公开学习路径

这是一个务实而非理想化的需求。[@sairahul1](https://x.com/sairahul1/status/2062810319920209933)（427 个赞、1,012 次收藏）指出 harness 工程和记忆架构没有被很好地教授，[@asmah2107](https://x.com/asmah2107/status/2062870047903605109)（60 个赞、112 次收藏）把系统与安全文献串成了一份阅读清单，[@DanKornas](https://x.com/DanKornas/status/2062972973435269324)（18 个赞、19 次收藏）则发布了一个可上手实践的源码仓库。机会：直接。人们想要的不是更多“灵感”，而是一套连贯的技能序列、示例和操作习惯。

### 能证明自己已经找到足够上下文的企业级检索

这是一个非常具体的技术需求。[@GoogleResearch](https://x.com/GoogleResearch/status/2062982001850974257)（238 个赞、202 次收藏）把可靠的企业级回答定义为查询分解与充分上下文检查的问题，而不是基础检索问题；[@mattpocockuk](https://x.com/mattpocockuk/status/2062825992486269441)（114 个赞、44 次收藏）则描述了更深层的权衡：是加载更丰富的一手来源，还是加载更便宜但有损的二手来源。机会：直接。缺口不在“搜索”本身，而在于系统是否知道自己已经掌握了足够证据来作答。

| Claude Code 动态工作流 | 编排/运行时 | (+) | 在早期实操中已用于重构、数据处理、临时评测、查 Bug 和安全任务 | 操作员仍需严格控制范围，避免过时假设在不同窗口间串流 |
| Google agentic RAG | RAG 框架 | (+) | 能拆解企业问题、重写查询、检查上下文是否充分，并在 Google 测试中取得 90.1% 的跨语料库准确率 | 需要规划器、查询重写和语料库路由等机制，而不是简单的检索配置 |
| RepoPrompt CE | 上下文工程/编排器 | (+) | 能构建高密度、可审阅的代码库上下文，并通过兼容 MCP 的工具协调 CLI Agent | 公开社区版是原生 macOS 应用，因此当前平台覆盖范围较窄 |
| Covenant | 运行时/治理 | (+) | 在一个操作层中集中处理权限、记忆、审计、身份和运行时分发 | README 表示，恶意代码沙箱和多节点协同仍在路线图上 |
| Skills API / skills.sh | 技能注册表 | (+/-) | 通过简单的注册表模型，让可复用的 Agent 能力可被跨 Agent 安装 | 注册表模式也带来了类似软件包生态中的版本锁定、审查和供应链风险 |
| Opus 4.8 AI 辅助审计 | 模型/安全方法 | (+/-) | 揪出了旧审计和 Opus 4.7 都漏掉的一个高难度 Zcash bug | 也降低了攻击者成本，而且原线程本身也说明这种检测并非确定性的 |
| atlas-agents | 学习仓库 | (+) | 为构建者提供了一条覆盖 ReAct、交接、LangGraph、CrewAI、MCP 和 A2A 的分章节学习路径 | 这是教育仓库，不是完整的生产级运行时或产品 |

总体满意度偏向那些能让 Agent 工作更结构化、更可检查的系统；而对于能力增长速度快于治理能力的东西，评价则较为复杂。最常见的应对办法仍是增加更多脚手架：限定范围的窗口、可审阅的上下文、签名能力、审计日志，或按章节组织的学习材料。竞争态势也在变化：人们讨论的重点不再是靠某一个模型取胜，而是靠包裹多模型的编排层、运行时层、技能层和可观测性层取胜。

RepoPrompt CE 和 Covenant 是针对同一结构性问题的两种不同解法。RepoPrompt 位于栈的更上层，通过以 MCP 为中心的 UI 筛选代码库上下文并编排工作；Covenant 则位于框架层之下，集中处理权限、审计、记忆和运行时分发。

Google 的 agentic RAG 框架代表了同一运动在企业侧的版本。它不是要求模型第一次就答对，而是先在生成前把检索问题拆成路由、重写和证据充分性判断。

atlas-agents 和 skills.sh 则展示了另一条并行的构建者路径：让 Agent 能力更可教、也更可复用。前者把示例打包成一条可学习的代码路径；后者则把能力打包成可安装的技能。

## 7. 机会所在

**[+++] 面向真实业务工作流的 Agent 脚手架与可观测性** —— 证据来自 Microsoft 的“脚手架”框架、Google 的多 Agent RAG 系统、Tenobrus 针对具体工作流的编排说明，以及 Sandeep Jain 的系统蓝图。需求之所以强烈，是因为多条帖文都收敛到模型之上的同一缺失层。

**[+++] 受治理的运行时与安全的技能供应链** —— RepoPrompt CE、Covenant、skills.sh、RoundtableSpace 的泄露测试，以及 Zcash 审计线程都指向同一缺口：可复用能力来得比审查、策略和审计纪律更快。

**[++] 从系统而非提示词出发的操作员教育** —— Sairahul 的路线图、Ashutosh Maheshwari 的阅读清单，以及 Dan Kornas 的 atlas-agents 仓库都显示，人们需要的是把上下文、记忆、编排、评测和治理一起覆盖的实用学习路径。

## 8. 要点总结

1. **竞争层已经上移到模型之上。** Microsoft 的“脚手架”框架、Matt Pocock 的上下文权衡模型、Google 的 agentic RAG 设计，以及 Tenobrus 面向具体工作流的编排示例，都指向同一个结论：价值正在向上下文、路由和执行结构聚集，而不只是基础模型质量。（[来源](https://x.com/RihardJarc/status/2062889341643350082)）
2. **可复用的 Agent 基础设施正在分化为注册表、编排器和操作层。** RepoPrompt CE、skills.sh 和 Covenant 从栈的不同位置切入同一个重复性问题，这说明市场正在真正成形，而不是只出现了零散工具。（[来源](https://x.com/pvncher/status/2062866814695092511)）
3. **安全不再是 Agent 构建者的支线任务。** Zcash 审计线程展示了当前沿模型变强后，高风险审查会多快发生变化；提示注入讨论则表明，很多默认防线依然十分脆弱。（[来源](https://x.com/P3b7_/status/2062807526463205876)）
4. **教育市场正在跟随操作员重心的迁移。** 关于 harness 工程、架构阅读清单和实操仓库的高收藏帖文说明，构建者想要的是 Agent 系统课程，而不是更多提示词技巧。（[来源](https://x.com/sairahul1/status/2062810319920209933)）
