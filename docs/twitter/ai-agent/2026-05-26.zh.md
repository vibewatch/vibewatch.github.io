# Twitter AI Agent - 2026-05-26

## 1. 人们在讨论什么

### 1.1 技能正成为可训练的产品与可复用的工程资产 🡕

5 月 26 日最明显的变化是，“技能”不再像私藏的提示词包袱，而开始呈现为可迁移资产。在高信号内容中，它们同时以三种形式出现：可销售的市场产品、可供智能体训练的外部状态，以及可跨运行时安装的可复用工程习惯。相比 5 月 25 日对记忆层和 harness 术语表的强调，5 月 26 日则把同一理念进一步推进到了变现、优化和分发层面。

[@Capafyai](https://x.com/Capafyai) [发布了](https://x.com/Capafyai/status/2059274292932878595)（373 个赞、227 条回复、254 条引用、119,630 次浏览）将 Capafy 描述为一个市场：在 Claude Code、Codex 或 OpenClaw 中构建的技能，可以在线运行，同时保持闭源。实时 [Capafy 网站](https://capafy.ai) 已经列出了电商广告、简历筛选、社交媒体文案、PDF 生成和数据分析等领域的专家智能体，而 [Capafy-skills 仓库](https://github.com/Capafy/Capafy-skills) 则解释了两种客户端流程——Capafy-Publisher 和 Capafy-User——以及闭源 Run Online 模式与普通 Download 模式之间的关键商业差异。

[@koylanai](https://x.com/koylanai) [认为](https://x.com/koylanai/status/2059113412278227328)（231 个赞、502 次收藏、55,849 次浏览）介绍了 SkillOpt 如何将 `SKILL.md` 文件转化为可训练参数，并配套留出验证闸门、有界编辑预算和跨 harness 可移植性。配图让这一主张变得格外具体：被接受的修改幅度很小、经过验证且可复用，而不是大范围重写。[SkillOpt 仓库](https://github.com/microsoft/SkillOpt) 和 [论文](https://arxiv.org/abs/2605.23904) 进一步用六项任务上的基准覆盖与已报告的提升幅度支撑这一点，其中包括 GPT-5.5 在 Codex 风格 harness 中提升 +24.8 分。

[@daniel_mac8](https://x.com/daniel_mac8) [翻译了](https://x.com/daniel_mac8/status/2059244838789218409)（281 个赞、10 条回复、18,606 次浏览、343 次收藏）把这一研究思路变成了一套可运行的 Codex 习惯：先读论文，进入 `/goal` 模式，再在本地配置中实现这一循环。这张截图之所以重要，是因为它一边展示论文，另一边展示具体的脚本与目标工作流，把“可训练技能”变成了编码智能体可以立刻采用的实践模式，而不只是又一个收藏链接。

[@HiTw93](https://x.com/HiTw93) [打包了](https://x.com/HiTw93/status/2059075254954401855)（47 个赞、9 条回复、10,160 次浏览）介绍了 Waza 的八项工程技能，涵盖规划、设计、调试、评审、阅读、写作、研究和健康检查。[Waza 仓库](https://github.com/tw93/Waza) 展示了 Claude Code 和 Codex 的安装流程，以及手动串联技能的方法，因此这篇帖子不只是关于习惯的口号，而是一套关于可复用工程行为如何跨智能体分发的具体方案。

**与前一天对比：** 5 月 25 日，技能主要被讨论为记忆层和可复用知识文件。到了 5 月 26 日，同一底层载体则更明确地被当作可以训练、安装和变现的对象。

### 1.2 Harness 设计从概念走向治理与可运维性 🡕

第二个主要主题是，harness 工程不再只是画架构图，而开始聚焦控制点：策略在哪里执行、状态存放在哪里，以及当智能体拥有真实权限或要服务多个用户时，会在哪些地方出问题。最有代表性的帖子把研究语言与具体实现接口结合起来，例如 YAML 策略内核、基于 Postgres 的状态，以及可组合的记忆层。

[@_vmlops](https://x.com/_vmlops) [强调了](https://x.com/_vmlops/status/2059207888393138556)（215 个赞、8 条回复、15,069 次浏览、364 次收藏）将 Microsoft Agent Governance Toolkit 描述为一个确定性层：在工具调用真正发出前进行拦截，并提供 YAML 策略、身份机制、沙箱和防篡改日志。[AGT 仓库](https://github.com/microsoft/agent-governance-toolkit) README 明确将提示词层安全界定为非控制面；但最有实质内容的一条回复补充了一个重要限制：工具调用层面的强制执行看不到提示词中的恶意指令，也看不到输出里的敏感内容，因此团队仍需要独立的输入与输出防护。

[@dair_ai](https://x.com/dair_ai) [重新定义为](https://x.com/dair_ai/status/2059294269698199929)（59 个赞、10 条回复、3,530 次浏览、54 次收藏）把整个问题概括为“系统扩展”，认为如今智能体质量来自记忆、上下文构建、技能路由、编排、验证与治理，而不只是模型规模。论文配图之所以重要，是因为它直接点出了三个 harness 瓶颈——上下文治理、可信记忆和动态技能路由——并将它们与参考 harness CheetahClaws 联系起来；项目页面则将其描述为原生支持 Python 且与模型无关。

![系统扩展论文的第一页，将上下文治理、可信记忆和动态技能路由列为核心编排瓶颈](https://pbs.twimg.com/media/HJQVOX_bEAATe44.png)

[@Hey_Amiko](https://x.com/Hey_Amiko) [表示](https://x.com/Hey_Amiko/status/2059317515180757277)（9 个赞、190 次浏览）指出，OpenHermit 之所以存在，是因为一旦智能体系统超出单用户场景，本地文件、密钥和会话状态就会失控。[OpenHermit 网站](https://openhermit.ai/) 和 [仓库](https://github.com/HCF-STUDIOS/openhermit) 明确划出了边界：内部状态放在 PostgreSQL 中，外部状态放在每个智能体各自的沙箱中，同时还提供面向整个集群的技能与 MCP 服务器 rollout 命令。[@mattapperson](https://x.com/mattapperson) [发布了](https://x.com/mattapperson/status/2059011048355639477)（94 个赞、7 条回复、11,134 次浏览、120 次收藏）则以相似思路介绍了 Noetic，带有 [七个可组合原语](https://github.com/mattapperson/noetic) 和一种多层记忆模型，试图让上下文边界变得可读，而非神神秘秘。

**讨论洞察：** 回复最终收敛到同一个边界条件：光靠提示词不够。即便是偏乐观的帖子，也会被追问是否具备版本化策略、明确回滚、集中式状态，以及模型之外的确定性强制执行。

**与前一天对比：** 5 月 25 日的 harness 讨论仍以解读文章、架构图和资源地图为主。到了 5 月 26 日，讨论进一步下沉到运行时策略、集群运维，以及那些必须直接工程化解决的 harness 层瓶颈。

### 1.3 实时智能体开始拥有更快的语音回路和可视化前端 🡕

还有一个规模较小但很清晰的讨论簇，聚焦于后端回路足够快之后，智能体会“看起来、听起来”像什么。共同点并不是某个新模型本身，而是围绕既有智能体加上的封装层：更低延迟的对话推理、替代固定聊天面板的动态画布，以及无需替换整套栈就能增加视觉存在感的头像层。

[@kwindla](https://x.com/kwindla) [报道称](https://x.com/kwindla/status/2059300287689756962)（88 个赞、4 条回复、7,712 次浏览、56 次收藏）称，由 Cerebras 提供服务的 Kimi K2.6 可以在 500 毫秒内完成启用推理的语音智能体单轮交互。这一点很关键，因为推理延迟通常会让对话式智能体变得难以使用。相关的 [Cerebras 博客](https://www.cerebras.ai/blog/cerebras-kimi-k2-Enterprise) 声称其输出速度达到每秒 981 个 token，最终答案生成时间比官方 Kimi 端点快 29 倍；Kwindla 的回复则交代了实际技术栈：Pipecat Smart Turn、Nemotron 流式 ASR、Cerebras Kimi K2.6 和 Kyutai Pocket TTS。

[@pika_labs](https://x.com/pika_labs) [分享了](https://x.com/pika_labs/status/2059341240655814993)（128 个赞、18 条回复、6,985 次浏览）介绍了“生成式 UI”：一种由语音控制的界面，智能体每一轮都会生成新的 HTML 布局，而不是往固定外壳里填内容。相关的 [generative-ui README](https://github.com/Pika-Labs/Pika-Experiments/tree/main/generative-ui) 说明，这是一个仅限本地运行的原型，基于 OpenAI Realtime、Pika MCP 和可选的 Google Workspace 工具；回复则强调，它是有意保持粗糙的实验品，并非面向生产环境。

[@AiwithYasir](https://x.com/AiwithYasir) [放大了](https://x.com/AiwithYasir/status/2059350044172812527)（59 个赞、11,420 次浏览）介绍了 LiveAvatar 面向 LiveKit、Pipecat、Agora 和 VisionAgent 的插件接入路径。[LiveKit LiveAvatar 文档](https://docs.livekit.io/agents/models/avatar/plugins/liveavatar/) 将其描述为叠加在现有语音应用之上的 Python 头像会话，这也强化了当天更大的趋势：多模态存在感正作为当前智能体栈之外的一层封装被加上去，而不是被视作一套独立技术栈。

**讨论洞察：** 这些帖子默认核心智能体已经存在。如今的工作重点正转向延迟、视觉编排和存在感层，让同一个底层智能体更像在对话，而不再只是困在终端里。

**与前一天对比：** 5 月 26 日的语音与 UI 信号比 5 月 25 日更明显。讨论从泛泛的“语音智能体”热情，转向了关于低于 500 毫秒回路、动态画布和头像插件的具体主张。

## 2. 什么让人沮丧

### 仅靠提示词的安全方案，总会在最需要信任的时刻失灵

严重程度：高。[@RoundtableSpace](https://x.com/RoundtableSpace) [推荐了](https://x.com/RoundtableSpace/status/2059322421438545930)（50 个赞、14 条回复、37,788 次浏览）分享了一个用于安全审查的 Claude 单提示词方案，但回复几乎都指向同一个结论：[@Trish_DIntel](https://x.com/Trish_DIntel) 说模型无法可靠识别自己会中哪些招，[@OraclesTech](https://x.com/OraclesTech) 认为容易受提示词注入攻击的同一个模型，不可能靠自己保护自己，[@0xDawny](https://x.com/0xDawny) 则呼吁做代码审计，而不是修补提示词。AGT 线程则从反方向强化了同样的挫败感：[@_vmlops](https://x.com/_vmlops) [提到了](https://x.com/_vmlops/status/2059207888393138556)（215 个赞、8 条回复、15,069 次浏览、364 次收藏）提出了确定性的工具调用治理，但一条详细回复仍指出，团队需要独立的提示词与输出防护。[@tom_doerr](https://x.com/tom_doerr) [分享了](https://x.com/tom_doerr/status/2059378639750218161)（17 个赞、8 条回复、1,242 次浏览、22 次收藏）将 Cisco Skill Scanner 视作一种尽力而为的回应，而那个线程里也立刻有人追问：它能否捕捉多步骤数据外泄。人们目前的应对方式，是在模型之外叠加扫描器、策略内核和人工审查。值得投入建设：是。

### 单用户文件布局撑不过生产环境

严重程度：高。[@Hey_Amiko](https://x.com/Hey_Amiko) [写道](https://x.com/Hey_Amiko/status/2059317515180757277)（9 个赞、190 次浏览）指出，一旦智能体框架超出单用户场景，本地文件会四散、密钥会泄露，扩展最终变成“SSH 加祈祷”。[@dair_ai](https://x.com/dair_ai) [认为](https://x.com/dair_ai/status/2059294269698199929)（59 个赞、10 条回复、3,530 次浏览、54 次收藏）认为，真正的系统扩展瓶颈是上下文治理、可信记忆和动态技能路由；[@mattapperson](https://x.com/mattapperson) [发布了](https://x.com/mattapperson/status/2059011048355639477)（94 个赞、7 条回复、11,134 次浏览、120 次收藏）则将 Noetic 描述为带有显式记忆与控制流原语的方案，而不是依赖框架的隐藏行为。当前可见的权宜之计，是集中内部状态、隔离工作区，并为技能、密钥和 MCP 服务器增加 rollout 入口。值得投入建设：是。

### 推理仍让语音智能体显得迟缓

严重程度：中。[@kwindla](https://x.com/kwindla) [报道称](https://x.com/kwindla/status/2059300287689756962)（88 个赞、4 条回复、7,712 次浏览、56 次收藏）指出，推理模式带来的延迟是语音智能体的真实痛点，并把 Kimi K2.6 的速度视为其变得可用的原因。回复里的实际解决方式是栈级方案，而非单一模型方案：把 Pipecat Smart Turn、流式 ASR、快速推理和 TTS 一起调优，让用户不用干等模型“思考”。值得投入建设：是——这个痛点具体、可量化，而且直接关系到用户体验。

### 构建者正被术语泛滥拖慢进度

严重程度：中。[@adithya_s_k](https://x.com/adithya_s_k) [抱怨道](https://x.com/adithya_s_k/status/2058939792390545433)（55 个赞、5 条回复、2,855 次浏览、28 次收藏）指出，harness、scaffold、上下文工程和 agentic workflows 这些术语常被当作共识来使用，尽管它们在实践中往往指的不是同一件事。回复大多是在感谢那篇术语表帖子建立了基础标准，而不是反驳这一抱怨。虽然这不如安全和扩展问题尖锐，但它依然在消耗工具评估、上手培训和框架比较的时间。值得投入建设：也许。

## 3. 人们希望出现什么

### 面向开放式智能体工作的验证器

数据里最明确的需求，是一种能像基准测试评判代码那样，严格评判写作、设计、策略与安全行为的闸门。[@koylanai](https://x.com/koylanai) [写道](https://x.com/koylanai/status/2059113412278227328)（231 个赞、502 次收藏、55,849 次浏览）指出，验证是瓶颈，因为基准测试的自动评分器无法迁移到开放式工作；AGT 与 Roundtable 线程在安全层面也暴露出同样的缺口：团队可以拦截工具调用，但仍缺乏可靠的提示词、输入和输出评估器。[@tom_doerr](https://x.com/tom_doerr) [分享了](https://x.com/tom_doerr/status/2059378639750218161)（17 个赞、8 条回复、1,242 次浏览、22 次收藏）把 Skill Scanner 当作一个部分答案，但它自己的 README 也把它定义为尽力而为，而回复立刻追问多步骤数据外泄。机会：直接。

### 面向智能体集群的生产控制平面，而不只是单兵智能体

人们想要的是：一旦牵涉团队或客户，智能体依然能把状态、密钥、日程和技能管理得可操作、可运维。[@Hey_Amiko](https://x.com/Hey_Amiko) [描述了](https://x.com/Hey_Amiko/status/2059317515180757277)（9 个赞、190 次浏览）将 OpenHermit 视为单用户文件散落问题的解法，[@mattapperson](https://x.com/mattapperson) [将其定位为](https://x.com/mattapperson/status/2059011048355639477)（94 个赞、7 条回复、11,134 次浏览、120 次收藏）将 Noetic 视为一个带有显式原语和记忆层的可定制 harness，而 [@dair_ai](https://x.com/dair_ai) [认为](https://x.com/dair_ai/status/2059294269698199929)（59 个赞、10 条回复、3,530 次浏览、54 次收藏）则指出，如今真正的瓶颈已经是系统扩展。这是一个很务实的需求，而且市场上已经有可用的部分答案，因此机会确实存在，但竞争大概率会很激烈。机会：直接且竞争激烈。

### 面向专家技能的闭源分发与支付能力

Capafy 的发布主张之所以成立，只是因为底层需求本来就存在：人们已经在 Claude Code、Codex 和 OpenClaw 中做出了有价值的技能，但并不想把这些文件免费公开。[@Capafyai](https://x.com/Capafyai) [将其概括为](https://x.com/Capafyai/status/2059274292932878595)（373 个赞、227 条回复、254 条引用、119,630 次浏览）给出的答案是闭源 Run Online 技能，用户可以直接调用，也可以通过另一个智能体接入使用。这个需求非常务实，也直接与钱有关，而非停留在愿景层面：保护诀窍、开放结果，并让别人为访问权限付费。机会：直接且竞争激烈。

### 可插入现有语音栈的视觉存在感

这些多模态帖子指向了一个具体的产品愿望：加上一张脸或一块画布，而不用从头重建智能体。[@AiwithYasir](https://x.com/AiwithYasir) [放大了](https://x.com/AiwithYasir/status/2059350044172812527)（59 个赞、11,420 次浏览）将 LiveAvatar 定位为叠加在 LiveKit、Pipecat、Agora 和 VisionAgent 之上的一层，[@pika_labs](https://x.com/pika_labs) [展示了](https://x.com/pika_labs/status/2059341240655814993)（128 个赞、18 条回复、6,985 次浏览）则展示了由同一对话回路驱动的动态 HTML 界面。这个需求仍在成形，但已经具体到构建者开始打包插件和实验，而不只是空谈多模态智能体。机会：竞争性机会。

## 8. 要点总结

1. **技能正在成为一等产品界面。** Capafy 的市场发布和 Waza 可安装的工程习惯，都把技能视为持久资产，而不是个人提示词文件。（[Capafy](https://x.com/Capafyai/status/2059274292932878595), [Waza](https://x.com/HiTw93/status/2059075254954401855)）
2. **技能优化正从直觉走向纪律化训练。** SkillOpt 的有界编辑和留出闸门，再加上 Codex 的 `/goal` 实现模式，表明智能体行为开始像可复用工件一样被改进，而不是临时反复改提示词。（[SkillOpt 讨论](https://x.com/koylanai/status/2059113412278227328), [Codex 工作流](https://x.com/daniel_mac8/status/2059244838789218409)）
3. **如今，harness 才是质量与信任的决胜处。** CheetahClaws 论文明确把上下文治理、可信记忆和动态技能路由列为瓶颈，而 AGT 则把策略强制执行下沉到提示词层之下。（[系统扩展](https://x.com/dair_ai/status/2059294269698199929), [AGT](https://x.com/_vmlops/status/2059207888393138556)）
4. **仅靠提示词的安全建议正在失去公信力。** 安全相关线程里最强烈的反应不是兴奋，而是反驳：模型无法可靠审计自身的提示词注入弱点，这也让扫描器、策略内核和其他外部控制的需求持续高企。（[安全提示词讨论串](https://x.com/RoundtableSpace/status/2059322421438545930), [Skill Scanner](https://x.com/tom_doerr/status/2059378639750218161)）
5. **随着延迟下降，智能体构建者正把更多时间花在存在感与界面上。** 低于 500 毫秒的语音单轮交互、动态 HTML 布局和头像插件，都指向同一个下一步：让同一个智能体显得更快、更可视，也更面向人类用户。（[Kimi 语音栈](https://x.com/kwindla/status/2059300287689756962), [Pika Generative UI](https://x.com/pika_labs/status/2059341240655814993), [LiveAvatar](https://x.com/AiwithYasir/status/2059350044172812527)）
