# Twitter AI Agent - 2026-05-13

## 1. 大家在讨论什么

### 1.1 检索原生记忆取代静态上下文文件，成为主要优化目标 🡕

当天最强的一条主线，已经不再是“加更好的指令”，而是“从一开始就别加载无关记忆”。至少有六条不同内容汇聚到同一个抱怨上：静态 Markdown 记忆文件、整仓库反复重读，以及冷启动会话都在浪费令牌、掩盖规则，并迫使人们一遍遍重复说明。更受认可的替代方案是检索层、按影响范围选择上下文，以及能够跨多次运行持续积累的持久化工作区。

[@ghumare64](https://x.com/ghumare64) [认为](https://x.com/ghumare64/status/2054470602132492718)（10 个赞、6 条回复、13 次收藏、359 次浏览）指出，几乎所有主流编码智能体仍把记忆存放在始终加载的 Markdown 文件里，造成“常开式注入”、没有相关性排序，也没有衰减机制。他声称，其基于检索的 `agentmemory` 方案结合了 BM25、向量搜索、知识图谱遍历、RRF 融合、工具调用后钩子和衰减机制，在保持召回率的同时，将包含 240 条观察记录的上下文加载量从 22,000 多个令牌降到 1,900 个。

![agentmemory 截图，展示了面向编码代理的检索优先记忆、本地存储，以及“相比预先加载完整的 CLAUDE.md 风格记忆可减少 92% token”的说法](https://pbs.twimg.com/media/HILyICMX0AAZuWL.jpg)

[@DailyDoseOfDS_](https://x.com/DailyDoseOfDS_) [报道](https://x.com/DailyDoseOfDS_/status/2054494541470969969)（34 个赞、3 条回复、34 次收藏、3,959 次浏览）表示，将 InsForge Skills + CLI 作为 Claude Code 的上下文层后，有一条工作流的令牌消耗从 1,040 万降至 370 万，错误数也从 10 个降为 0。公开的 [InsForge 仓库](https://github.com/InsForge/InsForge) 将其描述为一个面向智能体编程的一体化 TypeScript 后端平台，提供 MCP 和 CLI/Skills 接口，因此这条推文并不只是笼统地说一句“把提示词写得更好”。

[@hasantoxr](https://x.com/hasantoxr) [宣布](https://x.com/hasantoxr/status/2054592863200280762)（148 个赞、15 条回复、47 次收藏、36,444 次浏览）发布了 holaOS Beta 0.1，作为“智能体重置问题”的解决方案：每个重复性任务都会拥有一个永久工作区，内含记忆、规则、历史记录和子智能体。他后续回复里的信息才是关键证据：价值不在第 1 次运行，而在第 2、第 3 和第 10 次运行——那时工作区会开始持续积累，而不是逼着用户反复解释语气风格、信息来源和检查清单。

[@filicroval](https://x.com/filicroval) [分享了](https://x.com/filicroval/status/2054617233196798466)（1 个赞、1 条回复、1 次收藏、186 次浏览）介绍了 `code-review-graph`，这是一个基于 tree-sitter 和 SQLite 的影响范围选择器，会在智能体读取文件前追踪调用方、依赖方和测试。相应的公开 [GitHub 仓库](https://github.com/tirth8205/code-review-graph) 显示，该项目大约有 1.64 万颗星，说明这种“只读真正相关内容”的模式，已经获得了超出单条推文的真实吸引力。

![code-review-graph 截图，展示了通过仅追踪与代码审查变更相关的文件和测试，将 token 数从 13,205 降至 1,928](https://pbs.twimg.com/media/HIN3U_qWIAAYkuN.jpg)

**讨论观察：** 回复里并没有人为旧的“先把所有内容都加载进来”模式辩护。质疑更集中在一点：相比普通的 Markdown 记忆文件，检索系统是否真的能更好地处理并发写入、版本控制和持久化语义。

**与前一天对比：** 5 月 12 日的重点是 CLAUDE.md 文件、品牌上下文文件夹，以及基于文件的 skills 这类手工上下文基础设施。到了 5 月 13 日，讨论又往前推进了一步，转向检索、衰减、影响范围选择，以及试图让上下文自行完成筛选、而非始终常开的工作区。

### 1.2 编排从框架讨论走向面向用户的工作区 🡕

第二个内容集群显示，智能体编排正在从架构图变成产品层面的能力。重点不只是把多个智能体串起来，而是给它们共享环境、审批、回滚、可审计性和可复用上下文，让非工程师也能参与其中。

[@NotionHQ](https://x.com/NotionHQ) [推出了](https://x.com/NotionHQ/status/2054601077346246695)（176 个赞、10 条回复、14 次引用、17,476 次浏览）展示了 Notion 中的智能体编排，并给出一个具体示例：一张 Decagon 支持工单被路由给编码智能体，智能体提出修复方案，团队则直接在 Notion 内审核。后续回复又释放出更强信号：Notion 还在构建 External Agents API，并点名了首发集成对象，包括 Claude、OpenAI Codex、Cursor、Warp、Cognition、Flora、Amplitude、Console 和 Serval。

[@cursor_ai](https://x.com/cursor_ai) [宣布](https://x.com/cursor_ai/status/2054651529315889645)（106 个赞、4 条回复、11 次收藏、6,198 次浏览）介绍了面向云端智能体和自动化任务的多仓库环境。真正更重要的是回复串里的信息，而不是标题本身：每个环境都有版本历史、回滚、审计日志，以及受限的外部访问和密钥管理，使“智能体环境”更接近受治理的基础设施，而不是一次性的沙盒。

[@charlieholtz](https://x.com/charlieholtz) [表示](https://x.com/charlieholtz/status/2054345027082657957)（400 个赞、26 条回复、39 次收藏、24,952 次浏览）表示，Conductor 已将默认编码执行框架切换为搭载 GPT-5.5 的 Codex。回复中的使用层面细节，则为这一工具选择信号补上了更多操作性背景：资深用户要求支持多窗口布局，并报告了长会话中的滚动位置重置问题，并提到 `/goal` 线程有时会在完成后卡住，这表明如今人们评判编排产品时，工作区体验与模型质量同样重要。

[@DataScienceDojo](https://x.com/DataScienceDojo) [将其定义为](https://x.com/DataScienceDojo/status/2054290556549837068)（3 个赞、7 个收藏、984 次浏览）并未把“Agentic OS”当作又一个框架名称，而是将其定义为代理之上的协调层：负责路由工作、决定每个代理知道什么、追踪哪些内容会被记住，以及处理失败。这一框架与 [Agno](https://github.com/agno-agi/agno) 相契合；[@ashpreetbedi](https://x.com/ashpreetbedi) [展示了](https://x.com/ashpreetbedi/status/2054678134147203535)（8 个赞、2 条回复、1 次引用、485 次浏览）将其描述为托管工作区的基础，涵盖上下文、工具、权限、记忆、评审循环和领域专用技能。

![Agentic OS 架构幻灯片，展示了位于代理之上的协调层，包括编排器职责以及工作记忆、情景记忆和语义记忆等持久记忆类型](https://pbs.twimg.com/media/HIJOXICXIAAskqN.jpg)

**讨论洞察：** 这一主题中最耐人寻味的细节，在于构建者把具体精力花在了哪里：审批、回滚、作用域受限的密钥，以及审计历史。市场需要的是控制界面，而不只是更强的自主性。

**与前一天的比较：** 5 月 12 日的讨论更多集中在 harness 理论和教育资源上；到了 5 月 13 日，这些理论已转化为 Notion、Cursor、Conductor 和托管代理平台中的具体产品功能。

### 1.3 技能市场继续扩张，但信任转向运行时质量和第一方支持 🡕

技能生态仍在扩张，但讨论的基调变了。规模本身已不再足够；话题开始转向技能如何排序、归谁所有、哪些运行时能安全执行这些技能，以及厂商自身是否也愿意推出第一方技能。

[@milesdeutscher](https://x.com/milesdeutscher) [推广了](https://x.com/milesdeutscher/status/2054310749884002348)（139 个赞、21 条回复、282 个收藏、12,739 次浏览）发布了一个他称为“彻底改变游戏规则”的技能市场。其公开的 [SkillsMP 网站](https://skillsmp.com/) 显示，该市场索引了超过 120 万条来自 GitHub 的 SKILL.md 条目，会过滤掉 star 数低于 2 的仓库，并支持 Claude Code、Codex CLI 和 ChatGPT 风格的安装方式。但真正的信号来自回复区：用户立刻要求看到真实可用的示例、更严格的质量控制，以及更清晰的维护状态信号，而不只是更大的原始数量。

[@cgtwts](https://x.com/cgtwts) [总结道](https://x.com/cgtwts/status/2054592065259122922)（24 个赞、4 条回复、5 个收藏、2,887 次浏览）介绍了新近开源的 Cline SDK：这是一个可复用的运行时，可为 CLI、VS Code、JetBrains 和 Kanban 提供底层支持，并支持代理团队、插件、MCP、cron jobs 和消息连接器。这一点之所以重要，是因为它将讨论从“下载更多技能”转向了“标准化技能之下的底层 harness”。

[@KayvonJafar](https://x.com/KayvonJafar) [指出](https://x.com/KayvonJafar/status/2054637807105421557)（1 个赞、1 个收藏、26 次浏览）提到，Obsidian 的 CEO 亲自为该产品编写了 5 个官方技能：`obsidian-markdown`、`obsidian-bases`、`json-canvas`、`obsidian-cli` 和 `defuddle`。这与市场规模传递的是另一类信号：第一方厂商开始以官方方式界定代理应如何使用自家的工具。

![Obsidian README 截图，列出了五项官方代理技能，分别用于 markdown、bases、JSON canvas、CLI 任务管理，以及将网页清理为 markdown](https://pbs.twimg.com/media/HIN0w5FXQAAGjml.jpg)**讨论洞察：** 围绕技能的讨论反复回到同一个问题：供给充足并不难，难的是建立信任。目录规模、开放运行时和第一方技能都很重要，但排序、维护和安全执行仍然没有解决。

**与前一天相比：** 5 月 12 日重点是厂商自编技能以及首批市场界面的出现。5 月 13 日则把叙事扩展到搜索规模的发现机制和开放运行时层，同时，对质量的质疑也明显更尖锐了。

### 1.4 安全与治理成为智能体落地的准入门槛 🡕

第四个重要主题是，团队已不再把智能体风险当作未来才需要担心的问题。他们正把安全、沙箱、治理，甚至 Cookie 横幅处理，视为横亘在亮眼演示与可部署系统之间的真正障碍。

[@Dinosn](https://x.com/Dinosn) [提到了](https://x.com/Dinosn/status/2054635242632171826)（21 个赞、17 个收藏、1,051 次浏览）腾讯的 [AI-Infra-Guard](https://github.com/Tencent/AI-Infra-Guard)，这是一个公开的 Python 项目，在 GitHub 上约有 3.7k 个 star，明确以扫描智能体、技能、MCP 集成、基础设施和越狱行为为目标。值得注意的是，“Skills Scan”和“MCP scan”如今已成了产品化名词，而不再只是模糊的安全愿景。

[@neil_xbt](https://x.com/neil_xbt) [放大传播了](https://x.com/neil_xbt/status/2054446543063638070)（47 个赞、13 条回复、2,233 次浏览）Simon Willison 认为，TDD 如今已成为 AI 智能体的可靠性框架，而未经过沙箱隔离的智能体距离灾难只差一起严重事故。回复很快转向隔离层和提示注入，这表明讨论已从抽象的安全话题转向运营层面的隔离与控制。

[@Haleeeemahh](https://x.com/Haleeeemahh) [描述了](https://x.com/Haleeeemahh/status/2054495925502894343)（45 个赞、33 条回复、635 次浏览）有人提到首个因在缺乏安全知识的情况下进行 vibe coding 而被黑的应用，并以 bankrbot 和 OpenClaw 资金被抽干的案例作为背景。处在技术栈另一端的是，[@dongxinguo](https://x.com/dongxinguo) [报道](https://x.com/dongxinguo/status/2054660979879788670)（2 条回复、12 次浏览）提到某浏览器智能体连续四次失败，问题不在定价或推理，而在 Cookie 横幅，这也催生了新的 [browser-skills](https://github.com/bettyguo/browser-skills) 仓库，用确定性方案处理网页摩擦。

[@ingliguori](https://x.com/ingliguori) [将其概括为](https://x.com/ingliguori/status/2054536395260109091)（10 个赞、2 条回复、4 个收藏、127 次浏览）则体现了同一问题在企业场景中的版本：可见性、控制、问责，以及对“有哪些智能体在运行、它们能访问什么、谁对结果负责”等问题给出明确答案。

![治理信息图，展示了从代理实验走向受治理的规模化转变，强调可见性、控制力和问责性是企业的核心需求](https://pbs.twimg.com/media/HIMt9sXXsAAjJL3.jpg)

**讨论洞察：** 瓶颈已不再只是抵御越狱。真正的瓶颈是围绕智能体的整套运行层：测试、沙箱、扫描、审批、审计追踪，以及对那些乏味却依然会让自动化失灵的网页边角问题进行确定性处理。

**与前一天相比：** 5 月 12 日更聚焦于自主支付中的钱包护栏和提示注入风险。5 月 13 日则把问题扩展到技能供应链、编码智能体安全、浏览器失效模式和企业治理。

## 2. 什么让人们感到挫败

### 静态上下文臃肿、陈旧，而且难以排序

被反复提及的最大挫败感是，编码智能体在只做少量工作之前，仍要先读取过多无关的历史内容。[@dunik_7](https://x.com/dunik_7) [认为](https://x.com/dunik_7/status/2054502522895716627)（43 个赞、13 条回复、39 个收藏、4,130 次浏览）称，团队正在花钱让模型反复通读整个代码仓库，只为修几行代码，而 [@ghumare64](https://x.com/ghumare64) [表示](https://x.com/ghumare64/status/2054470602132492718)（10 个赞、6 条回复、13 次收藏、359 次浏览）指出，静态 Markdown 记忆会形成持续在线的注入，既没有相关性排序，也不会自然衰减。针对 [@dunik_7](https://x.com/dunik_7/status/2054502522895716627) 的一条回复用一句话点出了这种失效模式：一则陈旧的权宜说明一直留在上下文里，模型“一路照做，直到把自己带进坑里”。严重程度：高。最明确的应对办法是检索系统和爆炸半径控制，而不是换成更便宜的模型。

### 生产试点卡在治理和工作区体验的边角问题上

第二个令人沮丧的问题是，哪怕演示看起来已经很有说服力，智能体试点仍会在运营细节上失败。[@TatTvamAsea](https://x.com/TatTvamAsea) [分享了](https://x.com/TatTvamAsea/status/2054373196023967949)（2 条回复、12 次浏览）分享了一张统计卡片，称 AI 智能体试点进入生产环境的失败率高达 88%，其中评估缺口、治理摩擦和模型可靠性被列为最主要的阻碍。信息流也以更具体的产品形态印证了这一点：[@charlieholtz](https://x.com/charlieholtz) [转而使用了](https://x.com/charlieholtz/status/2054345027082657957)（400 个赞、26 条回复、39 次收藏、24,952 次浏览）将 Conductor 默认切换为 Codex，但回复里立刻出现了对长会话 bug 和工作区管理问题的抱怨；针对 [@NotionHQ](https://x.com/NotionHQ/status/2054601077346246695) 的一条回复则警告说，产品风险在于“AI 漂移”，而不只是缺少集成。严重程度：高。开发者正在用审批、回滚、审计日志和更严格的环境控制来弥补这些问题。

![统计卡片称，AI agent 试点项目进入生产环境的失败率高达 88%，其中评估缺口、治理摩擦和模型可靠性被列为三大主要阻碍因素](https://pbs.twimg.com/media/HIKZSutWoAAl54Z.png)

### 安全成熟度落后于 vibe coding 的速度

安全方面的抱怨都很具体，不是泛泛而谈。[@Haleeeemahh](https://x.com/Haleeeemahh) [表示](https://x.com/Haleeeemahh/status/2054495925502894343)（45 个赞、33 条回复、635 次浏览）提到，自己第一个用 vibe coding 做出的应用就被黑了，并把这种担忧与近期的 agent-drain 事件联系起来。[@neil_xbt](https://x.com/neil_xbt) [放大传播了](https://x.com/neil_xbt/status/2054446543063638070)（47 个赞、13 条回复、2,233 次浏览）提到了 Simon Willison 的判断：未经过沙箱隔离的智能体距离出事，只差一次严重事故；而 [Tencent 的 AI-Infra-Guard](https://github.com/Tencent/AI-Infra-Guard) 经由 [@Dinosn](https://x.com/Dinosn) [在一则短帖中](https://x.com/Dinosn/status/2054635242632171826)（21 个赞、17 次收藏、1,051 次浏览）曝光，也解释了为什么市场正把技能、MCP 集成和智能体运行时变成明确的扫描目标。严重程度：高。已观察到的应对办法包括 TDD、容器化隔离和专门的红队测试层。

### 浏览器智能体仍会被网站的常规界面元素卡住

最清楚的一类底层故障报告来自 [@dongxinguo](https://x.com/dongxinguo) [并表示](https://x.com/dongxinguo/status/2054660979879788670)（2 条回复、12 次浏览）：一个 AI 智能体四次都没能订到机票，原因不是价格或规划，而是 Cookie 横幅。随后出现了新的 [browser-skills](https://github.com/bettyguo/browser-skills) 包，提供了用于关闭 Cookie 横幅、处理无限滚动、操作日期选择器等浏览器摩擦点的确定性方案。严重程度：中等，但很有可操作性。这个方向值得投入，因为抱怨点很窄、反复出现，而且很容易在真实网站上验证。

## 3. 人们希望出现什么

### 能自行检索、排序并持续演化的记忆

最明确的实际需求，是让记忆别再像静态转储文件，而要像一个自适应系统那样工作。[@ghumare64](https://x.com/ghumare64) [介绍了](https://x.com/ghumare64/status/2054470602132492718)（10 个赞、6 条回复、13 次收藏、359 次浏览）详细展示了这种失效模式，[@hasantoxr](https://x.com/hasantoxr) [介绍了](https://x.com/hasantoxr/status/2054592863200280762)（148 个赞、15 条回复、47 次收藏、36,444 次浏览）给出了“可不断累积的工作区”这一产品化版本，而 [LongMemEval-V2](https://xiaowu0162.github.io/longmemeval-v2/) 则用 500 条轨迹、1.15 亿 token 的记忆测试，把这种需求变成了可量化指标。[@jiqizhixin](https://x.com/jiqizhixin) [新增了](https://x.com/jiqizhixin/status/2054610120957628469)（3 个赞、2 个收藏、198 次浏览）提出了一个互补视角：终端代理需要的是能够学会忽略什么的压缩规则，而不只是更大的上下文窗口。机会：直接。虽然已经有一些局部答案，但信息流仍显示，实验性检索系统与团队愿意作为默认基础设施来信任的东西之间，依然存在明显鸿沟。

### 具备质量信号、所有权和分析能力的技能生态

人们要的并不是抽象意义上更多的技能，而是更好的技能信任与管理方式。[@milesdeutscher](https://x.com/milesdeutscher) [带来了](https://x.com/milesdeutscher/status/2054310749884002348)（139 个赞、21 条回复、282 个收藏、12,739 次浏览）让一个收录超过百万项技能的市场获得了高度关注，但回复很快就追问排名、维护，以及是否真有证据证明这些东西有效。另一端则是 [@KayvonJafar](https://x.com/KayvonJafar) [重点介绍了](https://x.com/KayvonJafar/status/2054637807105421557)（1 个赞、1 个收藏、26 次浏览）中的 Obsidian 官方技能，以及 [@Tiny_Fish](https://x.com/Tiny_Fish) [展示了](https://x.com/Tiny_Fish/status/2054380934477287876)（9 个赞、1 条回复、2 个收藏、129 次浏览）中由代理自行编写新技能。机会：竞争性。发现机制已经存在，但信任、所有权和质量保障仍然支离破碎。

### 具备权限、审批和审计追踪的托管工作区

编排类帖文背后的情绪诉求和实际诉求，都是希望有一个能让代理开展工作、又不至于失控的地方。[@NotionHQ](https://x.com/NotionHQ) [实现了](https://x.com/NotionHQ/status/2054601077346246695)（176 个赞、10 条回复、14 次引用、17,476 次浏览）通过把路由和审批放进熟悉的工作区，让这一需求对业务团队变得清晰易懂；而 [@cursor_ai](https://x.com/cursor_ai) [推动了](https://x.com/cursor_ai/status/2054651529315889645)（106 个赞、4 条回复、11 个收藏、6,198 次浏览）则指向具备回滚、审计日志和作用域受限密钥的治理型环境。[@ashpreetbedi](https://x.com/ashpreetbedi) [总结了](https://x.com/ashpreetbedi/status/2054678134147203535)（8 个赞、2 条回复、1 次引用、485 次浏览）则直接给出了人们想要的整套组合：在一个托管工作区中集成上下文、工具、权限、记忆、审查闭环和领域专属技能。机会：直接。市场信号之所以强烈，是因为需求关乎协同与问责，而不是新奇感。

![托管式智能体工作区仪表盘，单一控制平面中展示了智能体、团队、追踪、记忆、审批和控制功能](https://pbs.twimg.com/media/HIOuzamawAApC5i.jpg)

### 代理无需每次会话都重新学习的确定性浏览器原语

这一需求虽然很窄，但异常清晰。[@dongxinguo](https://x.com/dongxinguo) [报道称](https://x.com/dongxinguo/status/2054660979879788670)（2 条回复、12 次浏览）提到，一个旅行预订代理光是在 Cookie 横幅上就失败了四次，随后将确定性的浏览器操作配方封装进 [browser-skills](https://github.com/bettyguo/browser-skills)。这指向一个实际缺口：许多浏览器代理的失败根本不是“AI 推理”问题，而是反复出现的界面杂务，本应一次解决、反复复用。机会：直接，但仍处于萌芽阶段。

### 多智能体研究点出了“旁观者效应”

[@dair_ai](https://x.com/dair_ai) [强调了](https://x.com/dair_ai/status/2054547408529530980)（25 个赞、3 条回复、39 次收藏、2,479 次浏览）提到一篇论文，认为多智能体系统即使在内部算出了正确答案，也仍可能为了与群体保持一致而压制这一答案。推文称，该研究在 GAIA、SWE-bench 和 Multi-Challenge 上运行了 22,500 条确定性轨迹，并将这种失败模式命名为“主权鸿沟”（Sovereignty Gap）。这一点之所以重要，是因为它用证据对当天更广泛的编排乐观情绪提出了反驳：更多智能体未必会自动提升推理能力，反而可能引入新的失败模式。

## 7. 机遇在哪里

**[+++］ 原生支持检索的记忆与上下文排序** — 当天最强烈且反复出现的需求。`agentmemory`, ［InsForge](https://github.com/InsForge/InsForge)、[code-review-graph](https://github.com/tirth8205/code-review-graph)、[LongMemEval-V2](https://xiaowu0162.github.io/longmemeval-v2/)，以及 TACO 都指向同一个缺口：编码代理和终端代理仍在过时或无关的上下文上浪费过多预算和注意力。这个判断很有说服力，因为证据同时来自用户挫败感、可运行原型和公开基准测试。

**[+++］ 面向长时间运行智能体系统的安全与治理** — ［AI-Infra-Guard](https://github.com/Tencent/AI-Infra-Guard)、[browser-skills](https://github.com/bettyguo/browser-skills)、Microsoft Agent Framework 1.0、Notion 和 Cursor 都共同指向同一个现实：要把代理真正交付出去，就需要扫描、审批、回滚、范围受限的密钥，以及确定性的回退方案。这个判断很有说服力，因为这种需求同时出现在独立开发者的痛点、企业治理话语和公开安全工具中。

**[++］ 基于信任评分的技能发现与第一方技能分发** — ［SkillsMP](https://skillsmp.com/)、Obsidian 官方技能集、[Cline](https://github.com/cline/cline) 运行时，以及 [TinySkill](https://github.com/tinyfish-io/tinyfish-cookbook/tree/main/skills/tinyskill) 表明，技能层现在既有供给，也有基础设施。缺失的环节是排序、维护可见性、归属权和安全执行，因此这是一个中等强度但竞争激烈的机会。

**[++］ 面向非工程团队的托管式智能体工作区** — Notion, Cursor, ［Agno](https://github.com/agno-agi/agno)，以及 holaOS 都在暗示同一类产品：具备上下文、权限、审查闭环和操作历史的共享代理环境。之所以判断为中等机会，是因为需求显而易见且覆盖面广，但已有许多参与者开始围绕这一方向布局。

**[+] 确定性的浏览器基础能力** —— 浏览器技能这种模式仍处于早期，但底层需求很明确，也很容易测试：代理不该在每次会话里都从头重新摸索 Cookie 横幅、无限滚动、日期选择器或登录流程。之所以说它仍处于新兴阶段，是因为目前公开需求还比较窄，但这个痛点非常具体，而且只要代理接触开放网络，就很可能反复出现。
