# Twitter AI Agent - 2026-11-06

## 1. What People Are Talking About

### 1.1 Shared context is turning into governed team memory (→)

Posts connect agent usefulness to what it can retrieve, what teammates can reuse, and whether old decisions can be corrected. The evidence ranges from an enterprise product announcement to practitioners' memory workflows; it does not establish broad adoption.

[@levie](https://x.com/levie) [described](https://x.com/levie/status/2118498574497665316) (74 likes, 11 retweets, 33 replies, 10,555 views, 31 bookmarks) Box and NVIDIA combining lexical and semantic retrieval for enterprise content, with Box access controls and governance. His post frames contracts, research, plans, and other documents as context agents need to find before taking action.

[@dabit3](https://x.com/dabit3) [argued](https://x.com/dabit3/status/2118821545879675356) (54 likes, 5 retweets, 10 replies, 2,124 views, 22 bookmarks) that cloud coding-agent sessions should retain shared history, so a teammate or a later session can continue work instead of rebuilding context. He also points to sharing how people break down problems as a benefit of multiplayer engineering.

[@unknownnode404](https://x.com/unknownnode404) [outlined](https://x.com/unknownnode404/status/2118673587678630160) (36 likes, 5 replies, 713 views, 28 bookmarks) a six-pass memory workflow: intake, atomize, link, verify, write a daily note, and test whether a fresh session can answer from it. The distinction is between preserving sources and maintaining small, linked notes that can be checked.

[@alex09x_dev](https://x.com/alex09x_dev) [described](https://x.com/alex09x_dev/status/2118605812218376272) (9 likes, 12 replies, 515 views, 1 bookmark) KYB, a Git-backed shared memory with versions, retractions, and separate current and historical views, after agents repeatedly rediscovered rejected decisions. In the thread, [@hey_its_pc](https://x.com/hey_its_pc) [asked](https://x.com/hey_its_pc/status/2118625696012767382) (6 views) for authorized teammates to be able to retract a bad note; [@alex09x_dev](https://x.com/alex09x_dev) [replied](https://x.com/alex09x_dev/status/2118628548118474884) (5 views) that authorized writers can correct entries while Git preserves searchable history.

**Discussion insight:** Enterprise context also raises least-privilege questions. [@martinvars](https://x.com/martinvars) [noted](https://x.com/martinvars/status/2118506363622232282) (1 like, 128 views) that medical agents need the right labs, medications, and prior notes with permissions and audit trails; [@FixChatWill](https://x.com/FixChatWill) [asked](https://x.com/FixChatWill/status/2118500374860660811) (42 views) whether Box retrieval uses its own agent permissions or inherits the calling user's access.

**Comparison to prior day:** Shared agent context had already appeared in OpenClaw Multiplayer and Perplexity Teammates announcements. Today's posts add enterprise access policy and explicit correction/history mechanisms to that collaboration theme: [@openclaw](https://x.com/openclaw) [introduced](https://x.com/openclaw/status/2118404891911864536) (40 likes, 3 retweets, 6 replies, 5,275 views, 13 bookmarks) its shared agent and context, while [@ChrisUniverse](https://x.com/ChrisUniverse) [shared](https://x.com/ChrisUniverse/status/2118412806554784195) (27 likes, 2 retweets, 7 replies, 2,079 views, 7 bookmarks) Perplexity Teammates screenshots.

### 1.2 Parallel-agent bottlenecks move to execution, coordination, and cost (→)

The practical posts focus less on spawning agents than on isolating their work, merging changes, and checking whether extra orchestration is worth its cost.

[@pauliusztin_](https://x.com/pauliusztin_) [proposed](https://x.com/pauliusztin_/status/2118757809269653788) (13 likes, 1 retweet, 10 replies, 305 views, 3 bookmarks) remote sandboxes with separate processes, memory, and filesystems so a local machine can remain a thin orchestrator. In reply to a question about agents changing the same repository, [@cyberogz](https://x.com/cyberogz) [suggested](https://x.com/cyberogz/status/2118769087450853432) (4 views) a clone and branch per sandbox at a pinned commit, with a merge queue rebasing changes one at a time.

[@stretchcloud](https://x.com/stretchcloud) [recounted](https://x.com/stretchcloud/status/2118421087696667083) (4 likes, 6 replies, 193 views) a single game-building anecdote: a 20-minute, $9 solo run did not respond to input, while a planner, generator, and evaluator took six hours and $200 but worked. This is an author's account of another author's comparison, not a controlled benchmark; the accompanying point is that correctness checks and permissions add cost as well as reliability.

[@AzianMike](https://x.com/AzianMike) [summarized](https://x.com/AzianMike/status/2118767826962207208) (15 likes, 3 retweets, 3 replies, 582 views, 2 bookmarks) October updates to the Agents API, including automatic action review, scheduled work, changing tools mid-session, sandbox snapshots or prewarming, and budget controls. The post lists shipped and experimental features but gives no usage or performance results.

[@ConsciousRide](https://x.com/ConsciousRide) [mapped](https://x.com/ConsciousRide/status/2118420880804196522) (16 likes, 3 retweets, 8 replies, 508 views, 15 bookmarks) ten harness concerns around the agent loop, including context, permissions, retries, sandboxing, completion checks, traces, evaluation, and recovery. This same checklist was already covered in the previous day's report, so it is a carry-over rather than a new signal.

**Comparison to prior day:** The previous day's report included a 100-task benchmark comparing coding-agent score gains and costs. Today's new evidence is more anecdotal, but it similarly contrasts extra orchestration cost with successful completion: [@HelloSurgeAI](https://x.com/HelloSurgeAI) [reported](https://x.com/HelloSurgeAI/status/2118109425697173658) (14 likes, 1 retweet, 9 replies, 1,022 views, 8 bookmarks) the earlier benchmark.

### 1.3 Agent trust and coordination extend beyond a single runtime (→)

Two research and standards directions address different parts of multi-agent behavior: how websites recognize delegated agents, and whether agent swarms can learn how to coordinate rather than receive fixed roles.

[@worldnetwork](https://x.com/worldnetwork) [introduced](https://x.com/worldnetwork/status/2118767624419160505) (34 likes, 6 retweets, 2 replies, 5,498 views, 3 bookmarks) the Trusted Agent Delegation framework with Cloudflare. Cloudflare's [whitepaper](https://blog.cloudflare.com/trusted-agent-delegation/) frames agents as intermediaries that can hide which user they represent, complicating access rules and accountability; the TAD [site](https://trustedagentdelegation.org/) describes a standards collaboration, not a finished protocol.

[@scottgeng00](https://x.com/scottgeng00) [shared](https://x.com/scottgeng00/status/2118768807573594357) (15 likes, 804 views) early work on training multi-agent systems with less hand-engineering. The linked [s³ research site](https://scalingswarms.com/) reports asynchronous swarms with no prescribed roles and results on two constrained tasks; its gains are the authors' reported experimental results, not evidence that the method generalizes to production agents.

**Comparison to prior day:** The previous report emphasized fixed harness structures and evaluation. Today's set adds a web-level delegation standards effort and an experimental approach that tries to learn coordination itself.

## 2. What Frustrates People

### Agents can repeat rejected decisions

**Severity: Medium; prevalence: one direct report.** [@alex09x_dev](https://x.com/alex09x_dev) [said](https://x.com/alex09x_dev/status/2118605812218376272) (9 likes, 12 replies, 515 views, 1 bookmark) agents kept rediscovering decisions the team had already rejected. The proposed workaround is versioned shared memory with retractions and current-versus-historical views; replies also raise who can correct a note and how historical context should be gated. This is a concrete team problem, but not a prevalence measure.

### Agent access can be too broad or hard to attribute

**Severity: High for restricted data; prevalence: not measured.** [@levie](https://x.com/levie) [described](https://x.com/levie/status/2118498574497665316) (74 likes, 11 retweets, 33 replies, 10,555 views, 31 bookmarks) enterprise retrieval under access controls, while a reply asks whether an agent gets its own permissions or inherits the caller's full access [@FixChatWill](https://x.com/FixChatWill) [asked](https://x.com/FixChatWill/status/2118500374860660811) (42 views). Cloudflare's [TAD whitepaper](https://blog.cloudflare.com/trusted-agent-delegation/) identifies user attribution, policy circumvention, and accountability as website-side problems when agents act as intermediaries. These are product and standards concerns, not a count of incidents.

### Parallel work needs repository coordination

**Severity: Medium when agents share a codebase; prevalence: one discussion.** A reply to [@pauliusztin_](https://x.com/pauliusztin_) [asked](https://x.com/Submarine_light/status/2118766312830947376) (4 views) how remote sandboxes avoid stepping on one another's changes. Another reply proposed isolated clones and branches at pinned commits with a sequential merge queue [@cyberogz](https://x.com/cyberogz) [suggested](https://x.com/cyberogz/status/2118769087450853432) (4 views). The thread offers a design response, not evidence that the workflow has been tested at the stated scale.

### Extra verification can raise cost sharply

**Severity: Medium in one anecdote; prevalence: unknown.** [@stretchcloud](https://x.com/stretchcloud) [recounted](https://x.com/stretchcloud/status/2118421087696667083) (4 likes, 6 replies, 193 views) a solo run that cost $9 but produced a nonfunctional game, compared with a $200 planner-generator-evaluator run that worked. The author attributes the comparison to another person's reading of company writeups; it is not a controlled benchmark. It is still a concrete reminder that orchestration and verification should be evaluated against successful outcomes, not spend alone.

## 6. New and Notable

### Learned swarm coordination reports task-specific gains

[@scottgeng00](https://x.com/scottgeng00) [pointed to](https://x.com/scottgeng00/status/2118768807573594357) (15 likes, 804 views) the s³ study, whose [site](https://scalingswarms.com/) reports 93% held-out success for four agents on an information-aggregation task, versus 35% for imitation and 13% with individual rewards. It also reports more than 25 times as many solved problems as the strongest baseline with eight agents on that task. The authors use Qwen3 0.6B and 1.7B models and two constrained tasks, so these results do not establish production performance.

### Trusted Agent Delegation frames a standards problem

[@worldnetwork](https://x.com/worldnetwork) [announced](https://x.com/worldnetwork/status/2118767624419160505) (34 likes, 6 retweets, 2 replies, 5,498 views, 3 bookmarks) the TAD collaboration with Cloudflare. The [whitepaper](https://blog.cloudflare.com/trusted-agent-delegation/) names identity, accountability, and machine-readable site policies as gaps, and discusses existing mechanisms such as Web Bot Auth, MOLE, and OAuth. TAD's [site](https://trustedagentdelegation.org/) describes an upcoming collaboration, not a deployed universal standard.

### Git storage is being tested against agent concurrency

[@github](https://x.com/github) [claimed](https://x.com/github/status/2118830274431873379) (6 likes, 2 retweets, 3 replies, 2,430 views, 3 bookmarks) that internal tests of its new Git storage architecture supported 5,000 concurrent agents and 7,200 pushes per second while serving read traffic. The post frames this as an internal test; it does not provide public methodology or independent verification.

## 8. Takeaways

1. **Agent context needs permission boundaries and accountability, not only retrieval.** Box's announcement and the TAD whitepaper approach this from enterprise search and website delegation respectively [@levie](https://x.com/levie) [described](https://x.com/levie/status/2118498574497665316) (74 likes, 11 retweets, 33 replies, 10,555 views, 31 bookmarks); [@worldnetwork](https://x.com/worldnetwork) [announced](https://x.com/worldnetwork/status/2118767624419160505) (34 likes, 6 retweets, 2 replies, 5,498 views, 3 bookmarks).
2. **Memory work is about maintaining and correcting knowledge across sessions.** KYB's author describes versions and retractions, while another post lays out a source-verification and answer-test workflow [@alex09x_dev](https://x.com/alex09x_dev) [described](https://x.com/alex09x_dev/status/2118605812218376272) (9 likes, 12 replies, 515 views, 1 bookmark); [@unknownnode404](https://x.com/unknownnode404) [outlined](https://x.com/unknownnode404/status/2118673587678630160) (36 likes, 5 replies, 713 views, 28 bookmarks).
3. **Parallel execution shifts work into isolation and merge coordination.** One thread proposes remote sandboxes and a pinned-commit merge queue; GitHub separately claims high write throughput in internal tests [@pauliusztin_](https://x.com/pauliusztin_) [proposed](https://x.com/pauliusztin_/status/2118757809269653788) (13 likes, 1 retweet, 10 replies, 305 views, 3 bookmarks); [@github](https://x.com/github) [reported](https://x.com/github/status/2118830274431873379) (6 likes, 2 retweets, 3 replies, 2,430 views, 3 bookmarks).
4. **Reliability and cost can move in opposite directions.** A single anecdote describes a higher-cost multi-agent run succeeding where a cheaper solo run failed, but does not support a general benchmark conclusion [@stretchcloud](https://x.com/stretchcloud) [recounted](https://x.com/stretchcloud/status/2118421087696667083) (4 likes, 6 replies, 193 views).
5. **Learned coordination is promising but still narrowly tested.** The s³ authors report gains over baselines on two constrained tasks using small models, not general production systems [@scottgeng00](https://x.com/scottgeng00) [shared](https://x.com/scottgeng00/status/2118768807573594357) (15 likes, 804 views).
