### 1.1 Harness 工程正成为定义智能体的核心学科 🡕

[@Vtrivedy10](https://x.com/Vtrivedy10) [发布](https://x.com/Vtrivedy10/status/2052100726608781363)（81 个赞、6 条回复、2 次引用、100 个收藏、4214 次浏览）发布了一份关于智能体 harness 工程的 8 点宣言：“只要围绕任务设计 harness，几乎在任何任务上，你都能胜过任何默认 harness+模型 的组合（包括 codex 和 claude code）。”核心观点包括：“通用型”智能体并不存在（本质上是定制时间与性能之间的权衡）；评测是护城河；前沿闭源模型“对于现实世界中绝大多数任务来说，成本高得过头了”。

[@oneill_c](https://x.com/oneill_c) [认可](https://x.com/oneill_c/status/2052076244527988759)（97 个赞、8963 次浏览）谈到 Harvey 的领域专用模型训练：“如今，全球最优秀的公司正利用自身的领域专长和真实世界的反馈闭环来构建评测与奖励（进而最终构建模型），从而超越仅靠提示词工程和 harness 工程使用闭源模型所能达到的水平。” [@itsandrewgao](https://x.com/itsandrewgao) [指出](https://x.com/itsandrewgao/status/2052115991187141054)（10 个赞、1628 次浏览）：“harness 工程相对基础模型所带来的提升，被严重低估了。”

[@tezos](https://x.com/tezos) [分享](https://x.com/tezos/status/2052056230189797417)（25 个赞、899 次浏览）提到一场 TezDev 2026 演讲，@yurug 在其中指出：“大多数使用 AI 智能体的团队，只是在适配现有流程——就像给自行车装上电机——而不是从底层重新思考工作流。团队真正需要修的是 harness。”

**与前一天的对比：** 5 月 5 日的重点是 /goal 命令和多日运行，代表了 harness 工程的实际落地。到了 5 月 6 日，讨论被提升到第一性原理层面——@Vtrivedy10 的宣言把 harness 工程视为一门拥有自身权衡曲线、成本模型和评测体系的学科，而 @oneill_c 则释放出另一个信号：前沿公司正在彻底越过提示词工程，转向由 harness 衍生评测驱动的定制模型训练。

**讨论洞察：** @BetterSayAJ 的回复精准点出了其中的张力：“这和经典 IR + 系统思维高度吻合。模型一旦固定，大多数提升都来自检索、工具和评测闭环。‘模型会吞掉脚手架’这个说法，在生产环境里依然显得不完整。” @Vtrivedy10 也承认，他预计“模型会吞掉更多脚手架”，但同时相信，那些“帮助智能体为自己准备好工具和上下文”的团队会做出更好的产品。

## 2. 什么让人沮丧

### Token 成本仍是智能体扩展的首要障碍

[@RoundtableSpace](https://x.com/RoundtableSpace) [演示](https://x.com/RoundtableSpace/status/2052089764136837184)（78 个赞、13 条回复、50 个收藏、46174 次浏览）再次凸显了昨天提到的巨大成本差异：“一次改动让 Claude Code 的 token 用量降低了 3 倍。之前：10.4M tokens、10 个错误、$9.21。之后：3.7M tokens、0 个错误、$2.81。作为上下文工程层，把 Supabase 换成了 Insforge Skills + CLI。”4.6 万次浏览和 13 条回复说明，这不是一天的新闻，而是持续存在的痛点。

### 演示型智能体与生产级智能体之间的鸿沟仍未解决

[@databricks](https://x.com/databricks) [重申](https://x.com/databricks/status/2051683930223325228)（56 个赞、20 个收藏、3198 次浏览）：“大多数‘agentic AI’仍然只是演示品。数据工作和编码是明确的例外。” [@LandonExplr](https://x.com/LandonExplr) 回复：“Agentic AI 只在输出可验证的场景下有效。数据管道符合这一条件。其他所有自称‘agentic’的东西，依然只是演示品。” [@tezos](https://x.com/tezos) 也呼应了 @yurug 的观察：团队只是在“给自行车装电机”，而不是重新设计工作流。

### 本地模型基础设施受制于硬件门槛

[@0xSero](https://x.com/0xSero) [展示](https://x.com/0xSero/status/2052114426078409122)（111 个赞、12 条回复、46 个收藏、5699 次浏览）展示了 vllm-studio 运行本地编码智能体，但 @BopityBibity 回复道：“在家里* *前提是你有几台价值 5000 美元、专门做推理的 GPU 机器。”本地智能体的承诺与实际所需硬件之间的落差，让那些无法为这笔资本开支找到合理性的从业者倍感挫败。

### 智能体规格交接仍然靠手工完成

[@hasantoxr](https://x.com/hasantoxr) [指出](https://x.com/hasantoxr/status/2052026311187853461)（104 个赞、70 个收藏、20572 次浏览）点出了核心问题：“编码智能体加速了‘能做出什么’，却没有加速‘该做什么’。PM 仍在 Google Docs 里写规格。智能体仍会幻觉化理解意图。工程师仍会交付错误的东西。”即使执行速度在提升，人类思考与智能体执行之间的交接仍是摩擦点。

### 在浏览前先做反爬检测

### 安全的智能体支付基础设施

[@Whitelist1Media](https://x.com/Whitelist1Media) [概述](https://x.com/Whitelist1Media/status/2051952346226422224)（61 个赞、3850 次浏览）介绍了智能体自主掌管资金所需的安全栈：“多因素批准（2-of-3 或 time-lock）、每日最大交易限额、链上监控 + 告警、密钥存放于硬件或 MPC 钱包。绝不能放进提示词。”其判断是：“风险已经不在技术本身，而在提示词质量、限额和治理。”

## 7. 机会在哪里

**[+++] 智能体 harness 工程即服务。** @Vtrivedy10 的宣言、@oneill_c 在 Harvey 推进领域专用模型训练，以及 @tezos 关于“修好 harness”的演讲，都指向同一个结论：团队需要帮助，才能从默认智能体配置走向面向任务优化的 harness。Insforge 带来的 3 倍 token 降幅证明了这件事的 ROI。谁能把 harness 优化（评测、技能、工具选择）打包成托管服务，谁就抓住了“智能体能工作”和“智能体高效工作”之间的缺口。

**[+++] 平台级智能体技能分发。** AWS 推出了 40+ 项技能和 15K API 访问。Neo4j 推出了领域专用技能。@mattpocockuk 正考虑开设技能编写课程。模式已经很清晰：技能就是新的软件包，而分发/发现层仍是一片空白。一个具备质量信号、验证机制和依赖管理的“智能体技能版 npm”尚无明确赢家。

**[++] 智能体持久性与记忆基础设施。** CopilotKit 的 Enterprise Intelligence Platform、@tom_doerr 的 MCP Memory Service、HermesOS 的持久化智能体，以及 @GithubProjects 的共享工作区，都瞄准了同一个缺口：让智能体跨会话保留上下文。“从演示到生产”的鸿沟越来越由记忆定义，而不是由能力定义。

**[++] 低于 200ms TTFA 的语音智能体基础设施。** @kimmonismus 设定了门槛，@jason_haugh 从 BPO 一侧给出了验证，Inworld 也推出了满足这一标准的模型。机会在于：构建语音智能体质量控制工具、延迟监控和回退系统，避免 @m13v_ 所指出的“补偿回路”故障模式。

**[+] 本地优先的智能体硬件生态。** @sudoingX 认为 DGX Spark 尚未被充分发掘，@0xSero 推出了面向本地编码智能体的 vllm-studio，而 @Vtrivedy10 则认为，随着团队开始把成本映射到 ROI，开源模型的 harness 工程将会“起飞”。定制内核、优化推理栈以及开箱即用的本地智能体方案，正受到越来越多成本敏感团队的需求驱动。

**[+] 智能体到智能体的商业与托管。** Boson Protocol 的 x402B、Bankr 的自筹资智能体、Swarms Marketplace 的 $30K 黑客松，以及 4lpha 的多智能体交易，都指向智能体彼此交易的未来。面向 agent-to-agent commerce 的信任与结算基础设施仍处于早期且高度碎片化。

## 8. 要点总结

1. **Harness 工程已经从技巧升级为学科。** @Vtrivedy10 的 8 点宣言、@oneill_c 对领域专用模型训练的认可，以及 @tezos 的会议演讲，都把 harness 工程描述为一种拥有自身权衡曲线的结构化实践——它不再是一堆技巧，而是一个拥有评测体系、成本模型和职业路径的领域。（[来源](https://x.com/Vtrivedy10/status/2052100726608781363)）

2. **AWS 通过 MCP 带来的 15,000 个可访问 API 技能，改变了技能分发格局。** @clare_liguori 发布 AWS Agent Toolkit，代表云服务商在单日内对智能体可访问能力最大规模的一次扩展。183 个收藏和几乎没有争论，表明从业者把它视为应当采纳的基础设施，而不是需要辩论的论点。（[来源](https://x.com/clare_liguori/status/2052115538701394205)）

3. **“自动驾驶代码库”已不再只是思想实验——四家公司都说出了自己的实现。** @grinich 列举 Ramp（Inspect）、Stripe（Minions）、Spotify（Honk）和 WorkOS（Horizon）分别独立构建了持续运行的智能体系统，这证明该模式在工程组织中已经形成势能。（[来源](https://x.com/grinich/status/2052082382358958512)）

4. **技能编写正成为一门可教授的技艺，而不只是使用智能体的副产品。** @mattpocockuk 那条关于技能写作课程的帖子收获 290 个赞，@asmah2107 建议手写技能，Neo4j 也推出了领域专用技能。这些信号都表明，“技能作者”正成为一种拥有可学习方法的独立角色。（[来源](https://x.com/mattpocockuk/status/2052132647770452286)）

5. **低于 200ms 的语音延迟如今已成为生产门槛——超过这一线，来电者会迅速流失。** @kimmonismus 给出了这个数字，@jason_haugh 从 BPO 运营一侧予以确认，@m13v_ 则指出了更深层的故障模式（用户补偿性填充沉默，进而破坏意图识别）。超过 300ms 的语音智能体不只是慢——还会引发连锁错误。（[来源](https://x.com/kimmonismus/status/2051772184432185445)）

6. **Anthropic 与 SpaceX 的算力合作以及 Dreaming 功能，预示着始终在线的智能体基础设施。** 300 MW 算力，再加上“回顾过去会话以持续改进智能体”的功能，意味着 Claude 正按持续运行而非请求-响应模式进行架构设计。智能体托管的经济模型正从按调用计费，转向按智能体生命周期计费。（[来源](https://x.com/RLanceMartin/status/2052138013564776949)）
