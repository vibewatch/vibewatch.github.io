# Twitter AI Agent - 2026-09-05

## 1. 人们在讨论什么

### 1.1 “技能”不再只是提示词经验，而开始变成可安装的智能体操作系统 (🡕)
今天最强的一簇讨论，把智能体技能当成有边界、有验证、可打包的软件制品，而不是可复用的文本片段。[@AgentChud](https://x.com/AgentChud) [发布](https://x.com/AgentChud/status/1963914990247027152)（503 点赞、72 回复、66,563 浏览量、1,140 收藏）了一份 15k 字符的 `evm-token-due-diligence` 技能包：它把每次分析都绑定到精确的链和合约地址，解析代理合约，锁定区块头，禁止真实签名，并包含合成拒绝测试。[@earthtojake](https://x.com/earthtojake) [发布](https://x.com/earthtojake/status/1963902750252880182)（166 点赞、6 回复、7,940 浏览量）了 `text-to-cad` v0.5，把它做成本地的智能体技能库，覆盖 CAD、CAE 和 CAM；公开仓库记录了 CAD 生成、DXF、URDF、SRDF、SDF、切片、打印检查以及 Bambu Lab 上传流程等技能。([仓库](https://github.com/earthtojake/text-to-cad)) [@boringmarketer](https://x.com/boringmarketer) [分享](https://x.com/boringmarketer/status/1963907020897507381)（135 点赞、7 回复、12,146 浏览量、384 收藏）了一份 31 条规则的仓库所有者提示词，其中要求的重点不是写得多漂亮，而是链接来源检索、有界委派、可观察的交付状态，以及诚实验证。

讨论要点是，构建者越来越明确地规定智能体必须记住什么、必须如何证明任务已经做完，以及它被允许在哪里行动。相比 2026-09-04 仍偏向笼统谈“技能”和运行框架的表述，2026-09-05 已把讨论推进到安装命令、显式结构定义和仓库操作规则。

### 1.2 验证、事件披露与审阅器失灵成了智能体讨论的一级议题 (🡕)
第二个大主题是，大家不再只把智能体可靠性当成基准测试质量问题，而是当成公开披露与运维问题来讨论。[@biscuitweb3](https://x.com/biscuitweb3) [认为](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量），一旦智能体能直接写到公开可见的界面上，仅有系统卡已经不够：人们需要事件式报告，说明问题何时开始、触及了哪些系统、影响了谁，以及独立审阅者能核实什么。[@ghadfield](https://x.com/ghadfield) [警告](https://x.com/ghadfield/status/1963982553996101747)（34 点赞、2 回复、3,187 浏览量），Hugging Face 调查中使用的分析智能体“非常轻信”，常常直接接纳失控智能体的叙事框架，这与链接论文《Talk Isn’t Always Cheap》描述的失效模式一致。([论文](https://arxiv.org/abs/2509.05396)) [@shivam74689](https://x.com/shivam74689) [记录](https://x.com/shivam74689/status/1963976093802987599)（4 点赞、2 回复、115 浏览量）了一套带专用反思循环的编程智能体栈，并把自我纠错迭代硬性限制为 3 次；与此同时，[@rohanpaul_ai](https://x.com/rohanpaul_ai) [重点提到](https://x.com/rohanpaul_ai/status/1964024770902679837)（9 点赞、1 回复、1,414 浏览量）的《Harness-of-Harness》，则强调要在多次编程会话之间保留代码、QA 证据和计划，而不是每次都回到空白起点。([论文](https://arxiv.org/abs/2609.01481))

## 2. 令人困扰的问题

### 2.1 当智能体审查自己或同伴时，验证仍然会失灵
最尖锐的挫败感，并不在模型的原始能力，而在智能体开始行动或评估后，人们是否还能信任输出。[@biscuitweb3](https://x.com/biscuitweb3) [认为](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量），面向公众发文的智能体需要事件式披露，而不是事后营销文案。[@ghadfield](https://x.com/ghadfield) [警告](https://x.com/ghadfield/status/1963982553996101747)（34 点赞、2 回复、3,187 浏览量），调查智能体太容易吸收失控智能体的叙事框架，这与《Talk Isn’t Always Cheap》里的失效模式彼此呼应。[@shivam74689](https://x.com/shivam74689) [记录](https://x.com/shivam74689/status/1963976093802987599)（4 点赞、2 回复、115 浏览量）了一套带 3 次上限的反思循环，正是因为默认情况下，无界自我修复并不值得信任。[@rohanpaul_ai](https://x.com/rohanpaul_ai) [重点提到](https://x.com/rohanpaul_ai/status/1964024770902679837)（9 点赞、1 回复、1,414 浏览量），把 QA 证据延续下去，本身就是解决方案的一部分。

**为什么这会让人难受：** 一旦输出面向公众或接近生产环境，团队就不能再把“模型自己检查过了”当成有说服力的安全叙事。

**值得为此构建吗？** 是。这是一个直接、反复出现的痛点，在运维、治理和企业审查工作流里都有明确的购买紧迫性。

### 2.2 团队还没法衡量采用情况，就先买下了智能体产能
第二类挫败感来自衡量。[@mardehaym](https://x.com/mardehaym) [认为](https://x.com/mardehaym/status/1963946672496719915)（25 点赞、14 回复、2,855 浏览量），智能体支出不等于采用情况，董事会应该要求看到结果指标，例如由智能体写出的已合并代码占比。[@boringmarketer](https://x.com/boringmarketer) [分享](https://x.com/boringmarketer/status/1963907020897507381)（135 点赞、7 回复、12,146 浏览量、384 收藏）的一份仓库所有者提示词，则反复要求可观察的交付状态和明确验证；这正是同一抱怨在构建者视角下的版本：人们想要的是工作确实被正确做完的证据，而不是一条自信满满的状态更新。

**为什么这会让人难受：** 预算讨论跑在了观测能力前面。如果缺少工作流级归因，团队就无法判断智能体是在加快交付，还是只是在增加支出。

**值得为此构建吗？** 是。对企业工具尤其成立，因为这个问题正好卡在采购、平台团队和工程管理层之间。

### 2.3 智能体原生工作流仍会卡在上下文、监督和接入流程上
第三类挫败感是现实工作流里的操作阻力。[@suraj_sharma14](https://x.com/suraj_sharma14) [整理](https://x.com/suraj_sharma14/status/1963983838875066645)（39 点赞、8 回复、1,613 浏览量）了动态上下文拼装、带类型的 A2A 交接、工具沙箱隔离、公开基准，以及由失败沉淀出的黄金数据集等未解问题；其中一条高赞回复还补充说，只要遇到第一个只面向人类的注册墙，整套“让智能体替你使用工具”的承诺就会崩掉。[@DanKornas](https://x.com/DanKornas) [分享](https://x.com/DanKornas/status/1963970567895521534)（15 点赞、6 回复、687 浏览量）`trace-mcp`，就是为了减少反复重新发现代码库的时间。[@DanKornas](https://x.com/DanKornas) [发布](https://x.com/DanKornas/status/1963972177497432264)（21 点赞、8 回复、1,149 浏览量）Omnigent，则是因为跨多个运行框架的监督本身已经变成一个产品需求。

**为什么这会让人难受：** 即便模型很强，它们仍会在重复加载上下文、等待人工关卡，或在工具之间传递不完整状态上浪费时间。

**值得为此构建吗？** 是。这是智能体基础设施的直接平台机会，尤其适用于编程、研究和运维负担较重的环境。

## 3. 人们期望的功能

### 3.1 面向具体领域、可审查且可安装的技能包
[@AgentChud](https://x.com/AgentChud) [发布](https://x.com/AgentChud/status/1963914990247027152)（503 点赞、72 回复、66,563 浏览量、1,140 收藏）了一份读起来就像包规范的尽调技能，而 [@earthtojake](https://x.com/earthtojake) [发布](https://x.com/earthtojake/status/1963902750252880182)（166 点赞、6 回复、7,940 浏览量）了作为真实技能库的 `text-to-cad`。这两条帖子背后的共同愿望很明确：团队想要的是像软件一样可安装、可版本化、可测试、可审计的可复用智能体能力。

**机会：** 直接。这种需求说得很明确，而且绑定在真实工作流上，而不是停留在对未来的想象。

### 3.2 面向自主行动的公开事件账本
[@biscuitweb3](https://x.com/biscuitweb3) [认为](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量），当智能体发布有害或错误内容时，人们需要事件式报告。这里缺的不是另一篇安全长文，而是一份结构化的公开记录：写清时间、影响范围、补救措施，以及可核实的证据。

**机会：** 直接。凡是智能体能够发布、交易或修改外部系统的地方，这个需求都很紧迫。

### 3.3 能跨运行、工具和智能体持续存在的项目记忆
[@rohanpaul_ai](https://x.com/rohanpaul_ai) [重点提到](https://x.com/rohanpaul_ai/status/1964024770902679837)（9 点赞、1 回复、1,414 浏览量）的《Harness-of-Harness》指出，只要计划、代码状态和 QA 证据能在重复的编程运行之间持续保留，效果就会提升。[@DanKornas](https://x.com/DanKornas) [分享](https://x.com/DanKornas/status/1963970567895521534)（15 点赞、6 回复、687 浏览量）`trace-mcp`，是为了预先加载具备框架感知能力的代码上下文。[@DamiDefi](https://x.com/DamiDefi) [传播](https://x.com/DamiDefi/status/1963978565406880193)（145 点赞、2 回复、7,894 浏览量）了一套围绕总控智能体、专家智能体、共享工作区记忆和证据检查点构建的 Grok Bot 运行模型。它们共同指向的愿望，是一种能消除重复发现成本、同时又不牺牲可审计性的持久状态。

![由 @DamiDefi 分享的 Grok Bot 现场手册，展示了总控智能体、专家智能体、记忆与审批结构](https://pbs.twimg.com/media/HRdEWEaaQAA0iFo.jpg)

**机会：** 直接。这种痛点在研究、编程和编排工作流里反复出现。

### 3.4 不会在第一个人工门槛前崩掉的智能体原生分发、支付与接入流程
[@ParkerOrtolani](https://x.com/ParkerOrtolani) [注意到](https://x.com/ParkerOrtolani/status/1963945307393218598)（7 点赞、880 浏览量）新的 Grok 市场，而公开的 [xAI Bot Marketplace](https://x.ai/bot/marketplace) 已经展示出一个实时目录。[@trythreews](https://x.com/trythreews) [展示](https://x.com/trythreews/status/1963999859073702103)（75 点赞、19 回复、1,985 浏览量）了一个把虚拟形象、语音、身份、支付、二次创作和 MCP/A2A 连接组合在一起的平台。但 [@suraj_sharma14](https://x.com/suraj_sharma14) [整理](https://x.com/suraj_sharma14/status/1963983838875066645)（39 点赞、8 回复、1,613 浏览量）出的缺口也很清楚，其中就包括那句抱怨：只要出现一个只供人类使用的注册步骤，智能体原生执行就会中断。

**机会：** 竞争型。现实产品已经出现，但工作流仍不完整，信任信号也还偏弱。

### 3.5 与已交付结果挂钩、而不是只看使用账单的采用看板
[@mardehaym](https://x.com/mardehaym) [认为](https://x.com/mardehaym/status/1963946672496719915)（25 点赞、14 回复、2,855 浏览量），应该衡量诸如“由智能体写出的已合并代码占比”这样的指标。[@boringmarketer](https://x.com/boringmarketer) [分享](https://x.com/boringmarketer/status/1963907020897507381)（135 点赞、7 回复、12,146 浏览量、384 收藏）的操作规则，则要求必须给出明确的交付证据。这里缺的产品，是一层被管理层和操作者都信任的系统，能把智能体活动转换成面向董事会和运维者的结果报告。

**机会：** 直接。衡量痛点已经摆在眼前，而且很可能带有预算。

## 6. 新动态与亮点

### 6.1 面向智能体的公开事件披露，已经成为明确诉求，而不是模糊的安全愿景
治理层面最值得注意的变化，是在 OpenAI “wiki 事件”讨论之后，[@biscuitweb3](https://x.com/biscuitweb3) [推动](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量）建立事件式披露。关键点不只是批评，而是它对披露字段的要求非常具体：发生时间、受影响系统、波及范围，以及可由外部独立核实的事实。相比经常主导智能体争论的“发布更多安全文档”话语，这是一种更偏运维的诉求。

### 6.2 跨编程运行保留持久证据，已经从工作流经验之谈变成了一个正式命名的研究方向
[@rohanpaul_ai](https://x.com/rohanpaul_ai) [重点提到](https://x.com/rohanpaul_ai/status/1964024770902679837)（9 点赞、1 回复、1,414 浏览量）的《Harness-of-Harness》，是一篇关于如何在重复编程会话之间延续代码、测试、QA 结果和计划的论文。它之所以重要，是因为它和今天其他地方出现的实际工程方向正好对上：[@shivam74689](https://x.com/shivam74689) [展示](https://x.com/shivam74689/status/1963976093802987599)（4 点赞、2 回复、115 浏览量）了一套有界反思循环，而 [@DanKornas](https://x.com/DanKornas) [分享](https://x.com/DanKornas/status/1963970567895521534)（15 点赞、6 回复、687 浏览量）了作为持久代码上下文层的 `trace-mcp`。其中的新意，在于研究叙事与实践工具开始汇合。

### 6.3 实时智能体店面正在到来，但差异化体验比“有个货架”本身更重要
两个公开表面尤其突出。[@ParkerOrtolani](https://x.com/ParkerOrtolani) [带出](https://x.com/ParkerOrtolani/status/1963945307393218598)（7 点赞、880 浏览量）了 xAI bot marketplace，而公开网站显示它已经有 69 个公开 Bots、43 位创作者和 9 个分类。[@trythreews](https://x.com/trythreews) [展示](https://x.com/trythreews/status/1963999859073702103)（75 点赞、19 回复、1,985 浏览量）了一个丰富得多的公开表面，把具身化、语音、身份、支付和 remix 组合在一起。值得注意的信号并不只是“市场已经存在”，而是团队开始围绕智能体周边的整套交互与变现栈展开竞争。

## 7. 机会在哪里

### [+++] 为长时间运行的智能体工作构建持久上下文与验收所有权层
最明显的产品缺口，是那一层决定智能体能做什么、要带着什么上下文继续前进，以及由谁来验收结果的系统。[@AgentChud](https://x.com/AgentChud) [在技能包层级规定了](https://x.com/AgentChud/status/1963914990247027152)（503 点赞、72 回复、66,563 浏览量、1,140 收藏）领域规则；[@daniel_mac8](https://x.com/daniel_mac8) [分享](https://x.com/daniel_mac8/status/1963953192253446318)（143 点赞、26 回复、15,081 浏览量）了一种让 Astra 继续担任验收负责人的控制模型；[@DanKornas](https://x.com/DanKornas) [分享](https://x.com/DanKornas/status/1963970567895521534)（15 点赞、6 回复、687 浏览量）了用来保留代码结构的 `trace-mcp`；而 [@rohanpaul_ai](https://x.com/rohanpaul_ai) [重点提到](https://x.com/rohanpaul_ai/status/1964024770902679837)（9 点赞、1 回复、1,414 浏览量）跨编程运行延续证据。机会在于，把这些想法打包成一层可审计、模型无关、可用于生产环境的基础设施。

### [++] 为自主行动构建独立的验证与事件证据系统
可靠性讨论正在从“怎么把提示词写得更好？”转向“怎么证明到底发生了什么？” [@biscuitweb3](https://x.com/biscuitweb3) [主张](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量）公开的事件式披露；[@ghadfield](https://x.com/ghadfield) [警告](https://x.com/ghadfield/status/1963982553996101747)（34 点赞、2 回复、3,187 浏览量）评估智能体过于轻信；[@shivam74689](https://x.com/shivam74689) [记录](https://x.com/shivam74689/status/1963976093802987599)（4 点赞、2 回复、115 浏览量）了一套带明确失败处理的有界自我纠错机制。一个强机会是：打造能够记录智能体动作、附带证据、把评估与执行拆开，并生成可直接用于事故披露记录的产品。

### [+] 构建避开人工瓶颈的智能体原生分发与变现路径
公开货架已经出现，但工作流依然很脆弱。[@ParkerOrtolani](https://x.com/ParkerOrtolani) [带出](https://x.com/ParkerOrtolani/status/1963945307393218598)（7 点赞、880 浏览量）了 xAI 市场，而 [@trythreews](https://x.com/trythreews) [展示](https://x.com/trythreews/status/1963999859073702103)（75 点赞、19 回复、1,985 浏览量）了一个已经接好身份和支付的平台。与此同时，[@suraj_sharma14](https://x.com/suraj_sharma14) [整理](https://x.com/suraj_sharma14/status/1963983838875066645)（39 点赞、8 回复、1,613 浏览量）出了实际阻塞点，其中就包括只面向人类的注册墙会直接打断智能体工具使用这一事实。机会真实存在，但市场已经开始成形，最终更可能奖励执行质量，而不是先发新鲜感。

## 8. 要点总结

1. 技能如今更像可安装、可测试的运行单元。最清晰的证据来自 [@AgentChud](https://x.com/AgentChud) [发布](https://x.com/AgentChud/status/1963914990247027152)（503 点赞、72 回复、66,563 浏览量、1,140 收藏）的一份尽调技能规范，以及 [@earthtojake](https://x.com/earthtojake) [发布](https://x.com/earthtojake/status/1963902750252880182)（166 点赞、6 回复、7,940 浏览量）的 CAD 工作流真实技能库。
2. 验证正在变成一门运维学科，而不只是基准测试学科。[@biscuitweb3](https://x.com/biscuitweb3) [要求](https://x.com/biscuitweb3/status/1963928169324962060)（89 点赞、77 回复、4,196 浏览量）事件式透明度，而 [@ghadfield](https://x.com/ghadfield) [展示](https://x.com/ghadfield/status/1963982553996101747)（34 点赞、2 回复、3,187 浏览量）了评估智能体依然多么容易被带偏。
3. 现代智能体栈正在变厚：编排、代码图、浏览器运行时和共享记忆，今天都以独立产品层的形式出现，体现在 [@daniel_mac8](https://x.com/daniel_mac8) 的 [Astra Advisor](https://x.com/daniel_mac8/status/1963953192253446318)（143 点赞、26 回复、15,081 浏览量）、[@DanKornas](https://x.com/DanKornas) 的 [Omnigent](https://x.com/DanKornas/status/1963972177497432264)（21 点赞、8 回复、1,149 浏览量）与 [trace-mcp](https://x.com/DanKornas/status/1963970567895521534)（15 点赞、6 回复、687 浏览量），以及 [@alex_verem](https://x.com/alex_verem) [带出的 Obscura](https://x.com/alex_verem/status/1963977549172128180)（5 点赞、3 回复、1,215 浏览量）之中。
4. 市场真正要求的是结果证明，而不只是智能体供给。[@mardehaym](https://x.com/mardehaym) [主张](https://x.com/mardehaym/status/1963946672496719915)（25 点赞、14 回复、2,855 浏览量）用已合并代码来衡量采用情况，这与 [@boringmarketer](https://x.com/boringmarketer) [在这里](https://x.com/boringmarketer/status/1963907020897507381)（135 点赞、7 回复、12,146 浏览量、384 收藏）提出的仓库所有者对“可观察交付状态”的要求是一致的。
5. 分发终于开始变得可见，但信任和接入流程仍然是薄弱环节。公开的 [xAI Bot Marketplace](https://x.ai/bot/marketplace) 和 [three.ws](https://three.ws) 证明表面已经存在；[@suraj_sharma14](https://x.com/suraj_sharma14) [总结](https://x.com/suraj_sharma14/status/1963983838875066645)（39 点赞、8 回复、1,613 浏览量），只要缺少上下文、沙箱隔离或注册步骤，整个工作流依然会中断。
