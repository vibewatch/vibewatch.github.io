## 1. 大家在讨论什么

### 1.1 Flue 发布首个 Agent Harness 框架 🡕

当天信号最强的一条，是 [@FredKSchott](https://x.com/FredKSchott) 发布了 [Flue](https://x.com/FredKSchott/status/2050274923852210397)（999 次点赞、1,255 次收藏、102,567 次浏览）——这是一个 TypeScript 框架，用于围绕内置 agent harness 构建 agent。Flue 的定位是“Claude Code，但 100% 无头且可编程”，默认不需要人类操作员参与。与 AI SDK 不同，Flue 是一个与运行时无关的框架：一次编写、构建后即可在任意环境部署 agent（Node.js、Cloudflare、GitHub Actions、GitLab CI/CD）。其一等概念包括 sessions、subagents、内置 sandboxes，以及用 Markdown 定义的 skills。该框架最初源自为 Astro GitHub 仓库内部 AI 工作流提供支持。

![Flue 代码示例，展示 agents/triage.ts 中的 session.skill()、session.prompt() 和 session.shell() API，演示结构化输出与沙箱执行](https://pbs.twimg.com/media/HHQG0eiagAEzUyh.jpg)

[@FredKSchott](https://x.com/FredKSchott) [澄清了定位](https://x.com/FredKSchott/status/2050287649928458619)：“框架 vs. SDK。有点像 Next.js/Astro 构建在 React 之上，Flue 则构建在 pi-agent-core 之上，为我们的 harness 提供能力。”

**讨论洞察：** [@LeoTava8](https://x.com/LeoTava8) 准确点出了它的吸引力：“这个行业痴迷于在循环里做 prompting，却忽视了我们从基础设施中学到的经验。我们需要显式的契约层和真正有状态的编排。Flue 看起来正是合适的基础原语——把 ‘what’ 和 ‘how’ 分开。”

**与前一天对比：** 4 月 30 日，Cursor 公布了其内部 harness 方法论，社区也开始将 harness engineering 视为一门独立学科。到了 5 月 1 日，首个围绕这一理念构建的专用开源框架出现，标志着它从方法论迈向可部署的产物。

### 1.2 Microsoft Agent 365 正式进入 GA 🡕

[@satyanadella](https://x.com/satyanadella) [宣布](https://x.com/satyanadella/status/2050251014691840015)（367 次点赞、22,451 次浏览）表示，Agent 365 现已正式可用，作为一个统一控制平面，用于在整个企业范围内观测、治理并保护 agents 及其交互。该系统将现有的身份、安全、治理和管理工作流扩展到每一个 AI agent——包括用 Microsoft AI 构建的 agents，以及第三方生态中的 agents。新的预览功能包括：对使用自身凭据运行的 agents 提供可观测性、通过 Microsoft Defender 和 Intune 发现 shadow AI，以及 Windows 365 for Agents（托管的沙箱环境）。

**讨论洞察：** [@GroverLovesh](https://x.com/GroverLovesh) 给出了实践者视角：“过去 60 天里，我排查的大多数 agent 故障都不是模型问题，而是身份/权限问题。Microsoft 解决的是那一半枯燥的问题。而恰恰是这枯燥的一半更大。没有按 agent 分配身份就上线的独立 agent 栈，在第一次合规审查时就会撞墙。”

**与前一天对比：** 4 月 30 日的重点，是开发者领域中 agent 框架的成熟。5 月 1 日则显示，企业治理层也在跟上——正是这“枯燥的一半”，让 agents 能以机构级规模真正投入生产。

### 1.3 Harness Engineering 正在固化为核心学科 🡒

多条高信号内容进一步强化了一个判断：harness engineering 已成为主导范式：

[@Vtrivedy10](https://x.com/Vtrivedy10) [解释了](https://x.com/Vtrivedy10/status/2050239109038232005)（81 次点赞、68 次收藏）介绍了 LangChain 的 Deep Agents 如何构建在 `create_agent` 之上——这一单一原语支持 filesystem tools、bash、compaction、subagents、skills、memory 和 hooks。他强调，这一原语的可扩展性，是所有 Deep Agents 工程能力的基础。

![LangChain 文档，展示带有 ReAct 循环图的 create_agent，以及包含 Model、Tools、System prompt、Memory、Middleware 的 API 界面](https://pbs.twimg.com/media/HHPplsvXcAEnLN_.jpg)

[@Vtrivedy10](https://x.com/Vtrivedy10) 另行 [演示了](https://x.com/Vtrivedy10/status/2050267113844048230) 表示，仅 GPT-5.5 中一条 steering instruction，就会让 Terminal Bench Score 发生 12% 的变化，为“Prompt and Harness Engineering still matter A TON today”提供了量化证据。

[@dntyk](https://x.com/dntyk) [分析了](https://x.com/dntyk/status/2050164326795722836)（33 次点赞、25 次收藏）提到 AHE 论文，其中自动进化出的 harness 在 Terminal-Bench 2 上达到 77.0%（手工设计的 Codex-CLI 为 71.9%）；其关键发现是：“收益来自工具、中间件和长期记忆。仅靠 system prompt 反而会退步。”

![AHE 论文标题：Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses，作者为 Lin 等人](https://pbs.twimg.com/media/HHH8Tc9a8AA_j3Y.png)

[@davidfowl](https://x.com/davidfowl)（116 次点赞、15,537 次浏览）[记录了](https://x.com/davidfowl/status/2050032712019484807) 道出了实践者的普遍心态：“我正准备自己造一个 agent orchestration system。现在大家都在这么干吗？？这算悲伤的第几个阶段？” [@stackbenchdev](https://x.com/stackbenchdev) 的回复是：“每个 harness 都编码了开发者对 agent 应该如何运行的理论。这就是为什么可移植模板至今没有成型。”

**与前一天对比：** 4 月 30 日，Cursor 公布了它的方法论，社区也识别出若干收敛中的模式。5 月 1 日则补上了实证证据（AHE 论文基准、单条指令引发 12% 波动）和实践者的挫败感（Fowl 开始自己造系统）——这门学科已经被验证，但工具空白依然存在。

### 1.5 跨 Agent 的 Skill 分发开始形成独立类别 🡕

三个彼此独立的项目，都在解决 skills 跨 agent 可移植性问题：

[@aidenybai](https://x.com/aidenybai) [推出了](https://x.com/aidenybai/status/2050256170775122174)（89 次点赞、61 次收藏）发布了 agent-install，这是一个开源工具，可通过 API 或 CLI 在 52 个 coding agents 之间安装 skills 和 MCPs。

![agent-install 代码展示了面向 cursor 和 claude-code 等多个 agent 的 skill.add() 与 mcp.add() API，以及对应的 CLI 命令](https://pbs.twimg.com/media/HHN5rYdbMAAMcZo.jpg)

[@tiangolo](https://x.com/tiangolo)（FastAPI creator）[发布了](https://x.com/tiangolo/status/2050140168003146198)（37 次点赞、24 次收藏）发布了 library-skills——该工具会扫描项目依赖，并安装随库一同打包的 AI skills（例如 FastAPI）。这些 skills 通过符号链接接入，因此库更新时能力会自动同步。支持 Python 和 Node.js，并带有用于 Claude Code 兼容的 `--claude` 标志。

[@ElevenLabsDevs](https://x.com/ElevenLabsDevs) [已上线](https://x.com/ElevenLabsDevs/status/2050244770140680405)（116 次点赞、78 次收藏）发布了可通过 `npx skills add elevenlabs/skills` 安装的 Voice Changer Skill，展示了能力供应商如何通过 skills 生态进行分发。

**讨论洞察：** [@mylifcc](https://x.com/mylifcc) 点出了收敛难题：“~/.claude/skills/SKILL.md 是我的 Claude Code 配置；Codex 和 Cursor 用的是不同路径。好奇 agent-install 是会把这些收敛成一个 manifest，还是只是按路径层面复制文件。”

**与前一天对比：** 4 月 30 日的挫败感，来自 skill 数量增长快于质量。到了 5 月 1 日，关注点转向了 skill 分发基础设施——skills 如何跨异构工具链到达 agents。

### 1.6 多 Agent 架构在研究与实践中同步推进 🡒

[@omarsar0](https://x.com/omarsar0) [分享了](https://x.com/omarsar0/status/2050261229315477988)（40 次点赞、39 次收藏）介绍了 RecursiveMAS 论文（arXiv:2604.25917，UIUC/Stanford/NVIDIA/MIT）：它提出，agents 应通过共享潜在空间中的递归计算协作，而不是彼此发送文本消息。结果显示，在 9 个基准上，准确率提升 8.3%、速度提升 1.2-2.4 倍，token 消耗减少 34.6-75.6%。

![RecursiveMAS 论文展示了 MATH500、AIME2025、GPQA-D 和 Code Gen 上的缩放定律图表，以及协作模式对比（Mixture、Deliberation、Distillation 风格）](https://pbs.twimg.com/media/HHP9uNbbIAAmhj8.jpg)

[@aakashgupta](https://x.com/aakashgupta) [描述了](https://x.com/aakashgupta/status/2050318603338342513) 展示了一个在 Claude Code 内运行的 21-agent 开发团队，他们在 2 小时 13 分钟内把一款 hockey rules app 交付到 TestFlight：“现在的瓶颈已经变成 spec 了。你到底想要什么，描述得有多清晰，会决定后面的一切。”

**讨论洞察：** [@haowjy](https://x.com/haowjy) 对 RecursiveMAS 提出了一个关键问题：“我在想，这能不能被改造成适配完全不同的模型？多 agent 系统的主要优势之一，就是可以让采用完全不同训练方法的模型协同工作。” [@FiftyOne_50_](https://x.com/FiftyOne_50_) 则提出了控制层面的担忧：“潜在空间中的 agent 协调也许能减少 tokens，但它也会隐藏更多过程。”

**与前一天对比：** 4 月 30 日，hackathon 获奖项目里已经出现多 agent 模式（observation + verification）。5 月 1 日则同时推进了理论（用潜在空间递归取代文本协调）和实践（21-agent 团队交付应用）。

## 2. 什么让大家感到挫败

### 人人都在自建编排系统 —— 严重程度：高

[@davidfowl](https://x.com/davidfowl)（Microsoft .NET architect）[表达了](https://x.com/davidfowl/status/2050032712019484807)（116 次点赞、46 条回复、15,537 次浏览）道出了核心挫败感：“我正准备自己造一个 agent orchestration system。现在大家都在这么干吗？？这算悲伤的第几个阶段？” 回复证实，这种情况非常普遍。[@stackbenchdev](https://x.com/stackbenchdev)：“每个 harness 都编码了开发者对 agent 应该如何运行的理论。这就是为什么可移植模板至今没有成型——现实里的方案看起来都不一样，因为工作流本来就不一样。” [@buildwithparas](https://x.com/buildwithparas)：“讨价还价阶段；等你不再把它叫作临时方案时，就是接受阶段了。”

这种挫败贯穿整个技术栈：AHE 论文显示，自动进化出的 harness 优于手工设计版本，但实践者仍然得从零开始搭建，因为还没有哪个框架能覆盖完整的 harness 表面。Flue 是第一次尝试在框架层面解决这个问题。

### Agent 身份与权限故障 —— 严重程度：高

[@GroverLovesh](https://x.com/GroverLovesh) [报道了](https://x.com/satyanadella/status/2050251014691840015)：“过去 60 天里，我排查的大多数 agent 故障都不是模型问题，而是身份/权限问题。没有按 agent 分配身份就上线的独立 agent 栈，在第一次合规审查时就会撞墙。” Microsoft 的 Agent 365 GA 是企业端对此的首个答案，但独立部署和跨云部署仍未解决。[@OfficialTravlad](https://x.com/OfficialTravlad) [指出](https://x.com/OfficialTravlad/status/2050274260522774573)：“一旦走出 GCP，身份就消失了。没有可移植性，也没有可追责性。”

### Harness 配置高度敏感 —— 严重程度：中

[@Vtrivedy10](https://x.com/Vtrivedy10) [演示了](https://x.com/Vtrivedy10/status/2050267113844048230) 称，GPT-5.5 中单个 `tool_choice: "none"` 设置会注入一条 steering instruction，从而让 Terminal Bench Score 波动 12%。[@ValsAI](https://x.com/ValsAI) 证实，OpenAI 注入这条指令的方式“并不是 tools: [] 那种方式”。实践者无法预测这些细微配置变化会如何与模型内部机制相互作用，因此 harness 调优既脆弱又不透明。

## 3. 大家希望出现什么

### 可移植的 Agent 编排框架

[@davidfowl](https://x.com/davidfowl/status/2050032712019484807) 及其 46 条回复表明：开发者想要的是一种不需要自己重造的编排能力。缺口在于这样一种框架：模型选择只是配置项，工作流是声明式的，harness 能覆盖完整表面（tools、middleware、memory、subagents）。Flue 是第一个专门朝这个方向尝试的项目，但其定位也明确还很早期。实践者之所以仍在构建定制方案，是因为还没有东西能以可移植的方式承载他们的工作流理论。

紧迫性：高 —— 机会：直接

### 跨 Agent 的 Skill Manifest 标准

[@mylifcc](https://x.com/mylifcc) [识别出](https://x.com/aidenybai/status/2050256170775122174) 点明了缺口：“~/.claude/skills/SKILL.md 是我的 Claude Code 配置；Codex 和 Cursor 用的是不同路径。好奇 agent-install 是会把这些收敛成一个 manifest，还是只是按路径层面复制文件。MCP stdio vs sse 是最棘手的跨 agent 问题。” 三个独立项目（agent-install、library-skills、skills.sh）都在解决分发问题，但在这 52+ 个 agents 之间，尚不存在统一的标准 manifest。

紧迫性：高 —— 机会：基础设施

### 透明的 Harness-Model 交互调试能力

单条 steering instruction 带来的 12% Terminal Bench 波动，以及 AHE 论文中的消融结果，都说明实践者无法观察 harness 配置如何与模型相互作用。[@InsiderPresider](https://x.com/InsiderPresider) [提问](https://x.com/Vtrivedy10/status/2050239109038232005)：“create_agent 肯定是一个很扎实的原语，但我在想，这层抽象是不是把对生产级 agent 安全至关重要的复杂性隐藏得太多了。” 需要的是：对 harness 选择（tools、middleware、prompts）如何在评测时影响模型行为，提供可观测性。

紧迫性：中 —— 机会：工具

## 6. 新动态与重点内容

### Flue：首个专用 Agent Harness 框架

[Flue](https://x.com/FredKSchott/status/2050274923852210397)（1,255 次收藏）是首个围绕 agent harness 概念构建的框架，而不是把这套能力附着在 SDK 之上。出自 Astro/Next.js creator 之手，它把 sessions、subagents 和 sandboxes 定位为框架级一等原语，而非 SDK 工具。flue build 和 flue run 命令，也呼应了 Web 框架的开发体验。如果说 harness engineering 是一门学科，那么 Flue 就是第一次尝试把它做成一个可部署、标准化的框架。

Signal strength: [+++]

### Google COSMO 揭示 Android 的完整 Agent OS

[泄露的 COSMO 截图](https://x.com/minchoi/status/2050290896382353432)（52 次收藏）显示，Google 正在把一个完整的 agent 操作系统构建进 Android：混合执行（云端 P1 + 本地 Nano）、环境感知（屏幕上下文、音频、交互、voice match）、带分类的可扩展 skills，以及一种把手机视为持久 agent runtime 的架构。这是 Google 对端侧 AI agent 问题的回答。

Signal strength: [+++]

### Microsoft Agent 365 作为企业 Agent 控制平面进入 GA

[Agent 365](https://x.com/satyanadella/status/2050251014691840015) 解决了阻碍企业采用 agents 的“枯燥一半”：按 agent 分配的身份、治理、合规，以及 shadow AI 发现。这个发布时间点也确认：企业需求已经进入可生产落地阶段，而不再只是实验性尝试。

Signal strength: [++]

### RecursiveMAS 提出潜在空间中的 Agent 协调

来自 UIUC/Stanford/NVIDIA/MIT 的 [RecursiveMAS 论文](https://x.com/omarsar0/status/2050261229315477988)（arXiv:2604.25917）提出，让 agents 传递潜在状态而不是文本消息，从而在准确率提升 8.3% 的同时，将 token 使用量降低 34.6-75.6%。如果 agent 间通信会成为下一个瓶颈，那么潜在空间递归提供了一条无需支付 token 税、也能扩展协作规模的路径。

Signal strength: [++]

### DeepSeek-V4-Pro 在 Agentic Coding 中匹配前沿模型

[@omarsar0](https://x.com/omarsar0) [报道了](https://x.com/omarsar0/status/2050009901234282649)（33 次收藏）称，DeepSeek-V4-Pro 是“第一个真正让人感觉像 Codex 或 Claude Code 体验的 open-weight 模型”——无需特殊配置，就能在基础 harness 中开箱即用。其混合式 CSA+HCA 注意力设计，使其在仅 10% KV cache 开销下支持 1M-token context。

Signal strength: [+]

## 7. 机会在哪里

**[+++］ 捕获完整编排表面的 agent harness 框架** -- ［@davidfowl](https://x.com/davidfowl/status/2050032712019484807)（46 条回复）、AHE 论文基准，以及 Flue 的发布都在说明同一件事：实践者需要的是 agent harness 框架，而不是 SDK。Flue（早期、仅限 TypeScript）与生产团队真正需要的能力（多语言、模型可移植、可观测）之间，仍有很大距离。谁能率先做出一个开放、可移植，同时达到 Cursor 级 harness 质量的框架，谁就能吸引那批被“我得自己造”困住的开发者。

**[+++] 跨 agent 的 skill 分发标准** —— 三个独立项目（支持 52 个 agents 的 agent-install、带自动更新符号链接的 library-skills、skills.sh 生态）都验证了 skill 可移植性的需求。但标准 manifest 仍然不存在。第一个推出可被 Claude Code、Cursor、Codex、Hermes 等原生读取的规范的团队，就会成为 agent skills 的包管理器。

**[++］ 围墙花园之外的 agent 身份与治理** -- Agent 365 解决了 Microsoft 内部的治理问题。［@OfficialTravlad](https://x.com/OfficialTravlad/status/2050274260522774573) 和 [@GroverLovesh](https://x.com/GroverLovesh) 共同确认了一个缺口：可跨云、可跨独立栈、可跨协议迁移的 agent identity。Google 已在 GCP 内部为 agent identity 花了 $750M。跨云、协议级的解决方案仍然空缺。

**[++] Harness 可观测性与调试工具** —— 单条 steering instruction 导致 12% 基准波动，加上 AHE 的消融结果（收益来自 tools/middleware/memory，而非 prompts），说明实践者无法预测或调试 harness 与模型之间的相互作用。面向 harness engineering 的专用可观测性——展示配置选择如何影响模型行为——仍是一个未被满足的需求。

**[+］ 取代订阅制的个人 agent 基础设施** -- ［@thegreatola](https://x.com/thegreatola/status/2050267709837861021) 证明，可以用一个部署在 VPS 上、月成本 $5-15 的个人 agent，替代每月 $200+ 的 AI 订阅。这个模式（Hermes + OpenRouter + Telegram + 自定义 skills）可以复现，但部署门槛仍然很高。把它产品化为一键式个人 agent 部署，是一个正在浮现的机会。

## 8. 要点总结

1. **Flue（1,255 次收藏、102K 次浏览）发布了首个 agent harness 框架，将“framework vs SDK”确立为 agent 基础设施的下一个前沿。** 该项目出自 Astro creator 之手，将 sessions、subagents 和 sandboxes 设为一等原语，并提供 `flue build` 和 `flue run` CLI——把 Web 框架模式引入 agent 开发。([来源](https://x.com/FredKSchott/status/2050274923852210397))

2. **Microsoft Agent 365 进入 GA，成为首个面向 agent identity、安全与治理的企业控制平面，也印证了“多数 agent 故障是身份/权限问题，而不是模型问题”这一判断。** 它把现有安全工作流扩展到所有 agents，包括使用自身凭据的 agents、shadow AI 发现，以及 Windows 365 沙箱环境。([来源](https://x.com/satyanadella/status/2050251014691840015))

3. **单条 harness steering instruction 就能让 Terminal Bench 波动 12%，而 AHE 论文证明自动进化出的 harness 比手工设计版本高出 5+ 分，这有力表明 harness engineering 的重要性已超过单纯的 prompt engineering。** 消融实验显示，收益来自 tools、middleware 和长期记忆——而不是 system prompts。([来源](https://x.com/Vtrivedy10/status/2050267113844048230), [来源](https://x.com/dntyk/status/2050164326795722836))

4. **Google 泄露的 COSMO 展示了一个完整的 Android agent OS：云端/本地混合推理、环境感知、voice match、可扩展 skills，以及 browser agent——把手机定位为持久的 agent runtime。** 其基于 skills 的架构及 Productivity/Information/Conversation 等分类，呼应了 coding agent 领域的 skill 模式，只是被移植到了移动端。([来源](https://x.com/minchoi/status/2050290896382353432))

5. **跨 agent 的 skill 分发开始固化为一个独立类别，三项彼此独立的发布（面向 52 个 agents 的 agent-install、带自动更新 symlink 的 library-skills、通过 skills.sh 分发的 ElevenLabs）都在推动这一方向，但整个生态仍无统一 manifest。** skill 路径的碎片化（~/.claude/skills vs ~/.agents/skills vs agent-specific locations）是当前的主要约束。([来源](https://x.com/aidenybai/status/2050256170775122174), [来源](https://x.com/tiangolo/status/2050140168003146198))

6. **据报道，DeepSeek-V4-Pro 是首个“无需任何特殊配置”即可在基础 agent harness 中运行的 open-weight 模型，能以远低于 Claude 和 Codex 的成本，提供相近体验和 1M-token context。** 其将 KV cache 压缩到 10% 的混合注意力设计，使 agentic loop “足够快，也足够便宜，能够真正落地使用”——这改变了 open-weight 模型的竞争前沿。([来源](https://x.com/omarsar0/status/2050009901234282649))
