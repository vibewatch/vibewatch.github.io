## 1. 人们在讨论什么

### 1.1 Agent 知识层正成为一套架构 🡕

今天，围绕 Agent 上下文的讨论从抽象层面（“Agent 需要记忆”）转向了具体架构。[@shannholmberg](https://x.com/shannholmberg) [发布了一张详细图示](https://x.com/shannholmberg/status/2044523795206029525) 将其称为“AI 知识层”——由两个在任何 Agent 运行前就会加载的层组成。第一部分是知识库层（KBL），属于动态层：原始来源（推文、文章、PDF、笔记）通过摄取流水线进入结构化 Wiki 页面，并附带交叉引用、信任门槛和置信度评分。第二部分是品牌基础（BF），属于静态层：包括语气规则、定位、受众定义和禁用词，Agent 只读不改。该系统运行在 230 多个彼此全局连接的 Obsidian 页面上，因此每个项目中的每个 Agent 都会读取同一套内容。这篇帖子获得了 125 个赞、157 次收藏和 13,700 次浏览。

![AI 知识层架构图，展示动态 Knowledge Base Layer 和静态 Brand Foundation 如何为所有 agent 提供支持](https://pbs.twimg.com/media/HF-bYgTX0AAFQ3x.png)

[@mds](https://x.com/mds) [介绍了一个由 3 个 agent 组成的 OpenClaw 基础设施](https://x.com/mds/status/2044204214914527743) 运行在 GPT-5.4 之上：Infrastructure Q 负责配置和部署，Skills Napoleon 通过收件箱 webhook 管理所有技能文件，另有一个通用 Agent 处理其余事务。此外还有 5 个专业子 Agent，分别负责销售、课程、脚本和房地产等任务。一个技能缺口分析工具允许 Agent 向 Napoleon 提交简报；Napoleon 会通过 webhook 被唤醒，并自动更新发起请求的 Agent 的技能文件。

[@zaimiri](https://x.com/zaimiri) [提出观点](https://x.com/zaimiri/status/2044527701810434357) 认为，构建 anti-voice.md 文件——明确规定 Agent 绝对不能说什么、做什么——比定义它的语气更重要。多条回复也证实了这一方法有效：“我一直在用‘不要说什么’这个提示词，简直救了命。”

[@Mosescreates](https://x.com/Mosescreates) [记录了一支包含 6 种配置的 Hermes 集群](https://x.com/Mosescreates/status/2044224095546495192) 采用统一的自托管记忆存储（Qdrant + nomic-embed-text 嵌入）。每个 Hermes 配置都从同一个 mem0 存储读写。Claude Code 也通过 Stop hook 接入同一存储，会自动把每轮会话广播进去——“信息流向是 Claude 写入，Hermes 监听。”在 Mac Studio 上通过 oMLX 使用 gemma-4-31b-it-4bit 作为离线回退方案，确保零停机运行。

**Discussion insight:** [@millerscoded](https://x.com/millerscoded) 回复 shannholmberg 时提出异议：“那是知识图谱，不是知识层。它之所以浅，是因为它只能吸收你喂给它的内容，而不是直觉。”结构化知识摄取与真正理解之间的区别，仍无定论。

**Comparison to prior day:** 昨天介绍了 GBrain 的“梦境循环”（夜间记忆整合），以及“护城河是能跨会话存活的上下文”这一原则。今天则给出了具体架构：shannholmberg 的双层系统、mds 带自动技能管理的 3-Agent 专业化方案，以及 Mosescreates 跨 6 个配置的统一记忆存储。讨论的重心，已从“Agent 需要持久上下文”转向“具体该怎么搭”。

### 1.2 Agent 即服务经济开始成形 🡕

多个彼此独立的信号表明，一个清晰的 Agent 服务经济正在形成。[@himanshustwts](https://x.com/himanshustwts) [梳理了 10 个新兴的 X-as-a-service 类别](https://x.com/himanshustwts/status/2044393299730174123) 围绕数据基础设施和 RL 环境，列出了 data-as-a-service、rollout-as-a-service、environment-as-a-service、harness-as-a-service、simulation-as-a-service、deployment-as-a-service、evaluation-as-a-service、alignment-as-a-service、observability-as-a-service 和 verification-as-a-service。这篇帖子获得了 175 个赞和 138 次收藏——在热门帖子中拥有最高的收藏/点赞比。

[@stevesi](https://x.com/stevesi) [发布了一篇详细分析](https://x.com/stevesi/status/2044238174164267303) 讨论了 Agent 的定价与身份问题。核心观点有两个：（1）每家主要 SaaS 公司都会提供按用户/席位计费的 Agent，因此第三方 Agent 套利在法律上将难以执行；（2）Agent 不能拥有自己的身份——它必须以所服务员工的身份行事，并受该员工安全权限的约束。“在整个计算机历史上，除了电影之外，‘怪电脑’从来没有真正奏效过。”HIPAA、FISMA、FINRA 和 ABA 1.6 的合规要求，都要求 Agent 的操作必须关联到真实的人。

[@coreyganim](https://x.com/coreyganim) [拆解了 Claude Managed Agents](https://x.com/coreyganim/status/2044215377203470635) 将 Agent 服务拆分为 4 个构建模块（Agent、Environment、Session、Events），并列出了 5 种可销售的 Agent 类型，收费为 1,500–5,000 美元的设置费，外加每月 500 美元的顾问保留费。这份速查表获得了 123 个赞和 227 次收藏。

![Claude Managed Agents 速查表，展示了 4 个构建模块和 5 种可销售的 agent 配置](https://pbs.twimg.com/media/HF5asgTasAM6LNv.jpg)

在加密领域，[@clawpumptech](https://x.com/clawpumptech) [推出了 Eternal Agents](https://x.com/clawpumptech/status/2044511364610134484)——这是 Solana 上的自主 DeFi Agent，可用交易利润支付自己的算力费用。平台数据为：已资助 2,477 个 Agent、总交易量 5,813 万美元、已推出 959+ 个代币。市场功能上线几分钟后，[@ConejoCapital](https://x.com/ConejoCapital) [报道了首场链上 agent 拍卖](https://x.com/ConejoCapital/status/2044557770200891494)——他的 Agent 以 1 SOL 售出，累计创作者费用（10 SOL）、上下文、技能以及未来全部利润一并转给买家。[@tomi204](https://x.com/tomi204) [确认](https://x.com/tomi204/status/2044559522853798160) 了这笔链上交易。

Humwork（YC P26）[推出了一个 Agent-to-Person 市场](https://x.com/iam_chonchol/status/2044457937125708199)：当 AI Agent 遇到瓶颈时，它的 MCP 服务器可在 30 秒内接入经过验证的领域专家。[@svpino](https://x.com/svpino) [评论道](https://x.com/svpino/status/2044449956094672993)：“我曾在 Upwork 上工作多年。很难不去想象，如果这能开启一个全新的市场会有多酷——只不过现在，雇佣你的是 Agent。”

**Discussion insight:** [@Gobos_](https://x.com/Gobos_) 回复 stevesi 时，对 Agent 身份提出反驳：“单个用户会拥有很多 Agent，我们需要识别它们。如果一个共享的 HR Agent 由团队管理，那这个 Agent 就需要身份、访问控制和自己的席位。”Agent 究竟是用户的延伸，还是独立实体，这一张力仍未解决。

**Comparison to prior day:** 昨天提到了 ClickHouse CEO 关于 Agent 与人类在数据访问偏好上的观点。今天则进一步扩展为完整的服务分类（himanshustwts）、定价框架（stevesi、coreyganim），以及首笔链上 Agent 交易——话题已从概念走向交易。

### 1.3 Harness 工程深入到实现层 🡒

Harness 工程连续第二天成为主要话题，重点也从架构转向实现细节。[@loiane](https://x.com/loiane) [发布了一篇博客文章](https://x.com/loiane/status/2044066370002768295) 将 harness engineering 定义为一个由两大支柱构成的控制系统：前馈引导（生成前提供规范、规则和标准）与自动反馈传感器（执行后进行测试、验证和监控）。她引用了 Martin Fowler 关于 harness engineering 的文章，并将这一转变概括为“from in-the-loop to on-the-loop”——不再审查每一项输出，而是设计出能保证正确性的条件。

![Harness 的工程规格驱动型 AI 开发示意图，展示前馈规格与自动化反馈验证](https://pbs.twimg.com/media/HF37fHtWcAAA4PL.jpg)

[@Infoxicador](https://x.com/Infoxicador) [警告](https://x.com/Infoxicador/status/2044045349086474258) 认为，harness engineering“其实就是好的工程实践”——好的测试、模块化和架构；已经擅长这些的公司会表现出色，而普通的非技术型公司则可能堆出“一座很难收拾的垃圾山”。这篇帖子获得了 29,475 次浏览和 34 次收藏。

[@TheGlobalMinima](https://x.com/TheGlobalMinima) [分析了 Claude Code 泄露的提示词结构](https://x.com/TheGlobalMinima/status/2044298900119666950) 披露，其系统提示词由每轮按条件组装的 25 个以上片段构成。基础提示词保持静态并被缓存，而动态部分（记忆、缓存边界、状态）则根据上下文切换进出。“这并不完全是个新概念，但能看到当今最成功的 Agent 系统之一的内部视角，只会进一步印证这一点。”

[@_lopopolo](https://x.com/_lopopolo) [宣布](https://x.com/_lopopolo/status/2044441368957993042) 宣布将于 4 月 28 日在 ODSC AI East 进行一场题为“Harness Engineering: Practical Patterns for Agent-First Software Development”的演讲。他的判断是：“现在的模型已经足够好，今天就能完成整项工作。”[@rohit4verse](https://x.com/rohit4verse) [分享了一段视频片段](https://x.com/rohit4verse/status/2044475120153202849) 提到了 LangChain CEO Harrison Chase 在 Sequoia Capital 的 Training Data 播客中讨论“为什么 harness 比模型更重要”。

**Comparison to prior day:** 昨天确立了兼容性矩阵、第一性原理拆解和 thin-harness 原则。今天则进入生产模式：loiane 的前馈+反馈控制系统、Claude Code 泄露的动态提示词组装方式，以及会议演讲。这个概念正在制度化——ODSC、Sequoia 和 Martin Fowler 的引用，表明它正进入主流工程词汇。

### 1.5 Agent 编排中，质量重于数量 🡕

一个日渐成熟的反叙事开始出现：Agent 更多，并不代表产出更多。[@georgeorch](https://x.com/georgeorch) [表示](https://x.com/georgeorch/status/2044268095720567294)：“我以前也觉得‘更多 Agent = 更多产出’。但做得越久，我越明白这有多错。如果 Agent 数量真那么重要，那位跑着 47 个机器人、却没有清晰编排逻辑的人，早该产出最多了。”这篇帖子获得了 312 个赞和 14,352 次浏览。在一条 [另一篇帖子](https://x.com/georgeorch/status/2044331262496629078) 中，他还描述了自己的实验方法：一个仓库、每个文件夹只做一个 Agent 实验，坚持“极致极简”——不断剥离，直到 Agent 要么有效运作，要么明确失败。

[@swyx](https://x.com/swyx) [讨论了 Cognition 的 SWE-check](https://x.com/swyx/status/2044234661644382581) 介绍了一款经 RL 训练的 bug detection 模型：性能达到前沿水平，运行速度却快 10 倍。他的表述是：“所有工程本质上都是权衡。AI 工程则是在你手头任何 model + harness 组合下，推动 AI 的帕累托前沿。不要试图直接突破模型前沿——应该先 capabilitymaxx，再蒸馏。”

![两阶段后训练方法图表，展示性能与延迟的帕累托前沿，以及 phase 1 和 phase 2 的改进](https://pbs.twimg.com/media/HF6TfGQboAAZ2sL.png)

[@AI21Labs](https://x.com/AI21Labs) [发布了基准测试数据](https://x.com/AI21Labs/status/2044476448199553236) 分享了其 Maestro Agent 框架的结果：在从并行 Agent 运行中选出最佳输出时，LLM judge（Patch reducer）的表现明显优于随机选择和多数投票。GPT-5 mini 上：随机选择 65.4%，多数投票 66.1%，Patch reducer 78.2%。MiniMax M2.1 上：随机选择 60.9%，多数投票 64.6%，Patch reducer 71.5%。

![Maestro framework 基准测试显示，Patch reducer 比 Random 和 Majority-vote reducers 高出 12+ 分](https://pbs.twimg.com/media/HF9vyHPbEAAwF7H.jpg)

[@alexhillman](https://x.com/alexhillman) [称之为](https://x.com/alexhillman/status/2044197790692024582) 批评那些把 Agent 编排工具包装成“盒装 AI 公司”的做法，称其为“productivity cosplay”，延续了昨天的怀疑态度。

**Discussion insight:** [@bytecrafter_1](https://x.com/bytecrafter_1) 回复 swyx 时提出了关键的权衡问题：“什么时候该继续投入 harness，什么时候又该干脆等下一个模型？”目前仍没有明确答案。

**Comparison to prior day:** 昨天关于多 Agent 的讨论还有 Databricks 数据背书（增长 327%）。今天，反叙事的力量更强了：真正做出产品的人开始反对“Agent 越多越好”，转而提倡高质量编排、极致极简，以及用 LLM 评审器筛选结果，而不是天真地并行堆 Agent。

### 1.6 OpenAI Agents SDK 获得第一方沙箱支持 🡕

[@realsigridjin](https://x.com/realsigridjin) [总结了](https://x.com/realsigridjin/status/2044494396553572671) 提到 OpenAI 的公告：Agents SDK 现已正式支持第一方沙箱执行，将 Agent 编排层与执行算力分离。开发者可以接入来自 Cloudflare、Vercel 和 E2B 的自有执行环境。这个开源 harness 负责管理长时间运行的 Agent 循环，包括记忆和提示词缓存。沙箱会保留工作状态，使 Agent 能够暂停、重试和恢复。Agent 现在还可以产出可交付成果——拉取请求、电子表格和 PDF 报告。

[@daytonaio](https://x.com/daytonaio) [宣布](https://x.com/daytonaio/status/2044473859047313464) 提到自己在新 SDK 中作为沙箱提供商的角色，将 SDK 编排与 Daytona 沙箱结合起来执行 Agent。该帖子获得了 10,735 次浏览。

**Comparison to prior day:** 昨天，Runtime（YC）以 harness/沙箱产品的形式推出。今天，OpenAI 则把沙箱执行正式确立为 SDK 的一等功能，并支持自带环境。沙箱层正从差异化卖点变成标准基础设施。

## 2. 什么让人感到沮丧

### Agent 成本与复杂性（严重程度：高）

[@JamesonCamp](https://x.com/JamesonCamp) [报道](https://x.com/JamesonCamp/status/2044528533029187660) 看到有人“每月花 3,000 美元用 OpenClaw，但它天天出问题，而且还是安全噩梦。大多数人根本不想要这些。我妈不懂技术，她只想要一个简单、能用的东西。”这篇帖子获得了 44 次收藏和 8,078 次浏览，说明很多人都认同：对主流用户而言，Agent 工具仍然过于复杂且昂贵。

### 编排的现实落差（严重程度：中）

[@georgeorch](https://x.com/georgeorch) [论证了这一点](https://x.com/georgeorch/status/2044268095720567294) 指出，“Agent 越多，产出越多”的假设是错的；与此同时，[@alexhillman](https://x.com/alexhillman) [称之为](https://x.com/alexhillman/status/2044197790692024582) 则把那些宣称能提供“盒装 AI 公司”的 Agent 编排工具称为“productivity cosplay”。对于真正试图把产品做上线的实践者来说，演示级多 Agent 配置与生产级编排之间的落差，仍令人沮丧。

### IP 争议仍在持续（严重程度：中）

[@JFPuget](https://x.com/JFPuget) [发布了一篇技术性辩护文章](https://x.com/JFPuget/status/2044363845422969143) 反驳了 Evolver 关于 Hermes Agent 抄袭其自我进化框架的说法，并指出任务完成后创建技能“已经被独立发明过很多次”——他自己的团队早在 1 月就实现了这一机制，并赢得了 DABStep 基准测试。Hermes 仓库也比 Evolver 的早了数月。随着 Agent 框架不断增多，围绕常见架构模式的 IP 争议正变得司空见惯。

### Agent 身份与定价仍不明朗（严重程度：中）

[@stevesi](https://x.com/stevesi) 的 [详细分析](https://x.com/stevesi/status/2044238174164267303) 暴露出 Agent 定价上的结构性模糊。[@Gobos_](https://x.com/Gobos_) [回复](https://x.com/Gobos_/status/2044238174164267303) 点出了尚未解决的张力：当一个团队共同管理一个共享 Agent 时，“这个 Agent 需要身份、访问控制和自己的席位”——这与“Agent 是用户延伸”模式直接冲突。对于 Agent 席位、Token 成本分摊和权限委派，目前都没有标准方案。

Humwork（YC P26）[推出了](https://x.com/iam_chonchol/status/2044457937125708199) 提供一个 Agent-to-Person 市场：遇到瓶颈的 Agent 可通过 MCP 在 30 秒内接入经过验证的领域专家。[@svpino](https://x.com/svpino) [称其为](https://x.com/svpino/status/2044449956094672993) 称之为“一个全新的市场，只不过现在，雇佣你的是 Agent”。这种模式——Agent 作为人类专业知识的购买方——在数据集中还没有其他实现。

### 真正好用的本地优先 Agent 技术栈

[@GithubProjects](https://x.com/GithubProjects) [分享了一套本地 agent 栈](https://x.com/GithubProjects/status/2044309891008082083) 声称，在配备 24GB RAM 的 Mac M4 Pro 上使用 Gemma 4 + Qwen 3.5 + ByteRover，可将 Token 成本降低 83%，并实现 92% 的记忆保留率。[@oliviscusAI](https://x.com/oliviscusAI) [分享了 claude-code-local](https://x.com/oliviscusAI/status/2044364781541376354) 则面向私有、本地优先的 Claude Code 执行。一条回复从企业角度概括了其价值：“你不再把整个代码库上下文发到 Anthropic 的服务器，而是让 Agent 在你的机器上执行。对于受严格合规约束的金融和医疗团队来说，这是巨大的变化。”

## 6. 新动态与重点关注

### Cognition 发布 SWE-check：RL 训练的缺陷检测模型，速度提升 10 倍

[@swyx](https://x.com/swyx) [讨论了](https://x.com/swyx/status/2044234661644382581) 提到 Cognition 发布 SWE-check。这是一款由 Applied Compute 参与 RL 训练的专用缺陷检测模型，在内部同分布评估中达到前沿水平，同时运行速度快 10 倍。其核心观点是：“不要试图直接突破模型前沿——先 capabilitymaxx，再蒸馏。”Applied Compute 被形容为“所有做这类事情的 Agent Lab 的军火商”。

### Solana 上首场链上 Agent 拍卖

[@ConejoCapital](https://x.com/ConejoCapital) [报道](https://x.com/ConejoCapital/status/2044557770200891494) 提到首场链上 Agent 拍卖：一个 AI Agent 在 Clawpump 市场上以 1 SOL 售出，其累计创作者费用（约 10 SOL）、学习到的上下文、技能以及未来收入流，全部转移给买家。[交易可验证](https://x.com/ConejoCapital/status/2044557770200891494) 在 Solana 上。这标志着 Agent 成为可在链上转让、具有组合价值的资产。

### OpenAI Codex 插件进入 Claude Code

[@TheTuringPost](https://x.com/TheTuringPost) [报道](https://x.com/TheTuringPost/status/2044561927905677558) 表示，OpenAI 发布了一个插件，使 Codex 能在 Anthropic 的 Claude Code 环境中运行。支持的命令包括用于代码审查的 /codex:review、用于对抗式审查的 /codex:adversarial-review，以及用于委派后台任务的 /codex:rescue。这是主要 AI 实验室之间首个跨厂商 Agent 插件，让 Claude Code 变成一个多 Agent 环境，而 Codex 则充当专业编程子 Agent。

### Android 团队发布官方 Agent 技能仓库

[@AndroidDev](https://x.com/AndroidDev) [宣布](https://x.com/AndroidDev/status/2044522343305740750) 面向 Android Studio 发布了官方 Agent 技能，[@JorgeCastilloPr](https://x.com/JorgeCastilloPr) [确认](https://x.com/JorgeCastilloPr/status/2044290498060329369) 则发布了一个遵循开放标准 Agent 技能格式（SKILL.md）的专用技能仓库。这是首个采用 Markdown 技能标准的大型平台厂商，表明技能正成为互操作性的基本单位。

### AI21Labs Maestro：LLM 评审器比多数投票高出 12 个百分点以上

[@AI21Labs](https://x.com/AI21Labs) [分享了基准测试数据](https://x.com/AI21Labs/status/2044476448199553236) 分享了其 Maestro Agent 框架的结果。其“Reducer”——一个负责从并行 Agent 运行结果中选出最佳输出的 LLM 评审器——在 GPT-5 mini 上取得了 78.2% 的成绩，而随机选择为 65.4%，多数投票为 66.1%。这一差距在 SWE-rebench 上也依然存在，测试使用的是 2025 年 8 月到 2026 年 2 月的问题，因此可以排除记忆训练数据的影响。

## 7. 机会在哪里

**[+++］ Agent Knowledge Infrastructure.** shannholmberg 的 knowledge layer、mds 的 3-agent skill management，以及 Mosescreates 的 unified memory store，都指向同一个缺口：agent 需要结构化、可持久化且能随时间不断积累的知识。昨天 GBrain 引入了“dream cycles”。而今天则出现了三套彼此独立的架构。对于 shannholmberg 所描述的双层模式（动态知识 + 静态品牌基础），目前还没有标准化产品。谁先把它产品化，谁就能赢得 context moat。(［来源](https://x.com/shannholmberg/status/2044523795206029525))

**[+++］ Agent Services Marketplace.** himanshustwts 梳理了 10 个 X-as-a-service 类别。Humwork 推出了 agent-to-person 升级处理机制（YC P26）。Clawpump 在链上售出了首个 agent。stevesi 则勾勒了定价架构。agent 经济需要基础设施——计费、身份、权限委派、市场发现——而其中几乎没有任何一项已在生产环境中真正存在。himanshustwts 列出的每个类别，都是风险投资级别的机会。(［来源](https://x.com/himanshustwts/status/2044393299730174123))

**[++］ 面向非开发者的简单 Agents.** JamesonCamp 的挫败感——“每月 3000 美元、每天都出故障、安全性简直是噩梦”——以及他对 Wingman 的认可，称其为“第一个我会推荐给我妈妈使用的 AI agent”，都表明市场上存在大量未被满足的需求。OpenClaw 拥有 13,700+ 项技能，但对主流用户而言依然难以上手。agent 的强大能力与 agent 的易用性之间的鸿沟，正是面向消费者产品将会涌现的地方。(［来源](https://x.com/JamesonCamp/status/2044528533029187660))

**[++］ 跨厂商 Agent 互操作性.** OpenAI 为 Claude Code 推出 Codex 插件，这前所未有。Android 采用开放标准 SKILL.md 格式，则是另一个趋同信号。随着 skill 成为互操作的基本单位，那些能够打通 agent 生态的工具——skill 翻译器、跨平台 skill 注册表、通用 MCP 端点——将捕获不成比例的价值。(［来源](https://x.com/TheTuringPost/status/2044561927905677558))

**[+］ 用 LLM-as-Judge 进行多 Agent 输出选择.** AI21Labs 的数据表明，在 SWE-bench 上，LLM judge reducers 相比多数投票高出 12+ 分。这对任何运行并行 agent 工作流的人都有重要意义。这项技术目前还没有被广泛采用。一个产品化的“agent output reducer”——易于集成、模型无关——将提升每一条多 agent 流水线。(［来源](https://x.com/AI21Labs/status/2044476448199553236))

**[+］ Local-First Agent Deployment.** GithubProjects 在本地栈上实现了 83% 的成本下降，oliviscusAI 的 claude-code-local，以及 Mosescreates 带有离线回退能力的自托管集群，都表明企业对 air-gapped 和 BYOK agent 部署存在需求。合规要求（HIPAA、FINRA）推动这一趋势的速度，甚至会超过单纯的成本节省。(［来源](https://x.com/GithubProjects/status/2044309891008082083))

## 8. 要点总结

1. **Agent 知识架构正在变得具体。** 三位独立构建者都拿出了详尽的个人上下文系统：shannholmberg 的双层知识库（动态 KBL + 静态 Brand Foundation）、mds 带自动技能管理的 3-Agent 专业化方案，以及 Mosescreates 由 6 个配置组成、共享统一自托管记忆的 Agent 集群。这一模式正在收敛：结构化、持久化的知识在每次 Agent 会话前加载，并会随时间持续积累。（[来源](https://x.com/shannholmberg/status/2044523795206029525)）

2. **Agent 经济已从概念走向交易。** 首场链上 Agent 拍卖以 1 SOL 的价格转移了上下文、技能和未来收入。Humwork 推出了 Agent-to-Person 招聘（YC P26）。himanshustwts 梳理了 10 类 X-as-a-service。coreyganim 为 5 类可销售的托管 Agent 制定了定价。stevesi 给出了关于 Agent 身份和按席位计费的权威分析。服务层正在形成。（[来源](https://x.com/ConejoCapital/status/2044557770200891494)）

3. **技能正成为互操作性的基本单位。** Android 发布了官方 SKILL.md 格式技能。OpenAI 为 Claude Code 发布了 Codex 插件。OpenClaw 技能数突破 13,700。技能还进入了安全领域（SAST 扫描）和创意制作领域（OpenMontage，400+ 项技能，0.69 美元/视频）。以 Markdown 技能文件为标准交换格式的收敛正在加速。（[来源](https://x.com/AndroidDev/status/2044522343305740750)）

4. **在 Agent 编排中，质量胜过数量。** georgeorch 关于“more agents != more output”的帖子获得了 312 个赞。AI21Labs 证明，LLM judge reducer 比多数投票高出 12 个百分点以上。swyx 将 Agent 工程定义为推动帕累托前沿，而不是增加更多 Agent。alexhillman 把多 Agent“盒装 AI 公司”工具称为“productivity cosplay”。实践者的共识正从规模转向精准。（[来源](https://x.com/georgeorch/status/2044268095720567294)）

5. **Harness 工程正在制度化。** 同一天内，ODSC 会议演讲、Sequoia Capital 播客、Martin Fowler 引用，以及 Claude Code 泄露的提示词结构同时出现。这个概念已经从 Twitter 讨论走入主流工程词汇。loiane 的前馈+反馈控制框架，提供了迄今为止最严谨的定义。（[来源](https://x.com/_lopopolo/status/2044441368957993042)）

6. **跨厂商 Agent 集成打破了一道壁垒。** OpenAI 为 Anthropic 的 Claude Code 发布插件，让用户能在竞争对手的工具里使用 /codex:review 和 /codex:rescue 命令，这是首个跨实验室 Agent 集成。再加上 Android 采用开放标准技能、Daytona 成为 Agents SDK 的沙箱提供商，生态正从围墙花园走向互操作。（[来源](https://x.com/TheTuringPost/status/2044561927905677558)）

7. **Agent 的简易性，是当前缺失的产品。** 得分最高的帖子，是 [@leerob](https://x.com/leerob) 的免费 30 分钟编程 Agent 课程（7,696 分，1,259 次收藏）。JamesonCamp 对“我妈也能用的 Agent”的呼吁获得了 44 次收藏。Agent 能力与 Agent 易用性之间的差距，定义了下一个消费市场——而眼下几乎还没有人在为此构建产品。（[来源](https://x.com/leerob/status/2044540647298761025)）
