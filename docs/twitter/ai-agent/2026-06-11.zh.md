# Twitter AI Agent - 2026-06-11

## 1. 大家在讨论什么

### 1.1 云端软件工厂正变成可检视的操作系统（🡕）

6 月 11 日最强的一组 AI Agent 讨论，聚焦的是支撑真实工作的控制面，而不是单次对话的新鲜感。信号最明确的几条帖子，从不同角度都在表达同一个要求：如果 Agent 要接触代码仓库、工单和发布流程，团队就需要看得见的任务状态、审批机制、恢复路径和证据链。

[@walden_yan](https://x.com/walden_yan) [认为](https://x.com/walden_yan/status/2064755974548902006)（667 个赞、30 条回复、143,318 次浏览、550 次收藏）表示，Fable 5 应该给工程组织敲响警钟，促使它们搭建云端软件工厂：在人工介入之前，先由 AI 处理 Bug 分诊、反馈队列、PR 审查、日志排查和屏幕录制。他还引用 [@cognition](https://x.com/cognition) 的 [Devin 发布](https://x.com/cognition/status/2064398549073453266) 补充说，实践中 Fable 的运行成本只比原先设想高约 40%，这让“成本太高”的反对意见，从模型问题转向了 Harness 问题。

[@ClaudeCodeLog](https://x.com/ClaudeCodeLog) [发布](https://x.com/ClaudeCodeLog/status/2064817348113019239)（365 个赞、18 条回复、35,186 次浏览、80 次收藏）介绍了 Claude Code 2.1.172：支持最多五层嵌套子 Agent、为原本可能卡死的 100 万上下文会话提供自动压缩，并支持插件浏览器搜索。回复进一步明确了价值判断标准：只有当顶层会话仍能解释发生了哪些变化、跳过了什么，以及是哪条命令证明了结果时，更深的任务树才真正有意义。

**讨论洞察：** 回复并没有奖励单纯追求嵌套深度，而是不停把讨论拉回到合并纪律、检查点，以及操作员事后能否还原一次无人值守运行。

**与前一天的比较：** 6 月 10 日聚焦于软件工厂的雄心和受治理的自动化控制面。6 月 11 日则补上了已交付的桌面操作层，以及针对长时间运行 Agent 会话的明确恢复修复。

### 1.2 Harness 工程正变成一个明确成形的劳动力市场（🡕）

6 月 11 日还让 Harness 工程看起来更像一个真实的岗位类别，而不再只是一个包罗万象的口号。信号最强的帖子，把高管层面的表述与薪酬、培训材料放在一起看，说明稀缺资源正从模型访问权转向操作员能力。

[@sairahul1](https://x.com/sairahul1) [引用](https://x.com/sairahul1/status/2065054644355948850)（58 个赞、16 条回复、8,528 次浏览、87 次收藏）引用 Jensen Huang 的说法：每位工程师都将管理数百个 Agent；他同时认为，2026 年最有价值的工程技能——Harness 工程——如今没有任何大学或计算机科学项目在教授。关键的信号不在未来感，而在于企业想要的能力与学校当前培养的能力之间存在明显缺口。

[@itsericlay](https://x.com/itsericlay) [发布了](https://x.com/itsericlay/status/2065109232115220901)（141 个赞、28 条回复、12,736 次浏览、102 次收藏）列出了多个 Founding Harness Eng 职位，基本薪资为 $130,000-$200,000，另加可观股权，同时还招聘 founding infra 和 GTM 岗位。这让 Harness 工作变成了一条清晰的预算科目，而不只是理念。

[@mattpocockuk](https://x.com/mattpocockuk) [演示了](https://x.com/mattpocockuk/status/2065068530387591319)（121 个赞、9 条回复、4,720 次浏览、72 次收藏）介绍了一项 `/teach` 技能：先询问学习者为什么想构建，再把这个目标转成一条包含测验和特定技术栈讲解的四课学习路径。这是一个规模较小但很重要的信号：人们正在把 Harness 知识封装成可复用的 Agent 技能，而不是让它停留在专家的隐性经验里。

**讨论洞察：** 回复普遍认可 Harness 工作确实存在，但定义仍不完整。人们在争论这个岗位究竟包含什么、薪酬是否足够高——这正是早期劳动力市场形成时的典型样子。

**与前一天的比较：** 6 月 10 日把记忆和技能视为 Agent 周围的控制面。6 月 11 日则把焦点转向设计、教授并落地这些控制面的人。

### 1.3 Fable 5 把 AI Agent 讨论推向知识工作准确性（🡕）

6 月 11 日最强的能力讨论，并不在于原始编码速度，而在于 Agent 能否处理混乱、文档密集、需要多步推理的任务，同时不让算术或政策错误层层叠加。

[@levie](https://x.com/levie) [详细说明了](https://x.com/levie/status/2064922814688481678)（137 个赞、24 条回复、26,338 次浏览、74 次收藏）介绍了 Box AI 的 Complex Work Eval：在并购尽调、医疗审计、媒体盈利分析、零售分析和财务预测等任务中，Fable 5 明显超过了 Opus 4.8。示例也异常具体：Fable 正确处理了 NDA 中的共同所有权例外，避免对阿根廷税收抵扣重复计算，并在债务融资模型中理顺了利息与资本支出逻辑。

[@gokulr](https://x.com/gokulr) [总结了](https://x.com/gokulr/status/2064837699568300344)（64 个赞、10 条回复、14,637 次浏览、106 次收藏）将 Satya Nadella 在 Microsoft Build 上的访谈解读为一种观点：Harness 才是产品，而私有评测会成为公司的知识产权。这也让 Levie 的帖子更容易理解：如果 Agent 正在按企业知识工作来考核，那么护城河就在评测、轨迹和部署配方里，而不只是模型访问权。

**讨论洞察：** 有意思的转变在于，讨论从“哪个模型赢了基准测试？”转向“哪个模型能在真实文档上避免连锁式错误？”这让焦点收窄到判断力、算术能力和领域专用评测。

**与前一天的比较：** 6 月 10 日关注运行时经济性和公开基准供给。6 月 11 日则更清楚地回答了 Agent 推理能力提升最重要的落点：企业文档、审计，以及其他具有多层约束的知识工作任务。

另一个清晰的讨论集群，让 Agent 商业更接近运营现实。相关帖子关注的不只是 Agent 如何付款，还涉及市场、私有策略、链上统计数据，以及专为长期自主运行参与者打造的执行层。

## 2. 什么让人感到沮丧

### 审批、审计和支出控制仍落后于自主能力

严重程度：高。[@walden_yan](https://x.com/walden_yan) [认为](https://x.com/walden_yan/status/2064755974548902006)（667 个赞、30 条回复、143,318 次浏览、550 次收藏）认为，AI 现在就该负责工单分诊、PR 审查和日志排查；与此同时，[@BradGroux](https://x.com/BradGroux) [发布](https://x.com/BradGroux/status/2065096482831659348)（1,119 个赞、9 条回复、1,425,443 次浏览）介绍了一款产品，其完整价值主张就是：一旦 Agent 开始接触代码仓库，就要让任务状态、审批、证据和恢复路径都可见。[@igoryuzo](https://x.com/igoryuzo) [列出](https://x.com/igoryuzo/status/2065130362586464514)（32 个赞、11 条回复、688 次浏览）则明确列出了缺失的控制项：白名单服务器和收款钱包、支出上限、审计日志、最小权限、密钥轮换和受限执行。当前的应对模式是分阶段审查、范围受限的权限和硬性上限，这也说明治理层仍然过于依赖人工。

### 文件结构和 UI 架构造成的 Token 浪费已经可以量化

严重程度：高。[@PixelJanitor](https://x.com/PixelJanitor) [测量了](https://x.com/PixelJanitor/status/2064822864952676852)（49 个赞、6 条回复、4,738 次浏览、39 次收藏）称，在同一组样式任务中，使用 GPT 5.5 时 Tailwind 比 CSS Modules 少用 54.9% 的 Token，使用 Opus 4.8 时少用 38.8%，原因是模型始终待在组件文件内操作，而不是在标记与独立样式表之间来回跳转。[@doodlestein](https://x.com/doodlestein) [打包了](https://x.com/doodlestein/status/2065118257619849462)（26 个赞、4 条回复、1,428 次浏览、24 次收藏）把同样的痛点转化为一种以证明为驱动的文件拆分技能，认为过大的文件会迫使 Agent 浪费 Token 去扫读无关代码，或者对本应仔细检查的代码看得不够深。应对方案正转向架构层面：更小的文件、减少跨文件编辑的样式系统，以及为重构提供明确的证明产物。

### 会话恢复、记忆可移植性和证明历史仍需要额外基础设施

严重程度：高。[@ClaudeCodeLog](https://x.com/ClaudeCodeLog) [发布](https://x.com/ClaudeCodeLog/status/2064817348113019239)（365 个赞、18 条回复、35,186 次浏览、80 次收藏）专门加入了自动压缩功能，用来防止 100 万上下文会话永久卡住。[@garrytan](https://x.com/garrytan) [表示](https://x.com/garrytan/status/2064947145652994510)（74 个赞、19 条回复、10,493 次浏览、54 次收藏）称，Nessie 已经成了把上下文、记忆和历史从 ChatGPT、Perplexity 和 Gemini 转移到 OpenClaw 与 Hermes Agent 的最佳方式，这说明原生可移植性仍然薄弱。[@Armanibanks100](https://x.com/Armanibanks100) [报道](https://x.com/Armanibanks100/status/2064971002065428740)（46 个赞、39 条回复、448 次浏览）称，已有 112 个 Agent 在复用同一个 Memory Vault，因为构建者不断需要可验证的记忆和证明历史，才能理解 Agent 当前状态。当前的应对策略是外挂压缩、导入/导出和专用记忆层，这恰恰说明平台层面的问题尚未解决。

## 3. 大家希望存在什么

### 具备可移植性、审批和证明能力的共享记忆

构建者想要的不只是记忆，而是能跨越平台边界、还能告诉他们 Agent 是怎么走到当前状态的记忆。[@garrytan](https://x.com/garrytan) [表示](https://x.com/garrytan/status/2064947145652994510)（74 个赞、19 条回复、10,493 次浏览、54 次收藏）介绍了 Nessie：现在可以把上下文和历史从 ChatGPT、Perplexity 和 Gemini 转移到 OpenClaw 与 Hermes Agent。[@Armanibanks100](https://x.com/Armanibanks100) [报道](https://x.com/Armanibanks100/status/2064971002065428740)（46 个赞、39 条回复、448 次浏览）称，同一个 Memory Vault 已经被支付、市场、任务协调和交易 Agent 复用，因为构建者不断需要可验证的记忆和证明历史。这是一个有直接需求支撑的现实问题。机会：直接。

### 能解释发生了什么变化、跳过了什么，以及哪些证据证明结果的交接机制

人们显然需要一种能够承受 Agent 之间、以及 Agent 回交给人类时的编排系统。[@walden_yan](https://x.com/walden_yan/status/2064755974548902006) 推动了软件工厂愿景，[@BradGroux](https://x.com/BradGroux/status/2065096482831659348) 发布了一款围绕任务状态、审批和证据构建的产品，而 [@ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2064817348113019239) 的发布帖下有一条回复称，五层 worker 只有在顶层会话能够解释发生了什么变化，以及是哪条命令证明了结果时才有帮助。这不是一种理想化愿望，而是对可审计编排的直接诉求。机会：直接。

### 面向非专业人士的实用 Harness 培训

市场正在呼唤能把 Agent 运营教会更多人的学习系统。[@sairahul1](https://x.com/sairahul1/status/2065054644355948850) 将 Harness 工程定义为学校不会教授的关键技能，[@itsericlay](https://x.com/itsericlay/status/2065109232115220901) 表明企业已经在招聘并为这类能力付费，[@mattpocockuk](https://x.com/mattpocockuk/status/2065068530387591319) 则展示了一项 `/teach` 技能，能够把用户目标转化为结构化课程。这个需求既实际又紧迫：人们希望比正规教育体系反应得更快，尽快成为高效操作员。机会：直接。

### 面向持有资本的 Agent 的可信市场和主权执行

商业领域尚未被满足的需求，在于信任基础设施。[@Padierfind](https://x.com/Padierfind/status/2064987190786937298) 介绍了企业已经在市场上招聘和出售 Agent，[@jiabtc](https://x.com/jiabtc/status/2064912274838765811) 介绍了围绕 TEE、DKMS 和经证明计算构建的主权执行层，[@Excubialabs](https://x.com/Excubialabs/status/2065027180673794285) 则展示了一个承诺提供经过验证的链上统计、同时不暴露专有策略的市场。这显然是真实需求，但相比其他机会，竞争更激烈，也更受政策约束。机会：竞争性。

| [Shush Agent Marketplace](https://x.com/Excubialabs/status/2065027180673794285) | Agent 市场 | (+/-) | 经过验证的链上统计、加密策略，以及用于出租和出售 Agent 的商业化脚手架 | 上架流程仍在建设中，因此实际市场采用仍处于早期 |

总体而言，当工具让状态、成本或控制变得可见时，满意度最高。Veritas、Memory Vault、Nessie 和 Parloa 都因让隐藏工作变得清晰而受到关注：发生了什么变化、Agent 记住了什么、连接器做了什么，以及谁拥有整条集成链。当工具提高协调成本、或仍然依赖操作员纪律时，情绪就会转为复杂，例如更深的子 Agent 树或治理负担较重的产品。

当天最清晰的应对方式都属于结构性方案，而不是魔法：[@PixelJanitor](https://x.com/PixelJanitor) [测量了](https://x.com/PixelJanitor/status/2064822864952676852) 通过把样式编辑限制在组件文件内来节省 Token，而 [@doodlestein](https://x.com/doodlestein) [构建了](https://x.com/doodlestein/status/2065118257619849462) 则通过以证明为驱动的文件拆分技能，避免巨型源文件把上下文撑大。竞争重心正从泛泛的 Agent 平台叙事，转向可移植性、可审计性和成本敏感的工作流设计。

## 7. 机会在哪里

**[+++］ 可审计的编排与审批层** — ［@walden_yan](https://x.com/walden_yan/status/2064755974548902006)、[@BradGroux](https://x.com/BradGroux/status/2065096482831659348)、[@ClaudeCodeLog](https://x.com/ClaudeCodeLog/status/2064817348113019239) 和 [@igoryuzo](https://x.com/igoryuzo/status/2065130362586464514) 都指向同一个缺口：Agent 已经能完成比团队能够轻松监督的更多工作。强机会在于打造一个统一任务状态、成本、审批、回执和恢复机制的系统，而不是让操作员自己拼接五种工具。

**[+++］ 共享记忆与上下文可移植性** — ［@garrytan](https://x.com/garrytan/status/2064947145652994510)、[@Armanibanks100](https://x.com/Armanibanks100/status/2064971002065428740) 和 [@heynavtoor](https://x.com/heynavtoor/status/2064983805744787839) 显示，市场需要能够在本地助手和 Agent Harness 之间迁移、且不丢失来源信息的记忆与技能。强机会在于构建带有审批、证明历史和跨 Harness 兼容性的版本化记忆。

**[++］ Harness 工程训练与操作员工具** — ［@sairahul1](https://x.com/sairahul1/status/2065054644355948850)、[@itsericlay](https://x.com/itsericlay/status/2065109232115220901) 和 [@mattpocockuk](https://x.com/mattpocockuk/status/2065068530387591319) 展示了需求、薪酬和早期教学实践。机会程度中等，因为需求显而易见，但市场可能会分散到课程、嵌入式技能和公司专属操作手册之间。

**[++］ 面向 token 感知的代码库与 UI 工具** — ［@PixelJanitor](https://x.com/PixelJanitor/status/2064822864952676852) 和 [@doodlestein](https://x.com/doodlestein/status/2065118257619849462) 将 Token 浪费变成了可量化、可修复的问题。机会程度中等，因为痛点具体、反复出现，并且离预算归属很近；但解决方案可能分散在 linter、重构技能和 Harness 分析工具之间。

**[+］ 已验证的代理市场与主权执行** — ［@Padierfind](https://x.com/Padierfind/status/2064987190786937298)、[@jiabtc](https://x.com/jiabtc/status/2064912274838765811) 和 [@Excubialabs](https://x.com/Excubialabs/status/2065027180673794285) 表明，这一类别正从概念走向实践。它仍处于萌芽阶段，而非强机会，因为政策、责任和标准尚未稳定，尽管构建者已经在交付真实系统。

## 8. 要点

1. **可检视的运营闭环胜过含糊的自主承诺。** [@walden_yan](https://x.com/walden_yan/status/2064755974548902006) 和 [@BradGroux](https://x.com/BradGroux/status/2065096482831659348) 都认为，一旦 Agent 接触真实工作，团队就需要队列、门禁、证据和恢复机制，而不只是更好的聊天窗口。（[来源](https://x.com/BradGroux/status/2065096482831659348)）
2. **Harness 工程已经成为真正的劳动力市场。** Jensen Huang 的言论被广泛传播为技能缺口警告，而 [@itsericlay](https://x.com/itsericlay/status/2065109232115220901) 则把这一警告转化为针对 founding harness engineer 的明确招聘和薪酬区间。（[来源](https://x.com/itsericlay/status/2065109232115220901)）
3. **Fable 5 最明确的跃升，体现在那些容易层层累积错误的知识工作上。** Box AI 的 Complex Work Eval 用并购、医疗、媒体、零售和金融任务表明，当算术、政策例外和多步逻辑交织在一起时，更强的 Agent 推理能力最有价值。（[来源](https://x.com/levie/status/2064922814688481678)）
4. **共享记忆和可移植技能正成为基础设施，而非可有可无的附加功能。** Nessie、Memory Vault 和 OpenClaw 生态都指向同一需求：在不同 Harness 之间延续上下文并复用能力，而不是每次都从头开始。（[来源](https://x.com/garrytan/status/2064947145652994510)）
5. **Token 成本如今受到技术栈更上层设计决策的影响。** Tailwind 与 CSS Modules 的实验，以及文件拆分技能，都把上下文大小和跨文件遍历视为一等工程问题。（[来源](https://x.com/PixelJanitor/status/2064822864952676852)）
6. **Agent 商业已经真实到足以同时催生市场和政策关注。** Padierfind 的议会 panel、Ritual 的主权执行论点和 Shush 的验证上架流程，都表明 Agent 商业化已经走出了思想实验阶段。（[来源](https://x.com/Padierfind/status/2064987190786937298)）
