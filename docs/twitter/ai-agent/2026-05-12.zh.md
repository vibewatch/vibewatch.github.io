### 1.2 Context engineering 正在取代 prompt engineering，成为首要优化目标 🡒

另一组并行出现的帖子认为，普通 AI 用户与专家级用户之间的生产力差距，如今已不再是智力水平或提示词质量，而是他们维护了多少持久化上下文。相关常用词汇包括：AGENTS.md、CLAUDE.md、soul.md、品牌上下文文件、品味文件。

[@NainsiDwiv50980](https://x.com/NainsiDwiv50980) 将这一转变概括为：“提示词工程已经成了新版‘学会更快打字’。”他对比了普通用户（使用泛化的角色提示词）与高阶用户：后者会把品牌语气存进 `.md` 文件，保存自己不喜欢的输出示例，并建立可复用的上下文文件夹（908 次浏览、34 次转发）（[帖子链接](https://x.com/NainsiDwiv50980/status/2054095565517144369)）。[@DamiDefi](https://x.com/DamiDefi) 也向 11,237 次浏览的受众表达了同样的观点：“在糟糕上下文里的完美提示词，产出的仍然是泛化结果；而在优质上下文里的简单提示词，几乎可以胜过一切。”（[帖子链接](https://x.com/DamiDefi/status/2054099767861662040)）

[@oliverwhudson](https://x.com/oliverwhudson) 介绍了其团队如何不是靠改进提示词，而是靠建设上下文基础设施，每月产出 6,000 条广告——包括品牌上下文、领域上下文、Claude Skills 路由逻辑、参考文件系统、Notion MCP 集成和质量门禁。他们的报告技能每月可为每位创意策略师节省两天时间，而推理轨迹会记录每一次策略决策，使系统随时间持续积累能力（1,529 次浏览、34 次收藏）（[帖子链接](https://x.com/oliverwhudson/status/2054256998422843767)）。

[@mark_k](https://x.com/mark_k) 则指出了更深层的问题：AI 仍然要求用户不断把自己的意图翻译成机器友好的指令，而真正的突破口，是一种界面——人们可以直接说、展示、指、打断、纠正，而不必为了机器重新组织自己的想法（4,554 次浏览、47 条回复）（[帖子链接](https://x.com/mark_k/status/2054137790896484760)）。他还在回复中预测，未来会是由 AI 针对当前任务动态生成 UI。

**讨论洞察：** 最有实质内容的回复，把“上下文”这一主题进一步延伸到了工具层：Obsidian vault、N8N 工作流、CLAUDE.md 文件和多智能体记忆存储，都被视为实际实现方式。模式非常一致——持久化、机器可读的上下文文件会不断复利，而临时拼接的提示词最终会触顶。

**与前一天对比：** 5 月 11 日，上下文工程还只是 harness 清单中的一项；到 5 月 12 日，它已经成为最强的独立主题，从业者开始分享具体的文件化工作流和生产力数据。

## 2. 什么让人感到沮丧

### Harness 的复杂性仍然是主要成本中心

最主要的挫败感——而且与前几天一致——是模型能力的提升，并没有降低 harness 的工程负担。[@akshay_pachaar](https://x.com/akshay_pachaar/status/2053815461150859272) 点出了十项必备能力，并把每一项都视为独立学科；一条回复又补了三项。多种说法指向的实际结论是：如今用智能体做开发，已经需要与构建生产级 ML 系统一样的工程深度，包括缓存策略、可观测性、回退链和成本归因，而这些都不会因为模型更强就自动消失。严重程度：高。除了一项项把这些能力补齐之外，没有观察到其他解决办法。

### 从演示到生产的鸿沟，本质上是错误处理基础设施

[@gao035](https://x.com/gao035)（在回复 @gregisenberg 时，[帖子链接](https://x.com/gregisenberg/status/2054261832718889216)）写道：“没人讨论的差距：智能体在演示里能工作 ✅。智能体在生产里不能工作 ❌。差别 = 错误处理基础设施。”这条回复虽短，却尖锐地概括了一个系统性抱怨。严重程度：高。@gregisenberg 提到的应对方式包括：监控网关崩溃的 watchdog、失败后的自动恢复，以及在 cron 作业出错时给你发邮件的智能体。

### 长会话场景下，上下文管理仍然会在规模扩大后失效

[@aiDotEngineer](https://x.com/aiDotEngineer/status/2053996320629596372) 带出的层级记忆讨论提到，Arize AI 的 Sally-Ann Delucia 构建了一个智能体，它必须分析自己生成的轨迹数据；随着会话变长，朴素截断和显而易见的摘要策略都失效了。真正有效的是：保留头尾内容 + 可检索记忆存储 + 处理超大上下文的子智能体。严重程度：在长周期部署中为高。当前没有现成方案，从业者仍在自行构建定制策略。

### 对带钱包智能体的提示注入问题仍未解决

[@somi_ai](https://x.com/somi_ai) [融资](https://x.com/CoinMarketCap/status/2054016755182309649) 给出了这一风险最清楚的表述：“如果智能体被越狱，向随机地址打款，链上支付是追不回来的。”[@AgentPays_app](https://x.com/AgentPays_app) 也强调，欺诈检测需要把智能体理解为可信行为者，而不是威胁信号。这个风险是带自主支付能力智能体所特有的。严重程度：高。回复中没有提出缓解方案；Circle 虽然描述了护栏机制，但并未公开展示它在注入场景下的防护效果。

### AI 界面仍然要求用户把意图翻译成机器指令

[@mark_k](https://x.com/mark_k/status/2054137790896484760)（4,554 次浏览、47 条回复）说：“AI 现在仍然太像在和一个终端说话。”回复表明，这是一种广泛存在的挫败感。[@Mikey100200](https://x.com/Mikey100200) 提到，编辑照片时，用户必须用精确文字描述改动，而不是直接圈出目标区域。严重程度：中等。已有一些部分缓解方案（Grok Imagine、HyperFrames Inspector、Google 的实验性鼠标指针演示），但都还没有成为主流。

## 3. 人们希望出现什么

### 不需要在会话之间反复重建的持久化上下文基础设施

[@NainsiDwiv50980](https://x.com/NainsiDwiv50980/status/2054095565517144369) 和 [@DamiDefi](https://x.com/DamiDefi/status/2054099767861662040) 都在隐含地呼唤一种工具：能够自动构建并维护上下文基础设施——把品牌语气、历史输出、风格违规记录和受众偏好保存在持久文件中，并在每次会话时自动载入。现在的替代方案仍是手工操作：`.md` 文件、Obsidian vault、N8N 管道和 AGENTS.md 配置。人们想要的是一个无需用户亲自管理、就能自行组装并更新这些上下文的系统。机会：直接——上下文基础设施工具市场活跃，但仍未被满足。

### 一个能让技能作者真正变现的智能体应用商店

[@dotey](https://x.com/dotey/status/2054033818474950769)（3,208 次浏览、4 次收藏）明确提出了这一点：MCP 负责连接，Skills 负责知识，但最后一公里——用户编辑与垂直工作流——仍未解决。其类比对象是 VSCode 扩展与 Chrome 插件：应该允许社区贡献高质量的垂直技能并对其收费，因为现有的技能模式没有变现通路。[@dotey](https://x.com/dotey) 提到，他的 `baoyu-skills` 仓库已接近 20,000 个 GitHub stars，但从中赚到的钱是 $0。Skills 透明、易复制；如果出现一个带支付与知识产权保护的插件市场，激励结构就会改变。机会：直接，但有争议——skillsmp.com、ClawHub 和 Codex 的早期 marketplace 都只是部分尝试。

### 真正能解决客户问题，而不只是接电话的语音智能体

[@ArtificialAnlys](https://x.com/ArtificialAnlys/status/2054234919887573292) 发布的 tau-Voice 基准表明，即使最好的语音智能体，也只能解决 52.1% 的客服场景。虽然回复里没有从业者直接抱怨，但数据缺口已经非常明显：行业需要的是能覆盖大量长尾边缘情况的语音智能体——包括口音、噪声、多轮策略合规——而不是在一半通话上仍需转人工。机会：竞争激烈——各大 AI 实验室都在积极冲击这一基准。

### 能赢得企业信任的智能体治理与信誉基础设施

[@Conste11ation](https://x.com/Conste11ation/status/2054232381666578839)（45 次点赞、739 次浏览）表示：“多智能体系统无法靠尽力而为的编排赢得企业信任。它们需要确定性的底层基座，并且从设计上就能生成可审计记录。这个溯源层，正是当前智能体经济缺失的部分。”[@Altcoinist](https://x.com/Altcoinist/status/2054081104286568912) 对 Virtuals.io 的分析则从加密侧指出了同样的缺口：为智能体建立不可篡改的链上履历，能够支撑大规模自主网络中的信任。机会：对于重视安全的企业买家而言是明确机会；对于链上信誉系统而言，则更偏理想化方向。

## 6. 新动态与值得关注的内容

### DeepMind Co-Mathematician 以 47.9% 登顶 FrontierMath Tier 4

Google DeepMind 发布了 [arXiv:2605.06651](https://arxiv.org/abs/2605.06651)《AI Co-Mathematician：用 Agentic AI 加速数学家工作》。该多智能体系统基于 Gemini 3.1 Pro，并加入文献检索与代码执行层，在 FrontierMath Tier 4 上取得 47.9%，显著超过 GPT-5.5 Pro 的 39.6% 和 Claude 4.7 Opus 的 22.9%。基础模型单独得分仅为 19%；多智能体框架贡献了完整的 28.9 个百分点提升。该系统每题可获得最多 48 小时的异步计算，而 OpenAI 模型则在标准 web harness 上接受测试，因此这组对比并非完全同类。但即便如此，这仍然是迄今最明确的公开证据，证明多智能体框架在高难推理任务上能带来显著能力增量，而这不是任何单一模型配置本身所能提供的。由 [@hsu_steve](https://x.com/hsu_steve/status/2053969087559061737) 提及。

### Google 正把鼠标指针变成智能体界面

[@GoogleDeepMind](https://x.com/GoogleDeepMind) 发布了实验性演示，重新想象这枚已有 50 年历史的鼠标指针，将其变成 AI 界面——用户只需指向屏幕元素，再说出自然简短的话（“修这个”“把那个移过去”），就能直接在屏幕上指挥 Gemini，而无需打开提示框。[@minchoi](https://x.com/minchoi/status/2054324208772038996) 将其形容为“提示框正在死去”。这些演示仍处于实验阶段，似乎尚未进入任何已发布产品，但它们是目前最具体的公开信号之一，表明大型 AI 实验室正在积极解决 [@mark_k](https://x.com/mark_k/status/2054137790896484760) 所指出的“意图翻译成本”问题。

### Cisco DefenseClaw 扩展至支持 9 个编码智能体

[@AISecHub](https://x.com/AISecHub/status/2053921989883052038) 报道称，Cisco DefenseClaw（Apache-2.0，Cisco 官方项目）现已支持 9 个编码智能体：Claude Code、OpenAI Codex、Cursor、Windsurf、Gemini CLI、GitHub Copilot、Hermes、OpenClaw 和 Zeptoclaw。该产品会检查每个智能体发出的每一次提示、补全和工具调用，然后按连接器执行阻止、批准或审计。一次性覆盖 9 个智能体，表明 Cisco 将智能体安全治理视为横向基础设施层，而不是单个智能体的附属功能。巧的是，就在同一天，[@DarkNavyOrg](https://x.com/DarkNavyOrg/status/2054094369192603950) 展示了一条针对 Claude Code 的有效利用链：通过把网页内容探索与其他漏洞组合起来，绕过权限检查。

### Anthropic Managed Agents 新增 Dreaming、多智能体编排、Outcomes 和 Webhooks

[@Alina_with_Ai](https://x.com/Alina_with_Ai/status/2054043269525631465) 和 [@JulianGoldieSEO](https://x.com/JulianGoldieSEO/status/2054026273962308063) 都提到了 Claude Managed Agents 的一次升级，新增四项功能：多智能体编排，用于把任务委派给专门的子智能体；Outcomes，基于 rubric 的自我改进与评估循环；Dreaming，让智能体从历史会话中学习并更新记忆；以及 Webhooks，用于无需轮询地接收事件更新。据称，有客户借助 Dreaming 将完成率提升了 6 倍。[@Vanarchain](https://x.com/Vanarchain) 在回复中补充了关键前提：“记忆 + 协同只有在始终扎根于可靠执行时才有意义，而不是仅仅让输出随着时间变得更好。”

## 7. 机会在哪里

**[+++] 持久化上下文基础设施工具** —— 这是当天最一致、被重复最多的信号：普通 AI 用户与专家级用户之间的差距，不在模型质量，也不在提示词技巧，而在上下文基础设施。目前没有主流产品能自动构建并维护品牌语气文件、风格违规库、受众上下文和会话连续性。所有被提到的从业者，都是靠 `.md` 文件和 Obsidian vault 手工完成这件事。一个能够组装、更新并版本化用户持久智能体上下文的工具，将同时服务个人运营者和团队。证据见第 1.2、2.1、3.1 和 4 节。

**[+++] 智能体安全治理层** —— 就在 Cisco DefenseClaw 扩展到支持 9 个智能体的同一天，针对 Claude Code 的有效利用也被公开演示。目前还没有任何产品，能以经过真实注入场景检验的方式，在多个智能体运行时上同时大规模地阻止、限速或审计智能体行为。问题扩张的速度快于解决方案。企业买家有明确需求——可审计记录、按连接器执行策略——但目前仍没有产品能完整满足。证据见第 1.6、2.4、3.4、5 和 6 节。

**[++] 面向专业领域工作的多智能体编排** —— TradingAgents 的架构（角色分工 + 对抗性辩论 + 投票）可以自然推广到任何“对抗性审查能提升质量”的领域，例如法律文件审查、临床决策支持、代码安全审计和金融分析。TradingAgents 已获得 73.7K GitHub stars，并有 arXiv 论文；DeepMind 的 Co-Mathematician 则把同一模式扩展到了数学研究，仅多智能体层就带来了 28.9 个百分点的提升。框架是开源的，结果经过同行评审，但尚无主导产品把这套架构封装给非技术领域买家。证据见第 1.6、5 和 6 节。

**[++] 让语音智能体可靠性突破 50% 门槛** —— tau-Voice 基准表明，当前没有任何语音智能体能端到端解决超过 52.1% 的客服场景。呼叫中心与预约服务已在部署语音智能体，但 50% 的上限意味着一半来电要么升级给人工，要么直接失败。最佳表现（52.1%）与“足够支持无人值守运行”（80%+）之间的差距，在抗噪性、多轮策略合规和优雅升级逻辑上，构成了明确的工程机会。证据见第 1.6、3.3 和 4 节。

**[+］ 面向技能作者的 Agent 变现原语** — ［@dotey](https://x.com/dotey/status/2054033818474950769) 点明了具体问题：skills 是透明的、便宜的、容易被复制的，而且无论质量或采用度如何，作者目前都赚不到钱。应用商店的类比（VSCode 扩展、Chrome 插件）已经很明确。缺的是一个内置支付、IP 保护和质量信号的可信 marketplace。Circle Agent Stack 的纳支付基础设施，从技术上已经能支持按次计费的技能收费；缺少的是其上的市场层。证据见第 1.5 和 3.2 节。

**[+] 守护进程化的智能体运行时（智能体 OS 模型）** —— ClawdOS 的定位——把智能体看作长期运行的 OS 进程，而不是无状态聊天会话——确实解决了一个真实问题：现有 harness 会重置状态、丢失连续性，也无法基于共享底座协调多个同时运行的智能体工作负载。如果智能体未来要持续执行后台任务（邮件分流、cron 作业、财务监控、代码审查），守护进程模型就是正确抽象。项目目前处于 Alpha，但定位足够差异化。证据见第 1.4 和 5 节。

## 8. 要点总结

1. **Harness engineering 的课程体系，已经成为一套结构化、可教授的知识体。** addyosmani 的文章、“学习 Harness Engineering”课程，以及 @MindBranches 的思维导图，共同构成了这门学科第一套连贯的课程体系。社区已经越过“harness engineering 是什么”，进入“去哪里学”。（[akshay_pachaar](https://x.com/akshay_pachaar/status/2053815461150859272)、[dishantwt_](https://x.com/dishantwt_/status/2054254402173854137)）

2. **面向智能体的机器支付金融基础设施已经上线。** Circle Agent Stack 在当天发布了 Agent Wallets、Agent Marketplace，以及免 gas 的 USDC 纳支付（$0.000001）。而尚未解决的问题——提示注入导致未授权转账——在上线数小时内就被指出，且尚无公开缓解方案。（[circle](https://x.com/circle/status/2053897932731285627)、[somi_ai via CoinMarketCap](https://x.com/CoinMarketCap/status/2054016755182309649)）

3. **在高难能力边界上，多智能体框架带来的增益超过模型升级。** DeepMind 的 Co-Mathematician 仅仅是在单一基础模型之上加了一层多智能体框架，就让 FrontierMath Tier 4 成绩提升了 28.9 个百分点。测试中最强的单模型配置 GPT-5.5 Pro，也没有超过 39.6%。（[hsu_steve](https://x.com/hsu_steve/status/2053969087559061737)）

4. **语音智能体正撞上约 50% 任务完成率的可靠性上限。** tau-Voice 是首个在真实条件下评估语音到语音模型 agentic 能力的公开基准。最佳模型端到端只能解决 52.1% 的客服场景，其余模型都低于 40%。这不是猜测性的市场空缺，而是一个已被量化的缺口。（[ArtificialAnlys](https://x.com/ArtificialAnlys/status/2054234919887573292)）

5. **如今区分高绩效智能体操作者的，不再是提示词质量，而是持久化上下文基础设施。** 多位已经跑出生产结果的从业者都表示，真正的核心杠杆不是反复打磨提示词，而是建设品牌语气文件、风格库和持久化上下文文件夹。这一模式同时出现在个人创作者（每月 6,000 条广告）、企业团队和开源构建者中。（[NainsiDwiv50980](https://x.com/NainsiDwiv50980/status/2054095565517144369)、[oliverwhudson](https://x.com/oliverwhudson/status/2054256998422843767)）

6. **智能体安全治理正在变成企业级基础设施。** Cisco DefenseClaw 扩展到 9 个智能体的同一天，针对 Claude Code 的有效利用链也被演示出来。攻防共同演化正在加速。任何使用浏览器工具或网页内容的智能体部署，都暴露在当前 harness 无法阻断的链式漏洞路径之下。（[AISecHub](https://x.com/AISecHub/status/2053921989883052038)、[DarkNavyOrg](https://x.com/DarkNavyOrg/status/2054094369192603950)）
