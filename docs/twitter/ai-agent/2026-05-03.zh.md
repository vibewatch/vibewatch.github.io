### 1.3 Harness 工程进入“自建还是购买”之争 🡒

关于 harness 工程的讨论重点，已经从“它是什么？”转向“你该不该自己做？”多种相互对立的观点开始清晰化：

[@_colemurray](https://x.com/_colemurray) [提出反对意见](https://x.com/_colemurray/status/2051045148252143669)（18 个赞、10 个书签）反对自建 harness：“你大概率不会在子代理编排、压缩、渐进式披露等方面提出什么值得为之拥有整套 harness 的新想法。把时间投在 harness 周边的部分：执行基础设施、自定义工具/MCP/技能，以及基于轨迹的自我改进。”

[@RoundtableSpace](https://x.com/RoundtableSpace) [演示了](https://x.com/RoundtableSpace/status/2050987500211183631)（37 个赞、3.7 万次观看）则持相反观点：“OPENAI SYMPHONY 配合扎实代码库上的 HARNESS，能让你的编码代理产出提升 5 倍”——这是一段 12 分钟教程，介绍如何把 Playwright CLI、boot skills 和 workflow.md 作为自定义 harness。

[@dexhorthy](https://x.com/dexhorthy) [给出了较为悲观的看法](https://x.com/dexhorthy/status/2050931243181576669)（64 个赞）：“嘿 Nikita，我真的很想再看点 AI 写的、关于 harness 工程的炒作垃圾，你能帮我整点吗？”——这反映出不少人已经对铺天盖地的定义型内容感到厌倦。

[@_overment](https://x.com/_overment) [指出了尚未解决的问题](https://x.com/_overment/status/2051000796515308030)（6 个书签）：“设置变化时，怎么保住上下文缓存？除了压缩，怎么保留重要上下文？当结果超出可用上下文窗口时，怎么把它呈现给模型？这里有整整一类新问题，至今还没解决。”

**讨论洞察：** [@DanIsBuilding](https://x.com/DanIsBuilding) 回复 @_overment：“我个人认为，我们正要从模型是瓶颈，转向 harness 设计才是瓶颈。上下文工程、工具披露和任务委派，已经在很大程度上限制了现有模型。”[@henrytdowling](https://x.com/henrytdowling) 则问 Cole Murray：“所以你的意思本质上是，与其从零开始造，不如 fork 一个现有 harness？”

**与前一天比较：** 5 月 2 日主要是在统一术语（Matt Pocock 定义了 Model/Harness/Environment/Agent）。到了 5 月 3 日，讨论已越过定义阶段，转向战略抉择——自建还是购买，以及还有哪些关键问题尚未解决。@dexhorthy 发出的反弹信号表明，这波讨论热度可能已经见顶。

## 2. 人们的挫败感来自哪里

### Hermes Agent 的基础设施缺口拖累了一个能力很强的代理——严重程度：高

[@Atenov_D](https://x.com/Atenov_D) [花了一整天进行测试](https://x.com/Atenov_D/status/2050899362260160968)（39 个赞、10 个书签）用 Hermes Agent 处理 Polymarket 数据时撞了墙：“没有 Claude 账号认证。Gemini Pro 一上来就撞限额。Groq 没集成。免费的 OpenRouter 模型几分钟就挂。NVIDIA 能跑，但会不断重写自己的设置，彻底丢线程。代理很聪明，围绕它的基础设施却一团糟。”他提出的问题无人回应：“现在大家都在用什么平台？到底哪个模型能真正扛得住？”[@monokern](https://x.com/monokern) 只简短回复：“你要是解决了这个问题，记得告诉大家。”

应对策略：继续坚持的用户，要么跑本地模型，要么直接付费上 Claude Pro，但这两条路径的文档都不完善。

### 框架臃肿吞掉上下文预算——严重程度：高

[@sudoingX](https://x.com/sudoingX) [清晰阐述了](https://x.com/sudoingX/status/2050979814992118249)（63 个赞）点出了核心问题：“openclaw 不能稳定调用工具，hermes 却能跑出干净的 agentic loops。坏掉的不是模型，而是框架自己的脚手架吃掉了一半上下文预算。harness 一旦消失，模型终于能开始思考。”被引用的 [@DavidOndrej1](https://x.com/DavidOndrej1) 帖子则说：“openclaw 太臃肿了，更新要很久，重启 gateway 也要很久，已经不是以前那个样子了。”

应对策略：实践者转向更轻的 harness（Hermes），或自己做极简定制版。

### Harness 工程内容疲劳——严重程度：中

[@dexhorthy](https://x.com/dexhorthy)（64 个赞）[表达了](https://x.com/dexhorthy/status/2050931243181576669) 说出了许多人的心声：“嘿 Nikita，我真的很想再看点 AI 写的、关于 harness 工程的炒作垃圾，你能帮我整点吗？”[@sanarsh11](https://x.com/sanarsh11) 回复一篇 harness 教程时则说：“又一个把同样复制粘贴式混乱重新包一层的东西。”围绕 harness 工程的教育与宣传内容已经远超新见解的产出速度，导致那些早已理解基础概念的从业者开始犬儒化。

应对策略：关注真正持续交付的构建者（Nous、badlogicgames），而不是只会总结概念的内容创作者。

### 并行代理会制造合并冲突——严重程度：中

[@loftyPuma](https://x.com/loftyPuma) [描述了](https://x.com/loftyPuma/status/2050793648539718063)（1.5 万次观看）描述了这种协调失灵：“一个代理刚提交修复，另一个代理已经在同一个文件改到一半——合并冲突层层级联，编排上的 token 浪费爆炸，等你醒来时，代码库已经悄悄自相矛盾。”Hermes Agent Kanban 宣称可通过任务锁和共享工作区解决这一问题，这是一次直接回应，但功能上线才几个小时。

紧迫程度：中——机会：平台/标准

## 7. 机会在哪里

**[+++］ 面向独立开发者的多智能体编排 UX** -- Hermes Agent Kanban（数小时内获得 171 个书签）验证了巨大的需求。Mac Mini 的爆款帖子（861 个书签）证明，独立开发者希望拥有多智能体配置。缺口在于：Kanban 是原生 CLI/终端方案。谁能做出一款精致的桌面应用，把智能体协作可视化、处理模型路由，并提供专家配置的一键部署，谁就能抓住那些看到了每月 3.4 万美元前景、却缺乏从零搭建技术能力的开发者。(［source](https://x.com/NousResearch/status/2050997692977844324), [来源](https://x.com/regent0x_/status/2050606522556612946))

**[+++］ 智能体市场基础设施** -- 超过 8 个团队在独立构建，ETHGlobal 黑客松产出了 3 个以上提交项目，@kuberdenis 呼吁标准化。@Cogladius 指出的缺失环节包括：价格发现、链上结算、自动化评判，以及带有真实利益约束的争议解决机制。谁若能以框架中立的方式解决这四点（同等支持 Claude、Codex、Hermes），谁就能赢下平台层。(［source](https://x.com/tetsuoarena/status/2050619858685989162), [来源](https://x.com/Cogladius/status/2050635594368229693))

**[++］ 自愈式 harness 自动化** -- HALO 通过自动化轨迹分析与 harness 重写，在基准测试中实现了 15 到 21 个百分点的提升。大多数团队仍在通过“手动翻查成千上万条轨迹”来调试智能体。若将这一闭环（轨迹收集、模式检测、自动修复、回归测试）产品化为服务，将大幅降低智能体维护成本。(［source](https://x.com/AlphaSignalAI/status/2050908503951200418))

**[++］ 智能体上下文自管理** -- @agiactivex 指出，目前还没有任何智能体会主动管理自己的上下文预算。结合 @_overment 提出的未解问题（缓存失效、压缩保真、溢出处理），这里的机会在于打造位于 harness 与模型之间的中间件，将上下文作为一种资源进行主动管理。(［source](https://x.com/agiactivex/status/2050971146221187322), [来源](https://x.com/_overment/status/2051000796515308030))

**[+］ 语音智能体最后一公里集成** -- xAI 已推出语音克隆，Deepgram 已支持多语言，但要把语音智能体接入电话线路，仍然需要定制化开发。Patter（4 行代码、MIT、alpha）验证了这一需求。一个面向生产环境的电话 SDK，若能提供号码开通、呼叫路由和合规能力（尤其适用于 5 月 2 日提到的医疗/保险场景），仍是服务不足的领域。(［source](https://x.com/Nicolo_Tognoni/status/2050683082982744455), [来源](https://x.com/xDaily/status/2050761914033049729))
