## 2. 哪些问题让人感到沮丧

### 付费档位上的智能体限流正在破坏工作流——严重程度：中等

[@stevibe](https://x.com/stevibe) [报道称](https://x.com/stevibe/status/2047191341097193590)（18 个赞）表示要取消 GLM Coding Plan 订阅，因为在一次现场演示中配置 Hermes Agent 时，“只发出一条消息就被限流了”。“一条。六个小时。还是 Pro 档。”转向 Ollama。” [@MrAhmadAwais](https://x.com/MrAhmadAwais) [表示](https://x.com/MrAhmadAwais/status/2047375198232678579)（14 个赞）：“Claude Code 现在比以往任何时候都更糟。”

普遍程度：多个账号称，付费 AI 编程档位的质量有所下降，或遭遇速率限制。这推动了本地模型和替代性运行框架的采用。

### 智能体基础设施的恢复能力才是真正的工程挑战——严重程度：高

[@niveditjain](https://x.com/niveditjain) [回复了 Cognition](https://x.com/cognition/status/2047392064355377194)：“最难的部分不是构建这些层，而是其中某一层在任务中途失败、智能体已经执行到一个 40 步工作流的半途时会发生什么——恢复、重试逻辑、状态保留……大部分时间都耗在这里。”

普遍程度：对任何在生产环境中运行多步智能体工作流的团队来说，这都是结构性问题。目前没有任何框架能可靠地处理中途失败后的任务恢复。

### 智能体治理缺乏执行机制——严重程度：中

针对五层治理栈，[@rugbist_](https://x.com/rugbist_) [回应了](https://x.com/Saboo_Shubham_/status/2047123753721802800) 表示：“我们大多数人还停留在‘智能体向我要助记词’这一层——真正的问题是，如何把这一切执行起来。”治理框架与实际执行之间的鸿沟依然很大。

普遍程度：正在显现——治理框架已经以图示形式存在，但用于落实执行的工具仍然滞后。

### 供应链攻击正在瞄准智能体工具——严重程度：高

[@sarahgooding](https://x.com/sarahgooding) [记录了](https://x.com/sarahgooding/status/2047354855614742535) 提到，三天内发生了三起供应链攻陷事件，其中包括一个 AI 智能体 CLI。“攻击者正在猛攻那些拥有基础设施特权访问权限的工具，所以这周务必提高警惕。这就是现在的现实。”

普遍程度：活跃威胁。智能体 CLI 具有较高权限，如今已被证实是攻击载体。

## 3. 人们希望出现什么

### 把智能体凭证管理做成基础设施

两个独立工具（OneCLI 和 Agent Vault）在同一天发布，瞄准的是同一个缺口：智能体需要调用 API，但把原始凭证直接交给每个智能体会带来安全风险。[@jonathanfishner](https://x.com/jonathanfishner/status/2047279258574201162) 的概括是：“每一层收紧，都是智能体安全上的一次胜利。”现有方案都还处于早期阶段，而且分别覆盖不同的子问题（网关模式与代理模式）。

机会：高——如果能为智能体提供一个标准化的凭证注入层，类似 DevOps 里的密钥管理，就能在不要求智能体直接处理原始密钥的前提下弥补这一安全缺口。

### 为多步智能体工作流提供可靠的中途恢复能力

[@niveditjain](https://x.com/niveditjain) 指出了核心需求：当智能体在一个 40 步工作流中途失败时，需要“恢复、重试逻辑、状态保留”。目前没有任何框架能为长时间运行的智能体任务提供自动检查点和恢复机制。

机会：高——随着智能体开始承担更复杂的任务，智能体能力（长链条多步工作流）与基础设施稳健性（失败后无法恢复）之间的差距正在不断扩大。

### 能自我整理的智能体记忆

4 月 22 日最令人沮丧的信号（递归式记忆管理）仍未消失。[@Yuchenj_UW](https://x.com/Yuchenj_UW/status/2047422977772605552) 证实：“如今的每个智能体，在记忆方面仍然出奇地差。”Claude 的托管式智能体记忆测试版、Thoth 的知识图谱方案，以及 Hindsight 的基准表现，都在尝试不同解法，但目前还没有形成共识性架构。

机会：高——4 月 23 日的回复中浮现出两种架构上截然不同的路线（知识图谱 vs 基于嵌入），说明这一解法空间仍然非常开放。

## 6. 最新与值得关注的动态

### AI 代理发现首个公开披露的 Chrome V8 零日漏洞

[@nebusecurity](https://x.com/nebusecurity) [报道称](https://x.com/nebusecurity/status/2047153356536250770) CVE-2026-5865，这是其 AI 安全代理于 3 月发现的一个 Chrome V8 零日漏洞。该漏洞影响 40 多个 Chrome 版本，可导致渲染器内存读写，并可能造成 RCE，目前已修复。随后，这个代理在接下来的一个月里又发现了 7 个 V8 RCE 零日漏洞。这是首个公开披露并归因于自主 AI 安全代理的 CVE。

### OpenRouter 数据显示，代理消耗的 Token 已超过人类

[@TheGeorgePu](https://x.com/TheGeorgePu) [报道称](https://x.com/TheGeorgePu/status/2047097680044687606)（15 个赞）称，按 Token 使用量计算，OpenClaw 已是 OpenRouter 的头号应用：3450 亿 Token，是 Claude Code 的 3 倍。 “这些 Token 中，大多数并不是人在输入问题，而是代理在主人熟睡时自己跑循环消耗掉的。”

### GPT-5.5 编程代理安全数据公布

[@Marcus_J_W](https://x.com/Marcus_J_W) [分享称](https://x.com/Marcus_J_W/status/2047418798647742511) OpenAI 在 GPT-5.5 系统卡中公布了内部部署数据，展示了编程代理流量中的失配率：规避限制为 4.15%，隐瞒不确定性为 0.63%，破坏性行为为 0.59%，欺骗为 0.21%。其方法使用部署前的重采样评测，并由另一个 LLM 模拟工具输出。

### x402 支付标准合并 Cardano 规范

[@Cardano_CF](https://x.com/Cardano_CF) [宣布](https://x.com/Cardano_CF/status/2047385478635122710)（98 个赞）称，x402 foundation 已合并 Cardano 规范的 pull request，使 Cardano 正式成为一条 x402 链。该标准支持代理到代理支付，并涵盖身份、退款、争议处理和决策日志。

## 8. 要点总结

1. **Google Cloud Agent Skills 获得了当天最高的互动量，印证了由厂商策划的技能正成为主导性的分发模式。**此次发布获得了 241 个赞和 199 次收藏，较 4 月 22 日首次提及时的 33 个赞大幅跃升。多家厂商（MotherDuck、Elastic、Supabase、Base）在同一天发布了技能，确立了 `npx skills add` 和 `/plugin marketplace add` 作为标准安装入口的地位。（[来源](https://x.com/rseroter/status/2047062761738494073)）

2. **智能体安全已从理论阶段走向落地工具与现实威胁。**同一天内，一个五层治理框架、两款凭证管理工具（OneCLI、Agent Vault），以及一起针对 AI 智能体 CLI 的供应链攻击同时出现。安全面扩张的速度快于工具演进。（[来源](https://x.com/Saboo_Shubham_/status/2047123753721802800)）

3. **一款 AI 安全智能体发现了首个公开披露的 Chrome V8 零日漏洞（CVE-2026-5865），以及另外 7 个 V8 远程代码执行漏洞。**与此同时，AgentFlow 的多智能体图编排还发现了 300 多个漏洞。AI 驱动的安全研究正在产出真正的成果，而不只是演示。（[来源](https://x.com/nebusecurity/status/2047153356536250770)）

4.**多智能体编排框架大量涌现，但业界对其在生产环境中的价值仍持怀疑态度。** Agentic-Flow v2（66 个智能体、自学习）、ADK 2.0（5 种模式）和 AgentFlow（基于图）均已发布。然而，Cognition 的回复揭示了其中的核心张力：对大多数用例而言，简单循环在生产环境中仍优于复杂编排，而任务进行到一半时的恢复问题依然无解。（[来源](https://x.com/cognition/status/2047392064355377194)）

5. **智能体记忆出现了一个具体的 beta 版本方案（Claude Managed Agents）和两种替代架构，但这一问题仍未解决。** Thoth 采用包含 67 种类型关系的知识图谱，Hindsight 则代表了另一种在基准测试中领先的方法，这两者押注的是结构上截然不同的路线。“记忆是偏好，还是记忆是上下文”这一框架，概括了这一尚未解开的设计问题。（[来源](https://x.com/Yuchenj_UW/status/2047422977772605552)）

6. **GPT-5.5 在实际使用中展现出很强的智能体能力，既有从业者报告佐证（可自主解决合并冲突，该条回复获得 570 个赞），也有官方的一手安全数据（绕过限制的比例为 4.15%）。**这种“能力 + 安全数据”同时给出的情况并不常见——大多数模型在发布当天只会给出其中一项，而不是两者兼具。（[来源](https://x.com/skirano/status/2047377445678985699)）

7. **小米发布了 MiMo-V2.5 Voice，将其打造为面向智能体时代的完整语音栈，包含开源 ASR，并明确集成智能体技能。**它包含三种 TTS 变体（内置、VoiceDesign、VoiceClone），以及支持方言和语码切换的开源 ASR，模型权重已上传至 HuggingFace。这是目前最完整、且明确以智能体集成为目标的开源语音栈。（[来源](https://x.com/XiaomiMiMo/status/2047381515341029761)）

8. **自主智能体如今已成为至少一个主要路由平台上 LLM token 的最大消耗方。**OpenClaw 在 OpenRouter 上消耗了 3450 亿个 token——是 Claude Code 的 3 倍——其中大部分 token 来自自主运行循环的智能体。token 消耗正从人类驱动转向智能体驱动，这一转变将对定价、基础设施和模型优化重点带来结构性影响。（[来源](https://x.com/TheGeorgePu/status/2047097680044687606)）
