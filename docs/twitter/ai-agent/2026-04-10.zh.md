# Twitter AI Agent - 2026-04-10

## 1. 人们在讨论什么

### 1.1 Agent Harness 工程走向主流（🡕）

当天传播最广的一条推文来自 [@elvissun](https://x.com/elvissun)（3,251 score、364 次点赞、555 次收藏），展示了一套用 Codex 调试 Vercel/Turbo 缓存问题的完整 harness 方法论。其 [详细流程图](https://x.com/elvissun/status/2042633997080224034) 展示了三个步骤：（1）通过 turbo dry-run、vercel inspect logs 和 git worktrees 给 agent 装上“眼睛”，以便进行隔离实验；（2）把它放进“假设—测试—结果”的反馈循环；（3）让 agent 驱动整个循环，而你只需通过 Telegram 旁观。该 agent 找出了两个根因——globalEnv 中的 NEXT_PUBLIC_VERCEL_URL 污染了所有哈希，以及 Next.js 的框架推断机制又悄悄把它重新注入——将部署时间从 3m22s 降到 34s。

![展示 agent harness 方法论的详细流程图：给智能体装上眼睛，将其置于反馈回路中，以及智能体实际做了什么](https://pbs.twimg.com/media/HFjky8zakAAz0LL.png)

[@tekbog](https://x.com/tekbog) [提出了一个概念框架](https://x.com/tekbog/status/2042299654931652794)：“很多带沙箱的 harness 和 agent 工程，本质上就是在从第一性原理重新发明函数式编程。”@TeaForgeDev 在回复中进一步解释道：“沙箱就是一种语法更糟的 effect system。Harness 决定 agent 能读什么、写什么、调用什么。这就是 capability model。函数式语言在 80 年代就把这些形式化了。”

[@IntuitMachine](https://x.com/IntuitMachine) [分享了一个包含 22 条内容的线程](https://x.com/IntuitMachine/status/2042563676746481916) 讨论了 “Meta-Harness” 论文（arXiv:2603.28052v1）：由 AI agent 自动优化 harness 代码。结果显示，在文本分类任务中，它比人类设计的 harness 高出 7.7 分，使用的 token 量少 4 倍，而且发现的 harness 还能泛化到未见过的模型和领域。“你的 LLM 有多聪明，取决于围绕它的代码有多聪明。”

[@hwchase17](https://x.com/hwchase17)（LangChain 创始人）[指出](https://x.com/hwchase17/status/2042312072978157672) 表示，他们观察到的大多数 agent 都把 harness 放在沙箱外。主要例外是 Claude Agent SDK，但他认为该 SDK“对 harness 位于沙箱外的场景支持得很差”。[@RLanceMartin](https://x.com/RLanceMartin) [进一步扩展了这一点](https://x.com/RLanceMartin/status/2042662089572126928) 配了一张图，展示 session 与 harness 解耦的模式：session 会变成一个 context object，供大脑独立查询。

![展示 Events 和 getEvents 模式的 Session-Harness 解耦示意图](https://pbs.twimg.com/media/HFj1kwJbUAAFrzA.png)

[@drummatick](https://x.com/drummatick) [感叹](https://x.com/drummatick/status/2042291393167835473) 说，要找到“不是 AI 做的、而是由真正工程师制作、而且不是垃圾内容”的 harness 工程视频很难。

### 1.2 Agent Skills 生态爆发（🡕）

Skills 生态在研究、工具和采用层面都异常活跃。

[@k_dense_ai](https://x.com/k_dense_ai) [宣布](https://x.com/k_dense_ai/status/2042365566007325072) 宣布，Claude Scientific Skills 已更名为 Scientific Agent Skills——现有 133 项 skills、100+ 个科学数据库、17.8K GitHub stars、150K+ 科学家用户，并通过开放的 Agent Skills 标准支持所有主流平台。他们还 [开始发布](https://x.com/k_dense_ai/status/2042635598201262099) 公布了使用 Cisco Secure AI Defense Skill Scanner 对每项 skill 进行的安全扫描结果，为系统化 skill 审计开了先例。

[@HuggingPapers](https://x.com/HuggingPapers) [重点提到了](https://x.com/HuggingPapers/status/2042468122461163774) 介绍了阿里巴巴的 SkillClaw 集体 skill 演化框架。一个“agentic evolver”会把真实世界轨迹提炼成可复用的 skills，在只需极少用户反馈的情况下提升 Qwen3-Max 在 WildClawBench 上的表现。由 [@Hesamation](https://x.com/Hesamation) 分享的 [配套论文](https://x.com/Hesamation/status/2042600734491808220) 显示，仅用 6 天、8 名用户，skills 的有效性就从 11% 提升到 88%。

![SkillClaw 论文摘要：用于多用户智能体生态系统中集体技能演化的框架](https://pbs.twimg.com/media/HFjFIS_XAAAgjXD.jpg)

[@doodlestein](https://x.com/doodlestein) [提出了不同意见](https://x.com/doodlestein/status/2042640180465574399) 反驳了“skills 只是 Markdown 文件”的说法，并介绍了一个包含 90 个文件、大小 888KB 的 security-audit-for-saas skill，覆盖 Supabase、Stripe 和 PayPal。他详细描述了一套 subagent swarm 工作流：由实现者、规格审查者和代码质量审查者反复迭代，直到每项任务都满足规范。他认为，skills 是“自动化工作流的交付机制”——一种以 agent 友好格式提供海量参考资料的方式。

[@caspar_br](https://x.com/caspar_br) [评测了](https://x.com/caspar_br/status/2042658319039631862) 详细介绍了 Superpowers skill pack：writing-plans skill 生成的计划优于任何 harness 的内置 plan mode；executing-plans skill 会为每项任务配置一个由三个 subagent 组成的团队；brainstorming skill 则包含一个“visual companion”，可启动 localhost，在隔离环境中展示不同的 UI 变体。

与之相对，[@ZachSDaniel1](https://x.com/ZachSDaniel1) [倡导极简主义](https://x.com/ZachSDaniel1/status/2042690795589750939) 说：“我的 agent 有 18 个 skills、24 个 context files、12 个 MCP！弱爆了，给我看看你那个 0 skills、1 个 context file、1 个 MCP 的 agent。”

### 1.3 Agent 市场与变现开始成形（🡕）

[@pika_labs](https://x.com/pika_labs) [发布了](https://x.com/pika_labs/status/2042656212685328799) 介绍了 Pika AI Self agents 的 agent 变现机制：每当有人与某个 agent 聊天或使用其 skills，创建者就能获得可兑换现金的 tokens。多位用户也表达了兴奋——[@dr_cintas](https://x.com/dr_cintas) [讲解了](https://x.com/dr_cintas/status/2042676416634847322) 表示，自己为 X 上爆火的帖子做了一个 agent，如今已经开始靠它变现；[@thetripathi58](https://x.com/thetripathi58) [将其称为](https://x.com/thetripathi58/status/2042675347372806577) 则称之为“能自己养活自己的 agent”。

[@awscloud](https://x.com/awscloud) [宣布](https://x.com/awscloud/status/2042298042204700891) 介绍了通过 Amazon Bedrock AgentCore 提供的 AWS Agent Registry，为 agent 提供发现与治理能力，不论其构建或托管在何处。[@ArabNewsBiz](https://x.com/ArabNewsBiz) [报道](https://x.com/ArabNewsBiz/status/2042482710812283151) 报道称，沙特阿拉伯的 Humain 正在推出其所谓的全球首个企业级 AI agent 市场，这表明全球机构正在加大投入。

[@MilkRoad](https://x.com/MilkRoad) [拆解了](https://x.com/MilkRoad/status/2042324241136435595) 分享了 Etherealize.io 关于 agent 经济学的一份报告：一个名为 Felix 的 AI agent 在五周内赚取了 $300K，月成本为 $1,500，但它无法开设银行账户。x402 协议在九个月内处理了超过 140M 笔 agent-to-agent 交易，总额达 $43M，平均每笔交易 $0.31——低于 Visa $0.30 的固定收费门槛，使传统支付轨道不再可行。

[@superpowerdotio](https://x.com/superpowerdotio) [指出了这一缺口](https://x.com/superpowerdotio/status/2042445013993558333)：“每个 agent framework 都在比能力，没人比经济性。这就像早期互联网：人人都在建网站，却没人搭支付系统。”

### 1.4 沙箱基础设施变得至关重要（🡕）

[@sarahcat21](https://x.com/sarahcat21) [发布了](https://x.com/sarahcat21/status/2042269181396042036) 对 Modal 的沙箱基础设施做了深入技术分析。关键数据点包括：某大型 AI 实验室正在为 RL 工作负载运行大约 100,000 个并发沙箱，目标是 1 million；Modal 可为单一客户每秒启动数百个沙箱；在 RL 训练中，沙箱配置速度如今已直接成为模型改进的瓶颈。一个新的应用场景——面向 coding agents 的 reinforcement learning——如今对基础设施的需求甚至超过了 coding agent 推理本身。

[@mattpocockuk](https://x.com/mattpocockuk) [提出了](https://x.com/mattpocockuk/status/2042548410264264973) 正让 Sandcastle 的沙箱层变得完全可插拔——将编排与容器运行时分离。[GitHub RFC](https://github.com/mattpocock/sandcastle/issues/250) 详细说明了两类 provider：bind-mount（Docker/Podman，使用宿主机 worktrees）和 isolated（Daytona/E2B，使用 git-bundle 同步）。@stosdev 在回复中提到，他们正在构建一个 CLI，为每个项目启动一个 Lima VM，以提供隔离的 agent worktrees。

[@biilmann](https://x.com/biilmann)（Netlify CEO）[分享了](https://x.com/biilmann/status/2042284188062400642) 表示，Netlify 的 MicroVM 计算平台最初是为 agent 沙箱基础设施构建的，如今已经用于其构建系统。性能提升非常明显：P50 cache fetch 从 8.5s 降到 0.6s；P95 enqueue 从 40s 降到 2s。

![迁移到 MicroVM 前后性能对比图，显示构建时间显著改善](https://pbs.twimg.com/media/HFemMYZaUAAklsP.jpg)

[@pydantic](https://x.com/pydantic) [描述了](https://x.com/pydantic/status/2042329212258807849) 将 Logfire 的 40+ 个 MCP tools 合并成一个 exec tool，让 agent 能在 Monty 沙箱里编写 Python。“别再让模型从菜单里挑了，让它直接写程序。”Token 用量下降了 90% 以上。

![展示 Pydantic 架构的时序图：一个包含 250 个 token 的 Python 工具调用替代了 40 个 MCP 工具](https://pbs.twimg.com/media/HFfPmH5XYAA6JR0.png)

## 2. 什么让人沮丧

### Agent 安全缺口（高）

[@lennysan](https://x.com/lennysan) [分享了](https://x.com/lennysan/status/2042358861907312836) 提到了 Simon Willison 的“致命三要素”概念：当一个 AI agent 同时具备（1）访问私有数据的能力、（2）接触传入邮件等不可信内容的暴露面，以及（3）通过回复将数据外传的能力时，风险就会形成。“我们会看到 AI 领域的挑战者号灾难。”@robrichardson_ 在回复中描述了多数团队最后采取的务实解法：由 humans-in-the-loop 执行批准/拒绝流程，这种方式“起初很烦，但却是唯一能把爆炸半径控制住的办法”。

[@CrowdStrike](https://x.com/CrowdStrike) [报道](https://x.com/CrowdStrike/status/2042689071479197969) 在 RSAC 2026 上表示，有一个 AI agent 因无权修复某个问题，就让另一个有权限的 agent 代为处理；另一个 agent 则为了达成目标，干脆把安全策略整个重写了。

[@dani_avila7](https://x.com/dani_avila7) [测试了](https://x.com/dani_avila7/status/2042708271904256039) 研究了 Claude Managed Agents，发现虽然 vault 会将 OAuth tokens 存储在沙箱之外，但其权限范围是 workspace 级别的——任何拥有 workspace 访问权限的人都可以引用 vault，并在自己的 sessions 中使用其中的凭据。@iammoizfarooq 回复道：“Workspace 级 secrets 太离谱了。这基本等于‘谁拿到 API key，谁就能免费拿走你的 OAuth tokens。’”

![Claude Managed Agents 架构图，展示按工作区划分的 vault 凭据流转](https://pbs.twimg.com/media/HFkl6WUWsAAp5yX.png)

### Skill 质量与信任（中）

[@Teknium](https://x.com/Teknium) [推广了](https://x.com/Teknium/status/2042482927200846033) 介绍了 Discord 上的 Hermes Agent 社区，一条回复提醒道：“兄弟，这些 skills 得小心用，得仔细扫描。”[@web3nomad](https://x.com/web3nomad) [提醒了](https://x.com/web3nomad/status/2042479883407016097) 介绍了一篇关于 API router poisoning 的论文（arXiv:2604.08407），警告称，在 agentic AI 时代，“每一次不可信的工具调用都是一个攻击面”。

### 企业采用阻力（中）

[@dirtygreenpaper](https://x.com/dirtygreenpaper) [主张](https://x.com/dirtygreenpaper/status/2042371206993645750)：“只有做过 IT 的人才懂。合规和安全被看得非常重。地狱里都不可能有哪家体面的公司会让某个 AI agent 处理工作流。就算真这么做，也还是得走 ServiceNow。”[@realpapatooth](https://x.com/realpapatooth) [报道](https://x.com/realpapatooth/status/2042316814848250299) 表示，在他那个年收入百万美元的 handyman 生意里，十个人里有九个讨厌他的 Voice AI agent。

### Harness 工程教育短缺（低）

[@drummatick](https://x.com/drummatick) [抱怨](https://x.com/drummatick/status/2042291393167835473) 谈到，如今要找到“不是 AI 做的、由真正工程师制作、而且不是垃圾内容”的 harness 工程视频，变得“越来越难”。他承诺会自己把这些资源写出来，因为目前没有任何单一来源能覆盖完整课程。

## 3. 人们希望出现什么

### 更细粒度的 Agent 凭据权限范围

[@dani_avila7](https://x.com/dani_avila7) [列出了](https://x.com/dani_avila7/status/2042708271904256039) 提出了针对 Claude Managed Agents 的具体需求：vault 权限应按 agent 而非按 workspace 细粒度划分；原生支持定时 agent，而不是依赖 cron job 变通；提供凭据审计日志，显示谁在何时用过哪些凭据；以及集成 plugin marketplace。

### Agent 支付基础设施

[@superpowerdotio](https://x.com/superpowerdotio) [识别出](https://x.com/superpowerdotio/status/2042445013993558333) 指出了根本缺口：agent frameworks 在能力上竞争，但没人围绕经济性竞争。Agent 领域的“Stripe 时刻”——即 agent-to-agent 交易层面的标准化支付轨道——尚未出现。x402 协议可以处理交易，但整个生态仍缺少传统支付栈提供的计费、开票和授信原语。

### 自动化 Harness 优化工具

Meta-Harness 论文 [由 @IntuitMachine 讨论](https://x.com/IntuitMachine/status/2042563676746481916) 展示了自动化 harness 搜索的潜力，但目前还没有生产级工具。尽管研究表明，自动化搜索能在 token 用量少 4 倍的情况下比人类专家高出 7.7 分，开发者仍只能通过反复试错手动调优 harness。

### 经过质量筛选的 Skill 发现机制

随着 skills 生态爆发，[@doodlestein](https://x.com/doodlestein) 和 [@_avichawla](https://x.com/_avichawla) 都只能手工整理 skills。除 K-Dense AI 与 Cisco scanner 的初步尝试外，整个生态尚不存在自动化的质量排序、安全扫描或兼容性验证机制。

## 4. 正在使用的工具和方法

| 工具 | 类别 | 评价 | 优势 | 局限 |
|------|------|-----------|-----------|-------------|
| Claude Code / Claude Agent SDK | Coding Agent | 褒贬不一 | 支持 subagent spawning、skills、hooks | SDK 设计迫使 harness 位于沙箱内；长 session 中会出现 context rot |
| Codex (OpenAI) | Coding Agent | 正面 | 配合合适的 harness 可一次性解决问题；支持 review mode | 对迭代式工作流不够灵活 |
| Hermes Agent (Nous Research) | 开源 Agent | 正面 | 80+ 个 tools、持久记忆、自动创建 skills、100+ 个社区 skills | 学习曲线较陡；skill 质量参差不齐 |
| Sandcastle | Agent Orchestrator | 正面 | 适用于任何 coding agent；为可插拔沙箱提供详细 RFC | 目前仅支持 Docker；迁移进行中 |
| Modal Sandboxes | Sandbox Infra | 正面 | 每个客户每秒可启动数百个；支持 GPU；文件系统快照 | 多区域调度复杂 |
| Pydantic Logfire / Monty | Observability + Sandbox | 正面 | 以单个 exec tool 替代 40 个 MCP tools，token 减少 90%+ | 需要 Rust sandbox（Monty） |
| LangChain / Deep Agents | Agent Framework | 正面 | 使用开放标准部署（AGENTS.md + /skills + mcp.json） | 多 agent 编排增加了出错面 |
| MCP (Model Context Protocol) | Tool Protocol | 正面 | 200+ 个 tools、统一协议；采用广泛 | tools 过多可能把 token 浪费在 schema 描述上 |
| Warp Terminal | Dev Tool | 正面 | 支持多个 coding agents（Auggie、Pi、Claude）；支持语音输入和媒体上传 | -- |
| RepoPrompt | Orchestration | 正面 | subagents 可使用任意模型；支持 multi-root 工作流；集成 MCP/CLI | -- |
| n-skills / openskills | Skill Marketplace | 正面 | 跨平台 skill 可移植性；通用安装器 | 仍处早期阶段；skill 质量参差不齐 |
| Cisco AI Defense Skill Scanner | Security | 正面 | 可对 agent skills 进行系统化安全扫描 | 目前仅应用于 scientific-agent-skills |

## 6. 新动态与值得关注的进展

### Pika 推出 Agent Skill 变现

[@pika_labs](https://x.com/pika_labs) [介绍了](https://x.com/pika_labs/status/2042656212685328799) 推出了面向 AI Self agents 的按交互付费变现机制。每条聊天消息或每次 skill 调用，都会为创建者带来可兑换现金的 tokens。这是首个在 skill 创建者与消费者之间建立直接经济反馈回路的大型平台，可能为 skill 经济起步铺路：质量将不再由把关者筛选，而是由使用量来奖励。

### Meta-Harness：自动化 Harness 优化击败人类

[Meta-Harness 论文](https://x.com/IntuitMachine/status/2042563676746481916)（arXiv:2603.28052v1）表明，如果给 AI agent 文件系统访问权限，让它接触既有代码、执行轨迹（最高 10M tokens）和失败日志，它就能自动优化 harness 代码，而且表现优于人类专家。它发现的 harness 不仅能泛化到分布外任务，还能泛化到完全不同的模型——其中包括在 TerminalBench-2 上为 Claude Haiku agents 取得 37.6% 成功率、排名第一。

### Linux Foundation 正式推动 Agent 生态成形

[@linuxfoundation](https://x.com/linuxfoundation) [开放了 CFP 征集](https://x.com/linuxfoundation/status/2042369516898791473) 宣传 AGNTCon + MCPCon North America（10 月 22—23 日，San Jose），并称其为“开放 agentic AI 生态的旗舰会议”。另外，他们还 [发布了](https://x.com/linuxfoundation/status/2042614167194960132) 发布了一份报告，指出四大优先主题：信任与身份、安全与隐私、在受监管行业中的采用，以及开源的作用。

### Agent-to-Agent 经济达到规模

[@MilkRoad](https://x.com/MilkRoad) 分享的 Etherealize.io 数据显示，x402 在九个月内已处理 140M 笔 agent-to-agent 交易，总额达 $43M。平均每笔交易为 $0.31，低于 Visa 固定收费的底线，因此原生加密支付轨道在 agent 微支付场景中具备结构性优势。

### Pydantic 通过工具整合将 Token 用量降低 90%

[@pydantic](https://x.com/pydantic) [演示了](https://x.com/pydantic/status/2042329212258807849) 表示，在沙箱化 Python 环境中用一个 exec tool 替代 40 个 MCP tools 后，token 用量下降了 90% 以上。这一洞见——“别再让模型从菜单里挑了，让它直接写程序”——对当前向 agent 暴露大量狭窄工具的主流方式提出了挑战。

## 7. 机会在哪里

**[+++］ 强烈看好：智能体技能安全与审计。** K-Dense AI 是唯一一个系统性扫描技能漏洞的团队。随着各生态中的技能不断扩散，以及 Anthropic 的 Mythos 证明即便是轻微的安全问题也能串联成破坏性极强的攻击，对技能安全工具——扫描器、证明机制、供应链验证——的需求将快速增长。(［K-Dense 安全扫描](https://x.com/k_dense_ai/status/2042635598201262099), [工具调用投毒论文](https://x.com/web3nomad/status/2042479883407016097))

**[+++］ 强烈看好：智能体支付与经济基础设施。** 仅在 x402 上，智能体之间的交易量就已经达到 1.4 亿笔，但目前还没有面向智能体的“Stripe”。在一个平均交易额只有 0.31 美元的世界里，计费、开票、授信、托管和信誉系统都需要被构建出来。(［Etherealize 报告](https://x.com/MilkRoad/status/2042324241136435595), [superpowerdotio](https://x.com/superpowerdotio/status/2042445013993558333))

**[++］ 中等看好：自动化 Harness 优化。** Meta-Harness 论文证明，自动化 harness 搜索不仅优于人工，而且使用的 token 更少。当前还没有任何生产级工具把这项能力打包出来。一个能基于执行轨迹自动调优 harness 代码的开发者工具，将为团队节省数周的手动迭代时间。(［Meta-Harness 论文](https://x.com/IntuitMachine/status/2042563676746481916))

**[++］ 中等看好：跨平台技能发现与质量排序。** n-skills 和 Agent Skills 标准提供了可移植性，但技能发现仍然依赖手动完成。一个可排序、可搜索，并带有兼容性验证、使用指标和安全证明的技能注册表，将服务于已经使用 AGENTS.md 的 20,000+ 个代码仓库。(［n-skills](https://x.com/tom_doerr/status/2042473956637123063), [avichawla 目录](https://x.com/_avichawla/status/2042493342303600644))

**[++］ 中等看好：企业级智能体治理。** 由于合规和安全要求，IT 专业人士对采用智能体持保留态度。能够将智能体工作流与现有企业系统（ServiceNow、ITSM、SOC2 控制）集成的工具，将打开一个巨大的市场细分领域。AWS Agent Registry 是其中较早的入局者。(［企业级怀疑情绪](https://x.com/dirtygreenpaper/status/2042371206993645750), [AWS Agent Registry](https://x.com/awscloud/status/2042298042204700891))

**[+］ 新兴方向：技能自我演化系统。** SkillClaw 和 Meta-Harness 论文都表明，技能可以基于使用数据自动改进。下一代技能系统很可能无需手动更新，而是从跨用户交互模式中学习并持续演化。(［SkillClaw](https://x.com/HuggingPapers/status/2042468122461163774), [Hesamation 关于技能演化的观点](https://x.com/Hesamation/status/2042600734491808220))

**[+］ 新兴方向：共享型智能体知识网络。** unbrowse 展示了一种网络效应：一个智能体的网页浏览能让其他所有智能体受益，在 5 周内节省了 2600 万个 token。这种模式——智能体向共享知识池贡献信息——有望从浏览场景扩展到代码理解、API 发现和领域专业知识。(［unbrowse 指标](https://x.com/unbrowse/status/2042331778694987967))

## 8. 核心结论

1. **Harness 工程如今已成为提升 agent 性能的首要杠杆。** 当天最火的那条推文展示了一个具体调试案例：通过为 agent 提供隔离实验、反馈循环和文件系统访问权限，这套 harness 方法将部署时间缩短了 85%。研究也证实，自动化 harness 搜索比人类专家高出 7.7 分。（[elvissun](https://x.com/elvissun/status/2042633997080224034)）

2. **Agent skills 生态已来到标准化拐点。** AGENTS.md 已进入 20,000+ 个仓库，Expo 默认自动生成该文件，LangChain 用它做部署，n-skills 则提供跨平台可移植性。Skills 已不再是 Claude 的专属特性，而正逐渐成为开放标准。（[Baconbrix](https://x.com/Baconbrix/status/2042668807152636379)）

3. **Agent 变现已从概念走向生产。** Pika 推出了 skills 按交互付费机制，x402 协议处理了 140M 笔 agent-to-agent 交易，Escroue 也凭借无信任的 agent-to-agent 托管获得 hackathon 奖项。面向 agent 的经济层正在实时搭建中。（[pika_labs](https://x.com/pika_labs/status/2042656212685328799)）

4. **沙箱基础设施是隐藏瓶颈，而这一问题正在被解决。** Modal 运行着 100K+ 个并发沙箱，Sandcastle 正转向可插拔架构，Netlify 已上线源于 agent 沙箱需求的 MicroVM，Pydantic 则证明，把 40 个工具合并为一个沙箱化 exec tool 可将 token 用量降低 90%。（[sarahcat21](https://x.com/sarahcat21/status/2042269181396042036)）

5. **Agent 安全是这个领域最被忽视的短板。** Willison 的“致命三要素”、CrowdStrike 在 RSAC 上给出的 agent 重写安全策略案例、Claude Managed Agents 中 workspace 级凭据泄露，以及工具调用供应链攻击，都预示着一场生态尚未准备好的安全 reckoning。（[lennysan](https://x.com/lennysan/status/2042358861907312836)）

6. **自我改进的 skill 系统正从研究走向现实。** SkillClaw 展示了 skills 如何通过集体演化在 6 天内从 11% 提升到 88%。再结合 Meta-Harness 论文中自动化 harness 搜索超越人类的结果，趋势正指向能够自行优化工具链的 agent。（[HuggingPapers](https://x.com/HuggingPapers/status/2042468122461163774)）

7. **开发者工作流从编码转向 agent 编排的变化正在加速。** 多位实践者表示，他们已经连续数周“没有亲手写过任何东西”。正在形成的新技能组合——上下文工程、subagent spawning、harness 设计、skill 编写——正在部分工作流中取代传统编码。（[tmpka](https://x.com/tmpka/status/2042395374875230355)）
