# Twitter AI Agent - 2026-04-29

## 1. 人们在讨论什么

### 1.1 Agentic Harness Engineering 论文将自我改进的 Harness 正式化 🡕

当天信号最强的内容是一篇新论文（arXiv:2604.25850v1），提出了 Agentic Harness Engineering（AHE）。该论文由 [@omarsar0](https://x.com/omarsar0) 在 [详细拆解](https://x.com/omarsar0/status/2049492169887748365) 中分享（500 个赞、1,013 个书签、34,840 次浏览）。这一框架通过三大支柱让 Harness 的演进变得可观测：组件可观测性（可回滚的文件级编辑）、经验可观测性（从数百万轨迹 token 中浓缩出的证据），以及决策可观测性（可根据任务结果检验的可证伪预测）。结果显示：经过十轮迭代，Terminal-Bench 2 的 pass@1 从 69.7% 提升至 77.0%，超过人工设计的 Codex-CLI（71.9%）以及自我演进基线 ACE 和 TF-GRPO。演进后的 Harness 还能跨模型家族迁移，带来 +5.1 到 +10.1 个百分点的提升，同时减少 12% 的 token 使用量。

![Agentic Harness Engineering 论文摘要，展示三大可观测性支柱和基准测试结果](https://pbs.twimg.com/media/HHFCQ83aUAAhdyU.jpg)

Martin Fowler [链接](https://x.com/martinfowler/status/2049480328423608522)（139 个赞、170 个书签）在其 fragments 页面推荐了 Birgitta Böckeler 的 harness engineering 视频和 Chris Parsons 更新后的 AI 编程指南。后者指出：“现在比的已经不是‘我们能多快构建出来’，而是‘我们能多快判断它是否正确’。”[@jobergum](https://x.com/jobergum) [发文](https://x.com/jobergum/status/2049391374189973839)（80 个赞、91 个书签）分享了清华大学的 Skill Retrieval Augmented Agents 论文。该论文提出从包含 26,262 项技能的语料库中动态检索技能。其 SRA-Bench 发现：无论任务是否真的需要外部能力，当前 agent 加载技能的频率都相近——瓶颈不在于知道*检索什么*，而在于知道*何时加载*。

![Skill Retrieval Augmentation for Agentic AI 论文摘要，包含 SRA-Bench 方法论](https://pbs.twimg.com/media/HHDmDfZa8AAAGci.jpg)

**讨论洞察：** [@RuijieRao](https://x.com/RuijieRao) 给出了最贴近实践的回应：“手动调优这件事确实存在。构建 agent 工作流时，我大部分时间并不是在写核心逻辑，而是在迭代 harness 配置……瓶颈在于，不运行完整任务，就无法评估 harness 的质量。”[@ethankongee](https://x.com/ethankongee) 则把这个框架扩展为：自我改进 + 自我修复 + 自我安全 + 自我维护 = 完整愿景。[@DylSwanepoel](https://x.com/DylSwanepoel) 点出了核心价值：“让 agent 的改进变得可证伪，而不是凭感觉。”

**与前一天对比：** 4 月 28 日，harness engineering 通过 ODSC 演讲登上会议舞台；4 月 29 日则出现了首个用基准结果验证、可自动化 harness 演进的同行评审框架，推动范式从“教它”转向“让它自己改进”。

### 1.3 Cursor SDK 和 /multitask 将 Agent 作为基础设施交付 🡕

Cursor 做出了两项重要动作。[@cursor_ai](https://x.com/cursor_ai) [推出了 Cursor SDK](https://x.com/cursor_ai/status/2049499866217185492) 发布后，开发者可以使用驱动 Cursor 的同一套运行时、harness 和模型来构建 agent——可从 CI/CD 流水线、自动化流程中运行，也可嵌入产品。[@alphabatcher](https://x.com/alphabatcher) [将其定义为](https://x.com/alphabatcher/status/2049598518860431807)（11 个赞）写道：“CI 失败 > agent 被唤醒 > 检查仓库 > 修补 bug > 发起 PR > 如果需要人类接手，它就会出现在 Cursor 里。到某个阶段，IDE 不再是 agent 栖身之处，而变成了你检查 agent 的地方。”

与此同时，[@kevinkern](https://x.com/kevinkern) [报道称](https://x.com/kevinkern/status/2049581481195090035)（33 个赞、12 个书签）称 Cursor 已发布 /multitask：“不再由一个 agent 在一个超长上下文里包办所有事，主 agent 可以把工作拆分成更小的异步子 agent……你还可以在 Cursor 的 harness 里为不同任务使用不同模型。我一直让 Opus 4.7 充当主协调器，让 GPT-5.5 high 负责实现任务。”

**讨论洞察：** [@infix_fun](https://x.com/infix_fun) 指出了一项限制：“我只是希望它能稳定工作。它并没有像我想要的那样尽可能并行化。”这种跨模型编排模式——高端模型负责协调、低成本模型负责实现——正成为现实中的默认方案。

**与前一天对比：** 4 月 28 日，jcode 推出了处于灰色地带的并行 agent 会话；4 月 29 日，Cursor SDK 给出了正式版本：官方支持、可嵌入 CI/CD 的 agent 运行时，以及通过 /multitask 实现的 IDE 原生编排。

[@akoratana](https://x.com/akoratana) [描述](https://x.com/akoratana/status/2049202079185698937)（90 个赞、135 个书签）分享了“context graph”——一种不是靠手工文档，而是从工作过程留下的痕迹中自然形成的公司世界模型。核心论点是：PlayerZero 仅凭六个月积累的上下文，就把模拟准确率从 54% 提升到了 95+%。[@DeepLearningAI](https://x.com/DeepLearningAI) [报道](https://x.com/DeepLearningAI/status/2049252707144499246)（25 个赞、11 个书签）分享了一场关于记忆工程和上下文工程的工作坊，其中有一句话：“没有记忆的 AI Agent，不过是胸怀野心的自动补全。”

**与前一天对比：** 4 月 28 日聚焦于记忆架构的逆向工程（Hermes 五层系统）；4 月 29 日则上升到更高抽象层次：把编排与上下文视为统一的工程学科。

### 1.5 Agent-to-Agent 商业交易首次获得真实资金证据 🡕

[@omooretweets](https://x.com/omooretweets) [分享](https://x.com/omooretweets/status/2049516859658293303)（70 个赞、64 个书签、9,949 次浏览）分享了 Anthropic 内部的“Project Deal”实验：Claude 采访了 69 名员工，了解他们想买卖的物品，搭建了一个分类信息市场，并由 agents 自主协商交易。结果是达成 186 笔匹配，完成了超过 $4,000 的真实交易，交换的实物从滑雪板到乒乓球不等。参与者表示愿意为类似服务付费。

![Anthropic 博客摘录，介绍 Project Deal：共 186 笔交易，总交易额超过 4,000 美元](https://pbs.twimg.com/media/HHFWe1GaEAApzre.jpg)

[@ryanmcnutty33](https://x.com/ryanmcnutty33) 指出了基础设施缺口：“我觉得要让这件事成立，我们需要一种供 agents 使用的无线电。我想的是某种新基础设施，像广播一样让其他 agents 看见彼此，而不只是依赖中心化查询。发现机制会是个大问题。”[@pjmfinn](https://x.com/pjmfinn) 则将应用场景扩展到：“LinkedIn 也该往这个方向走。用一个 agent 中介来验证传入信息，并帮你处理传出信息。”

**讨论洞察：** 从“agent 协商理论交易”转向“agent 在真实员工之间用真实资金协商真实实物交易”，是一次显著的证据升级。被指出的瓶颈——agent 发现基础设施——从另一个角度映射了技能检索问题。

**与前一天对比：** 4 月 28 日通过 [@DeFi_Pop](https://x.com/DeFi_Pop) 首次报道了这一实验；4 月 29 日则浮现出一手来源（Anthropic 博客）以及聚焦基础设施缺口的实践者反馈。

### 1.7 OneManCompany 组织型 MAS 框架获得关注 🡕

[@TheTuringPost](https://x.com/TheTuringPost) [发布](https://x.com/TheTuringPost/status/2049589752899510471)（6 个赞、6 个书签）详细拆解了华为诺亚方舟实验室的 OneManCompany 框架。关键创新包括：Skills 变成 Talents（包含角色、工具、提示词、配置在内的完整 agent 包）；Container = 运行时（Claude Code、LangGraph、脚本）；用于动态招聘的 Talent Market；E2R（Explore-Execute-Review）树搜索；以及包含绩效评估、PIP、离职和替换在内的人力资源生命周期。结果是：在 PRDBench 上达到 84.67%，比基线高出 15 个百分点。

[@Jiaru_Zou](https://x.com/Jiaru_Zou) [推出](https://x.com/Jiaru_Zou/status/2049551828296389118)（34 个赞、28 个书签、5,360 次浏览）分享了 RecursiveMAS，这是一种互补方案：通过潜在空间递归实现多 agent 协作，在 9 个基准测试中平均准确率提升 +8.3%，推理速度提升 1.2-2.4 倍，token 使用量减少 34.6-75.6%。

**与前一天对比：** 4 月 28 日，OMC 获得了 68 个书签；4 月 29 日则新增了详细的技术拆解和一种互补的递归方案，进一步坐实了组织隐喻作为主流多 agent 架构模式的地位。

## 2. 什么让人沮丧

### 编程 Agent 不会把反馈沉淀为可复用知识——严重程度：高

[@RhysSullivan](https://x.com/RhysSullivan) [阐明](https://x.com/RhysSullivan/status/2049540492908810559)（34 个赞、1,787 次浏览）指出了这一缺口：“编程 agents 不会充分推动你去复用反馈。我刚刚告诉我的 agent，它做 optimistic updates 的方式不对，但并没有一个被鼓励的‘第二步’，去把这些知识编码下来供未来使用。”[@skeptrune](https://x.com/skeptrune) 证实了这个问题：“claude code 已经开始说‘我为此添加了一条 memory’，但我倾向于认为，这么做只会把你带向上下文腐化。”[@_jack_hogan](https://x.com/_jack_hogan) 补充道：“大量使用 memories 感觉不对（而且不可靠），我也不确定怎样做才是最优的。”唯一明确的变通办法来自 [@NathanOyler](https://x.com/NathanOyler)：“我会把知识编码进 skills……也会用 cronjobs 去改进 skills。”

### Harness 主权 vs 平台锁定——严重程度：中

[@Vtrivedy10](https://x.com/Vtrivedy10) [认为](https://x.com/Vtrivedy10/status/2049597811226726682)（12 个赞）指出，harness “会深刻影响 agent 表现”，把它外包就意味着“祈祷实验室或封闭 harness 替你把这件事做好，并且他们的目标和你一致”。[@jobergum](https://x.com/jobergum) 说得很直接：“不要把你的 agent harness 外包出去。”[@itunpredictable](https://x.com/itunpredictable) [整理汇编](https://x.com/itunpredictable/status/2049479276873855218)（53 个赞、3,337 次浏览）列举了涌向实践者的相互冲突的话术：“我们在做一家 agent harness 公司。我们要转型做面向编程 agents 的开源 IDE。这是你内部大脑的上下文引擎。”信号很明确：开发者想掌握 harness 的所有权，但生态碎片化让选择代价很高。

### Cursor /multitask 的并行化不稳定——严重程度：低

[@infix_fun](https://x.com/infix_fun) [报道称](https://x.com/kevinkern/status/2049581481195090035)：“它并没有像我希望的那样尽可能并行化。事实上，我有一次会话里，它一直把任务派发给同一个 agent。”这属于早期编排 UX：能力已经有了，但可靠性仍不均衡。

## 3. 人们希望出现什么

### 默认将反馈转化为技能的 Agent 行为

[@RhysSullivan](https://x.com/RhysSullivan/status/2049540492908810559) 和多条回复都证实：当你纠正一个 agent 时，这个纠正应该自动变成可复用的技能或规则，而不是脆弱的 memory 条目。当前方案（会腐化的 memories、手动创建 skills）都需要额外的人力投入，抵消了效率提升的意义。需求是：一个框架级的“反馈捕获 > 技能合成 > 验证”流水线。

紧迫性：高 —— 机会：直接产品

### 面向商业交易的 Agent 发现基础设施

[@ryanmcnutty33](https://x.com/ryanmcnutty33) 在回应 Anthropic 的 marketplace 实验时指出：“需要某种新基础设施，像广播一样让其他 agents 看见彼此，而不只是依赖中心化查询。”随着 agents 开始进行交易，它们需要去中心化的发现机制——相当于 agent 服务世界里的 DNS。

紧迫性：中 —— 机会：基础设施

### 大规模技能质量验证

SR-Agents 论文显示，agents 不论是否需要技能，都会加载技能。随着技能语料库不断扩大（该基准中已达 26,262+ 项），缺失的一层是自动质量评分和相关性门控——不仅要知道*哪些*技能存在，还要知道加载它是否真的有助于当前任务。

紧迫性：中 —— 机会：研究转产品

## 6. 最新且值得关注

### Agentic Harness Engineering 论文引入可观测的自我改进

[AHE 论文](https://x.com/omarsar0/status/2049492169887748365)（1,013 个书签）是首个展示自动化 harness 演进且具备可证伪预测的同行评审成果。Terminal-Bench 2 上 77.0% 的 pass@1 同时超过人工设计的 harness 和此前的自我演进方案，并且能跨模型家族迁移。代码：[github.com/china-qijizhifeng/agentic-harness-engineering](https://github.com/china-qijizhifeng/agentic-harness-engineering)。

信号强度：[+++]

### Cursor SDK 让 IDE 的 Agent 运行时可嵌入

[Cursor SDK](https://x.com/cursor_ai/status/2049499866217185492) 让开发者可以在 CI/CD 流水线、自动化流程或产品中运行同一套 agent runtime。再结合 /multitask（跨模型编排），Cursor 从 IDE 转变为 agent 基础设施提供商。[@alphabatcher](https://x.com/alphabatcher) 描述的“CI 失败 > agent 修补 > 发起 PR”工作流，如今已获得官方支持。

信号强度：[+++]

### Martin Fowler 认可“验证优先”的 Harness Engineering

Fowler 的 [fragments 页面](https://x.com/martinfowler/status/2049480328423608522)（170 个书签）传递的核心论点是：“现在比的已经不是‘我们能多快构建出来’，而是‘我们能多快判断它是否正确’。”他对 Birgitta Böckeler 的 harness engineering 文章（以及一场新的视频讨论）的认可，表明这一概念已从实践者 Twitter 进入软件架构主流圈层。

信号强度：[++]

### Anthropic 的 Project Deal：186 笔真实资金的 Agent-to-Agent 交易

Anthropic 的 [内部市场实验](https://x.com/omooretweets/status/2049516859658293303)（64 个书签）在 69 名员工之间促成了 186 笔交易，真实成交金额超过 $4,000，且交易的都是实体商品。这是迄今最有力的证据，证明 agent-to-agent commerce 在真实利益驱动下也能运作。参与者明确表示“愿意为类似服务付费”，显示出消费者需求。

信号强度：[++]

### xAI 通过 Grok Skills 标签页加入 Skills 生态

[@WesRoth](https://x.com/WesRoth/status/2049534178249846887) 报道称，xAI 正在为 Grok 开发 Skills 标签页（目前隐藏），Grok 4.3 支持创建技能。这使 xAI 成为继 Google、Anthropic 生态、OpenAI 之后，第四个采用 skills 作为扩展原语的主要平台，正接近普遍收敛。

信号强度：[+]

## 7. 机会在哪里

**[+++］ 反馈到技能的流水线**——“我纠正了我的代理”和“代理永久学会了这件事”之间的差距，是多个独立实践者最一致提到的痛点。［@RhysSullivan](https://x.com/RhysSullivan/status/2049540492908810559)、[@skeptrune](https://x.com/skeptrune) 和 [@_jack_hogan](https://x.com/_jack_hogan) 都证实，当前做法（memories、手动编写 skills）并不够好。机会在于构建自动化系统：捕获纠正内容，将其合成为经过验证的 skills，并清理陈旧技能。当前唯一被明确提到的有效模式，是 [@NathanOyler](https://x.com/NathanOyler) 手动用“cronjobs 改进 skills”——这非常适合产品化。

**[+++］ 具备可观测演化的开放 harness**——AHE 论文证明，harness 可以实现可量化的自我改进。［@Vtrivedy10](https://x.com/Vtrivedy10/status/2049597811226726682) 和 [@jobergum](https://x.com/jobergum) 都认为，开发者应掌握自己的 harness。机会在于打造一个开源 harness 底座，并内置 AHE 式可观测性：每次编辑都被跟踪、每个预测都可证伪、性能提升无需完整重跑任务也能衡量。第一个把这些能力做成产品特性的 harness，将吸引那些当前仍在手动调优的实践者。

**[++] Agent discovery and commerce infrastructure** -- Anthropic proved agents can transact. [@ryanmcnutty33](https://x.com/ryanmcnutty33) 指出了缺失的一层：广播/发现基础设施，让 agents 无需中心化查询就能彼此发现。随着 skills 市场持续扩张（Swarms、Cursor、Google），agent-to-agent 服务发现的互操作层将成为关键基础设施。

**[++］ 技能质量与相关性门控**——SR-Agents 论文（［@jobergum](https://x.com/jobergum/status/2049391374189973839) 揭示了 agents 会不加区分地加载技能。随着技能语料规模达到并超过 26,262 项，机会在于构建一个在加载前就评估技能相关性的检索层——避免上下文浪费和错用技能。这就是 skills 生态里的“搜索质量”问题。

**[+］ 跨模型编排工具**——［@kevinkern](https://x.com/kevinkern/status/2049581481195090035) 展示了 Opus 4.7 负责编排、GPT-5.5 负责实现的模式。Cursor 的 /multitask 支持这种模式，但并不稳定。机会在于构建可靠的跨模型编排：高端模型负责规划，低成本模型负责执行，并根据子任务复杂度自动选择模型。

## 8. 要点总结

1. **Agentic Harness Engineering 论文（1,013 个书签）证明，harness 的自我改进既可衡量也可迁移：十轮迭代后，pass@1 从 69.7% 提升至 77.0%，超过人工设计和自我演进基线，同时减少 12% 的 token 使用量。** 这让 harness engineering 从“教人如何调优”转向“让 harness 在可观测契约下自行调优”。（[来源](https://x.com/omarsar0/status/2049492169887748365)）

2. **Agent skills 生态已完成收敛：Obsidian（27K stars）、xAI/Grok、VS Code Agent Plugins、Cursor SDK、Google，以及多个垂直领域仓库都在同一天发布或宣布支持 skills，使 Agent Skills spec 成为事实上的 agent 扩展标准。**（[来源](https://x.com/bigaiguy/status/2049452001592025415)、[来源](https://x.com/WesRoth/status/2049534178249846887)、[来源](https://x.com/code/status/2049299889381626029)）

3. **Cursor SDK 正把 IDE 从工作空间转变为 agent 基础设施提供商：可嵌入 CI/CD 的运行时、通过 /multitask 实现的跨模型编排（Opus 4.7 规划、GPT-5.5 执行），以及明确的论点——“IDE 会变成你检查 agents 的地方”。**（[来源](https://x.com/cursor_ai/status/2049499866217185492)、[来源](https://x.com/kevinkern/status/2049581481195090035)）

4. **Anthropic 的 Project Deal 提供了迄今最强的 agent-to-agent commerce 证据：186 笔真实交易、超过 $4,000 的成交额、实体商品交换，且参与者愿意为该服务付费——讨论焦点由“agents 能否交易？”转向“它们需要什么样的发现基础设施？”**（[来源](https://x.com/omooretweets/status/2049516859658293303)）

5. **“反馈到技能”的断层，成了当天最一致的实践者痛点：agents 会接受纠正，却不会把纠正沉淀为可复用技能，导致开发者在不同会话中反复纠正同样的错误。** 现有变通方案（memories、手动 skills、cronjobs）都被一致认为不够理想。（[来源](https://x.com/RhysSullivan/status/2049540492908810559)）

6. **Martin Fowler 对“验证优先”的 harness engineering 的认可——“现在比的不是‘我们能多快构建’，而是‘我们能多快判断它是否正确’”——标志着这一概念已获得软件架构主流认可，完成了从 Twitter 讨论到 Fowler 推荐的演进。**（[来源](https://x.com/martinfowler/status/2049480328423608522)）
