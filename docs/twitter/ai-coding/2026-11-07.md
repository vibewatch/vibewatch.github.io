## 2. What Frustrates People

### Context loss and compaction

**Severity: High for the users reporting it; prevalence is unknown.** [@JafarNajafov](https://x.com/JafarNajafov) says tool output, issue lists, and logs consume substantial context, and that compaction can leave the agent forgetting active files and tasks. Context Mode is presented as both an output filter and local SQLite-backed state store; the post's percentage savings are the author's claims, not an independent benchmark. ([post](https://x.com/JafarNajafov/status/2119009890379452866); 24 likes, 10 retweets, 20 replies, 1 quote, 1,261 views, 3 bookmarks.)

![Context Mode README graphic promoting context savings and listing integrations; the graphic is product material, not an independent benchmark](https://pbs.twimg.com/media/HWg8RAXbgAA_GE8.jpg)

**Discussion insight:** A reply argues that raw tool output should remain in a file for targeted search rather than merely being trimmed, and another asks whether the plugin preserves task lists after compaction. The disagreement is about durable, inspectable state, not just reducing tokens.

The attached screen depicts a 100% used five-hour Gemini limit alongside a 25% weekly limit. ## 3. What People Wish Existed

### More predictable, person-level usage

The explicit request is for at least 2x more quota on an Antigravity plan, with family-shared usage described as interrupting individual work. This is a practical and urgent need for the user who raised it; the screenshot provides a usage view, but not a remedy for the requested headroom. **Opportunity: Direct**, with prevalence still unestablished. ([@Soso_fun_yt](https://x.com/Soso_fun_yt), [post](https://x.com/Soso_fun_yt/status/2118959006752358704); 35 likes, 7 replies, 3,150 views, 6 bookmarks.)

### Session state that survives context pressure

The desired outcome is for an agent to retain active files, task lists, and useful tool output across compaction, with raw material still searchable. Context Mode partially addresses this with output filtering and local SQLite state, while a reply argues that keeping raw output available for targeted search matters more than simply shrinking it. **Opportunity: Competitive**, since a solution is already being promoted but the thread raises open questions about what survives. ([@JafarNajafov](https://x.com/JafarNajafov), [post](https://x.com/JafarNajafov/status/2119009890379452866); 24 likes, 10 retweets, 20 replies, 1 quote, 1,261 views, 3 bookmarks.)

### More reliable browser recordings and profiles

A tester said OpenCode Browse worked, then asked for higher-quality recordings and easier setup of separate profiles. This is a practical workflow request rather than a request for browser control itself, which Browse already provides. **Opportunity: Competitive**, because the underlying product exists and the requested gaps are specific to configuration and replay. ([@maharshi365](https://x.com/maharshi365), [reply in the OpenCode test thread](https://x.com/thdxr/status/2118878460391137310); 4 likes, 1 reply, 877 views, 1 bookmark.)

The strongest evidence is direct user testimony and public issue reports, not a measure of how many users are affected. ## 8. Takeaways

1. **Browser access and project isolation solve different boundary problems.** OpenCode Browse works through a user's browser session, while DevVM isolates each project's agent environment. ([@opencode](https://x.com/opencode), [post](https://x.com/opencode/status/2118895128152621153); 183 likes, 12 retweets, 11 replies, 4 quotes, 4,272 views, 44 bookmarks; [@RoundtableSpace](https://x.com/RoundtableSpace), [post](https://x.com/RoundtableSpace/status/2118874827683774478); 26 likes, 2 retweets, 24 replies, 48,708 views, 9 bookmarks.)

2. **The clearest user frustrations concern context continuity and usage limits.** They include specific requests and issue reports, but do not establish how widespread the problems are. ([@JafarNajafov](https://x.com/JafarNajafov), [post](https://x.com/JafarNajafov/status/2119009890379452866); 24 likes, 10 retweets, 20 replies, 1 quote, 1,261 views, 3 bookmarks; [@Soso_fun_yt](https://x.com/Soso_fun_yt), [post](https://x.com/Soso_fun_yt/status/2118959006752358704); 35 likes, 7 replies, 3,150 views, 6 bookmarks.)

3. **Agent coordination is becoming a product surface of its own.** Projects, team chat integrations, skill sources, and code-review controls appear across the day's launches. ([@github](https://x.com/github), [post](https://x.com/github/status/2119133311465353675); 114 likes, 10 retweets, 35 replies, 1 quote, 20,008 views, 30 bookmarks; [@papercliping](https://x.com/papercliping), [post](https://x.com/papercliping/status/2119172409995505851); 25 likes, 4 retweets, 4 replies, 1 quote, 1,068 views, 11 bookmarks.)

4. **Demos show concrete outputs, not adoption.** Trips, desktop app examples, and a long-running harness playbook provide implementation detail, but remain demos or single reported examples. ([@haydenbleasel](https://x.com/haydenbleasel), [post](https://x.com/haydenbleasel/status/2118849385992003748); 13 likes, 1 retweet, 4 replies, 991 views, 6 bookmarks; [@Asteri_eth](https://x.com/Asteri_eth), [post](https://x.com/Asteri_eth/status/2119015743572398348); 4 likes, 1 reply, 22 views, 3 bookmarks.)
