### 1.5 对抗式多模型工作流开始成为一种实践 🡕

[@0xLatencyZero](https://x.com/0xLatencyZero) [发布了一张工作流图](https://x.com/0xLatencyZero/status/2047739858656067709)（1 个赞、137 次浏览、2 个收藏）介绍了“对抗式审查”——先用 Claude Code 中的 Opus 4.7 起草实现，再用 Codex 插件里的 GPT-5.5 审查 diff：“两款前沿模型。训练不同，盲点不同，彼此独立审查。”流程是：开发者把意图发给 Claude Code，由它起草并构建；再把 diff 交给 Codex，由后者标记逻辑漏洞、回归问题和安全偏移；审查通过后代码再发布。

![对抗式审查工作流，显示 Claude Code Opus 4.7 先起草实现方案，再由 Codex GPT-5.5 审查 diff 以查找逻辑漏洞和回归问题](https://pbs.twimg.com/media/HGsHxzQbwAASSQR.png)

[@mr_the_dooom](https://x.com/mr_the_dooom) [描述了类似的模式](https://x.com/mr_the_dooom/status/2047561045041156219)（0 个赞、27 次浏览）：“让 Claude 纯粹担任经理、架构师和文档维护者，让 codex 当一个由 Claude 驱动的写码苦工。不知为何，这种搭配产出高得离谱，而且 token 用量很低。”

Nadella 的帖子也从平台层面印证了这一点。他描述了“Rubber Duck agent”：由“GPT-5.5 审查另一个模型的输出，或者反过来”。

**讨论洞察：** 对抗式多模型审查正同时从两个方向浮现：一是自上而下，由 Nadella 将其描述为平台功能；二是自下而上，由从业者自行摸索出来。共同认识是：不同实验室的模型有不同失效模式，因此跨实验室审查能抓到同模型自审容易漏掉的 bug。

**与前一天对比：** 4 月 23 日，人们注意到，评测框架质量比模型选择更重要（kylejeong 展示了同一模型也会产出不同结果）。而今天，这一模式进一步发展成有意设计的多模型流水线：由不同实验室的模型承担互补角色，一个负责起草，另一个负责审查。

### 1.7 Copilot SDK v0.3.0 与 JetBrains Agent Mode 发布 🡕

[@GHCopilotCLILog](https://x.com/GHCopilotCLILog) [宣布](https://x.com/GHCopilotCLILog/status/2047710970454114772)（24 个赞、1,231 次浏览）介绍了带来 40 项功能与增强的 Copilot SDK v0.3.0。关键能力包括：支持按会话进行 GitHub 身份验证，使不同会话可携带不同身份；通过 `defaultAgent.excludedTools` 实现按智能体控制工具可见性，从而支持带子智能体委派的编排模式；自定义智能体可通过声明 `skills: string[]` 注入特定技能；以及在消息增量事件中通过 `agentId` 标识子智能体流，以便进行更细粒度的 UI 过滤。会话默认不再在 30 分钟后超时，技能也改为严格的选择加入机制，以防止从父智能体意外继承。

**讨论洞察：** 这次 SDK 发布表明，Copilot 正在把自己的智能体平台推向接近最终 GA 的状态。按会话身份和子智能体委派等功能，使其具备了多智能体编排模式所需的能力，也与从业者社区里正在浮现的对抗式工作流形成呼应。

## 8. 要点

1. **GPT-5.5 的采用正在带来真实的订阅迁移，而不只是基准测试热度。** [@mckaywrigley](https://x.com/mckaywrigley) [报告称](https://x.com/mckaywrigley/status/2047806060061507971) 在不到三个月内从 80/20 的 Claude/GPT 变成了 80/20 的 GPT/Claude。[@Kappaemme1926](https://x.com/Kappaemme1926) [贴出了 Claude 取消订阅邮件](https://x.com/Kappaemme1926/status/2047598921996984495)。[@Colewherld](https://x.com/Colewherld) [称 Codex 为](https://x.com/Colewherld/status/2047684720675221653) 则称其“比 Claude Code 强了几个光年”。上线次日释放出的信号，是迁移，而不是继续观望。

2. **速率限制已成为所有提供商共同面对的核心用户体验问题。** [@notjazii](https://x.com/notjazii) [迅速耗尽了](https://x.com/notjazii/status/2047616448818708828) 在 36 小时内就耗尽了 Antigravity 配额（90 条回复，为数据集最高）。[@MilkRoadAI](https://x.com/MilkRoadAI) [报告称](https://x.com/MilkRoadAI/status/2047797528293188024) 还提到 Anthropic 下调 Claude 的思考深度。2026 年超大规模云厂商合计 7000 亿美元的资本开支，依旧无法满足需求。算力短缺是结构性的，不是暂时性的。

3. **OpenCode 已成为评估新模型的中立地带。** [@rileybrown](https://x.com/rileybrown) [提问](https://x.com/rileybrown/status/2047734309361254897) 向 4,998 人提出了“测试新版 Deepseek 模型的最佳方式是什么？”而答案是 OpenCode。[@mehulmpt](https://x.com/mehulmpt) [用了它](https://x.com/mehulmpt/status/2047778103645364295) 则用它做了一次四模型对比。[@opencode](https://x.com/opencode) [集成了](https://x.com/opencode/status/2047562491878572153) 又在 DeepSeek V4 发布几小时内就完成了接入。随着各实验室持续垂直整合（Codex、Claude Code、Gemini Code Assist、Cursor/xAI），模型无关层会变得愈发关键。

4. **对抗式多模型工作流正在演变为生产实践。** [@0xLatencyZero](https://x.com/0xLatencyZero) [发布了](https://x.com/0xLatencyZero/status/2047739858656067709) 展示了 Claude 起草、Codex 审查的流水线。[@satyanadella](https://x.com/satyanadella) [描述了](https://x.com/satyanadella/status/2047743653045837988) 则把多模型反思描述为平台功能。核心洞见在于：不同实验室的模型有互补盲点，因此跨实验室审查比单模型工作流更能抓出 bug。

5. **20 美元 AI 编程工具市场没有明确赢家，用户困惑却达到最高点。** [@Bhavani_00007](https://x.com/Bhavani_00007) 的 [问题](https://x.com/Bhavani_00007/status/2047653349550612623) 收到 41 条回复，仍没有形成共识。Codex、Cursor 和 Claude Code 在不同使用场景中各有支持者。这种入门价位的碎片化，为聚合或路由型解决方案创造了空间。

6. **Copilot 智能体平台的成熟速度，快于生态系统对它的关注。** SDK v0.3.0 带来了 40 项功能，包括按会话身份验证、子智能体委派和技能选择加入（[@GHCopilotCLILog](https://x.com/GHCopilotCLILog)、[发布](https://x.com/GHCopilotCLILog/status/2047710970454114772)）。JetBrains 内联智能体模式也进入了公开预览（[@GHchangelog](https://x.com/GHchangelog)、[公告](https://x.com/GHchangelog/status/2047722253098311791)）。当大多数注意力还停留在模型对比上时，多智能体编排所需的基础设施已经在持续落地。
