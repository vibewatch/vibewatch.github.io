# Twitter AI 编程 - 2026-11-16

## 1. 大家在讨论什么

### 1.1 Codex 容量有所改善，但用户仍在呼吁调整使用限制 🡕

当天热度最高的帖子及其回复都在讨论 Codex 容量错误，另一条讨论串则呼吁调整会话限制。容量更新附带的图表显示，报告的错误占比从 6.82% 降至 0.085%。

[@thsottiaux](https://x.com/thsottiaux) [称 Codex 团队或许已经修复了“模型容量已满”错误](https://x.com/thsottiaux/status/2122206990101536852)（2,517 个赞、85 次转发、798 条回复、162,441 次浏览、149 次收藏）。

![图表显示，Codex 容量错误占比从 6.82% 降至 0.085%](https://pbs.twimg.com/media/HXOX68AaYAAlezW.jpg)

[@JamesMalsawm](https://x.com/JamesMalsawm) [请用户在新模型、累积用量和取消 Plus 五小时限制之间做出选择](https://x.com/JamesMalsawm/status/2122230689487897008)（39 个赞、35 条回复、2,848 次浏览）。

**讨论洞察：** 回复对容量改善表示欢迎，但对改善原因并未达成一致；一条获得大量点赞的回复认为，用户转向了 Opus 5.5。另一条关于使用限制的讨论串则出现了要求重置限制、减少长任务中断的呼声。

**与前一天的对比：** 11月15日的报告聚焦于计划审查、安全工作流和检查清单。当天的讨论中，容量错误和订阅限制更加突出。

### 1.2 验证流程纳入了智能体无法绕过的检查 🡕

四条帖子分别介绍了相关的故障模式与控制措施：测试全绿却仍发生生产事故、跨模型检查脚本、代码库验证工作流，以及有上限的重试规则。这些证据从单次故障报告到工作流建议不等，并不能说明这类问题有多普遍。

[@PatchOnChain](https://x.com/PatchOnChain) [报告称，某个智能体生成了 48 项测试、覆盖率达到 99.4% 后，出现重复扣费和 500 错误](https://x.com/PatchOnChain/status/2122087566774296914)（6 个赞、10 条回复、869 次浏览）。作者称，问题出在模拟对象对自身桩代码进行了断言。

[@elessarqq](https://x.com/elessarqq) [分享了一套由四个文件组成、支持跨模型的配置](https://x.com/elessarqq/status/2122365816725233718)（17 个赞、1 次转发、10 条回复、548 次浏览）。作者称，关键在于模型之外的检查。回复中也有人提到，工作尚未执行、却先声称“已完成”的情况同样会发生。

[@alexmichael](https://x.com/alexmichael) [总结了 Claude Code 团队的验证实践](https://x.com/alexmichael/status/2122458189295665505)（5 个赞、1 条回复、59 次浏览），内容包括针对每个代码库的验证技能、从39项清单中选取检查项，以及连续三轮失败后转交人工处理。

![验证工作流：运行并检查应用，然后再提交代码](https://pbs.twimg.com/media/HXR8VhCXIAAa_wW.jpg)

[@AISystems_hq](https://x.com/AISystems_hq) [建议按步骤循环执行规划、构建、检查和修复](https://x.com/AISystems_hq/status/2122459955962024082)（1 条回复、45 次浏览），其中设置了最多尝试三次的限制，并提供了记录受阻工作、继续执行独立步骤的方法。

![智能体陷入循环时的处理规则：限制重试次数，并将受阻任务移交他人](https://pbs.twimg.com/media/HXR-FRta4AAgcS5.jpg)

**讨论洞察：** 有人回复 PatchOnChain 时指出，测试“始终没有跳出桩件”；回复 Elessar 的用户则称，外部检查是两个模型都无法绕过的环节。

**与前一天的对比：** 11月15日的帖子将检查清单和计划审查描述为智能体运行框架的组成部分。当天的帖子则补充了生产环境故障，以及具体的验证和重试流程。

### 1.3 明确记录上下文与智能体间的交接 🡒

三条帖子介绍了让智能体工作流更易复现的不同做法：将指令保存为技能，在全新上下文中审查书面规格说明，以及在智能体之间交接未通过的回归测试。这些都是对工作流的描述，并非能证明它们可以减少缺陷的实测证据。

[@github](https://x.com/github) [将智能体技能描述为可复用的指令，用于沉淀以往决策和组织知识](https://x.com/github/status/2122425932933959975)（65 个赞、8 次转发、28 条回复、11,796 次浏览、56 次收藏）。回复中有人区分了可移植的指令和可移植的行为，并提出需要共享跨客户端测试；另有人指出，还需要删除过时的笔记。

[@agenticgirl](https://x.com/agenticgirl) [介绍 Elephant-Goldfish Model](https://x.com/agenticgirl/status/2122215592497492278)（1 个赞、1 条回复、60 次浏览）：由掌握丰富上下文的智能体起草规格说明，再由在全新上下文中工作的审阅者进行评估，最后由人类批准后再实施。[Google 代码仓库](https://github.com/google/elephant-goldfish-model)介绍了一款跨智能体插件，包含代码库文档和规格说明偏差检查。

![Elephant-Goldfish 工作流图，展示规范起草、在全新上下文中审查以及人工批准](https://pbs.twimg.com/media/HXK9ynxaYAAjbm-.jpg)

[@googledevs](https://x.com/googledevs) [展示 Hydrogen 如何分类处理 GitHub 问题，同时由 Carbon 负责较大型的重构和安全检查](https://x.com/googledevs/status/2122449973300298188)（60 个赞、6 次转发、5 条回复、4,734 次浏览）。一条回复称，失败的回归测试可以成为这两个角色之间有用的交接载体。

**与前一天的对比：** 11 月 15 日的内容已介绍过 Elephant-Goldfish 这一全新上下文审查模式。今天的帖子重复了其设计和配图；两篇帖子都没有提供结果数据。

### 1.4 专业模型的协同编排被认为有助于减少交接和配额消耗 🡕

Google 发布的 Antigravity Orchestrator 帖子介绍了如何将规划和审查交给 Gemini 4 Carbon，将编辑和测试交给 Hydrogen。Google 报告称，在 Terminal-Bench 4.1 上，配额使用量降低了 24%，运行速度提高了 19%；另一位从业者的帖子则称赞 Hydrogen，但认为 Carbon 速度较慢，有时也难以信任。

[@koltregaskes2](https://x.com/koltregaskes2) [介绍 Orchestrator 的推出及其公布的基准测试结果](https://x.com/koltregaskes2/status/2122230438928568689)（11 个赞、1 条回复、444 次浏览）。这些数据由 Google 报告，并非独立复现的结果。

[@thtbee_](https://x.com/thtbee_) [分享了亲身对比体验](https://x.com/thtbee_/status/2122375462970331442)（155 个赞、2 次转发、25 条回复、3,523 次浏览）：作者觉得 Hydrogen 积极主动、速度快，而 Carbon 反应迟缓，有时可能难以信任；作者还表示，幻觉问题并未消失。

**讨论要点：** 这些报告分别讨论了速度、任务分配和可信度，并未将某个模型说成适用于所有编码任务的最佳选择。

### 1.5 智能体效率优化涵盖 token 用量和代码库基础设施 🡒

两项成果分别针对智能体密集型开发中的不同成本：TokenEconomizer 关注会话和工具调用开销，OpenAI 的 Pando 则着眼于并发 Git 操作；两者都给出了具体的基准测试结果或生产环境数据。

[@alperebicoglu](https://x.com/alperebicoglu) [分享了 Microsoft 的 TokenEconomizer 项目](https://x.com/alperebicoglu/status/2122217188828586438)（4 个赞、1 次转发、3 条回复、20 次浏览）。其 [代码仓库](https://github.com/microsoft/TokenEconomizer)报告称，在 277 项 SWE-Bench 任务中，五种智能体与模型组合的平均成本降低了 18.4–30.9%，其中四种组合的 Pass@1 更高。

![TokenEconomizer 示意图，展示会话学习、移除未使用工具以及检测失败循环](https://pbs.twimg.com/media/HXOhApXXYAAPOHs.png)

[@oliviscusAI](https://x.com/oliviscusAI) [介绍了 OpenAI 的 Pando Git 后端](https://x.com/oliviscusAI/status/2122301000321249558)（13 个赞、2 次转发、7 条回复、609 次浏览）。OpenAI 的 [工程技术文章](https://openai.com/index/scaling-git-at-openai/)称，Pando 目前已用于其单体仓库，支持并发推送，并将推送延迟中位数缩短至原来的近五分之一。

![Pando 示意图，展示 Git packfile 和后端数据路径](https://pbs.twimg.com/media/HXPtaxgbQAA5izz.png)

### 1.6 编码模型的表现仍取决于具体任务 🡒

ValsAI 对 Qwen 4 Max 的比较显示，其编码表现优于 Qwen 3.8 Max 0902；但该帖的回复称，模型在金融和税务任务上的表现变化并不一致。因此，这只是特定基准测试下的结果，并不代表编码能力的综合排名。

[@ValsAI](https://x.com/ValsAI) [在其榜单中将 Qwen 4 Max 列为综合第 11 名](https://x.com/ValsAI/status/2122152965293457822)（24 个赞、2 次转发、4 条回复、1,598 次浏览）。在 Vibe Code Bench 的讨论串中，帖子称生成的应用有 21 个通过了全部测试（共 50 个），而上一代模型有 16 个通过（共 50 个）；一条回复称，Tax Agent 的得分低于上一代模型。

![ValsAI 对比图，展示 Qwen 各模型在编程及其他任务上的结果](https://pbs.twimg.com/media/HXNkGtcaoAAygWa.jpg)

## 2. 令人沮丧的问题

### 容量和会话限制打断工作

**严重程度：中等。** Codex 容量图表显示，报告中的容量已有显著提升，但回复中仍有人要求重置用量或减少限制。另一项投票让用户在新模型、可结转用量和取消 Plus 五小时限制之间选择；一条回复称，用量上限会打断长时间任务。这些帖子反映了具体诉求，但无法据此判断问题有多普遍。（[@thsottiaux](https://x.com/thsottiaux) [容量更新](https://x.com/thsottiaux/status/2122206990101536852)（2,517 个赞、798 条回复、162,441 次浏览）；[@JamesMalsawm](https://x.com/JamesMalsawm) [用量限制投票](https://x.com/JamesMalsawm/status/2122230689487897008)（39 个赞、35 条回复、2,848 次浏览））

### 测试通过也可能掩盖生产环境故障

**严重程度：报告事件为高；普遍程度未知。** 一位开发者称，某个由智能体生成的 Stripe webhook 实现虽然通过了 48 项测试、覆盖率达到 99.4%，上线后却出现重复扣款和 500 错误。一条回复认为，模拟对象实际上是在自我验证；另一位从业者则建议进行独立于模型的检查。这些帖子指出，在模拟对象或智能体之外进行验证是一种应对方法，但没有提供该方法成功率的实测数据。（[@PatchOnChain](https://x.com/PatchOnChain) [事件报告](https://x.com/PatchOnChain/status/2122087566774296914)（6 个赞、10 条回复、869 次浏览）；[@elessarqq](https://x.com/elessarqq) [跨模型检查配置](https://x.com/elessarqq/status/2122365816725233718)（17 个赞、10 条回复、548 次浏览））

### 智能体反复重试可能耗尽长时间运行任务的时间

**严重程度：中等；一位从业者的提醒。** 一篇帖子称，如果某个步骤出错，无人值守运行的 Claude Code 可能会反复尝试同一项修复，而不是继续完成后续工作。帖子提出的变通办法是限制尝试次数、记录受阻步骤，并继续处理相互独立的任务；但并未说明这种情况实际发生的频率，也未提供节省时间的实测数据。（[@AISystems_hq](https://x.com/AISystems_hq) [重试规则帖子](https://x.com/AISystems_hq/status/2122459955962024082)（1 条回复、45 次浏览））

### 模型下线后需要更新工作流

**严重程度：中等。** GitHub 于 11 月 16 日宣布在大多数 Copilot 使用场景中弃用 Claude Opus 4.8、Claude Opus 5 和 GPT-5.6 Terra，并列出了替代选项。一位用户质疑模型是否应该获得更长的支持期限；这场讨论并未说明有多少用户需要更多迁移时间。（[GitHub 更新日志](https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026)； [@GHchangelog](https://x.com/GHchangelog) [公告](https://x.com/GHchangelog/status/2122434567940329551)（5 个赞，1,028 次浏览）；[@temitope_rotimi](https://x.com/temitope_rotimi) [用户反馈](https://x.com/temitope_rotimi/status/2122236712927498379)（7 个赞，10 条回复，322 次浏览））

## 3. 人们期待出现的能力

### 延长编程智能体的使用时长，或允许用量结转

在一条 Codex 讨论串中，用户明确要求提供可结转的用量，或取消 Plus 的五小时限制，同时推出新模型。一条回复称，限额会中断长时间任务；另一张单独的容量图表显示，有一项可用性指标有所改善，但并未解决用户提出的会话时限问题。**紧迫性：中。机会类型：竞争型。**（[@JamesMalsawm](https://x.com/JamesMalsawm) [投票](https://x.com/JamesMalsawm/status/2122230689487897008)（39 个赞，35 条回复，2,848 次浏览）；[@thsottiaux](https://x.com/thsottiaux) [容量更新](https://x.com/thsottiaux/status/2122206990101536852)（2,517 个赞，798 条回复，162,441 次浏览））

### 防止智能体靠话术蒙混过关的完成检查

据报道，Stripe 事件表明，测试数量和覆盖率并不能确保 webhook 在生产环境中正常运行。另一位从业者表示，最有用的检查应在模型之外进行；对 Claude Code 工作流程的描述则提到，会在仓库层面进行验证，并在多次失败后转交人工处理。现有检查在一定程度上满足了这一需求，但这些帖子并未比较它们的有效性。**紧迫性：高（针对报道中的支付事件）。机会类型：竞争型。**（[@PatchOnChain](https://x.com/PatchOnChain) [事件](https://x.com/PatchOnChain/status/2122087566774296914)（6 个赞，10 条回复，869 次浏览）；[@elessarqq](https://x.com/elessarqq) [检查配置](https://x.com/elessarqq/status/2122365816725233718)（17 个赞，10 条回复，548 次浏览）；[@alexmichael](https://x.com/alexmichael) [Claude Code 验证实践总结](https://x.com/alexmichael/status/2122458189295665505)（5 个赞，1 条回复，59 次浏览））

### 可移植的智能体指令，以及共享的行为测试

GitHub 的技能帖子讨论了如何保存可重复使用的指令；一条回复则呼吁建立一套跨客户端共用的测试集，用来检验同一任务、预期证据和停止行为。同一讨论还指出，可移植的指令并不意味着行为也能跨平台保持一致。技能在一定程度上满足了知识复用的需求；可比较的行为测试仍是一个直接诉求。**紧迫性：中。机会类型：直接。**（[@github](https://x.com/github) [智能体技能帖子](https://x.com/github/status/2122425932933959975)（65 个赞，28 条回复，11,796 次浏览，56 次收藏））

### 用于架构实验的可复用大语言模型构件

[@rasbt](https://x.com/rasbt) [询问是否能提供一个 API，让更换模型组件的成本更低](https://x.com/rasbt/status/2122336040899711282)（66 个赞、6 次转发、11 条回复、3,239 次浏览），以 GQA 与 MLA、稠密 FFN 与 MoE 为例。随文图示展示了这些组件；一条回复认同关于切换成本的抱怨，但也提醒，共享抽象层可能会让最底层用例的差异变得模糊。

![展示可互换的 LLM 构件和架构组件的示意图](https://pbs.twimg.com/media/HXQNCyAW8AAebT6.jpg)

作者列举了 torchtitan、torchtune、Megatron Core 和 OLMo-core 等现有项目，同时指出这些项目并未达到其所需的抽象层级。**紧迫度：中。机会：愿景型**，因为这条讨论描述的是一项重大的工程与应用挑战，而非现成的产品需求。

## 7. 机遇何在

**[+++] 在智能体之外进行验证。** 一篇关于支付 Webhook 的帖子称，尽管测试全部通过，生产环境仍出现故障；其他帖子则建议进行独立检查、限制重试次数，并在必要时转交人工处理。多个不同案例都支持采用可复用的测试框架，不只依靠模拟对象和模型来检查行为；不过，这些帖子均未比较不同产品，也未报告故障减少幅度的量化数据。 ([@PatchOnChain](https://x.com/PatchOnChain) [事件](https://x.com/PatchOnChain/status/2122087566774296914)（6 个赞、10 条回复、869 次浏览）；[@elessarqq](https://x.com/elessarqq) [检查设置](https://x.com/elessarqq/status/2122365816725233718)（17 个赞、10 条回复、548 次浏览）；[@alexmichael](https://x.com/alexmichael) [验证摘要](https://x.com/alexmichael/status/2122458189295665505)（5 个赞、1 条回复、59 次浏览）；[@AISystems_hq](https://x.com/AISystems_hq) [重试规则](https://x.com/AISystems_hq/status/2122459955962024082)（1 条回复、45 次浏览））

## 8. 要点

1. **容量和会话时长是用户关注的两个不同问题。** Codex 更新附带的图表显示，据报告，容量错误有所减少；与此同时，用户仍在要求额度结转，或取消五小时限制。（[@thsottiaux](https://x.com/thsottiaux) [更新](https://x.com/thsottiaux/status/2122206990101536852)（2,517 个赞，798 条回复，162,441 次浏览）；[@JamesMalsawm](https://x.com/JamesMalsawm) [投票](https://x.com/JamesMalsawm/status/2122230689487897008)（39 个赞，35 条回复，2,848 次浏览））
2. **如果测试只是重复模拟对象的假设，那么测试全绿也不够。** Stripe webhook 帖子称，尽管有 48 项测试、覆盖率达到 99.4%，仍发生了重复扣款；其他帖子则建议在模型之外进行检查，并在代码仓库层面验证。（[@PatchOnChain](https://x.com/PatchOnChain) [事件](https://x.com/PatchOnChain/status/2122087566774296914)（6 个赞，10 条回复，869 次浏览）；[@elessarqq](https://x.com/elessarqq) [检查设置](https://x.com/elessarqq/status/2122365816725233718)（17 个赞，10 条回复，548 次浏览）；[@alexmichael](https://x.com/alexmichael) [验证摘要](https://x.com/alexmichael/status/2122458189295665505)（5 个赞，1 条回复，59 次浏览））
3. **效率优化如今既涉及模型路由，也涉及智能体开销。** Google 报告称，Orchestrator 降低了配额使用量、加快了运行速度；TokenEconomizer 则报告称，其基准测试显示成本有所下降。两项说法都仅适用于各自所述的测试范围。（[@koltregaskes2](https://x.com/koltregaskes2) [Orchestrator 帖文](https://x.com/koltregaskes2/status/2122230438928568689)（11 个赞，1 条回复，444 次浏览）） [@alperebicoglu](https://x.com/alperebicoglu) [TokenEconomizer 相关文章](https://x.com/alperebicoglu/status/2122217188828586438)（4 个赞、3 条回复、20 次浏览）；[代码仓库](https://github.com/microsoft/TokenEconomizer)）
4. **可复用的指令并不能保证不同智能体的行为可以互换。** GitHub 技能帖的回复呼吁开展跨客户端测试；Elephant-Goldfish 则让审查独立于设计讨论，并保留人工审批环节。（[@github](https://x.com/github) [技能相关文章](https://x.com/github/status/2122425932933959975)（65 个赞、28 条回复、11,796 次浏览）；[@agenticgirl](https://x.com/agenticgirl) [EGM 相关文章](https://x.com/agenticgirl/status/2122215592497492278)（1 个赞、1 条回复、60 次浏览）；[代码仓库](https://github.com/google/elephant-goldfish-model)）
5. **模型质量和支持情况需要按任务和版本进行比较。** Qwen 4 Max 在 Vibe Code Bench 上有所提升，但相关讨论帖称其 Tax Agent 得分较低；GitHub 还于 11 月 16 日将三个 Copilot 模型列为弃用，并列出了替代选项。（[@ValsAI](https://x.com/ValsAI) [基准测试相关文章](https://x.com/ValsAI/status/2122152965293457822)（24 个赞、4 条回复、1,598 次浏览）；[@GHchangelog](https://x.com/GHchangelog) [模型公告](https://x.com/GHchangelog/status/2122434567940329551)（5 个赞、1,028 次浏览）；[官方更新日志](https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026)）
6. **大量使用智能体的开发不仅影响编辑器，也会影响代码仓库的数据平面。** OpenAI 表示，Pando 目前已为其单体仓库提供支持，将推送速度中位数提升至原来的近五倍，同时每天处理近 1 拍字节的 Git 数据。（[OpenAI 工程博客文章](https://openai.com/index/scaling-git-at-openai/)；[@oliviscusAI](https://x.com/oliviscusAI) [Pando 摘要](https://x.com/oliviscusAI/status/2122301000321249558)（13 个赞、2 次转发、7 条回复、609 次浏览）)
