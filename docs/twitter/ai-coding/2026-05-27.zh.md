# Twitter AI 编程 - 2026-05-27

## 1. 人们在讨论什么

### 1.1 Antigravity 的讨论已从发布期话题转向教程密集出现和工作流配方 🡕

Google 5 月 19 日的发布仍是背景，但 5 月 27 日信号更强的帖子，已经不只是发布公告，而是教程、配置方案和工作流搭配。这很重要，因为信息流把 Antigravity 当作人们想立刻上手落地的东西，而不只是围观和赞叹的对象。

[@viktoroddy](https://x.com/viktoroddy) [发帖称](https://x.com/viktoroddy/status/2059636921962545657)（986 个赞、21 条回复、58,698 次浏览、1,272 次收藏）发布了一则 19 分钟教程，演示如何用 Antigravity 和 GPT Image 2 搭建一个动画网站。这里最明确的信号是收藏数：人们是在把它当作可复用的工作流保存，而不只是给一段发布演示视频点赞。

[@primemans](https://x.com/primemans) [认为](https://x.com/primemans/status/2059546987113160802)（131 个赞、29 条回复、11,317 次浏览、83 次收藏）表示，NotebookLM 加 Antigravity 是一个讨论不足的组合。主帖本身较为宽泛，但回复串具体谈到了自主研究笔记、自定义业务技能、上下文感知仪表板，以及自动生成报告或音频。

[@googledevs](https://x.com/googledevs) [宣布](https://x.com/googledevs/status/2059348847671783625)（155 个赞、10 条回复、11,332 次浏览、38 次收藏）把 Antigravity 2.0 纳入 Google 的开发者更新；与此同时，[@RoundtableSpace](https://x.com/RoundtableSpace) [转发并放大](https://x.com/RoundtableSpace/status/2059367748124229914)（80 个赞、7 条回复、48,780 次浏览、75 次收藏）则用一门四小时的 Antigravity 课程体现了这一转向。对长篇教程的需求，是整条信息流里反复出现、也最强烈的信号之一。

**讨论洞察：** Google 官方帖子下的回复分成两派：一派对本地 CLI agent 很兴奋，另一派则在抱怨兼容性、生产可用性，以及新模型这种权衡是否真的更优。Antigravity 赢得了关注，但还没有赢得毫无保留的信任。

**与前一天对比：** 5 月 26 日，Antigravity 的讨论重点还在于从 Gemini CLI 迁移，以及这次过渡是否连贯。到 5 月 27 日，话题已转向教程、被照搬的工作流，以及与 NotebookLM 的搭配。

### 1.2 Codex 和 Hermes 的可靠性问题，让信息流变成了修复日志 🡕

关于 Codex 的最大讨论簇，并不是新基准测试，而是 agent 出故障、用户互相比对症状，以及资深用户在上游服务不断变化的情况下发布补丁。整体氛围偏运维，而不是偏愿景。

[@Teknium](https://x.com/Teknium) [报道称](https://x.com/Teknium/status/2059467329138999709)（624 个赞、90 条回复、31,781 次浏览、54 次收藏）表示，OpenAI Codex 的 OAuth 问题已经修复，但前提是用户先运行 `hermes update`。回复显示，恢复并没有立刻对所有人生效，因此这件事仍然作为一个真实的运维事件持续发酵，而不是已经关闭的状态更新。

[@zekyure](https://x.com/zekyure) [报道称](https://x.com/zekyure/status/2059428282672500867)（52 个赞、33 条回复、6,784 次浏览）表示，即使重启并更新之后，Hermes 在 OpenAI Codex 提供方上仍然失败。配图通过反复出现的 `NoneType object is not iterable` 错误和回退失败，把问题具体呈现了出来。

![Hermes 手机界面显示反复出现的 NoneType object is not iterable 错误以及失败的回退尝试](https://pbs.twimg.com/media/HJSPG7fWAAAdPSA.jpg)

[@altryne](https://x.com/altryne) [发布](https://x.com/altryne/status/2059431754562416854)（8 个赞、4 条回复、1,234 次浏览、10 次收藏）发布了一个临时 Hermes 补丁：当流式 Codex 输出已经到达，但最终的 `response.completed` 帧遗漏了 `response.output` 时，该补丁会捕获 `TypeError`。[@thdxr](https://x.com/thdxr) [补充说](https://x.com/thdxr/status/2059701453925552609)（34 个赞、6 条回复、1,972 次浏览）表示，OpenCode 也已在 v1.15.11 中修补了 Codex 订阅端点问题，尽管回复里仍有人提到看不见的权限卡顿，以及一个尚未解决的无限循环投诉。

**讨论洞察：** 用户并没有因此弃用这些工具，而是像运维人员一样应对：切换模型、检查日志、修补运行时、重启网关，并等待上游恢复。

**与前一天对比：** 5 月 26 日的主题还是价格焦虑和对工具选择的猜测。到 5 月 27 日，讨论里已经出现了当天可执行的具体修复步骤，以及真实环境中的故障截图。

### 1.3 策略、配额和安全边界正越来越成为产品本身的一部分 🡕

另一个强信号讨论簇，围绕 AI 编程的控制平面展开：私有网络访问、组织级模型规则、仪表板界面、即将到来的倍率变化，以及供应链风险。这个类别正不断向治理层抬升。

[@OpenAIDevs](https://x.com/OpenAIDevs) [宣布](https://x.com/OpenAIDevs/status/2059703536825565499)（202 个赞、14 条回复、6,330 次浏览、104 次收藏）介绍了面向私有 MCP 服务器的 Secure MCP Tunnel。链接中的 [OpenAI 指南](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 表示，`tunnel-client` 运行在私有网络内部，只通过出站 HTTPS 对 OpenAI 发起长轮询，让 ChatGPT、Codex 和 Responses API 在无需开放入站防火墙端口的情况下访问 MCP 服务器。

[@GHchangelog](https://x.com/GHchangelog) [报道称](https://x.com/GHchangelog/status/2059371515741679884)（13 个赞、2,015 次浏览、6 次收藏）表示，企业所有者现在可以把特定 Copilot 模型定向分配给特定组织。链接中的 [GitHub 更新日志](https://github.blog/changelog/2026-05-26-target-copilot-models-to-organizations-with-model-rules) 确认了这种定向模型规则，以及一个经过刷新、用于管理企业级默认模型可用性的单页界面。

[@VazeKshitij](https://x.com/VazeKshitij) [警告](https://x.com/VazeKshitij/status/2059502720508407860)（286 个赞、40 条回复、21,055 次浏览、20 次收藏）表示，GitHub 已将 Copilot Opus 4.5 的倍率从 3x 提高到 27x，于 6 月 1 日生效，而且许多同事可能要等到把配额烧完后才会发现这一变化。[@argofowl](https://x.com/argofowl) [认为](https://x.com/argofowl/status/2059562833986396540)（269 个赞、27 条回复、7,353 次浏览）表示，Codex 的 2x 用量促销将在 5 月 31 日结束，这会让 Pro 的可用空间明显收紧；随后又在回复中澄清，$200 档仍保留每周 20x 限额，但会失去临时的五小时窗口 25x 到 20x 提升，而 $100 档则会同时失去每周和五小时窗口的双倍限额。

[@haydenbleasel](https://x.com/haydenbleasel) [展示了](https://x.com/haydenbleasel/status/2059682059799736328)（34 个赞、3 条回复、1,579 次浏览、8 次收藏）提到 API 仪表板里新增了一个 Codex 页面，以及 Codex 内置的 OpenAI Developer 插件。虽然这条的社交传播不算高，但作为产品证据很有价值：管理界面和项目引导界面正在不断增多。

![Codex 仪表盘截图，显示专门的 Codex 页面以及用于启动项目的 OpenAI Developer 插件界面](https://pbs.twimg.com/media/HJV16haaQAAjzVu.jpg)

**讨论洞察：** 共同主线不只是模型质量，还包括什么可以被安全暴露、实际有哪些配额，以及组织内哪些人能获得哪些界面。

**与前一天对比：** 5 月 26 日已经有预算争论。到 5 月 27 日，又增加了官方机制：仅出站的安全 MCP、定向 Copilot 模型规则，以及更显眼的配额变化。

## 2. 什么让人沮丧

### 在服务提供方边界处出现的可靠性断裂

严重程度：高。[@Teknium](https://x.com/Teknium) [报道称](https://x.com/Teknium/status/2059467329138999709)（624 个赞、90 条回复、31,781 次浏览、54 次收藏）表示，在 OpenAI 调整 Codex 的 OAuth/spec 行为后，用户需要运行 `hermes update`。[@zekyure](https://x.com/zekyure) [展示了](https://x.com/zekyure/status/2059428282672500867)（52 个赞、33 条回复、6,784 次浏览）记录了一起仍在发生的 Hermes 故障，错误为 `NoneType object is not iterable`；[@altryne](https://x.com/altryne) [记录了](https://x.com/altryne/status/2059431754562416854)（8 个赞、4 条回复、1,234 次浏览、10 次收藏）则给出了代码补丁和更新后的验证步骤，因为本地修复之后仍可能在后续丢失。[@thdxr](https://x.com/thdxr) [表示](https://x.com/thdxr/status/2059701453925552609)（34 个赞、6 条回复、1,972 次浏览）表示，OpenCode 也不得不为 Codex 端点不稳定打补丁。人们的应对方式是切换模型、重启网关以及在本地修补运行时。这值得为之构建产品，因为这种痛点打断的是正在进行的工作，而不是未来规划。

### 配额和倍率变化很难预判

严重程度：高。[@VazeKshitij](https://x.com/VazeKshitij) [警告](https://x.com/VazeKshitij/status/2059502720508407860)（286 个赞、40 条回复、21,055 次浏览、20 次收藏）表示，一次 Copilot 倍率变动可能会让整个团队在周一早晨措手不及；而 [@argofowl](https://x.com/argofowl) [转而](https://x.com/argofowl/status/2059562833986396540)（269 个赞、27 条回复、7,353 次浏览）则把 Codex 促销回撤变成了要求永久提高限额的请愿。[@GHchangelog](https://x.com/GHchangelog) [展示了](https://x.com/GHchangelog/status/2059371515741679884)（13 个赞、2,015 次浏览、6 次收藏）也展示了部分应对方向：采用组织级模型规则，而不是所有人共用同一个默认模型。这值得为之构建产品，因为人们显然需要在配额耗尽之前就完成预测和路由。

### 对 AI 编程供应链的信任非常脆弱

严重程度：高。[@AikidoSecurity](https://x.com/AikidoSecurity) [警告](https://x.com/AikidoSecurity/status/2059760227747291323)（11 个赞、2 条回复、391 次浏览、2 次收藏）表示，`codexui-android` 一直在悄悄窃取 OpenAI Codex 认证令牌。链接中的 [分析](https://www.aikido.dev/blog/codex-remote-ui-steals-ai-tokens) 表示，恶意代码只存在于 npm 发布包中，而不在 GitHub 仓库里，并把完整的 `auth.json` 内容发送到 `sentry.anyclaw.store`。这意味着，仅做源码审查并不够。这值得为之构建产品，因为被攻击的资产恰恰是 AI 编程工具所依赖的本地凭据材料。

## 3. 人们希望出现什么

### 更永久、也更清晰的使用余量

[@argofowl](https://x.com/argofowl) [请愿要求](https://x.com/argofowl/status/2059562833986396540)（269 个赞、27 条回复、7,353 次浏览）呼吁 OpenAI 将 Codex 面向 Pro 订阅者的 2x 限额永久化。[@VazeKshitij](https://x.com/VazeKshitij) [警告](https://x.com/VazeKshitij/status/2059502720508407860)（286 个赞、40 条回复、21,055 次浏览、20 次收藏）说明了这在实际中的意义：团队成员可能直到突然被限流，才意识到倍率已经变化。这不是单纯抱怨，而是对配额可预测性和稳定余量的现实需求。机会：直接。

### 兼容 Antigravity 的生态支持

[@jqdsouza](https://x.com/jqdsouza) [表示](https://x.com/jqdsouza/status/2059365628348334311)（5 个赞、3 条回复、160 次浏览）表示，在 Google 宣布过渡之后，客户已经开始询问 Agent Beacon 是否会支持 Antigravity CLI，而他的回复是支持已经上线。结合当天大量 Antigravity 教程流量，这体现出一种非常具体的需求：连接器、遥测和配套工具需要尽快跟上这一新 harness。机会：直接且有竞争性。

### 更好的运行时状态和权限可见性

信心较低，但需求依然具体。在对 [@thdxr](https://x.com/thdxr/status/2059701453925552609)（34 个赞、6 条回复、1,972 次浏览）的回复中，一位用户问，Codex 卡住是否其实是权限问题，因为 UI 从来没有显示那个提示；与此同时，[@altryne](https://x.com/altryne/status/2059431754562416854)（8 个赞、4 条回复、1,234 次浏览、10 次收藏）建议做能跨更新保留的验证，因为本地修复可能会在升级后消失。大家要的不是更好的模型，而是更清晰的状态、更好的健康检查，以及更少的隐形故障。机会：直接。

## 6. 新鲜且值得注意的内容

### 私有 MCP 隧道，作为企业桥接方案

[@OpenAIDevs](https://x.com/OpenAIDevs) [宣布](https://x.com/OpenAIDevs/status/2059703536825565499)（202 个赞、14 条回复、6,330 次浏览、104 次收藏）介绍了一项功能：在让私有 MCP 服务器继续处于仅出站 HTTPS 的防护边界之后，仍可让 ChatGPT、Codex 和 Responses API 访问它们。这很重要，因为它让企业采用 AI 编程的路径，更贴近现有网络边界，而不是要求开放公网入口。

### 隐藏在发布包中的 Codex 令牌窃取

[@AikidoSecurity](https://x.com/AikidoSecurity) [报道称](https://x.com/AikidoSecurity/status/2059760227747291323)（11 个赞、2 条回复、391 次浏览、2 次收藏）表示，`codexui-android` 一直在窃取 OpenAI Codex 认证令牌。链接中的 [分析](https://www.aikido.dev/blog/codex-remote-ui-steals-ai-tokens) 表示，恶意代码只存在于 npm tarball 中，而不在 GitHub 仓库里，因此这比普通的源码审查故事更值得警惕。

### Agent 可观测性正在形成独立的微型品类

[@DanWahlin](https://x.com/DanWahlin) [构建了](https://x.com/DanWahlin/status/2059401567892377800)（40 个赞、3 条回复、1,829 次浏览、17 次收藏）介绍的是一个围绕 Copilot CLI 本身构建的仪表板，而不是又一个模型封装层。这值得关注，因为它契合了当天更广泛的模式：一旦团队开始依赖 agent，回放、可见性和运维界面就会成为第一顺位的产品特性。

## 7. 机会在哪里

**[+++] 可靠性与恢复控制平面** —— 多条高信号帖子讨论的都是 Hermes 与 Codex 的故障、本地补丁、隐藏的权限卡顿，以及回退行为，而不是 prompt 质量。一个能够监测提供方漂移、验证会话、显示被阻塞权限并推荐安全回退方案的产品，可以解决 Teknium、zekyure、altryne 和 OpenCode 用户当天就面临的痛点。

**[++] 跨 harness 的支出与权益规划** —— Opus 倍率跃升、Codex 促销回撤、定向 Copilot 模型规则，以及新的 OpenAI 管理控制，都指向同一个缺口：用户需要在开始工作之前，而不是配额耗尽之后，获得按任务的成本预测和按套餐感知的路由能力。

**[+] 面向 agent 工作流的本地可观测性与信任工具** —— Copilot Mission Control、安全 MCP 隧道，以及 Aikido 供应链警告，都指向一个更广泛的方向：为 AI 编程技术栈提供本地优先的可观测性、来源追踪与制品验证。这个信号更早期，但逻辑是连贯的。

## 8. 要点总结

1. **Antigravity 的关注点已从发布讨论转向被照搬的工作流。** 最强的帖子是教程、长篇课程，以及 NotebookLM 的组合配方，而不是新的发布宣传。 ([来源](https://x.com/viktoroddy/status/2059636921962545657))
2. **可靠性问题如今催生的是公开代码补丁，而不只是抱怨串。** 当 Codex 行为发生变化时，Hermes 和 OpenCode 用户分享了具体修复方案、重启步骤和解析器层面的说明。 ([来源](https://x.com/altryne/status/2059431754562416854))
3. **治理正成为 AI 编程工具竞争维度的一部分。** 私有 MCP 隧道、Copilot 模型规则，以及显性的配额变化，共同塑造了当天的讨论。 ([来源](https://x.com/OpenAIDevs/status/2059703536825565499))
4. **构建者正越来越多地在 agent 之外叠加上下文、可见性和编排层。** Copilot Mission Control、fisn 和 Repo Prompt Community Edition 都位于模型本体之上的一层。 ([来源](https://x.com/DanWahlin/status/2059401567892377800))
