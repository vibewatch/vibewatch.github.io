# Twitter AI 编程动态 - 2026-05-08

## 1. 人们在讨论什么

### 1.1 GitHub Copilot 的治理更严格、价格更高、运营约束更多 🡕

GitHub Copilot 主导了当天围绕具体产品与定价的讨论。主线不只是模型质量，而是治理：重度用户听到了大幅涨价的消息，GitHub 正式宣布将在 6 月 1 日移除 GPT-4.1，Copilot CLI 也开始支持组织级插件分发。综合这些帖子来看，Copilot 正在告别宽松、固定价格的试验阶段，转向集中管理、由策略驱动的使用模式。

[@SouthernValue95](https://x.com/SouthernValue95) [警告](https://x.com/SouthernValue95/status/2052497809769992446) 表示（96 个赞、4 条回复、43 次收藏、20,966 次浏览），微软一直在“巨额补贴”每月 $30 的 GitHub Copilot 套餐，而且按当前用量，一家大客户预计 6 月成本将上涨 10 倍。在回复中，SouthernValue95 表示 Anthropic 也面临同样的问题：代理时代的工作负载消耗的 token，远超自动补全时代定价模型的预期。

[@GHchangelog](https://x.com/GHchangelog) [确认](https://x.com/GHchangelog/status/2052546539923411028) 宣布了一项官方模型变更（69 个赞、5 条回复、4 次引用、12 次收藏、9,036 次浏览）：GPT-4.1 将于 6 月 1 日在 Copilot 的各项体验中停用，企业管理员可能需要启用替代模型。回复很快就把这件事从路线图更新变成了运营层面的抱怨：一名用户称，推荐的替代模型贵了 7.5 倍；另一名用户则警告，强制换模可能导致 CI 出问题，除非先固定版本并重新测试。

[@_Evan_Boyle](https://x.com/_Evan_Boyle) [分享](https://x.com/_Evan_Boyle/status/2052788245080223979) 表示（43 个赞、2 条回复、15 次收藏、5,583 次浏览），Copilot CLI 现在支持企业托管插件，配置存储在 `.github-private` 中，并会自动安装到组织用户环境里。

![Copilot CLI 企业托管插件公开预览界面，显示来自组织的配置和插件推出控制](https://pbs.twimg.com/media/HHz3hWZacAAQnmg.jpg)

[@visualc](https://x.com/visualc) [新增](https://x.com/visualc/status/2052497811045036464) 还提到一项规模较小但很具体的工作流升级：Windows 上的 Copilot 构建性能分析现在可以针对单个 MSBuild 项目或 CMake 目标，而不是整个解决方案。这也与 Microsoft 博客中的解释一致：这一变化来自大型代码库和游戏工作室用户的反馈。

**讨论洞察：** 回复把成本、治理和质量连在了一起。关于弃用的讨论担心模型访问权限和 CI 失效；[@YoavCodes](https://x.com/YoavCodes) 还单独抱怨 Copilot 代码审查“很糟糕”且难以关闭。这意味着，该平台一方面正变得更深入工作流核心，另一方面一旦出错也会受到更严苛的审视。

**与前一天对比：** 5 月 7 日，定价问题基本还只是一个大客户的个例传闻。到了 5 月 8 日，GitHub 的官方通知和企业插件的推出让这一转向变得更具体：Copilot 不只是让部分团队成本更高，也正在成为一个治理更严格的企业平台。

### 1.2 多代理工作流正从新鲜事变成工作流基础设施 🡕

信息流里，人们花在讨论如何连接代理上的时间，已经多于讨论谁才是“赢家”。最强的几条帖子把多代理工作视为一种实用工作流：一个代理写代码，另一个代理审查；用快捷键在工具之间转移上下文；把技能组合成可复用的构建步骤。

[@EXM7777](https://x.com/EXM7777) [总结](https://x.com/EXM7777/status/2052810528452718757) 用一句话概括了一种新模式：“Claude 编写，Codex 做对抗式审查。”帖子称，OpenAI 发布了一个 Claude Code 插件，提供 `/codex:review`、`/codex:adversarial-review` 等命令以及后台任务控制功能，让跨模型审查从手动复制粘贴变成了一等工作流。

![Claude Code 的 Codex 插件，显示审查和后台作业命令，例如 /codex:review 和 /codex:status](https://pbs.twimg.com/media/HH0MTCZaoAAiHRX.png)

[@thesquashSH](https://x.com/thesquashSH) [发布](https://x.com/thesquashSH/status/2052622044597215663) 提到一款单键 iTerm 交接工具，可在 Claude Code、Codex、Gemini 和 OpenCode 之间转移会话。链接中的 [仓库](https://github.com/pirate/iterm-agent-fork) 表示，同一代理内的分支原生支持，跨代理转移则使用 `casr`；而 [@Timur_Yessenov](https://x.com/Timur_Yessenov) 的一条回复点出了难点：如何保留当前工作目录、权限、记忆假设和未解决的 diff。

![iTerm 分叉版本的交接菜单，提供 Claude Code、Codex、Gemini 和 OpenCode 作为活动 Codex 会话的移交目标](https://pbs.twimg.com/media/HHxgo1ZacAAmXTw.jpg)

[@gabrielchua](https://x.com/gabrielchua) [展示](https://x.com/gabrielchua/status/2052628452017394008) 表示，只要把 OpenAI Docs skill/MCP 和 macOS 应用构建 skill 组合起来，就足以让 Codex 在不到 5 分钟内生成一个可运行的菜单栏实时翻译工具。重点不在这个具体应用，而在于这种工作流：skill 正在成为可复用的积木，而不是一次性提示词。

**讨论洞察：** EXM7777 帖子下的回复异常具体：用户说，双代理循环之所以有效，是因为第二个模型真的会和第一个模型“抬杠”；但他们马上又追问，如果两个代理都改了同一个文件，谁来裁决合并。社区似乎已经确信多代理审查有用，只是围绕它的控制平面仍在搭建中。

**与前一天对比：** 5 月 7 日，Codex 的扩张故事还主要围绕 Chrome、iOS 和远程监控等新入口。到了 5 月 8 日，重点下移了一层：新工作集中在现有代理之间的互操作、交接、审查和可复用技能组合。

### 1.3 OpenCode 既展现了优势，也暴露了依赖关系 🡕

OpenCode 产出了数据集中得分最高的一条推文，但它不是发布公告，而是一则状态更新。这很重要，因为它同时展示了用户为什么信任这款工具，以及这套技术栈仍然脆弱在哪里：OpenCode 可以很快推出有用的工作流改进，但一旦上游模型供应商出故障，用户仍会立刻感知到影响。

[@opencode](https://x.com/opencode) [报道](https://x.com/opencode/status/2052687449508266270) 表示（268 个赞、16 条回复、8 次引用、10 次收藏、9,808 次浏览），OpenCode Go 在使用 DeepSeek 模型时遇到了问题，原因是上游供应商故障。链接中的 DeepSeek 状态页随后显示，5 月 8 日这起事故当天就被识别、修复并标记为已解决；用户回复也证实，这次故障立刻影响到了他们的工作流。

[@jlongster](https://x.com/jlongster) [已发布](https://x.com/jlongster/status/2052800474189877378) 同一天还提到一项 Git 工作流改进：OpenCode 现在会显示现有 worktree，而不是强制用户只能通过 OpenCode 自己来创建。回复中有人请求支持 `jj` workspace，也有用户借机把 OpenCode 和 Claude Code 的 branch/worktree 行为做了对比，并更看好 OpenCode。这表明 Git 体验可能是它最清晰的差异化之一。

**讨论洞察：** 故障帖子和 worktree 帖子正好互相补充。前者展示了 OpenCode 作为成熟产品对事故的透明通报；后者则表明，社区会因为它在日常开发流程里推出细小但实用的改进而给予回报。

**与前一天对比：** 5 月 6 日和 5 月 7 日更多是 OpenCode 势头和对比讨论。5 月 8 日则增加了更鲜明的运营层面证据：用户先看到了真实的依赖故障，又在同一天看到了围绕 Git 工作流的快速产品迭代。

### 1.4 自带模型路径正从爱好者话题变成真正的替代方案 🡕

几条彼此独立的帖子收敛到了同一种策略：如果供应商的定价、地域限制或政策成了障碍，那就绕过去。值得注意的变化在于，这些替代方案已经非常具体：Azure 托管的 Claude 部署、Copilot Chat 里的 Ollama、本地模型的硬件配置，以及因为官方功能受地区限制而自己做出来的浏览器控制克隆。

[@pamelafox](https://x.com/pamelafox) [展示](https://x.com/pamelafox/status/2052808984965599464) 表示（14 个赞、1 条回复、11 次收藏、903 次浏览），Claude Code 可以运行在 Microsoft Foundry 中部署的 Claude 模型上。链接文档说明了 Azure 资源配置、API key 或 Entra ID 认证，以及通过环境变量固定模型；她的终端截图也显示，这个工作流确实跑起来了。

![通过环境变量配置为使用 Microsoft Foundry Anthropic 端点的 Claude Code 终端会话](https://pbs.twimg.com/media/HH0KvkeawAAZJI_.jpg)

同一位作者 [@pamelafox](https://x.com/pamelafox)，[询问](https://x.com/pamelafox/status/2052480662717006077) 还在探讨（28 个赞、5 条回复、6 次收藏、1,980 次浏览），一台配备 64 GB RAM 的 M5 Max MacBook Pro 能把本地 SLM 推到什么程度，并把 `qwen3.6:27B` 列为候选模型。

![MacBook Pro 硬件详情，显示一台配备 64 GB RAM 的 M5 Max 机器，用于本地模型实验](https://pbs.twimg.com/media/HHvgLeXbEAAXMsP.png)

[@_vmlops](https://x.com/_vmlops) [描述](https://x.com/_vmlops/status/2052641304711143808) 提到一款 VS Code 扩展，可通过 GitHub Copilot Chat 里的 Ollama 在本地运行 DeepSeek、Llama 和 Qwen，支持工具调用、MCP 和视觉能力，而且不需要云端密钥。[@alessandro_a0](https://x.com/alessandro_a0) [更进一步](https://x.com/alessandro_a0/status/2052604702471139768) 还表示，由于 Codex 浏览器控制功能尚未在欧盟推出，他就在 Agent Zero 中借助 Venice 上的 Gemma 4 31B 复刻了这一能力，并称稍后会发布 CLI 版本。

**讨论洞察：** 触发这些方案的原因是现实需求，而不是意识形态：价格敏感、隐私与控制、Azure 兼容性，以及地区性功能缺失。围绕本地或替代部署路径的讨论，越来越不像自托管身份展示，更像是运营层面的绕行方案。

**与前一天对比：** 本周早些时候，声量最大的帖子还是托管代理路线图泄露和产品发布。到了 5 月 8 日，更强的信号变成了可部署性：当定价、合规或地域因素让默认路径不再理想时，人们开始展示继续工作的具体办法。

### 1.5 Antigravity 的讨论转向课程和提示词手册，但碎片化抱怨仍在持续 🡖

Google Antigravity 仍在讨论范围内，但主要是通过教育内容和工作流配方，而不是新的产品证据。这让反差更明显：用户显然有兴趣学习 Antigravity，但仍有人觉得 Google 周边的 AI 编程产品线过于碎片化，难以顺畅理解和使用。

[@hey_andersonnn](https://x.com/hey_andersonnn) [发布](https://x.com/hey_andersonnn/status/2052696926064447627) 提到一套将 Claude 与 Antigravity 结合用于移动应用构建的五提示词工作流，涵盖创意验证、UX 架构、全栈代码生成和调试。[@JulianGoldieSEO](https://x.com/JulianGoldieSEO) [推送](https://x.com/JulianGoldieSEO/status/2052292330892513760) 则提到另一门时长 4 小时的 Antigravity 课程，进一步强化了这种印象：当前的增长面主要是教程和提示词包。

[@1littlecoder](https://x.com/1littlecoder) [提供](https://x.com/1littlecoder/status/2052434838490423805) 则是另一种声音：“Jules 是 IDE，但不，它是给 Agents 用的！Google AI Studio 适合部署 Apps，但它又不等同于 Antigravity……Gemini CLI 也在那里游离着，但它也是 IDE！”这条帖子与其说是在报技术 bug，不如说是在抱怨产品定位：重叠入口太多了。

**讨论洞察：** 这条提示词帖子很能说明问题，因为它把产品默认能力的缺失，变成了由用户自己维护的工作流脚手架。作者并不是说 Antigravity 已经知道如何端到端管理应用规划，而是手动用可复用提示词定义了各个步骤。

**与前一天对比：** 5 月 6 日和 5 月 7 日，Antigravity 最强的信号还是围绕屏幕录制和自定义代理的路线图泄露。到了 5 月 8 日，这股热度冷却成了课程、提示词配方，以及持续存在的碎片化抱怨。

## 2. 人们感到沮丧的地方

### 成本波动和模型更替 —— 高

定价摩擦出现在多个工具中，而不只是某一家供应商。[@SouthernValue95](https://x.com/SouthernValue95) [报道](https://x.com/SouthernValue95/status/2052497809769992446) 表示（96 个赞、43 次收藏、20,966 次浏览），一家大型 GitHub Copilot 客户按当前用量预计 6 月成本将上涨 10 倍；与此同时，[@GHchangelog](https://x.com/GHchangelog) [宣布](https://x.com/GHchangelog/status/2052546539923411028) 提到 GPT-4.1 将于 6 月 1 日在 Copilot 的各项体验中停用。回复立刻把它转化成运营层面的痛点：替代模型更贵、替代方案访问权限不确定，以及如果团队不在切换前固定并重测工作流，CI 可能会出问题。

同样的成本敏感也体现在工具切换上。[@mjovanovictech](https://x.com/mjovanovictech) [表示](https://x.com/mjovanovictech/status/2052712879443382280) 表示，他本以为自己已经不用 Cursor 了，却还是被收了 $100，这促使他重新认真评估 GitHub Copilot。令人不满的不只是“AI 工具很贵”，而是当代理被用于更大、更长的任务时，账单很难准确预测。

当前的应对策略：同时比较多个工具，而不是只忠于一家；在被迫迁移前固定模型；寻找本地模型或更低价层级等更便宜的备选。值得投入建设的程度：高。团队显然需要在真正承诺采用代理工作流之前，获得更好的成本估算、路由和策略模拟能力。

### 供应商和地区依赖会打断原本不错的工作流 —— 中

数据集中得分最高的一条推文是一则故障通知。[@opencode](https://x.com/opencode) [告知用户](https://x.com/opencode/status/2052687449508266270) 表示，DeepSeek 模型故障是由上游供应商事故引发的；回复显示，用户立刻就在自己的会话里识别出了同样的症状，而链接中的状态页后来也把问题标记为已解决。这里令人沮丧的并不是 OpenCode 的界面，而是其底层模型栈的脆弱性。

同一问题的另一种版本出现在 [@alessandro_a0](https://x.com/alessandro_a0) 的 [帖子](https://x.com/alessandro_a0/status/2052604702471139768) 中：Codex 浏览器控制功能尚未在欧盟推出，所以他就在 Agent Zero 里借助 Venice 上的 Gemma 4 31B 重建了这一能力。[@1littlecoder](https://x.com/1littlecoder) [将其描述为](https://x.com/1littlecoder/status/2052434838490423805) 则把 Google 那边的问题描述成产品蔓延，而不是故障中断，但实际影响相似：开发者之所以要同时保留多套工具，是因为他们无法相信单一路径会一直可用、足够清晰，或者在本地区可安全使用。

当前的应对策略：盯状态页、准备备用工具；当供应商默认方案受阻时，转向本地或 Azure 托管替代方案。值得投入建设的程度：中到高。路由和故障转移基础设施正在成为核心产品的一部分，而不是锦上添花。

### 粗糙的自动化仍会制造噪音和幻觉 —— 中

[@YoavCodes](https://x.com/YoavCodes) [抱怨](https://x.com/YoavCodes/status/2052439367965442521) 表示，GitHub Copilot 代码审查不断往他的仓库里塞低质量建议，还会反复运行；如果不想完全关闭 PR contribution，就很难把它轻松禁用。

![GitHub 工作流列表显示反复运行的 Copilot 代码审查，说明这是审查垃圾信息而非有用信号](https://pbs.twimg.com/media/HHu5qROWQAIDQt5.png)

[@JamesOR](https://x.com/JamesOR) [做出](https://x.com/JamesOR/status/2052466833765113900) 则把同样的抱怨提升到了更高层面：把一个遗留 Express 应用一次性塞进单条 LLM 提示词，会带来幻觉并浪费上下文窗口。[@DeepLearningAI](https://x.com/DeepLearningAI) [提炼](https://x.com/DeepLearningAI/status/2052870397826101516) 进一步把这条教训总结成一条规则：先写规格，否则代理会很自信地做错事。

当前的应对策略：关闭噪音过大的审查自动化；把高风险工作拆成有计划的阶段；在允许代理执行前加入规格或验证阶段。值得投入建设的程度：高。信息流显示，大家需要的是围绕代理的质量控制层，而不只是更强的代理自主性。

## 3. 人们希望出现什么

### 能保留状态的跨代理交接

最强烈的未满足需求并不是“再来一个代理”，而是能在现有代理之间可靠地转移工作，同时不丢失上下文。[@thesquashSH](https://x.com/thesquashSH) [构建](https://x.com/thesquashSH/status/2052622044597215663) 提到一款面向 Claude Code、Codex、Gemini 和 OpenCode 的键盘驱动会话交接工具，这本身就说明缺口真实存在。最有价值的一条回复来自 [@Timur_Yessenov](https://x.com/Timur_Yessenov)：难点不在快捷键，而在保留工作目录、权限、记忆假设和未解决的 diff。[@EXM7777](https://x.com/EXM7777) 则从另一个角度补充了相邻缺口：一旦两个代理都开始工作，如果它们改了同一个文件，谁来裁决冲突？

这是一项实用需求，不是猎奇诉求。今天已经有一些部分解法，比如 iTerm 交接工具和 Claude Code 的 Codex 插件，但两者都没有在一个流程里同时解决状态转移、合并裁决和审查历史。机会：直接。紧迫性：高。

### 在熟悉工作流里提供更小、更便宜的模型选项

定价讨论和本地模型实验指向的是同一个愿望：人们希望在不离开现有工具的前提下，用上更便宜或更小的模型。[@Presidentlin](https://x.com/Presidentlin) [明确要求](https://x.com/Presidentlin/status/2052760216496664985) 在花了大半天使用 GPT-5.4-mini 之后，直接点名想要 GPT-5.5-mini。[@pamelafox](https://x.com/pamelafox) [询问](https://x.com/pamelafox/status/2052480662717006077) 在问，一台 64 GB 的 M5 Max 机器能把本地 SLM 推到什么程度；[@_vmlops](https://x.com/_vmlops) [强调](https://x.com/_vmlops/status/2052641304711143808) 则展示了一条通过 Ollama 在 Copilot Chat 中运行本地模型的路径。这些都叠加在 SouthernValue95 的警告之上：Copilot 的重度使用可能会被大幅重新定价。

这个需求既现实又紧迫：日常工作需要低成本模式，只在必要时无缝升级到高端模型。本地模型、Ollama 和 Azure 托管 Claude 都是部分答案，但当天没有哪条帖子展示出一种会自动选择低成本路径的干净默认工作流。机会：直接。紧迫性：高。

### 为 AI 构建的产品提供构建完成后的分发支持

[@iishaparekh](https://x.com/iishaparekh) [记录](https://x.com/iishaparekh/status/2052694801158656324) 点出了数据集中最简洁的商业侧缺口：AI 让编程更容易，vibe coding 让发布更快，但分发、注意力、叙事、增长、人脉，以及获得真实用户，“仍然很难”。这里的情绪不是惊叹，而是受限感：构建已经不再是主要瓶颈，创始人现在直接面对那些还无法轻易自动化的 go-to-market 工作。

这是一项现实需求，虽然加速器、社区和代理机构已经提供了部分解法，但 AI 原生版本仍明显建设不足。Shiphouse 是一种尝试，但更大的缺口仍然存在：帮助人们更快构建的工具，已经跑在了帮助他们找到用户的工具前面。机会：竞争型。紧迫性：中。

### 面向代理工作的规格与验证脚手架

数据集还指出了另一种愿望：在执行开始前就有更强的护栏。[@DeepLearningAI](https://x.com/DeepLearningAI) [认为](https://x.com/DeepLearningAI/status/2052870397826101516) 表示，除非团队先写规格，否则代理会很自信地把事情做错。[@JamesOR](https://x.com/JamesOR) [回答](https://x.com/JamesOR/status/2052466833765113900) 则展示了一种具体迁移模式：围绕审计任务和验证计划来组织工作，而不是依赖一次性提示词。

这更多是实用诉求，而不是情绪诉求：人们并不只是想要“更好的代理”，而是想在遗留系统迁移这类高风险任务中，有可靠的方法去约束并验证代理工作。课程和手工搭建的验证计划已经存在，但仍有空间做出一种产品，把规格、检查和分阶段执行变成默认工作流。机会：直接。紧迫性：中到高。

## 7. 机会在哪里

**[+++］ 跨代理审查与分阶段编排** — ［@EXM7777](https://x.com/EXM7777/status/2052810528452718757)、[@JamesOR](https://x.com/JamesOR/status/2052466833765113900) 和 [@alessandro_a0](https://x.com/alessandro_a0/status/2052604702471139768) 都指向同一个缺失层：如何在代理或阶段之间转移工作、保留上下文，并在中间插入结构化审查或验证。回复里关于合并裁决、受限功能和遗留系统风险控制的讨论，让这一点比泛泛的“多代理”趋势更扎实。

**[+++] 成本感知路由与更低价的模型层级** —— SouthernValue95 关于 6 月重新定价的警告、GitHub 关于 GPT-4.1 停用的通知、Presidentlin 对 GPT-5.5-mini 的直接点名需求，以及 Pamela Fox 对本地模型的实验，都在描述同一个缺口：团队需要一种默认工作流，把日常任务发给更便宜的模型，只在必要时升级。这一机会之所以强，是因为它在一天的数据里同时具备痛点、未满足需求和清晰的绕行行为。

**[++] 验证优先的代理执行** —— JamesOR 的现代化中心、DeepLearningAI“先写规格”的警告，以及 YoavCodes 对审查垃圾信息的抱怨，都表明没有护栏的自主性只会制造额外工作。把规格、检查、分阶段执行和回滚做成高风险代理任务的默认路径，能解决一个真实的质量问题。

**[++] 符合地区和策略要求的部署适配器** —— alessandro_a0 因为官方 Codex 版本在欧盟不可用而重建了浏览器控制，Pamela Fox 和 _vmlops 则展示了 Azure 托管和本地模型替代方案。机会不只是自托管，而是给团队一条合规路径：当地域、政策或供应商默认方案成了阻碍时，仍能保持同样的工作流。

**[+] 为 AI 构建产品提供构建后的分发支持** —— iishaparekh 指出，分发、注意力、叙事和获得首批用户仍然很难，这是一个正在浮现但已经明确的机会。构建越来越容易；下一个切入口，是帮助 AI 构建的产品在发布后真正获得增长。

## 8. 要点

1. **GitHub Copilot 从宽松默认方案转向受管平台，这一变化今天变得具体了。** 面向重度用户的 6 月重新定价警告，与 6 月 1 日 GPT-4.1 停用的官方通知以及企业托管插件的推出同时出现。这意味着，成本、模型策略和组织治理如今已经是同一个故事，而不再是彼此分离的话题。（[定价](https://x.com/SouthernValue95/status/2052497809769992446)、[弃用](https://x.com/GHchangelog/status/2052546539923411028)）
2. **跨代理审查正从黑客技巧变成标准工作流。** Claude Code 的 Codex 插件把对抗式第二模型审查变成了具名命令，而回复也显示，人们已经把“一个代理写、一个代理审”当成正常做法。（[来源](https://x.com/EXM7777/status/2052810528452718757)）
3. **验证优先的脚手架正成为编程栈的一部分。** JamesOR 的迁移流程和 DeepLearningAI“先写规格”的警告说的是同一件事：代理越快，做错事的风险就越显眼，因此计划、审计步骤和分阶段审查正从可选流程变成核心工具。（[迁移](https://x.com/JamesOR/status/2052466833765113900)、[规范优先](https://x.com/DeepLearningAI/status/2052870397826101516)）
4. **自带模型路径正成为实用的逃生舱。** 从 Microsoft Foundry 上的 Claude，到 Copilot Chat 里的本地模型，再到 M5 Max 上的本地模型实验，数据集显示开发者正在主动搭建面向成本、合规和控制的备用路径。（[来源](https://x.com/pamelafox/status/2052808984965599464)）
5. **OpenCode 的差异化在于工作流打磨，但供应商可用性仍然关键。** 同一天里，用户既遇到了由 DeepSeek 引发的故障，也看到了实用的 worktree 改进上线，这恰好同时体现了当前终端代理栈的吸引力与脆弱性。（[来源](https://x.com/opencode/status/2052687449508266270)）
6. **AI 消除构建摩擦的速度，快于它消除验证和市场推广摩擦的速度。** DeepLearningAI“先写规格”的提醒，以及 iishaparekh“分发仍然很难”的帖子，共同指向同一个现实：当代理让发布变得更容易后，下一个瓶颈就是质量控制和获取用户。（[验证](https://x.com/DeepLearningAI/status/2052870397826101516)、[分发](https://x.com/iishaparekh/status/2052694801158656324)）
