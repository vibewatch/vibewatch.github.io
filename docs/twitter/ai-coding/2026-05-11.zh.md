# Twitter AI 编程 - 2026-05-11

## 1. 人们在讨论什么

### 1.1 Copilot 正被塑造成多模型终端工作台，而不只是编程插件 🡕

GitHub Copilot 的讨论连续第二天保持强势，但重心已经不再只是简单的上手引导。当天的内容把面向新手的 Copilot CLI 官方推广、Copilot 内部高端模型的公开比较，以及围绕代理式开发的多语言活动宣传结合在一起，让这款产品看起来更像一个宽广的操作界面，而不只是单一助手。

[@github](https://x.com/github) [推广了](https://x.com/github/status/2053541834513645730) GitHub Copilot CLI 新手系列，相关博客称，这套工作流现在从 npm install、`/login`、文件夹权限、基于仓库上下文的提示，以及 `/delegate` GitHub Copilot 云端代理开始。该帖中最有分量的回复来自 [@BrandGrowthOS](https://x.com/BrandGrowthOS)，他表示，聊天模式已经比把报错复制到另一个助手里更快，因为它能就地理解代码库。

[@0xAbhiii](https://x.com/0xAbhiii) [发布了](https://x.com/0xAbhiii/status/2053778390503813510) GitHub 已将 Claude Opus 4.7 加入 Copilot；他的截图展示了该版本的 GitHub 更新日志页面，而推文强调的是对大型代码库的理解、多文件重构，以及编码前先做规划的能力。

![GitHub 更新日志截图，显示 Claude Opus 4.7 已在 Copilot 中正式可用](https://pbs.twimg.com/media/HIBDkm4bsAAVSWh.jpg)

[@burkeholland](https://x.com/burkeholland) [认为](https://x.com/burkeholland/status/2053942497928167927) GPT 5.5 现在已经成了他在 Copilot 里做设计工作时最喜欢的模型，尽管价格不菲；附带的 Paperwalls for Mac 截图让这一说法有了具体佐证，而不是泛泛地吹嘘基准测试。

![Paperwalls for Mac 界面，被 Burke Holland 用作 Copilot 中 GPT 5.5 设计工作的示例](https://pbs.twimg.com/media/HIERrRnWQAAew7g.jpg)

[@code](https://x.com/code) [宣布](https://x.com/code/status/2053962474425077902) GitHub Copilot Dev Days Online 将于 5 月 25 日至 27 日举行，提供巴西葡萄牙语、西班牙语、英语和简体中文版本，把同样的教育推广延伸成公开活动系列，而不只是一次性教程。

**讨论洞察：** GitHub 教程帖下的回复，讨论重点不在自动补全，而在工作流是否契合。用户在问哪些命令会最先变成日常习惯，而最实质性的肯定则指向“理解仓库上下文的终端聊天”——这正是它区别于把错误粘贴给另一个独立模型的地方。

**与前一天相比：** 5 月 10 日，Copilot 最强的信号还是新手系列本身的发布。到了 5 月 11 日，同一条上手线程仍位居前列，但又叠加了明确的模型选择讨论和活动编排，因此围绕 Copilot 的讨论面显得更广，也更偏向实际操作。

### 1.2 Codex 的速度正成为人们争论的头号功能 🡕

关于 Codex 的讨论，焦点从浏览器和移动端扩展收缩到了延迟。最有力的证据是一档泄露出来的速度层级，而回复也立刻把循环耗时视为产品本身的一个功能，而不只是实现细节。

[@testingcatalog](https://x.com/testingcatalog) [报道](https://x.com/testingcatalog/status/2053827038402716142) 一条已删除的 Codex GitHub 仓库条目曾短暂提到 Ultrafast 模式。第一张截图是关键证据：其中显示了一个 `ultrafast` 档位，描述为“为对延迟敏感的工作提供最快的可用响应”。这比笼统猜测“Codex 会更快”要具体得多。

![已删除的 Codex repo 差异，显示了一个面向延迟敏感型工作的超高速档位](https://pbs.twimg.com/media/HICozlBWYAAdvBN.jpg)

[@mark_k](https://x.com/mark_k) [做出了](https://x.com/mark_k/status/2053770170259169634) 把用户侧的核心判断说得很明确：编程代理当前的瓶颈，已经不是原始智能，而是等待循环完成的时间。他在回复里进一步把这种权衡说透，而不是简单压平成“越快越好”：一条回复说“循环时间就是用户体验”，另一条则追问，更快是否必然意味着更笨。

**讨论洞察：** 回复并没有把速度当成无条件的好事。有人认为，用户感受到的是转圈等待，而不是基准测试中的细微差距；但也有人反驳说，审查时间和回答质量仍然比单纯的返回速度更重要。

**与前一天相比：** 5 月 10 日，Codex 的关注点集中在移动端和浏览器端。到了 5 月 11 日，讨论从“我能在哪里运行它？”下沉到了“这个循环到底能快到什么体感？”

### 1.3 记忆、执行层和策略控制正逐渐变成彼此独立的产品 🡕

第三组帖子把编程工具周边的代理技术栈当成了一个独立市场。值得注意的不是又一轮模型发布，而是持久记忆、自然语言动作执行，以及围绕代理权限设置的防护栏。

[@petergyang](https://x.com/petergyang) [分享了](https://x.com/petergyang/status/2053845230596903340) 一套围绕明确的指令文件、上下文文件和记忆文件搭建的 Claude Code“个人操作系统”方案，并在回复中补充说，每次聊天都应该写下一条记忆，而夜间的“dreaming”任务则应把这些笔记压缩成长期记忆。

[@lcx](https://x.com/lcx) [发布了](https://x.com/lcx/status/2053846804077428865) 一条 MCP 流程：用户用自然语言询问余额或订单，助手选择合适的 MCP 工具，再由 LCX 通过交易所基础设施执行。这张图之所以重要，是因为它显示 MCP 的讨论正在从开发者配置转向具体的资金操作。

![LCX 工作流程图，展示 AI assistant 如何使用 MCP 将自然语言交易请求转换为交易所操作](https://pbs.twimg.com/media/HIC6mD3bgAA2IEu.jpg)

[@AISecHub](https://x.com/AISecHub) [声称](https://x.com/AISecHub/status/2053921989883052038) Cisco DefenseClaw 现已支持 Claude Code、Codex、Cursor、Windsurf、Gemini CLI、Copilot、Hermes、OpenClaw 和 Zeptoclaw；截图显示，它可以检查提示词、补全内容和工具调用，并按连接器进行拦截、批准或审计。

**讨论洞察：** 这一组讨论的重点集中在验证和治理。有人在 DKG 发布帖下追问，是否也覆盖执行验证；而 DefenseClaw 的材料则把价值定位为策略执行与可审计性，而不是更高程度的自主性。

**与前一天相比：** 5 月 10 日的讨论集中在打包技能、新手工作流和 MCP 技术栈。到了 5 月 11 日，话题转向了持久记忆、安全执行，以及覆盖在代理之上的治理层。

## 2. 什么让人感到沮丧

### 成本、缓存和配额带来的拖累——高

最清晰的现实痛点依然是经济账。[@MaxNiederman](https://x.com/MaxNiederman) [分享了](https://x.com/MaxNiederman/status/2053658722958983183) 一张支出图显示，他近期使用 Claude Code 的成本里有 61.6% 来自缓存费用，其中缓存读取和缓存写入占了账单的大头。[@xoofx](https://x.com/xoofx) [表示](https://x.com/xoofx/status/2053696882912682223) 一名开发者表示，100 美元的 ChatGPT business Codex 订阅含 2,500 个积分，却撑不过一天；[@ihtesham2005](https://x.com/ihtesham2005/status/2053805356137238812) 则借着同样的痛点推介 9router，称它可以压缩工具输出，并在付费订阅之外回退到更便宜或免费的模型。

![Claude Code 支出图表，显示缓存成本占某位用户近期 Opus 4.7 账单的大部分](https://pbs.twimg.com/media/HIAPYH4aYAAT_BX.jpg)

[@Hey_Aivetra](https://x.com/Hey_Aivetra) [补充说](https://x.com/Hey_Aivetra/status/2053907207214035357) 另一张“付费应用 vs 免费替代品”的图表，则从更偏大众用户的角度提出了同样的抱怨，覆盖 Copilot、Cursor Pro、Postman Pro、Datadog 等工具。就连回复也很诚实地反映了差距：有人说这些替代品“已经足够接近，可以先试水”，也有人说付费 AI 工具依然更好。

应对方式很一致：使用路由器、比较替代方案，并在额度见底前备好回退选项。值得构建程度：高。

### 强大的代理仍然需要信任与验证层——高

执行层越来越强，但当天的证据表明，用户并不想要没有护栏的裸执行。[@lcx](https://x.com/lcx) [展示了](https://x.com/lcx/status/2053846804077428865) MCP 被用于查询余额和下单，但图示把执行流程接到了受监管的交易所，而不是把助手本身当作可信终点。[@origin_trail](https://x.com/origin_trail) [将其定位为](https://x.com/origin_trail/status/2053820227901653252) 把 DKG 描述为带来源信息的共享记忆，而马上就有人追问，执行验证是否也在计划之内。

[@AISecHub](https://x.com/AISecHub) [做出了](https://x.com/AISecHub/status/2053921989883052038) 则把治理方面的抱怨直接说透：DefenseClaw 作为一层能力，检查提示词、补全内容和工具调用，同时阻止高风险行为、密钥外泄和不安全的工具使用。之所以评为高，是因为每条帖子都在暗示同一件事：基础代理已经能行动，但团队仍需要另一套系统来决定哪些行为应被允许、验证或回滚。值得构建程度：高。

### AI 生成代码的质量正在成为团队问题，而不只是个人烦恼——中

最尖锐的一波从业者反弹来自 [@FilippoTarpini](https://x.com/FilippoTarpini)，他 [写道](https://x.com/FilippoTarpini/status/2053958111178694744) 表示，那些从未掌握底层技艺的“vibe coder”产出的内容，往往无法复用、难以理解，而且膨胀得远超代码库能吸收的程度。[@nateliason](https://x.com/nateliason) [发布了](https://x.com/nateliason/status/2053845053617910202) 一张截图显示，Claude 错误地解释了他的“OpenClaw + Wiki + Granola”工作流，仿佛 OpenClaw 只是 Claude Code 的俚语。这是这些技术栈里工具混淆的一个较小但具体的例子。

更多偏宣传性质的帖子下，回复也指向同样的问题。在 xBubble 的公告下，一条回复 [认为](https://x.com/thealtcoinchief/status/2053842901256278388) 表示，即便是“vibe-code”工作流，人们仍然需要具备基础的编程理解。之所以评为中，是因为这些帖子并不是反对 AI 编程本身，而是反对那种理解不足、却把清理成本转嫁给他人的输出。值得构建程度：中到高。

## 3. 人们希望存在什么

### 付费容量耗尽后，仍能保持相同工作流的无缝回退机制

这一需求更多是通过补丁式构建表现出来，而不是直接诉求，但意图很清楚。[@ihtesham2005](https://x.com/ihtesham2005/status/2053805356137238812) 把 9router 描述为一种压缩工具输出、并能在 Claude 订阅和更便宜或免费的提供方之间自动回退的方式，而且无需改动外围编程工具；[@Hey_Aivetra](https://x.com/Hey_Aivetra/status/2053907207214035357) 则从购买者角度，用一张付费与免费替代品对比图表达了同样的压力。[@xoofx](https://x.com/xoofx/status/2053696882912682223) 则提供了紧迫性：即便是 100 美元的 Codex business 套餐，在真实使用下也可能一天之内就烧完。

这不是理想化需求，而是现实需求。路由器和替代技术栈已经给出了一些局部答案，但公开证据仍显示，用户主要还是在自己拼装这些故障切换能力。机会：直接。

### 跨代理可查询、可持久保存、可验证的共享记忆

[@origin_trail](https://x.com/origin_trail/status/2053820227901653252) 明确指出，当前代理会建立上下文，然后又把它丢掉；而 DKG V10 仓库则把这一抱怨落实成设计：私人草稿记忆、团队共享记忆，以及带来源信息的永久锚定记录。[@petergyang](https://x.com/petergyang/status/2053845230596903340) 则从更本地的角度指向同一缺口，主张使用 `claude.md`、`user.md`、`tools.md`，再加上记忆文件夹和夜间“dreaming”压缩任务。[@RLanceMartin](https://x.com/RLanceMartin/status/2053906836181668241) 随后又补上了一张图，把记忆、增强、验证和周期性更新全部放进同一系统中。

这项需求既现实，也已在市场中活跃出现：人们希望上下文能够留存、可检查，并能在不同会话和代理之间复用。虽然已有一些局部解法，但今天的证据并未显示出一个占主导地位的默认方案。机会：直接。

### 以审查优先的 AI 生成变更协作方式

[@bearlyai](https://x.com/bearlyai/status/2053659292285403288) 在这里很有代表性，因为 OpenADE 首先推销的不是“更自主的代码生成”，而是协作、评论、更快查看 diff，以及构建在 Claude Code 和 Codex 之上的“Plan → Revise → Execute”工作流。这与 [@FilippoTarpini](https://x.com/FilippoTarpini/status/2053958111178694744) 的观点直接吻合：真正的失效模式，是代码落得很快，却既不适配代码库，也无法促进协作。

这既是现实需求，也是情绪需求：团队希望借助 AI 提升效率，同时不失去代码的可读性、可审查性和共同所有权。OpenADE 以及 DefenseClaw 这类治理层已经给出了一些部分答案，但整体讨论看起来仍像一个早期市场。机会：竞争性。

## 4. 正在使用的工具和方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |
|---|---|---|---|---|
| GitHub Copilot CLI / Copilot | 终端与 IDE 代理 | (+) | 官方上手引导、基于仓库上下文的聊天、`/delegate`、Copilot 内不断扩展的模型选择、公开教育推广 | 高端模型价格昂贵，访问权限或账户状态问题仍会挡住部分用户 |
| OpenAI Codex | 编程代理 | (+/-) | 自主性强，可能会有面向延迟敏感工作的 ultrafast 档位，关注度广 | 速度带来质量与定价方面的疑问，积分消耗依旧明显 |
| Claude Code | 终端代理 | (+/-) | 很适合记忆循环、文件式例行流程和个人操作系统工作流 | 缓存成本高、可维护性方面的担忧仍在 |
| OriginTrail DKG V10 | 记忆层 | (+) | 共享、可验证、带来源信息且可查询的多代理记忆 | 仍是测试网上的候选发布版本，治理和生产成熟度仍待验证 |
| Model Context Protocol | 集成协议 | (+) | 让助手通过工具适配器调用外部系统；LCX 展示了真实的余额/下单流程 | 高信任操作仍需要安全执行后端和策略控制 |
| 9router | 路由网关 | (+) | 压缩工具输出、暴露本地端点，并可在付费、低价和免费提供方之间自动回退 | 增加了一层配置复杂度，而且依赖提供方兼容性 |
| DefenseClaw | 治理与安全 | (+) | 检查提示词/工具调用，提供拦截、批准、审计控制、可观测性和连接器覆盖 | 团队必须先把这层策略调好，它才真正有用 |
| OpenADE | 代理式开发环境 | (+) | Plan → Revise → Execute 流程、可评论的 diff、离线模式、worktrees、Claude/Codex harness | 仍是早期产品，Windows 被标为实验性，且仍依赖外部模型访问 |
| 通过 OpenCode + 自定义技能使用本地模型 | 本地编程方法 | (+/-) | 与更紧凑的工具结构和技能配合后，能让较小的本地模型更有用 | 需要调节 token/上下文，整体仍落后于托管的前沿模型 |

表格之下的总体模式是“分层”。人们并不把代理当成完整产品，而是在主代理之外叠加记忆、路由、治理，或是审查优先的界面。成本压力是这种行为的原因之一，但信任同样重要：同一条信息流一边在庆祝更快的循环，一边又不断给这些循环补上来源信息、策略和规划层。

迁移行为也同样清晰。Copilot 被讨论成“终端界面 + 模型菜单”，Codex 被按循环速度评判，Claude Code 被外包上一套记忆例程，而 9router 这类路由器之所以存在，恰恰是因为用户预期自己会在不同提供方之间切换，而不是长期忠于某一家。竞争态势已经不再是“哪个模型会赢？”，而是“当价格、延迟或信任发生变化时，哪套技术栈还能持续工作？”

| DefenseClaw | [@AISecHub](https://x.com/AISecHub) / Cisco AI Defense | 一层治理能力，可检查多个编程代理的提示词、补全内容和工具调用 | 减少高风险操作、机密外泄和审计轨迹缺失 | Go、策略引擎、基于连接器的代理控制 | Beta | [仓库](https://github.com/cisco-ai-defense/defenseclaw), [帖子](https://x.com/AISecHub/status/2053921989883052038) |

9router 是当天最清晰的构建模式，因为它直接回应了重复最多的抱怨：当价格档位或积分池耗尽时，工作流不应该一起停掉。其公开 README 声称，通过压缩工具输出可节省 20-40% 的 token，并把路由器定位成一个稳定的本地端点，让外围编程工具保持不变。

OriginTrail DKG 和 OpenADE 指向第二种模式：人们正在给代理加结构，而不是把筹码全押在裸提示词上。DKG 试图让记忆跨代理持久存在且可验证，OpenADE 则试图让规划、评论和修订在执行之前就成为一等能力。DefenseClaw 又把同样的冲动延伸到安全侧，把提示词和工具调用治理当作独立的产品类别。

## 6. 新动态与值得关注之处

### Copilot 现在被评估为一个模型组合，而不是单一助手

真正有用的新信号，不只是 GitHub 继续推广 Copilot CLI，而是用户马上开始讨论自己想在 Copilot 内部使用哪一个模型。[@0xAbhiii](https://x.com/0xAbhiii/status/2053778390503813510) 指向 Copilot 内的 Opus 4.7，用于处理大型代码库；[@burkeholland](https://x.com/burkeholland/status/2053942497928167927) 则表示，即使成本更高，GPT 5.5 也已成为他最喜欢的 Copilot 模型，尤其适合偏设计的输出。再结合 [@github](https://x.com/github/status/2053541834513645730) 和 [@code](https://x.com/code/status/2053962474425077902)，Copilot 的叙事现在看起来更像是“分发能力 + 模型选择”，而不只是“GitHub 也有一个助手”。

### 代理治理已经显眼到足以直接对外营销

第二个值得注意的变化是，治理不再藏在企业策略文档里。[@AISecHub](https://x.com/AISecHub/status/2053921989883052038) 公开宣传 DefenseClaw，把它定位成一层用于拦截、批准和审计代理行为的能力；[@origin_trail](https://x.com/origin_trail/status/2053820227901653252) 则强调带来源信息与可验证性的记忆，而不只是便利性。这让安全性和可审计性看起来像 AI 编程技术栈中的顶层产品界面。

## 7. 机会在哪里

**[+++] 保持开发者现有工具界面的成本感知型路由** —— 最强的痛点和最强的构建信号指向同一个缺口。缓存账单高企、积分一天烧完、付费与免费替代品对比图，以及 9router 的快速传播，都说明用户想要的是不改变工作方式的平滑回退。

**[++] 跨代理、带来源信息且可验证的共享记忆** —— DKG V10、个人操作系统式记忆文件夹和“dreaming”工作流，都指向同一个缺失的默认能力：上下文应当能够留存、保持可查询，并在会话结束后仍可复查。

**[++] 面向 AI 生成变更的审查与治理层** —— OpenADE 和 DefenseClaw 从不同方向切入同一个问题，但回应的是同一个市场信号：团队希望在代理输出变成生产代码之前，就有规划、评论、策略和审计轨迹把它包起来。

**[+] 通过结构化技能和工具纪律，让较小的本地模型变得可用** —— OpenCode + Qwen3.5 9B 的讨论表明，更好的 harness 和更严格的技能约束，可以让较弱的本地模型也足以胜任真实工作，尤其是在高端模型成本压力持续存在的情况下。

## 8. 要点

1. **Copilot 的公开叙事已从“试试 CLI”扩展为“在其中选对模型和工作流”。** GitHub 继续把新手系列顶在信息流前排，而用户则开始讨论 Opus 4.7、GPT 5.5，以及围绕代理式开发举行的公开 Dev Days 活动。（[来源](https://x.com/github/status/2053541834513645730)）
2. **Codex 的速度成了当天争议最大的产品杠杆。** ultrafast 泄露之所以重要，是因为它给了人们一个具体可争论的对象，而回复也立刻分成了“循环时间就是用户体验”和“更快也可能只是答案更差”两派。（[来源](https://x.com/testingcatalog/status/2053827038402716142)）
3. **记忆和治理正在从技术栈中分离为独立层。** OriginTrail、个人操作系统式工作流和 DefenseClaw 都预设了一点：基础代理本身并不够；接下来真正重要的是持久记忆、来源信息，以及围绕执行建立的策略。（[来源](https://x.com/origin_trail/status/2053820227901653252)）
4. **经济压力仍然大到足以催生一个独立产品类别。** 缓存成本高企、积分寿命很短，以及免费替代品对比图，都让路由器和回退系统看起来更像核心基础设施，而不是可有可无的优化项。（[来源](https://x.com/ihtesham2005/status/2053805356137238812)）
5. **对低理解度 vibe coding 的反弹如今已经很明确。** 最强烈的质疑并不是反 AI，而是反对那种难以复用、难以审查、难以维护，且无法融入真实团队的草率输出。（[来源](https://x.com/FilippoTarpini/status/2053958111178694744)）
