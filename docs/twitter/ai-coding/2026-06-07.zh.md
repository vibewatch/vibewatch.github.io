# Twitter AI 编程 - 2026-06-07

## 1. 大家在讨论什么

### 1.1 Harness 设计压过了模型之争 🡕

6 月 7 日最有分量的帖子认为，决定性能的关键层已经不再只是基础模型本身。记忆文件、规划阶段、MCP 接线、工具命名、压缩策略，以及服务层选择，才是大家反复提到的差异化因素。4 条保留内容支撑了这一主题。

[@Suryanshti777](https://x.com/Suryanshti777) [认为](https://x.com/Suryanshti777/status/2063548198195777847)（108 次点赞，16 条回复，4,910 次浏览，110 次收藏）称，Claude Code 用户如今分成了两派：一派把它当成更聪明的 Copilot，另一派则会给它配上记忆、规划阶段、专用 MCP，以及面向开发各阶段预先写好的提示词。这里最鲜明的观点并不是某个模型突然变得神奇，而是 `plan -> code -> review -> test -> document` 必须被编码为一个系统。

[@usr_bin_roygbiv](https://x.com/usr_bin_roygbiv) [写道](https://x.com/usr_bin_roygbiv/status/2063420146174119991)（82 次点赞，20 条回复，3,037 次浏览，79 次收藏）称，人们总是在把 harness、模型和 serving 混为一谈。他认为，Claude Code 或 Codex 之所以能比更轻量的 harness 消耗多得多的 token，是因为工具调用、系统提示词和编辑策略会直接改变工作流本身；而一条回复则把重点说得更透：很多针对模型的判断，其实只是披着模型外衣的 wrapper 判断。

[@JamesMontemagno](https://x.com/JamesMontemagno) [表示](https://x.com/JamesMontemagno/status/2063407603858981304)（7 次点赞，2 条回复，766 次浏览，5 次收藏）称，工具集即将变得重要；其链接的 VS Code 变更《在用户工具集中支持限定工具名称》新增了完整引用查找，并为工具集通配符、嵌套工具引用等限定名称补充了测试（[PR](https://github.com/microsoft/vscode/pull/320265)）。这只是一个很小的发版细节，但它强化了同一个判断：竞争层正在转移到 harness 及其工具语法上。

[@championswimmer](https://x.com/championswimmer) [提出异议](https://x.com/championswimmer/status/2063461079691264243)（149 次点赞，15 条回复，22,128 次浏览，90 次收藏）在回应 Boris Cherny 的“write loops”框架时表示，当前 agentic 系统的质量和能力仍未达标，并点名 OpenCode、Pi、Amp 和 Goose 是值得尝试的替代方案。回复串里还补充了一个重要细节：有回应者说，真正的问题不是缺少测试，而是在合并前没有任何机制对这些循环说“不”。

**讨论洞察：** 最有价值的分歧并不在于谁是基准测试第一，而在于失败究竟发生在哪里：是模型本身、包裹它的 wrapper，还是阻止劣质工作不断累积的审查关卡。

**与前一天对比：** 6 月 6 日已经把 specs、skills 和 canvases 的重要性抬到了高于原始上下文窗口大小的位置。到了 6 月 7 日，harness、model、serving 的拆分被明确说透，并成为当天最清晰的实践派论点。

### 1.2 访问套利成了工作流的一部分 🡕

关于经济性的讨论持续从抽象的价格抱怨，转向更具体的绕行路径。人们不再只问哪个助手值得付费，而是开始强调捆绑访问、用户自带密钥的工具，以及免席位费的替代方案。2 条保留内容支撑了这一主题。

[@hqmank](https://x.com/hqmank) [发布](https://x.com/hqmank/status/2063634869096444007)（579 次点赞，100 条回复，117,160 次浏览，329 次收藏）称，Google AI Pro 订阅用户可以在 Antigravity 中使用 Claude Opus 4.6。回复和原帖同样重要：一条更正指出该模型其实自 2 月 5 日起就已上线，而 [@hqmank](https://x.com/hqmank) 则回应说，价值只是在于又多了一条使用 Opus 的路径。这让信号从“新品发布”转成了“访问路径路由”。

![Antigravity 模型选择器，显示 Claude Opus 4.6 与 Gemini 3.5 和 GPT-OSS 选项并列列出](https://pbs.twimg.com/media/HKOA0o6acAAi6TU.jpg)

[@heynavtoor](https://x.com/heynavtoor) [认为](https://x.com/heynavtoor/status/2063555411010257136)（27 次点赞，7 条回复，4,501 次浏览，39 次收藏）表示，Copilot 和 Cursor 的定价如今意味着“你在 2026 年不得不配额式使用 AI 编程”，并把 Cline 作为反例。截图和 Cline 的公开界面解释了为什么这个对比能引发共鸣：该项目把 CLI、Web 看板、VS Code 扩展、JetBrains 插件和 SDK 结合在一起，同时采用 provider-direct 的模型计费，而不是按席位定价的 wrapper（[仓库](https://github.com/cline/cline)）。

![Cline README 截图，显示同一款编程代理产品支持 CLI、看板、VS Code 扩展、JetBrains 插件和 SDK 等界面](https://pbs.twimg.com/media/HKM4teBaEAAvgXl.jpg)

**讨论洞察：** Antigravity 那条帖子下最有信息量的回复，并不是在庆祝一个新功能，而是在纠正时间线的同时依然认可这种行为：人们更在意可用的访问路径，而不是发布本身的新鲜感。

**与前一天对比：** 6 月 6 日仍把价格压力放在中心位置。到 6 月 7 日，这种行为又向前走了一步，转向寻找套餐、provider-direct 计费，以及保留工作流但改变收款方的开源 wrapper。

### 1.3 构建者开始打包更大的 agent 界面与可复用系统 🡕

构建者发布的内容越来越不像提示词技巧，越来越像运行环境。值得关注的项目，不再只是又一种聊天工作流，而是在打包更广的工作界面、跨平台安装能力，或可复用的 agent 系统。4 条保留内容支撑了这一主题。

[@sharbel](https://x.com/sharbel) [展示](https://x.com/sharbel/status/2063369348828610886)（175 次点赞，21 条回复，8,999 次浏览，294 次收藏）`/last30days`，这是一项能并行搜索 Reddit、X、YouTube、HN、TikTok、Polymarket、GitHub 和 Web，并在综合成摘要前先对结果打分的 skill。截图和公开仓库让它不止停留在概念层面：README 展示了 Claude Code 的单独安装流程，以及 `npx skills` 在 Codex、Cursor、Copilot、Gemini CLI 和 50 多个 Agent Skills 宿主上的安装方式；仓库还说明 Reddit、HN、Polymarket 和 GitHub 可立即使用，而 X、YouTube 和 TikTok 则需要后续的可选配置（[仓库](https://github.com/mvanhorn/last30days-skill)）。

![/last30days 的 README 截图，显示 Claude Code 的安装命令，以及适用于 Codex、Cursor、Copilot 和 Gemini CLI 等 Agent Skills 宿主的安装命令](https://pbs.twimg.com/media/HKKPOn1WAAEliYg.jpg)

[@_Evan_Boyle](https://x.com/_Evan_Boyle) [展示](https://x.com/_Evan_Boyle/status/2063382647943143758)（34 次点赞，7 条回复，3,914 次浏览，27 次收藏）把 Copilot App canvases 描述为由 agent 创建、支持热重载的应用。他在回复中补充了关键细节：terminal、browser 和 Markdown 编辑器都算 agentic canvases，而自定义 canvas 则是 JavaScript/HTML 扩展，既能控制会话，也能通过 Copilot SDK 暴露工具。

[@RoundtableSpace](https://x.com/RoundtableSpace) [分享](https://x.com/RoundtableSpace/status/2063739023366263082)（49 次点赞，11 条回复，32,790 次浏览，29 次收藏）介绍了一份开源的 Claude Code playbook，它把一个 agent 变成了一个工程团队，内含负责安全、记忆、规划和代码审查的 subagents。ECC 仓库为这一说法补上了实质内容：它描述了一个原生于 harness 的 operator 系统，包含 skills、记忆优化、持续学习、安全扫描，以及覆盖 Codex、Claude Code、Cursor、OpenCode、Gemini、Zed 和 GitHub Copilot 的跨 harness 工作流（[仓库](https://github.com/affaan-m/ECC)）。

[@rohanpaul_ai](https://x.com/rohanpaul_ai) [报道称](https://x.com/rohanpaul_ai/status/2063608828558737714)（41 次点赞，8 条回复，3,236 次浏览）称，OpenAI 正在为编码、AI agents、图像生成和商业软件准备一个 ChatGPT 超级应用。Livemint 转载的 Financial Times 报道称，该产品将先在 ChatGPT Web 和移动端推出，提升 Codex 的显著位置，并引导用户使用编码、图像生成及 Canva、Booking.com 等合作方应用（[文章](https://www.livemint.com/companies/news/chat-is-dead-openai-plans-biggest-chatgpt-overhaul-ahead-of-ipo-pivots-to-ai-agents-says-report-11780809387032.html)）。

**讨论洞察：** 共同的目标并不是更多聊天，而是一个可复用的工作界面，能够贯通代码仓库工作、工具、浏览器和外部服务，同时不丢失 agent 上下文。

**与前一天对比：** 6 月 6 日强调的是 specs、skills、canvases 和具体基础设施。到 6 月 7 日，这一趋势又扩展为可安装的跨 harness 系统，以及更大的 superapp 式工作界面。

## 2. 什么最让人沮丧

### 计费与席位模式仍让 AI 编程像在“限量供应”

严重程度：高。[@heynavtoor](https://x.com/heynavtoor) [认为](https://x.com/heynavtoor/status/2063555411010257136)（27 次点赞，7 条回复，4,501 次浏览，39 次收藏）表示，Copilot 和 Cursor 的定价加超额费用，意味着开发者正在对 AI 编程进行配额管理；而 [@hqmank](https://x.com/hqmank) [曝光](https://x.com/hqmank/status/2063634869096444007)（579 次点赞，100 条回复，117,160 次浏览，329 次收藏）则指出，Antigravity 里又多了一条可用的 Opus 路径，回复也把重点放在访问路径而非新鲜感上。今天最清晰的应对模式，是转向捆绑式或 provider-direct 的方案，比如 Google AI Pro 加 Antigravity，或 Cline 这样的开源 wrapper。这值得围绕它构建产品，因为用户已经开始围绕计费边界而非品牌忠诚度来重新设计工具选择。

### 更好的模型仍在脆弱的 harness 中被评价

严重程度：高。[@usr_bin_roygbiv](https://x.com/usr_bin_roygbiv) [认为](https://x.com/usr_bin_roygbiv/status/2063420146174119991)（82 次点赞，20 条回复，3,037 次浏览，79 次收藏）表示，许多日常失败来自 harness 或 serving 层，而不是模型本身；回复也进一步强化了这一点：很多对模型的看法，其实是在评价 wrapper。[@championswimmer](https://x.com/championswimmer) [反驳](https://x.com/championswimmer/status/2063461079691264243)（149 次点赞，15 条回复，22,128 次浏览，90 次收藏）认为 Claude Code 的质量和能力仍不到位，而 [@JamesMontemagno](https://x.com/JamesMontemagno) [指出](https://x.com/JamesMontemagno/status/2063407603858981304)（7 次点赞，2 条回复，766 次浏览，5 次收藏）则指出了一个正在推进的具体修复方向——限定工具名称。这值得围绕它构建产品，因为这种失败模式是可重复出现的：用户不断把源于工具语法、wrapper、审查流程或基础设施选择的问题，归咎于模型。

### 更 agentic 的工作流制造了监督缺口

严重程度：中。[@Suryanshti777](https://x.com/Suryanshti777) [描述](https://x.com/Suryanshti777/status/2063548198195777847)（108 次点赞，16 条回复，4,910 次浏览，110 次收藏）把高表现配置描述为由多个阶段、记忆和专用 MCP 组成，[@_Evan_Boyle](https://x.com/_Evan_Boyle) [展示](https://x.com/_Evan_Boyle/status/2063382647943143758)（34 次点赞，7 条回复，3,914 次浏览，27 次收藏）则展示了一个 Copilot 界面：browser、terminal 和 Markdown 面板都变成了 agentic canvases。在这样的背景下，[@mksglu](https://x.com/mksglu) [推出](https://x.com/mksglu/status/2063628334026625125)（5 次点赞，4 条回复，102 次浏览）推出了 Context Mode Insight，用来回答谁卡住了、团队之间如何对比、哪些会话更能预测最终发布的 commit，同时不存储提示词或源代码。这值得围绕它构建产品，因为团队采用的 agent 界面越多，如果没有新的遥测层，就越难搞清楚到底发生了什么。

## 3. 大家希望存在什么

### 一个可移植的 agent 操作系统，而不是一堆一次性提示词栈

人们提出的需求既实际又迫切。[@Suryanshti777](https://x.com/Suryanshti777) [将其定位为](https://x.com/Suryanshti777/status/2063548198195777847)（108 次点赞，16 条回复，4,910 次浏览，110 次收藏）把性能归因于记忆、规划和专用 MCP 的组合；[@sharbel](https://x.com/sharbel) [分发](https://x.com/sharbel/status/2063369348828610886)（175 次点赞，21 条回复，8,999 次浏览，294 次收藏）则展示了一个可跨 Claude Code 及众多其他宿主运行的研究 skill；ECC 则把 subagents、记忆和安全规则打包成一个可复用系统（[仓库](https://github.com/affaan-m/ECC)）。缺少的，是一个人们只需配置一次、就能带着跨多个 harness 使用的层，而不是在每个工具里都重建同样的指令。机会：直接且竞争激烈。

### 清晰的 BYOK 路由与预算可见性

人们实际上是在要求一个既不打断工作流、又能让计费清晰可见的统一界面。[@hqmank](https://x.com/hqmank) [估值](https://x.com/hqmank/status/2063634869096444007)（579 次点赞，100 条回复，117,160 次浏览，329 次收藏）提到 Antigravity 中另一条可靠的 Opus 访问路径，而 [@heynavtoor](https://x.com/heynavtoor) [对比](https://x.com/heynavtoor/status/2063555411010257136)（27 次点赞，7 条回复，4,501 次浏览，39 次收藏）则对比了席位费用和超额收费，与 Cline 的 provider-direct 模型计费。如今套餐和开源 wrapper 只是在一定程度上满足了这个需求，但还没有形成一个可跨工具稳定工作的抽象层。机会：直接。

### 可共享且保持可检查的工作界面

构建者希望 agent 运行在一个他们看得见、能引导的界面上，而不是藏在不透明的聊天窗口里。[@_Evan_Boyle](https://x.com/_Evan_Boyle) [展示](https://x.com/_Evan_Boyle/status/2063382647943143758)（34 次点赞，7 条回复，3,914 次浏览，27 次收藏）展示了可热重载并能把工具重新暴露回会话中的 canvases，而 [@rohanpaul_ai](https://x.com/rohanpaul_ai) [总结](https://x.com/rohanpaul_ai/status/2063608828558737714)（41 次点赞，8 条回复，3,236 次浏览）则提到据报道中的 OpenAI superapp，将把编码、图像生成和合作方应用统一路由到一个 shell 中。缺失的并不是野心，而是在更多工具被折叠进一个产品后，仍能保持可检查、可引导、可组合的共享界面。机会：竞争性。

### 不泄露源码的团队可观测性

最清晰的新兴需求来自 [@mksglu](https://x.com/mksglu) [推介](https://x.com/mksglu/status/2063628334026625125)（5 次点赞，4 条回复，102 次浏览）：基于 15 款编码工具的结构化事件，提供 dashboard、REST API 和远程 MCP 访问，同时明确避免捕获提示词和源代码。这表明它对应的是一种实际需求，而不是虚荣指标：管理者想要进度与风险信号，但不想再增加一个充满监控意味的 agent wrapper。这里的证据不如其他需求类别充分，但其框架已经具体到足以引起重视。机会：新兴。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |
|---|---|---|---|---|
| Claude Code | Agent CLI | (+/-) | 与记忆、规划、MCP 和审查阶段结合时表现强 | 用户仍报告输出有 bug、token 消耗重、循环过度自信 |
| Google Antigravity | Agent 工作空间 | (+/-) | 以 UI 为先的界面，提供多模型选择，并为 Google AI Pro 用户捆绑 Opus 访问 | 可发现性不均，批评者称框架质量可能落后于模型质量 |
| GitHub Copilot / Copilot App | IDE agent / 工作空间 | (+/-) | Canvases、Cloud Agent 工具集、热重载界面、强编辑器集成 | 按使用量计费，以及仍在演进中的工具集体验，都会让用户沮丧 |
| Cline | 开源编码 agent | (+) | CLI、看板、VS Code、JetBrains、SDK、provider 选择、人工审批 | 用户仍需自行管理 provider 密钥和模型支出 |
| /last30days | 研究 skill | (+) | 跨平台搜索、按互动权重评分、多宿主安装 | 部分来源在初始设置后仍需用户密钥或浏览器会话 |
| ECC | Agent 操作系统 | (+) | 跨 harness skills、subagents、记忆优化、安全扫描、持续学习 | 覆盖面大、配置复杂，本身就是学习曲线的一部分 |
| Agent Skills / user tool sets | 打包 / 工具选择 | (+) | 可移植行为、可复用安装界面、工具与工具集的限定命名 | 支持仍不均匀，命名相关的底层打通仍在修补 |
| Context Mode Insight | 分析 / 治理 | (+) | 基于 15 种工具的结构化事件视图，不包含提示词或源代码 | 仍属早期信号，除发布帖外公开证据有限 |

总体情绪上，大家最看好的是那些能提升可移植性或降低成本的 wrapper 层；而对高端旗舰型界面的态度则最为复杂。最常见的应对方式，是在模型周围增加更多结构：记忆文件、规划阶段、skills、带命名空间的工具集，或 provider-direct 路由。迁移趋势持续从编辑器自动补全走向 agent 系统，也从平面的席位订阅走向套餐或 BYOK wrapper。当前最主要的竞争分野，已经变成试图掌控整套工作界面的大型平台，与那些让这些平台变得更便宜或更可控的开放系统之间的分化。

`/last30days` 和 ECC 从不同角度展示了同一种构建模式：把缺失的协同能力打包成可安装系统，而不是要求用户去记住更多提示词。前者打包的是碎片化的社交与代码仓库搜索，后者打包的是多 agent 工程行为、记忆与防护措施，统一成一个可复用的 operator 层。

Cline 和 Copilot Canvases 则表明，UI 界面本身已经成为产品的一部分。Cline 把一次 agent 体验延伸到 terminal、看板、编辑器插件和 SDK，而 GitHub 则把 browser、terminal 和 Markdown 面板变成 agent 可直接操控的 canvases。两者都说明，产品不再只是模型给出的回答，而是工作实际发生的那个地方。

Context Mode Insight 指向了团队内 agent 普及后的下一种构建模式：可观测性。这些项目反复触发的需求是可移植性、成本控制、共享上下文和可见性，而不是原始自动补全质量。

## 7. 机会在哪里

**[+++] 跨 harness 的 agent 操作系统** —— 证据横跨第 1、3、4、5 节：Suryanshti 的“记忆 + 规划”配置、`/last30days`、ECC，以及限定工具集命名，都指向了对可跨 harness 持续生效的可复用行为的需求。这一方向很强，因为用户和构建者正从两端同时逼近同一个缺失层。

**[++] 具备预算感知的 BYOK 工作界面** —— 证据包括 Antigravity 中捆绑的 Opus 访问、对 Copilot/Cursor 成本的批评，以及 Cline 的 provider-direct 模式。这一方向属中等强度，因为这种痛点已经在改变行为，但各种局部 wrapper 也在迅速涌现。

**[++] 可检查的共享 canvases 与 superapps** —— 证据来自 Copilot Canvases、据报道中的 ChatGPT superapp 重设计，以及更广泛的趋势：把 browser、terminal、markdown 和 agent 工作整合到同一个界面中。这一方向属中等强度，因为平台推进很快，但可检查性和可引导性仍未解决。

**[+] 不捕获源码的团队可观测性** —— 证据主要来自 Context Mode Insight，以及多阶段、多界面 agent 工作流的普遍上升。这是一个新兴方向，因为需求已经很具体，但目前公开证据仍主要集中在一条发布帖上。

## 8. 要点总结

1. **6 月 7 日最强的帖子，把 harness 视为真正的产品。** 反复出现的杠杆是记忆、规划、MCP 接线、限定工具名称、压缩和审查循环，而不是对基础模型的原始偏好。（[来源](https://x.com/usr_bin_roygbiv/status/2063420146174119991)）
2. **价格压力如今驱动的是路由行为，而不只是抱怨。** 无论是 Antigravity 中捆绑的 Opus 访问，还是 Cline 这类 provider-direct 替代方案，都被视为工作流决策。（[来源](https://x.com/heynavtoor/status/2063555411010257136)）
3. **构建者正在打包可复用系统，而不是一次性的提示词套件。** `/last30days`、ECC 和 Copilot Canvases 都是在把重复行为转化成可安装或可检查的界面。（[来源](https://x.com/sharbel/status/2063369348828610886)）
4. **大型平台想要更广的工作界面，但用户仍要求可检查性。** Copilot Canvases 和据报道中的 ChatGPT superapp 都指向更大的 AI 工作外壳，而当天对 harness 的批评则说明了为什么可见性依然重要。（[来源](https://x.com/_Evan_Boyle/status/2063382647943143758)）
