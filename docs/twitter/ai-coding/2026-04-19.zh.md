### 1.1 Ollama 发布 Copilot CLI 集成，解锁免费的本地智能体运行 🡕

当天最受关注的话题是 [@ollama](https://x.com/ollama) [宣布原生支持 GitHub 的 Copilot CLI](https://x.com/ollama/status/2045686038274990147)（407 个赞、113 次收藏、36,321 次浏览）。这项集成让用户可以完全在本地硬件上，通过 Ollama 托管的模型运行 Copilot CLI 终端智能体：浏览 issue 和 PR、根据工单搭建工作框架、在陌生代码库中导航。命令是 `ollama launch copilot`。在回复串中，Ollama [致谢 @scaryrawr](https://x.com/ollama/status/2045686038274990147) 对这项贡献表示感谢，并向一位觉得 Pro 计划用量过少的用户提供了缓存命中问题的排查建议。

[@itsafiz](https://x.com/itsafiz) [发布了一份分步指南](https://x.com/itsafiz/status/2045908305688629348)（22 个赞、24 次收藏、2,002 次浏览）展示了如何零成本通过 Ollama 运行 Copilot CLI，并用 Haystack 搭建完整的 RAG 流水线。

![GitHub Copilot CLI v1.0.32 使用本地 Ollama 模型构建 Haystack RAG 流水线的截图，展示了文件编辑和目录浏览](https://pbs.twimg.com/media/HGSGvy5WgAAvEr_.jpg)

**与前一天相比：** 昨天对 Copilot CLI 的关注点还在自动模型选择正式可用，以及 10% 的 premium 折扣。今天，焦点转向通过 Ollama 实现本地执行，这彻底消除了 API 成本，也让 Copilot CLI 成为首个通过官方集成提供完整本地选项的主流智能体。

## 7. 机会在哪里

**[+++] Local-First Agent Infrastructure** — Ollama's Copilot CLI integration (1,159 score, 36K views) proves that local model serving for terminal agents is viable and in high demand. Qwen 3.6 35B on M5 Max delivers ~90tps with flawless coding performance ([@ivanfioravanti](https://x.com/ivanfioravanti), [帖子](https://x.com/ivanfioravanti/status/2045853328819515540)）。当前的空白在于：还没有工具能自动完成本地模型选择、在本地资源不足时回退到云端，或比较本地与云端两条执行路径的成本。服务商速率限制、订阅透明度不足，以及已被验证的本地模型质量，共同构成了一个结构性且持续增长的需求。

**[+++] Cross-Agent Review and Verification Workflows** — [@drivelinekyle](https://x.com/drivelinekyle) 展示了一种“审查—修复—下一步”的交错协议：在 Claude Code 会话中插入 Codex 审查（[帖子](https://x.com/drivelinekyle/status/2045873804841271625)）。[@Viewforge](https://x.com/Viewforge) 则表明，即便是 Codex，也会在长时间运行的计算机操作任务中失效（[帖子](https://x.com/Viewforge/status/2045924743342334263)）。如果有一个自动化的跨智能体验证层——让一个智能体在执行过程中持续审查另一个智能体的输出——就能同时满足质量闸门需求（昨天的第 4 个机会）和多工具编排需求。这个交错模式已经有人手动在做，机会在于把它产品化。

**[++] AI Coding Subscription Intelligence** — [@GraemeVIP](https://x.com/GraemeVIP) 展示了一个 20 GBP 的 Claude 订阅，对应 103 美元的 API 等价用量（[帖子](https://x.com/GraemeVIP/status/2045674250460144107)）。[@Jasonzhouzld](https://x.com/Jasonzhouzld) 记录了 Anthropic 客服承认后端 bug 存在，却无法修复（[帖子](https://x.com/Jasonzhouzld/status/2045751646542819657)）。[@johncrickett](https://x.com/johncrickett) 指出，企业会因为能接触到人工客服而选择 Copilot（[帖子](https://x.com/johncrickett/status/2045760498352722181)）。一款订阅健康监控工具，如果能跨服务商跟踪权益状态、对同步问题发出告警、比较实际使用价值与订阅价值，并推荐最优的服务商分配，就能同时服务个人开发者和企业采购方。

**[++］ 面向 AI 编码的设计系统集成** — awesome-claude-design 为 Claude Code 提供的 68 个设计系统（［帖子](https://x.com/sharbel/status/2045809668660850703)）解决了“通用灰色 UI”问题，但目前只覆盖 Claude。若把设计系统上下文扩展到 Codex、Antigravity、Cursor 和其他工具，并建立一个社区贡献设计系统的市场，就能承接更广泛的“不要千篇一律 AI UI”需求。

**[+］ 非编码型 Agent 技能市场** — The Minimalist Entrepreneur skills（［帖子](https://x.com/chenzeling4/status/2045813354854240306)）展示了 Claude Code 的 skill 系统已经被用于商业策略，而非代码。[@VaibhavSisinty](https://x.com/VaibhavSisinty) [列出](https://x.com/VaibhavSisinty/status/2045853757062398070) 展示了 Codex 在文件整理、CSV 合并、报告生成、网页浏览和应用控制等方面的能力。围绕非编程型智能体 skill 建立一个精选市场，面向产品经理、分析师、营销人员和创始人，将把编程智能体平台的可服务市场从开发者扩展到更广范围的人群。

## 8. 要点总结

1. **Ollama 的 Copilot CLI 集成是当天最具定义性的事件。** 该帖获得 1,159 分和 36,321 次浏览，互动量高出第二名 5 倍。运行 `ollama launch copilot` 后，任何人都可以零 API 成本地在本地模型上使用 GitHub 的终端智能体。这是主流本地模型服务器与主流云原生编程智能体之间的第一座官方桥梁。（[@ollama](https://x.com/ollama), [帖子](https://x.com/ollama/status/2045686038274990147)）

2. **Codex 的计算机操作能力如今既有真实基础设施任务的成功案例，也有竞争性失败的记录。** 一位用户用 Codex 把 Raspberry Pi 配置成 VPN 出口节点，过程中 Codex 还自主导航了 Tailscale 管理后台（[@_julianschiavo](https://x.com/_julianschiavo), [帖子](https://x.com/_julianschiavo/status/2045757690081919312)）。与此同时，Viewforge 的基准显示，Codex + GPT-5.4 未能完成一项从 YouTube 到 TikTok 的任务，而第三方计算机操作工具包成功完成了它（[@Viewforge](https://x.com/Viewforge), [帖子](https://x.com/Viewforge/status/2045924743342334263)）。计算机操作在目标明确的任务上可行，但在长时间、多步骤工作流中仍会失灵。

3. **随着客服系统失灵的证据增加，用户对服务商的信任进一步流失。** Anthropic 的 AI 客服确认了后端订阅同步 bug，却明确表示无法修复、无法升级给人工，也无法提供补偿（[@Jasonzhouzld](https://x.com/Jasonzhouzld), [帖子](https://x.com/Jasonzhouzld/status/2045751646542819657)）。另一家拥有 60 多个账号的企业则在没有解释的情况下被封，唯一申诉渠道只是一个 Google Form（[@johncrickett](https://x.com/johncrickett), [帖子](https://x.com/johncrickett/status/2045760498352722181)）。昨天这个主题还只是“政策不透明”，今天已经变成“支持系统失去功能”。

4. **多工具工作流如今已经发展出明确的交错协议。** 不再只是笼统地说“两个都用”，而是开始出现具体模式：在 Claude Code 里每隔一步让 Codex 做一次审查，以便在偏差滚大之前及时发现（[@drivelinekyle](https://x.com/drivelinekyle), [帖子](https://x.com/drivelinekyle/status/2045873804841271625)）。Google 自家员工也明确支持把 Claude Code 和 Codex 与 Google 工具一起用（[@LyalinDotCom](https://x.com/LyalinDotCom), [帖子](https://x.com/LyalinDotCom/status/2045674717487509776)）。多工具模式正从“采用”走向“方法论”。

5. **“vibe coding 宿醉”正在成为新兴反弹的命名。** 在 vibe coding 扩散到生活方式文化和入门教育的同时，实践者也开始点出后果：缺乏清晰架构的 AI 生成代码库会积累越来越重的技术债（[@DanTheronX](https://x.com/DanTheronX), [帖子](https://x.com/DanTheronX/status/2045925420957147462)）。代码质量崩塌与安全事故也开始被——即便带有讽刺意味——与 AI 编程实践联系起来（[@0xfeMMANUEL](https://x.com/0xfeMMANUEL), [帖子](https://x.com/0xfeMMANUEL/status/2045978573576544401)）。

6. **多份独立报告都确认了本地模型的质量。** 通过 mlx_lm 在 M5 Max 上运行的 Qwen 3.6 35B，可提供约 90tps 的“非常愉快的编程体验”（[@ivanfioravanti](https://x.com/ivanfioravanti), [帖子](https://x.com/ivanfioravanti/status/2045853328819515540)）。同一模型在 OpenCode 中也表现“惊艳”（[@loktar00](https://x.com/loktar00), [帖子](https://x.com/loktar00/status/2045974956337512521)）。但 harness 敏感性仍是个现实问题：在 Hermes 中，它会“反复从惊艳到彻底灾难，再回到惊艳”（[@paulmarin90](https://x.com/paulmarin90)）。模型本身没问题；质量波动主要发生在集成层。
