## 1. 人们在讨论什么

### 1.1 Claude Code 遇上 Google Antigravity：集成热潮与反弹（🡕）

当天得分最高的推文来自 [@TawohAwa](https://x.com/TawohAwa)，TA [发布了分步教程](https://x.com/TawohAwa/status/2043639262315520214) 分享了如何将 Claude Code 与 Google Antigravity 结合使用：“如果把 Claude Code 和 Google Antigravity 结合起来，你就能自动化并构建任何东西。”这条教程线程详细介绍了如何下载 Antigravity、在其中安装 Claude Code 的 VS Code 扩展，并启用集成。该帖获得 92 个赞和 155 次收藏，是今天数据集中收藏数最高的内容，说明大量用户将其保存以备参考。

但这股热情并未免于质疑。[@pcshipp](https://x.com/pcshipp) [予以回击](https://x.com/pcshipp/status/2043643091127824826) 发布了当天回复最多的帖子（54 条回复）：“Antigravity 是 Google 做过的最失败的产品之一。即使免费了，它仍然无法与 Cursor、Codex 和 Claude Code 等工具竞争。质量 >> 免费。”与此同时，[@lMDU1zXxSEbWc5c](https://x.com/lMDU1zXxSEbWc5c) [报道称](https://x.com/lMDU1zXxSEbWc5c/status/2043644008917000383) 表示：“google antigravity 挂了？没有响应！”这一可靠性问题进一步强化了外界对其质量的批评。

[@alvinfoo](https://x.com/alvinfoo) [梳理了 Google 更广泛的 AI 生态](https://x.com/alvinfoo/status/2043575605212647769)，列出了从 Gemini、Veo 到 Antigravity 的 11 款工具，并认为：“Google 拥有最好的 AI 工具生态，而且优势大到根本没有可比性。”另一条 [配套信息图](https://pbs.twimg.com/media/HFw9LhMakAEWSNe.jpg) 则详细梳理了完整技术栈，包括 Firebase Studio、Google App Builder，以及 Gemini 在 Sheets 和 YouTube 中的集成。

[@xdadevelopers](https://x.com/xdadevelopers) [发布了为期一个月的对比评测](https://x.com/xdadevelopers/status/2043645461035188490) 对 Cursor、Claude Code 和 Google Antigravity 进行了对比，并称“胜者非常明确”。配图展示了 Claude Code 的 Cowork 模式正在构建一个带实时预览的响应式 Next.js 作品集网站。

分歧已经很清楚：Antigravity 的免费定价吸引了教程创作者和生态拥护者，但真正用过替代方案的实践者认为，它与竞品之间存在免费也无法弥补的质量差距。昨天的报告指出，用户正收敛到 2-3 个付费订阅；今天的数据则显示，这个免费竞品仍难以打入这套工具组合。

### 1.3 GitHub Copilot CLI 走向远程与移动端（🡕）

两条帖子记录了 GitHub Copilot CLI 能力的一次重要扩展。[@msdev](https://x.com/msdev) [演示了](https://x.com/msdev/status/2043769670688461051) 展示了如何用三条 Copilot CLI 命令，在不到 30 分钟内构建一个板球计分应用：`/plan` 用于界定范围，`/autopilot` 用于构建，`/fleet` 用于扩展。该帖获得 77 个赞和 47 次收藏。

另一边，[@GHchangelog](https://x.com/GHchangelog) [宣布](https://x.com/GHchangelog/status/2043705785843171838) 宣布远程控制 CLI 会话进入公开预览。[更新日志文章](https://github.blog/changelog/2026-04-13-remote-control-cli-sessions-on-web-and-mobile-in-public-preview) 详细说明，`copilot --remote` 会将 CLI 活动实时流式传输到 GitHub。用户可以通过网页或移动端监控并引导会话，包括：在会话中途发送引导消息、查看和修改计划、在 plan/interactive/autopilot 模式之间切换、批准或拒绝权限请求，以及响应 `ask_user` 提示。`/keep-alive` 命令则可在长任务期间防止设备休眠。该功能目前已在 Android beta 和 iOS TestFlight 上提供。

[@h34j3j8j](https://x.com/h34j3j8j) [询问其中的区别](https://x.com/h34j3j8j/status/2043774154013389201) 对比了 IntelliJ 中 Copilot 的 “Ask” 模式和 “Agent” 模式，并这样概括区别：“With Ask, it tells me where and what to do. With Agent, it actually does it.” 配图展示了 IDE 状态栏中的模式下拉菜单（Ask、Edit (Deprecated)、Agent、Plan）。

![GitHub Copilot 模式选择器，显示 Ask、Edit Deprecated、Agent 和 Plan 选项](https://pbs.twimg.com/media/HFzxUyAXQAAqWdc.png)

远程会话、移动端访问和 /fleet 扩展命令的结合，意味着 Copilot CLI 正从本地编码助手转向与设备无关的开发平台。

When Claude Code becomes the primary interface for enterprise tooling, the who-can-build-what question changes completely.”

[@DataChaz](https://x.com/DataChaz) [重点介绍了 Multica](https://x.com/DataChaz/status/2043634352933028277) 介绍了 Multica——一个开源版的 Claude Managed Agents 克隆项目，几天内就获得了 4,000+ GitHub stars。Multica 可集成 Claude Code、OpenAI Codex、OpenClaw 和 OpenCode，提供自托管代理基础设施、可复用技能、多工作区隔离，以及共享的人机任务看板。其工作流——启动守护进程、分配工单、隔离工作区、通过 WebSocket 实时更新——与 Anthropic 的托管方案高度相似，但运行在开发者自己的服务器上。

## 2. 什么让人感到沮丧

### Claude Code 的 Token 臃肿与幽灵 Token（高）

三个独立来源都记录了 Claude Code 过度消耗 Token 的问题。[@de1lymoon](https://x.com/de1lymoon) [报道称](https://x.com/de1lymoon/status/2043668578570744085) 分享了自己在 Google 11 年的经验：“Claude breaking conventions 40% of the time... one hidden bug 20,000 ghost tokens burned.” 仅靠一个 markdown 规则文件，就把违反约定的比例从 40% 降到了 3%。[@grok](https://x.com/grok) [证实了](https://x.com/grok/status/2043672440966967661) 指出：“newer Claude Code versions (2.1.100+) inject ~20k extra server-side tokens per request, as confirmed by HTTP proxy tests, Reddit analysis, and open GitHub issues.” [@a_lamparelli](https://x.com/a_lamparelli) [展示了截图](https://x.com/a_lamparelli/status/2043710164964983197) 展示了一次没有任何工具调用的单独 “continue” 命令就消耗了 2% 的会话配额。`/context` 的拆解显示了这些开销来自哪里：system prompt 7k tokens（3.5%）、system tools 8.9k（4.5%），以及 autocompact buffer 33k（16.5%）——而这一切都发生在用户发送任何消息之前。

![Claude Code 上下文使用情况，显示 200k tokens 中已使用 49.5k，并按类别提供详细细分](https://pbs.twimg.com/media/HFy2jBzWkAANn3I.jpg)

这延续了昨天报告中关于缓存 TTL 和 Token 成本的担忧，而今天的证据则补上了具体版本号和独立验证方式。

### Gemini CLI 账号封禁（中）

[@championswimmer](https://x.com/championswimmer) [报道称](https://x.com/championswimmer/status/2043645123196604478) 分享了自己被 Gemini CLI 封禁的经历，收到的提示是：“This service has been disabled in this account for violation of Terms of Service,” 尽管 TA 很少使用这个工具。该用户表示，这已经成了一种模式：“The weird CLI tool bans continue.” [@justcardz](https://x.com/justcardz) 建议通过 Google 表单申诉，并称可以在一小时内解决。

![Gemini CLI 终端，显示因违反服务条款导致账号被禁用，并附有申诉说明](https://pbs.twimg.com/media/HFx8OiwXkAADi5N.jpg)

### Google Antigravity 的质量与可靠性（中）

[@pcshipp](https://x.com/pcshipp) 引发了 54 条回复——是数据集中回复最多的帖子——原因是 [宣称](https://x.com/pcshipp/status/2043643091127824826) 表示：“Antigravity is one of the worst failed products created by Google. Even after making it free, it still can't compete with tools like Cursor, Codex, and Claude code.” 另外，[@lMDU1zXxSEbWc5c](https://x.com/lMDU1zXxSEbWc5c) [报道称](https://x.com/lMDU1zXxSEbWc5c/status/2043644008917000383) 还直接反映了宕机问题。54 条回复的讨论量说明，这并非孤立抱怨，而是一种广泛存在的不满。

### Claude Code 的学习曲线（低）

[@zodchiii](https://x.com/zodchiii) [以幽默方式记录了](https://x.com/zodchiii/status/2043709527938207755) 描绘了典型的 Claude Code 用户路径：“type a long prompt, get a result, rewrite everything yourself, discover Claude has /commands, the checkpoint was always the documentation.” 这个段子之所以有效，是因为它描述了许多人的共同经历：在了解 /commands、/clear 和其他 slash commands 等内置功能之前，用户已经浪费了不少 Token 和精力。

## 3. 人们希望出现什么

### Token 成本透明度与可观测性

[@a_lamparelli](https://x.com/a_lamparelli) 的 [截图](https://x.com/a_lamparelli/status/2043710164964983197) 显示，Claude Code 的 `/context` 命令可以给出 Token 构成拆解，但一次 “continue” 就烧掉 2% 会话配额这件事，对用户来说依然无法解释。[@grok](https://x.com/grok) [指出](https://x.com/grok/status/2043672440966967661) 指出，约 20k 的服务器端 Token 注入并无文档说明。结合昨天关于缓存 TTL 回退的报告，用户一再表达的是：希望获得实时成本可见性和可预测的计费方式。相关信息虽然存在于服务器端，但没有以开发者可操作的形式呈现出来。

### 了解团队约定的 AI 编程代理

[@de1lymoon](https://x.com/de1lymoon) [演示了](https://x.com/de1lymoon/status/2043668578570744085) 指出，仅一个 markdown 文件就把 Claude Code 违反约定的比例从 40% 降到了 3%。从“开箱即用”到“能正确遵守你团队的约定”之间的落差，目前仍主要依赖手动配置来弥补。如果有一种代理能自动识别并适应项目约定——包括 lint 规则、命名模式和架构决策——而无需手工编写规则文件，就能解决 Claude Code 最常见的失效模式。

### 移动优先的代理式开发

GitHub 的 [远程 CLI 会话](https://github.blog/changelog/2026-04-13-remote-control-cli-sessions-on-web-and-mobile-in-public-preview) 已开始回应这一需求，但该功能仍处于公开预览阶段，且移动端覆盖有限（Android beta、iOS TestFlight）。从 [@msdev](https://x.com/msdev) 那条获得 47 次收藏的帖子以及远程会话公告释放出的信号来看，开发者希望能从任意设备监控、引导并批准代理的工作，而不只是依赖运行 CLI 的那台机器。

## 6. 新动态与值得关注的消息

**GitHub Copilot CLI 远程会话进入公开预览。** `copilot --remote` 命令会将 CLI 活动实时流式传输到 GitHub，从而支持通过网页或移动端进行监控和引导。功能包括会话中途发送消息、查看计划、切换模式，以及在任意设备上批准权限。现已在 Android beta 和 iOS TestFlight 上提供。（[更新日志](https://github.blog/changelog/2026-04-13-remote-control-cli-sessions-on-web-and-mobile-in-public-preview)）

**OpenAI Codex “超级应用”截图曝光。** 首批公开图片显示，Codex 正从聊天界面转向完整的桌面开发环境，集成浏览器、项目侧边栏以及 Basic/Advanced UI 模式。默认模型为 GPT-5.4 Extra High。同一线程中还提到了一起供应链安全事件（Axios 入侵、macOS 签名证书轮换）。（[帖子](https://x.com/chetaslua/status/2043634180979085785)）

**Multica 作为开源托管代理基础设施，获得 4,000+ stars。** 该项目复刻了 Anthropic 的 Managed Agents，但以自托管方式运行，并集成 Claude Code、Codex、OpenClaw 和 OpenCode。它提供可复用技能、工作区隔离，以及共享的人机任务看板。（[帖子](https://x.com/DataChaz/status/2043634352933028277)）

**Claude Code v2.1.100+ 已确认每次请求会注入约 20k 个服务器端 Token。** 来自 HTTP 代理测试和 Reddit 分析的独立验证印证了有关未文档化 Token 开销的报告。另有一位 Google 工程师单独量化了约定违规率（基线为 40%，使用 markdown 规则文件后降至 3%）以及幽灵 Token 消耗（每个隐藏 bug 消耗 20,000 个）。（[帖子](https://x.com/grok/status/2043672440966967661), [帖子](https://x.com/de1lymoon/status/2043668578570744085)）

**MCP 进入 Anthropic Registry，扩展到 Web3 游戏。** Dungeon Roll 作为已验证的 MCP server 上线，使 AI 代理能够自主下注 ETH 并执行链上游戏操作——这是一种新型的代理到区块链交互模式。（[帖子](https://x.com/dungeonroll/status/2043823101377470643)）

## 7. 机会在哪里

**[+++] 强：自托管代理基础设施**

Multica 在几天内获得 4,000+ stars，量化了市场对云锁定型托管代理平台替代方案的需求。Anthropic 的 Managed Agents 绑定其云服务和定价；企业团队则需要运行在自有服务器上的代理编排能力，并能自由选择模型（Claude、GPT、开源模型）。Multica 已经验证了这套模式：守护进程、工单分配、隔离工作区、实时更新、可复用技能。机会在于将其打磨成企业级产品：SOC 2 合规、审计日志、基于角色的访问控制，以及与现有 CI/CD 流水线的集成。任何构建代理基础设施的团队都应密切关注这一方向。

**[++] 中等：AI 编程工具的 Token 成本可观测性**

今天的数据为昨天关于缓存 TTL 的担忧补上了更具体的证据。[@a_lamparelli](https://x.com/a_lamparelli) 的 `/context` 截图显示，在用户发送第一条消息之前，系统开销（prompt + tools + autocompact buffer）就会消耗约 50k tokens。[@grok](https://x.com/grok) 提到，v2.1.100+ 每次请求还会额外注入约 20k 个服务器端 tokens。[@de1lymoon](https://x.com/de1lymoon) 则报告，每个隐藏 bug 会消耗 20,000 个幽灵 tokens。一个能让这些成本变得可见、可预测且可优化的代理或仪表板，将服务于所有触及 Claude Code 配额上限的用户。数据已经存在，只是没有以可操作的方式呈现出来。

**[++] 中等：MCP 作为通用中间件层**

今天，MCP 出现在三个彼此无关的场景中：企业低代码（Power Apps）、Web3 游戏（Dungeon Roll）和代理基础设施（Multica）。[@oscar_ster3808](https://x.com/oscar_ster3808) 抓住了这一趋势：“MCP is quietly eating the middleware stack.” 随着该协议逐渐成为 AI 代理与外部系统之间的默认集成层，MCP 周边工具将迎来机会——包括发现、测试、安全扫描和 MCP server 监控。Anthropic MCP Registry 正在成为新兴的应用商店；帮助开发者发布、验证和维护 MCP server 的工具，将填补明显的基础设施空白。

**[+] 新兴：面向非编码用户的 AI 熟练度工具**

[@clairevo](https://x.com/clairevo) 将 Cowork 描述为“无需打开终端，就能教会你 Claude Code 的思维模型”，而 [@degensing](https://x.com/degensing) 对九类非开发工程岗位的 AI 工具要求所做的梳理，则都指向同一个结论：正在出现一批需要 AI 熟练度、却不具备 CLI 熟练度的新用户。“Brain” 文件这种模式——一份告诉 AI 你是谁、你如何工作的持久上下文文档——是一种可以从 Cowork 泛化到任何 AI 工具的工作流创新。面向 QA、DevOps、SRE 和数据岗位的角色化 AI 熟练度模板与培训材料，代表着一个尚未被充分服务的市场。

**[+] 新兴：与设备无关的代理式开发**

GitHub 的远程 CLI 会话和 Codex 的桌面“超级应用”都在解决同一个约束：代理式编码工作流被锁定在单一设备上。机会在于工具层——实现设备间的无缝接力：在工作站上启动任务，用手机监控，再用平板批准权限。GitHub 凭借 `copilot --remote` 拿到了先发优势，但这种模式并不局限于它，任何 CLI 代理都适用。面向代理引导而不仅仅是监控的移动原生界面，将是下一步。

## 8. 要点

1. **Google Antigravity 让 AI 编码社区明显分化。** 当天排名最高的推文（155 次收藏）在推广 Claude Code + Antigravity 集成，而回复最多的帖子（54 条回复）则称 Antigravity 是“最失败的产品之一”。面对 Cursor、Codex 和 Claude Code 的质量与可靠性差距，免费定价并未扭转局面。（[教程](https://x.com/TawohAwa/status/2043639262315520214), [批评](https://x.com/pcshipp/status/2043643091127824826)）

3. **GitHub Copilot CLI 正变得与设备无关。** 远程会话、移动端访问和 /fleet 扩展命令，使 Copilot CLI 更像一个开发平台，而不再只是本地工具。从“在你的机器上运行”转向“从任意设备引导”，改变了 CLI 代理的定义。（[更新日志](https://github.blog/changelog/2026-04-13-remote-control-cli-sessions-on-web-and-mobile-in-public-preview)）

6. **自托管代理基础设施需求强劲。** Multica 在几天内获得 4,000+ stars。作为 Anthropic Managed Agents 的开源克隆项目，它证明云锁定式代理编排本身就是障碍，而开源社区在一周内就做出了替代方案。（[Multica](https://x.com/DataChaz/status/2043634352933028277)）

7. **AI 工具熟练度正在成为跨岗位要求，而不再只是开发者技能。** 九类工程岗位如今都出现了未写明的 AI 工具要求。竞争优势在于“采用速度，而不是技能”。Claude Cowork 及类似工具正成为非编码用户的上手入口。（[角色映射](https://x.com/degensing/status/2043616031592300631), [协作指南](https://x.com/clairevo/status/2043709557915132086)）
