# Twitter AI 编程 - 2026-07-06

## 1. 人们在讨论什么

### 1.1 循环工程取代写提示词，成为更严肃的思考框架（🡕）

最明显的概念转变，是从“写出更好的提示词”转向“设计一个能替你发出提示、检查结果并重试的系统”。至少有四项入选内容支撑了这一主题：Boris Cherny 的三阶段框架、Anthropic 的大规模使用研究、从业者关于重验证评审的帖子，以及新近打包推出的循环框架。相比 7 月 5 日更宽泛的工作流层讨论，7 月 6 日真正成为头条的是循环工程本身。

[@alex_prompter](https://x.com/alex_prompter) [认为](https://x.com/alex_prompter/status/2073809060533883364)（103 个赞、21 条回复、27,137 次浏览、229 次收藏）称，负责 Anthropic Claude Code 的 Boris Cherny 已经不再停留在直接写提示词，而是转向编写会触发、验证并重复执行的“循环”，并行运行数百个 Claude 实例，用于 Twitter 监控和 GitHub 分诊等任务。

[@milan_milanovic](https://x.com/milan_milanovic) [总结道](https://x.com/milan_milanovic/status/2074017002788974610)（2 个赞、1 条回复、515 次浏览、3 次收藏）提到 Anthropic 对约 400,000 个 Claude Code 会话的公开分析；关联报告称，人们仍负责大多数规划决策，而 Claude 负责大多数执行决策；领域专业知识会提高成功率；在为期七个月的时间窗口内，调试在会话中的占比大幅下降。

![来自 Anthropic 的 Claude Code 研究的图表，显示领域专业水平越高，成功会话越多，失败越少](https://pbs.twimg.com/media/HMhjeRbaUAArGwD.jpg)

[@AntonMartyniuk](https://x.com/AntonMartyniuk) [展示了](https://x.com/AntonMartyniuk/status/2074017796107743252)（3 个赞、76 次浏览、2 次收藏）则给出了同一故事的从业者版本：AI 辅助的 .NET 开发仍然意味着逐行读代码，找出 N+1 查询和糟糕的异步模式，修补薄弱测试，并在功能真正安全前手动重写大段代码。

**讨论洞察：** 最有价值的反驳并不是“循环是假的”，而是只有当验证层能捕捉到一位细心的人类评审本来也会发现的问题时，循环才真正构成一次实质性的跃迁。Boris 这条帖子下的回复反复回到系统设计、恢复能力和验证机制。

**与前一天对比：** 7 月 5 日强调的是 harness 和编排层。7 月 6 日保留了这一底层框架，但把词汇本身变成了故事主角：循环、验证和领域专业知识取代了泛泛的提示词讨论。

### 1.3 成本、额度与认证摩擦仍在决定人们到底能用哪些工具（🡕）

最大的运营主题仍然是受限条件下的连续性：哪条模型通道可用、耗尽后会发生什么，以及认证是否根本能正常工作。公开证据涵盖路由器、开放权重模型选择、协议转换、自托管，以及 OAuth 彻底失灵。相比 7 月 5 日关于路由和钱包的讨论，7 月 6 日增加了更尖锐的认证抱怨和更直接的成本疲劳。

**与前一天对比：** 7 月 5 日聚焦于路由器和预付费访问。7 月 6 日则叠加了认证失败、Copilot 内部的开放权重模型选择，以及更强的证据表明，成本正在塑造日常的工具选择。

### 1.4 专用代理界面扩展到安全、代码理解和运行时工具（🡕）

## 2. 什么让人沮丧

### 限制、额度和认证失败仍会打断原本有用的工作流

严重程度：高。最一致的挫败感并不是代理毫无用处，而是它们总在错误的时刻停下。[@Teknium](https://x.com/Teknium) [表示](https://x.com/Teknium/status/2073956256327577698)（328 个赞、21 条回复、14,125 次浏览）称，Google 会阻止部分用户使用 Antigravity 和 Gemini CLI 的 OAuth；而 [@dr_cintas](https://x.com/dr_cintas) [推荐了](https://x.com/dr_cintas/status/2074161566539186371)（54 个赞、14 条回复、4,887 次浏览、69 次收藏）之所以提到 9Router，正是因为人们会在会话中途用完额度，想要在不重配一切的前提下自动回退。[@alexcooldev](https://x.com/alexcooldev) [总结道](https://x.com/alexcooldev/status/2074192149927878761)（41 个赞、27 条回复、2,116 次浏览）则呈现了经济层面：vibe coding 感觉很好，直到账单又开始像养一整个开发团队。应对模式已经很清楚：路由器、更便宜或开放权重的模型通道（如 Copilot 中的 Kimi），或者在自有硬件上跑自托管端点。值得围绕这一点构建产品，因为人们已经在安装独立的控制平面，只为让工作不中断。

![Microsoft 365 Copilot Cowork 错误截图：在资金或配额失败后，引导用户前往 GitHub Copilot 设置](https://pbs.twimg.com/media/HMeIYlOWgAA-wgc.jpg)

### 大型 diff 和长循环中，评审与验证仍会失效

严重程度：高。[@awakecoding](https://x.com/awakecoding) [展示了](https://x.com/awakecoding/status/2074235982346330266)（3 个赞、2 条回复、253 次浏览）提到 GitHub Copilot 因为拉取请求变更超过 20,000 行而拒绝评审。[@0x_sakata](https://x.com/0x_sakata) [警告说](https://x.com/0x_sakata/status/2074053744631898439)（50 个赞、29 条回复、565 次浏览、8 次收藏）称，Claude Code 里的 Codex 评审门会形成漫长的评审循环，如果放任不管，会耗尽使用额度。[@AntonMartyniuk](https://x.com/AntonMartyniuk) [认为](https://x.com/AntonMartyniuk/status/2074017796107743252)（3 个赞、76 次浏览、2 次收藏）指出，真实生产工作仍然需要人工去抓细微 bug、N+1 查询、薄弱测试和糟糕的异步决策；而 Boris 的循环帖子则从另一个角度传达了同样的信息：验证仍是稀缺资源。值得围绕这一点构建产品，因为代理输出如今已经扩展到足够大的范围，以至于评审失效会成为硬阻塞，而不只是烦人的小问题。

![GitHub Copilot 的消息称，由于 diff 超过 20,000 行变更，无法审查某个 pull request](https://pbs.twimg.com/media/HMkqjJeWoAAZ2jm.png)

### 隐蔽的本地设置仍让代理行为难以解释

严重程度：中高。[@emollick](https://x.com/emollick) [删除并更正了](https://x.com/emollick/status/2074015247627682171)（28 个赞、5 条回复、4,094 次浏览）提到一则关于 Claude Code 记忆文件的抱怨：用户后来才发现，其中一台机器仍允许写入记忆文件；后续补充则说，很难分清哪些设置是全局的、机器本地的，哪些又是 Web 专属的。上文提到的 Microsoft 365 Copilot Cowork 错误，从另一个角度也指向了同一类问题：当额度或策略状态暴露得不清楚时，用户无法判断一次失败到底来自计费、认证、产品接线方式，还是模型本身。值得围绕这一点构建产品，因为即便模型行为本身还算合理，隐藏的本地状态也会削弱信任。

### 随着代理接触网页、仓库和本地历史记录，安全与隐私担忧正在上升

严重程度：高。[@israfill](https://x.com/israfill) [将其描述为](https://x.com/israfill/status/2073789727698743516)（74 个赞、25 条回复、6,260 次浏览、91 次收藏）提到 Page Agent 可把任何网页变成 AI 控制的工作流，但回复很快就追问：模型到底能看到哪些 DOM 数据，又会记录哪些内容。[@DanKornas](https://x.com/DanKornas) [提到了](https://x.com/DanKornas/status/2074030310371496249)（8 个赞、2 条回复、1,336 次浏览、8 次收藏）提到 MEDUSA，因为 AI 仓库可能带有被投毒的配置，本地助手历史记录也可能泄露密钥；而 [@RedHat_AI](https://x.com/RedHat_AI) [推荐了](https://x.com/RedHat_AI/status/2074169435728830966)（11 个赞、2 条回复、836 次浏览、8 次收藏）则提到自托管开放模型，以便把数据留在自有硬件上。应对模式已经可见：克隆前先扫描，让高风险界面可审计，并把敏感推理迁移到受控基础设施。值得围绕这一点构建产品，因为浏览器、仓库和本地历史记录这些界面，带来的都是具体暴露点，而不是抽象的未来风险。

## 3. 人们希望出现什么

### 原生路由、额度感知和认证恢复

人们一再在核心工具之外解决同一个连续性问题。[@dr_cintas](https://x.com/dr_cintas) [展示了](https://x.com/dr_cintas/status/2074161566539186371)（54 个赞、14 条回复、4,887 次浏览、69 次收藏）解释了 9Router 为什么会引发共鸣：单一本地端点、额度跟踪，以及跨不同提供方层级的回退。[@Teknium](https://x.com/Teknium) [展示了](https://x.com/Teknium/status/2073956256327577698)（328 个赞、21 条回复、14,125 次浏览）则展示了当 OAuth 本身被拦住时，这种需求会变得多么尖锐；[@xapi_to](https://x.com/xapi_to) [演示了](https://x.com/xapi_to/status/2074055150331891942)（5 个赞、2,601 次浏览）则体现了朝固定目标模型进行协议转换的需求。这不是理想化愿景，而是紧迫的现实需求。机会：直接。

### 跨工具共享的事实来源文件与持久工作流记忆

人们要的并不只是更大的上下文窗口；他们还在围绕“缺少持久、可审查的计划”这个问题构建方案。[@DanKornas](https://x.com/DanKornas) [分享了](https://x.com/DanKornas/status/2074188982544400860)（10 个赞、6 条回复、1,357 次浏览、4 次收藏）提到 Spec-Driven-Development，因为否则 Claude、Cursor 和 Copilot 会彼此分叉；[@DanKornas](https://x.com/DanKornas) [分享了](https://x.com/DanKornas/status/2073769852154638467)（28 个赞、6 条回复、2,115 次浏览、34 次收藏）提到 AI Workflow，因为每次新会话都得从零开始。[@oliviscusAI](https://x.com/oliviscusAI) [提到了](https://x.com/oliviscusAI/status/2073956850660508149)（3 个赞、2 条回复、219 次浏览、2 次收藏）提到 OpenWiki，用来在代码库变化时维护代理可读文档。这个需求既现实又紧迫：需要一种能在多工具之间保持对齐的持久上下文。机会：直接。

### 面向多代理、跨设备和多 worktree 的任务控制中心

最大的编排诉求并不是再来一个单代理 IDE，而是有一个地方能监督多个已经在运行的代理。[@Sumanth_077](https://x.com/Sumanth_077) [介绍了](https://x.com/Sumanth_077/status/2074125418391916641)（12 个赞、3 条回复、1,835 次浏览、6 次收藏）提到 Omnigent，覆盖跨设备会话、混合封装层和策略栈；[@DanKornas](https://x.com/DanKornas) [分享了](https://x.com/DanKornas/status/2073803836666384494)（27 个赞、6 条回复、2,210 次浏览、23 次收藏）提到 multi-agent-shogun，支持可见的并行 shell；[@YoussefHosni951](https://x.com/YoussefHosni951) [展示了](https://x.com/YoussefHosni951/status/2073847022180844026)（3 个赞、3 条回复、127 次浏览）提到 Orca，支持隔离 worktree 以及桌面和移动端监督。现在已经有几个早期答案，但还没有明显的标准。机会：竞争型。

### 可在规模化场景下持续可用的评审界面与设置可见性

用户希望代理工具能在失败白白浪费数小时之前，就暴露出自己的失败模式。[@awakecoding](https://x.com/awakecoding) [展示了](https://x.com/awakecoding/status/2074235982346330266)（3 个赞、2 条回复、253 次浏览）体现了 PR 评审的硬上限；[@emollick](https://x.com/emollick) [描述了](https://x.com/emollick/status/2074015247627682171)（28 个赞、5 条回复、4,094 次浏览）则说明，如果用户不知道状态到底存在哪里，本地记忆写入设置就会看起来像模型行为。这不只是一个 UX 打磨请求。对于依赖长时间运行评审、大型 diff 或机器本地策略的任何工作流来说，这都是现实需求。机会：直接。

整体模式是组合，而不是替代。人们正在现有编码工具之上叠加路由代理、技能包、元封装层、文档层和领域适配器。[@pierceboggan](https://x.com/pierceboggan) [指出](https://x.com/pierceboggan/status/2074177216196554868)（28 个赞、1 条回复、1,323 次浏览）称 Copilot 现在已是 JetBrains 中的原生集成代理，但同一天的信息流也显示，外部路由器、外部评审插件，以及外部记忆/规范层，仍在第一方界面旁边蓬勃发展。

在成本和监督方面，满意度光谱最宽。高价代理仍然承担规划、评审和更难的推理，而更便宜、开放权重或自托管的通道，则被推进到连续性、后台任务或敏感基础设施场景。迁移压力同时朝两个方向拉扯：人们想要更多原生产品界面，但也仍在安装独立控制层，因为内置工具还没有暴露出足够多的路由、记忆、策略或评审状态。

## 7. 机会在哪里

**[+++] 面向混合代理栈的原生路由、额度与认证控制** — 第 1、2、3、4 节的证据都指向这里：9Router、xAPI routing、Copilot 中的 Kimi K2.7、自托管 OpenShift AI 端点、M365 Cowork 故障，以及 Teknium 关于 OAuth 的抱怨。它们都在说明同一个缺口：团队希望会话能跨额度限制、认证漂移和提供方切换持续运行，而不用另装一层独立代理。

**[+++] 共享规范、外部状态与验证循环** — Boris 的循环讨论、Anthropic 的专业知识研究、Spec-Driven-Development、AI Workflow 和 OpenWiki 都在指向同一个需求：代理应从稳定计划出发，在多次运行之间记住正确的产物，并能依据可审查的标准证明自己已完成任务。这个机会很强，因为它把生产力、正确性和多工具一致性连在了一起。

**[++] 并行代理的任务控制中心** — Omnigent、multi-agent-shogun、Orca 和 codex-plugin-cc 都把核心问题视为编排与监督，而不是裸模型质量。这个机会中等偏强，因为痛点已经非常具体，但 shell、桌面、浏览器和手机界面上都已有多个早期答案在竞争。

**[++] 代理安全与设置治理** — MEDUSA、Page Agent 回复中的担忧、Emollick 对记忆设置的困惑，以及推动自托管模型的讨论，都说明人们需要更清楚地知道代理能看到什么、被允许做什么，以及敏感状态存放在哪里。这是一个很强的防御型机会，因为暴露点都是现实存在的，用户也已经很熟悉。

**[+] 围绕现有工具的领域专用代理界面** — Understand Anything、OpenWiki、JVM Pulse、MCP for Unity 和 GeoAgent 表明，一层不断增长的扩展正在把代理接到代码图谱、Java 遥测、游戏编辑器和 GIS 栈等具体系统上。相较于路由和工作流控制，这个信号仍在形成中，但它已经比泛泛的“开发者 AI”讨论具体得多。

## 8. 要点

1. **循环工程成了当天最清晰的心智模型，但验证仍是真正的瓶颈。** Boris Cherny 的工作流框架之所以引发共鸣，是因为它同时贴合 Anthropic 的使用研究，以及从业者关于大量评审工作仍由人类承担的描述。（[来源](https://x.com/alex_prompter/status/2073809060533883364)）
2. **模型周围的那一层，扩张速度仍快于模型故事本身。** AI Workflow、multi-agent-shogun、Omnigent、codex-plugin-cc 和 Spec-Driven-Development 都把协调、记忆和共享事实视为真正的产品界面。（[来源](https://x.com/Sumanth_077/status/2074125418391916641)）
3. **成本、额度和认证摩擦仍在塑造真实采用。** 9Router 的流行、Teknium 关于 OAuth 的抱怨、M365 Cowork 错误，以及更便宜、开放权重和自托管的替代方案，都表明可用性几乎和模型质量一样重要。（[来源](https://x.com/dr_cintas/status/2074161566539186371)）
4. **专用扩展让代理变得更有用，靠的是暴露证据，而不是追求更好的“感觉”。** MEDUSA、Understand Anything、OpenWiki、JVM Pulse、MCP for Unity 和 GeoAgent 都为代理提供了通向仓库、图谱、遥测、编辑器或领域工具的结构化界面。（[来源](https://x.com/DAIEvolutionHub/status/2074084604097765643)）
5. **领域专业知识仍决定代理最后能否收得漂亮。** Anthropic 的公开报告，以及 Anton Martyniuk 这类第一手帖子，都认同一个核心点：人的优势在于理解问题和验证结果，而不是打字速度。（[来源](https://x.com/milan_milanovic/status/2074017002788974610)）
