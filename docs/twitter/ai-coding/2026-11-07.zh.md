## 2. 令人沮丧的问题

### 上下文丢失与压缩

**严重程度：对反映此问题的用户而言较高；问题普遍程度未知。** [@JafarNajafov](https://x.com/JafarNajafov) 表示，工具输出、问题列表和日志会占用大量上下文，而压缩可能导致智能体忘记正在处理的文件和任务。文中将 Context Mode 描述为兼具输出过滤器和本地 SQLite 状态存储的工具；帖子中提到的节省比例是作者的说法，并非独立基准测试结果。（[帖文](https://x.com/JafarNajafov/status/2119009890379452866)；24 个赞，10 次转发，20 条回复，1 次引用，1,261 次浏览，3 次收藏。）

![Context Mode README 配图，宣传节省上下文并列出集成项；该配图属于产品宣传材料，并非独立基准测试](https://pbs.twimg.com/media/HWg8RAXbgAA_GE8.jpg)

**讨论中的观点：** 一条回复认为，原始工具输出应该保存在文件中，以便按需搜索，而不应只是删减；另一条回复则询问，该插件能否在压缩后保留任务列表。双方争论的焦点是如何持久保存并查验状态，而不只是减少 token 数量。

## 3. 用户期待的功能

### 更可预测的个人用量

用户明确提出，希望 Antigravity 计划的配额至少翻一倍，并表示家庭共享用量会打断个人工作。对提出这一需求的用户来说，这既实际又迫切；截图展示了用量情况，却没有提供用户要求的额外额度。**机会判断：直接**，但需求的普遍程度尚不明确。（[@Soso_fun_yt](https://x.com/Soso_fun_yt)、[帖文](https://x.com/Soso_fun_yt/status/2118959006752358704)；35 个赞，7 条回复，3,150 次浏览，6 次收藏。）

### 在上下文压力下保留会话状态

用户希望智能体在上下文压缩后仍能保留当前文件、任务列表和有用的工具输出，同时让原始材料仍可搜索。Context Mode 通过过滤输出和使用本地 SQLite 状态，部分满足了这一需求；一条回复则认为，与其单纯缩减原始输出，不如保留原始输出以便定向搜索。**机会判断：竞争性**，因为已有解决方案正在推广，但讨论串也提出了哪些内容能够保留这一问题。（[@JafarNajafov](https://x.com/JafarNajafov)、[帖文](https://x.com/JafarNajafov/status/2119009890379452866)；24 个赞，10 次转发，20 条回复，1 次引用，1,261 次浏览，3 次收藏。）

### 更可靠的浏览器录制和配置文件

一位测试者表示 OpenCode Browse 可以正常工作，随后提出希望提高录制质量，并简化独立配置文件的设置。这是对工作流程的实际需求，而非要求增加浏览器控制功能——Browse 已经提供了这项功能。**机会判断：竞争性**，因为相关产品已经存在，用户提出的不足主要在配置和回放方面。（[@maharshi365](https://x.com/maharshi365)、[在 OpenCode 测试帖串中回复](https://x.com/thdxr/status/2118878460391137310)；4 个赞，1 条回复，877 次浏览，1 次收藏。）

## 8. 要点

1. **浏览器访问与项目隔离解决的是不同的边界问题。** OpenCode Browse 通过用户的浏览器会话运行，而 DevVM 则隔离每个项目的智能体环境。（[@opencode](https://x.com/opencode), [帖子](https://x.com/opencode/status/2118895128152621153)；183 个赞、12 次转发、11 条回复、4 次引用、4,272 次浏览、44 次收藏；[@RoundtableSpace](https://x.com/RoundtableSpace), [帖子](https://x.com/RoundtableSpace/status/2118874827683774478)；26 个赞、2 次转发、24 条回复、48,708 次浏览、9 次收藏。）
