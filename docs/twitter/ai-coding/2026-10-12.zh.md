### 1.2 人们评判 Codex 公告时，看的是额度账而不是发布文案（🡕）

围绕 OpenAI 的 Codex 的讨论，核心在于近期关于上下文窗口和定价的公告，是否真的改变了实际使用条件。公开证据分成两层：一层是官方传达的信息，即默认窗口更大，以及订阅用户使用长上下文的成本更低；另一层则是用户的反弹，他们认为相比额度削减和重置规则之争，这些更新要么幅度很小，要么前后矛盾。最终，这讲的是信任问题，而不只是能力问题。

[@alexgetmancom](https://x.com/alexgetmancom) [认为](https://x.com/alexgetmancom/status/2109445163315613840)（167 个赞，28 条回复，10,069 次浏览）称，OpenAI 的 Day 7 Codex sprint 把默认上下文从 272K 提升到 500K 这件事说得过于夸张了，因为最大值原本就已经可以手动设到 1M。被引用的 [官方更新](https://x.com/thsottiaux/status/2109430343346581527) 确实说明，500K 现在成了经过测试的默认最佳区间，但回复显示出明显分歧：一些用户表示默认值很重要，因为大多数人从不修改 `config.toml`；另一些人则认为，这个更新太小，不足以成为头条式发布内容。（[帖子链接](https://x.com/alexgetmancom/status/2109445163315613840)）[@_jayyy18_13k](https://x.com/_jayyy18_13k) [分享](https://x.com/_jayyy18_13k/status/2109442614701576249)（12 个赞，5 条回复，481 次浏览）这一配套说法称，订阅中的 GPT-6.1 Sol 长上下文费用已被取消。但这并没有结束这轮抱怨。[@babayagatwt](https://x.com/babayagatwt) [反驳称](https://x.com/babayagatwt/status/2109592466685075727)（5 个赞，2 条回复，81 次浏览）表示，产品变得更高效，本应让客户受益，随后附上一张定价截图，称新的 Pro 200 订阅如今反而配额更低，理由是这些模型“效率越来越高”。用户抓住的，正是更慷慨的宣传口径与更紧的配额之间的矛盾。

![定价文字说明称，新的 Pro 200 订阅之所以使用额度更低，是因为模型正变得越来越高效，而月费仍保持为 200 美元](https://pbs.twimg.com/media/HUbHKj7bMAAWXZR.jpg)

**讨论洞察：** 对这次发布最可信的辩护，不是说用户错了，而是默认设置确实会改变真实行为，因为大多数会话都使用默认设置。即便如此，这种辩护也承认了更深层的抱怨：人们想要的是更清楚地说明使用政策到底改了什么，而不只是一条喜气洋洋的功能发布帖。

**与前一天对比：** 2026-10-11 的抱怨集中在硬性上限和中途削减套餐；到了 2026-10-12，同样的挫败感进一步收束为一个更具体的抱怨：发布时的叙事框架与配额政策正朝着相反方向移动。

### 1.3 安全讨论转向具体的本地控制与基准化权衡（🡕）

这场安全讨论具体得不同寻常。信息流里不再只是泛泛警告代理风险，而是出现了一篇基准测试论文、一个转录内容密钥清洗工具、一个本地取证监控器，以及一张互动不高但信息量很足的 Windows 持久沙箱服务截图。合在一起看，这些内容显示社区正在从“要小心”转向“边界设在哪里、挂什么 hook、代价是什么？”

[@al3rez](https://x.com/al3rez) [总结](https://x.com/al3rez/status/2109570007613259850)（6 个赞，10 条回复，322 次浏览）HarnessSecurity-Bench，而所链接的 [arXiv 论文](https://arxiv.org/abs/2610.07639) 也支持这条推文中的核心数字：覆盖五类攻击面的 23 项任务、2,500 次试验、六种 harness，并且 auto-approve 会把攻击成功率从 29.2% 提高到 95.6%。最有价值的回复并不危言耸听，而是偏向实操：有位回复者表示，完全离线模式会破坏 `npm install` 和 `git pull`，因此他们团队改为采用经批准主机的短 allowlist，而不是一刀切的网络隔离。（[帖子链接](https://x.com/al3rez/status/2109570007613259850)）

![来自 HarnessSecurity-Bench 的图示，展示了围绕编码代理 harness 循环的六个攻击面，包括代码仓库产物、指令、工具接口、记忆、外部服务以及直接用户输入](https://pbs.twimg.com/media/HUayvNWbwAEl13L.jpg)

[@44errrr](https://x.com/44errrr) [表示](https://x.com/44errrr/status/2109585066279981310)（4 个赞，10 条回复，97 次浏览）指出，代理转录和工具运行会在磁盘上留下明文秘密信息，随后提到可将 spillage 作为 Claude Code、Codex、Gemini CLI、Cursor 和 Cline 的一层缓解措施。公开的 [spillage 仓库](https://github.com/maximilianfeix/spillage) 与这条推文的表述一致：hooks 会拦截包含密钥的提示词、`.env` 读取，以及 `printenv`，而扫描和清洗则处理十四种代理日志中已经泄露的内容。[@DFIR_Radar](https://x.com/DFIR_Radar) [重点介绍了](https://x.com/DFIR_Radar/status/2109615943882334701)（3 个赞，2 条回复，237 次浏览）numbat，而公开的 [numbat 仓库](https://github.com/perplexityai/numbat) 则展示了同一问题的另一面：本地 hooks，只读 `numbat scan` 重建，以及针对受支持的前置操作钩子的可选拦截。

[@TambaClan](https://x.com/TambaClan) [发布](https://x.com/TambaClan/status/2109570811086643471)（1 条回复，90 次浏览）的一张截图显示，`codex-windows-sandbox-service.exe` 以 Windows `ChatGPT` 服务的形式在 `LocalSystem` 下运行，并且能抗拒禁用尝试。互动量很小，但这张图为本地运行时增添了一层不透明感，而此前信号更强的基准测试和缓解措施讨论，已经让人们开始注意这一点。

**讨论洞察：** 回复不断收敛到同一个权衡：最安全的控制措施往往也是干扰性最大的，因此团队都在寻找一种边界——比提示词指令更严格，但又不像完全离线模式那样宽泛。

**与前一天对比：** 在 2026-10-11，关于信任的讨论主要围绕将沙箱和遥测作为产品功能展开。到 2026-10-12，信息流中又增加了更扎实的证据：经基准测试量化的攻击差异、具体的密钥清洗工作流，以及只读取证工具。

### 1.4 开发者仍在用持久化、技能和领域适配器封装智能体（🡕）

最强的开发者热情依然集中在围绕现有智能体构建外层，而不是新的基础模型。最突出的项目呈现出一个共同模式：让工作在聊天结束后仍能延续、让输出更容易审查，或将智能体扩展到 CAD 和技术插图等狭窄但实用的领域。换句话说，差异化来自工作流结构。

[@DanKornas](https://x.com/DanKornas) [介绍了](https://x.com/DanKornas/status/2109565724641391044)（14 个赞，7 条回复，805 次浏览）介绍了 Overtime：一款面向智能体的终端应用，让它们能跨会话保留自己的文件夹、笔记、日程安排和唤醒机制；而公开的 [仓库](https://github.com/ukanwat/overtime) 表示，该应用通过 ACP 驱动 Claude、Codex、Gemini CLI、GitHub Copilot、OpenCode 及其他后端。截图展示了这一主张在实际中的样子：左侧是智能体状态，右侧是统一的决策界面，而且无需一直盯着原始工具日志看。（[帖子链接](https://x.com/DanKornas/status/2109565724641391044)）

**讨论洞察：** 这些项目始终把模型当作可互换的后端。项目之间真正变化的是控制层：文件夹、日程、审批、渲染器、查看器，以及领域专属技能。

**与前一天的对比：** 2026-10-11 的 wrapper 项目主要集中在编排和呈现上。到了 2026-10-12，最强的一批构建则更加侧重连续性和领域适配器，让 agents 产出用户可以检查或制造的制品。

### Secure harness 的设置看起来仍然要么默认过松，要么全面启用的成本过高

严重程度：高。[@al3rez](https://x.com/al3rez) [重点标出](https://x.com/al3rez/status/2109570007613259850)（6 次点赞，10 条回复，322 次浏览）给出了基准测试证据：自动批准会让攻击成功率从 29.2% 升至 95.6%；同时有一条回复称，完全离线模式会破坏像 `npm install` 和 `git pull` 这样的常规任务。[@44errrr](https://x.com/44errrr) [添加了](https://x.com/44errrr/status/2109585066279981310)（4 次点赞，10 条回复，97 次浏览）称，即便用户试图谨慎操作，转录记录和本地日志里仍可能保留明文密钥。人们想要的是比提示词约束更强、但又不至于像把 agent 锁进地堡那样严苛的边界。值得构建：高。

## 3. 人们希望有什么

### 面向模型访问权限、套餐权益和发布变更的公开台账

Antigravity 用户不该靠菜单、重定向 URL 和消失的模型来推断权益策略。[@StatsWire](https://x.com/StatsWire/status/2109568320676499854) 矩阵、[@blankspeaker](https://x.com/blankspeaker/status/2109718114355347951) 下线通知，以及 [@yoftahe](https://x.com/yoftahe/status/2109686224516727286) 升级重定向，三者共同指向一个明显缺失的产品：一份变更日志，清楚说明谁能使用哪些模型、这些权限何时变化，以及接下来会下线什么。机会：直接。

### 默认安全的本地 agent 操作

当天最强的信任信号都指向同一个诉求：把经过基准验证的 harness 控制、会话记录卫生和取证可见性整合进一个默认安全的方案里。[@al3rez](https://x.com/al3rez/status/2109570007613259850) 说明了自动批准为何危险，[@44errrr](https://x.com/44errrr/status/2109585066279981310) 说明了事后清理 secret 为何重要，而 [@DFIR_Radar](https://x.com/DFIR_Radar/status/2109615943882334701) 则说明了为什么响应人员希望在不先改造每条工作流的前提下重建会话。机会：直接。

### 能唤醒、暂停并请求批准的持久化任务管理器

[@DanKornas](https://x.com/DanKornas/status/2109565724641391044) 将 Overtime 描述为一种让 agent 在聊天结束后继续运行的方式，而 [@matchaman11](https://x.com/matchaman11/status/2109702983550382452) 则展示了 Open Dots 如何把类似思路推进到带审批和周期性提示的自托管 sandbox 中。这两条帖子背后的诉求很简单：让开发者只需一次性分配长时间运行的工作，之后只在 agent 真正遇到决策节点时再回来介入。机会：直接。

### 产出可检查工件而不只是文字的垂直领域 agent 技能

Anatomy 和 text-to-cad 之所以受到关注，是因为它们让 agent 生成的是用户可以直接评估的东西：解释图、3D 场景、STEP 文件，或可打印部件。[@wheresryan22](https://x.com/wheresryan22/status/2109435267316641989) 和 [@thesupermannx](https://x.com/thesupermannx/status/2109467005380362478) 表明，还有一种更广泛的诉求：狭而深的专项技能，用来弥合“模型说它理解了”和“输出实际上可以被检查或制造”之间的差距。机会：竞争型。

## 6. 新动态与值得关注的事

### GitHub 解释了为什么拖垮超大 PR 界面的不是代码行，而是评论

[@github](https://x.com/github) [报道](https://x.com/github/status/2109707357857218667)（143 个赞、27 条回复、30,344 次浏览、39 次收藏）表示，在 Copilot 应用里渲染一个百万行 diff 反而是容易的，真正的扩展性难题在评论，因为在渲染前无法预知它们的高度。链接中的 [工程博客文章](https://github.blog/engineering/user-experience/how-we-built-the-github-copilot-app-to-work-on-prs-with-over-a-million-lines-of-code/) 把这套架构讲清楚了：将代码行的几何信息与动态评论的几何信息拆分开来，然后围绕视口进行循环测量，而不是让 `ResizeObserver` 直接把结果写回布局。

### Harness 安全研究给出了一个让人容易记住、也便于复用的数字

[@al3rez](https://x.com/al3rez) [分享](https://x.com/al3rez/status/2109570007613259850)（6 个赞、10 条回复、322 次浏览）给出了一个很可能会持续流传的安全结果：auto-approve 使基准攻击成功率从 29.2% 提升到 95.6%。值得注意的不只是警示本身，更在于论文和回复也带出了操作层面的权衡，尤其是围绕网络隔离和 allowlist 的取舍，这让这个基准比单纯的“恐慌帖”更具可操作性。

### 本地性能调优终于有了前后对比的耗时数据

[@VRAMCalculator](https://x.com/VRAMCalculator) [发布](https://x.com/VRAMCalculator/status/2109761179383906720)（7 个赞、2 条回复、226 次浏览、5 次收藏）给出了当天最干净的一组运行时测量之一：在 Strata/OpenCode 配置中，一个 14K-token 的 coding-agent 轮次，耗时从 94.8 秒降到 6.9 秒，并在启用 `--prompt-cache 6` 后进一步降到 4.1 秒。

### Antigravity 不再像传言，更像一次迁移

综合来看，[@StatsWire](https://x.com/StatsWire/status/2109568320676499854) 的套餐矩阵、[@blankspeaker](https://x.com/blankspeaker/status/2109718114355347951) 标注日期的下线通知，以及 [@LuminaBench](https://x.com/LuminaBench/status/2109771800485769391) 的选择器截图（19 个赞、2 条回复、878 次浏览），让当天关于 Antigravity 的讨论变成了一则清晰可辨的迁移故事。即便没有一篇明确、定论式的上线公告，围绕权益变化与模型消失的证据基础，也已经很难再被当作纯粹的猜测。

## 7. 机会在哪里

**[+++] agent 界面的权益追踪** - Antigravity 用户实际上是在靠截图、跳转和不断消失的模型菜单，自己拼出一份变更日志。一个能够记录不同用户在不同套餐下获得了哪些模型、以及这些权限何时发生变化的产品，可以立即补上这道信任缺口。**[+++] 安全的本地代理操作套件** - HarnessSecurity-Bench、spillage、numbat，以及 Codex sandbox-service 的截图，都指向同一个打包机会：将主机白名单、审批闸门、转录清理、会话重建和清晰的本地运行时说明，作为一个具有明确设计取向的一体化套件交付。

**[++] 持久化代理监督器** - Overtime 和 Open Dots 显示出市场对这类代理的需求：它们可以休眠、唤醒、重新检查文件、请求批准，并在聊天会话结束后继续运行。这个空白在“这种持久性仍然可审查且易于覆盖”时最为明显。

**[++] 能输出真实工件的领域专用技能** - Anatomy 和 text-to-cad 之所以获得关注，是因为它们能产出图表、场景和制造文件，用户可以直接判断其质量。对于更多聚焦的窄技能，仍有空间把编码代理的推理转化为带有独立验证路径的工件。

**[++] 可随复杂度扩展的审查界面** - GitHub 的 PR-viewer 讨论串表明，一旦代理开始处理非常大的 diff，瓶颈就会从模型原始输出转移到渲染、导航和评论布局，而不是模型输出本身。更好的审查界面正成为 AI 编码栈的一部分。

## 8. 要点

1. **访问策略已成为产品现实。** 2026-10-12 关于 Antigravity 的讨论，驱动力与其说是基准测试带来的兴奋，不如说是“谁能使用哪些模型、能用多久”这些可见变化。
2. **使用信任如今与原始能力同样重要。** Codex 用户愿意详细讨论上下文默认设置和订阅费用，因为真正的问题是：花同样的钱，产品是否确实变得更好用了。
3. **安全讨论正从警告转向运维工具。** 基准测试数据、转录清理器和取证扫描器都显示出一种转变：从抽象的安全担忧，转向具体的边界设计。
4. **构建者的差异化正体现在工作流层，而不只是模型选择上。** Overtime、Open Dots、Anatomy 和 text-to-cad 都是在现有代理之上，叠加了连续性、审批流程或领域专用输出。
5. **下一阶段的竞争优势是可审查性。** 无论问题是模型使用权限、超大的 PR、机密泄露，还是长时间运行的任务，正在获得关注的产品，都是那些让代理行为更容易被看见、验证和控制的产品。
