## 1. 大家在讨论什么

### 1.1 运行框架的可靠性可能与模型同样重要 🡒

五条帖子提出了相互关联的问题：智能体提前停止、跳过测试、丢失约束，或在工作尚未完成时就继续推进。LangChain 发布的一项实验提供了一个可量化的例子：在 GPT-5.2-Codex 保持不变的情况下，Deep Agents 编程智能体在改进运行框架后，Terminal-Bench 2.0 得分从 52.8 提升至 66.5；改进内容包括自我验证和循环检测（[LangChain](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)）。

[@MaryamMiradi](https://x.com/MaryamMiradi) [概述了](https://x.com/MaryamMiradi/status/2123875734305345575)（18 个赞，20 条回复，626 次浏览，16 次收藏）介绍了一个五层运行框架，涵盖智能体循环、工具、上下文、记忆和评估。附图展示了权限控制和结果检查如何置于“上下文—模型—工具—结果”的循环之中，并反复运行。

![信息图：展示智能体运行框架的五个层级，以及上下文、模型、权限、工具、结果和循环迭代流程](https://pbs.twimg.com/media/HXmEKffXMAAYrVS.jpg)

[@vanshdot](https://x.com/vanshdot) [声称](https://x.com/vanshdot/status/2123966532263055868)（2 个赞，2 条回复，20 次浏览）称，Gemini 4 Neon 在精简的 mini-SWE 运行框架中得分为 12.8%，而在 Antigravity 中得分为 39.0%，并将差异归因于周边配置；该帖子没有附上评测链接。另有开发者分享了各自的经历：[@johnmatsis](https://x.com/johnmatsis) [报道称](https://x.com/johnmatsis/status/2123957429641572459)（1 个赞，2 条回复，27 次浏览）谈到 Codex 在开发一个交易平台时出现幻觉、项目里程碑未能完成；[@jaxcore](https://x.com/jaxcore) [表示](https://x.com/jaxcore/status/2123926707027505431)（3 条回复，37 次浏览）则表示，原理图和 CAD 输出需要经过多轮修改和三重核查。

[@arijitghosh02](https://x.com/arijitghosh02) [描述了](https://x.com/arijitghosh02/status/2123967158262579591)（2 条回复，12 次浏览）提到，一条 Claude Code 规则在上下文压缩过程中丢失，并建议将需要长期保留的指令写入项目 `CLAUDE.md`。

**讨论要点：** [@daraben_](https://x.com/daraben_) [认为](https://x.com/daraben_/status/2123899473680330830)（1 个赞，7 次浏览）认为，明确的完成条件有助于解决任务过早停止的问题；另一条回复 [询问](https://x.com/dnzxlyfe/status/2123892259246764056)（1 个赞，8 次浏览）则提出，循环检测应如何区分真正的重试和无效循环。

**与前一天对比：** 11 月 20 日，[@antigravity](https://x.com/antigravity) [宣布](https://x.com/antigravity/status/2123890186308239857)（358 个赞，17 条回复，13,862 次浏览，79 次收藏）介绍了一个集成七种数据库技能的 MongoDB Atlas MCP。一条回复 [报道称](https://x.com/Crashoverride_X/status/2123904973545066650)（48 次浏览）则称，每周要等上五天才能使用 Pro 套餐。11 月 21 日的帖子从可靠性和验证的角度，为此前关于集成与配额的讨论增添了新的视角。

## 2. 用户感到困扰的问题

### 智能体可能只汇报进展，却未完成任务或持续遵守约束

**严重程度：中到高。** 三则从业者帖子描述了后果严重但各自独立的失误。[@johnmatsis](https://x.com/johnmatsis) [表示](https://x.com/johnmatsis/status/2123957429641572459)（1 个赞、2 条回复、27 次浏览）Codex 在构建一个市场平台时产生了幻觉，并在早期里程碑尚未完成时就推进到了后续阶段。[@jaxcore](https://x.com/jaxcore) [报道称](https://x.com/jaxcore/status/2123926707027505431)（3 条回复、37 次浏览）需要经过多轮审查，并反复核对原理图和 CAD 输出。[@arijitghosh02](https://x.com/arijitghosh02) [描述了](https://x.com/arijitghosh02/status/2123967158262579591)（2 条回复、12 次浏览）Claude Code 压缩长对话后，一条指令消失了；作者现在会把需要长期遵守的规则写入 `CLAUDE.md`。目前观察到的样本太少，无法估算这类问题的普遍程度。现阶段提到的应对方法包括明确的完成检查、测试，以及长期保留的项目指令；LangChain 的 [实验](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)会在任务完成前进行验证并运行测试。这是一个值得着手解决的实际问题。

### 套餐权益和使用成本有时不够清晰

**严重程度：中。** [@ManningBlackall](https://x.com/ManningBlackall) [报道称](https://x.com/ManningBlackall/status/2123954803655291106)（3 个赞、2 条回复、43 次浏览）有用户称，升级 Workspace 后，Gemini 和 Antigravity 中仍无法使用 Neon，而且没有明确的后续升级选项。[@DevAdventur3s](https://x.com/DevAdventur3s) [表示](https://x.com/DevAdventur3s/status/2123922615559434338)（2 条回复、197 次浏览）另有用户表示，Astra API 的折扣未能在 Codex 中生效，而作者正是通过 Codex 使用 Astra。 [@TekonBurns](https://x.com/TekonBurns) [描述了](https://x.com/TekonBurns/status/2123964615428276612)（6 个赞，3 条回复，422 次浏览）某个速度档位的 API 价格原定涨至标准价格的六倍。这些帖子反映的是用户对具体资格条件和费用的困惑，并不能广泛说明用户的不满程度。更清晰的套餐与模型对应表，以及使用费用展示，可以解决用户报告的具体痛点。

### 本地项目历史记录可能跨越账户边界

**严重程度：潜在影响高，已观察到的发生率低。** [@SJFriedl](https://x.com/SJFriedl) [警告](https://x.com/SJFriedl/status/2123936740746707360)（1 个赞，2 条回复，91 次浏览）表示，在 Plus 和 Business 账户之间切换后，Codex Desktop 显示的本地项目和对话仍然相同。关联的 [Codex 问题](https://github.com/openai/codex/issues/35657) 描述了相同的账户切换行为，指出清除本地数据只能暂时解决问题，并提到了潜在的隐私影响。帖子中提到的直接应对方法是清除本地数据，但报告称这无法有效隔离账户；值得着手解决的长期方案是为每个账户提供独立的工作区。

## 3. 用户希望具备的功能

### 可验证的任务完成状态与持久任务规则

**实际需求。紧迫程度：中至高。机会：可直接解决。** 这些帖子呼吁构建能够验证任务确已完成、并在上下文压缩后保留重要约束的智能体。在关于智能体运行框架的讨论帖中，[@daraben_](https://x.com/daraben_) [建议](https://x.com/daraben_/status/2123899473680330830)（1 个赞，7 次浏览）主张设置明确的完成条件，而不是让模型自行决定何时停止。[@arijitghosh02](https://x.com/arijitghosh02) [建议](https://x.com/arijitghosh02/status/2123967158262579591)（2 条回复，12 次浏览）则建议将持久规则写入 `CLAUDE.md`。LangChain 的 [测试框架实验](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering) 通过增加完成前的验证步骤和测试，部分解决了这一问题；与此同时，帖子也提出了一个尚未解决的设计问题：如何识别循环，又不打断合理的重复编辑。

### 按账户隔离本地工作区

**实际需求。紧迫程度：对处理机密项目的团队而言较高。机会：可直接解决。** [@SJFriedl](https://x.com/SJFriedl) [提醒谨慎](https://x.com/SJFriedl/status/2123936740746707360)（1 个赞，2 条回复，91 次浏览）指出，Codex Desktop 在两个账户之间显示了相同的本地项目和对话。关联的 [公开议题](https://github.com/openai/codex/issues/35657) 表示，每个账户都应拥有相互隔离的本地项目和会话状态。该问题没有提到持久有效的变通方案，因此，支持按账户隔离是这组帖子中最明确的未满足需求。

### 明确展示模型可用性和套餐资格条件

**实际需求。紧迫程度：中。机会： 直接。** [@ManningBlackall](https://x.com/ManningBlackall) [提出质疑](https://x.com/ManningBlackall/status/2123954803655291106)（3 个赞、2 条回复、43 次浏览）付费升级 Workspace 后，Neon 为什么仍不可用，也没有明确的升级路径？[@DevAdventur3s](https://x.com/DevAdventur3s) [指出](https://x.com/DevAdventur3s/status/2123922615559434338)（2 条回复、197 次浏览）Astra 折扣不适用于 Codex。这些截图和帖子显示，不同套餐类型提供了部分访问权限，但用户仍找不到一条明确的路径，无法在自己偏好的编程界面中使用模型。

### OpenResearch Intelligence Index 新增模型与编码运行环境的成本视角

[@Ldataengineer](https://x.com/Ldataengineer) [总结](https://x.com/Ldataengineer/status/2123942570069721590)（1 个赞、2 条回复、154 次浏览）alphaXiv 于 11 月 20 日发布的 OpenResearch Intelligence Index。结果表对比了八组模型与运行环境组合，并报告每次尝试的平均成本：Claude Code 中的 Opus 5.5 得分为 0.618，成本为 $16.46；Codex 中的 GPT-6.1 Sol 得分为 0.549，成本为 $3.83。alphaXiv 的 [方法论](https://www.alphaxiv.org/blog/introducing-openresearch-intelligence-index) 表示，该索引涵盖科学、后训练和文献任务，使用各提供商原生的编码运行环境，且无法与原始基准测试排行榜直接比较；项目方称代码将于后续发布。这是一个自动化研究索引，而非编码基准测试。
