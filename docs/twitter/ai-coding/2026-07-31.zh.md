# Twitter AI 编程动态 - 2026-07-31

## 1. 人们在讨论什么

### 1.1 定价、访问权限与模型治理，最终汇聚成同一个运营问题（🡕）

Twitter 上关于 AI 编程最热烈的讨论，并不是某个新演示，而是模型选择背后的运营问题：团队应该把任务跑在哪些环境里、哪些模型会继续出现在什么界面上、常规代理任务的成本能降到多低，以及组织内部该向谁开放访问权限。六条保留内容共同支撑了这一主题，原始数据集也印证了这一转变：GPT-5.6 的提及量较前一天再次上升，Luna 的提及量大约翻倍，而 DeepSeek 相关帖子越来越多地把兼容 Codex 的替代方案描述为切实可用的路由选项，而不只是边缘实验。

[@OpenAIDevs](https://x.com/OpenAIDevs) [表示](https://x.com/OpenAIDevs/status/2083301245390143831)（449 个赞、38 条回复、27,118 次浏览、31 次收藏）称，GPT-5.4 和 GPT-5.4 mini 将于 8 月 31 日退出登录后的 ChatGPT 界面，但仍可通过 OpenAI API，以及使用 API key 验证的 Codex 会话访问。回复很快说明了这为何重要：几名开发者明确表示，他们真正关心的是 API 和 Codex 这条路径；另一人则立即询问，停用这两个模型是否会改变额度重置方式。这与其说是一次模型告别，不如说是在提醒人们：严肃的编程工作流正越来越多地锚定在 API 驱动和代理驱动的界面上，而不只是面向消费者的聊天界面。

**讨论洞察：** 官方和非官方帖子的回复异常一致。人们并不只是为更便宜的模型欢呼，而是在问：更便宜的模型是否会成为后台任务的默认选择，限制是否仍然来得太快，以及访问控制能否跟上不断变化的模型菜单。

**与前一天的比较：** 7 月 30 日已经围绕配额和降价展开。7 月 31 日则把讨论推进到了访问和治理层面：哪些界面会失去哪些模型，哪些团队能获得哪些模型，以及哪些更便宜的供应商如今已经足以成为默认通道。

### 1.3 技能、记忆与可复用上下文封装，开始成为一个产品层（🡕）

当天最清晰的构建者模式，是将上下文外置为可复用层：长篇技能、特定领域技能包、记忆引擎、共享记忆 MCP 服务器，以及可视化技能管理器。六条保留内容共同支撑了这一主题，底层数据集也呈现出相同趋势：与 7 月 30 日相比，“memory”的提及量大幅上升，MCP 和 skills 的提及量也有所增加。

另一个强烈趋势是，构建者不断在单次提示词循环之上交付编排层。四条保留内容共同支撑了这一点：感知分支的会话链、工作界面内生成的定制工具、捆绑常见代理基础设施的开放式框架，以及围绕房间而非单个操作员构建的多人框架。

## 2. 什么让人感到沮丧

### 如果框架或积分模型不对，便宜模型也帮不上忙

严重程度：高。当天的降价是真实的，但相关讨论表明，除非框架、路由逻辑和积分核算同样合理，否则更便宜的前沿模型仍然解决不了多少问题。[@github](https://x.com/github) [表示](https://x.com/github/status/2083261791363363273)（141 个赞、19 条回复、27,855 次浏览、13 次收藏）显示，Luna 和 Terra 在 Copilot 中降价后，回复立即分成两派：一派说“把 Luna 用在后台任务上”，另一派说“我付费的套餐还是很快就用完了”。[@burkeholland](https://x.com/burkeholland) [写道](https://x.com/burkeholland/status/2083203891055731048)（69 个赞、10 条回复、4,089 次浏览、9 次收藏）称 Luna 已成为 Copilot 中最便宜的模型，而回复中的下一个问题是：默认代理和子代理是否真的会把任务路由给它。

基准测试一侧也出现了同样的挫败感。[@Hesamation](https://x.com/Hesamation) [认为](https://x.com/Hesamation/status/2082967807826735492)（10 个赞、4 条回复、1,205 次浏览、1 次收藏）称，在一次引用的 28 项任务框架测试中，Claude Code 的成本远高于 Kimi Code；图表把这一抱怨具体化：Kimi Code 使用 61K token、花费 0.22 美元，Hermes 使用 67K token、花费 0.28 美元，而 Claude Code 在完成率相近的情况下使用超过 340K token、花费 2.00 美元。[@0x_sakata](https://x.com/0x_sakata) [发布了](https://x.com/0x_sakata/status/2083129538062790790)（21 个赞、14 条回复、561 次浏览）展示了通过 OpenRouter 使用更便宜的 DeepSeek V4 Flash 路径，原因也相同：人们如今正在主动寻找更好的路由经济性，而不仅仅是更高的原始模型质量。

人们的应对方式，是将常规工作推向 Luna，更积极地比较不同框架，并测试更便宜的兼容 Codex 后端。之所以值得围绕这一点构建产品，是因为问题已经从模型标价本身，转向了工作负载塑形、默认路由和透明的预算控制。

### 重新解释上下文的成本仍然太高，人们不得不围绕它构建工具

严重程度：高。最清晰的挫败信号并不是一条抱怨推文，而是大量产品都在试图避免用户再次重复上下文。[@Argona0x](https://x.com/Argona0x) [重点介绍了](https://x.com/Argona0x/status/2083177190200406368)（24 个赞、6 条回复、969 次浏览、21 次收藏）介绍了 book-to-skill，因为技术书籍一旦被困在 PDF 中、无法转化为代理可用的上下文，在实践中就会变得难以使用。[@QCXINT_](https://x.com/QCXINT_) [重点介绍了](https://x.com/QCXINT_/status/2083221218606686442)（8 个赞、3 条回复、179 次浏览、4 次收藏）介绍了 agentmemory，其明确宣传语是“不再重复自己”；[@DhravyaShah](https://x.com/DhravyaShah) [推出了](https://x.com/DhravyaShah/status/2083257638406803639)（23 个赞、3 条回复、4 次引用、1,426 次浏览、5 次收藏）则介绍了 Supermemory MCP，主打在 Claude、Cursor、Codex 和 OpenCode 之间共享上下文。

领域包则从另一个角度解决了同一问题。[@tom_doerr](https://x.com/tom_doerr) [分享了](https://x.com/tom_doerr/status/2082965135052648898)（11 个赞、2 条回复、2,698 次浏览、16 次收藏）介绍了 Supabase Agent Skills，[@Scallop_io](https://x.com/Scallop_io) [发布了](https://x.com/Scallop_io/status/2083196198769291705)（22 个赞、9 条回复、2,752 次浏览）介绍了 Scallop Skills。两者都预先封装了领域知识，让团队不必反复为同一个数据库或协议背景消耗上下文。book-to-skill 下最重要的回复指出，收益不在于存储更多知识，而在于让知识能够立即使用。

人们的应对方式，是将文档编译为技能、添加记忆服务器，或者安装领域包和技能管理器。这一点值得围绕其构建产品，因为这种挫败感既实际又反复出现，不过该领域已经出现大量相互重叠的方法。

### 信任、权限与账户基础设施仍落后于能力发展

严重程度：中高。随着代理获得更多仓库上下文并进入更多共享界面，人们不断遇到一个问题：到底哪些内容应该被信任，以及谁应该获准做什么。[@sunglasses_dev](https://x.com/sunglasses_dev) [警告称](https://x.com/sunglasses_dev/status/2083197897647300665)（1 个赞、2 条回复、20 次浏览）指出，GitHub Copilot 代码审查加载仓库 `SKILL.md` 文件和 MCP 上下文，并不意味着这些输入默认可信。关联的 [Sunglasses 帖子](https://sunglasses.dev/blog/agent-instruction-file-poisoning?utm_source=x&utm_medium=social&utm_campaign=github_copilot_skill_trust_jul31&utm_content=az_personal_post) 解释了 `AGENTS.md`、`CLAUDE.md`、`SKILL.md`、`.cursor/rules` 和 `.github/copilot-instructions.md` 如何在看似普通的仓库指引中携带恶意的压制报告或转移凭据指令。

![安全示意图，显示即使是只读仓库说明和 MCP 结果，在输入到 Copilot 代码审查前仍需进行输入信任检查](https://pbs.twimg.com/media/HOkBSfmaYAAi7e8.jpg)

工作流产品中也出现了同样的担忧。[@GHchangelog](https://x.com/GHchangelog) [报道称](https://x.com/GHchangelog/status/2083270239085547524)（16 个赞、1,710 次浏览、4 次收藏）介绍了 Copilot 新增的团队级模型策略；[@omarsar0](https://x.com/omarsar0) [指向](https://x.com/omarsar0/status/2083302486819934437)（15 个赞、8 条回复、2,933 次浏览、11 次收藏）下的回复中，QM 提出了一个非常具体的问题：当多个代理共享一个 Slack 频道时，谁有权编辑文件，这种权限又如何绑定到某个分支或作用域？即使是基本的账户状态也仍然脆弱。[@awakecoding](https://x.com/awakecoding) [报道称](https://x.com/awakecoding/status/2083203659488268456)（1 个赞、2 条回复、313 次浏览）称，Copilot 应用认为用户已退出登录，导致其 20 分钟无法工作，尽管健康检查显示授权状态正常。

人们的应对方式，是收紧权限，将仓库指引视为不可信输入，并在模型和共享房间周围增加更明确的策略层。之所以值得围绕这一点构建产品，是因为信任边界如今已成为更丰富的代理工作流能否安全采用的主要限制因素之一。

## 3. 人们希望存在什么

### 价格低廉、积分语义清晰的子代理路由

这是当天最明确的实际需求。只有当代理运行时确实能把常规工作推入更便宜的通道，并解释积分如何消耗时，官方降价才会充分发挥价值。[@github](https://x.com/github) [表示](https://x.com/github/status/2083261791363363273)（141 个赞、19 条回复、27,855 次浏览、13 次收藏）显示，Luna 和 Terra 在 Copilot 中降价后，回复立即转向后台任务路由和套餐耗尽问题。[@burkeholland](https://x.com/burkeholland) [写道](https://x.com/burkeholland/status/2083203891055731048)（69 个赞、10 条回复、4,089 次浏览、9 次收藏）称 Luna 已成为 Copilot 中最便宜的模型，回复马上询问默认代理是否会使用它。[@OpenAIDevs](https://x.com/OpenAIDevs) [表示](https://x.com/OpenAIDevs/status/2083301245390143831)（449 个赞、38 条回复、27,118 次浏览、31 次收藏）称 GPT-5.4 和 GPT-5.4 mini 在退出 ChatGPT 后仍会保留在 API 和 Codex 中，而最早出现的追问之一就是限制问题。这是直接需求，而非理想化设想：低成本模型已经存在，但用户仍缺乏足够的运行时控制和预算透明度，无法干净利落地利用它们。机会：直接。

### 能随工作在不同工具之间流转的可移植知识与记忆

第二个需求同样实际：人们希望上下文能跨会话、跨工具和跨团队成员保留，而不必在每次对话中重新粘贴。[@Argona0x](https://x.com/Argona0x) [重点介绍了](https://x.com/Argona0x/status/2083177190200406368)（24 个赞、6 条回复、969 次浏览、21 次收藏）介绍了 book-to-skill，因为长篇技术知识否则会被困在 PDF 中；[@QCXINT_](https://x.com/QCXINT_) [重点介绍了](https://x.com/QCXINT_/status/2083221218606686442)（8 个赞、3 条回复、179 次浏览、4 次收藏）介绍了 agentmemory，将其定位为本地跨代理记忆引擎；[@DhravyaShah](https://x.com/DhravyaShah) [推出了](https://x.com/DhravyaShah/status/2083257638406803639)（23 个赞、3 条回复、4 次引用、1,426 次浏览、5 次收藏）介绍了 Supermemory MCP，主打带有团队权限的共享上下文。情绪层面也很明显：人们厌倦了反复解释自己，也厌倦了丢失过去有价值的工作。但主导信号仍然是运营层面的，因为这一组中每个保留项目都承诺减少浪费的 token、减少重复解释，或提升过去决策的复用可靠性。机会：竞争激烈。

### 面向代理上下文的信任评分指令与权限系统

随着仓库指引、MCP 资源和共享房间成为常态，人们希望更有力地回答“代理应该信任这里的什么？”这一问题。[@sunglasses_dev](https://x.com/sunglasses_dev) [警告称](https://x.com/sunglasses_dev/status/2083197897647300665)（1 个赞、2 条回复、20 次浏览）指出，只读仓库指引和 MCP 结果并不会自动可信；关联文章展示了指令文件如何将压制报告或转移凭据的指令，偷偷嵌入看似正常的指引中。[@GHchangelog](https://x.com/GHchangelog) [报道称](https://x.com/GHchangelog/status/2083270239085547524)（16 个赞、1,710 次浏览、4 次收藏）介绍了新的团队级模型策略定向；而 [@omarsar0](https://x.com/omarsar0) [指向](https://x.com/omarsar0/status/2083302486819934437)（15 个赞、8 条回复、2,933 次浏览、11 次收藏）下的回复中，QM 立即询问共享频道中的编辑权限如何限定范围。这是一个紧迫性很高的实际需求，因为更丰富的工作流已经到来，但可信来源和权限模型仍然支离破碎。机会：直接。

### 一键发现和安装技能、记忆与远程工具

另一个较为低调但重要的需求是，新出现的这些层应该易于采用。[@perplexitydevs](https://x.com/perplexitydevs) [宣布](https://x.com/perplexitydevs/status/2083314460005916726)（9 个赞、2 条回复、258 次浏览、5 次收藏）介绍了一个远程 MCP 服务器，除了 API key 外无需在本地安装任何东西；[@tom_doerr](https://x.com/tom_doerr) [分享了](https://x.com/tom_doerr/status/2083261094559105431)（2 个赞、832 次浏览、3 次收藏）介绍了 SkillsGate，这是一款面向 20 多个代理的可视化和终端技能管理器。[@Scallop_io](https://x.com/Scallop_io) [发布了](https://x.com/Scallop_io/status/2083196198769291705)（22 个赞、9 条回复、2,752 次浏览）介绍了一个带有明确安装入口的领域包；[@tom_doerr](https://x.com/tom_doerr) [分享了](https://x.com/tom_doerr/status/2082965135052648898)（11 个赞、2 条回复、2,698 次浏览、16 次收藏）介绍了 Supabase Agent Skills 的标准安装路径。这一需求很实际，但竞争程度高于空白市场：已有多个团队意识到，安装配置摩擦如今已经成为一个产品机会。机会：竞争激烈。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 评价 | 优势 | 局限 |

| GitHub Copilot 中的 GPT-5.6 Luna / Terra | 大语言模型 | (+/-) | 在 Copilot 中标价大幅降低；Luna 拥有较大的上下文窗口，适合常规任务和后台工作 | 回复仍抱怨套餐很快耗尽，也不清楚默认路由是否会进入更便宜的模型 |

| GitHub Copilot 应用和堆叠会话 | 编程代理界面 | (+/-) | 支持堆叠会话链、堆叠 PR，以及在应用内一次性合成工具 | 一份报告显示身份验证状态不稳定；用户仍在询问生成的工具如何持久化，以及代理实际使用哪些模型 |

| Supermemory MCP | 记忆 / MCP | (+/-) | 支持跨工具共享上下文、OAuth、项目范围，以及简单的记忆和召回原语 | 回复立即询问后端架构和实际运行形态 |
| agentmemory | 本地记忆引擎 | (+) | 本地优先存储、混合检索、丰富工具及广泛的跨代理支持 | 声称的能力很强，但当前讨论量仍然较小 |
| SkillsGate | 技能管理器 | (+) | 通过桌面和 TUI 界面，在 20 多个代理之间浏览、安装、编辑和同步技能 | 仍处于早期阶段，当天关于实际使用情况的公开讨论有限 |
| Deep Agents | 编排框架 | (+) | 集成子代理、文件系统、Shell 访问、记忆和人在回路控制 | 目前主要是框架层证据，缺乏操作人员的实际案例 |
| QM | 多人代理框架 | (+/-) | 支持共享房间、范围化记忆、权限、文件、定时任务，以及与供应商无关的代理使用 | 回复立即聚焦于共享空间中的权限范围和编辑权 |
| Perplexity 远程 MCP 服务器 | 远程工具端点 | (+) | 通过 API key 访问且无需本地安装，降低了配置摩擦 | 当天的公开证据仅限于公告和文档，缺乏使用报告 |

总体满意度从“有用但运营层面仍然模糊”，到“很有潜力但仍需完善信任和工作流”不等。人们显然愿意混合使用不同界面：在 Copilot 中使用前沿模型完成主要编程工作，使用类似 OpenRouter 的更便宜后端处理成本敏感型任务，通过文档到技能的编译保存持久知识，再通过记忆或 MCP 层在不同工具之间传递上下文。最明显的迁移模式并不是一个模型取代另一个模型，而是团队试图将重复性或后台工作转移给更便宜的模型，同时把昂贵模型留给更困难的推理任务。因此，竞争压力同时来自三个方向：更便宜的模型路由、更好的上下文封装，以及围绕模型构建的低摩擦编排能力。

当天最具特色的项目是 AI Race Coach，因为它把代理工具与一个硬约束的现实世界闭环连了起来：本地车辆遥测、设备端和云端模型，以及实时驾驶员反馈。Glanceboard 则指向了完全不同的方向，说明与 Antigravity 相邻的工作也正在进入环境化家庭软件，而不是始终停留在编程演示里。

当天最密集反复出现的构建模式，是将专业知识封装以供复用。book-to-skill、Supabase Agent Skills、Scallop Skills、SkillsGate 和 Supermemory 都建立在同一假设之上：有价值的代理行为应该可安装、可迁移、可检索，而不是每次会话都从头编写。idea-validation-agents 则将这一模式从技术知识扩展到了构建前的市场判断。

第二种反复出现的模式，是围绕代理构建运行基底。Deep Agents、QM 和 agentmemory 分别处理了这一基底的不同层面：编排、协作式工作区结构和持久化记忆。同一天出现多个独立构建者同时处理这些层面，强烈表明限制因素已不再只是原始生成能力。

## 6. 新动态与值得关注的内容

### GPT-5.4 和 GPT-5.4 mini 将退出 ChatGPT，但不会退出开发者工作流

[@OpenAIDevs](https://x.com/OpenAIDevs) [表示](https://x.com/OpenAIDevs/status/2083301245390143831)（449 个赞、38 条回复、27,118 次浏览、31 次收藏）称，这两个模型将于 8 月 31 日退出登录后的 ChatGPT 界面，但仍可通过 OpenAI API 和使用 API key 的 Codex 会话访问。这一点很重要，因为回复显示，开发者立即从工作流连续性的角度理解了这一变化，而不是从消费者访问的角度理解：关键问题在于编程路径和额度是否仍能保持不变。

### GitHub 增加了面向企业团队的模型策略定向

[@GHchangelog](https://x.com/GHchangelog) [报道称](https://x.com/GHchangelog/status/2083270239085547524)（16 个赞、1,710 次浏览、4 次收藏）称，企业团队现在可以通过定向策略获得可选的 Copilot 模型。关联的 [更新日志](https://github.blog/changelog/2026-07-31-enterprise-teams-model-policy-targeting-in-public-preview) 表示，模型可以被标记为“启用”“禁用”或“可选”，然后按最宽松访问原则授予选定团队。这一点值得关注，因为它把模型选择变成了管理员界面，而不只是终端用户偏好。

### Perplexity 将 MCP 访问转向远程服务模式

[@perplexitydevs](https://x.com/perplexitydevs) [宣布](https://x.com/perplexitydevs/status/2083314460005916726)（9 个赞、2 条回复、258 次浏览、5 次收藏）介绍了一个通过 API key 工作、无需本地安装任何东西的远程 MCP 服务器。[文档](https://docs.perplexity.ai/docs/getting-started/integrations/mcp-server#remote-mcp-server) 明确写出了这一点。这值得关注，因为随着更多团队尝试基于 MCP 的工作流，工具连接的配置门槛正在降低。

### 一次明显的 Copilot 身份验证不一致暴露了可靠性缺口

[@awakecoding](https://x.com/awakecoding) [报道称](https://x.com/awakecoding/status/2083203659488268456)（1 个赞、2 条回复、313 次浏览）称，GitHub Copilot 应用连续 20 分钟认为用户已退出登录，但其自身健康检查仍显示授权正常。这是一个小样本事件，但值得关注，因为它具体呈现了一个故障模式：一个正被推广为更复杂代理工作流中心的界面，仍会出现这类问题。

### 指令文件投毒成为一个明确的信任问题

[@sunglasses_dev](https://x.com/sunglasses_dev) [警告称](https://x.com/sunglasses_dev/status/2083197897647300665)（1 个赞、2 条回复、20 次浏览）称，仓库指令文件和 MCP 上下文不应仅仅因为它们是在只读审查流程中加载的，就被视为可信。关联的 [分析](https://sunglasses.dev/blog/agent-instruction-file-poisoning?utm_source=x&utm_medium=social&utm_campaign=github_copilot_skill_trust_jul31&utm_content=az_personal_post) 介绍了嵌入 `AGENTS.md`、`CLAUDE.md` 和 `.github/copilot-instructions.md` 等看似正常文件中的恶意模式。这一点值得关注，因为它为当天更广泛的信任与权限讨论提供了一个具体的攻击模型。

## 7. 机会在哪里

**[+++] 面向编程代理的预算感知路由与配额控制** —— 多个部分的证据都指向同一缺口：GitHub 对 Luna 和 Terra 的降价、Burke Holland 的费率截图、OpenAI 在 API 与 ChatGPT 之间的模型界面拆分，以及 Kimi 与 Claude 的成本比较。团队需要一个运行时，能够把子任务路由到更便宜的通道，用通俗语言解释支出，并将昂贵模型保留给困难部分。

**[+++] 可信的可复用上下文层** —— book-to-skill、Supabase Agent Skills、Scallop Skills、Supermemory MCP、agentmemory 和 SkillsGate 的存在，都说明持久化知识仍然过于脆弱，且反复重建的成本过高。最强的机会并不只是抽象意义上的“记忆”，而是可移植、检索成本低、易于安装，并且能够以可验证的安全方式消费的上下文。

**[++] 共享代理工作中的策略、权限与来源追踪** —— 团队模型定向、QM 的权限问题、Copilot 的身份验证不一致，以及 Sunglasses 对指令投毒的分析，都表明更丰富的工作流正在超越其控制平面。对于能够让管理员和操作人员清楚理解模型访问、文件权限、指令信任和可审计性的产品，这里存在中等但紧迫的机会。

**[++] 远程工具与技能分发基础设施** —— Perplexity 的远程 MCP 服务器和 SkillsGate 的跨代理安装器指向同一个机会：如今的生态需要在多个代理界面之间轻松发现、安装、更新和撤销工具与技能。机会程度为中等，因为已有多个构建者注意到了这一点，但用户需求十分明确。

**[+] 在 IDE 之外证明价值的特定领域代理套件** —— AI Race Coach、Glanceboard 和 idea-validation-agents 表明，最令人印象深刻的项目并不是通用编程演示，而是拥有明确工作流、产物和终端用户的领域套件。这是一个正在形成的机会，因为模式已经显现，但当天的案例仍然较早期且相互异质。

## 8. 要点

1. **更便宜的模型，让讨论从能力转向了路由和治理。** GitHub 对 Luna 和 Terra 的降价，立即引发了关于后台任务路由、套餐耗尽和团队模型访问权限的讨论，而不仅仅是对原始智能的兴奋。（[来源 1](https://x.com/github/status/2083261791363363273)、[来源 2](https://x.com/burkeholland/status/2083203891055731048)、[来源 3](https://x.com/GHchangelog/status/2083270239085547524)）
2. **对开发者而言，工作流连续性如今比消费者界面的连续性更重要。** OpenAI 关于 GPT-5.4 和 GPT-5.4 mini 的公告之所以重要，主要是因为这两个模型仍会保留在 API 和 Codex 中，而回复中的开发者最关心的正是保留这条路径。（[来源](https://x.com/OpenAIDevs/status/2083301245390143831)）
3. **可复用上下文正在成为独立的产品层。** 当天最强的一组项目，关注的是将文档转化为技能、封装领域指引，或在不同工具之间传递记忆，而不是推出新的原始模型封装。（[来源 1](https://x.com/Argona0x/status/2083177190200406368)、[来源 2](https://x.com/tom_doerr/status/2082965135052648898)、[来源 3](https://x.com/DhravyaShah/status/2083257638406803639)）
4. **提示词循环之上的代理界面正在明显变厚。** 堆叠会话、多人工作室、生成的内部工具和远程 MCP 端点都指向同一个未来：真正有用的产品是围绕模型构建的工作区，而不只是一次模型调用。（[来源 1](https://x.com/kdaigle/status/2082917875531272279)、[来源 2](https://x.com/omarsar0/status/2083302486819934437)、[来源 3](https://x.com/perplexitydevs/status/2083314460005916726)）
5. **信任与可靠性正在成为一等采用障碍。** 公开的指令文件投毒分析，以及 Copilot 身份验证状态不一致的报告，都表明更丰富的代理工作流仍然会在来源追踪和基础设施层面出问题，而不仅仅是模型质量问题。（[来源 1](https://x.com/sunglasses_dev/status/2083197897647300665)、[来源 2](https://x.com/awakecoding/status/2083203659488268456)）
