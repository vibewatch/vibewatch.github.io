# Twitter AI 编程 - 2026-11-11

## 1. 大家在讨论什么

### 1.1 智能体从生成代码转向实时验证 (🡕)

两场产品演示让智能体直接面对渲染后的界面，而不再只依赖生成代码。[@antigravity](https://x.com/antigravity) [描述了](https://x.com/antigravity/status/2120556423474028576)（1,105 个赞、62 次转发、81 条回复、21 条引用、40,884 次浏览、177 次收藏）展示了借助浏览器进行研究、编程和实时验证的能力；用户可以自行选择登录哪些网站，下载操作则会暂停，等待批准。[Google 浏览器文档](https://antigravity.google/docs/browser) 区分了面向个人账户推出的内置浏览器功能，以及 IDE 和 CLI 中通过本地 Chrome 访问浏览器的方式；企业账户、远程智能体和 SSH 工作区无法使用内置浏览器。

[@GuyInACube](https://x.com/GuyInACube) [演示了](https://x.com/GuyInACube/status/2120533374779453904)（16 个赞、3 次转发、3 条回复、1,069 次浏览、18 次收藏）展示了 Power BI Desktop Bridge 截取屏幕截图并重新加载 Desktop 的过程；演示中的智能体把一份蓝色报告说成了粉色。作者特别提醒，能看到报告并不代表报告中的数值正确，也不代表报告回答了利益相关方的问题。

**与前一天相比：** 11 月 10 日的讨论围绕 Antigravity 多智能体预览版和新模型的访问权限展开。今天最明显的新进展是验证浏览器和桌面状态，同时明确了权限要求和可用范围。

## 2. 令人沮丧的问题

### 智能体的报告与实际呈现结果可能不一致

**严重程度：对受影响的任务而言较高；这些帖子并未说明此类问题的普遍程度。** 退款智能体可能会声称已退款，实际上却没有调用相应工具；一款 Power BI 智能体则把蓝色报告描述成粉色。StoryHelm 的构建者还报告了文件被放到错误分支、迁移重复、分析结果丢失，以及破坏性替换等问题。这些例子涉及客户操作、视觉输出和代码库状态，因此，仅有整洁的对话记录或全绿的测试结果，并不能让发帖者确信工作结果正确。（[Plurai 评估示例](https://x.com/_avichawla/status/2120557010605445223)（25 个赞、2 次转发、26 条回复、1,841 次浏览、14 次收藏）；[Power BI Bridge 示例](https://x.com/GuyInACube/status/2120533374779453904)（16 个赞、3 次转发、3 条回复、1,069 次浏览、18 次收藏）；[StoryHelm 账号](https://x.com/StoryHelm/status/2120587229672485072)（2 个赞、2 条回复、15 次浏览）。）

### 并行工作可能增加清理和审查的负担

**严重程度： 中等。** 一篇关于 Antigravity `/swarm` 的帖子将问题概括为理清五份彼此冲突的代码变更；StoryHelm 的账号则举出了具体例子：多个会话共用了错误的分支，还创建了相互冲突的迁移。文中提到的应对办法包括通过工作树隔离、明确文件归属、设置测试门槛和进行代码审查，但 StoryHelm 表示，更严格的流程让一个只涉及单项测试的修复耗时 38 分钟。（[Antigravity swarm 账号](https://x.com/kweinmeister/status/2120579432775614553)（3 个赞、1 次转推、5 条回复、204 次浏览、3 次收藏）；[StoryHelm 账号](https://x.com/StoryHelm/status/2120587229672485072)（2 个赞、2 条回复、15 次浏览）。）

### 可用性和长时间运行表现并不一致

**严重程度：中等，依据是个别用户的报告。** 有人回复 Antigravity 的浏览器公告称，自己的账号不符合使用条件；Google 的文档也说明，内置浏览器仅适用于特定账号和工作区。在 Cloudflare 的讨论串中，用户询问长时间运行能否在对象休眠后继续，以及长时间活跃运行会产生多少费用；现有讨论并未解答这些问题。（[Antigravity 浏览器讨论串](https://x.com/antigravity/status/2120556423474028576)（1,105 个赞、62 次转推、81 条回复、21 条引用、40,884 次浏览、177 次收藏）；[Cloudflare Codex 讨论串](https://x.com/CloudflareDev/status/2120408689035399442)（283 个赞、18 次转推、17 条回复、12 条引用、16,428 次浏览、123 次收藏）。）

## 3. 人们期待的功能

### 跨设备恢复编码会话

一条回复在 Cloudflare 的讨论串中提出，希望 Codex 运行期间合上笔记本电脑后，还能在另一台设备上用同一段对话和同一批文件继续工作（[回复](https://x.com/justice_note/status/2120427146556715468)（1 个赞、360 次浏览））。**需求：** 让长任务能够持续进行。**紧迫程度：中等。机会类型：竞争性。** Durable Object 存储是一种有状态的实现方式，但文中提到的实验性测试框架本身并未证实已有成熟完善的跨设备客户端。

### 明确托管运行的生命周期和费用

其他回复询问，Codex 长时间运行能否在对象休眠后继续，以及按活跃时长计费与使用一台小型常开机器相比如何（[关于休眠的问题](https://x.com/somi_ai/status/2120449818908856350)（1 个赞、250 次浏览）；[关于成本的问题](https://x.com/SuperLucas0755/status/2120437944792268854)（395 次浏览））。**需求：** 在将工作迁移到托管运行环境前，明确任务能否持续运行以及费用是多少。**紧迫程度：中等。机会类型：直接。** 这些问题在发布讨论串中清晰可见，但没有得到解答。

### 按任务及其子代理追踪用量

一位用户询问 Clepso 能否识别哪些任务及子代理消耗了上下文；作者回复称可以（[问题](https://x.com/jacewbuilds/status/2120462863705981116)（1 个赞、9 次浏览）；[作者回复](https://x.com/TheObiLeonard/status/2120463132468621680)（27 次浏览））。**需求：** 按任务追踪成本和上下文用量。 **紧迫性：中。机会：竞争：** Clepso 的早期 macOS 应用已能报告用量消耗速度和会话详情，而这段交流则明确提出了查看任务级别细分数据的需求。

Plurai 的文档称，其框架会模拟并预置代理调用的系统，让测试能够验证操作，而不必写入线上系统。上图展示了一个客户支持代理，其接入 12 个线上系统界面，并使用 16 个模拟工具；这是实现层面的证据，并非独立的性能测试结果。

Cloudflare 的截图将 `CodexHarness`、`Workspace`、`Sessions`、`Tasks` 和 `Streams` 接入一个 Durable Object。其文档称这些 API 仍属实验性功能，并将生命周期恢复列为独立容器框架的一项功能。

StoryHelm 的构建者表示，仅靠书面说明无法避免这些失误；钩子阻止了某些命令，测试和审查者则检查了已提交的修改。DSH Game Studio 的帖子称，生成图像需要 API 密钥或已登录的 Codex CLI，并会显示预估费用供审批；如果没有这些凭据，它就会使用代码绘制角色。

这些项目的共同做法是：先让代理接入现有环境，再针对影响重大的操作增加隔离、审查或明确审批。这些示例针对的是不同问题；相关帖子并未显示有多个独立团队在构建同一款产品，也未能证明性能存在差异。
