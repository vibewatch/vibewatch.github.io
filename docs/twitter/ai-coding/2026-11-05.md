# Twitter AI Coding - 2026-11-05

## 1. What People Are Talking About

### 1.1 Antigravity is adding notebook and remote workflows (🡕)

Two product updates in the day's posts extend Antigravity beyond local code editing: native notebook viewing, voice input, and cloud-hosted agent sessions. The official v2.29 changelog lists all three; its remote-agent documentation says sessions run in a Google-managed environment and are gradually rolling out to personal Google AI Pro and Ultra accounts.

[@antigravity](https://x.com/antigravity) [announced](https://x.com/antigravity/status/2118234632801910871) (493 likes, 27 replies, 25,411 views; 68 bookmarks) that `.ipynb` files now render code cells, Markdown, tables, images, and cell outputs inside the file viewer. [@testingcatalog](https://x.com/testingcatalog) [reported](https://x.com/testingcatalog/status/2118089695443714458) (186 likes, 25 replies, 11,135 views; 27 bookmarks) the changelog's voice mode and remote-agent rollout. Google's [v2.29 changelog](https://antigravity.google/docs/changelog#rel-hub-2.29.0) confirms the feature list and gradual rollout; the [remote-agent documentation](https://antigravity.google/docs/remote-agents/) specifies the eligible plans and account types.

**Discussion insight:** One reply says the notebook viewer works; others ask whether it runs notebook cells and request a Gemini notebook connection. The changelog promises rendering, not execution. The rollout is gradual, and a reply asks whether voice can redirect an agent mid-task.

**Comparison to prior day:** The previous day's report emphasized Google's large Fortran-to-Rust migration demonstration. Today's items turn toward everyday workflow surfaces: inspecting notebooks, speaking to an agent, and continuing work in the cloud. ([Google Labs write-up](https://blog.google/innovation-and-ai/models-and-research/google-labs/fortran-to-rust-antigravity/))

### 1.2 Model choice is shifting toward routing and local execution (🡕)

GitHub presented Copilot Fusion as a router that selects models and execution patterns; Microsoft separately described running a coding model locally through Copilot. These are distinct approaches to model choice, and the local-inference evidence is vendor-reported rather than an independent benchmark.

[@github](https://x.com/github) [described](https://x.com/github/status/2118431920295989588) (100 likes, 27 replies, 14,633 views; 29 bookmarks) Fusion's Single, Cascade, and Critique patterns and said users choose an effort level rather than a model for each task; the post also advertised a 30% discount through November 30. GitHub's [documentation](https://docs.github.com/en/copilot/concepts/models/copilot-fusion) explains that Fusion routes by task and effort. The attached diagram shows the three execution paths:

![Diagram of Copilot Fusion's Single, Cascade, and Critique execution patterns](https://pbs.twimg.com/media/HWYumsZXcAAjkHa.jpg)

[@QwenAIFans](https://x.com/QwenAIFans) [shared](https://x.com/QwenAIFans/status/2118421584948113601) (6 likes, 2 replies, 808 views; 4 bookmarks) a throughput chart for Foundry Local and Qwen3.8-27B connected to Copilot. The linked [Microsoft Foundry post](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/) says the RTX 5090 test used a 32 GB card and a 4-bit model of about 18 GB; across prompt lengths from 4K to 260K, Microsoft's reported generation speeds were 1.36x to 1.95x those of llama.cpp. Microsoft says 24 GB of VRAM supports context up to 64K, while 32 GB or more supports longer contexts up to 262K, so the 260K result should not be read as a 24 GB result. The vendor also notes that local models may have weaker reasoning than advanced cloud models.

![Microsoft-reported Foundry Local versus llama.cpp generation-speed chart across 4K to 260K prompt lengths](https://pbs.twimg.com/media/HWYlJ7bbIAA0CEh.jpg)

[@TeksEdge](https://x.com/TeksEdge) [transcribed](https://x.com/TeksEdge/status/2118440717928612147) (68 likes, 6 replies, 4,923 views; 78 bookmarks) the same Microsoft figures and cautioned that the comparison is with llama.cpp, not every optimized runtime, and that the baseline configuration needs clarification. This is a second post about the same vendor benchmark, not an independent replication.

**Discussion insight:** Two replies to GitHub's Fusion announcement say the feature remains expensive or consumes more credits despite the announced discount. Microsoft's post supplies the primary source for Foundry's figures; its measurements do not establish how other inference engines would compare.

### 1.3 Project coordination and user control remain open workflow questions (🡒)

One Copilot Projects discussion and one Postman integration thread show concrete requests for better context management and clearer control over changes to developer tools. Both are individual discussions, not evidence that these issues affect most users.

Replies request cloud-defined project setup, scoped context and memory, cost analytics, session management, and cross-project tools; Boggan says cloud-native projects and project tools are being worked on.

The post includes a screenshot of the reported change and a second image of a Postman staff response saying it would be reversed and redesigned with more user control.

![Screenshot accompanying the report about an automatically added Postman integration](https://pbs.twimg.com/media/HWWZQm3XkAAgHRx.jpg)

## 2. What Frustrates People

### Unexpected integrations and weak user control

**Severity: Medium.** In one thread, [@Pirat_Nation](https://x.com/Pirat_Nation) [reported](https://x.com/Pirat_Nation/status/2118342578383057220) (72 likes, 23 replies, 7,114 views; 7 bookmarks) that a Postman desktop update added an integration to coding tools without asking first. The post includes Postman's stated plan to reverse and redesign the change; replies call the behavior unwanted, and one user says they encountered it. No prevalence estimate is supported. The announced reversal is the only explicit remedy in this discussion. This points to a user-control need, but one thread is not enough to establish a broad market.

### Model access and eligibility are unclear in one reported case

**Severity: Medium for the affected user; confidence: Low.** [@bebuu_ai](https://x.com/bebuu_ai) [reported](https://x.com/bebuu_ai/status/2118247644841599422) (91 likes, 11 replies, 11,449 views; 22 bookmarks) that users on an Indian Jio Google AI Pro promotion saw a recurring six-hour warning beside Gemini 4 Argon models in Antigravity and alleged that the plan's access had changed. The screenshot confirms a warning in the model picker, but does not establish the timer behavior or Google's plan policy; no independent confirmation is present. The author's specific complaint is that the interface should state eligibility clearly. No workaround is documented.

![Antigravity model picker screenshot showing a warning beside Gemini 4 Argon](https://pbs.twimg.com/media/HWWG_BXacAAUgHA.png)

### Copilot Fusion cost and credit use

**Severity: Low to Medium.** Two replies to [@github](https://x.com/github)'s [Fusion announcement](https://x.com/github/status/2118431920295989588) (100 likes, 27 replies, 14,633 views; 29 bookmarks) say that the feature is expensive or consumes more credits despite the announced 30% discount through November 30. The comments identify a concern with cost visibility and control, but do not quantify spend or show how common the experience is. No workaround or detailed pricing comparison appears in the discussion.

## 3. What People Wish Existed

### Projects with shared, scoped context

The Copilot Projects discussion contains a concrete request for project definitions that connect code and knowledge repositories, instructions, and scoped memory. [@OrenMe](https://x.com/OrenMe) [spelled out](https://x.com/OrenMe/status/2118103139047907421) (1 like, 1 reply, 207 views) that wishlist in a reply to the [Projects thread](https://x.com/pierceboggan/status/2118101171361501518) (71 likes, 12 replies, 3,149 views; 23 bookmarks). [@pierceboggan](https://x.com/pierceboggan) [responded](https://x.com/pierceboggan/status/2118104458781507815) (1 like, 1 reply, 199 views) that cloud-native projects accessible from Copilot surfaces and project tools were being worked on. The same thread includes a request for better session management and for finding completed work.

**Opportunity rating: Direct.** The feature requests are explicit and the product author says related work is underway; the discussion does not establish how many users need each capability.

### Save and queue prompts while agents are busy

[@JamesMontemagno](https://x.com/JamesMontemagno) [shared](https://x.com/JamesMontemagno/status/2118417623641882763) (5 likes, 1 reply, 623 views) Parked Prompts, a preview for VS Code and Copilot Canvas that saves prompts with files or images, restores them unsent, and can queue them in Canvas. The post quotes a request from a developer who wants to draft and save a prompt with attachments while other agents are busy. The [project page](https://jamesmontemagno.github.io/parked-prompts/) says queued prompts are sent one at a time while the canvas stays open.

**Opportunity rating: Competitive.** A preview tool already addresses this narrowly; the evidence supports demand for prompt handoff, not broader adoption or a need for a separate product.

### Clearer model access and effort controls

The Jio-promotion post explicitly asks for model eligibility to be labeled clearly, while replies to GitHub's [Fusion announcement](https://x.com/github/status/2118431920295989588) (100 likes, 27 replies, 14,633 views; 29 bookmarks) include requests for command-line selection and a personal effort-level control. [@ciano_dowd](https://x.com/ciano_dowd) [asked](https://x.com/ciano_dowd/status/2118468467800392037) (12 views) for an effort slider and [@nwp](https://x.com/nwp) [asked](https://x.com/nwp/status/2118470858230386895) (5 views) when command-line control would be available.

**Opportunity rating: Aspirational.** Clear eligibility, effort, and usage controls recur across two products, but the requests are few and no common implementation or measured impact is established.
