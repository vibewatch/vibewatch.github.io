# Twitter AI 编程 - 2026-04-11

## 1. 人们在讨论什么

### 1.1 速率限制收紧波及所有供应商（🡕）

当天的主导话题是：所有主要 AI 编程供应商都在同时收紧使用限制，开发者正忙着设法适应。

[@HarshithLucky3](https://x.com/HarshithLucky3) [发布了互动量最高的帖子](https://x.com/HarshithLucky3/status/2043038717317910640)（722 个赞，6.8 万次浏览）：“Google 先降低了 Pro 用户的 Antigravity 速率限制。接着 Anthropic 对 Claude 网页版/应用版和 Claude Code 做了同样的事。现在，OpenAI 也在 Codex 上这么做了。”在每月 100 美元套餐推出后，Plus 用户称自己的可用额度只剩下此前的大约三分之一。[@cepvi0](https://x.com/cepvi0) 回复说，Google 最早这么做，所以“大家都忘了”，随后注意力转向了 Anthropic 之后的削减。[@Alaric4678](https://x.com/Alaric4678) 则问 GitHub Copilot 会不会是下一个，并认为开源模型是“唯一的解决方案”。

这个预测当天就应验了。[@douglascamata](https://x.com/douglascamata) [指出](https://x.com/douglascamata/status/2043104475280294060) 指出，GitHub Copilot 发布了一条更新日志——“实施新限制并从 Copilot Pro+ 中下线 Opus 4.6 Fast”——引入了高级请求配额：Pro（10 美元/月）每月 300 次，Pro+（39 美元/月）每月 1,500 次，超额部分按每次请求 0.04 美元收费；前沿模型的倍率从 1x 到 50x 不等。他称这是“高明的模糊发帖，用来避免反弹”，因为帖子没有给出新旧限制的具体对比。[@SPARKSERiAN](https://x.com/SPARKSERiAN) [记录了时间点](https://x.com/SPARKSERiAN/status/2043040208409477240)：“我刚还在说，在 OpenAI 和 Anthropic 都推出那种 5 小时限制之后，GitHub Copilot 套餐是现在最好的选择……结果就出了这事。”

[@andacgvn](https://x.com/andacgvn) [分享了一张截图](https://x.com/andacgvn/status/2043088063803379947) 分享了 Reddit 帖子《Anthropic 让 Claude 变笨了 67%，却没告诉任何人：一名开发者运行了 6,852 次会话来证明这一点》。数据相当惊人：共分析了 17,871 个 thinking block，推理深度下降了 67%；每次会话读取的文件数从 6.6 个降到 2 个；三分之一的编辑是在根本没读取文件的情况下完成的；输出中 “simplest” 一词的出现次数增加了 642%。Anthropic 的 Boris Cherny 将此归因于一项“自适应思考”功能：它原本旨在为简单任务节省 token，却错误地把困难问题也一起限流了。尽管用户反对，该问题仍被关闭。

[@rvtond](https://x.com/rvtond) [制作了一个桌面小组件](https://x.com/rvtond/status/2043112109722996846) 做了一个同时追踪 Claude、OpenRouter、Amplify 和 Codex 速率限制的工具——“不用再刷新 27 个浏览器标签页了”。组件截图显示，一名开发者正在同时消耗五家供应商的额度，其中 Claude 已用到当前周期限制的 42%，Codex 为 21%。

### 1.2 开源模型与预算叠加成为应对方式（🡕）

速率限制收紧正直接推动开发者通过聚合服务转向开源模型。

[@mhdcode](https://x.com/mhdcode) [阐明了价值逻辑](https://x.com/mhdcode/status/2043039620519145613)（240 个赞，172 次收藏）：“10 美元的 OpenCode Go + 10 美元的 GitHub Copilot = 约等于 80 美元价值的用量。”已确认 OpenCode Go 首月 5 美元，之后 10 美元/月；它按消费设置限制（12 美元/5 小时、30 美元/周、60 美元/月），可使用 GLM-5、GLM-5.1、Kimi K2.5、MiMo-V2-Pro、MiMo-V2-Omni、MiniMax M2.5 和 MiniMax M2.7。[@Wayland_Six](https://x.com/Wayland_Six) 回复询问 OpenCode 是否支持其他模型网关，[@mhdcode](https://x.com/mhdcode) 确认可以通过 opencode.json 配置实现。

[@andacgvn](https://x.com/andacgvn) [发布了一份全面的定价指南](https://x.com/andacgvn/status/2043088063803379947) 为希望逃离速率限制挤压的开发者整理了一份方案。内容涵盖六种替代服务：OpenCode Go（10 美元/月）、Xiaomi MiMo Token Plans（6-100 美元/月，分层额度池）、MiniMax Token Plans（10-50 美元/月，最高档每 5 小时最多 30,000 次请求）、Chutes（3-20 美元/月）、Novita Coding Plans（19.90-199.90 美元/月，RPM 保证最高 450）、Alibaba Cloud Coding（50 美元/月，每 5 小时 6,000 次请求）以及 Z AI GLM Plans（10-80 美元/月）。

[@gubatron](https://x.com/gubatron) [直接发声支持](https://x.com/gubatron/status/2043114427688616267)：“真正的好朋友不会眼看着你用 Claude 4.6 Sonnet，却不提醒你通过 OpenRouter 在 OpenCode harness 里切到 GLM-5.1。编程和工具使用的智能水平差不多，但价格只要零头。”他估计开源模型目前落后 2.2-2.5 个月，并预测除非 Anthropic 和 OpenAI 在价格上展开竞争，否则开源模型会赢。

[@robinebers](https://x.com/robinebers) [批评了 Z AI 的定价](https://x.com/robinebers/status/2043101066875801734) 专门谈了 GLM-5.1：18 美元/月的 Lite 套餐速度慢、限制低；跳到 72 美元/月的 Pro 又过于陡峭；而 160 美元/月的 Max 看起来更不合理，因为 OpenCode Go 只要 10 美元/月就能提供同一个模型。

![Z AI 定价页面显示：Lite 为 $18/月，Pro 为 $72/月，Max 为 $160/月，均可访问 GLM-5.1](https://pbs.twimg.com/media/HFqNlydakAAv7Lc.jpg)

[@ardadev](https://x.com/ardadev) [为生态作出了贡献](https://x.com/ardadev/status/2043085512404021476) 通过把 Kilo Code gateway 的全部模型同步到 models.dev 数据库，让它们能在 OpenCode 中工作，起步是为 GLM-5.1 提交 PR。

### 1.3 Harness 层正在成为真正的产品（🡒）

还有一条相对安静、但在结构上很重要的讨论线索：AI 编程工具的价值，正在从模型本身转向周边基础设施。

[@brunoborges](https://x.com/brunoborges) [演示了](https://x.com/brunoborges/status/2043105483289137461)（79 个赞）解释了为什么 GitHub Copilot 的价值主张在于 agent harness，而不是某一个单独模型。他的截图展示了 Copilot 的 issue 分配对话框，里面有模型选择器（Claude Opus 4.6）和 agent 下拉菜单，列出三个内置 agent（Copilot、Claude、Codex）以及自定义 agent（Agentic Workflows、OpenGrep Autofix Agent）。“我为什么要订阅 GitHub Copilot？因为你能用上三个 CLI Runner 的 agent harness。”

![GitHub Copilot 代理分配界面，显示 Copilot、Claude 和 Codex 代理，以及带有 Claude Opus 4.6 模型选择器的自定义代理](https://pbs.twimg.com/media/HFqRm1HakAMtMGh.jpg)

[@VeritasDYOR](https://x.com/VeritasDYOR) [分析了 Claude Code npm 源码泄露事件](https://x.com/VeritasDYOR/status/2043113713071178215)：512,000 行 TypeScript，在 24 小时内完成 clean-room 重写，并拿下 10 万个 GitHub Star（史上最快）。他的架构图对比了大多数开源工具当前的重点——从发现（MCP/API 聚合）到模型推理再到执行的薄封装——以及 Claude Code 源码所揭示的“生产栈”：在发现层和模型之间，存在一个庞大的 harness 层，负责工具沙箱、上下文管理、错误恢复、权限控制、状态检查点和子代理编排。

![架构图对比了薄封装方案与 Claude Code 中包含 51.2 万行代码的生产级 harness 栈](https://pbs.twimg.com/media/HFqXfTNWsAAh4f_.jpg)

[@samsaffron](https://x.com/samsaffron) [具体说明了 harness 差距](https://x.com/samsaffron/status/2043114497791943092) 通过比较 Claude Code 与 Gemini CLI 的表格渲染来说明这一点。Claude Code 会把结构化数据（一个团队花名册）渲染成格式正确、列对齐、间距合理的 ASCII 表格；而 term-llm 展示同样数据时，对齐很差，换行也处理失败。“Claude Code 的表格渲染实现非常用心——里面有很多小细节，比如空间不够时会折叠表格，并改用不同的渲染方式。”

![并排对比：Claude Code 渲染出整洁对齐的表格，而 Gemini CLI 的列对齐则已损坏](https://pbs.twimg.com/media/HFqZzxUWcAAHuXD.jpg)

[@RNR_0](https://x.com/RNR_0) [提出了经济层面的问题](https://x.com/RNR_0/status/2043079655859654918)：“Claude 用 API 时贵得离谱。只能用他们的 Claude Code 或聊天产品，而他们很可能是在巨额亏损运营。Codex 便宜，而且和 Hermes、OpenClaw 等配合得很好。”这把 harness 层描绘成一种用来把用户留在生态里的亏本引流品。

## 2. 什么让人沮丧

### 同步下调速率限制（高）

所有主要供应商——Google（Antigravity）、Anthropic（Claude Code）、OpenAI（Codex），以及现在的 GitHub Copilot——都在同一时期下调了使用限制，给人一种协调一致、集体劣化的观感。[@HarshithLucky3](https://x.com/HarshithLucky3) 用 [获得 722 个赞同](https://x.com/HarshithLucky3/status/2043038717317910640) 记录了这一模式。各平台的 Plus 档用户都表示，在相同价格下，可用量只剩下原来的约三分之一。100 美元/月的套餐，实际上是在重新定价过去 20 美元/月所能获得的额度。

### 隐性质量下降（高）

Claude Code 的“自适应思考”事件（[由 @andacgvn 分享](https://x.com/andacgvn/status/2043088063803379947)）反映出更深层的不满：供应商在悄悄削弱模型能力。一名开发者运行了 6,852 次会话、分析了 17,871 个 thinking block，量化出 67% 的推理深度下降。Anthropic 直到数据被公开发到 GitHub 上后才承认这个 bug。尽管用户反对，该问题仍被关闭。[@cousinvanko](https://x.com/cousinvanko) [总结了这种情绪](https://x.com/RNR_0/status/2043079655859654918)：“这些公司都该把精力放在别让模型发布两个月后就把思考能力和智能炸到地狱里去。”

### 定价不透明与档位宰客（中）

多家供应商对相同的底层模型给出了差异极大的价格。GLM-5.1 通过 OpenCode Go 只要 10 美元/月，但在 Z AI 的 Pro 档，为了更快访问就要 72 美元/月。[@robinebers](https://x.com/robinebers) [称这一价格“离谱”](https://x.com/robinebers/status/2043101066875801734)。问题在于，行业里没有统一基准来说明“更快”或“更高限制”在实际中到底意味着什么，因此用户很难真正横向比较。

### 多供应商切换的额外负担（中）

[@rvtond](https://x.com/rvtond) [做了一个小组件](https://x.com/rvtond/status/2043112109722996846) 专门做了一个工具，因为要同时追踪五家以上供应商的用量，得刷新 27 个浏览器标签页。这种操作负担——管理多个订阅、API key、限速窗口和计费周期——本身就在吞噬生产力；而在过去，一个订阅就够用时，这种问题根本不存在。

## 3. 人们希望出现什么

### 统一的速率限制与成本仪表盘

[@rvtond](https://x.com/rvtond) 做了一个原型，但开发者真正需要的是成熟的跨供应商仪表盘：既能追踪用量、预测何时触顶，又能实时把请求自动路由到当前最便宜的可用供应商。小组件方案适合监控，但缺乏能真正优化支出的路由智能。

### 透明的模型质量指标

Claude Code 那次 67% 的质量下降，直到有用户跑了数千次会话才被发现。没有哪家供应商会持续公布其编程模型的质量指标。开发者希望有第三方基准测试服务，持续监测模型在真实编程任务上的表现，并在性能回退时发出告警。

### 面向前沿模型的 OpenCode 式 Harness

[@gubatron](https://x.com/gubatron) 和 [@mhdcode](https://x.com/mhdcode) 都认为 OpenCode 是当前性价比最高的选择，但它目前只适用于开源模型。开发者希望获得同样的 harness 灵活性——与模型无关、与供应商无关、支持本地配置——同时在开源模型处理复杂任务力有不逮时，也能切换到前沿模型（Claude Opus 4.6、GPT-5.4）。

### 标准化的供应商价格比较

[@andacgvn](https://x.com/andacgvn) 手动整理了六家供应商的价格对比。理想状态下，这应当是一个持续维护、可搜索的数据库，并采用标准化指标：每次请求成本、每个 token 成本、每个时间窗口可发出的请求数、模型可用性，以及延迟保证。

## 6. 新鲜且值得关注的动态

### Claude Code 源码泄露，暴露出 512K 行的 Harness 基础设施

[@VeritasDYOR](https://x.com/VeritasDYOR) [分析了](https://x.com/VeritasDYOR/status/2043113713071178215) 讨论了 Claude Code 源码因一次失败的 npm 发布而泄露所带来的影响。这 512,000 行 TypeScript 在 24 小时内被 clean-room 重写，并迅速积累了 10 万 GitHub Star——速度创下 GitHub 历史纪录。这里最重要的架构启示在于：生产级编程 agent 需要在工具发现与模型推理之间加入一层庞大的 harness，负责工具沙箱、上下文管理、错误恢复、权限控制、状态检查点和子代理编排。大多数开源替代品都只是薄封装，几乎完全跳过了这一层。

### GitHub Copilot 引入高级请求配额

GitHub [发布了](https://github.blog/changelog/2026-04-10-enforcing-new-limits-and-retiring-opus-4-6-fast-from-copilot-pro/) 于 4 月 10 日引入新的速率限制，推出“高级请求”这一配额单位。Pro 用户（10 美元/月）每月有 300 次高级请求，Pro+（39 美元/月）每月有 1,500 次，超额部分按每次 0.04 美元收费。高级模型带有最高 50x 的倍率，这意味着一次 Claude Opus 4.6 交互就可能消耗每月 300 次额度中的 50 次。Opus 4.6 Fast 模式也已从 Pro+ 中下线。至此，这轮全行业收紧已完整成形：Google、Anthropic、OpenAI，如今再加上 GitHub，都在相隔数周内下调了限制。

### Hermes Agent 达到 7.7 万 GitHub Star，完整自托管方案成形

由 [@nesquena](https://x.com/nesquena) 发布的 Hermes Agent [对比页面](https://nesquena.github.io/hermes-webui/)，将自托管 agent 定位为一种综合解法：持久化记忆以本地 Markdown 文件保存，支持 cron 调度实现自主任务，内置 47 个工具，接入 15+ 消息渠道（Telegram、Discord、Slack、WhatsApp、Signal、Matrix 等），还可以把 Claude Code 或 Codex 作为子 agent 启动。它拥有 7.7 万+ GitHub Star，采用 MIT 许可，代表着目前最成熟的开源替代方案之一，可对抗供应商锁定的编程 agent。[@cgarciae88](https://x.com/cgarciae88) [演示了](https://x.com/cgarciae88/status/2043110461613412779) 则展示了如何在 OpenCode 中用 Gemini Flash Light 实时调试并修复 Hermes 的 WhatsApp gateway。

![Hermes Agent 落地页：开源、自托管、MIT 许可，具备持久记忆和自主调度能力](https://pbs.twimg.com/media/HFqb3WracAAz4be.jpg)

### OpenCode Go 成为预算敏感型开发者的默认选择

10 美元/月即可使用 GLM-5.1、Kimi K2.5、MiMo-V2-Pro、MiniMax M2.5 和 MiniMax M2.7，OpenCode Go 正迅速成为预算敏感型开发者的默认推荐。多位彼此独立的用户（[@mhdcode](https://x.com/mhdcode)、[@gubatron](https://x.com/gubatron)、[@robinebers](https://x.com/robinebers)）得出了相同结论：通过 OpenCode 使用开源模型，可以以远低于前沿模型的成本，获得相近的编程质量。

## 7. 机会在哪里

**[+++] Strong: Cross-Provider Usage Management and Smart Routing.** Every developer in today's dataset manages multiple AI coding subscriptions with different rate windows, pricing models, and billing cycles. [@rvtond](https://x.com/rvtond) 已经做出了监控小组件；下一步就是智能路由：根据实时配额状态、任务复杂度和模型能力，自动把请求发往当前最便宜的可用供应商。这是一个独立于任何单一供应商的工具层问题。（[rvtond widget](https://x.com/rvtond/status/2043112109722996846)、[mhdcode budget stacking](https://x.com/mhdcode/status/2043039620519145613)）

** 独立的模型质量监测与回归告警也存在明显机会：供应商不会持续公开质量指标，市场需要第三方长期跟踪真实编程任务表现的服务。（[+++］ 强：持续的模型质量监测。** Claude Code 67% 的性能退化事件表明，服务商会悄然降低模型质量，而目前并不存在独立监测机制。一个能够在标准化任务上持续对编程模型性能进行基准测试——追踪推理深度、代码正确性、文件读取模式和思维 token 使用量——并发布回归预警的服务，将同时为开发者和评估服务商可靠性的企业采购团队提供价值。(［andacgvn Reddit data](https://x.com/andacgvn/status/2043088063803379947)）

** 混合式工作流同样有空间：让开源模型承担日常任务，把前沿模型留给复杂边缘场景，从而兼顾成本与能力。（[++］ 中等：开源 Harness 基础设施。** Claude Code 的生产级 harness 与典型开源薄封装之间 51.2 万行代码的差距，如今已被公开记录。那些在开源模型之上构建生产级 harness 层——上下文管理、错误恢复、状态检查点、子代理编排——的项目，可能获取目前仍锁定在专有编程代理内部的价值。Hermes Agent 是目前最接近的参与者，但其重点在通用代理工作流，而非纯编程。(［VeritasDYOR architecture analysis](https://x.com/VeritasDYOR/status/2043113713071178215)、[samsaffron table rendering comparison](https://x.com/samsaffron/status/2043114497791943092)）

**[++] Moderate: Standardized AI Coding Provider Marketplace.** [@andacgvn](https://x.com/andacgvn) 手动整理了六家供应商的价格。一个持续维护的对比平台，如果能提供标准化指标——每次请求成本、每美元可得 token 数、每个时间窗口的请求数、模型可用性、延迟和质量基准——就能显著减少目前由开发者个人承担的调研负担。（[andacgvn pricing guide](https://x.com/andacgvn/status/2043088063803379947)、[robinebers pricing critique](https://x.com/robinebers/status/2043101066875801734)）

**[+] Emerging: Model-Agnostic Agent Harnesses with Frontier Fallback.** The current ecosystem bifurcates: OpenCode/Hermes for open-source models, Claude Code/Copilot for frontier models. A harness that defaults to cheap open-source models but seamlessly escalates to frontier models for complex tasks -- with cost guardrails and quality thresholds -- would capture the developer workflow [@gubatron](https://x.com/gubatron) 描述的，正是一种工作流：开源模型处理常规工作，前沿模型处理边界情况。（[gubatron on GLM-5.1 parity](https://x.com/gubatron/status/2043114427688616267)）

## 8. 要点总结

1. **速率限制收紧是全行业同步发生的。** Google、Anthropic、OpenAI 和 GitHub 都在数周内收紧了限制。20 美元/月档位如今只能提供约为六个月前三分之一的额度，而 100 美元/月套餐则重新买回了原本的配额。这不是临时调整，而是结构性重定价。（[HarshithLucky3](https://x.com/HarshithLucky3/status/2043038717317910640)、[douglascamata on Copilot](https://x.com/douglascamata/status/2043104475280294060)）

2. **开源模型是这轮变化的最大受益者。** 通过 OpenCode Go 以 10 美元/月使用 GLM-5.1、Kimi K2.5 和 MiMo-V2-Pro，已经成为多位独立实践者的一致推荐；他们认为其编程质量可与前沿模型相比，而成本只占一小部分。开源模型的能力差距被估计在 2.2-2.5 个月，并且还在缩小。（[mhdcode](https://x.com/mhdcode/status/2043039620519145613)、[gubatron](https://x.com/gubatron/status/2043114427688616267)）

3. **护城河在 harness 层，而不在模型本身。** Claude Code 泄露出的 512K 行 TypeScript 基础设施——工具沙箱、上下文管理、错误恢复、状态检查点——代表的是多年工程积累，不是薄封装的开源工具短期内能复制的。GitHub Copilot 的价值主张也明确在于多 agent harness，而不是某个单独模型。（[brunoborges](https://x.com/brunoborges/status/2043105483289137461)、[VeritasDYOR](https://x.com/VeritasDYOR/status/2043113713071178215)）

4. **隐性质量下降仍是尚未解决的信任问题。** 一名开发者不得不跑 6,852 次会话，才证明 Claude Code 的推理深度下降了 67%。供应商只在受到公开压力后才承认问题，而目前并不存在独立监测服务。对于需要可靠性保证的企业团队来说，这会成为采购障碍。（[andacgvn](https://x.com/andacgvn/status/2043088063803379947)）

5. **多供应商套利已经成为新的开发者工作流。** 重度用户如今同时管理五个或更多 AI 编程订阅，在不同限速窗口和定价模型之间做优化。由此产生的运营负担——追踪配额、切换上下文、管理 API key——本身又在催生六个月前还不存在的新工具需求。（[rvtond](https://x.com/rvtond/status/2043112109722996846)）

6. **自托管 agent 提供了逃离挤压的路径。** 拥有 7.7 万 GitHub Star 的 Hermes Agent，代表着一种成熟替代方案：开发者掌控自己的基础设施，选择自己的模型，不必承受外部强加的速率限制。代价是运维复杂度，但随着供应商限制持续收紧，这种权衡正变得越来越划算。（[nesquena](https://x.com/nesquena/status/2043116759125983720)）
