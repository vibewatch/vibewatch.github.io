# Twitter AI 编程动态 - 2026-07-08

## 1. 人们在讨论什么

### 1.1 基准测试讨论变得更看重价格，也更缺乏信任（🡕）

围绕模型的讨论更热，也更难形成共识。`grok` 的提及量从 7 月 7 日的 4 次升至 37 次，`codex` 则从 69 次升至 104 次。但更重要的变化在于争论焦点：人们讨论的不再只是赢家是谁，还包括单项任务成本，以及排行榜本身是否仍然可信。这一天既有 Grok 基准成绩的大幅跃升，也有 GPT-5.6 将于周四发布的倒计时，还有 OpenAI 自己发出的警告——一个被广泛引用的编程基准部分已经失真。

[@ArtificialAnlys](https://x.com/ArtificialAnlys) [报道称](https://x.com/ArtificialAnlys/status/2074956932289282087)（740 个赞，57 条回复，700,585 次浏览，112 次收藏）称，Grok 4.5 在 Artificial Analysis Intelligence Index 上达到 54 分，在 Grok Build 的 Coding Agent Index 上达到 76 分；在编程方面已与 Codex 中的 GPT-5.5 持平，但使用的 token 更少、成本也更低。回复进一步给出了更具体的运营数据：Grok 4.5 每项编程任务的成本为 2.49 美元，Codex 中的 GPT-5.5 为 5.07 美元，Claude Code 中的 Fable 5 则为 11.80 美元。于是，成本效率不再只是基准叙事里的附带信息，而成了核心组成部分。

![Artificial Analysis 基准图表，对比 Grok 4.5、GPT-5.5 和 Fable 5 在 coding-agent 得分与成本方面的表现](https://pbs.twimg.com/media/HMu5OK1XgAAUFaY.jpg)

[@mark_k](https://x.com/mark_k) [表示](https://x.com/mark_k/status/2074756801384284485)（154 个赞，16 条回复，4,234 次浏览）称，GPT-5.6“Sol、Terra、Luna”将于周四正式登陆 Codex 和 ChatGPT，这也解释了模型对比类帖子为何明显加速。与此同时，[@fanofaliens](https://x.com/fanofaliens) [放大了这一观点](https://x.com/fanofaliens/status/2074982837946867735)（2 个赞，23 次浏览，2 次收藏）提到 OpenAI 的警告：SWE-Bench Pro 已不再可靠，因为约 30% 的任务存在问题，原因包括测试过于严格、提示语模糊、测试覆盖率低或提示具有误导性。

**讨论洞察：** 同一时间线里，一边在庆祝 Grok 的性价比跃升，一边也在传播 OpenAI 对基准测试的审计结果。这让部分讨论从“哪个模型最好”转向了“哪些衡量指标仍值得信任”。

**与前一天相比：** 7 月 7 日的讨论主要是对 GPT-5.6 的初步期待，以及规模较小的 Grok 话题。到了 7 月 8 日，基准测试的经济性和质量成了模型讨论的中心。

### 1.2 Copilot 不再只是一个应用，而成了需要监控、充满政策约束的操作界面（🡕）

Copilot 的讨论热度依旧很高，但重点已从发布消息转向运营控制。面向所有套餐的桌面应用公告仍是核心，不过更值得关注的后续话题是浏览器代理工具、移动端会话跟踪、企业托管遥测，以及通过 skills 实现的实际自动化。人们不再只是问 Copilot 是否可用，而是越来越关心它将如何被监督、路由和治理。

[@github](https://x.com/github) [宣布](https://x.com/github/status/2074574687942946819)（198 个赞，16 条回复，39,931 次浏览，106 次收藏）称，GitHub Copilot 应用现已向所有套餐开放，也支持自带密钥模式。[@code](https://x.com/code) [随后报道](https://x.com/code/status/2074943855967821851)（102 个赞，10 条回复，12,482 次浏览，29 次收藏）则介绍了 VS Code 的一次更新：新增浏览器代理工具、Agents 窗口预览、BYOK 模型发现和编辑器内成本可视化。回复认为，成本可视化才是最有意义的部分，因为人们已经在不清楚花费的情况下盲跑代理循环。

[@GHchangelog](https://x.com/GHchangelog) [补充说](https://x.com/GHchangelog/status/2074897571093344561)（5 个赞，930 次浏览，4 次收藏）称，GitHub Mobile 现在会为远程 Copilot CLI 会话显示实时通知；[还宣布](https://x.com/GHchangelog/status/2074973070637379893)（6 个赞，720 次浏览，2 次收藏）则介绍了面向 VS Code 和 Copilot CLI 的企业托管 OpenTelemetry 导出功能。抓取到的更新日志明确显示了发展方向：通过手机监控状态、接收等待输入提醒，以及由管理员控制导出端点、请求头，以及是否允许采集提示词、响应和工具内容。

[@brunoborges](https://x.com/brunoborges) [指出](https://x.com/brunoborges/status/2074888055446516102)（6 个赞，401 次浏览，3 次收藏）介绍了 GitHub Blog 的一篇实操文章：Copilot CLI 配合一个 Namecheap skill，在约 14 分钟内把一个公开仓库部署成使用自定义域名和 HTTPS 的 GitHub Pages 网站，而且无需手动编辑 DNS 记录。这比“生成代码”更偏向实际运维场景，也符合当天更广泛的趋势：让代理处理繁琐的平台基础工作。

**讨论洞察：** 回复较少关注访问权限，更多聚焦控制能力。BYOK、支出可见性和企业遥测策略之所以引发共鸣，是因为用户已经默认需要路由模型、监控成本，并审查代理宿主正在输出什么。

**与前一天相比：** 7 月 7 日的核心是面向所有套餐的 Copilot 应用发布。7 月 8 日，这一叙事进一步延伸到治理、手机端监督和基础设施自动化。

第四个讨论簇传递出的信息是：模型已经不再等于整个产品。路由器相关话题的提及量从 5 次以上升至 12 次，多个项目也发布或放大了针对特定代理失效模式的补丁层：配额耗尽、代码库搜索开销、空白项目初始化、文档难以阅读，以及只能通过终端远程访问。大家的共同假设是，如今的生产力不仅取决于模型本身，也同样取决于模型外层的那一圈基础设施。

## 3. 人们希望存在的东西

### 跨供应商和额度边界的原生连续性

人们希望，当某个模型、配额或资助额度耗尽后，会话仍能继续。[@FareaNFts](https://x.com/FareaNFts) [想要](https://x.com/FareaNFts/status/2074916115902603578)（25 个赞，7 条回复，4,550 次浏览，29 次收藏）描述了一个可在 237 家供应商和 90 多个免费层之间滑动切换的网关；[@xmangonic](https://x.com/xmangonic) [想要](https://x.com/xmangonic/status/2074759742921068974)（4 个赞，1 条回复，193 次浏览，3 次收藏）反映出人们希望更清楚地看到重置时间，以避免浪费 Codex 用量；[@MengTo](https://x.com/MengTo) [想要](https://x.com/MengTo/status/2074671084163698876)（60 个赞，11 条回复，9,407 次浏览，45 次收藏）则反映出人们希望 Claude Code 和 Codex 能为开源工作提供有意义的额度。这是现实需求，不是理想化愿景；而今天的局部解法仍分散在资助计划、BYOK 和第三方路由器之间。机会：直接。

### 能保留正确需求和仓库知识的持久上下文

## 4. 正在使用的工具和方法

| 工具 | 类别 | 评价 | 优势 | 局限 |
|---|---|---|---|---|
| Grok Build 中的 Grok 4.5 | 模型 + 测试框架 | (+/-) | 编程代理基准成绩强劲，单项任务成本低，token 效率高 | 基准测试的可信度正受到新一轮审视，公开的实际上手证据仍然有限 |
| GitHub Copilot 应用 / VS Code 代理栈 | IDE / 桌面代理界面 | (+/-) | 所有套餐均可访问、BYOK、浏览器代理工具、成本可视化、移动端监控 | 今天仍暴露出仓库/工作树异常、有害工作流行为和端点警报冲突 |
| Google Antigravity / Managed Agents | 代理平台 | (+) | 自然语言 skills、后台任务、远程 MCP、托管沙箱、凭证刷新 | 今天的许多证明仍是教程或引导式演示，而非长期生产案例 |
| Spec Kit | 规格优先工作流 | (+) | 将规格、计划和任务转化为可执行的开发流程 | 部分用户认为规格优先会增加负担，或是“披着 AI 外衣的瀑布式开发” |
| OmniRoute | 路由网关 | (+) | 通过一个端点连接 237 家供应商，提供配额回退、token 压缩及 MCP/A2A 支持 | 增加了一个需要维护的本地层，并依赖质量参差不齐的供应商 |
| CodeGraph | 代码智能索引 | (+) | 本地图谱减少重复搜索、工具调用和 token 消耗 | 需要建立索引，并为每个项目增加一次集成步骤 |
| claude-mem | 记忆层 | (+/-) | 持久化跨会话记忆、本地存储、渐进式披露 | 配置更复杂，而且记忆本身无法修复糟糕的需求或错误的仓库上下文 |
| Agentic Awesome Skills | 技能库 | (+) | 为 Copilot、Claude Code、Cursor、Codex 和 Antigravity 提供可复用、可安装的工作流 | 增加了用户需要整理和筛选的目录层 |
| agentic-seo | 文档审计 CLI | (+) | 揭示文档对代理而言是否可读、可发现、可负担 | 能暴露缺口，但不会自动解决文档质量问题 |
| TailClaude | 浏览器 / 移动代理界面 | (+/-) | 支持二维码/浏览器访问、会话历史和实时成本仪表盘，无需 SSH | 需要再信任一个封装层，并通过 tailnet 或公网将其暴露出去 |

满意度呈现出两个层次的分化。在模型层面，Grok 4.5 因为在公开编程基准中显得高效而获得好评，而 GPT-5.6 仍主要停留在期待阶段，尚缺少多少实际使用报告。在工作流层面，人们持续奖励那些能消除路由、记忆、规格、搜索、文档或远程访问摩擦的工具，例如 [@FareaNFts](https://x.com/FareaNFts) [推送到](https://x.com/FareaNFts/status/2074916115902603578)（25 个赞，7 条回复，4,550 次浏览，29 次收藏）的 OmniRoute、[@rohanpaul_ai](https://x.com/rohanpaul_ai) [推送到](https://x.com/rohanpaul_ai/status/2074675705162653816)（27 个赞，10 条回复，4,286 次浏览，22 次收藏）的 Spec Kit，以及 [@Suryanshti777](https://x.com/Suryanshti777) [推送到](https://x.com/Suryanshti777/status/2074767860212347387)（9 个赞，4 条回复，595 次浏览，2 次收藏）的 CodeGraph。

最常见的应对方式是叠加，而不是迁移。人们没有放弃自己偏好的代理，而是在其上增加 BYOK、供应商路由器、记忆插件、skills、文档审计工具或浏览器外壳。这让竞争态势不再是“从工具 A 切换到工具 B”，而是“保留工具 A，再补上缺失的基础设施”。
