### 1.2 可靠性、配额和上下文管理，仍是惊艳演示与日常使用之间的落差（🡕）

关于配额和可靠性的抱怨明显升级。`quota` 提及量升至 31，高于 9 月 14 日的 21，约为上周均值 15.3 的两倍。最强烈的抱怨已不再是笼统的价格焦虑，而是关于容量故障、强制压缩，以及支持渠道无法解释实际情况的具体报告。

**与前一日对比：** 9 月 14 日，讨论重点是指令和路由开销；到 9 月 15 日，这些问题转化为对容量错误、强制压缩，以及真实工作场景中支持不透明的更强烈愤怒。

### 1.3 Copilot 正向上延伸到工作跟踪、实时干预和 PR 审查（🡕）

Copilot 的讨论重点不再是模型本身的质量，而是提示框之上的编排界面。`copilot` 提及量从 9 月 14 日的 23 升至 28；值得注意的更新，集中在如何让任务、提问和审查都留在同一个工作界面中。

**讨论洞察：** 回复并没有否定这些功能，而是在要求更清晰的入口：更容易发现画布、更便捷地针对选中文本提问、更轻量的应用性能，以及更少的隐藏步骤。

**与前一日对比：** 9 月 14 日强调路由和供应商选择；到 9 月 15 日，竞争界面上移了一层，开始围绕哪些任务正在进行、能否中断、能否审查，以及哪些环节在等待人工处理展开。

## 2. 什么让人感到沮丧

### 不透明的配额和静默压缩，让高级套餐显得不可信

最强烈的挫败感并不是高级编程代理需要付费，而是用户在工作开始后不再信任限制机制。[@MmuzTW](https://x.com/MmuzTW) [描述了](https://x.com/MmuzTW/status/2099779773736370357)（154 个赞、27 条回复、13,063 次浏览）描述了一个体验变差、受容量限制、且无法通过官方渠道解释清楚的 Pro 20x 账户。[@Soso_fun_yt](https://x.com/Soso_fun_yt) [新增了](https://x.com/Soso_fun_yt/status/2099921193474342973)（61 个赞、11 条回复、6,783 次浏览）从技术角度提出了同一问题：模型可能宣传很大的上下文窗口，但 harness 仍能通过激进的压缩策略抹去这一优势。[@rodydavis](https://x.com/rodydavis) [确认了](https://x.com/rodydavis/status/2099930512303555007)（131 个赞、20 条回复、4,921 次浏览）提到 Antigravity 中 Gemini 3.8 Flash 的一起实时故障，使这种痛点显得具有系统性，而非个别案例。

![私信线程截图，显示一次带有线程 ID 的反馈上传，以及之后一次未获回复的跟进](https://pbs.twimg.com/media/HSPonsobgAAUhtL.png)

严重程度为高，因为问题关乎运行层面的信任，而不只是价格。用户觉得自己即使付费获得访问权限，也可能在运行中途被困住，却得不到关于原因的诚实解释。值得构建程度：高。

### 有用的工作流界面仍然摩擦过大

第二个挫败点是，许多正确的功能确实已经上线，但仍需要用户反复摸索，或依赖过多周边机制。[@pierceboggan](https://x.com/pierceboggan) [展示了](https://x.com/pierceboggan/status/2099572243240276466)（29 个赞、3 条回复、3,171 次浏览）介绍 Copilot 中的 Jira 画布，但回复立即提到无效的 Jira 数据，以及让代理先把该界面打开本身就很别扭。[@burkeholland](https://x.com/burkeholland) [展示了](https://x.com/burkeholland/status/2099604401312694576)（46 个赞、6 条回复、2,413 次浏览）表示，`/ask` 可以有效打断运行，但回复仍希望支持针对选中文本提问，并抱怨应用过于臃肿。[@VisualStudio](https://x.com/VisualStudio) [将其描述为](https://x.com/VisualStudio/status/2099875891899768906)（10 个赞、3,482 次浏览）将 PR 审查与 Copilot 交接整合为一个流程，方向明确，但仍绑定于特定宿主界面。[@paolino](https://x.com/paolino) [认为](https://x.com/paolino/status/2099865252238131629)（7 个赞、363 次浏览）则直接提出反例：简单的 issue 分诊不应要求 2,000 行 agentic YAML 和昂贵模型；一个小型 Ruby action 配合 GPT-5.6-Luna 就能完成。

严重程度为中高，因为需求显然真实存在，但当前方案往往显得过度复杂，或难以发现。值得构建程度：高。

### 提示注入和沙箱逃逸已从理论变成具体图示与补丁级修复

安全讨论异常具体。[@_orcaman](https://x.com/_orcaman) [分享了](https://x.com/_orcaman/status/2099856720176546300)（33 个赞、10 条回复、1,333 次浏览）列出了两种有名称的 Codex 逃逸技术——Overpatch 和 Heapjack，以及修复版本门槛。[@gossy_84](https://x.com/gossy_84) [展示了](https://x.com/gossy_84/status/2099876923530760430)（2 条回复、77 次浏览）说明，被动提示注入如何藏在 GitHub issue 的 HTML 注释中，最终仍可能导致 token 外泄。[@DataScienceDojo](https://x.com/DataScienceDojo) [认为](https://x.com/DataScienceDojo/status/2099927360459985170)（2 个赞、3 条回复、490 次浏览）指出，“跳过权限”实际上只是加速手段；如果底层没有更强的沙箱，它会扩大影响范围。

严重程度为高，因为这些案例已经具体到可以直接采取行动：明确的利用机制、明确的补丁版本，以及明确的边界主张。值得构建程度：高。

## 3. 人们希望存在什么

### 覆盖套餐、模型和溢出路径的透明预算与路由控制

用户显然希望拥有 Copilot 刚刚推出的那种路由旋钮，同时还要配套真实的配额状态和官方认可的溢出通道。[@MmuzTW](https://x.com/MmuzTW) [希望](https://x.com/MmuzTW/status/2099779773736370357)（154 个赞、27 条回复、13,063 次浏览）希望高级套餐不会静默降级；[@markfenner](https://x.com/markfenner) [强调了](https://x.com/markfenner/status/2099848905105997949)（10 个赞、3 条回复、473 次浏览）体现了明确路由偏好的价值；[@MrTacticalX](https://x.com/MrTacticalX) [分享了](https://x.com/MrTacticalX/status/2099987516392624371)（5 个赞、34 次浏览）展示了 Claude Code 中的备用容量方案；[@AileLabs](https://x.com/AileLabs) [主打](https://x.com/AileLabs/status/2099755678948556851)（22 个赞、3 条回复、2,123 次浏览）则提供了绕开高级模型价格的市场路径。这一需求务实且紧迫。机会：直接。

### 能展示压缩策略，并允许用户自行权衡取舍的长上下文代理

数据反复表明，开发者想要的不只是更大的理论上下文窗口。他们想知道 harness 何时会压缩、会丢弃什么，以及能否用速度换取连续性。[@Soso_fun_yt](https://x.com/Soso_fun_yt) [制作了](https://x.com/Soso_fun_yt/status/2099921193474342973)（61 个赞、11 条回复、6,783 次浏览）通过 256k 与 1M 的对比明确提出了这一需求；[@thtbee_](https://x.com/thtbee_) [展示了](https://x.com/thtbee_/status/2099566404546769397)（34 个赞、6 条回复、3,367 次浏览）则表明，Antigravity 已经暴露出足够多的运行时结构，可以更诚实地呈现这些信息。[@0xBoomz](https://x.com/0xBoomz) [提供了](https://x.com/0xBoomz/status/2099922584967971254)（2 个赞、1 条回复、173 次浏览）提供了压缩层方案，但更强烈的未满足需求，是让 harness 本身原生具备透明度。机会：直接。

### 易于中断、检查并可跨任务延续的工作区

Copilot 应用的更新指向一个真实需求：用户希望看到正在进行的工作，在运行中提问，附加 PR 或 issue 上下文，并在之后重新进入同一任务，而无需从头开始。[@github](https://x.com/github) [推出了](https://x.com/github/status/2099931978498007147)（48 个赞、4 条回复、27,153 次浏览）对应“我的工作”；[@burkeholland](https://x.com/burkeholland) [演示了](https://x.com/burkeholland/status/2099604401312694576)（46 个赞、6 条回复、2,413 次浏览）对应 `/ask`；[@VisualStudio](https://x.com/VisualStudio) [展示了](https://x.com/VisualStudio/status/2099875891899768906)（10 个赞、3,482 次浏览）则是 PR 审查与 `#pullrequest` 交接。在这一技术栈之外，[@xunio98](https://x.com/xunio98) [认为](https://x.com/xunio98/status/2099677078257799627)（2 条回复、31 次浏览）指出，agentic 编程需要的是运行时，而不是另一个聊天面板，并将 [herdr](https://github.com/herdrdev/herdr) 视为持久化层。这一需求务实且已有部分解决方案，因此机会是竞争性的，而非假设性的。机会：竞争。

### 默认安全的执行边界，而不是基于信任的“跳过权限”

人们不想永远手动管理审批，但也不希望安全性取决于精心设计提示词。[@gossy_84](https://x.com/gossy_84) [展示了](https://x.com/gossy_84/status/2099876923530760430)（2 条回复、77 次浏览）展示了被动提示注入所需的用户可见行为有多么少；[@_orcaman](https://x.com/_orcaman) [展示了](https://x.com/_orcaman/status/2099856720176546300)（33 个赞、10 条回复、1,333 次浏览）表明，即使是成熟的编程代理界面，也可能出现真实的逃逸问题；[@DataScienceDojo](https://x.com/DataScienceDojo) [认为](https://x.com/DataScienceDojo/status/2099927360459985170)（2 个赞、3 条回复、490 次浏览）则要求更坚固的容器加 microVM 边界。这是一项务实且紧迫的需求。机会：直接。

### 衡量工具调用耐久性，而不仅是显存占用的本地模型与 harness 匹配

本地模型的话题仍然很容易被过度简化。[@akshay_pachaar](https://x.com/akshay_pachaar) [展示了](https://x.com/akshay_pachaar/status/2099857657872122108)（18 个赞、8 条回复、3,799 次浏览）介绍 Magnitude，称其可以分析硬件，并为主流 harness 推荐本地模型；公开的 [Magnitude 仓库](https://github.com/magnitudedev/magnitude) 则将这一方向转化为具体产品。但回复透露了更深层的需求：人们希望了解长时间运行的工具调用、上下文行为和 harness 稳定性，而不仅是模型能否装入内存。因此，这是一个务实但竞争更激烈的细分方向。机会：竞争。
