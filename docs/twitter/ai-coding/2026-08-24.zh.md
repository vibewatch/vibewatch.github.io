## 1. 人们在讨论什么

### 1.1 Agent 工作正转向共享、移动和多模型界面（🡕）

### 1.2 持久化代码库记忆和可复用参考 skills，成为应对上下文浪费的默认手段（🡕）

第二个主题是，人们越来越把反复探索文件视为一个可以解决的系统性问题，而不是 Agent 工作不可避免的成本。相关内容并不是泛泛的提示词包，而是面向代码库、书籍、论文和组织技能的具体编译器与打包层。相比 2026-08-23 当时 skills 层仍以目录和索引为主，2026-08-24 出现了更多明确的上下文引擎，承诺能跨会话保留下来。

### 1.3 治理、读回和 harness 设计，比再做一次原始模型对比更重要（🡕）

第三个主题是，讨论不断从模型上移到流程、权限和审查架构。最有力的证据来自安全工具、正式工作流指导、企业采用图表，以及明确主张 harness 选择可能比模型选择更重要的论文。相比 2026-08-23 当时开放模型排名和切换行为仍占据大量注意力，2026-08-24 的讨论更多聚焦于谁能检查、批准并标准化这些工作。

[@aacle_](https://x.com/aacle_) [解释道](https://x.com/aacle_/status/2091546000951480830)（29 个赞、1,668 次浏览、19 次收藏）解释了他们为何 fork Burp 的官方 MCP 服务器：它基本是单向的。修复清单具体且偏操作层，而非哲学讨论：暂存 Repeater 请求并按名称读回、检查 Intruder 结果、管理扫描、读取站点地图和历史记录、在获批后使用 scope 和 cookie jars，并通过实时 Burp 仪表板呈现所有信息。这篇帖子读起来就像一份压缩过的需求文档，说明严肃的领域集成目前仍然缺少什么。

[@dair_ai](https://x.com/dair_ai) [分享了](https://x.com/dair_ai/status/2091896571730493746)（7 个赞、2 条回复、1,094 次浏览、6 次收藏）介绍了一篇论文 [Applying Anthropic Primitives at Large Enterprises](https://arxiv.org/abs/2608.20622)。其摘要认为，前沿模型降低了编写定制代码的成本，却没有降低审查、理解和维护碎片化定制方案的成本。论文提出的答案，是在不同部署之间采用稳定的 harness 主干；作者还明确把其中一个关键主张概括为：“在 Agent 基准测试结果中，harness 选择造成的差异比模型选择更大。”

[@techyoutbe](https://x.com/techyoutbe) [提到了](https://x.com/techyoutbe/status/2091903735379202401)（7 个赞、2 条回复、1,044 次浏览、3 次收藏）介绍了 AWS 的 [AI-DLC 2.0](https://github.com/awslabs/aidlc-workflows) 和配套的 [AWS 概览](https://aws.amazon.com/blogs/devops/ai-driven-development-life-cycle/)，两者都描述了同样的人在回路中的节奏：AI 制定计划、提出澄清问题，并只在验证后才实施。这一点很重要，因为官方工作流措辞明确强调的是可验证、可自我纠正的工程，而不是无人观察的自主运行。

![AI-DLC 2.0 公告，展示了一个可验证、可自我纠正且包含人工审核环节的工程工作流](https://pbs.twimg.com/media/HQfs4WyaYAAbTMK.jpg)

[@rickyho_1989](https://x.com/rickyho_1989) [分享了](https://x.com/rickyho_1989/status/2091690491461132689)（6 个赞、7 条回复、980 次浏览、3 次收藏）展示了一张图表，图中标注数据来源为 OAI Signals：法律行业每周活跃的企业 Codex 用户相较 2 月基数增长了 108 倍，而销售和招聘增长 41 倍，工程领域增长 5 倍。正确的解读应当是图表本身显示的指数化增长，而不是作者更具推测性的劳动力市场外推：公开信号表明，人们如今正把 Agent 采用视为更广泛的知识工作基础设施，这也抬高了标准化审查和治理层的价值。

**讨论洞察：** 共同主线并不是“哪个模型赢”，而是“当更多团队和领域开始使用 Agent 后，什么能让人类检查、批准、路由并标准化这些工作？”

**与前一天对比：** 2026-08-23，治理问题主要通过追踪工具和对单向 MCP 的抱怨浮现。到了 2026-08-24，这些问题扩展到了正式工作流准则、企业采用图表，以及 harness 设计本身正在成为差异化因素的明确主张。

### 1.4 Codex 的信任度有所提升，但价格、政策和故障表现仍在推动用户切换（🡒）

Codex 仍是单一最大话题，但讨论的质地已经变了。相较前一天，Codex 的提及量依然很高；然而，最有力的新证据不再是另一篇根因复盘，而是现实使用中是否已经能看到修复效果、竞争方案看起来便宜或灵活多少，以及当服务提供商或模型层级出问题时，用户应当多快切换到备用方案。相比 2026-08-23，讨论从诊断 bug 转向了检验修复后的真实表现。

## 2. 什么让人感到沮丧

### 单向集成和迁移折腾仍在打断严肃工作

这是一个高严重度挫折，因为最有力的例子来自已经在接近生产环境的工作流中使用 Agent 的人，而不是初学者。[@aacle_](https://x.com/aacle_) [表示](https://x.com/aacle_/status/2091546000951480830)（29 个赞、1,668 次浏览、19 次收藏）表示，官方 Burp MCP 服务器可以发送请求，却无法把响应读回来、检查 Intruder 结果或管理扫描，因此他们自己做了 fork 和实时 Burp 仪表板。[@CodexReleases](https://x.com/CodexReleases) [报道称](https://x.com/CodexReleases/status/2091929016194289782)（88 个赞、7 条回复、7,260 次浏览、16 次收藏）表示 `codex mcp-server` 已被弃用，改由 app server 和 Claude Code 插件取代；回复区随即充满脚本失效的抱怨，以及要求提供更好迁移链接的声音。

同样的摩擦也出现在较新的界面里。[@OpenAIDevs](https://x.com/OpenAIDevs) [即将上线](https://x.com/OpenAIDevs/status/2091995301397893501)（156 个赞、13 条回复、16,878 次浏览、71 次收藏）下的一条回复称，语音驱动的移动工作流会让确认机制更严格，而不是更宽松；[@DanKornas](https://x.com/DanKornas) [介绍了](https://x.com/DanKornas/status/2092014887962554680)（1 个赞、349 次浏览）则把 [Kandev](https://github.com/kdlbs/kandev) 当作对另一个问题的回应：如何审查 5 个并行的 Agent 任务。人们正通过替换官方连接器、增加仪表板，或转向以审查为先的控制平面来应对。这看起来值得直接构建。

### 价格、身份验证政策和故障表现持续推动用户在不同技术栈之间切换

### 能运行的软件，仍不等于可信的软件

这是一个中等严重度挫折，因为相关证据数量少于控制平面之争，但例子非常尖锐。[@ozi_bekee](https://x.com/ozi_bekee) [警告说](https://x.com/ozi_bekee/status/2091767462266057017)（5 个赞、3 条回复、50 次浏览）表示，AI 生成的登录流程可以运行得毫无问题，但一旦有人尝试攻破它，仍然可能是不安全的。重点并非理论问题：整个讨论都围绕发布前检查展开，而这些检查超出了“UI 看起来没问题”的范围。
