## 3. 大家希望出现什么

### 默认具备 Token 成本可见性与优化能力

[@InduTripat82427](https://x.com/InduTripat82427) [汇编](https://x.com/InduTripat82427/status/2049894134417326432) 列出 10 个可降低 Token 消耗的仓库（RTK：60%–90%，Context Mode：98%，Token Savior：97%）。开发者需要自己去发现、安装并叠加 2–3 个独立工具来管理 Token 消耗，这一事实本身就说明，这些能力理应内置进代理。当前没有任何编程代理原生提供 Token 预算管理或任务前成本估算。

紧迫性：高。机会：直接——GitHub Copilot 将于 6 月 1 日上线基于用量的计费。

### Codex 在子代理能力上追平 Claude Code

[@aniketapanjwani](https://x.com/aniketapanjwani) [识别出](https://x.com/aniketapanjwani/status/2049661842373451855) 指出三项差距：Codex 最多支持 6 个子代理（Claude Code 为 16 个）；子代理需要用户显式调用（无法自动拉起）；插件不能包含子代理。对于依赖并行分析的代码审查工作流来说，6 个代理的上限是首要瓶颈。

紧迫性：中。机会：直接——这项能力由 OpenAI 自己掌控；重度用户反馈可能加速推进。

### 为代理式工作流自动引导搭建 Worktree 环境

## 7. 机会在哪里

**[+++] Token Budget Management as a Native Agent Feature** -- [@InduTripat82427](https://x.com/InduTripat82427) 的 [汇编](https://x.com/InduTripat82427/status/2049894134417326432)列出了 10 个彼此独立的 Token 优化仓库（RTK：终端输出节省 80%，Context Mode：通过 SQLite 沙箱节省 98%，Token Savior：导航节省 97%），这说明 Token 管理目前仍分散在社区工具之中。随着 GitHub Copilot 将于 6 月 1 日启动按量计费，以及重度用户使用 Codex 时会在 2.5 天内烧完每周限额（aniketapanjwani），原生 Token 预算能力——任务前估算、按分支归因、自动优化——是当下最直接的机会。到 6 月 1 日，每个代理用户都可能成为潜在客户。

**[+++] Agent Skills 市场与发现机制** —— Obsidian Skills（几天内 2.7 万 Star）、andrej-karpathy-skills（总计 10.1 万、单周新增 2.4 万）、Matt Pocock 的工程 skills，以及 awesome-copilot 仓库，都表明可组合 agent skills 的需求正在爆发。目前还没有一个统一市场，能跨 Claude Code、Codex 和 OpenCode 发现、评分、组合这些 skills。`npx skills add` 这种模式已经存在，但发现仍主要靠 Twitter 上的口耳相传。

**[++] Visual Workspace for Agentic Coding** -- [@nimbalyst](https://x.com/nimbalyst) 的 [开源发布](https://x.com/nimbalyst/status/2049849943133749541)提供 Markdown、原型图、图表和 diff 的可视化编辑器，并可与 Codex、Claude Code、OpenCode 配合使用，正好回应了那个持续存在的抱怨：终端代理缺乏视觉反馈。Codex Desktop App 相比 Claude Code 纯终端界面拥有更好的 UI（aniketapanjwani），这为给任意代理补上一层可视化界面的工具留下了空缺。

**[+] Provider-Agnostic Harness Benchmarking** -- [@caspar_br](https://x.com/caspar_br) 的 [deepagents profiles](https://x.com/caspar_br/status/2049672406260924729)通过按提供商调优 harness，能带来 10–20 分的提升。大多数开发者仍在使用默认配置。如果有工具能针对你的具体代码库，对多种 harness profiles 做基准测试并推荐最优设置，就能捕捉到目前仍需手工试验才能获得的那部分价值。

## 8. 核心结论

1. **微软的 AI 经济性正面临公开的可信度挑战。** [@edzitron](https://x.com/edzitron) 的 [批评](https://x.com/edzitron/status/2049885224738472366)（204 个赞、11,543 次浏览）把叙事从“Copilot 调价”改写成“这笔 3000 亿美元投资当初到底成不成立”。转向基于 Token 的计费，被解读为承认单位经济模型出了问题，而不是一次常规定价更新。这给所有以“摆脱微软锁定”为卖点的替代方案送上了论据。

2. **Codex 正从编程工具转向通用工作平台。** [角色选择器](https://x.com/aakashgupta/status/2049966530822332502)中的角色选择器（从 Engineering 到 Student）、[CLI 0.128.0](https://x.com/fcoury/status/2049917871799636201)中的 /goal 持续目标功能，以及 GPT-5.5 派对，都在说明 OpenAI 正把 Codex 打造成一个横向平台。[@blakeandersonw](https://x.com/blakeandersonw) 的 [计数器](https://x.com/blakeandersonw/status/2049975392841158938)提到 Claude“在第二、三梯队知识工作者中势头强得多”，说明这场竞争争夺的是数量更庞大的非开发者群体。

3. **Agent skills 正在成为新的价值创造层。** Obsidian Skills（2.7 万 Star）、andrej-karpathy-skills（10.1 万 Star、周增 2.4 万）、free-claude-code（周增长 85%）以及 Matt Pocock 的工程 skills，都表明真正的差异化已不再只是“你用哪个模型”，而是“你挂了哪些 skills”。那些 Token 优化仓库（RTK、Context Mode）也说明，skills 正在解决代理本身尚未覆盖的问题。

4. **Harness 工程正在被正式产品化。** [@caspar_br](https://x.com/caspar_br) 的 [deepagents profiles](https://x.com/caspar_br/status/2049672406260924729)（提升 10–20 分），以及 Cursor 按模型分别调 harness（Quan2m2），都在把 harness 优化从黑客文化里的玩法（4 月 29 日的 goblin mode）推向主流工具。现在这个洞见已趋于共识：同样的模型 + 更好的 harness = 明显更好的输出。

5. **Antigravity 的可靠性侵蚀已进入连续第六天。** [@amritwt](https://x.com/amritwt)（161 个赞）、[@TheGlobalMinima](https://x.com/TheGlobalMinima)、[@y_qecea](https://x.com/y_qecea)（14,127 次浏览）以及缺失的 Opus 4.7 模型（luicho9_）都在延续这一模式。20 美元/月的高性价比主张（immasiddx，32 个赞）仍是唯一的辩护，但前提是服务本身必须可用。

6. **Codex 与 Claude Code 的竞争，已经从模型层转向功能层。** [@aniketapanjwani](https://x.com/aniketapanjwani) 的 [详细对比](https://x.com/aniketapanjwani/status/2049661842373451855)（29 个书签）——子代理上限、权限模式、插件架构、环境引导搭建——表明竞争已不再是“哪个模型更会写代码”，而是“哪个 harness 更能处理复杂工作流”。下一波差异化就会发生在这里。
