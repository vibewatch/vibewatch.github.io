# Twitter AI 编程 - 2026-11-17

## 1. 大家在讨论什么

### 1.1 编程代理正被并行编排，但共享状态风险依然明显 🡕

Google 发布的内容展示了 Antigravity 如何协调分工不同的模型：Hydrogen 负责快速分诊并处理问题、修改 UI，Carbon 则负责规模较大的重构、功能开发和安全检查。另一个演示则用代理把 Google Sheets 变成像素画布。这些都是产品演示，并非可靠性对比测试。

[@googledevs](https://x.com/googledevs) [展示 Hydrogen 和 Carbon 处理代码仓库问题与拉取请求](https://x.com/googledevs/status/2122449973300298188)（181 个赞，8 条回复，15,141 次浏览，73 次收藏）。有回复指出，两个代理同时编辑同一个文件可能会发生冲突；还有人建议，让代理通过一个未通过的回归测试交接工作，维护者可以重新运行该测试。

[@GoogleDeepMind](https://x.com/GoogleDeepMind) [演示 Hydrogen 将 Sheets 单元格用作像素画布](https://x.com/GoogleDeepMind/status/2122807824531275826)（370 个赞，43 条回复，21,863 次浏览，52 次收藏）。这条帖子展示的是一种创意界面用法，并非编程基准测试。

### 1.2 技能被视为缩小小模型与大模型差距的一种方式 🡕

一条帖子称，配备技能文件的 Haiku 完成了 84 项任务中的 27.7%，而未配备该文件的 Opus 完成了 22.0%。由于模型和任务指令都发生了变化，这项对比无法单独衡量技能的影响，也不能证明在条件一致时 Haiku 能胜过 Opus。

[@distortgeekin](https://x.com/distortgeekin) [分享了 84 项任务的对比结果](https://x.com/distortgeekin/status/2122668627849613789)（79 个赞，20 条回复，3,690 次浏览，95 次收藏）。有回复询问是否也用同一套技能测试了 Opus；帖子没有提供这一对照。

### 1.3 新模型和路由方案的讨论聚焦于每项编程任务的成本 🡒

Microsoft 发布 MAI Code 2、GitHub 宣布 Copilot Fusion，均介绍了成本更低的替代方案和面向编程任务的模型路由。GitHub 表示，Fusion 会在单模型、级联和评审式方案之间进行选择；其公开文档称，只有任务需要时才会额外调用模型。

[@github](https://x.com/github) [公布了 Copilot Fusion 在 Terminal-Bench 4.1 中的成绩](https://x.com/github/status/2122756587073028306)（35 个赞，9 条回复，6,433 次浏览）。GitHub 声称，在该基准测试中，其问题解决率为 71.2%，成本低于 Fable 5.2 和 Opus 5.5。这是供应商发布的声明，不应将其推广到所述基准测试范围之外。

** 与前一天相比：** 11 月 16 日的报告讨论了容量限制、外部验证和模型编排。今天的内容延续了编排主题，但对模型价格声明和代理并行工作流程着墨更多。

### 1.4 在真实服务环境中测试生成的代码，是部署流程的瓶颈 🡒

一条发布帖称，AWS ECS 的部署可能需要数小时，而代理只需几分钟就能生成代码变更；帖中还介绍了一种方法，可以在不等待完整部署的情况下，用预发布环境流量测试代理编写的代码。同一天还出现了一个小型代理运行框架，要求先通过由父代理编写的验收脚本，才能将工作标记为完成。

[@aviramyh](https://x.com/aviramyh) [宣布推出适用于 ECS 的 mirrord](https://x.com/aviramyh/status/2122699881550594226)（13 个赞，3 条回复，107 次浏览，3 次收藏）。帖子称，代码可以在笔记本电脑或代理沙箱中运行，同时使用选定的预发布环境流量和环境数据；这只是产品介绍，并非独立的性能证据。

## 2. 大家感到不满的地方

### 并行代理编辑共享文件时可能相互冲突

** 严重程度：中等；这是一个具体的故障场景，并非发生率估计。** 有回复在 Google 发布的 Antigravity 演示下提醒说，代理在同一代码仓库中工作时，合并前可能看不到彼此的差异。另一条回复建议用未通过的回归测试作为交接产物，让负责修复的代理和维护者都能验证。（[@googledevs](https://x.com/googledevs/status/2122449973300298188)（181 个赞，8 条回复，15,141 次浏览，73 次收藏））

### 在真实环境中测试所需时间可能超过生成代码的时间

** 对使用 ECS 的团队而言，严重程度为中等；帖子没有提供具有代表性的调查结果。** 一条发布帖称，编写变更只需几分钟，但完整的 ECS 构建、推送和部署流程可能需要数小时。帖子将 mirrord for ECS 介绍为一种无需等待部署完成，就能使用预发布环境流量进行测试的方法。（[@aviramyh](https://x.com/aviramyh/status/2122699881550594226)（13 个赞，3 条回复，107 次浏览，3 次收藏））

### 对比技能时需要匹配的基线

** 严重程度：低；这是评估局限性，证据可信度有限。** 据称进行的 84 项任务对比中，Haiku 使用了技能文件，而 Opus 没有；有回复询问是否用同一套技能测试了两个模型。信息流没有回答这个问题，因此无法判断结果差异究竟来自模型、指令，还是两者兼有。（[@distortgeekin](https://x.com/distortgeekin/status/2122668627849613789)（79 个赞，20 条回复，3,690 次浏览，95 次收藏））

## 3. 大家希望出现什么

### 让代理安全地协同修改同一个代码仓库

Antigravity 演示展示了 Hydrogen 和 Carbon 之间的任务分工，而有回复指出，共享文件冲突仍是一个未解决的问题。建议采用回归测试交接，既能为下一个代理提供明确目标，也能让维护者重新运行测试进行检查。** 紧迫程度：中等。机会： 直接。** ([@googledevs](https://x.com/googledevs/status/2122449973300298188) (181 次点赞，8 条回复，15,141 次浏览，73 次收藏))

### 通过受控对比区分技能与模型的影响

这篇涉及 84 项任务的帖子表明，书面指令可能会显著影响编程表现，但其中的对比并未让不同模型在相同技能条件下接受测试。若能让每个模型使用相同的任务、工具和技能文件进行基准测试，结果将更具可操作性。**紧迫性：中等。机会：直接。** ([@distortgeekin](https://x.com/distortgeekin/status/2122668627849613789) (79 次点赞，20 条回复，3,690 次浏览，95 次收藏))

### 无需完整部署周期的快速真实环境测试

ECS 发布帖介绍了一种做法：使用选定的预发流量测试智能体生成的变更，而不必等待完整部署。这针对的是一个具体的工作流瓶颈，但帖子没有提供独立的延迟或可靠性测量数据。**紧迫性：对 ECS 用户而言为中等。机会：竞争性。** ([@aviramyh](https://x.com/aviramyh/status/2122699881550594226) (13 次点赞，3 条回复，107 次浏览，3 次收藏))

## 6. 新品与亮点

### Copilot Fusion 为每项任务选择模型和执行模式

GitHub 将 Fusion 描述为一种运行时路由器，可根据任务和推理力度设置，选择使用单个模型、带裁判模型的级联，或并行评议。文档称，只有在确有必要时才会增加审查调用；这是产品描述，而另行提及的 Terminal-Bench 结果仍是由提供方报告的基准测试数据。（[Copilot Fusion 文档](https://docs.github.com/en/copilot/concepts/models/copilot-fusion)；[@github](https://x.com/github/status/2122756587073028306) (35 次点赞，9 条回复，6,433 次浏览)）

### MAI Code 2 和 Code 2 Flash 在 Copilot 中正式开放使用

GitHub 表示，这两款 Microsoft 编程模型现已在 Copilot 应用、CLI 和代码编辑体验中提供，并将其中一款定位为适用于更复杂的任务，另一款则面向常规且注重成本效益的工作。（[公告](https://x.com/github/status/2122814155979706846) (23 次点赞，6 条回复，5,234 次浏览)）

## 7. 机遇所在

## 8. 要点

1. **并行编码工作流仍需要共享状态管控机制。** Google 的演示展示了基于角色分工的智能体，而一条回复提醒，共享同一文件可能引发冲突，并指出回归测试可用于检查交接情况。（[Antigravity 演示](https://x.com/googledevs/status/2122449973300298188)（181 个赞，8 条回复，15,141 次浏览，73 个收藏））
2. **技能可能影响结果，但文中引用的比较并非受控实验。** 在报告提及的84项任务中，使用技能的 Haiku 和未使用技能的 Opus 表现不同；但该讨论串没有给出匹配条件下的比较。（[技能对比](https://x.com/distortgeekin/status/2122668627849613789)（79 个赞，20 条回复，3,690 次浏览，95 个收藏））
3. **测试耗时可能成为智能体循环中的主要瓶颈。** 文中将用于 ECS 的 mirrord 介绍为一种测试变更的方法，无需等待完整部署即可在预发布环境中进行测试。（[公告](https://x.com/aviramyh/status/2122699881550594226)（13 个赞，3 条回复，107 次浏览，3 个收藏））
