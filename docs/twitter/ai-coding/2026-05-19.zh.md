# Twitter AI 编程 - 2026-05-19

## 1. 人们在讨论什么

### 1.1 GitHub Copilot 正从助手转向编排者 🡕

今天信息流中最明显的变化，不只是 Copilot 会写代码，而是它获得了更多运行场景、更多任务交接方式，以及更多可监督手段。相比 5 月 18 日围绕远程控制和 hooks 的密集发布，5 月 19 日新增了云端托管的 CI 修复、桌面会话派生、面向移动端的模型上线，以及用户对 Copilot 应用人体工学的最新讨论。

[@code](https://x.com/code) [宣布](https://x.com/code/status/2056460035278962738)（140 个赞，2 条回复，18,463 次浏览）表示，GitHub Copilot CLI 和 `@code` 会话的远程控制现已正式可用。这将 Copilot 描绘成一种可以随时随地监控和审批的对象，而不再是绑定在某个终端窗口里的工具。这个更完整的运行时叙事，在 [@GHchangelog](https://x.com/GHchangelog) [表示](https://x.com/GHchangelog/status/2056506408497996144)（11 个赞，1,069 次浏览）所说的更新中变得更具体：Copilot Business 和 Enterprise 用户现在可以一键让云端代理修复失败的 GitHub Actions 作业。相关更新日志称，Copilot 会在自己的云开发环境中排查问题，将修复推送到分支，并 @ 用户进行审查。

[@jfversluis](https://x.com/jfversluis) [展示了](https://x.com/jfversluis/status/2056646051457536373)（4 个赞，3 条回复，272 次浏览）展示了 Copilot 应用如何在第一个会话内部再拉起第二个会话，为其注入另一个仓库的上下文，并让它独立开始代码搜索。相比泛泛的“多代理”营销，这个说法更扎实，因为截图显示，被派生出来的会话创建了 worktree，并在搜索 MAUI toolbar badge 代码。[@lexrus](https://x.com/lexrus) [补充说](https://x.com/lexrus/status/2056545172679528886)（9 个赞，3 条回复，1,386 次浏览）则提供了一个产品设计视角：先贴出新版 Copilot 应用 UI，又在回复里表示它比 Codex 更卡，尤其是在渲染 Markdown 时。这让桌面应用从抽象的发布话题，变成了可直接比较的体验反馈。

![GitHub Copilot 应用截图，显示一个先规划后执行的工作区，旁边有 Changes、Plan 和 Terminal 窗格，以及生成的任务树](https://pbs.twimg.com/media/HIpP6Ttb0AAHsSg.jpg)

![第二张 Copilot 应用截图，显示一个新启动的 Copilot 会话正在创建 worktree，并在单独的仓库中搜索 MAUI 工具栏徽章代码](https://pbs.twimg.com/media/HIqsrvlXwAAuGDV.jpg)

**讨论洞察：** 即便是支持者的讨论，如今关注的也已不是自动补全的新鲜感，而是编排质量：云端代理的叙事强调后台执行和可审查输出，而应用截图则引发了与 Codex 在响应速度上的直接比较。

**与前一天对比：** 5 月 18 日，Copilot 最有力的证据还是远程控制、hooks，以及 Spaces/API 的覆盖面。到了 5 月 19 日，讨论进一步转向实际的运营交接：派生会话、云端托管的 CI 修复，以及一个已经被用户拿来与竞争性代理运行时做基准对比的桌面应用。

### 1.2 安全与治理已走到代理讨论的中心 🡕

另一个强烈主题是，代理的采用如今开始以企业控制的语言来讨论：代码在哪里运行、如何访问私有系统，以及怎样把凭据交给代理而不泄露到提示词或上下文窗口里。这是信息流中证据最密集的部分之一，因为其中同时出现了产品公告、架构图和外部报道。

[@testingcatalog](https://x.com/testingcatalog) [总结道](https://x.com/testingcatalog/status/2056681929915699404)（38 个赞，3 条回复，2,004 次浏览）介绍了 Anthropic 为 Claude Managed Agents 提供的自托管沙箱和 MCP 隧道。附带架构图进一步说明了其设计：由 Anthropic 管理的代理循环将任务推送到沙箱控制平面，再由后者把执行委派到桌面、浏览器或云端沙箱。回复也进一步点明了意义：对于不能让敏感代码流经第三方基础设施的企业来说，私有 MCP 访问和自托管执行能够消除关键的信任门槛。

![Anthropic 托管代理示意图，显示代理循环将工作推送到沙箱控制平面，再由其分派到桌面、浏览器和云端沙箱](https://pbs.twimg.com/media/HIrNTGtXMAAhqbS.png)

[@ithilgore](https://x.com/ithilgore) [指出](https://x.com/ithilgore/status/2056793901495947432)（6 个赞，985 次浏览）链接到 Forbes 对 OpenAI 与 1Password 在 Codex 安全方面合作的报道。文章补上了缺失的关键信息：1Password 的 Environments MCP Server 能让 Codex 按需获取凭据，而无需把密钥放进提示词、代码或模型上下文；OpenAI 的代理安全负责人也明确主张，随着子代理越来越常见，需要审计轨迹、持续授权和凭据中介机制。合起来看，这些内容表明市场关注点正在从“代理能不能做”转向“由谁控制、用什么凭据、留下什么审计记录”。

**讨论洞察：** 讨论并未围绕抽象的 AI 安全展开，而是始终停留在具体问题上：私有网络中的 MCP 访问、自托管沙箱、按需凭据，以及对子代理行为的可观测性。

**与前一天对比：** 5 月 18 日，治理问题更多体现为围绕 Copilot 远程控制的信任感，以及管理员可见性的焦虑。到 5 月 19 日，讨论已成熟到网络边界架构和凭据中介层面，而且桌面上同时摆出了 Anthropic 与 OpenAI 相关的证据。

### 1.3 成本控制与路由正成为工作流中的一等问题 🡕

定价和 token 纪律依旧是核心话题，但语气已经从抱怨转向操作层面的变通方案。信息流中出现了多个例子，展示人们如何调整 harness、路由器和模型组合，让编程代理在经济上变得可承受。

[@DeepakNesss](https://x.com/DeepakNesss) [分享了](https://x.com/DeepakNesss/status/2056532049482428523)（4 个赞，2 条回复，80 次浏览）介绍了一种具体的 OpenCode 优化模式：用 Kimi K2.6 作为主编排器，再由更便宜的 DeepSeek v4 Flash 子代理执行命令和测试，这样输出就不会消耗昂贵的上下文。截图的重要性在于，它详细解释了机制，而不是只笼统声称成本更低。

![OpenCode 成本优化截图，解释了 Kimi K2.6 编排器如何将命令执行交给 DeepSeek v4 Flash 子代理](https://pbs.twimg.com/media/HIpFACSaQAAgVLd.jpg)

[@FellMentKE](https://x.com/FellMentKE) [强调了](https://x.com/FellMentKE/status/2056653226083340452)（3 个赞，2 条回复，3,132 次浏览）提到 UncommonRoute；相关仓库称，这个本地路由器在 100 个留出测试的 SWE-bench Verified 任务中解决了 75 个，而仅用 Opus 的方案解决了 74 个，但 API 成本低了 53%。它还提供了一个仪表板，用于展示 Claude Code、Codex、Cursor 和 OpenAI SDK 的逐请求路由决策。在平台侧，[@Sarthak4Alpha](https://x.com/Sarthak4Alpha) [警告称](https://x.com/Sarthak4Alpha/status/2056706236729704799)（16 个赞，12 条回复，213 次浏览）指出，GitHub Copilot 将于 6 月 1 日启用基于 token 的计费，这会比简单补全更明显地冲击重度代理工作流，连代码审查也会被纳入 GitHub Actions 的计量体系。

**讨论洞察：** 信息流如今已把路由视为常规工程杠杆。人们不再只是选一个最喜欢的模型，而是引入子代理、本地路由器和基于任务的升级规则来控制消耗。

**与前一天对比：** 5 月 18 日，定价主题仍更多围绕配额冲击和免费层失灵。到了 5 月 19 日，更强的信号是适应：把请求导向更便宜的模型、对不同命令采用不同计量方式，并审计多步骤代理工作流的真实成本。

### 1.4 Google 的编程模型势头更多体现在 Copilot，而非 Antigravity 🡒

与 Google 相关的关注度依然很高，但最有力的证据并不来自 Antigravity 本身。今天数据集中最具体的 Google 模型消息，是 GitHub 在 Copilot 中分发 Gemini 3.5 Flash；与此同时，独立的 Antigravity 仍伴随着怀疑和“先围观再说”的等待状态。

[@github](https://x.com/github) [宣布](https://x.com/github/status/2056801675042779279)（52 个赞，4 条回复，6,710 次浏览）称 Gemini 3.5 Flash 已正式可用，并正在 GitHub Copilot 中逐步推出；[@GHchangelog](https://x.com/GHchangelog) [补充说](https://x.com/GHchangelog/status/2056808371538276802)（50 个赞，5 条回复，3,123 次浏览）则表示，它正覆盖 Copilot Pro、Pro+、Business 和 Enterprise 用户，并登陆主要 IDE 和 GitHub Mobile。相关更新日志称，GitHub 认为该模型能以 Flash 级别的速度和成本提供接近 Pro 的编程质量，同时具备很强的工具使用能力和较高的缓存效率；但日志也提到，一个暂定的高级请求倍率为 14 倍，企业方案还可能受策略开关限制。

与这条分发消息并列的，是对独立产品较弱的信心。[@Surendar__05](https://x.com/Surendar__05) [表示](https://x.com/Surendar__05/status/2056707733672616078)（24 个赞，28 条回复，650 次浏览）表示，他们接触到的人里没有谁真的在用 Antigravity 或 Gemini 模型写代码，附图也只是一张品牌标题卡，而不是产品证据。[@EdenKollcinaku](https://x.com/EdenKollcinaku) [发布了](https://x.com/EdenKollcinaku/status/2056644721930350947)（292 个赞，8 条回复，16,930 次浏览）则是一张通向 I/O 的倒计时图片，再次体现的是期待，而非产品层面的证明。

**讨论洞察：** Google 的编程叙事依然是分裂的：一边是围绕 I/O 品牌界面的兴奋和猜测，另一边则是在 Gemini 通过别人的编程产品分发时，才出现更清晰的日常采用证据。

**与前一天对比：** 5 月 18 日，Antigravity 相关猜测主要由泄露文化和路由截图推动。到了 5 月 19 日，公开且结构化的发布信号来自 GitHub 在 Copilot 中上线 Gemini 3.5 Flash，而 Antigravity 本身仍缺乏同等级别的用户信心。

## 2. 什么让人感到沮丧

### 计量式代理工作流暴露出真实的成本焦虑

[@Sarthak4Alpha](https://x.com/Sarthak4Alpha) [警告称](https://x.com/Sarthak4Alpha/status/2056706236729704799)（16 个赞，12 条回复，213 次浏览）指出，GitHub Copilot 的 token 计费会让重度代理工作流更贵，甚至会把代码审查也拉进 GitHub Actions 分钟数的计费里。令人沮丧的并不是 AI 编程要花钱，而是更丰富的自主工作流如今被更明确地计量了，这让人感觉自己可能直到账单出来才真正知道每月会暴露出多少成本。严重程度：高。

信息流中的其他内容也展示了相应的变通模式。[@DeepakNesss](https://x.com/DeepakNesss) [使用了](https://x.com/DeepakNesss/status/2056532049482428523)（4 个赞，2 条回复，80 次浏览）提到用更便宜的执行型子代理处理命令密集型工作；而 [@FellMentKE](https://x.com/FellMentKE/status/2056653226083340452) 链接的 UncommonRoute 仓库则明确把逐请求模型路由当作一种方案来卖：在不牺牲基准性能的前提下，将 API 账单减半。值得构建：是。这个痛点具体、反复出现，而且已经催生出临时拼装的路由层。

### 与 Codex 风格竞品相比，Copilot 的新桌面端界面仍显粗糙

[@lexrus](https://x.com/lexrus) [发布了](https://x.com/lexrus/status/2056545172679528886)（9 个赞，3 条回复，1,386 次浏览）发布了新版 GitHub Copilot 应用，并在回复中表示它比 Codex 更卡，尤其是在 Markdown 内容较多的视图里。这是一个很实际的抱怨，而不是阵营式嘲讽：用户已经开始按渲染速度、会话清晰度，以及跟踪代理工作进度的难易程度来给这些产品做横向比较。严重程度：中。

问题并不是 Copilot 功能不够；第 1 节恰恰说明了相反的情况。问题在于，一旦用户能跨工具比较派生会话、计划模式和远程控制，产品打磨上的差距就会更显眼。值得构建：是，但方向应是工作流可观测性和界面质量，而不是再做一个单纯的模型封装壳。

### Google 仍未说服从业者相信 Antigravity 是日常编程工具

[@Surendar__05](https://x.com/Surendar__05) [询问](https://x.com/Surendar__05/status/2056707733672616078)（24 个赞，28 条回复，650 次浏览）质问：如果 Google 数十年来一直在抓取代码，为什么 Gemini 在编程上依然很差；同时还表示，他们接触到的人里没人真的在用 Antigravity。相比当天那些倒计时和品牌宣传帖，这才是更强烈、也更实操层面的抱怨，后者主要体现的是期待而不是成功使用。严重程度：中。

人们的应对方式，是在其他产品把工作流衔接做得更好时，间接使用 Google 模型。今天 GitHub 推出 Gemini 3.5 Flash，正好说明了这一点。值得构建：可能，但机会更多在产品包装和工作流集成，而不是原始模型可用性本身。

## 3. 人们希望有什么产品

### 企业网络边界内可审计且安全的代理运行时

今天信息流中最明确的实际需求，是让代理能够访问私有系统，同时又不迫使团队放弃安全控制。[@testingcatalog](https://x.com/testingcatalog) [报告称](https://x.com/testingcatalog/status/2056681929915699404) 介绍了 Claude Managed Agents 的自托管沙箱和 MCP 隧道；而 [@ithilgore](https://x.com/ithilgore/status/2056793901495947432) 链接的 Forbes 文章则主张，在 Codex 中提供按需凭据访问、持续授权和可审计的子代理行为。机会评级：直接。

### 跨代理技术栈的更智能成本路由与预算控制

[@DeepakNesss](https://x.com/DeepakNesss) [记录了](https://x.com/DeepakNesss/status/2056532049482428523) 展示了一种压低 OpenCode 积分消耗的子代理模式；[@FellMentKE](https://x.com/FellMentKE/status/2056653226083340452) 链接的 UncommonRoute 仓库则用本地路由、仪表板和具备成本感知的模型选择，把同样的直觉正式产品化。这个需求既实际又紧迫，因为计量式代理使用已经不再是假设。机会评级：直接。

### 更好的离桌监督能力，适配持续运行的代理

[@code](https://x.com/code) [宣布](https://x.com/code/status/2056460035278962738) 展示了 Copilot CLI 和应用会话的远程控制；[@DevAdventur3s](https://x.com/DevAdventur3s) [展示了](https://x.com/DevAdventur3s/status/2056785949602754929)（4 个赞，1 条回复，167 次浏览）则展示了 ChatGPT 应用中的 Codex 如何接收截图，并在移动端呈现验证检查。人们显然希望代理在自己离开电脑后继续工作，同时还能通过手机进行审批、检查和纠偏。机会评级：直接。

### 从买方视角提供更清晰的代理可观测性

[@anandPa94](https://x.com/anandPa94) [推出了](https://x.com/anandPa94/status/2056805283142480052)（4 个赞，2 条回复，49 次浏览）介绍了 Scope：一个展示 Claude Code、Codex、Cursor 及类似代理如何与产品交互、在哪里卡住、以及何时转向竞品的平台。这个定位之所以成立，是因为它回答了买方一个具体的新问题：不再是“哪个模型最好”，而是“代理究竟是如何体验我的产品的？”机会评级：竞争性。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |
|---|---|---|---|---|
| GitHub Copilot / Copilot app / cloud agent | AI 编程助手 + 托管代理 | (+/-) | 远程控制、派生会话、一键修复 CI，以及覆盖 GitHub 多个界面的广泛分发 | 桌面应用的打磨程度仍在与 Codex 对比中处于下风；更丰富的工作流如今也暴露出计费担忧 |
| Gemini 3.5 Flash in Copilot | 编程工具内的模型分发 | (+) | GitHub 声称其以 Flash 级速度和成本提供接近 Pro 的编程质量，工具使用能力强、响应快、缓存效率高 | 暂定 14 倍高级请求倍率；企业访问可能需要启用相关策略 |
| Claude Managed Agents with self-hosted sandboxes + MCP tunnels | 企业代理运行时 | (+) | 可访问私有网络、自托管执行，对敏感代码库给出更清晰的安全姿态 | 今天公开的证据仍停留在架构层面，而非实操吞吐量或 DX 证明 |
| Codex mobile in ChatGPT | 移动端代理监督 | (+) | 展示验证步骤、截图证据，以及离桌时的远程任务审查 | 今天的证据量仍然较少，且偏移动端，不是深度工作站替代方案 |
| OpenCode | 终端编程代理 | (+/-) | 用户称赞其 UX 更清爽、支持无头运行；也支持多供应商配置和 harness 试验 | 成本仍重要到让用户自行发明子代理执行方案，并迁移 harness |
| UncommonRoute | 模型路由器 / 代理 | (+) | 本地逐请求路由、仪表板、经基准测试的成本节省，以及对 Claude Code/Codex/Cursor/OpenAI SDK 的即插即用支持 | 仍是早期基础设施层，又增加了一个需要运维的组件 |
| 1Password Environments MCP Server for Codex | 代理凭据 / 安全层 | (+) | 按需获取凭据，同时不把密钥暴露到提示词或模型上下文中 | 增加了身份与访问管理复杂性，团队仍需谨慎设计 |

整体满意度分布很广，但基调务实。只要每一层都能解决具体的工作流问题，人们愿意混搭模型、路由器、移动端监督和托管代理。最大的迁移模式并不是“所有人都从工具 X 转向工具 Y”，而是加入路由层和 harness 层，以更低成本或更高安全性使用同样的模型。竞争态势也在变化：今天 Google 最有力的编程模型证据，是通过 Copilot 分发体现出来的；而 OpenCode 和 Codex 则继续在用户体验和运行时控制上赢得心智。

## 7. 机会在哪里

**[+++] 代理治理与安全中介层** —— Anthropic 的自托管沙箱和 MCP 隧道，以及 OpenAI/1Password 围绕 Codex 的工作，都指向同一个尚未解决的层面：私有网络访问、凭据中介、审计轨迹，以及对子代理的持续授权。这个机会很强，因为它已经被界定为具体的运营问题，而不是抽象的安全话语。

**[+++] 代理工作流的成本路由与支出可见性** —— DeepakNess 的 OpenCode 子代理模式、UncommonRoute 经基准验证的本地路由器，以及 Copilot 引发的 token 计费焦虑，都在表达同一件事：团队需要帮助来判断，什么时候值得为前沿级推理付费，什么时候不值得。最强的产品切入点不是更便宜的模型，而是一个负责路由、预算和支出解释的控制平面。

**[++] 面向产品与工作流负责人的代理可观测性** —— Scope 的定位和整个信息流都表明，企业越来越需要了解代理如何穿过 onboarding、文档、认证和功能流程。这个机会中等偏强，因为可观测性已经有竞争，但底层需求正变得越来越显性。

**[+] 常开型代理的远程监督界面** —— Copilot 远程控制、Codex 移动端截图，以及黑客马拉松上的可穿戴控制，都显示出人们希望通过其他设备监督长期运行代理的需求。这个信号正在形成，因为实际使用已经存在，但市场形态仍在摸索中。

## 8. 要点

1. **GitHub Copilot 的叙事已从功能发布转向工作流编排。** 远程控制、云端托管的 CI 修复，以及 Copilot 应用中的派生会话，让这款产品更像运行时管理器，而不只是侧边栏里的聊天工具。（[来源](https://x.com/code/status/2056460035278962738)）
2. **企业代理采用如今是通过网络边界与凭据设计来论证的。** Anthropic 的沙箱/隧道架构，以及 OpenAI-1Password 的 Codex 叙事，核心都在安全执行和受控访问，而不是模型原始能力。（[来源](https://x.com/testingcatalog/status/2056681929915699404)）
3. **成本控制正围绕编程代理发展成一个独立产品类别。** 这一天既出现了廉价执行型子代理的实践配方，也出现了一个把本地模型路由与仅用 Opus 的基线做基准比较的仓库。（[来源](https://x.com/DeepakNesss/status/2056532049482428523)）
4. **Google 的编程模型势头，通过 Copilot 体现得比通过 Antigravity 本身更清晰。** 最具体的 Google 模型信号，是 GitHub 在 Copilot 中上线 Gemini 3.5 Flash；而围绕 Antigravity 的讨论仍更多停留在期待和怀疑上。（[来源](https://x.com/GHchangelog/status/2056808371538276802)）
5. **构建者越来越倾向于给代理加控制层，而不是替换代理本身。** 今天最值得注意的项目集中在路由、评估、可观测性和远程监督，而不是再做一个全新的编程助手。（[来源](https://x.com/anandPa94/status/2056805283142480052)）
