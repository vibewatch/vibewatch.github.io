# Twitter AI 编程 - 2026-11-05

## 1. 大家在讨论什么

### 1.1 Antigravity 正在增加 Notebook 和远程工作流功能 (🡕)

当天的帖子介绍了两项产品更新，让 Antigravity 不再局限于本地代码编辑：原生 Notebook 查看、语音输入和云端托管的代理会话。官方 v2.29 更新日志列出了这三项功能；远程代理文档称，会话运行在 Google 管理的环境中，目前正逐步向个人 Google AI Pro 和 Ultra 账户开放。

[@antigravity](https://x.com/antigravity) [宣布](https://x.com/antigravity/status/2118234632801910871)（493 个赞、27 条回复、25,411 次浏览；68 次收藏）称，`.ipynb` 文件现在可在文件查看器中显示代码单元格、Markdown、表格、图片和单元格输出。[@testingcatalog](https://x.com/testingcatalog) [报道称](https://x.com/testingcatalog/status/2118089695443714458)（186 个赞、25 条回复、11,135 次浏览；27 次收藏）介绍了更新日志中的语音模式和远程代理逐步开放情况。Google 的 [v2.29 更新日志](https://antigravity.google/docs/changelog#rel-hub-2.29.0) 确认了功能列表和逐步开放安排；[远程代理文档](https://antigravity.google/docs/remote-agents/) 说明了符合条件的套餐和账户类型。

**讨论要点：** 一条回复称 Notebook 查看器可以正常使用；其他人则询问它能否执行 Notebook 单元格，并请求接入 Gemini Notebook。更新日志承诺的是渲染功能，而非执行功能。该功能正在逐步开放，另有回复询问语音能否在任务进行中改变代理的行动方向。

**与前一天相比：** 前一天的报道重点介绍了 Google 大规模将 Fortran 迁移到 Rust 的演示。今天的话题转向日常工作流：查看 Notebook、通过语音与代理交互，以及在云端继续工作。([Google Labs 的介绍文章](https://blog.google/innovation-and-ai/models-and-research/google-labs/fortran-to-rust-antigravity/))

### 1.2 模型选择正转向路由与本地执行 (🡕)

GitHub 将 Copilot Fusion 介绍为一种可选择模型和执行模式的路由器；Microsoft 则另行介绍了如何通过 Copilot 在本地运行编码模型。这是两种不同的模型选择方式，而关于本地推理的证据来自厂商报告，并非独立基准测试。

[@github](https://x.com/github) [描述了](https://x.com/github/status/2118431920295989588)（100 个赞、27 条回复、14,633 次浏览；29 次收藏）介绍了 Fusion 的 Single、Cascade 和 Critique 模式，并表示用户为每项任务选择投入等级，而非逐项指定模型；帖子还宣传截至11月30日可享受30%折扣。GitHub 的 [文档](https://docs.github.com/en/copilot/concepts/models/copilot-fusion) 解释说，Fusion 会根据任务和投入等级进行路由。附图展示了三种执行路径：

![Copilot Fusion 的 Single、Cascade 和 Critique 执行模式示意图](https://pbs.twimg.com/media/HWYumsZXcAAjkHa.jpg)

[@QwenAIFans](https://x.com/QwenAIFans) [分享了](https://x.com/QwenAIFans/status/2118421584948113601)（6 个赞、2 条回复、808 次浏览；4 次收藏）发布了一张 Foundry Local 与 Qwen3.8-27B 接入 Copilot 后的吞吐量图表。链接中的 [Microsoft Foundry 帖文](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/) 称，RTX 5090 测试使用了 32 GB 显卡和约 18 GB 的 4-bit 模型；在提示词长度从 4K 到 260K 的范围内，Microsoft 报告的生成速度是 llama.cpp 的 1.36 至 1.95 倍。Microsoft 表示，24 GB 显存支持最高 64K 的上下文长度，32 GB 或更大显存则支持更长上下文，最高可达 262K；因此，260K 的结果不应被视为 24 GB 显存下的结果。厂商还指出，本地模型的推理能力可能弱于先进的云端模型。

![Microsoft 报告的 Foundry Local 与 llama.cpp 在提示词长度为 4K 至 260K 时的生成速度对比图](https://pbs.twimg.com/media/HWYlJ7bbIAA0CEh.jpg)

[@TeksEdge](https://x.com/TeksEdge) [转录了](https://x.com/TeksEdge/status/2118440717928612147)（68 个赞、6 条回复、4,923 次浏览；78 次收藏）发布了 Microsoft 的同一组数据，并提醒读者，这项比较针对的是 llama.cpp，而非所有优化过的运行时；基准配置也有待进一步说明。这是关于同一项厂商基准测试的另一条帖子，并非独立复现。

**讨论要点：** GitHub 发布 Fusion 的帖子下，有两条回复称，尽管官方宣布了折扣，该功能仍然很贵，或会消耗更多额度。Microsoft 的帖子提供了 Foundry 相关数据的一手来源；这些测量结果并不能说明其他推理引擎的表现如何。

## 3. 人们希望拥有的功能

### 共享且范围明确的项目上下文

关于 Copilot Projects 的讨论中，有人具体提出，希望项目定义能够关联代码库和知识库、指令以及范围明确的记忆。 [@OrenMe](https://x.com/OrenMe) [明确说明了](https://x.com/OrenMe/status/2118103139047907421)（1 个赞、1 条回复、207 次浏览）在回复 [Projects 讨论串](https://x.com/pierceboggan/status/2118101171361501518)（71 个赞、12 条回复、3,149 次浏览；23 次收藏）时提出了这份愿望清单。[@pierceboggan](https://x.com/pierceboggan) [回应了](https://x.com/pierceboggan/status/2118104458781507815)（1 个赞、1 条回复、199 次浏览）表示，团队正在开发让用户可通过 Copilot 界面和项目工具访问云原生项目的功能。同一讨论串中，还有用户要求改进会话管理，并希望能找到已完成的工作。

**机会评级：直接。**这些功能请求十分明确，产品作者也表示相关工作正在进行；但讨论并未说明有多少用户需要每项功能。

### 智能体忙碌时保存并排队提示词

[@JamesMontemagno](https://x.com/JamesMontemagno) [分享了](https://x.com/JamesMontemagno/status/2118417623641882763)（5 个赞、1 条回复、623 次浏览）介绍了 Parked Prompts。这项面向 VS Code 和 Copilot Canvas 的预览功能，可以将提示词连同文件或图片一起保存，之后恢复为未发送状态，也可以在 Canvas 中将提示词加入队列。帖子引用了一位开发者的请求：其他智能体忙碌时，他希望能起草并保存带附件的提示词。[项目页面](https://jamesmontemagno.github.io/parked-prompts/)称，只要画布保持打开，排队中的提示词就会逐条发送。

**机会评级：竞争型。**目前已有一款预览工具针对性地解决了这一需求；现有证据表明用户需要提示词交接，但不足以证明更广泛的采用需求，也无法说明是否需要单独开发一款产品。

### 更清晰的模型使用资格与推理力度控制

Jio 促销帖明确要求清楚标注哪些模型符合使用资格；GitHub 的 [Fusion 公告](https://x.com/github/status/2118431920295989588)（100 个赞、27 条回复、14,633 次浏览；29 次收藏）下的回复则提出，希望能在命令行中选择模型，并能单独控制推理力度。[@ciano_dowd](https://x.com/ciano_dowd) [询问了](https://x.com/ciano_dowd/status/2118468467800392037)（12 次浏览）询问何时会推出推理力度滑块，[@nwp](https://x.com/nwp) [询问了](https://x.com/nwp/status/2118470858230386895)（5 次浏览）则询问何时能在命令行中进行控制。

**机会评级：前瞻型。**两款产品中都出现了对清晰的使用资格说明、推理力度和用量控制的需求，但相关请求数量有限，也没有确立共同的实现方案或可量化的影响。

## 7. 机遇在哪里

**[+++] Project context and prompt handoff** — The Copilot Projects discussion specifies cross-repository context, scoped memory, and session management; the product author says cloud-native projects and project tools are being worked on. Parked Prompts independently addresses the narrower need to save requests and attachments while agents are occupied.
