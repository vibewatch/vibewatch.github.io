## 1. 人们在讨论什么

### 1.1 成本、配额和速率限制，正开始替人们决定该用哪个代理 🡕

当天信号最强的一组讨论，核心不是谁的基准测试更好看，而是支出上限。Microsoft 收缩许可证、GitHub Copilot 倍率截图，以及 Antigravity 的配额应对办法，都把 AI 编程首先变成了预算问题，其次才是模型选择问题。就连关于 Antigravity 上线的正面消息，焦点也集中在更低的 token 消耗和配额重置，而不是新增能力。

### 1.2 模型之上的竞争，正加厚为工作流文件、记忆和编排层 🡕

最有代表性的工作流帖子，并不是“这里有个更好的模型”，而是“我怎么把代理串起来”“我怎么把自己的约定教给助手”，以及“我怎么让同一套工作流在换工具后还能继续用”。这让当天更像是一场控制平面之争，而不是谁家 UI 最好的较量。

[@Teknium](https://x.com/Teknium) [宣布](https://x.com/Teknium/status/2059038964552745378)（58 个赞、8 条回复、2,271 次浏览、47 次收藏）称，Hermes Agent 现在可以通过可安装技能来编排 OpenHands。配图中的信息图把这项集成说得很具体：OpenHands 成了可选的 Hermes 技能，基于 LiteLLM 支持 Anthropic、OpenAI、DeepSeek、Qwen、Ollama、vLLM 和 Nous，并提供了明确的无头模式参数。

![Hermes Agent 信息图，说明如何将 OpenHands 作为可选技能进行安装和运行，并支持基于 LiteLLM 的模型及 headless 标志](https://pbs.twimg.com/media/HJMsYV2bYAAMjAP.jpg)

[@dosco](https://x.com/dosco) [表示](https://x.com/dosco/status/2058691472455839960)（27 个赞、3 条回复、878 次浏览、20 次收藏）称，Ax/Aithy 的核心设计优势，在于把对话历史视为可检查、可提炼的结构化数据。他附上的评测截图则把更难的一层要求说得很明确：目前缺的仍是一条一等公民级的编码代理工具通道，需要具备受限仓库搜索、事务性补丁、诊断、回滚和溯源能力。

**与前一天对比：** 5 月 24 日强调的是订阅路由和本地模型；5 月 25 日则在这层路由之上，又加上了更厚的规则、技能、记忆和委派代理层。

### 1.3 构建者正在围绕现有代理封装专用适配层，而不是正面替代它们 🡕

最清晰的项目分享帖，都是在流行工具链上补上一项缺失能力：语义代码智能、合规知识、供应商自由度，或者更快的远程连接。这和“再做一个新助手”的构建模式不同，更像是在为用户已经信任的代理铺基础设施。

[@pvergadia](https://x.com/pvergadia) [重点提到](https://x.com/pvergadia/status/2058910976620306535)（1 个赞、185 次浏览、5 次收藏）提到 codegraph 是本周增长最快的 GitHub 仓库之一。公开的 [colbymchenry/codegraph 仓库](https://github.com/colbymchenry/codegraph) 将其描述为面向 Claude Code、Codex CLI、Cursor、OpenCode 和 Hermes Agent 的 TypeScript 语义代码知识图谱；其 README 声称，在 7 个代码库上的基准测试中，平均可节省 35% 成本，并减少 71% 的工具调用。

[@VivekIntel](https://x.com/VivekIntel) [分享了](https://x.com/VivekIntel/status/2058756434570236092)（3 个赞、110 次浏览、3 次收藏）提到 [mlunato47/claude-grc-plugin](https://github.com/mlunato47/claude-grc-plugin)，其 README 称，它为 Claude Code 和 OpenCode 提供 72 个以上参考文件、15 个框架和 24 个斜杠命令，覆盖 FedRAMP、NIST 800-53、CMMC、SOC 2、ISO 27001、HIPAA 及相关合规工作流。

[@Liz_Binance](https://x.com/Liz_Binance) [指向了](https://x.com/Liz_Binance/status/2058717824802054219)（2 个赞、2 条回复、806 次浏览）提到 [ajsai47/backdoor](https://github.com/ajsai47/backdoor)——一个 Python 代理，其 README 称可将 Claude Code 重新路由到 DeepSeek、Groq、Ollama、OpenRouter 和 NVIDIA NIM 等兼容 OpenAI 的提供方。这条帖子真正有价值的，不是那个未经证实的“抄袭”指控，而是出现了一个公开的路由层，专门用来保留 Claude Code 的工具链，同时替换底层模型和价格档位。

[@tmsdnl](https://x.com/tmsdnl) [表示](https://x.com/tmsdnl/status/2059035873996570671)（2 个赞、272 次浏览）称，一个 Codex 功能请求从 GitHub issue 到合并只用了 10 小时 41 分钟，并附上新的 `app-server` WebSocket 流程和 `/status` 输出截图。即便只是个小功能，也说明市场奖励的是薄适配层和快速工作流修复，而不是全栈重造。

**讨论洞察：** 这些构建者的出发点都一样：先选一个已经足够强的代理，再补上一样缺的东西——语义上下文、合规知识、供应商自由度或委派执行。它是一种增量模式，不是替代模式。

**与前一天对比：** 5 月 24 日已经出现了面向特定工作流的技能包；5 月 25 日则把这一路线继续扩展成更专门的基础设施层：知识图谱、合规插件、提供方代理和编排技能。

## 3. 人们希望出现什么

### 与代理行为匹配的突发计费与配额仪表盘

最强烈的需求，不是再来一个抽象基准，而是能回答这些问题的机制：一个任务会花多少钱、哪些档位已经耗尽、何时刷新、便宜档位到底能不能把工作做完。[@air_codex](https://x.com/air_codex) [展示了](https://x.com/air_codex/status/2058906435807744259)（43 次浏览）展示了用户侧的故障模式，[@balakoteswar](https://x.com/balakoteswar) [浮出水面](https://x.com/balakoteswar/status/2058876408269824384)（4 个赞、378 次浏览）展示了套餐侧的倍率变化，而关于 Microsoft 的报道则呈现了同一问题的企业版本。机会：直接。

### 能经受工具切换的可迁移工作流包

[@EXM7777](https://x.com/EXM7777) [认为](https://x.com/EXM7777/status/2059016738570993859)（54 个赞、19 条回复、2,097 次浏览、44 次收藏）表明，原则比界面更耐久；而 [Microsoft Build 会话页面](https://build.microsoft.com/en-US/sessions/LTG402) 则明确把规则、提示词文件、技能和自定义代理框定为向 Copilot 传授团队约定的方式。[@PhilSeamark](https://x.com/PhilSeamark) [展示了](https://x.com/PhilSeamark/status/2058689470782988783)（54 次浏览）则在非开发者语境中表达了同样的需求：真正的资产，是一套可重复的工作流，能处理转录文本、日历、笔记和历史记录，而不是每次从零开始。机会：直接且具竞争性。

### 面向受监管与非代码工作的领域专用代理层

围绕 [claude-grc-plugin](https://github.com/mlunato47/claude-grc-plugin) 的构建活动，以及 Phil Seamark 的 Copilot 工作流，其实都指向同一个缺口：通用代理仍需要一层真正理解用户领域的能力。前者意味着 FedRAMP、NIST 800-53 和文档审查命令；后者则意味着客户笔记、差旅行政、产品反馈和日记类工作流。机会：直接。

### 安全的多代理预设，而不是空白画布式编排

[@Teknium](https://x.com/Teknium) [公告](https://x.com/Teknium/status/2059038964552745378)（58 个赞、8 条回复、2,271 次浏览、47 次收藏）下的回复要求提供预设组合；[@dosco](https://x.com/dosco) [列出了](https://x.com/dosco/status/2058691472455839960)（27 个赞、3 条回复、878 次浏览、20 次收藏）则更正式地列出了缺失的护栏：受限仓库搜索、事务性编辑、诊断、回滚和溯源。人们似乎想要的，是从一个值得信赖的预设起步，而不是面对一堆旋钮。机会：具竞争性。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |
|---|---|---|---|---|
| GitHub Copilot / Copilot CLI | 编码助手 / 工具链 | (+/-) | 原生支持规则、提示词文件、技能和自定义代理；同时出现在企业与知识工作流程中 | 倍率调整和套餐核算正在收紧；部分采用还受到成本与内部自用决策的推动 |
| Claude Code | 编码代理 | (+/-) | 仍然流行到让 Microsoft 不得不主动缩减许可证；其强工具链也激发了路由与代理项目 | 企业级成本压力真实存在，配置蔓延也是反复出现的抱怨 |
| Google Antigravity | 代理运行时 / IDE / CLI | (+/-) | 新增 Flash Low，覆盖多个界面，仍然吸引重视自动化的用户 | 高流量失败、严格配额，以及反复出现的宣传帖，持续削弱用户信任 |
| Gemini 3.5 Flash (Low) | 模型档位 | (+/-) | 被宣传为比 Flash Medium 约高 45% 的 token 效率，并已可在 Antigravity 各界面中使用 | 用户仍在质疑，它在真正撞上限制前，究竟能多撑出多少实际余量 |
| Hermes Agent | 编排工具链 | (+) | 支持可安装技能，以及跨多个代理后端进行委派执行 | 回复显示，用户需要更安全的预设、更成熟的配置组合，以及更少的无关改动 |
| OpenHands | 自主编码代理 | (+) | 现在可以通过 Hermes 以及多个由 LiteLLM 支持的提供方被编排 | 复杂性仍然会通过参数和环境变量泄露给用户 |
| CodeGraph | 语义代码智能 | (+) | 预索引本地图谱有望减少工具调用、降低成本，并加快多个代理中的探索 | 需要额外的索引流程，目前看起来仍像早期基础设施软件 |
| GRC Knowledge Plugin | 领域插件 | (+) | 为 Claude Code 和 OpenCode 增加合规映射、文档审查和操作命令 | 如果不在受监管环境中工作，适用面就较窄 |
| Backdoor | 提供方代理 | (+) | 保留 Claude Code 的工具链，同时切换到更便宜、本地或其他提供方 | 仍处于早期阶段，配置负担较重，也受提供方兼容性限制 |
| VS Code + Copilot + Power Automate 文件 | 工作流模式 | (+) | 把编码环境变成全天工作空间，用于处理转录文本、日记、客户笔记和子代理 | 目前仍更像一套自定义技术栈，而不是默认产品体验 |

总体来看，当工具提升了可迁移性，或封装了真实的工作流知识时，满意度最高；而当使用上限或计费倍率打断工作时，满意度最低。迁移模式并不是从工具 A 干净利落地切换到工具 B，而是路由与叠层：保留用户喜欢的工具链，替换提供方，加一层语义索引，加一个领域插件，或接上一个委派代理。竞争正在从单纯的模型质量，转向上下文、编排和价格控制。

## 7. 机会在哪里

**[+++] 预算感知路由、配额预测和突发计费** — 第 1 节显示，Microsoft 和 GitHub 的决策正在围绕支出上限弯曲；第 2 节则显示，即便 Google 推出了 Flash Low，Antigravity 用户仍会在任务中途被拦下。Backdoor 已经是构建者给出的回应，而这通常意味着痛点真实且迫切。

**[++] 可迁移工作流包与记忆层** — 第 1.2 节和第 3 节显示，规则、提示词文件、技能、子代理和持久工作区，正在成为高于任何单一模型之上的耐久资产。这个机会评级为中等，因为一方产品已经在陆续推出其中的一部分，但跨工具版本仍然空着。

**[++] 面向现有工具链的专用插件** — 第 5 节中最强的一批构建者是 CodeGraph、GRC Knowledge Plugin 和 Backdoor。三者都不是替代现有代理，而是在其外层增加更窄但更有效的杠杆，因此这看起来像一个可信的产品类别，而非一次性 hack。

**[+] AI 工具讨论的验证与纠偏层** — 第 2 节展示了标题叙事和宣传式铺垫帖需要多快被纠正。这个机会仍在形成，因为读者已经在通过 Community Notes、截图和来源链接手工完成这项工作。

## 8. 要点

1. **企业支出如今正在引导工具选择。** Microsoft 的 Experiences + Devices 团队将在 6 月底前逐步取消大多数 Claude Code 许可证，并推动许多开发者转向 Copilot CLI，这让成本和内部杠杆都成为产品决策的一部分。（[来源](https://www.theverge.com/tech/930447/microsoft-claude-code-discontinued-notepad)）
2. **更便宜的模型档位，并不能单独缓解配额焦虑。** Flash Low 上线时附带了 45% token 效率提升的说法，但用户在做完基础工作后，仍在发布高流量和配额归零的截图。（[来源](https://x.com/air_codex/status/2058906435807744259)）
3. **真正持久的层正在上移到模型之上。** Hermes 加 OpenHands 的编排、Microsoft Build 对规则与技能的 framing，以及面向知识工作的 Copilot 配置，都把工作流文件、技能和记忆视为长期优势。（[来源](https://x.com/Teknium/status/2059038964552745378)）
4. **构建者正靠交付适配层取胜。** CodeGraph、GRC Knowledge Plugin、Backdoor，以及 Codex 的 app-server 改动，都是在现有代理周围增加杠杆，而不是试图直接取而代之。（[来源](https://github.com/colbymchenry/codegraph)）
5. **关注度和上行空间看起来仍然集中。** Google 搜索趋势图显示，Claude Code 和 Codex 的关注度正在明显加速；与此同时，就在企业抱怨成本的同一天，小型构建者账号仍在发布自报收入截图。（[来源](https://x.com/RealNickMugalli/status/2059033135963426950)）
