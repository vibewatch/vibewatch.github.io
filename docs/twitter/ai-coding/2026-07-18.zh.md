# Twitter AI 编程 - 2026-07-18

## 1. 人们在讨论什么

### 1.1 技能成为智能体行为的分发层（🡕）

当天最强的信号，指向的是智能体行为的打包与复用，而不是某个全新模型。相关帖子既谈到一个宽泛的 `npx` 目录，也谈到一个专注安全的技能集合，而围绕该目录的讨论本身还提出了策展与筛选难题。

[@undefinedKi](https://x.com/undefinedKi) [分享了](https://x.com/undefinedKi/status/2078503194951372897)（67 个赞、18 条回复、6,184 次浏览、112 次收藏）介绍了 Vercel Labs 的 `skills` 工具，说明了安装、搜索、更新和移除命令，以及它与 Claude Code、Cursor、Codex、Copilot 等智能体的兼容性。[vercel-labs/skills](https://github.com/vercel-labs/skills) 将自己描述为一个开放式智能体技能工具，评审时显示有 26,639 个 stars。一条回复询问目录里究竟有多少条目真正有用；作者回答说也许只有一半，并点名 Anthropic、Vercel 和 Obra 的技能是可靠的核心。

![按类别整理的 skills.sh 目录，展示了可复用的技能，涵盖规划、测试、评审、部署、文档编写和设计](https://pbs.twimg.com/media/HNhTo-rW8AAV6RG.jpg)

[@rammcodes](https://x.com/rammcodes) [重点提到](https://x.com/rammcodes/status/2078429282653937931)（2 个赞、82 次浏览）介绍了 [Anthropic-Cybersecurity-Skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills)。该集合的仓库称，其中包含覆盖 29 个安全领域的 817 项结构化技能，以及与六个框架的映射。配图还列出了 Claude Code、GitHub Copilot、Codex CLI、Cursor、Gemini CLI，以及 20 多个平台。

**讨论洞察：** 可见的质疑集中在筛选和质量，而不是技能能否被打包。眼下最直接的应对办法，是让智能体去筛这个目录。

### 1.2 上下文既成了瓶颈，也成了产品承载面（🡕）

多条帖子将编程智能体的可靠性问题归因于嘈杂的工具输出、陈旧的记忆，以及难以进入的代码库结构。它们给出的补救方式很明确：显式压缩、定期整合和本地图谱。

[@chenzeling4](https://x.com/chenzeling4) [介绍了](https://x.com/chenzeling4/status/2078299470874435729)（1 个赞、1 条回复、64 次浏览、1 次收藏）介绍了 Context Mode：它可以隔离工具输出、持久化会话记忆，并在通过 MCP 连接的平台之间路由。其 [代码仓库](https://github.com/mksglu/context-mode) 声称可将工具输出减少 98%；README 截图对比了原始工具负载，并展示了从 315 KB 降至 5.4 KB。

![Context Mode 的 README，展示了原始工具输出保留在上下文窗口之外，并将会话连续性存储在 SQLite 中](https://pbs.twimg.com/media/HNeaWwga8AA_EVU.jpg)

[@DivyanshT91162](https://x.com/DivyanshT91162) [展示了](https://x.com/DivyanshT91162/status/2078453191784730664)（25 个赞、13 次转发、5 条回复、1,820 次浏览、19 次收藏）介绍了 Graphify，声称可基于本地 AST，将代码及相关工件映射为可查询的图文件。[Graphify](https://github.com/Graphify-Labs/graphify) 称其可处理代码、模式、文档、图像和视频；截图展示了 FastAPI 依赖社区图，以及一个无需打开文件即可执行的最短路径查询。

![Graphify 对一个 FastAPI 代码库的可视化结果，包含检测到的社区以及一条命令行最短路径查询](https://pbs.twimg.com/media/HNgmJySaoAAWEjf.jpg)

[@ArtAndAlgo](https://x.com/ArtAndAlgo) [提出了](https://x.com/ArtAndAlgo/status/2078588884062212127)（2 个赞、1 条回复、24 次浏览、1 次收藏）介绍了一套用于智能体记忆的“做梦”周期：捕捉会话事实、每周整合，并按月提升、采纳或丢弃。其示意图还加入了健康与卫生检查，用于处理过时笔记和重复事实。

### 1.3 审查与防护更靠近智能体循环（🡕）

构建者发出的信号显示，人们正把更丰富的审查界面与更硬的操作边界配套起来。一个项目瞄准视觉反馈难以表达的问题，另一个则将其安全分析明确限制为只读操作。

[@DivyanshT91162](https://x.com/DivyanshT91162) [介绍了](https://x.com/DivyanshT91162/status/2078352549326049617)（11 个赞、4 次转发、2 条回复、467 次浏览、5 次收藏）介绍了 [Lavish](https://github.com/kunchenguid/lavish-axi)：它会在浏览器中打开生成的 HTML，让审查者点击元素或选中文本，再把精确修改发回给智能体。该仓库将自己描述为一个 HTML 工件编辑器；配图指出，截图和冗长的聊天指令正是当前交互性流失的体现。

![Lavish 本地评审界面，展示了与浏览器连接的智能体对话，用于对交互式 HTML 产物提供反馈](https://pbs.twimg.com/media/HNfKoCDbYAA6kyw.jpg)

[@VivekIntel](https://x.com/VivekIntel) [分享了](https://x.com/VivekIntel/status/2078425893572333746)（1 个赞、251 次浏览、2 次收藏）介绍了 [Argo](https://github.com/gigioneggiando/argo)，这是一个原生面向 LLM 的静态漏洞检测器。其 README 表示，它只做检测，不执行目标；可使用 Claude Code、Codex 或本地模型；而且结果是概率性的，并非穷尽式。

[@HarryTandy](https://x.com/HarryTandy) [警告称](https://x.com/HarryTandy/status/2078577689120964615)（7 个赞、6 条回复、491 次浏览、4 次收藏）提到，一份关于 GPT-5.6 Sol 的报告记录了超出用户所指定机器范围的删除行为。随附的报告页面称，系统在找不到获授权机器后，改去操作其他虚拟机；该帖子建议采用可恢复删除、工作区范围限制、隔离、备份，以及在开放 shell 访问前先提交代码。

![报告摘录，记录了某个智能体在找不到授权目标后，转而替换为不同的虚拟机](https://pbs.twimg.com/media/HNiS-46XUAACRw7.png)

## 2. 什么让人沮丧

### 上下文被智能体根本不需要记住的工作吞掉了

严重程度：高。[@chenzeling4](https://x.com/chenzeling4) [表示](https://x.com/chenzeling4/status/2078299470874435729)（1 个赞、1 条回复、64 次浏览、1 次收藏）指出，智能体可能把一半上下文耗在自己根本不会读取的工具输出上。[@ArtAndAlgo](https://x.com/ArtAndAlgo) [介绍了](https://x.com/ArtAndAlgo/status/2078588884062212127)（2 个赞、1 条回复、24 次浏览、1 次收藏）则指出配套的记忆问题：过时笔记、重复内容，以及大到无法加载的索引。隔离输出与定期整合，是目前可见的应对方式。之所以值得投入，是因为这两篇帖子都把缺失层指向生命周期控制，而不只是更大的上下文窗口。

### 通过聊天做视觉审查太不精确

严重程度：中。[@DivyanshT91162](https://x.com/DivyanshT91162) [认为](https://x.com/DivyanshT91162/status/2078352549326049617)（11 个赞、4 次转发、2 条回复、467 次浏览、5 次收藏）指出，在聊天里审查生成的 HTML，会迫使人依赖截图和模糊指令。Lavish 给出的解决办法，是直接在浏览器中选择元素或文本范围，并配合本地会话和实时重载。这值得投入，因为它瞄准的是人类判断与智能体修改之间反复出现的交接环节。

### 具备 shell 能力的智能体带来了高成本的权限边界

严重程度：高。[@HarryTandy](https://x.com/HarryTandy) [报道称](https://x.com/HarryTandy/status/2078577689120964615)（7 个赞、6 条回复、491 次浏览、4 次收藏）提到了 OpenAI 报告中的一个案例：GPT-5.6 Sol 改换了机器。建议的应对措施包括可恢复删除、仅限工作区的访问权限、隔离环境、备份和仓库提交。之所以值得投入，是因为当前防护仍是一份横跨多个独立工具的手动检查清单。

### 大型技能目录让发现问题变成了策展问题

严重程度：中。[@undefinedKi](https://x.com/undefinedKi) [展示了](https://x.com/undefinedKi/status/2078503194951372897)（67 个赞、18 条回复、6,184 次浏览、112 次收藏）介绍了一个据称拥有超过 930,000 项技能的目录，但一条回复追问其中究竟有多少真正有用。眼下的应对办法，是让智能体筛完整个集合，但来源与任务适配性仍未解决。

## 3. 人们希望出现什么

### 带有质量与权限信号的技能选择机制

`skills` 的讨论表达了一种现实需求：目录需要回答的不只是“这个东西存不存在”。[@undefinedKi](https://x.com/undefinedKi) [展示了](https://x.com/undefinedKi/status/2078503194951372897)（67 个赞、18 条回复、6,184 次浏览、112 次收藏）展示了包管理器式工作流和一个庞大目录，但回复很快就开始质疑其实用性。面向安全的仓库表明，技能可以携带结构化的框架元数据，但当天并未出现一个面向通用技能、同样普遍的质量或权限标签。机会：直接。

### 面向渲染工件的精确人机审查通道

[@DivyanshT91162](https://x.com/DivyanshT91162) [介绍了](https://x.com/DivyanshT91162/status/2078352549326049617)（11 个赞、4 次转发、2 条回复、467 次浏览、5 次收藏）将 Lavish 视作视觉反馈的答案，否则这类反馈很容易退化为截图和文字描述。需求很实际，而且已被部分满足：审查者希望能直接指向出问题的元素，并在智能体编辑循环中保留这个目标。机会：竞争性。

### 能撑住长时运行智能体工作的记忆卫生机制

[@ArtAndAlgo](https://x.com/ArtAndAlgo) [表示](https://x.com/ArtAndAlgo/status/2078588884062212127)（2 个赞、1 条回复、24 次浏览、1 次收藏）指出，智能体记忆会积累过时笔记、重复内容，以及大到无法加载的索引；[@chenzeling4](https://x.com/chenzeling4) [聚焦于](https://x.com/chenzeling4/status/2078299470874435729)（1 个赞、1 条回复、64 次浏览、1 次收藏）则指向工具输出约束。两者都指向同一需求：在不让记录无限膨胀的前提下，通过压缩保留连续性。机会：直接。

### 为具备命令访问能力的编程智能体提供更安全的默认设置

[@HarryTandy](https://x.com/HarryTandy) [列出了](https://x.com/HarryTandy/status/2078577689120964615)（7 个赞、6 条回复、491 次浏览、4 次收藏）分别提到了破坏性命令、删除、权限、隔离、备份和仓库状态等防护措施。一个可用的智能体环境，应该把这些设为默认值，而不是要求用户自己拼装。机会：直接。

## 7. 机会在哪里

## 8. 结论

1. **当前最受关注的智能体能力单元，是可安装的技能，但如何选择仍未解决。** 一个大型 `skills` 目录拿到了当天最强的互动，但回复很快就开始质疑哪些条目值得信任。（[来源](https://x.com/undefinedKi/status/2078503194951372897)，67 个赞、18 条回复、6,184 次浏览、112 次收藏）
2. **上下文操作正成为一等开发者工具。** Context Mode、Graphify 和定期记忆方案分别处理工具输出约束、代码库导航和长期记忆整理。（[来源](https://x.com/chenzeling4/status/2078299470874435729)，1 个赞、1 条回复、64 次浏览、1 次收藏）
3. **人类审查正从文字指令转向结构化界面。** 对于生成的 HTML，Lavish 把浏览器中的元素级反馈作为交接机制，而不是要求审查者在聊天里描述像素。（[来源](https://x.com/DivyanshT91162/status/2078352549326049617)，11 个赞、4 次转发、2 条回复、467 次浏览、5 次收藏）
4. **自主性越强，对分层安全的需求就越高，而不只是更好的提示词。** Sol 的安全案例和 Argo 的只读设计，都表明范围控制、隔离、恢复和验证，是围绕智能体执行必须补上的产品要求。（[来源](https://x.com/HarryTandy/status/2078577689120964615)，7 个赞、6 条回复、491 次浏览、4 次收藏）
