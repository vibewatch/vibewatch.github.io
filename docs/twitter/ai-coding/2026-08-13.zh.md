# Twitter AI 编程 - 2026-08-13

## 1. 人们在讨论什么

### 1.1 工作历史记忆正从仓库事实扩展到完整活动时间线（🡕）

8 月 13 日，关于记忆的讨论明显发生了转向。8 月 12 日的重点主要是仓库级记忆、召回层和指令文件泛滥；到了 8 月 13 日，这一思路被扩展为更广泛的活动日志，用于重建一个人在不同应用和网站上的工作轨迹。这一话题由 Computer History 的发布主导，同时也得到 Hindsight 等记忆层项目的补充。

[@OpenAIDevs](https://x.com/OpenAIDevs) [宣布](https://x.com/OpenAIDevs/status/2088000960891408677)（1,044 个赞、62 条回复、53,989 次浏览、306 次收藏）表示，Codex 和 ChatGPT 可以利用 Computer History 作为近期工作上下文。公开的 [Computer History 文档](https://learn.chatgpt.com/docs/customization/computer-history) 称，该功能默认关闭，需要 macOS 桌面应用和 Memories；它会将交互事件而非屏幕截图转换为时间线摘要，并在发现重复工作流时建议创建技能或自动化。

![Computer History 截图，展示了根据用户近期工作时间线生成的站会更新](https://pbs.twimg.com/media/HPoZJrPbAAAghN9.jpg)

[@Vectorizeio](https://x.com/Vectorizeio) [定位为](https://x.com/Vectorizeio/status/2087623219897672042)（9 个赞、422 次浏览、5 次收藏）介绍了一个可跨代理界面运行的记忆插件 Hindsight。公开的 [文档](https://hindsight.vectorize.io/) 称，它结合了语义、关键词、图和时间检索，并存储心理模型、观察结果和事实，而不是简单的向量缓存。这让当天的记忆讨论不再只是“代理是否应该记住”，而是进一步聚焦于什么样的检索方式和控制界面才可以接受。

**讨论洞察：** 人们积极回应的是连续性和工作流复用，但谨慎态度也立即出现：一条回复将 Computer History 描述为 ChatGPT 在审视用户昨天的工作，而相关文档本身则强调了用户主动选择、排除项，以及不会记录屏幕截图或音频。

**与前一天的比较：** 8 月 12 日的记忆讨论主要局限于代码仓库，并围绕过时的指令文件展开。8 月 13 日，讨论范围扩大到完整工作历史、本地记忆文件，以及根据重复行为生成技能。

### 1.2 Antigravity 成为自定义代理、插件和 Gemini 3.7 Flash 的封装层（🡕）

Antigravity 主导了当天的讨论，而 Gemini 3.7 Flash 同时以模型发布和分发事件的形式出现。将两者联系起来的是封装：基于文件的代理、插件清单、新模型可用性，以及在 shell 之上构建的具体项目。相比 8 月 12 日将自定义代理视为一项功能，8 月 13 日的讨论显示，Antigravity 正逐渐成为模型和扩展的分发表层。

[@antigravity](https://x.com/antigravity) [宣布](https://x.com/antigravity/status/2087611597896224961)（686 个赞、40 条回复、54,516 次浏览、186 次收藏）介绍了 Custom Agents。公开的 [custom agents 博客](https://antigravity.google/blog/introducing-custom-agents) 称，这些文件位于 `.agents/agents/` 或 `~/.gemini/config/agents/` 下，并可对称地作为主代理或委派的子代理运行。配图很重要，因为它展示了一个下拉界面：用户可以直接选择这些角色，而不必面对隐藏的配置。

![Antigravity 自定义 agents 卡片，显示一个主 agent 下拉菜单，其中包含 agent-creator 和 ci-agent 等特定角色条目](https://pbs.twimg.com/media/HPivr3SXUAApyLp.jpg)

[@antigravity](https://x.com/antigravity) [宣布](https://x.com/antigravity/status/2087953243552743525)（646 个赞、48 条回复、18,625 次浏览）介绍了 Antigravity 中的 Gemini 3.7 Flash。Google 公开的 [模型发布公告](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-3-7-flash/) 称，与 3.6 Flash 相比，3.7 Flash 在 DeepSWE v1.1（65.3% 对 49.0%）、FrontierCode 1.1 Main（43.6% 对 34.4%）、WebDev Arena（1588 对 1538）和 AutomationBench（30.4% 对 17.0%）上均有提升。这让 Antigravity 获得了一个成本更低的主力模型，并在编程和代理工作流方面带来公开可见的改进。

![Gemini 3.7 Flash 基准测试图表，对比了每项任务成本以及相对于 Claude、GPT、Muse 和 DeepSeek 模型的 DeepSWE 性能](https://pbs.twimg.com/media/HPnmaL5X0AEh5Ko.jpg)

[@JackWoth98](https://x.com/JackWoth98) [推出](https://x.com/JackWoth98/status/2087594616602103927)（188 个赞、17 条回复、11,965 次浏览、106 次收藏）介绍了一个随 Antigravity 打包的 Gemini API 插件。Google Cloud 公开的 [插件文档](https://antigravity.google/docs/cli/plugins) 将 `plugin.json` 定义为技能、代理、MCP 配置、钩子和规则所需的清单。[@googledevs](https://x.com/googledevs) [分享了](https://x.com/googledevs/status/2087639575623520270)（153 个赞、10 条回复、17,117 次浏览、66 次收藏）介绍了 [Gemma Translator 仓库](https://github.com/google-gemma/gemma-translator)：它借助 LiteRT-LM 和 Moonshine 在 Raspberry Pi 5 上本地运行 Gemma 4，展示了 Antigravity 如何被用于交付具体的离线设备，而不只是演示提示词。

**讨论洞察：** 人们对成本更低的 Flash 模型和可复用的代理文件持积极态度，但最明显的摩擦集中在可发现性和权限控制上：一条关于自定义代理的回复称，下拉菜单是在更新之后才出现；Copilot 的回复则指出，企业管理员必须先启用 Gemini 3.7 Flash，用户才能选择它。

**与前一天的比较：** 8 月 12 日将自定义代理作为新的专业化界面引入。8 月 13 日，这一界面开始汇聚模型发布、插件清单和真实硬件项目。

### 1.3 代理周边的运行层正变得更可视化、更易评审，也支持更多界面（🡕）

最有意思的构建者帖子，并不是在宣称又出现了一个更强的模型，而是在展示围绕现有代理的新控制界面：可视化编辑器、图控制平面、规范优先的命令栈、基于 ACP 的 IDE 切换、可回放会话，以及可复现评估。这延续了 8 月 12 日关于运行层的趋势，但 8 月 13 日的设计更加具体，也更具主张性。

[@charliejhills](https://x.com/charliejhills) [认为](https://x.com/charliejhills/status/2087813340839972961)（23 个赞、12 条回复、2,555 次浏览）称，GitHub 的 [Spec Kit](https://github.com/github/spec-kit) 通过强制按需求、澄清、规划、任务和实现的结构化顺序推进，纠正了“先写代码、后补需求”的倒置流程。[@Alan_Earn](https://x.com/Alan_Earn) [分享了](https://x.com/Alan_Earn/status/2087773787928592398)（24 个赞、10 条回复、370 次浏览、6 次收藏）介绍了 [Airship](https://github.com/0xnyn/airship)。其公开 README 称，该项目会在运行中的开发服务器前放置一个设计画布，用户可以点击元素、描述修改，并让 Claude Code、Codex 或 OpenCode 在本地编写差异。

![Airship 截图，展示了开发服务器前方的实时设计画布，以及编辑检查器和 agent 面板](https://pbs.twimg.com/media/HPlC8dsbcAAP4Xt.jpg)

[@WebStormIDE](https://x.com/WebStormIDE) [推出](https://x.com/WebStormIDE/status/2087898878251028643)（16 个赞、2 条回复、1,150 次浏览）介绍了 WebStorm 中基于 ACP 的代理选择。公开的 [JetBrains 文章](https://blog.jetbrains.com/webstorm/2026/08/the-lsp-moment-for-ai-agents-webstorm-acp/) 称，ACP 让团队能够切换服务商，同时保留本地索引，也不必额外购买 JetBrains AI 订阅。[@airealitynoslop](https://x.com/airealitynoslop) [指出](https://x.com/airealitynoslop/status/2087971516075925705)（3 个赞、1 条回复、35 次浏览、3 次收藏）介绍了 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：它将模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 都作为 Cordis 之上的插件，从而将模块化推进到比普通工具／插件划分更深的层次。

[@codeglitch](https://x.com/codeglitch) [提炼了](https://x.com/codeglitch/status/2087649697674481775)（4 个赞、3 条回复、162 次浏览）用一张图概括了这一层的评审理念：不应由一个代理负责全部步骤，证据应从分诊流向复现、实现和评审。同样的可评审性也出现在 [@s7rthaks](https://x.com/s7rthaks/status/2087763659846193423) [构建](https://x.com/s7rthaks/status/2087763659846193423)（1 个赞、1 条回复、64 次浏览）中：这是一个可复现的基准测试 CLI，在一个容器中运行求解器，再在一个全新的容器中评估补丁。

**讨论洞察：** 从业者最有价值的细节并不在于原始能力，而在于协作成本。一条关于命名 Claude Code 会话的回复称，这种模式确实可行，但代理彼此唤醒并聊天会产生高昂的 token 成本，这进一步说明了显式图、协议和评审阶段的必要性。

**与前一天的比较：** 8 月 12 日显示，运行层正围绕采集、分析和安全逐渐形成。8 月 13 日，这一层进一步落到具体的用户体验上：画布、协议、图、质量门和带有证据的评估闭环。

## 2. 什么让人感到沮丧

### 既有用、又不会让人觉得被侵犯的记忆

这是一个高严重性问题，因为最大的积极信号和最大的质疑都来自同一项功能。[@OpenAIDevs](https://x.com/OpenAIDevs) [宣布](https://x.com/OpenAIDevs/status/2088000960891408677)（1,044 个赞、62 条回复、53,989 次浏览、306 次收藏）介绍了 Computer History 如何帮助 ChatGPT 和 Codex 获取近期工作，但公开的 [文档](https://learn.chatgpt.com/docs/customization/computer-history) 在介绍便利性的同时，也同样强调排除项、删除、本地存储、提示注入风险，以及对敏感应用的同意要求。一条回复用玩笑直白地概括了这种不适：ChatGPT 似乎在审视用户昨天和上周的工作。

同样的技术层面问题也出现在 [@Vectorizeio](https://x.com/Vectorizeio) [定位](https://x.com/Vectorizeio/status/2087623219897672042)（9 个赞、422 次浏览、5 次收藏）对 Hindsight 记忆层的介绍中。正如公开的 [文档](https://hindsight.vectorize.io/) 所述，对于需要时间推理或整合观察结果的问题，简单的向量召回并不够用。人们正在通过加入显式记忆库、排除项和保留规则来应对，而不是完全信任默认聊天窗口。这个方向值得直接投入，因为需求十分明确；但产品必须让范围、来源和删除机制一目了然。

### 单次放手型代理仍然需要评审架构和可重复评估

在构建者帖子中，这是一个高严重性问题，即使相关帖子的互动量并不高。[@codeglitch](https://x.com/codeglitch) [提炼了](https://x.com/codeglitch/status/2087649697674481775)（4 个赞、3 条回复、162 次浏览）将核心抱怨归结为一条规则：不应由一个代理负责全部步骤。[@s7rthaks](https://x.com/s7rthaks/status/2087763659846193423) [构建了](https://x.com/s7rthaks/status/2087763659846193423)（1 个赞、1 条回复、64 次浏览）介绍了一个基准测试 CLI，通过隔离求解和全新的评估流程，避免继续相信退出代码或求解器输出；[@PatrickToulme](https://x.com/PatrickToulme/status/2087961631275786542) [描述了](https://x.com/PatrickToulme/status/2087961631275786542)（11 个赞、10 条回复、1,657 次浏览）则介绍了 AgentSage：它会记录可回放的会话轨迹，并在任何内容离开设备前进行脱敏和密钥扫描。

讨论中也出现了协作成本。[@adocomplete](https://x.com/adocomplete) [展示了](https://x.com/adocomplete/status/2087728817012162973)（8 个赞、2 条回复、334 次浏览、4 次收藏）介绍了可以相互发送私信的命名 Claude Code 会话，但一条回复称，这种设置成本很高，因为代理会浪费上下文彼此聊天、相互唤醒。当前的解决方法，是在代理周边增加门禁、分离角色或使用回放工具。这个方向值得直接投入，因为问题并不是代理什么都做不了，而是团队无法信任它们的工作结果，也无法低成本地验证这些结果。

### 模型可访问性的改善快于部署经济性的改善

这一问题的严重性介于中等和高之间：能力曲线快速上升，但访问仍受政策和硬件限制。[@github](https://x.com/github) [宣布](https://x.com/github/status/2087988626265395417)（91 个赞、16 条回复、24,044 次浏览）介绍了 Copilot 中的 Gemini 3.7 Flash，但公开的 [更新日志](https://github.blog/changelog/2026-08-13-gemini-3-7-flash-is-now-available-in-github-copilot/) 称，企业和商业版管理员必须启用预览政策，用户才能选择该模型。即使是符合条件的计划，Copilot 各界面的发布也仍在逐步进行。

在本地运行这一端，[@burkeholland](https://x.com/burkeholland) [报道](https://x.com/burkeholland/status/2087629748063129872)（67 个赞、13 条回复、8,567 次浏览、19 次收藏）介绍了通过 Ollama 在 GitHub Copilot 应用中运行 Qwen3-Coder 30B，速度约为每秒 85 个 token；但回复很快就集中到 96GB 显存需求和硬件价格上。Antigravity 和 Copilot 帖子中对 Flash 级模型的兴趣，部分源于重试和工具调用的成本，而不只是质量。这是一个值得竞争性投入的方向，因为人们需要在托管、本地和受政策限制的模型之间进行路由，而不必成为基础设施专家。

## 3. 人们希望有哪些东西存在

### 能将重复工作转化为可复用产物的记忆

人们想要的不只是一个能够记住事情的代理，而是一个能将重复工作转化为可复用、可评审成果的代理。公开的 [Computer History 文档](https://learn.chatgpt.com/docs/customization/computer-history) 称，重复工作流可以触发技能或自动化建议；[@OpenAIDevs](https://x.com/OpenAIDevs/status/2088000960891408677) [将其定义为](https://x.com/OpenAIDevs/status/2088000960891408677)（1,044 个赞、62 条回复、53,989 次浏览、306 次收藏）则围绕“从上次中断处继续”和理解工作模式展开。[@Vectorizeio](https://x.com/Vectorizeio/status/2087623219897672042) [支持了](https://x.com/Vectorizeio/status/2087623219897672042) 将这一点与跨代理记忆层联系起来，其公开的 [文档](https://hindsight.vectorize.io/) 明确将记忆建模为 retain、recall 和 reflect。这是一个现实需求，而非理想化设想。机会：直接。

### 经得起工具切换的封装

自定义代理、插件清单、协议适配器和模型发布都指向同一个诉求：只定义一次行为，并在周边工具变化时保持可移植。[@antigravity](https://x.com/antigravity/status/2087611597896224961) [展示了](https://x.com/antigravity/status/2087611597896224961)（686 个赞、40 条回复、54,516 次浏览、186 次收藏）介绍了基于文件的自定义代理；Google Cloud 公开的 [插件文档](https://antigravity.google/docs/cli/plugins) 将 `plugin.json` 作为封装根；[@WebStormIDE](https://x.com/WebStormIDE/status/2087898878251028643) [定位为](https://x.com/WebStormIDE/status/2087898878251028643)（16 个赞、2 条回复、1,150 次浏览）则将 ACP 作为一种方式，让用户无需额外订阅，便可在同一个 IDE 中使用 GitHub Copilot、Claude Code 或任何兼容代理。这个需求既现实又具有竞争性，因为开发者显然希望在 shell、IDE 和服务商之间切换，而不必重写整个运行层。机会：竞争性。

### 将规划、执行、验证和评审分开的编排

几篇帖子使用了不同表述，却汇聚到了同一种期望模式。[@charliejhills](https://x.com/charliejhills/status/2087813340839972961) [描述了](https://x.com/charliejhills/status/2087813340839972961)（23 个赞、12 条回复、2,555 次浏览）介绍了 Spec Kit 如何在编码前强制完成需求、规划和任务拆解。[@tom_doerr](https://x.com/tom_doerr/status/2087789164200657062) [分享了](https://x.com/tom_doerr/status/2087789164200657062)（4 个赞、1,023 次浏览）介绍了 [Pilot Shell](https://github.com/maxritter/pilot-shell)，其公开仓库将 Claude Code 和 Codex 转化为 `/prd`、`/spec`、`/build` 和 `/fix` 工作流，并加入质量门。[@ctrlnodeai](https://x.com/ctrlnodeai/status/2087706719778386048) [构建了](https://x.com/ctrlnodeai/status/2087706719778386048)（3,488 次浏览）介绍了一个图控制平面；[@codeglitch](https://x.com/codeglitch/status/2087649697674481775) [认为](https://x.com/codeglitch/status/2087649697674481775)（4 个赞、3 条回复、162 次浏览）则强调，证据应在步骤之间交接，而不是由一个代理包办一切。这是一个紧迫且直接的需求，因为用户已经在自行拼装编排层。机会：直接。

| [WebStorm ACP](https://blog.jetbrains.com/webstorm/2026/08/the-lsp-moment-for-ai-agents-webstorm-acp/) | IDE 协议／自带密钥（BYOK） | (+) | 无需离开已建立索引的 IDE 即可切换代理，也不需要额外的 JetBrains AI 订阅 | 需要支持 ACP 的代理，并要求认真完成配置 |
| [Spec Kit](https://github.com/github/spec-kit) | 规划工作流 | (+) | 在实现前强制完成需求、澄清、规划和任务拆解；支持广泛的代理集成 | 增加前置流程，对纯粹“输入提示词即开始”的用户吸引力较低 |
| [Airship](https://github.com/0xnyn/airship) | 可视化编辑器／UI 工作流 | (+) | 将设计画布直接置于开发服务器前，并将修改保留在本地 | 仍需权衡不同代理的能力差异和安全模式 |
| [Pilot Shell](https://github.com/maxritter/pilot-shell) | 工作流层 | (+) | 增加规范／构建／修复通道、TDD、质量钩子、记忆共享和本地控制台 | 具有明确主张的运行层，需要单独安装并遵循自身约定 |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | 代理运行框架 | (+/-) | 在模型、工具、会话、存储和 UI 等界面采用一切皆插件的架构 | 仍处于开发者预览阶段，后续将明确进行兼容性破坏性变更 |
| [CTRL NODE](https://github.com/ctrlnode-ai/ctrlnode) | 代理图控制平面 | (+/-) | 提供图画布、混合服务商、仅出站的 Bridge 和实时任务活动 | 处于早期阶段，正在寻找工作流契合点并收集操作人员反馈 |
| [OpenCode](https://opencode.ai/) | 开源代理 shell | (+) | 支持多服务商，持续改进上下文压缩，提供使用统计，并拥有移动客户端生态 | 仍在公开调整压缩、路由和服务商行为 |

满意度呈现出清晰的分化。人们对能够保留上下文、减少重复提示，或让现有代理更易于驾驭的层最为积极：工作历史记忆、更便宜的 Flash 模型、规范优先工作流、可视化编辑器和协议适配器。当这些层带来隐私边界、管理员启用、GPU 成本等新问题，或让人怀疑是否值得运营另一个控制平面时，评价就转为复杂。

迁移模式也很明显。人们没有选择一个通用聊天界面并完全依赖它，而是在多个代理周边增加封装和控制：IDE 中的 ACP、Antigravity 中的插件清单、CTRL NODE 中的图编排、Spec Kit 和 Pilot Shell 中的规范优先流程，以及围绕 OpenCode 的本地／移动扩展。竞争越来越集中于谁能拥有模型周边的运行层，而不仅仅是谁拥有模型本身。

## 7. 机会所在

**[+++] 保护隐私的工作历史与记忆治理** — Computer History 和 Hindsight 都显示出人们对跨会话连续性的强烈需求，但 OpenAI 的文档和回复模式清楚表明，来源排除、删除控制、来源追踪和同意边界都是产品的一部分，而不是可有可无的政策文字。

**[+++] 具有明确结论、可评审的编排** — Spec Kit、Pilot Shell、基准测试 CLI、codeglitch 的评审幻灯片和 AgentSage 都指向同一个缺口：团队需要将规划、求解、检查和发布分成独立阶段，并为每个阶段附上证据的工作流。

**[++] 跨代理封装与协议工具** — Antigravity 自定义代理、`plugin.json`、WebStorm ACP 和 DeepSeek Harness 都将可移植性视为一项首要需求。围绕同一代理包在不同 shell、IDE 和服务商之间进行转换、验证或管理，仍有很大空间。

**[++] 编程代理周边的可视化、图和移动控制界面** — Airship、CTRL NODE 和 OpenCode iOS 客户端表明，终端已不再是代理编程工作的唯一重要界面。机会中等，因为价值已经显现，但这些产品仍处于早期且彼此割裂。

**[+] 本地优先的边缘构建与离线代理体验** — Gemma Translator 以及 Copilot 中的本地模型实验表明，人们仍希望代理和模型能够在自己的硬件上运行。这个方向正在形成，因为已有具体案例，但成本和硬件限制仍将受众范围限制在较小规模。

## 8. 要点

1. **记忆从仓库上下文转向工作历史采集。** OpenAI 发布的 Computer History 将近期应用和网站活动转化为代理可用的上下文，甚至能够建议技能；Hindsight 则从基础设施侧展示了同样的需求。（[来源](https://x.com/OpenAIDevs/status/2088000960891408677)）
2. **Antigravity 的角色从自定义代理功能扩展为封装层。** 8 月 13 日，它承载了自定义代理、Gemini 插件、Gemini 3.7 Flash 以及离线 Gemma 硬件项目，而不再只是一个 UI 界面。（[来源](https://x.com/antigravity/status/2087611597896224961)）
3. **编程代理周边的运行层正变得更加明确，也更加产品化。** Spec Kit、Airship、WebStorm ACP、CTRL NODE、Pilot Shell 和 DeepSeek Harness 关注的都是工作如何被组织、路由和评审，而不仅仅是原始生成能力。（[来源](https://x.com/Alan_Earn/status/2087773787928592398)）
4. **验证和证据正成为差异化因素。** 基准测试 CLI、codeglitch 的评审幻灯片、AgentSage 回放，以及 IronRDP GUI 测试轨迹，都试图让代理输出可供检查，而不只是看起来合理。（[来源](https://x.com/s7rthaks/status/2087763659846193423)）
5. **模型选择如今已无法与分发经济性割裂。** Gemini 3.7 Flash 的势头来自基准提升、广泛发布和更低的工具循环成本；与此同时，本地模型实验仍受到显存成本和政策限制的影响。（[来源](https://x.com/github/status/2087988626265395417)）
