# Twitter AI 编程 - 2026-05-23

## 1. 人们在讨论什么

### 1.1 编程代理正从封闭产品变成可移植的工具框架 🡕

5 月 23 日最明显的变化是，人们谈论编程代理时，越来越把它们视为包裹模型访问能力的可替换外壳，而非某家厂商的唯一终点。最有力的证据来自 OpenAI 自己的 Codex 负责人：他承认，已有相当可观的生产流量运行在其他工具框架上。与此同时，关于 OpenCode 的推广以及围绕 Codex 工作流的帖子，关注点也从模型新鲜感转向了路由、会话和设备控制。

[@thsottiaux](https://x.com/thsottiaux) [表示](https://x.com/thsottiaux/status/2058071172361998482)（302 个赞、56 条回复、6,265 次浏览、33 次收藏）表示，Codex 的生产流量中约 5% 已运行在 Pi 上，另有 5% 运行在 OpenCode 上，并补充说，ChatGPT 账户可以用于“一个蓬勃发展的其他工具集合”。这不是用户间的推测性对比，而是 OpenAI 的产品负责人公开说明：对同一个账户而言，替代性工具框架已经是现实中的使用去向。

[@VaibhavSisinty](https://x.com/VaibhavSisinty) [认为](https://x.com/VaibhavSisinty/status/2058179951304814780)（35 个赞、8 条回复、1,563 次浏览、33 次收藏）表示，OpenCode 本质上是一个免费、开源、类似 Claude Code 的工作流：以终端为原生界面，能读取代码库、编辑文件、运行命令，并连接 Claude、GPT、Gemini、DeepSeek、Qwen、Ollama，以及现有的 ChatGPT Plus、Claude Pro 或 GitHub Copilot 订阅。公开的 [opencode 仓库](https://github.com/opencode-ai/opencode) 将其描述为一款基于终端的编程助手，支持多提供商、会话管理、工具执行、持久化存储和 LSP 集成。

[@airkatakana](https://x.com/airkatakana) [表示](https://x.com/airkatakana/status/2058159363194568776)（28 个赞、3 条回复、1,240 次浏览、6 次收藏）表示：“顺带一提，codex app 能做到这个，而 cli 不行。” 附带截图显示，该应用会对远程实验服务器建立持久 SSH 连接，在复用实时 shell 执行后续步骤前等待 OTP。

![Codex App 截图，显示向远程服务器发起持续 SSH 连接请求，以及一个等待 OTP 的实时 shell](https://pbs.twimg.com/media/HJAM75waQAAnqcu.jpg)

[@hqmank](https://x.com/hqmank) [指出](https://x.com/hqmank/status/2058077682395439467)（11 个赞、2 条回复、1,662 次浏览、4 次收藏）表示，他那篇关于 `/goal` 工作流的帖子获得了 Tibo 点赞；他引用的例子把 Codex App 的 goal mode 描述为一种可跨多个回合持续工作直到完成的方式。重点不只是对某项功能的追捧，而是长时间运行的任务和可复用工作流，已经成为人们比较编程代理的标准之一。

**讨论洞察：** Tibo 帖子下的回复并没有追问哪个基础模型赢了，而是在问：为什么还要停留在单一工具框架里？如果不切换工具，Codex 还是否足够好用？如果 Pi 和 OpenCode 已经能在别处提供 GPT 访问，那 GPT 访问本身到底还有什么意义？

**与前一天对比：** 5 月 22 日的重点还是围绕现有代理搭建共享服务器、聊天桥接和 BYOK 适配层。到了 5 月 23 日，讨论又向前推进了一步：OpenAI 管理层公开承认了平台外的 Codex 流量，而用户则开始比较持久 SSH 会话和 `/goal` 式自主性等应用专属能力。

**与前一天对比：** 5 月 22 日已经出现了针对 Codex 和 Antigravity 的配额消耗抱怨。5 月 23 日则进一步出现了更明确的套餐截图、关于捆绑内容的争论，以及对缓存 token 可见性和七天追踪的直接产品诉求。

### 1.4 Vibe coding 正同时成为一种产品理念和原型习惯 🡒

最后一个反复出现的主题，与其说指向某个具体厂商，不如说指向人们如何为 AI 辅助创作辩护，以及如何实际使用它。证据一部分来自对 vibe coding 的理念性捍卫，另一部分则来自用代理工具做出的具体个人原型。

[@dhh](https://x.com/dhh) [认为](https://x.com/dhh/status/2058066314795614306)（83 个赞、6 条回复、3,651 次浏览）表示，对 vibe coding 反感，与开源的理想并不相容：如果开源意味着让更多人有能力改变软件，那么 AI 辅助编程就应被视为“Open The Gates”，而不是另起门槛的理由。

[@ivanfioravanti](https://x.com/ivanfioravanti) [展示](https://x.com/ivanfioravanti/status/2058285618233274425)（12 个赞、3 条回复、993 次浏览、5 次收藏）展示了一个用 OpenCode 和 `ds4-agent --power 50` 构建的 Wipeout 风格竞速原型。在线程里，他直接贴出了完整的分阶段提示，因此讨论变得异常具体：通过 CDN 引入 Three.js、使用单文件 `index.html`、固定时间步长物理、空气制动、Catmull-Rom 赛道、圈数验证和追尾视角镜头。他还提到，Grok 4.3 在同样的需求说明下失败了，这使得这条帖子更像一次轻量对比测试，而不只是宣传。

[@om_patel5](https://x.com/om_patel5) [分享](https://x.com/om_patel5/status/2057990459981496738)（6 个赞、2 条回复、426 次浏览）介绍了一款名为“Under Training”的浏览器游戏：玩家会像大型语言模型一样经历原始数据摄取、训练、推理和评估。这个概念被形容为“ADHD the game”，但更有实质内容的回复问的是：这个设计是否也捕捉到了上下文窗口滑移和工具调用变异？这说明，即便是更偏玩票性质的 vibe-coded 项目，也开始按其是否诚实呈现代理失败模式来接受评判。

**讨论洞察：** 支持者并不是在说审查已不再重要，而是在主张 AI 辅助创作扩大了“谁能构建”的范围；与此同时，回复又不断把话题拉回验证、信任，以及这些产物能否经得起真实约束。

**与前一天对比：** 5 月 22 日的构建故事大多围绕现有代理之上的封装层、桥接工具和团队控制平面。到了 5 月 23 日，则增加了更多个人实验、更多对 vibe coding 本身的文化性辩护，以及更多借助代理快速产出可玩或可发布成果的例子。

## 2. 什么让人们感到沮丧

### 配额计算和定价依然不透明，足以扭曲购买决策

严重程度：高。让用户沮丧的不只是编程工具要花钱，而是他们仍然搞不清自己到底买到了什么。[@SouthernValue95](https://x.com/SouthernValue95) [写道](https://x.com/SouthernValue95/status/2057950870470324542)（76 个赞、11 条回复、7,370 次浏览、77 次收藏）表示，一名 GitHub Copilot 客户收到的报价是涨价 10 倍，达到每月约 300 美元；发帖者把这件事作为一个粗糙但具体的 AI TAM 模型输入之一。[@adahstwt](https://x.com/adahstwt) [询问](https://x.com/adahstwt/status/2058216650189799451) 直接把“如果只能选一个订阅该买什么”抛成公开问题，而 [@Presidentlin](https://x.com/Presidentlin) [抱怨](https://x.com/Presidentlin/status/2058173859514179730) 则表示，Antigravity 仍未展示缓存 token、百分比或可用的七天视图。[@vikaskansalHQ](https://x.com/vikaskansalHQ) [补充说](https://x.com/vikaskansalHQ/status/2058179019728977929) 则指出，Google 更高付费档位提供 20x AI 用量，而较低档位只有 5x。用户现在的应对方式，是自己手动比价、在社交平台上发起投票，而不是依赖第一方给出的清晰说明。这个问题值得关注，因为它会在用户甚至尚未评估输出质量之前，就先影响产品选择。

### 应用、CLI 和模式边界之间的产品行为仍在持续分化

严重程度：中高。多篇帖子描述的问题并不是模型本身弱，而是功能割裂。[@airkatakana](https://x.com/airkatakana) [表示](https://x.com/airkatakana/status/2058159363194568776) 表示，Codex app 能做到 CLI 做不到的事，并用持久 SSH 截图作为证据。[@Presidentlin](https://x.com/Presidentlin) [表示](https://x.com/Presidentlin/status/2058173859514179730) 表示，Antigravity 2.0 仍然不支持 WSL，结果把他逼回了 IDE。[@anumness](https://x.com/anumness) [写道](https://x.com/anumness/status/2058169648600764773)（24 个赞、6 条回复、1,055 次浏览）表示，Claude 在 Chat、Cowork 和 Code 之间的分裂，使人很难再把它当作一个连贯的聊天应用来看待。当前的应对办法，是维持多套心智模型——一个产品负责聊天，一个负责写代码，一个 shell 负责长任务——但用户正是对这种碎片化日益厌倦。

### 环境输入和语音优先工作流在复杂现实环境里仍会以混乱方式失灵

严重程度：中。[@katienotopoulos](https://x.com/katienotopoulos) [报道称](https://x.com/katienotopoulos/status/2058189843637645806)（6 个赞、4 条回复、1,291 次浏览）表示，Wispr Flow 会不断误录背景声音，并把转写内容写进 Business Insider CMS、Slack 及其他工作界面，其中甚至包括私人争吵和电视对白。她后来又引用 CEO 的说法，把它称作语音转写界的“Final Destination”。这类挫败和配额问题不同：即便模型本身没问题，免手操作的编程工具仍可能引发社交和隐私事故。当前的应对机制只是更小心地按快捷键，而这显然不是长久之计。

## 3. 人们希望出现什么

### 一个能解释所有编程工具额度限制的中立使用量仪表板

最强烈的未满足需求，是一个面向配额和重置时间的控制平面。[@Presidentlin](https://x.com/Presidentlin/status/2058173859514179730) 希望 Antigravity 提供缓存 token 可见性、百分比和七天追踪。[@adahstwt](https://x.com/adahstwt/status/2058216650189799451) 把订阅选择变成公开提问，因为市场仍没有让这些取舍变得足够清晰。[@SouthernValue95](https://x.com/SouthernValue95/status/2057950870470324542) 和 [@vikaskansalHQ](https://x.com/vikaskansalHQ/status/2058179019728977929) 则提供了相关定价和套餐层级的证据，说明这个问题为何重要。机会：直接。

### 能跨工具框架和设备延续的长时任务

信息流反复暗示，用户真正想要的是可持续的工作闭环，而不是又一个聊天框。[@hqmank](https://x.com/hqmank/status/2058077682395439467) 强调了 Codex App 的 `/goal` 工作流，可让任务跨多个回合持续进行；[@airkatakana](https://x.com/airkatakana/status/2058159363194568776) 则展示了能维持持久 SSH 会话的应用界面的价值。[@thsottiaux](https://x.com/thsottiaux/status/2058071172361998482) 进一步确认，替代性的 Codex 工具框架已经承载了真实流量。当前缺失的产品，是一种能在 app、CLI 和第三方 shell 之间跟随用户流转的可移植工作状态，而不是被锁死在某一个界面中。机会：直接且具竞争性。

### 可跨客户端运行的可信、可复用技能与上下文包

支持这一需求的证据异常广泛。[@msdev](https://x.com/msdev/status/2057948984531169427) 把 Build CLI 作为可安装的 Copilot 技能发布，[@_nerdai_](https://x.com/_nerdai_/status/2058225622950780943) 把 skills 定义为跨客户端标准，而 [@kurlyk27](https://x.com/kurlyk27/status/2058120499645894946) 则描述了一个公开挑战赛：skills 文件和 MCP 服务器是扩展编程代理的常规方式。用户已经明确需要这一层。仍然缺失的是，如何以清晰可信的方式在不同厂商之间打包、审计和共享这些模块。机会：直接。

### 一个会持续积累而非反复重置的编程“第二大脑”

[@cyrilXBT](https://x.com/cyrilXBT) [描述](https://x.com/cyrilXBT/status/2058014454529364339)（11 个赞、1 条回复、125 次浏览）把 Claude Code 加 Obsidian 描述为“一个真正了解你的 AI”——知道你的目标、上下文和历史，而不是每次会话都要重新交代的聊天机器人。这不是诗意表达，而是现实需求。它也解释了为什么这么多邻近工具现在都在强调记忆、索引化上下文和可复用工作流。机会：竞争型。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |
|---|---|---|---|---|
| OpenAI Codex | 编程代理 | (+/-) | 心智占位强，具备 `/goal` 工作流，app 可维持远程会话，在对比讨论中仍是参照点 | 用户抱怨 app 与 CLI 存在能力差距，仍被形容为早期产品，并卷入喧闹的定价争议 |
| OpenCode | 开源编程代理 | (+) | 支持 BYOM 路由，可复用现有付费订阅，终端原生工作流，社区关注度持续上升 | 现有证据大多仍是将其相对 Codex 或 Claude Code 来描述，而非把它当成成熟既有玩家 |
| Google Antigravity | 代理 IDE / 运行时 | (+/-) | 可与 NotebookLM 配合使用，Google 捆绑套餐覆盖广，一些用户认为它在真实工作中也能跟上 | 配额不透明，追踪体验弱，且存在 WSL 与 CLI 方面的抱怨 |
| GitHub Copilot | 编程助手 / 工具框架 | (+/-) | 企业存在感强，插件生态丰富，Build CLI 让它具备项目感知的会议搜索能力 | 存在价格冲击类报告，也有人调侃某些“AI 转型”本质上只是买个订阅 |
| Claude Code | 编程代理 | (+/-) | 被视为严肃的工作流界面，激发了重基础设施配置和持久记忆实验 | 价格高到足以主导“只能订一个”时的权衡，而且常与 Claude 的其他产品模式形成尴尬重叠 |
| CodeGraph | 上下文 / 索引工具 | (+) | 预索引知识图谱，公开仓库基准声称成本降低 35%、token 减少 59% | 需要先做索引和配置，且仍需在各个项目中接受真实世界验证 |
| NotebookLM | 研究 / 上下文工具 | (+) | 支持从研究到报告的工作流，是 Antigravity 方案中的有用输入层，并被打包进 Google AI 套餐 | 当天证据主要来自配置展示和捆绑营销，而非中立的生产使用报告 |
| MicrosoftBuild CLI | Copilot CLI 技能 | (+) | 能读取依赖文件、查找相关 Build 会话、基于会话脚手架代码，并与 Learn MCP 集成 | 受活动场景限制且依赖网络，因此更像是对通用编程工具的补充，而非替代 |

整体模式并不是所有人都迁移到单一赢家，而是有选择地叠加使用。用户会依据配额、界面形态以及自己对上下文的控制程度，在 Codex、OpenCode、Claude Code、Antigravity 和 Copilot 之间分配工作。CodeGraph 这类开源基础设施工具之所以走热，是因为它们能减少 token 浪费，却不要求用户切换模型；与此同时，付费套件的竞争也越来越建立在捆绑价值与使用量可见性上，而不只是模型品牌。

最重要的项目层信号，不是人们在创立全新的编程代理品类，而是在现有代理之上搭建狭窄但有用的附加层。Build CLI 把会议内容转成具备项目感知能力的终端上下文；CodeGraph 则把仓库转成可复用图谱，让代理不必每次运行都为相同的探索成本反复付费。

规模更小的构建案例也指向同一方向。Bidsstack 用 Antigravity 做的是实打实的产品迭代，而不是演示式表演；Wipeout 原型则表明，只要能把任务边界收紧，个人开发者已经很乐于使用代理工具完成复杂、分阶段的构建。

## 6. 新动态与值得关注的内容

### 离线、工具增强型代理评测正变得更具体

[@kurlyk27](https://x.com/kurlyk27) [描述](https://x.com/kurlyk27/status/2058120499645894946) 将 SentientAGI 的 Arena Challenge 0 描述为一项离线评测：代理必须在无法联网的条件下，围绕 697 份 Treasury Bulletin 文档回答数值问题，只能使用一个 YAML 配置文件，并可选配 MCP 服务器或 skills bundle。这一点之所以重要，是因为它把编程代理扩展视为一种可在受限环境中衡量的基础设施，而不只是社区惯例。

### Skills 正在成为独立的教育与分发类别

[@_nerdai_](https://x.com/_nerdai_/status/2058225622950780943) 借 Manning 的书籍章节教授 Agent Skills，将其作为一种可互操作标准；与此同时，增长最快仓库榜单也同时抬升了 `academic-research-skills`、`agentmemory` 和 `codegraph`。新的信号不只是人们在构建 skills，而是学习材料、市场分发和排行榜热度开始互相强化。

## 7. 机会在哪里

**[+++] 跨工具使用量与账单可见性** - 订阅投票、套餐截图、Copilot 每席位涨到约 300 美元的说法，以及对缓存 token 和七天追踪的明确要求，都指向同一个缺口：用户仍然无法清楚看见或比较自己真实的编程代理预算。

**[++] 可移植的 goal mode 与远程工作状态** - Codex App 的持久 SSH 案例、`/goal` 工作流帖子，以及 Tibo 对 Pi 和 OpenCode 流量的确认，都表明市场对一种不被困在单一 shell 里的持久工作状态存在需求。

**[++] 安全的技能与上下文分发** - Build CLI、CodeGraph、academic-research-skills 以及 Sentient 挑战赛，都依赖可安装模块、索引化上下文或 MCP 子进程。缺失的一层，是跨客户端的信任、可审计性与可移植打包。

**[+] 会随时间积累的个人编程记忆** - Claude Code 加 Obsidian 的“第二大脑”模式显示出一种正在形成的需求：用户想要的是能记住目标、上下文和既往决策的 AI 编程伙伴，而不是每次会话都从零开始。

## 8. 要点

1. **工具框架正在成为产品本身。** OpenAI 的 Codex 负责人公开表示，已有相当规模的生产流量通过 Pi 和 OpenCode 运行；用户比较的重点也转向了 SSH 持久性和 goal mode，而不再只是模型质量。（[来源](https://x.com/thsottiaux/status/2058071172361998482)）
2. **配额体验如今与原始能力同样影响采用。** 关于订阅选择的讨论、Antigravity 的额度截图和套餐层级比较表明，使用量与重置时间的可见性已成为核心产品要求。（[来源](https://x.com/Presidentlin/status/2058173859514179730)）
3. **技能和索引化上下文已经从建议变成软件。** Build CLI、CodeGraph、市场中的 skills，以及 Sentient arena，都把 skills、MCP 服务器和索引当成可安装的基础设施。（[来源](https://x.com/msdev/status/2057948984531169427)）
4. **Vibe coding 正在产出真实原型，而不只是段子。** Wipeout 风格构建、Bidsstack 的迭代以及可在浏览器中游玩的“Under Training”都表明，人们正在借助代理快速交付或测试具体成果。（[来源](https://x.com/ivanfioravanti/status/2058285618233274425)）
