# Twitter AI 编程 - 2026-09-14

## 1. 人们在讨论什么

### 1.1 人们把 Antigravity 视为执行表面，而不是神秘模型 (🡕)

当天关于 Google 的最强信号，不是什么新基础模型泄露，而是一连串公开纠偏：`antigravity-preview-09-2026` 到底代表什么。4 条彼此独立的高信号内容，都把 Antigravity 描述成一个智能体端点：它有经过沙箱隔离的 Linux 执行环境、浏览器与文件访问、一套分层权限系统，以及很可能已经在铺设的远程工作空间底层管线。这一点之所以重要，是因为讨论焦点已经从“这背后到底是哪套权重？”转向“这个运行时到底能安全做什么？”

[@HarshithLucky3](https://x.com/HarshithLucky3) [提到](https://x.com/HarshithLucky3/status/2099449924916252736)（205 点赞、7 回复、9,266 浏览量），`antigravity-preview-09-2026` “不是模型”，而是“Antigravity 的智能体端点”；它托管在一个带 Linux 沙箱的环境里，具备代码执行、文件和浏览器访问能力，并表示其背后的默认模型是 Gemini 3.8 Flash。配图之所以重要，是因为它把这一说法锚定在 Google 公开的模型表面上，而不只是停留在传言层面。

![Google 对 antigravity-preview-09-2026 的列表截图，这张图成了外界争论它究竟是模型还是智能体端点的依据](https://pbs.twimg.com/media/HSK-k6IacAEMdJt.jpg)

[@Soso_fun_yt](https://x.com/Soso_fun_yt) [发布了](https://x.com/Soso_fun_yt/status/2099528603977544040)（70 点赞、8 回复、39 收藏、9,017 浏览量）一条很长的逆向工程讨论串，认为 Antigravity 2.13.0 已经内置了编译好的 SSH 远程栈，包括 Protobuf `exa.remoting.RemotingService`、能返回 `HTTP 200` 的本地回环端点、SOCKS5 隧道、`~/.ssh/config` 自动发现、堡垒机支持，以及一个隐藏的 `hideRemoteWorkspaceOption` UI 开关。[@meteatamel](https://x.com/meteatamel) [补充了](https://x.com/meteatamel/status/2099454419356012816)（6 点赞、907 浏览量）一篇关联的 Medium 指南，说明 Antigravity 真正的控制表面是一套横跨全局、项目和会话范围的权限层级，并且对文件、网络、浏览器 JavaScript、终端执行、非沙箱命令和 MCP 工具都设有明确规则。

![权限图展示了 Antigravity 在全局、项目、会话三层上的设置，以及针对文件、网络、浏览器、终端和 MCP 的细粒度规则](https://pbs.twimg.com/media/HSLCftjWUAA6OF9.jpg)

**讨论要点：** 真正有价值的回复是在纠偏，而不是欢呼。Philipp Schmid 在 Harshith 的讨论串下回复说，这个条目“和我们在 Gemini API 里的智能体运行框架有关”；另一条回复则称它“是执行表面，不是权重”。而在 Soso 的讨论串下，也有人怀疑“已经在生产环境里”并不等于一定会公开发布，这让猜测始终没有失控。

**与前日对比：** 9 月 13 日已经把运行框架和工作空间视为产品表面；到 9 月 14 日，讨论又进一步下探到 API 命名、权限边界，以及隐藏的远程基础设施。

### 1.2 成本和指令开销开始被量化，而不只是被抱怨 (🡕)

配额压力依然是核心话题，但语气已经从笼统的挫败感转向操作层的测量。4 条保留下来的内容，都给这个问题配上了具体数字：Astra/Codex 用量被快速耗尽、UI 限额与实际行为不一致、指令文件的逐轮成本，以及哪些旧规则现在会在特定模型上反噬自己。这让当天关于成本的主题，不再只是简单的“这东西太贵了”。

[@DanDr1s](https://x.com/DanDr1s) [写道](https://x.com/DanDr1s/status/2099601768237650136)（223 点赞、45 回复、7,998 浏览量），GPT-6 Astra “很惊艳”，但用量限制“快把它掐死了”；他还补充说，Codex 的额度掉得很快，而即使有人愿意多花钱，现在也没有升级到 Pro 的路径。[@iliaa](https://x.com/iliaa) [发帖](https://x.com/iliaa/status/2099494247581864306)（6 点赞、3 回复、483 浏览量）给出了一个传播量更低、但技术细节更强的案例：一次由 Whetstone 驱动的 Antigravity 审查会话，在 Gemini 3.8 Flash 上总共消耗了约 12.59 亿 token，其中约 96% 是缓存读取；即便如此，在已经触发套餐上限报错的情况下，UI 仍显示 5 小时预算还剩 9%。

![用量面板显示 Codex work 用量已耗尽，直观呈现了 Astra 抱怨背后的配额断崖](https://pbs.twimg.com/media/HSNHi7JWIAEfEFC.png)

[@undefinedKi](https://x.com/undefinedKi) [测量了](https://x.com/undefinedKi/status/2099498629153054778)（14 点赞、9 回复、9 收藏、1,012 浏览量）指令文件的逐轮成本，称 Airflow 的 `AGENTS.md` 每轮会额外带来 8,640 个 token，40 轮会话累计就是 345,600 个 token；而在不删减任何规则的前提下，只做规则去重就把这部分开销削掉了 22%。[@Mnilax](https://x.com/Mnilax) [则认为](https://x.com/Mnilax/status/2099537639338602613)（27 点赞、20 收藏、253 浏览量），Astra 的新行为让过去那种“没问清楚就绝不行动”的老规则，真的会变成阻塞项；而按主题组织的技能描述、重复的测试说明，以及“每次编辑前都先读这三份文档”之类的脚手架，现在只会浪费上下文，或在错误的时机把模型带偏。

![论文风格的测量图，展示了一个 8,640-token 的 AGENTS.md 示例，以及 40 轮会话里 345,600-token 的累计成本](https://pbs.twimg.com/media/HSLpKmFWUAEHOsl.png)

**讨论要点：** 回复最终收敛到同一种权宜模式：大部分落地工作交给更便宜的模型，前沿模型留给架构决策或最终审查，同时先把重复指令修剪掉，再考虑为更多配额买单。还有人回复那份 AGENTS 审计时说，他们自己的栈每轮都要带一个 157k 的指南，166 个工具 schema 会让单轮起步就占掉 200k 上下文窗口里的 190k。

**与前日对比：** 9 月 13 日已经把配额和计费摩擦放在报告前列；到了 9 月 14 日，这个主题又往下走了一层，把隐藏成本量化到了 token、缓存读取和重复指令文件的级别。

### 1.3 围绕智能体的加固层正逐渐成为独立产品 (🡕)

另一个强模式是，最具体的构建者投入，落在模型之上的那层纪律系统上：测试框架、技能注册表、行为评估，以及有官方文档支撑的云插件。4 条保留下来的内容，都在描述如何让智能体更容易审查、边界更清晰，或在事后更容易打分评估。这和泛泛宣传“AI 编程有用”相比，是一个很有意义的转向。

[@OpenAIDevs](https://x.com/OpenAIDevs) [分享](https://x.com/OpenAIDevs/status/2099543890286284815)（461 点赞、64 回复、32,766 浏览量）称，Codex 里的 GPT-6 Astra 正在帮助 Perplexity 构建端到端测试框架，并模拟第三方 API 响应。回复之所以有价值，是因为它们立刻指出了这种模式会在哪里失效：有回复认为，纯 mock 的响应会把字段改名、null 值或 429 响应体变化这类问题藏起来，并建议按固定周期录制真实响应，再用 VCR 式方式回放。

[@DuncanRogoff](https://x.com/DuncanRogoff) [推广了](https://x.com/DuncanRogoff/status/2099545413736886591)（1 点赞、259 浏览量）`agent-skills`，并称技能市场里 13.4% 的智能体技能包含严重问题；他把这个项目定位成一个可安装技能的扫描注册表，面向 Claude Code、Copilot、Cursor、Windsurf 等其他智能体。关联的公开仓库写明，该目录基于 TypeScript、按需拉取，并在发布前通过 Snyk Agent Scan 扫描，因此这是当天更具体的供应链回应之一。

![注册表海报突出展示了一项说法：技能市场里 13.4% 的智能体技能包含严重问题](https://pbs.twimg.com/media/HSMVbL6WoAArrPU.png)

[@DanKornas](https://x.com/DanKornas) [介绍了](https://x.com/DanKornas/status/2099543441944228079)（1 点赞、1 回复、1,129 浏览量）Superpowers Evals：一个公开的 [Quorum 仓库](https://github.com/prime-radiant-inc/superpowers-evals)，它驱动真实的编程智能体 CLI，把静态检查和可信的在线评估分开，并把每次运行都隔离在一次性的用户主目录里。[@RRweb3](https://x.com/RRweb3) [则将](https://x.com/RRweb3/status/2099477904866635875)（39 点赞、40 回复、776 浏览量）Google 新推出的 [Google Cloud Developer Plugin](https://cloud.google.com/blog/topics/developers-practitioners/introducing-the-google-cloud-developer-plugin-for-ai-coding-agents) 描述为一种方式：把技能、基于官方文档的接地能力以及安全护栏打包进一个可安装包里，从而避免编程智能体继续对 GCP 认证、项目和命令靠猜。

**讨论要点：** 回复并没有否定这些加固层，而是在收紧“什么样才值得信任”的门槛。在 Google Cloud 插件那条讨论里，最尖锐的回复要求默认只读发现、对变更显式提权，以及能记录实际执行主体的审计日志。

**与前日对比：** 9 月 13 日强调的是打包好的上下文、地图和套件；到 9 月 14 日，这已经变成更偏运维的栈：扫描过的技能注册表、工作流合规评估，以及带有明确护栏的云套件。

### 1.4 厂商开始把路由和模型连接的选择做成显式设置 (🡕)

最像产品更新的厂商动作，都围绕操作控制：谁来选模型，这个选择要花多少钱，以及智能体把 token 发往哪里。2 条保留下来的内容从不同角度把这件事讲明白了，也和开发者整体情绪一致：大家想要的是操纵杆，而不是黑箱。

[@GHchangelog](https://x.com/GHchangelog) [宣布](https://x.com/GHchangelog/status/2099547509840343162)（17 点赞、3 回复、1,717 浏览量），[Copilot 自动模型选择](https://github.blog/changelog/2026-09-14-configure-cost-and-quality-in-copilot-auto-model-selection) 现在在 VS Code、Copilot CLI 和 GitHub Copilot app 里，都显式提供了效率、平衡和智能三个档位。关联的更新日志写明，系统底层依然是从同一个模型池里自动选择，但现在用户可以按单次提示词，把 Auto 偏向更低成本、更平衡的取舍，或更高质量的推理。

[@alperebicoglu](https://x.com/alperebicoglu) [分享](https://x.com/alperebicoglu/status/2099567734631592358)（1 点赞、8 浏览量）称，[ABP Studio 的 AI Agent](https://abp.io/community/articles/bring-your-own-key-use-your-own-ai-models-in-abp-studio-ai-04g19x7f) 已加入 BYOK 支持。关联文章称，Enterprise 用户现在可以让同一个具备 ABP 感知能力的智能体，在内置 AI 与面向兼容 OpenAI 服务、Azure OpenAI 或 Ollama 的提供商连接之间切换，同时保留产品现有的项目感知工具和模型—任务路由表面。

![ABP Studio AI Agent 宣传图，展示了自带密钥支持，以及产品内部具备 ABP 感知能力的执行方式](https://pbs.twimg.com/media/HSMphARXQAAHog_.jpg)

**讨论要点：** 这些并不只是 UI 小修小补。两项更新都在回应数据集中其他地方反复出现的同一个操作层关切：用户希望能明确控制成本、延迟、质量和数据路径，同时又不失去周边工作流表面。

**与前日对比：** 9 月 11 日就已经显示出 Copilot 越来越像一层路由与定价表面；到 9 月 14 日，这种趋势又往前走了一步，把路由档位和提供商连接做成了明确的产品设置。

## 2. 令人困扰的问题

### 配额读数与真实用量对不上

最明确的挫败感在于，人们能看见 Astra 或 Gemini 支撑的工作流质量，却不信任围绕它们的预算表面。[@DanDr1s](https://x.com/DanDr1s) [表示](https://x.com/DanDr1s/status/2099601768237650136)（223 点赞、45 回复、7,998 浏览量），Astra “很惊艳”，但它的用量掉得太快，而且没有一条真正可用的加购路径。[@iliaa](https://x.com/iliaa) [又补上](https://x.com/iliaa/status/2099494247581864306)（6 点赞、3 回复、483 浏览量）一个更技术性的错位案例：在一次由 Whetstone 驱动的代码审查工作负载里，明明套餐上限报错已经出现，UI 却仍显示 5 小时 Gemini 预算还剩 9%。这个问题的严重程度是高，因为人们抱怨的不是抽象的价格敏感，而是在真实工作中觉得“剩余预算”这个显示根本不可信。

回复和相邻的构建者帖子里，也能看到应对策略。有人在回复 DanDr1s 时说，唯一可持续的做法，是把大部分落地工作路由到更便宜的模型上，再把 Astra 留给架构或最终审查。[@TheNwadikeLouis](https://x.com/TheNwadikeLouis) [发布了](https://x.com/TheNwadikeLouis/status/2099444253084529048)（4 点赞、27 浏览量）[tokenmonitor](https://github.com/louisnwadike52-design/tokenmonitor)：一个本地 CLI，会读取 Claude Code、Codex CLI 和 Gemini CLI 日志，在不上传遥测的前提下估算用量和支出。值得为此构建：高，因为挫败感横跨 UI 真实性、超额购买路径，以及自助式可观测性。

### 会烧掉 token 或绊住新模型的指令脚手架

第二类挫败感是，昨天大家还当成“安全”的指令模式，今天可能会悄悄变成操作拖累。[@undefinedKi](https://x.com/undefinedKi) [测量了](https://x.com/undefinedKi/status/2099498629153054778)（14 点赞、9 回复、9 收藏、1,012 浏览量）一个仓库级指令文件，发现它每轮都会带来 8,640 个 token 的成本，而且仅仅删除重复规则，就能在不损失任何行为的前提下把这部分成本降 22%。[@Mnilax](https://x.com/Mnilax) [认为](https://x.com/Mnilax/status/2099537639338602613)（27 点赞、20 收藏、253 浏览量），Astra 现在会把过去那种“没问清楚就绝不行动”的表述当成字面上的停止条件；而按主题组织的技能说明和模板化测试指令，则会让模型加载错误的引导，或者为早就不再需要的引导继续付费。

这个问题的严重程度是中高，因为它会在看不见的地方层层累积。用户可能以为问题出在模型质量或配额规模上，实际卡点却是重复指令、过于宽泛的技能触发，或者已经过时的收工标准。现在可见的权宜办法，是合并重复的指令文件、把技能范围收紧到真正适用的时刻，并用明确权限替代那些一刀切的禁令，只保留对安全工作流真正有帮助的约束。值得为此构建：高，因为只要没人量化，它就会在每一轮里持续吞噬成本。

### 云端访问与远程能力仍然跑在安全边界前面

第三类挫败感是，能力的到来速度快过了控制平面。[@RRweb3](https://x.com/RRweb3) [喜欢](https://x.com/RRweb3/status/2099477904866635875)（39 点赞、40 回复、776 浏览量）Google Cloud 插件为智能体提供官方文档接地能力与工具的想法，但最强的回复立刻追问：它默认是不是只读发现、IAM 权限是怎么收口的，以及它能不能避免凭空杜撰项目状态。[@meteatamel](https://x.com/meteatamel) [展示了](https://x.com/meteatamel/status/2099454419356012816)（6 点赞、907 浏览量）Antigravity 现有权限层到底有多复杂；与此同时，[@Soso_fun_yt](https://x.com/Soso_fun_yt) [则认为](https://x.com/Soso_fun_yt/status/2099528603977544040)（70 点赞、8 回复、39 收藏、9,017 浏览量），原生 SSH 远程基础设施其实已经编译进去了，只是还被一个 UI 开关藏着。

人们的挫败感不是“请再给智能体更大权力”，而是“请把这份权力变得可读、可审查”。他们想要的是清晰的权限范围、可审计性和安全提权流程，而不是运行到一半才发现智能体能做的事比预想更多。值得为此构建：中高，因为这个需求明显且反复出现，但多家厂商也已经在竞速给出部分答案。

## 3. 人们期望的功能

### 诚实的支出控制和真正可用的超额付费路径

最强烈的现实需求，是预算表面要和实际使用体验对得上。[@DanDr1s](https://x.com/DanDr1s) [表示](https://x.com/DanDr1s/status/2099601768237650136)（223 点赞、45 回复、7,998 浏览量），大家愿意为更高的 Astra/Codex 上限付费，但现在做不到；[@iliaa](https://x.com/iliaa) [则展示了](https://x.com/iliaa/status/2099494247581864306)（6 点赞、3 回复、483 浏览量）一个可见剩余预算与实际套餐上限行为发生分歧的案例。这是一个现实且紧迫的需求。[tokenmonitor](https://github.com/louisnwadike52-design/tokenmonitor) 只能部分补上可观测性，但它解决不了产品内部的配额策略或超额购买。机会：直接。

### 按触发条件加载的指令系统，而不是巨大的常驻提示词文件

数据集中反复透露出一种愿望：指令栈应该只在真正有用的时候才加载。[@undefinedKi](https://x.com/undefinedKi) [测量了](https://x.com/undefinedKi/status/2099498629153054778)（14 点赞、9 回复、9 收藏、1,012 浏览量）大型指令文件带来的反复 token 税；[@Mnilax](https://x.com/Mnilax) [则认为](https://x.com/Mnilax/status/2099537639338602613)（27 点赞、20 收藏、253 浏览量），按主题组织的技能和旧式权限措辞，如今会在 Astra 上主动失效。这里真正的诉求，不是抽象意义上的“少一点指令”，而是“在对的时刻加载对的指令，而且别让我每一轮都为死掉的脚手架付费”。Google Cloud 插件那条帖子和 Google 自己的公告，也通过明确提到打包技能可以减少上下文窗口占用，强化了这种模式。机会：直接。

### 既懂文档、也知道何时不该动手的云插件

人们显然希望智能体建立在官方云文档和工具之上，但他们也希望这些智能体不要盲目改动基础设施。[@RRweb3](https://x.com/RRweb3) [把](https://x.com/RRweb3/status/2099477904866635875)（39 点赞、40 回复、776 浏览量）Google Cloud Developer Plugin 描述成一种方式，能减少围绕认证、项目和 `gcloud` 的猜测；但回复立刻要求默认只读发现、写操作显式提权、带主体感知的审计日志，以及比“把整个项目都交给智能体”更紧的范围控制。这是现实需求，不是理想化愿景；而且其紧迫性达到中高，因为能力已经到位，信任模型却仍有争议。机会：竞争性。

### 权限边界清晰可见的原生远程工作空间

[@Soso_fun_yt](https://x.com/Soso_fun_yt) 的逆向工程讨论串[显示](https://x.com/Soso_fun_yt/status/2099528603977544040)（70 点赞、8 回复、39 收藏、9,017 浏览量），Antigravity 用户正在积极寻找一等公民级别的 SSH 远程能力；[@meteatamel](https://x.com/meteatamel) [则梳理了](https://x.com/meteatamel/status/2099454419356012816)（6 点赞、907 浏览量）围绕这种能力的权限模型到底有多复杂。对于那些在无头机器、云 VM 和团队基础设施上工作的人来说，这个需求既现实，也越来越紧迫。今天还没有强有力的证据显示，一个完全可审查的答案已经落地。机会：直接。

## 6. 新动态与亮点

### OpenAI 自己的基础设施案例，成了编程智能体的一个证明点

[@imjustnewatai](https://x.com/imjustnewatai) [总结](https://x.com/imjustnewatai/status/2099589480453927216)（17 点赞、9 收藏、1,098 浏览量）称，OpenAI 那篇关联的存储文章讲的是这样一个故事：两名工程师借助 Codex 和 GPT-5.5，把 Habitat 服务重写成了 Rust。推文称，现在 Habitat 95% 的流量都已运行在 Rust 上，相比 Python 拿到了 6 倍 CPU 效率和 15 倍内存效率；关联的 OpenAI 页面也确认，这个故事属于公司那篇《Rapidly scaling online storage to serve over 1 billion ChatGPT users》文章的一部分。这件事之所以重要，是因为它把“AI 编程可以帮上大型系统”从一句泛泛判断，变成了一个具体的内部基础设施案例。

### 技能供应链问题第一次出现了具体的公开数字

[@DuncanRogoff](https://x.com/DuncanRogoff) [声称](https://x.com/DuncanRogoff/status/2099545413736886591)（1 点赞、259 浏览量），技能市场里的智能体技能有 13.4% 包含严重问题，并把这一点和公开的 [Agent Skills 仓库](https://github.com/tech-leads-club/agent-skills) 绑在一起：这个项目围绕发布前扫描和策展式分发来组织。即便互动量不高，这个数字仍然很显眼，因为它是数据集中少数几个给出明确漏洞比例的说法之一，也和当天其他内容里围绕评估实验室、权限图和安装护栏的更大趋势一致。

## 7. 机会在哪里

**[+++] 具备支出感知能力的智能体运营层** —— 证据横跨第 1、2、4、5 节。[@DanDr1s](https://x.com/DanDr1s) [提到](https://x.com/DanDr1s/status/2099601768237650136)（223 点赞、45 回复、7,998 浏览量），人们愿意为更多 Astra/Codex 容量付费，但做不到；[@iliaa](https://x.com/iliaa) [则展示了](https://x.com/iliaa/status/2099494247581864306)（6 点赞、3 回复、483 浏览量）真实审查工作负载下的 UI 预算错位。[tokenmonitor](https://github.com/louisnwadike52-design/tokenmonitor) 展示了构建者的回应，但更强的机会在于一层产品表面：把真实预算状态、路由选择、超额控制，以及具备审计质量的用量拆解组合到一起。

**[+++] 指令压实与按触发条件收口的引导系统** —— [@undefinedKi](https://x.com/undefinedKi) [测量了](https://x.com/undefinedKi/status/2099498629153054778)（14 点赞、9 回复、9 收藏、1,012 浏览量）指令文件的逐轮成本，而 [@Mnilax](https://x.com/Mnilax) [则认为](https://x.com/Mnilax/status/2099537639338602613)（27 点赞、20 收藏、253 浏览量），旧式限制模式如今会主动干扰 Astra。这个机会之所以强，是因为痛点具有系统性、每一轮都会重复出现，而且目前只被手工清理部分解决。若有工具能审计重复引导、把按主题组织的技能改写成按触发条件组织的技能，并模拟逐轮提示成本，就能正面击中一个显眼缺口。

**[++] 安全的技能与插件供应链** —— [@DuncanRogoff](https://x.com/DuncanRogoff) [抛出了](https://x.com/DuncanRogoff/status/2099545413736886591)（1 点赞、259 浏览量）13.4% 的严重问题说法，[@DanKornas](https://x.com/DanKornas) [则指向了](https://x.com/DanKornas/status/2099543441944228079)（1 点赞、1,129 浏览量）工作流合规评估，而 Google 的 [插件公告](https://cloud.google.com/blog/topics/developers-practitioners/introducing-the-google-cloud-developer-plugin-for-ai-coding-agents) 也明确把插件描述成一种打包关联技能和 MCP 工具的方式。这个机会属于中等强度，因为已经有一些能力不弱的项目存在，但信任问题仍然真实而公开。

**[++] 带显式权限边界的远程执行** —— [@Soso_fun_yt](https://x.com/Soso_fun_yt) [认为](https://x.com/Soso_fun_yt/status/2099528603977544040)（70 点赞、8 回复、39 收藏、9,017 浏览量），Antigravity 已经包含了相当成熟的 SSH 远程底层管线；[@meteatamel](https://x.com/meteatamel) [则记录了](https://x.com/meteatamel/status/2099454419356012816)（6 点赞、907 浏览量）现有权限模型已经有多分层、多复杂。这个机会属于中等强度，因为基础设施显然在推进，但数据集中还没有人展示出一个完整答案，能同时把远程执行、最小权限、可审查性和清晰的 UI 交互都组合起来。

## 8. 要点总结
