## 2. 大家遇到的挫折

### 基于 CLI 的 API 替代方案未必能绕开使用限制

严重程度：中。开发者希望使用 Antigravity 订阅，而不是调用 Gemini API，但回复指出，常规使用限额仍然适用，也有人提出了集成方面的顾虑。小型测试虽能运行，但讨论表明，成本与集成上的取舍依然存在。值得投入开发的程度：中。

### 某模型服务的一次测试需要反复重试

严重程度：低。在一项开发者进行的对比测试中，使用相同的测试框架和提示词，CommandCode GOAT 的一次运行在多次重试后失败，但最终仍生成了可用代码。[@nothingto12](https://x.com/nothingto12) [报告了](https://x.com/nothingto12/status/2114460558758236351)（94 个赞、18 条回复、3,041 次浏览、39 次收藏）只反映了这一次测试结果，不足以据此对服务商进行整体排名。

附图截图记录了一次测试结果：DeepSeek API 耗时 54 分钟 12 秒，以每秒 211 个 token 的速度完成，没有失败调用；OpenCode Go 耗时 1 小时 17 分钟 37 秒，以每秒 159 个 token 的速度完成，失败调用 3 次；CommandCode GOAT 耗时 2 小时 28 分钟 4 秒，以每秒 140 个 token 的速度运行后被标记为失败，失败调用 91 次。

![DeepSeek API、OpenCode Go 和 CommandCode GOAT 的单次运行基准测试对比，展示了运行状态、耗时、吞吐量和失败调用次数](https://pbs.twimg.com/media/HVgPrViXAAAMyHY.jpg)

值得投入开发的程度：低，可将其作为一项可靠性信号纳入可重复的评测。

## 3. 大家希望出现什么

### 一张能持久呈现代码库内部关联的地图

Graphify 的主张是，智能体应该查询一张持久化地图，而不是反复搜索文件，并随着上下文窗口逐渐被占满而丢失线索。它的代码仓库提供了一个可运行的实现，但帖子没有将这种方法与现有的语言专用索引进行比较。机会：竞争型。

### 一个统一管理专用智能体运行框架的控制界面

HarnessRouter 所描述的协调器模式，可以减少分别为每个模型或编程智能体搭建连接的工作，并支持按任务路由。它是一个开源项目，但信息流中没有提供有关其可靠性或部署工作量的独立结果。机会：直接型。

## 7. 机遇所在

**[+++] 跨智能体持久保存项目上下文** - Graphify、可复用的工程技能和 HarnessRouter，从不同方向解决代码仓库信息反复查找、方法重复执行以及工具集成零散等问题。

**[++] 按任务路由模型和运行框架** - 协调器模式和 CLI 实验表明，人们有兴趣根据任务选择工具，但这批内容并未证明不同服务提供商在可靠性或成本方面存在优势。**[+] 明确配额与集成边界** - 无头 CLI 变通方案引发了人们对订阅限制和集成问题的关注，也说明需要有受支持、可预测的方式，将本地应用接入智能体套餐。

## 8. 要点

1. **持久化的仓库上下文是开发者关注的一个重要主题。** Graphify 提出构建可查询的关系图，并明确区分提取出的关系与推断出的关系。[@techNmak](https://x.com/techNmak) [描述了](https://x.com/techNmak/status/2114313618611220950)（85 个赞、45 条回复、3,848 次浏览、92 次收藏）显示，这一做法受到关注。
2. **跨智能体编排正被设计为一层路由机制。** HarnessRouter 的作者介绍了由一个协调器将专业任务分派给不同的独立运行时。[@BrianRoemmele](https://x.com/BrianRoemmele) [概述了](https://x.com/BrianRoemmele/status/2114128789349490731)（98 个赞、30 条回复、8,704 次浏览、146 次收藏）反映出这一工作流受到关注。
3. **复用本地 CLI 并不一定能消除使用限制或集成约束。** 这款应用的实验在小规模测试中奏效，但相关讨论也提到了配额和集成方面的限制。[@ai_for_success](https://x.com/ai_for_success) [分享了](https://x.com/ai_for_success/status/2114413719430340961)（83 个赞、28 条回复、4,995 次浏览、54 次收藏）显示，这项测试引发了关注。
