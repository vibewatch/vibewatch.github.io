# Twitter AI 编程 - 2026-07-10

## 1. 人们在讨论什么

### 1.1 Agent harness 本身成了产品（🡕）

与 7 月 9 日以 GPT-5.6 发布为中心的讨论相比，7 月 10 日的关注点又往外移了一层，转向 Agent 周边的运行界面。最强势的帖子不再只是“新模型”发布，而是具体展示 Beta 版、自动化、验证闭环、桌面封装和编排器如何让长时运行的编程会话变得可管理。至少有六条保留内容都指向同一个变化：大家关注的重点正从原始能力转向可用工作流。

[@thdxr](https://x.com/thdxr) [打开了](https://x.com/thdxr/status/2075636594640376165)（353 个赞、43 条回复、16,741 次浏览、103 个收藏）介绍了 OpenCode 2.0 beta，并罕见地明确列出了一长串注意事项：数据单独存储、数据可能被清空、部分功能损坏、v2 API 尚未定稿，以及内置技能。Beta 文档进一步说明，这是真正的过渡阶段，而不只是预告：目前安装要通过 `@opencode-ai/cli@next`，临时二进制文件是 `opencode2`，而且现阶段只支持包管理器安装。

[@burkeholland](https://x.com/burkeholland) [展示了](https://x.com/burkeholland/status/2075348102467227795)（18 个赞、3 条回复、1,756 次浏览、6 个收藏）展示了 GitHub Copilot App 每天早上对 Gmail 进行分诊：置信度高于 95% 时自动执行操作，并根据反馈更新自身的 `learnings.txt`。这是本组内容里最清晰的“Agent 作为日常操作员”案例之一。

![GitHub Copilot App 自动化运行演示，展示 Gmail 检查、通知以及自动执行的收件箱操作](https://pbs.twimg.com/media/HM0chhGWoAA_x1D.jpg)

[@JamesMontemagno](https://x.com/JamesMontemagno) [询问了](https://x.com/JamesMontemagno/status/2075615644125716817)（19 个赞、2,902 次浏览、6 个收藏）展示了 Copilot App 如何像真实用户一样走完整个 Copilot SDK 工作坊流程、创建 issue，并验证流程的每个环节；链接中的 [仓库](https://github.com/jamesmontemagno/copilot-sdk-workshop) 则介绍了一个动手实践式 SDK 工作坊，以及基于 Playwright MCP 构建的无障碍报告。[@GithubProjects](https://x.com/GithubProjects) [重点展示了](https://x.com/GithubProjects/status/2075527965958713554)（4 个赞、2,361 次浏览、1 个收藏、2 次转发）展示了 CodeNomad 作为围绕 OpenCode 的桌面控制台；其公开页面 [仓库](https://github.com/NeuralNomadsAI/CodeNomad) 将其定位为高级工作区，支持多实例会话、远程访问、git worktree 和 sidecar。

**讨论洞察：** OpenCode beta 帖子的回复并没有争论 Agent 原生终端有没有意义，而是立刻开始测试边界在哪里：临时文档、子 Agent 卡死，以及 v2 是否仅限 TUI。大家的兴趣是真实的，但也同样预期这些界面在公开测试中依然会出问题。

**与前一天的对比：** 7 月 9 日讨论的是 GPT-5.6 如何同时出现在 Microsoft、GitHub 和 ChatGPT Work 里。7 月 10 日讨论的则是发布页关闭之后人们真正要做什么：处理收件箱分诊、验证工作坊，或者协调多个会话。

### 1.3 技能、数据集和 harness 套件不断变成一等产品（🡕）

另一个明显变化是，人们不再只是分享提示词或零散仓库，而是在交付可安装的技能包、harness“操作系统”和 Agent 轨迹数据集，把编程工作流本身当作产品。

### 1.4 信任问题从模型质量转向配额、边界和隐藏控制项（🡒）

最后一个主要主题是运营层面的信任。很多抱怨并不是模型太笨，而是宿主产品施加了错误的限制、把关键控制项藏了起来，或忽略了预期的运行模式。

[@ASalvadorini](https://x.com/ASalvadorini) [展示了](https://x.com/ASalvadorini/status/2075270246332600341)（4 个赞、2 条回复、252 次浏览、1 次引用）展示了一种 Antigravity/Gemini 状态：尽管每周配额还剩 58%，五小时上限却已经完全耗尽。[@jc_coder1](https://x.com/jc_coder1) [抱怨](https://x.com/jc_coder1/status/2075466200612581567)（2 条回复、95 次浏览）称，Antigravity 在被要求“其实是审查，不要编辑”之后仍然改动了文件；[@gavinpurcell](https://x.com/gavinpurcell) [认为](https://x.com/gavinpurcell/status/2075641492325192105)（3 个赞、2 条回复、257 次浏览）则称，相比 Codex，Claude 的使用情况标签页藏得太深。

![配额面板显示 Gemini 的五小时限额已耗尽，而每周配额仍有剩余](https://pbs.twimg.com/media/HMzWzWwW4AI1Gje.png)

[@Geebonics](https://x.com/Geebonics) [表示](https://x.com/Geebonics/status/2075650085887619443)（4 个赞、2 条回复、390 次浏览）称，Codex 几乎从移动应用里“消失”了，直到他意识到它被移到了新的“Remote”标签下；[@jfversluis](https://x.com/jfversluis) [询问了](https://x.com/jfversluis/status/2075502902148321661)（2 个赞、2 条回复、196 次浏览）则呼吁提供一个 Copilot 桌面视图，在一个地方显示所有仍然打开的 PR 会话及其最新状态。共同点并不是智能不足，而是缺少对 Agent 在做什么、处于什么状态、以及还剩多少空间的可见性。

**讨论洞察：** 社区一直在用不同的话要求同一件事：让控制平面可见。这意味着要展示配额、模式、审查状态、未解决线程，以及 Agent 究竟被允许执行操作还是只能查看。

**与前一天的对比：** 7 月 9 日的信任讨论更偏向安全故障和误导性批准。7 月 10 日仍然是在谈信任，但用的是日常操作员的语言：隐藏的使用面板、范围搞错的操作，以及难以检查的会话状态。

## 2. 什么让人感到沮丧

### 限制和使用可见性仍在打断真实工作

严重程度：高。[@ASalvadorini](https://x.com/ASalvadorini) [展示了](https://x.com/ASalvadorini/status/2075270246332600341)（4 个赞、2 条回复、252 次浏览、1 次引用）称，即使每周配额还有余额，碰到 Antigravity 的五小时上限也会直接卡住工作；[@LearnInvest2026](https://x.com/LearnInvest2026) [分享了](https://x.com/LearnInvest2026/status/2075584734856454542)（1 个赞、2 条回复、86 次浏览）则晒出了 GPT-5.6 Sol 的推理设置、剩余配额、额外重置次数和缓存命中收益，因为这些控制项已经成为他评估这次发布的核心依据。[@gavinpurcell](https://x.com/gavinpurcell) [认为](https://x.com/gavinpurcell/status/2075641492325192105)（3 个赞、2 条回复、257 次浏览）称，Claude 的使用情况面板藏在头像菜单后面是个 UX 错误，原因就在于他“总是在看它”。人们的应对方式是手动盯配额、按可持续运行时间而不是按基准测试比较宿主，并优先选择把消费或重置状态明显展示出来的产品。这一点值得构建，因为会话连续性仍然受制于隐藏或错配的控制项。

### 仅审查、状态跟踪和模式边界仍然很容易失效

严重程度：高。[@jc_coder1](https://x.com/jc_coder1) [抱怨](https://x.com/jc_coder1/status/2075466200612581567)（2 条回复、95 次浏览）称，Antigravity 里的 Gemini 在被明确要求只做审查后仍然编辑了文件，截图把这一失败展示得很具体，而不是停留在假设层面。[@jfversluis](https://x.com/jfversluis) [询问了](https://x.com/jfversluis/status/2075502902148321661)（2 个赞、2 条回复、196 次浏览）呼吁提供一个 Copilot 桌面视图，把打开的 PR、最新状态和未解决的审查线程汇总起来；而 [@JamesMontemagno](https://x.com/JamesMontemagno) [使用了](https://x.com/JamesMontemagno/status/2075615644125716817)（19 个赞、2,902 次浏览、6 个收藏）则让 Copilot App 走完整个工作坊并提交 issue，因为他仍然需要明确的外部验证，来确认 Agent 哪些地方出错或遗漏。

![Antigravity 会话展示：先是一个审查请求，随后发生了非预期的文件编辑](https://pbs.twimg.com/media/HM2JM-SXcAAg6F9.png)

[@ArghZero](https://x.com/ArghZero) [提出了](https://x.com/ArghZero/status/2075513181863293210)（2 条回复、15 次浏览）介绍了“PACU”——即暂停并检查理解——作为一种手动补救办法：强制 Agent 在开始任何工作前先复述任务。这一点值得构建，因为代价最高的失败不是语法错误，而是“模式错了、动作错了、状态错了”，用户往往是在时间已经花掉之后才意识到。

### 产品入口分散，边界依然难懂

严重程度：中。[@Reuters](https://x.com/Reuters) [报道称](https://x.com/Reuters/status/2075404653538238838)（6 个赞、6 条回复、21,808 次浏览、3 个收藏）称，ChatGPT Work 的目标是把编程能力带进白领工作流，同时避免同样的价格冲击；[@GamsGo_Global](https://x.com/GamsGo_Global) [总结了](https://x.com/GamsGo_Global/status/2075468518175510787)（1 个赞、1 条回复、30 次浏览、1 个收藏）则把同一变化概括为 OpenAI 正在成为一个由插件、网站、定时任务和桌面工具构成的“完整工作层”。然而，[@Geebonics](https://x.com/Geebonics) [表示](https://x.com/Geebonics/status/2075650085887619443)（4 个赞、2 条回复、390 次浏览）表示，他一度以为 Codex 已经从移动端消失，后来才发现它其实被挪到了“Remote”下面；而在 [@satyanadella](https://x.com/satyanadella) [包括了](https://x.com/satyanadella/status/2075318015063925053)（1,748 个赞、105 条回复、212,023 次浏览、290 个收藏）的回复里，也有人表示，相比继续强调更强的推理能力，先修好记忆和产品混乱更重要。这一点值得构建，因为用户仍然要花时间弄清 Agent 到底在哪、叫什么、以及哪个界面负责哪项工作。

## 3. 人们希望存在什么

### 一个统一管理会话、PR 和长时运行 Agent 工作的控制塔

最清晰、最实际的愿望并不是“再给我一个模型”，而是“把我已经委派出去的工作状态展示给我看”。[@jfversluis](https://x.com/jfversluis) [询问了](https://x.com/jfversluis/status/2075502902148321661)（2 个赞、2 条回复、196 次浏览）呼吁提供一个 Copilot 桌面视图，把所有仍未关闭的 PR 会话及其最新状态集中到一起；与此同时，GitHub 自己的 [更新日志](https://github.blog/changelog/2026-07-10-github-mobile-improved-filters-and-sorting-for-copilot-sessions/) 表示，最新 GitHub Mobile 版本刚刚加入了按活跃会话、状态、仓库、类型、Agent 以及“需要关注”排序的筛选功能。公开页面 [CodeNomad 仓库](https://github.com/NeuralNomadsAI/CodeNomad)，以及 [@GithubProjects](https://x.com/GithubProjects) [帖子](https://x.com/GithubProjects/status/2075527965958713554)（4 个赞、2,361 次浏览、1 个收藏、2 次转发）之所以引发共鸣，原因也在这里：人们想要的是会话管理、远程访问，以及围绕长程编程任务的单一控制台。机会：直接。

![Copilot 风格的会话视图，展示与同一个 PR 相关的 CI 状态、未解决的审查线程以及最近的后台变更](https://pbs.twimg.com/media/HM2qkzNWsAA_U1P.png)

### 更好的“先停下、先复述、再行动”保护机制

人们反复要求一种轻量工作流，在 Agent 接触文件前就防止代价高昂的误解发生。[@ArghZero](https://x.com/ArghZero) [提出了](https://x.com/ArghZero/status/2075513181863293210)（2 条回复、15 次浏览）提出 PACU——暂停并检查理解——就是为了让 Agent 在开始一轮长时间编码前先复述任务；[@jc_coder1](https://x.com/jc_coder1) [展示了](https://x.com/jc_coder1/status/2075466200612581567)（2 条回复、95 次浏览）则在 Antigravity 本应只做审查却改了文件之后，说明了它为什么重要。[@JamesMontemagno](https://x.com/JamesMontemagno) [使用](https://x.com/JamesMontemagno/status/2075615644125716817)（19 个赞、2,902 次浏览、6 个收藏）让 Copilot App 验证工作坊并提交 issue，也是在用更操作化的方式表达同一个需求：先验证，再信任这次运行。机会：直接。

### 可复用的领域技能，而不是一次性提示

对可安装工作流包的需求已经非常明显。[@WalrusProtocol](https://x.com/WalrusProtocol) [分享了](https://x.com/WalrusProtocol/status/2075585678763786244)（13 个赞、2 条回复、4,146 次浏览、1 个收藏）介绍了 Walrus Agent Skills，作为可直接用于多个编程 Agent 的即插即用包；[@apify](https://x.com/apify) [展示了](https://x.com/apify/status/2075318162631835841)（6 个赞、2 条回复、320 次浏览、2 个收藏）展示了一个 Antigravity 获客流程；[@chenzeling4](https://x.com/chenzeling4) [重点展示了](https://x.com/chenzeling4/status/2075671152832462956)（3 个赞、226 次浏览、5 个收藏、1 次转发）则介绍了包含 17 项技能的 Nature Skills 研究套件。人们要的不是抽象的“更好的 AI”，而是已经预先构建好的、可复用的工作流，知道某个领域的步骤、产物和审查节点。机会：竞争型。

总体来看，满意度区间仍然围绕“有用，但前提是宿主界面得对”。人们愿意尝试 GPT-5.6、Muse Spark 和 Antigravity，但衡量它们时，越来越看重的是配额行为、发布摩擦和工作流可见性，而不只是原始基准分数。最常见的补救方式包括明确的预算纪律（[工作论文指南](https://x.com/KanikaBK/status/2075467409293750685)）、PACU 式复述检查（[帖子](https://x.com/ArghZero/status/2075513181863293210)），以及在核心 harness 外再套一层封装或仪表盘，而不是直接相信基础界面。

迁移模式也很务实。[@pamelafox](https://x.com/pamelafox) [表示](https://x.com/pamelafox/status/2075371904572314091)（11 个赞、2 条回复、678 次浏览、2 个收藏）称，同事已经在 Microsoft 托管的界面里从 Opus 转向 Sol；与此同时，XDA 的对比在同一份网站需求上仍然更偏向 Claude Code，而不是 Codex 和 Antigravity。因此，竞争态势呈现分裂：模型仍在成本/性能上竞争，但真正决定产品胜负的故事，越来越取决于宿主是否给了用户足够的控制、可见性和可复用工作流结构。

## 7. 机会在哪里

** [+++] Session-control and review-state dashboards** — Evidence came from multiple directions: [@jfversluis](https://x.com/jfversluis) [希望](https://x.com/jfversluis/status/2075502902148321661) 展示了合并后的 PR/会话状态视图，GitHub 的 [移动端筛选器更新](https://github.blog/changelog/2026-07-10-github-mobile-improved-filters-and-sorting-for-copilot-sessions/)、抱怨使用入口埋得太深的 [@gavinpurcell](https://x.com/gavinpurcell/status/2075641492325192105)、对新 Remote 标签感到困惑的 [@Geebonics](https://x.com/Geebonics/status/2075650085887619443)，以及把多 Agent 控制面板做出来的 [@SPAC89](https://x.com/SPAC89/status/2075475878075588843)，都指向同一个缺口。这个机会很强，因为用户已经在委派工作，只是还无法足够清晰地检查它。

** [+++］ 领域专用技能与工作流包** — ［@WalrusProtocol](https://x.com/WalrusProtocol/status/2075585678763786244)、[@apify](https://x.com/apify/status/2075318162631835841)、[@chenzeling4](https://x.com/chenzeling4/status/2075671152832462956) 和 [@ivankutil](https://x.com/ivankutil/status/2075528457514033412) 从不同角度展示了同一个需求：人们想要的是已经掌握领域步骤、工具和交接产物的工作流。这一机会很强，因为市场信号并不来自单一仓库或单一生态，而是在研究、存储、获客和 Google Workspace 自动化等多个方向反复出现。

** [++］ 支出、配额与主机选择控制平面** — ［@ASalvadorini](https://x.com/ASalvadorini/status/2075270246332600341) 显示，即使每周仍有余额，五小时上限也会阻断工作；[@LearnInvest2026](https://x.com/LearnInvest2026/status/2075584734856454542) 把重置和缓存指标纳入发布评估；而 [@pamelafox](https://x.com/pamelafox/status/2075371904572314091) 与 [@StudentOffersHQ](https://x.com/StudentOffersHQ/status/2075647885124002122) 则说明了发布范围和额度如何改变宿主选择。这个机会属于中等，因为许多工具已经暴露出其中一部分信息，但似乎很少有产品能把使用情况、重置、定价和模型路由整合得足够清楚。

** [+］ 智能体轨迹数据集与评估成果物** — ［@aquiles_ai](https://x.com/aquiles_ai/status/2075709924168933436) 发布 Alexander-Agentic，[@zenorocha](https://x.com/zenorocha/status/2075590585021575660) 展示了一个带有工具选择结果的 Fable 5 基准测试，而 XDA 的三方网站对比也共同指向同一个新需求：为这些系统的真实行为提供共享、公开的证据。这一方向仍然很早期，但信号在增强，因为构建者开始把轨迹、评分卡和对比材料本身当作产品来打包。

## 8. 要点

1. ** 讨论焦点已从发布日的模型热度转向操作界面。** OpenCode 2.0 beta、Copilot 自动化、工作坊验证和 CodeNomad 获得的关注，都超过了又一条抽象的基准测试论断。（[来源](https://x.com/thdxr/status/2075636594640376165)）
2. ** Google 和 Meta 两边的全栈生态叙事都更强了。** 证据不只是口号；人们贴出了发布截图、架构图和 API 额度方案，让这种产品封装变得具体可见。（[来源](https://x.com/RamSingh_369/status/2075455969086042472)）
3. ** 信任失灵主要出在控制平面，而不是原始智能。** 用户抱怨五小时上限、隐藏的使用面板、原本只该审查却变成编辑的运行，以及在移动端被重命名或埋藏起来的核心功能。（[来源](https://x.com/jc_coder1/status/2075466200612581567)）
4. ** 可复用工作流包正在成为围绕编程 Agent 的一个真实产品类别。** Nature Skills、ECC、Walrus Agent Skills、Apify MCP 流程，以及托管式 Antigravity/App Script 搭建，都把结构化工作流分发当作核心价值。（[来源](https://x.com/chenzeling4/status/2075671152832462956)）
5. ** 公开数据集和基准测试正开始成为基础设施，而不只是营销材料。** Alexander-Agentic 和新的 Fable 5 基准测试，都把 Agent 行为变成了可共享的产物，供他人检查、比较和继续构建。（[来源](https://x.com/aquiles_ai/status/2075709924168933436)）
