# Twitter AI 编程 - 2026-10-11

## 1. 大家在讨论什么

### 1.1 信任被移到了代理之外（上升）

Twitter 上关于 AI 编程的讨论反复回到同一个现实问题：怎样才能让代理接触真实代码，又不把整台机器的权限都交给它？最有力的证据并不来自抽象的安全讨论，而是那些已经发布或接近发布的控制层：沙箱执行、企业托管的默认模型、手动启动 MCP，以及可追溯的会话日志。

[@twtayaan](https://x.com/twtayaan) [报道称](https://x.com/twtayaan/status/2109171389051576690)（245 个赞，41 条回复，17,106 次浏览，159 次收藏）表示，Microsoft Execution Containers，也就是 MXC，为代理提供了文件、网络和系统资源的边界，而且这些边界是在代理控制范围之外强制执行的；它还采用了一套可在 Windows、Linux 和 macOS 间共享的 JSON 策略模型。公开的 `microsoft/mxc` 仓库也印证了这条推文的说法：MXC 是一层跨平台的沙箱式代码执行层，在 Linux 上可使用 Bubblewrap 等后端，并且已集成到 GitHub Copilot、Codex、Replit 和 OpenClaw 中，后续还计划支持 Claude Code。

![演讲幻灯片展示了 Microsoft Execution Containers 作为控制层，位于众多代理端点与众多隔离执行目标之间](https://pbs.twimg.com/media/HUSrPpUaAAALs8P.jpg)

[@GHchangelog](https://x.com/GHchangelog) [宣布](https://x.com/GHchangelog/status/2108999788209303689)（12 个赞，1,295 次浏览）表示，JetBrains 版 Copilot 现在提供企业托管的默认模型、快速修复诊断，以及对 MCP 服务器启动的手动控制。[@TheDailyViber](https://x.com/TheDailyViber) [认为](https://x.com/TheDailyViber/status/2109275336865141198)（2 条回复，45 次浏览）表示，Copilot 应用的 OpenTelemetry 能为团队提供模型调用、工具调用、慢速 span 和错误的追踪；当代理留下可疑的 diff 时，这让“它到底做了什么？”从只能靠猜，变成了可供检查的对象。

![宣传追踪图，展示了一个 Copilot 代理会话中的模型调用、工具调用、错误，以及触发调查的差异](https://pbs.twimg.com/media/HUWmvEfWMAAFPjj.jpg)

**讨论洞察：** 这套信任逻辑并不是单向度的。[@spencerclarkdev](https://x.com/spencerclarkdev) [警告称](https://x.com/spencerclarkdev/status/2109307482900201814)（8 条回复，463 次浏览）表示，如果配置不当，Qwen Code、Codex 和 Claude Code 默认输出的 OTel 可能会暴露提示词、文件读取记录、记忆内容，或与邮箱关联的指标。因此，当天关于信任的主题其实是“更多控制”，而不是“默认收集更多数据”。

### 1.2 运行框架与上下文工程成了竞争层（上升）

许多帖子不再只争论哪个前沿模型最好，而是把运行框架的行为、工具加载方式和提示词结构视为真正的性能杠杆。一个共同观点是：同一个模型，外层 shell 如何注入时间、工具和上下文，会决定它看起来是聪明、迟缓，还是浪费。

[@teortaxesTex](https://x.com/teortaxesTex) [认为](https://x.com/teortaxesTex/status/2109365290316230882)（42 个赞，15 条回复，3,804 次浏览，25 次收藏）表示，Claude Code 与 Codex 的差异越来越多地体现在运行框架兼容性上，而不是工具数量。附带的基准表援引了 [@maksym_andr](https://x.com/maksym_andr/status/2109338314067366198)，显示 GPT-6 Astra 对请求工作时长的遵循度远高于 Fable 5.1，而且即使更换运行框架后仍然更强；回复则指出，原因更可能在于时钟重新注入和指令加载，而非前沿模型本身的质量。

![基准测试表，对比了 Fable 5.1、GPT-5.6 Sol 和 GPT-6 Astra 在 Claude Code 和 Codex 测试框架下对请求时长指令的遵循情况](https://pbs.twimg.com/media/HUX4IayWIAAq7iC.jpg)

[@ScarletKc](https://x.com/ScarletKc) [收集了](https://x.com/ScarletKc/status/2109175220833771620)（3 个赞，512 次浏览）从更密集的跨厂商角度阐述了同一个观点：Anthropic 的工具搜索文档称，55K token 的多服务器配置可削减 85% 以上；OpenAI 将工具搜索描述为一种保留缓存的延迟加载；Cursor 表示动态上下文发现将 MCP 工具 token 降低了 46.9%；GitHub 则表示，将 Copilot 默认工具集从 40 个缩减到 13 个后，基准测试成功率提高了 2 到 5 个点。[@OrenMe](https://x.com/OrenMe) [显示](https://x.com/OrenMe/status/2109352078044983331)（3 个赞，55 次浏览，1 次收藏）则把同样的优化放到了提示词层面：VS Code 的实验性 `chat.copilot.stabilityOrderedPrompt.enabled` 设置把稳定指令前移、把会话特定内容后置，在他的两次会话测试中，缓存读取量从 14.5K 提升到 23K，报告的 credits 则从 5.9 降到 1.6。

![VS Code 中 Stability Ordered Prompt 的设置面板，该功能通过重排稳定提示部分和会话特定提示部分来提升缓存复用率](https://pbs.twimg.com/media/HUXsLLTWkAALWn9.jpg)[@ajutqs](https://x.com/ajutqs) [测得](https://x.com/ajutqs/status/2109147629573816497)（3 条回复，65 次浏览）一则来自真实任务日志的相关运行时现象：在 `gpt-6.1-sol` 上运行的 Codex，在关闭 Fast 模式时，输出速度从 10 月 8 日的每秒 19 个 token 提升到 10 月 11 日的每秒 36 个 token；而 Fast 模式对研究、编程和写作任务的帮助，大于那些大多只是在等待页面加载的浏览器任务。

**讨论洞察：** 回复中一直在区分“模型质量”和“harness 质量”。有人在回复 teortaxes 时表示，同一个模型只要换个 shell，就会从表现敏锐变得无所适从；还有人说，精简指令后，同一个模型一夜之间就变得更快也更便宜。

### 1.3 限额、路由不透明与任务连续性影响了采用（上升）

当天围绕产品的争论，与其说是“谁的模型最聪明？”，不如说是“我到底能持续使用什么而不被打断？” 隐藏路由的传言、套餐缩减、5 小时限制，以及失效的线程交接，比基准测试截图更直接地左右了工具选择。

[@0xtoberry](https://x.com/0xtoberry) [指出](https://x.com/0xtoberry/status/2109251998209945954)（115 个赞，27 条回复，7,656 次浏览）一则尚未证实的 Antigravity 路由传言：Gemini 3.8 Flash 对部分用户似乎会被路由到 Argon，而 Gemini 3.1 Pro 在 Antigravity 中似乎会被路由到 3.8 Flash。发帖者明确表示这尚未得到证实，但它之所以引发广泛讨论，恰恰说明用户仍在根据暴露出来的模型 ID 推测发布状态，而不是从厂商那里得到清晰解释。

[@SamPassey3](https://x.com/SamPassey3) [表示](https://x.com/SamPassey3/status/2109088579347677654)（36 个赞，2 条回复，2,447 次浏览，6 次收藏）称，Stanford 的 ChatGPT Edu Pro 用户在合约期中途，原本承诺的 20x Codex + Chat 使用额度被下调为 10x，而附带截图补充了最棘手的细节：如果用户已经用掉每周额度的 50% 或更多，剩余额度可能会被直接降为零。[@Ananth7e](https://x.com/Ananth7e) [认为](https://x.com/Ananth7e/status/2109266037883732096)（80 个赞，26 条回复，3,907 次浏览）称，未来如果 OpenAI 的某个新模型胜出，今天的配额决定会让用户更难受；其附带投票显示，用户略微更偏好“没有 5 小时限制，使用量不变”（38.7%），而不是“有 5 小时限制，每周使用量 2X”（32.4%）。

![Stanford 支持页面摘录称，ChatGPT Edu Pro 的使用额度从 20 倍下调至 10 倍，且部分原本已高频使用的用户失去了其剩余的每周额度](https://pbs.twimg.com/media/HUT84pcaYAATwmJ.jpg)

[@jessepollak](https://x.com/jessepollak) [报道称](https://x.com/jessepollak/status/2109063969931776495)（28 个赞，6 条回复，7,115 次浏览）称，电脑端 Dots 与 Codex 的任务连通性双向都已失效，而所链接的 [GitHub issue](https://github.com/openai/codex/issues/52873) 记录了 Dots 在尝试读取用户创建的 Codex 线程时出现的 placement-version 和 placement-region 错误。有条回复把这种故障称为“不可用”，认为它不适合长期运行的项目工作；而 [@JustLingonberry](https://x.com/JustLingonberry) [询问](https://x.com/JustLingonberry/status/2109387252875014329)（29 个赞，23 条回复，826 次浏览）则在问，是否还有其他人在切换到 Opus 5.5 后，基本已经不再使用 Codex。

**讨论洞察：** 限额和连续性以不同方式打断了工作流，但实际结果是一样的：只要某个平台打断正在进行中的工作的频率高于竞争对手，用户就愿意立刻更换工具。

### 1.4 构建者仍在为智能体叠加新的执行层（上升）

最强的构建者热情并不在新基础模型上，而是在围绕智能体做封装。人们发布了用于逆向工程、演示呈现、多智能体控制、移动端插件、基于 webhook 的研究委派，以及 PR 审查自动化的各类执行层。

[@celineodier](https://x.com/celineodier) [强调](https://x.com/celineodier/status/2109281121749856655)（35 个赞，26 条回复，484 次浏览）REA，一个开源仓库，让智能体可以在本地逆向分析应用行为，并在不需要源代码的情况下“拿出证据”解释功能如何运作。[@DivyanshT91162](https://x.com/DivyanshT91162) [展示了](https://x.com/DivyanshT91162/status/2109202448997040155)（9 个赞，7 条回复，595 次浏览，8 次收藏）称，“用 HTML 回答我”可以把智能体输出的 Markdown 转成独立的 HTML 讲解页，包含图解、对比表格和离线浏览支持，同时还声称在作者的基准测试中，输出 token 约为原来的八分之一，生成速度提升 2.6 倍。

![来自 Answer me with HTML 的对比图：左侧是终端风格的大段文本，右侧是包含丰富图表的单页 HTML 讲解](https://pbs.twimg.com/media/HUVkcd0bAAAXWYO.jpg)[@DanKornas](https://x.com/DanKornas) [描述](https://x.com/DanKornas/status/2109203357101367729)（10 个赞，7 条回复，784 次浏览）提到 ReevesAgents：这是一个基于 tmux 的本地工作区，可让 Claude Code、Codex、Kimi 和 OpenCode 并排运行；以及 [宣布](https://x.com/DanKornas/status/2109169371469775281)（3 条回复，403 次浏览）提到的 Ordewell：一种“规划优先”的编排器，会把改动代码的任务隔离在各自的 worktree 中，只有在出现完成标记后才会放行。[@badlogicgames](https://x.com/badlogicgames) [表示](https://x.com/badlogicgames/status/2109210439015862663)（67 个赞，9 条回复，4,123 次浏览，21 次收藏）称，pi-mobile 现在已支持可热重载的联网插件，以及多用户、多终端支持；与此同时，[@agentnative_](https://x.com/agentnative_) [分享了](https://x.com/agentnative_/status/2109351438862389575)（4 个赞，3 次引用，451 次浏览，5 次收藏）提到一种 webhook 流程，可让 Claude Code 把 X 上的实时调研任务交给 GrokBot，待答案返回后再继续。

## 2. 什么让人感到挫败

### 配额削减和限制设计打断了实际工作

严重性：高。[@SamPassey3](https://x.com/SamPassey3) [表示](https://x.com/SamPassey3/status/2109088579347677654)（36 个赞，2 条回复，2,447 次浏览，6 次收藏）称，Stanford ChatGPT Edu Pro 用户失去了他们原以为已付费购买的 20x 配额，降到了 10x，有时还会失去某个已部分使用周剩余的额度。[@Ananth7e](https://x.com/Ananth7e) [认为](https://x.com/Ananth7e/status/2109266037883732096)（80 个赞，26 条回复，3,907 次浏览）指出，限制设计与总额度同样重要，因为 5 小时上限可能会在任务运行到一半时将其打断；而他发起的投票中，“没有 5h 限制、总用量不变”略微领先于“恢复 5h 限制但提高每周额度”。[@JustLingonberry](https://x.com/JustLingonberry) [询问](https://x.com/JustLingonberry/status/2109387252875014329)（29 个赞，23 条回复，826 次浏览）询问，是否还有其他人在用过 Opus 5.5 后就干脆不再使用 Codex，这表明使用摩擦已经开始转化为切换行为。值得构建：高。

### Dots 和 Codex 的连续性，偏偏在用户最期待长期协助的地方出了问题

严重性：高。[@wynand_schoeman](https://x.com/wynand_schoeman) [总结道](https://x.com/wynand_schoeman/status/2109198971348378110)（52 个赞，13 条回复，401 次浏览）将 DevDay 描述为一次朝着“能跨对话记住上下文的智能体”以及“可在电脑、手机或完全在云端运行的 Codex”推进的发布。可在这样的背景下，[@jessepollak](https://x.com/jessepollak) [报道称](https://x.com/jessepollak/status/2109063969931776495)（28 个赞，6 条回复，7,115 次浏览）称，Dots 既无法管理并非由 Dots 创建的现有电脑任务，也不能可靠地看到由 Dots 创建的任务；其中一条回复还表示，这让产品无法用于驱动许多长时间运行的项目任务。人们的应对方式是退回本地会话、借助第三方控制层，或手动不断催动。值得构建：高。

### 当默认设置不明确时，可观测性依然让人觉得有风险

严重性：中到高。[@TheDailyViber](https://x.com/TheDailyViber) [认为](https://x.com/TheDailyViber/status/2109275336865141198)（2 条回复，45 次浏览）称，当会话出问题时，Copilot 应用追踪可以显示模型调用、工具调用、错误和 diff 上下文——这正是团队所需要的那类证据。但 [@spencerclarkdev](https://x.com/spencerclarkdev) [警告称](https://x.com/spencerclarkdev/status/2109307482900201814)（8 条回复，463 次浏览）指出，Qwen Code、Codex 和 Claude Code 中的默认遥测如果配置不够谨慎，可能会包含提示词、文件读取、记忆内容或与邮箱关联的指标。[@GHchangelog](https://x.com/GHchangelog) [宣布](https://x.com/GHchangelog/status/2108999788209303689)（12 个赞，1,295 次浏览）提到了 JetBrains 的手动 MCP 启动控制，这看起来像是一种应对机制：先收紧运行时控制，再逐步扩大信任。值得构建：高。

### 隐藏的路由和隐藏的 harness 行为，让性能变得难以判断

严重性：中。[@0xtoberry](https://x.com/0xtoberry) [指出](https://x.com/0xtoberry/status/2109251998209945954)（115 个赞、27 条回复、7,656 次浏览）提到一种看似真实、但在 Antigravity 中仍未得到证实的模型路由行为。[@teortaxesTex](https://x.com/teortaxesTex) [认为](https://x.com/teortaxesTex/status/2109365290316230882)（42 个赞、15 条回复、3,804 次浏览、25 次收藏）指出，harness 兼容性的变化，足以改变时间感知和精力调节，进而影响人们对模型质量的主观评价；[@OrenMe](https://x.com/OrenMe) [展示了](https://x.com/OrenMe/status/2109352078044983331)（3 个赞、55 次浏览、1 次收藏）则称，仅提示词顺序的调整，就可能在一次测试中大幅压低报告中的 credits。人们的应对方式包括：观察界面显示出的模型 ID、比较不同 shell 而不只比较模型，以及手动调整上下文顺序。值得构建：中等。

## 3. 人们希望存在什么

### 一层能跨对话、设备和代理延续的连续性机制

最强烈、最实际的需求，并不是一个更聪明的回答框，而是任务在 Dots、Codex、手机、电脑和云端之间流转时，仍能保持连续性而不丢失。[@wynand_schoeman](https://x.com/wynand_schoeman/status/2109198971348378110) 用可记忆上下文和多端 Codex 概括了 OpenAI 自身的产品方向，而 [@jessepollak](https://x.com/jessepollak/status/2109063969931776495) 则展示了这种交接在现实中失效时会有多痛苦。ReevesAgents 和 Ordewell 也从外部部分回应了同样的需求：让本地运行过程可见且结构化；但当天的证据表明，这种连续性依然是碎片化的。机会：直接。

### 既能证明发生了什么、又不过度暴露信息的沙盒与追踪

MXC、Copilot 应用追踪、JetBrains 运行时控制，以及那条关于遥测的警示帖，都指向同一个诉求：让代理的动作可检查，但不要为了获得这种可见性，就要求团队泄露提示词、文件或身份信息。[@twtayaan](https://x.com/twtayaan/status/2109171389051576690) 描述了一种在代理之外强制执行的沙盒，[@TheDailyViber](https://x.com/TheDailyViber/status/2109275336865141198) 展示了会话追踪的价值，[@spencerclarkdev](https://x.com/spencerclarkdev/status/2109307482900201814) 则说明了默认设置为何重要。现有解法虽然存在，但整个工作流仍更像是东拼西凑，而不是一体化方案。机会：直接。

### 可视化、紧凑且可评论的解释方式

[@DivyanshT91162](https://x.com/DivyanshT91162/status/2109202448997040155) 之所以持续吸引关注，是因为它点出了一个真实痛点：代理可以解释一个系统，但答案往往以终端输出的形式倾泻而来。“用 HTML 回答我”之所以存在，是因为一页富含图示的离线页面，比起一长串不断滚动的 Markdown，更易阅读、分享和评论；该项目还声称，把排版工作卸载给 CLI，也能显著减少输出 token。这看起来是实际需求，不只是表现层面的润色。机会：竞争性。

### 自动进行、具备成本意识的 harness 调优

当天出现了异常具体的证据，表明提示词排序、工具搜索、动态上下文发现，以及 harness 的时间注入，都会实质性地改变成本和质量。[@ScarletKc](https://x.com/ScarletKc/status/2109175220833771620)、[@OrenMe](https://x.com/OrenMe/status/2109352078044983331)、[@teortaxesTex](https://x.com/teortaxesTex/status/2109365290316230882) 和 [@ajutqs](https://x.com/ajutqs/status/2109147629573816497) 都指向这样一类优化：大多数用户目前仍需手动摸索。如果有一层系统能按任务自动调优这些选择，就能满足一个活跃且现实的需求。机会：直接。

总体来看，用户对那些提升了控制力、可读性或协同能力的封装工具评价偏正面；而对第一方智能体界面的反馈则较为复杂，因为配额、路由或会话连续性问题仍然存在。迁移压力已经显现：[@JustLingonberry](https://x.com/JustLingonberry) [提问](https://x.com/JustLingonberry/status/2109387252875014329)（29 个赞，23 条回复，826 次浏览）询问大家在试过 Opus 5.5 之后，是否实际上已经停止使用 Codex；而 [@teortaxesTex](https://x.com/teortaxesTex) [认为](https://x.com/teortaxesTex/status/2109365290316230882)（42 个赞，15 条回复，3,804 次浏览，25 次收藏）则指出，模型外层的 shell 仍然解释了这种偏好的一部分原因。

最重要的竞争态势并不是“哪家厂商的基础模型最聪明？”，而是“哪种工作流浪费的 tokens 更少、隐藏的状态更少、打断的任务更少？”工具搜索、提示词排序、沙箱、多智能体规划器和 HTML 渲染，都是对这个更大工作流问题的不同回答。

## 7. 机会在哪里**[+++] 面向长期工作的跨工具连续性与记忆** - Dots 和 Codex 的 bug、DevDay 对云端加手机加电脑工作流的推动，以及 ReevesAgents 和 Ordewell 的流行，都指向同一个缺口：用户需要让任务、上下文和控制状态能跨不同界面延续，而不必依赖脆弱的交接。最佳切入点是一个可检查、可移植且不绑定单一提供商的连续性层。

**[+++] 融合沙箱、追踪与隐私防护的安全执行套件** - MXC、Copilot 应用追踪、JetBrains 启动控制，以及关于遥测警告的讨论帖，都表明市场需要这样一种方案：既能说明“代理始终在这些边界内运行”，又能在不过度泄露信息的前提下给出“这就是证据”。信任工具正在成为一个独立的产品类别。

**[++] 成本感知的 harness 优化** - 工具搜索、动态上下文发现、提示词排序和速度日志都表明，如今许多最大的收益来自会话结构的设计，而不是切换模型。若有产品能按任务自动调优工具加载、缓存友好性和提示词布局，就能满足当前运营者的现实需求。

**[++] 以可检查产物取代终端倾倒输出的结果与审查层** - “用 HTML 回答我”和 Open Code Review 之所以成功，是因为它们把代理的工作转化为人类真正能够评估的东西：渲染后的页面、PR 中的行内评论、有边界的审查摘要。市场仍有空间容纳更多产品，把原始代理输出转换成更适合阅读、审批和审计的格式。

**[++] 具备显式依赖关系与隔离执行能力的多代理规划器** - ReevesAgents、Ordewell、pi-mobile 插件，以及 GrokBot 的 webhook 流程，都将编排视为独立于生成之外的问题。机会最明确的方向，是让协调层把计划可视化、保持代理彼此隔离，并为人类保留一个清晰统一的控制界面。

## 8. 要点

1. **信任栈正在进入产品层。** MXC、JetBrains 运行时控制和 Copilot 会话追踪表明，代理的安全性与可检查性正被封装为产品功能，而不再留给本地惯例解决。
2. **harness 与上下文工程如今已成为首要杠杆。** 围绕工具搜索、提示词排序、时长跟踪和速度测量的公开证据表明，工作流管线对成本和感知质量的影响，已经可以与模型选择本身相提并论。
3. **配额设计与连续性 bug 正在直接塑造采用情况。** Stanford 的方案削减、关于 5 小时限制的投票、Dots/Codex 问题，以及围绕 Opus 5.5 的切换讨论，都说明中断比营销更重要。
4. **开发者正在围绕代理构建封装层，而不是试图超越前沿模型。** 当天最突出的项目集中在逆向工程、HTML 展示、多代理控制、移动插件、PR 审查和 webhook 委派。
5. **最明确的机会在记忆、控制与可检查性。** 凡是某个产品能让代理工作更容易续接、结构化成本更低、运行更安全，或更便于人类审查，相关证据就最为充分。
