# Twitter AI 编程 - 2026-11-19

## 1. 大家在讨论什么

### 1.1 智能体从聊天走向实际工作流 🡕

最有力的一手信号是，智能体正融入持续推进的工程工作流，通过审查和验证循环完成任务，而不是一次性生成代码。[@OpenAIDevs](https://x.com/OpenAIDevs) [描述了](https://x.com/OpenAIDevs/status/2123471880292299171)（755 赞、101 条回复、40,828 次浏览、215 次收藏）介绍了 Codex 的 Performance Factory：它会调查回归问题、提出由工程师审查的修复方案，并检查生产环境中的结果。在相关讨论串中，[@OpenAIDevs](https://x.com/OpenAIDevs) [解释了](https://x.com/OpenAIDevs/status/2123471882858963146)（54 赞、2 条回复、3,865 次浏览）展示了共享的 `perf-forensics` 技能和云端发起的任务如何自动开展调查；随后，[@OpenAIDevs](https://x.com/OpenAIDevs) [详细介绍了](https://x.com/OpenAIDevs/status/2123471884876427328)（52 赞、1 条回复、6,181 次浏览）展示了围绕拉取请求反馈和部署的任务交接。[@OpenAIDevs](https://x.com/OpenAIDevs) [报道称](https://x.com/OpenAIDevs/status/2123471887628140642)（33 赞、1 条回复、5,072 次浏览、29 次收藏）则报告称，在短短三个多月里开展了 1,700 多项调查，并找到了 600 多个根本原因。

GitHub Copilot Evals 将同样强调可重复验证的思路应用于已配置的技能、自定义智能体和 MCP 工具：它会检查结果和步骤，启动前须经批准，并允许用户比较前后两次运行的结果。[@KostyaAI](https://x.com/KostyaAI) [总结了](https://x.com/KostyaAI/status/2123333571993645308)（6 赞、5 条回复、261 次浏览）介绍了公开预览版；[GitHub 的更新日志](https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview/) 则说明了其涵盖范围。

### 1.2 编码工具拓展至更多环境 🡕

桌面端和 IDE 厂商着重介绍了对更多执行环境和模型的支持。[@antigravity](https://x.com/antigravity) [宣布了](https://x.com/antigravity/status/2123476398601908551)（663 赞、30 条回复、18,220 次浏览）宣布其桌面应用原生支持通过 SSH 连接远程服务器。前一天发布的 Gemini 4 Neon 可用性消息 [@antigravity](https://x.com/antigravity) [聚焦于](https://x.com/antigravity/status/2123176067380711725)（407 赞、29 条回复、15,004 次浏览）聚焦模型接入；这次更新则聚焦智能体可以在哪些地方工作。[@windowsdev](https://x.com/windowsdev) [表示](https://x.com/windowsdev/status/2123520282426028096)（13 赞、1 条回复、1,400 次浏览）介绍 Copilot Fusion 可将编码任务分配给开发者 PC 上的本地模型，以减少云端令牌消耗；Microsoft 的 [Ignite 文章](https://blogs.windows.com/windowsexperience/2026/11/17/microsoft-ignite-2026-building-windows-for-the-next-era-of-work/) 提供了产品背景。[@msdev](https://x.com/msdev) [宣布了](https://x.com/msdev/status/2123474202246492217)（14 赞、1 条回复、2,090 次浏览）则介绍了 GitHub Copilot 应用中的 MAI Code 2。

## 2. 人们感到不满的地方

### 行为难以预测，模型归属不明确

一位从业者描述了一个能力出众、却仍然难以使用的模型： [@davis7](https://x.com/davis7) [报道称](https://x.com/davis7/status/2123276731952042403)（55 个赞，5 条回复，4,491 次浏览）描述了行为反复无常、沟通不畅，以及出错后的善后工作。这是一则详细的个人经历，不能据此判断此类情况是否普遍存在。另有 [@NoneNullptr](https://x.com/NoneNullptr) [指出了](https://x.com/NoneNullptr/status/2123288732539515347)（1 个赞，2 条回复，36 次浏览）提到，Codex 聊天中选择的是 GPT-6.2 Astra，但使用记录里显示的却是较旧的模型名称。作者询问实际处理请求的是哪个模型，但帖子并未给出答案。

![Codex 使用记录显示了较旧的模型名称；作者称该对话使用的是 GPT-6.2 Astra](https://pbs.twimg.com/media/HXdvuMfaMAAg2wQ.jpg)

### 提示缓存成本与访问条款变更

[@TekonBurns](https://x.com/TekonBurns) [报道称](https://x.com/TekonBurns/status/2123525121168314876)（20 个赞，2 条回复，2,128 次浏览）称，一则 Codex issue 记录了 GPT-6.2 顶层指令的缓存 token 数为零，以及 Sol 的缓存命中率从 97.4% 降至 46.4%。链接的 [问题](https://github.com/openai/codex/issues/62312) 讨论了这一情况；报告中提到的账单影响，并非经过独立测量的全账户范围结果。另有 [@StatsWire](https://x.com/StatsWire) [表示](https://x.com/StatsWire/status/2123345975464878339)（21 个赞，2 条回复，1,402 次浏览）称，Antigravity 的通知将现有套餐中第三方模型访问权限的计划终止日期推迟至 11 月 30 日，此前公布的日期都更早。这些都是个别报告，但都表明有必要清楚说明用量和套餐变更。

### 启用智能体的代码仓库存在不安全的默认设置

Bitdefender [报道称](https://www.bitdefender.com/en-us/blog/labs/how-ai-agents-become-new-targets-in-github-malware-campaign) 报告了 22 个恶意 GitHub URL，目标是使用 AI 编程助手的开发者。[@yituihi](https://x.com/yituihi) [总结了](https://x.com/yituihi/status/2123273058471330015)（7 个赞，10 条回复，348 次浏览）提及这项警告，并称此次活动影响了 14 个智能体系统。稳妥的做法是审查不可信的代码仓库，并保持审批关卡开启；观察到的样本并不能说明开发者遇到此类情况的频率。

## 3. 人们希望拥有的功能

### 支持实时数据和团队访问的共享应用

**机会：直接。** [@heynavtoor](https://x.com/heynavtoor) [表示](https://x.com/heynavtoor/status/2123425872065786330)（1 个赞，1 条回复，495 次浏览）称，用不同智能体框架构建的工具“没有共享数据，也没有访问控制”，团队成员之间也难以交接；[Deepnote 的 Data Apps](https://deepnote.com/blog/apps) 提供实时笔记本后端、版本历史记录和按人员设置的访问权限。该产品在一定程度上满足了所述需求，但当天的帖子不足以证明它已被更广泛地采用。

### 更安全的无人值守智能体执行

**机会：竞争。** [@chr33s](https://x.com/chr33s) [构建了](https://x.com/chr33s/status/2123276048934842415)（4 个赞，4 条回复，337 次浏览）提到一种代理程序；作者称，它可以通过拦截工具调用，让自己的编程智能体更安全。GitHub Agentic Workflows 也主打只读、 默认在沙箱中运行作业（[仓库](https://github.com/github/gh-aw)）。这些都是具体的解决思路；Bitdefender 的报告则表明，代码仓库的可信度已成为现实问题。现有证据表明问题确实存在，但不足以证明市场需求尚未满足，更不足以判断其规模。

### 减少对智能体的看护，提升进度可见性

**机会：竞争激烈。** [@nishantsingh211](https://x.com/nishantsingh211) [表示](https://x.com/nishantsingh211/status/2123483918368407648)（5 个赞、3 条回复、60 次浏览）表示，同时监督 20 项任务就像一份全职工作，因此开发了 T3 Orchestrator，用于安排并行运行，并仅在必要时请求人工介入。[@dextune](https://x.com/dextune) [描述了](https://x.com/dextune/status/2123302754978537686)（2 条回复、47 次浏览）介绍了一个本地仪表板，用于查看智能体状态、计时器和停滞的任务。这些都只是早期开发者的信号，尚不能证明需求普遍存在。

### 准确追踪模型、配额和成本

**机会：理想化。** [@NoneNullptr](https://x.com/NoneNullptr) [询问](https://x.com/NoneNullptr/status/2123288732539515347)（1 个赞、2 条回复、36 次浏览）在用量标签对不上时，询问某次对话实际由哪个模型提供服务；[@TekonBurns](https://x.com/TekonBurns) [报道](https://x.com/TekonBurns/status/2123525121168314876)（20 个赞、2 条回复、2,128 次浏览）讨论了提示缓存问题，并提出了变通办法。本地模型路由和基准测试成本对比，展现了团队应对相关问题的其他方式，但这些帖子并未证明存在公认的首选方案。

## 6. 新动态与值得关注的内容

### 后训练结果：置信度仍存疑

Handshake 的研究人员 [@jomulr](https://x.com/jomulr) [报道称](https://x.com/jomulr/status/2123545413466931441)（3 个赞，2 条回复，49 次浏览）称，在 mini-swe-agent 测试框架中对 Qwen3.8-Flash-Next 进行 GRPO 后训练后，Terminal-Bench 4 的准确率从 11.6% 提升至 15.7%。[研究文章](https://joinhandshake.com/research/ai/post-training-qwen-terminal-bench-4/) 报告的配对 95% 置信区间包含零，因此这一结果不足以证明性能确有可靠提升。

![Handshake 基准测试图表，对比了 Terminal-Bench 4 的测试结果](https://pbs.twimg.com/media/HXhH8jkbwAAVz3v.jpg)

### 基准讨论仍需结合具体测试解读

一张用户发布的 Artificial Analysis Coding Agent Index 图表 [@MdMannan748890](https://x.com/MdMannan748890) [声称](https://x.com/MdMannan748890/status/2123418860967870739)（6 个赞，6 条回复，63 次浏览）显示，Gemini 4 Neon 得分为 59，Claude Fable 5.2 得分为 58，GPT-6.2 Astra 得分为 53；Neon 的任务成本估算也更低。另一则互动较少的帖子 [@AtSynct](https://x.com/AtSynct) [分享了](https://x.com/AtSynct/status/2123421997778841837)（3 个赞，2 条回复，27 次浏览）展示了一张有利于 Neon 的 CursorBench 排名图表。两则帖子都没有提供足够的方法细节，因此不能将图中的结果视为通用的模型排名；这些说法也不同于第 1 节中的排行榜对比。

## 7. 机遇所在

**[+++] 回归检查与生产环境反馈闭环** — OpenAI 介绍了由工程师审查智能体调查结果、并在部署后进行检查的做法；GitHub Copilot Evals 则提供了可重复运行的技能和智能体测试。两者共同表明，人们需要能让智能体变更可观测、可比较的工作流（[@OpenAIDevs](https://x.com/OpenAIDevs) [报道称](https://x.com/OpenAIDevs/status/2123471880292299171)（755 个赞，101 条回复，40,828 次浏览）；[@KostyaAI](https://x.com/KostyaAI) [描述了](https://x.com/KostyaAI/status/2123333571993645308)（6 个赞，5 条回复，261 次浏览））。

**[+++] 为连接代码仓库的智能体提供更安全的默认设置** — Bitdefender 报告称，有恶意 GitHub 内容针对 AI 编码工作流；开发者则采取了工具调用拦截，以及只读、沙盒化的代码仓库自动化方案。更完善的审查、权限控制， 以及可审计性，既有事故报告为依据，也有相关项目作为支撑（[Bitdefender 报告](https://www.bitdefender.com/en-us/blog/labs/how-ai-agents-become-new-targets-in-github-malware-campaign)；[@chr33s](https://x.com/chr33s) [介绍了](https://x.com/chr33s/status/2123276048934842415)（4 个赞，4 条回复，337 次浏览）；[GitHub Agentic Workflows](https://github.com/github/gh-aw)）。

**[++] 智能体调度与进度可见性**——T3 Orchestrator 的作者表示，监督 20 项任务就像一份全职工作；另一位开发者则展示了用于查看卡住会话的本地仪表板。关键在于减少人工协调，同时保留明确的人工审核与合并节点（[@nishantsingh211](https://x.com/nishantsingh211) [表示](https://x.com/nishantsingh211/status/2123483918368407648)（5 个赞，3 条回复，60 次浏览）；[@dextune](https://x.com/dextune) [分享了](https://x.com/dextune/status/2123302754978537686)（2 条回复，47 次浏览））。

**[++] 共享实时数据的内部应用**——一位从业者明确指出，不同运行框架下构建的工具之间缺少共享数据机制和访问控制；Deepnote 基于笔记本的 Data Apps 提供了一种应对方案。相关证据具体，但仅来自少量讨论样本（[@heynavtoor](https://x.com/heynavtoor) [介绍了](https://x.com/heynavtoor/status/2123425872065786330)（1 个赞，1 条回复，495 次浏览）；[Deepnote Data Apps](https://deepnote.com/blog/apps)）。

**[+] 成本与模型使用情况透明度**——Codex 缓存问题、尚未解决的用量标签差异、本地模型路由以及任务成本基准测试，都表明对可见性和控制能力的需求正日益显现。现有样本无法说明用户更希望获得更完善的账单诊断、本地推理能力，还是套餐层面的调整（[@TekonBurns](https://x.com/TekonBurns) [报道称](https://x.com/TekonBurns/status/2123525121168314876)（20 个赞，2 条回复，2,128 次浏览）；[@windowsdev](https://x.com/windowsdev) [介绍了](https://x.com/windowsdev/status/2123520282426028096)（13 个赞，1 条回复，1,400 次浏览））。

## 8. 要点

1. **智能体正融入实际运营闭环。** OpenAI 描述了由智能体主导的回归问题调查流程，并配有工程师审核和生产环境检查， 在略多于三个月的时间里，报告了 1,700 多项调查和 600 多个根本原因（[@OpenAIDevs](https://x.com/OpenAIDevs) [报道称](https://x.com/OpenAIDevs/status/2123471887628140642)（33 个赞、1 条回复、5,072 次浏览））。
2. **易用性仍与能力相互牵制。**一位从业者展示了 GPT-6.2 Astra 在高难度任务中的输出，同时也谈到其表现时好时坏，还需要后续整理（[@davis7](https://x.com/davis7) [介绍了](https://x.com/davis7/status/2123276731952042403)（55 个赞、5 条回复、4,491 次浏览））。
3. **模型排名若不计入任务成本，就不完整。**Artificial Analysis 的排行榜不仅列出得分，还列出了各模型不尽相同的平均任务成本（[@KratosBrief](https://x.com/KratosBrief) [总结了](https://x.com/KratosBrief/status/2123540213486235852)（1 个赞、2 条回复、65 次浏览））。
4. **团队集成也应成为构建目标。**Deepnote 的 Data Apps、T3 Orchestrator 和本地智能体仪表盘，着眼于共享、调度和会话可见性，而不只是代码生成（[@heynavtoor](https://x.com/heynavtoor) [介绍了](https://x.com/heynavtoor/status/2123425872065786330)（1 个赞、1 条回复、495 次浏览））。
5. **安全性和可观测性仍是现实中的短板。**Bitdefender 报告称，GitHub 上出现了针对编程智能体工作流的恶意内容；与此同时，开发者正为工具调用增加控制措施，并采用沙箱化自动化（[Bitdefender 报告](https://www.bitdefender.com/en-us/blog/labs/how-ai-agents-become-new-targets-in-github-malware-campaign)；[@chr33s](https://x.com/chr33s) [介绍了](https://x.com/chr33s/status/2123276048934842415)（4 个赞、4 条回复、337 次浏览））。
