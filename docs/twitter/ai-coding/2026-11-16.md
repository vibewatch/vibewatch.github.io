### 1.2 Verification now includes checks the agent cannot waive 🡕

Four posts describe related failure modes and controls: a production incident despite green tests, a cross-model check script, a repository verification workflow, and a bounded retry rule. The evidence ranges from one reported failure to workflow advice; it does not establish how prevalent these problems are.

[@PatchOnChain](https://x.com/PatchOnChain) [reported double charges and 500 errors after an agent produced 48 tests and 99.4% coverage](https://x.com/PatchOnChain/status/2122087566774296914) (6 likes, 10 replies, 869 views). The author blamed a mock that asserted against its own stub.

[@elessarqq](https://x.com/elessarqq) [shared a four-file, cross-model setup](https://x.com/elessarqq/status/2122365816725233718) (17 likes, 1 repost, 10 replies, 548 views) and said the decisive part was a check outside the model. Replies described the same “done” claim arriving before the work runs.

[@alexmichael](https://x.com/alexmichael) [summarized Claude Code team verification practices](https://x.com/alexmichael/status/2122458189295665505) (5 likes, 1 reply, 59 views), including a per-repository verify skill, checks selected from a 39-item list, and a human handoff after three failed rounds.

![Verification workflow showing the app being run and checked before a commit](https://pbs.twimg.com/media/HXR8VhCXIAAa_wW.jpg)

[@AISystems_hq](https://x.com/AISystems_hq) [recommended a step-level plan, build, check, and fix loop](https://x.com/AISystems_hq/status/2122459955962024082) (1 reply, 45 views), with a three-attempt cap and a way to record blocked work and continue with independent steps.

![Agent stuck-loop rule showing a retry cap and blocked-work handoff](https://pbs.twimg.com/media/HXR-FRta4AAgcS5.jpg)

**Discussion insight:** A reply to PatchOnChain observed that tests “never left the stub”; a reply to Elessar called an external check the part neither model can argue past.

**Comparison to prior day:** Nov. 15 described checklists and plan review as harness components. Today’s posts add a production failure and concrete verification and retry procedures.

### 1.3 Context and agent handoffs are being made explicit 🡒

Three posts cover separate ways to make an agent workflow repeatable: save instructions as skills, review a written specification in a fresh context, and pass a failing regression test between agents. These are workflow descriptions, not measured evidence that they reduce defects.

[@github](https://x.com/github) [described agent skills as reusable instructions for past decisions and institutional knowledge](https://x.com/github/status/2122425932933959975) (65 likes, 8 reposts, 28 replies, 11,796 views, 56 bookmarks). Replies distinguish portable instructions from portable behavior and ask for shared cross-client tests; another notes the need to delete stale notes.

[@agenticgirl](https://x.com/agenticgirl) [outlined the Elephant-Goldfish Model](https://x.com/agenticgirl/status/2122215592497492278) (1 like, 1 reply, 60 views): a context-rich agent drafts a specification, fresh-context reviewers assess it, and a human approves before implementation. The [Google repository](https://github.com/google/elephant-goldfish-model) describes a cross-agent plugin with codebase documentation and specification-drift checks.

![Elephant-Goldfish workflow diagram showing specification drafting, fresh-context review, and human approval](https://pbs.twimg.com/media/HXK9ynxaYAAjbm-.jpg)

[@googledevs](https://x.com/googledevs) [showed Hydrogen triaging GitHub issues while Carbon handles larger refactors and security checks](https://x.com/googledevs/status/2122449973300298188) (60 likes, 6 reposts, 5 replies, 4,734 views). A reply describes a failing regression test as a useful handoff between those roles.

**Comparison to prior day:** Nov. 15 already covered Elephant-Goldfish as a fresh-context review pattern. Today’s post repeats its design and image; neither post provides outcome measurements.

### 1.4 Specialist-model orchestration is pitched as a way to reduce handoffs and quota 🡕

Google’s Antigravity Orchestrator post describes assigning planning and review to Gemini 4 Carbon and edits and tests to Hydrogen. Google reports 24% lower quota use and 19% faster runs on Terminal-Bench 4.1; a separate practitioner post is positive about Hydrogen but calls Carbon slower and sometimes untrustworthy.

[@koltregaskes2](https://x.com/koltregaskes2) [described the Orchestrator rollout and its reported benchmark results](https://x.com/koltregaskes2/status/2122230438928568689) (11 likes, 1 reply, 444 views). These are Google-reported figures, not an independent replication.

[@thtbee_](https://x.com/thtbee_) [shared a first-hand comparison](https://x.com/thtbee_/status/2122375462970331442) (155 likes, 2 reposts, 25 replies, 3,523 views): Hydrogen felt proactive and fast, while Carbon felt slow and could be untrustworthy; the author said hallucinations were not gone.

**Discussion insight:** The reports separate speed, task assignment, and trust rather than presenting a single model as best for every coding task.

### 1.5 Agent efficiency work spans token use and repository infrastructure 🡒

Two artifacts address different costs of agent-heavy development. TokenEconomizer targets session and tool overhead, while OpenAI’s Pando targets concurrent Git operations; both include concrete benchmark or production claims.

[@alperebicoglu](https://x.com/alperebicoglu) [shared Microsoft’s TokenEconomizer project](https://x.com/alperebicoglu/status/2122217188828586438) (4 likes, 1 repost, 3 replies, 20 views). Its [repository](https://github.com/microsoft/TokenEconomizer) reports 18.4–30.9% lower mean cost across five agent-model combinations on 277 SWE-Bench tasks, with higher Pass@1 in four of five combinations.

![Pando diagram showing Git packfiles and the backend data path](https://pbs.twimg.com/media/HXPtaxgbQAA5izz.png)

**Severity: Medium; one practitioner’s warning.** A post says a broken step can lead an unattended Claude Code run to repeat the same fix instead of finishing later work. ([@AISystems_hq](https://x.com/AISystems_hq) [retry-rule post](https://x.com/AISystems_hq/status/2122459955962024082) (1 reply, 45 views))

**Severity: Medium.** GitHub deprecated Claude Opus 4.8, Claude Opus 5, and GPT-5.6 Terra in most Copilot experiences on Nov. 16 and listed alternatives. ## 3. What People Wish Existed

### Longer or bankable coding-agent usage

Users in one Codex thread explicitly asked for banked usage or removal of the Plus five-hour limit, alongside a new model. A reply says the cap cuts off long tasks; the separate capacity chart suggests one availability measure improved but does not address the requested session window. **Urgency: Medium. Opportunity: Competitive.** ([@JamesMalsawm](https://x.com/JamesMalsawm) [poll](https://x.com/JamesMalsawm/status/2122230689487897008) (39 likes, 35 replies, 2,848 views); [@thsottiaux](https://x.com/thsottiaux) [capacity update](https://x.com/thsottiaux/status/2122206990101536852) (2,517 likes, 798 replies, 162,441 views))

### Completion checks that agents cannot talk around

The reported Stripe incident shows that test count and coverage did not ensure the webhook behaved correctly in production. Another practitioner says the most useful check is outside the model; Claude Code’s described workflow adds repository-level verification and a human handoff after repeated failures. Existing checks partially address the need, but the posts do not compare their effectiveness. **Urgency: High in the reported payment incident. Opportunity: Competitive.** ([@PatchOnChain](https://x.com/PatchOnChain) [incident](https://x.com/PatchOnChain/status/2122087566774296914) (6 likes, 10 replies, 869 views); [@elessarqq](https://x.com/elessarqq) [check setup](https://x.com/elessarqq/status/2122365816725233718) (17 likes, 10 replies, 548 views); [@alexmichael](https://x.com/alexmichael) [Claude Code verification summary](https://x.com/alexmichael/status/2122458189295665505) (5 likes, 1 reply, 59 views))

### Portable agent instructions with shared behavior tests

GitHub’s skills post discusses saving repeatable instructions, while a reply asks for a shared cross-client test set that checks the same task, expected evidence, and stopping behavior. The same discussion notes that portable instructions do not guarantee portable behavior. Skills partially address knowledge reuse; comparable behavior tests remain a direct request. **Urgency: Medium. Opportunity: Direct.** ([@github](https://x.com/github) [agent-skills post](https://x.com/github/status/2122425932933959975) (65 likes, 28 replies, 11,796 views, 56 bookmarks))

### Reusable LLM building blocks for architecture experiments

[@rasbt](https://x.com/rasbt) [asked for an API to make swapping model components less costly](https://x.com/rasbt/status/2122336040899711282) (66 likes, 6 reposts, 11 replies, 3,239 views), naming examples such as GQA versus MLA and dense FFNs versus MoE. The attached diagram illustrates the components; a reply supports the switching-cost complaint but warns that a shared abstraction could flatten the lowest-level use cases.

![Diagram of interchangeable LLM building blocks and architecture components](https://pbs.twimg.com/media/HXQNCyAW8AAebT6.jpg)

The author names existing projects such as torchtitan, torchtune, Megatron Core, and OLMo-core, while saying they do not provide the desired level of abstraction. **Urgency: Medium. Opportunity: Aspirational**, because the thread describes a significant engineering and adoption challenge rather than a ready-made product request.
