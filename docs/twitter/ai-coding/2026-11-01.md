The [Microsoft Research paper](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/) describes APEC, which moves summaries off the critical path and reports up to 25.4% lower total cost and 9.6% less agent execution time.

## 2. What Frustrates People

### Agent “done” does not guarantee a correct result

**Severity: Medium.** In the Gemini 3.8 Flash thread, one developer replied that the model failed a small, clearly prompted task, while DeepSeek V4.1 Flash completed and tested it with the same prompt; the original post relayed a much more positive daily-use report [thread](https://x.com/Its_lakshya_ai/status/2116877694424039662) (191 likes, 46 replies, 14,783 views). On wicked-studio, replies noted that transcripts and diffs show what an agent did but not whether it met the task’s acceptance criteria; the author recommended writing those checks before a run [discussion](https://x.com/DanKornas/status/2116818195776467080) (26 likes, 38 replies, 1,377 views). The day’s evidence is mixed, but does show the need to verify outcomes rather than accept confident completion messages. **Worth building for:** yes, especially for testable acceptance criteria and approvals tied to the exact reviewed change.

### Model access and usage limits are hard to predict

**Severity: Medium.** A Jio bundle user may have Google AI Pro in name but still lack Argon in Antigravity; replies described confusion when the same account has different model availability in Gemini web and the coding workspace: [thread](https://x.com/StatsWire/status/2116764563836141981) (181 likes, 25 replies, 14,929 views), with [Google’s model matrix](https://antigravity.google/docs/models) documenting access tiers. Separately, users questioned how much ChatGPT/Codex capacity will be shared and whether heavier models will drain it faster; the new policy says usage is token-based but does not publish plan totals in the announcement: [thread](https://x.com/hiarun02/status/2116765734424699120) (36 likes, 24 replies, 823 views), and the [OpenAI Help Center](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits) explains the policy. **Worth building for:** yes, through clearer entitlement checks and per-task usage estimates before users commit to a long run.

### Long sessions expose cache and compaction costs

**Severity: Medium.** The public Copilot trace shows cached prompt share dropping from 59.6% just before five minutes to 26.1% just after; Microsoft’s separate study says the 7.8% of sessions that compacted consumed 44.2% of tokens ([cache analysis](https://siddhantkhare.com/writing/coding-agent-cache-five-minutes); [Microsoft Research](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/)). These are measured cost and latency signals, not proof that every harness behaves the same way. **Worth building for:** moderate to high for long-running agents, where cache-aware continuation and background compaction can reduce wasted work.

## 3. What People Wish Existed

### Task acceptance checks that remain valid after an agent edit

The practical need is not another transcript, but a check that proves the task was met and is still tied to the exact code the user approved. wicked-studio already surfaces diffs, transcripts, and approval gates, but its author had not verified whether later edits force a fresh review; replies also noted that acceptance criteria are still the user's responsibility in the [discussion](https://x.com/DanKornas/status/2116818195776467080) (26 likes, 38 replies, 1,377 views). **Opportunity: Direct.** An approval flow that binds tests and user-defined acceptance checks to a versioned diff would address this gap.

### Team memory for rejected decisions, with scope

RoBrain’s pitch is to carry decisions and rejected alternatives across agents and sessions, so teams do not repeatedly revisit a settled choice. Its [project post](https://x.com/DanKornas/status/2116682206122766587) (14 likes, 30 replies, 759 views) links to the [repository](https://github.com/adelinamart/robrain). Replies pointed out that an `AGENTS.md` section can cover simpler cases and that a decision rejected for one service should not automatically apply everywhere. **Opportunity: Competitive.** A useful product needs scoped, reviewable memory rather than a global “never suggest” list.

### Predictable usage budgets before a long run

One user explicitly asked OpenAI to publish the shared ChatGPT/Codex allowance before rollout, noting that heavy chat use could reduce coding capacity in this [request](https://x.com/RyanYanBuilds/status/2116710069589123506) (2 likes, 2 replies, 73 views). The [OpenAI Help Center](https://help.openai.com/en/articles/20001625-understanding-chatgpt-and-codex-usage-limits) explains shared metering and reset visibility, but the reported plan change does not give a per-plan token amount. **Opportunity: Direct.** Pre-run estimates, clear remaining balances, and predictable reset guidance would reduce uncertainty.

## 7. Where the Opportunities Are

**[+++] Verifiable agent completion.** EGM, Spec Kit, and wicked-studio all put design, review, or evidence around code generation; replies on wicked-studio specifically ask for acceptance checks tied to the reviewed diff. The [wicked-studio discussion](https://x.com/DanKornas/status/2116818195776467080) (26 likes, 38 replies, 1,377 views) and [EGM discussion](https://x.com/stretchcloud/status/2116625003277881615) (111 likes, 5 replies, 10,416 views) support a product that links task criteria, tests, and approval to a versioned change.

**[++] Scoped memory for decisions and context.** RoBrain targets repeated rejected decisions, while the cache and compaction work targets repeated prompt/context cost. The [RoBrain post](https://x.com/DanKornas/status/2116682206122766587) (14 likes, 30 replies, 759 views) and [cache analysis](https://siddhantkhare.com/writing/coding-agent-cache-five-minutes), alongside the [APEC paper](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/), inform this opportunity. Simple repository notes already serve some teams, so value depends on reliable scope and carry-over rather than another generic memory store.

**[++] Budget-aware agent operation.** OpenAI’s shared ChatGPT/Codex pool, the five-minute cache drop, and TokenEconomizer’s benchmark each expose a different cost lever: the [OpenAI usage update](https://x.com/hiarun02/status/2116765734424699120) (36 likes, 24 replies, 823 views) and [TokenEconomizer discussion](https://x.com/ragnarh/status/2116862603242659869) (10 likes, 7 replies, 764 views). Clear pre-run estimates, cache-aware scheduling, and reversible repo-specific optimizations have concrete evidence behind them.

**[+] Multi-harness integration.** HarnessRouter’s API and EGM’s documented support across several coding agents show builders working to avoid one-off integrations. [HarnessRouter’s post](https://x.com/agenticgirl/status/2116940912395981307) (2 likes, 4 replies, 164 views) links to the [EGM repository](https://github.com/google/elephant-goldfish-model). This is an emerging builder signal rather than a demonstrated end-user demand trend.

## 8. Takeaways

1. **Agent workflows are expanding into research and task management.** DeepMind’s Antigravity protein workflow has a candidate in wet-lab validation, while “Chief of Stuff” remains an unreleased report. [Antigravity](https://x.com/antigravity/status/2116952756342677919) (623 likes, 18 replies, 23,207 views) and [TestingCatalog](https://x.com/testingcatalog/status/2116885887313133576) (461 likes, 112 replies, 23,456 views) describe those developments.
2. **Specification and verification are becoming product features, not just prompt habits.** EGM, Spec Kit, and wicked-studio each formalize a different pre-build or review step; replies still place acceptance criteria and final judgment with the user. The [EGM post](https://x.com/stretchcloud/status/2116625003277881615) (111 likes, 5 replies, 10,416 views) and [wicked-studio post](https://x.com/DanKornas/status/2116818195776467080) (26 likes, 38 replies, 1,377 views) illustrate the approach.
3. **Usage predictability is both a product and infrastructure problem.** A shared plan allowance changes how users budget, while cache retention and context compaction affect how many tokens long sessions consume. The [OpenAI usage discussion](https://x.com/hiarun02/status/2116765734424699120) (36 likes, 24 replies, 823 views), [cache analysis](https://siddhantkhare.com/writing/coding-agent-cache-five-minutes), and [Microsoft Research paper](https://www.microsoft.com/en-us/research/publication/benchmarking-long-horizon-agent-context-compaction-with-compactionbench/) cover these layers.
4. **Treat new model-version reports as telemetry, not launches.** Codex screenshots show a `gpt-6.2-astra` label, but the public OpenAI model directory lists GPT-6 Astra only. One [user report](https://x.com/TokenGremlin/status/2116834891744600291) (128 likes, 16 replies, 5,306 views) conflicts with the public [model directory](https://developers.openai.com/api/docs/models).
