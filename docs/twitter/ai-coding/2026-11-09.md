# Twitter AI Coding - 2026-11-09

## 1. What People Are Talking About

### 1.1 Make planning and review separate agent jobs (↗)

The strongest process signal was to make a plan or specification before implementation, then expose it to a reviewer that has not inherited the drafting conversation. Google’s open-source Elephant-Goldfish Model (EGM) assigns full project context to the drafting agent and fresh context to reviewers; the developer resolves trade-offs and approves the design. The same day’s posts also show contrasting practice: one developer keeps tasks small and reviews diffs manually, while another reports a multi-model review pipeline.

[@oliviscusAI](https://x.com/oliviscusAI) [described](https://x.com/oliviscusAI/status/2119745987744772191) (44 likes, 20 replies, 2,483 views) EGM’s two roles and linked the [public repository](https://github.com/google/elephant-goldfish-model). Its documentation says fresh subagents review the draft and referenced material, and that human approval and tests remain necessary.

[@johan_builds](https://x.com/johan_builds) [illustrated](https://x.com/johan_builds/status/2119528808890134625) (4 likes, 3 replies, 152 views) the three-role boundary: an Elephant drafts with project context, Goldfish reviewers see the draft without the chat, and the developer approves before code. The images make the separation explicit:

![EGM workflow card describing an Elephant that plans with context and a Goldfish that reviews with fresh context](https://pbs.twimg.com/media/HWoUGwQbMAAxLOh.jpg)
![EGM roles: project-context drafting, fresh-context review, and developer approval](https://pbs.twimg.com/media/HWoUGwQaMAAMmxZ.jpg)

[@esrtweet](https://x.com/esrtweet) [described](https://x.com/esrtweet/status/2119843690403242404) (189 likes, 21 replies, 4,529 views) a simpler supervised alternative: Codex in a terminal, small tasks, local Qwen as a fallback, and manual diff review before commits. By contrast, [@kevintheo](https://x.com/kevintheo) [reported](https://x.com/kevintheo/status/2119786737366917286) (1 like, 3 replies, 118 views) 418 rounds of four-model code review, followed by Claude trying to reproduce each finding. The author says no human checked the verdicts and the log cannot count bugs all four reviewers missed, so these are personal workflow statistics, not a model benchmark.

![Self-reported counts of confirmed hints from four code reviewers, with the author’s no-human-check caveat](https://pbs.twimg.com/media/HWr-tqhWQAA961Z.jpg)

**Discussion insight:** Replies to the EGM post questioned whether a person still approves the work. The repository says the developer owns the architectural decisions and that review does not replace tests or human judgment.

**Comparison to prior day:** Google’s EGM announcement was already prominent on November 8. The next day’s discussion added examples of how fresh-context review fits alongside individual review habits and model ensembles. [@GoogleCloudTech](https://x.com/GoogleCloudTech) [announced](https://x.com/GoogleCloudTech/status/2119203243054023129) the plugin (426 likes, 22 replies, 23,738 views).

### 1.2 Agent work is moving across devices, modes, and interfaces (↗)

Several separate announcements focused on where an agent runs and how people resume or steer it. [@_samirism](https://x.com/_samirism) [reported](https://x.com/_samirism/status/2119884573190545726) (376 likes, 71 replies, 13,984 views) that users can connect multiple computers to a desktop Codex “dot.” Google announced both voice-driven coding and remote agents that can build, test, and prepare pull requests in isolated cloud environments. GitHub’s Copilot app-session handoff brings the task, plan, conversation, and code changes into VS Code. Antigravity also introduced a research-and-writing layout that keeps its agent harness, plugins, and MCP tools while removing terminal and Git clutter.

### 1.3 Local inference and durable execution address different constraints (↗)

The local-inference path is represented by Foundry Local running Qwen3.8-27B through GitHub Copilot. Microsoft’s [article](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/) describes a hybrid workflow: keep everyday work local and send harder problems to the cloud. Its published setup says 4-bit weights take about 18 GB, a 24 GB NVIDIA GPU supports up to 64K context, and 32 GB or more can support up to 262K. The cited hardware and model requirements make this a specific option, not a general desktop baseline.

[@arcbang_xyz](https://x.com/arcbang_xyz) [summarized](https://x.com/arcbang_xyz/status/2119588871747096826) the setup (2 likes, 3 replies, 109 views). The image is the author’s diagram, not a Microsoft benchmark or product screenshot:

![Author-created diagram of Foundry Local and Qwen3.8-27B, GPU memory requirements, and a local-cloud hybrid loop](https://pbs.twimg.com/media/HWpKuUtbIAEMAjP.jpg)

Cloudflare’s [experimental Codex harness example](https://developers.cloudflare.com/changelog/post/2026-11-09-codex-harness/) takes a different route: it persists sessions, files, streams, and completed tool/model results in a Durable Object so an agent can recover after interruption. The documentation stresses that this is example code using internal SDK APIs, not a full Codex CLI harness. [@mattzcarey](https://x.com/mattzcarey) [shared](https://x.com/mattzcarey/status/2119858443695853976) the announcement screenshot (3 likes, 1 reply, 370 views).

## 2. What Frustrates People

### Long tasks become less reliable

**Severity: Medium, based on individual reports.** One Antigravity user says long-running tasks produce random errors, need repeated nudging, and slow down as they continue. A separate multi-computer Codex thread includes reports of browser-control failures in a Windows sandbox and the agent forgetting instructions during extended conversations. ([@vipinxtwt](https://x.com/vipinxtwt) [reported](https://x.com/vipinxtwt/status/2119754376696955210): 26 likes, 9 replies, 2,370 views; [@_samirism](https://x.com/_samirism) [thread](https://x.com/_samirism/status/2119884573190545726): 376 likes, 71 replies, 13,984 views.) Another user says three assistants pointed at one repository yielded slower progress, but gives no detailed diagnosis, so this remains a single anecdote. ([@jsmahay](https://x.com/jsmahay) [reported](https://x.com/jsmahay/status/2119539038533345322) 4 replies, 30 views.)

People cope by keeping tasks small and reviewing diffs themselves; [@esrtweet](https://x.com/esrtweet) [described](https://x.com/esrtweet/status/2119843690403242404) this approach (189 likes, 21 replies, 4,529 views). Persistent sessions and background execution appear in the Cloudflare and Antigravity examples, but the posts do not establish that they resolve the reported quality or context-loss issues. This is worth building for where long-running work is common, with the evidence suggesting a direct need for recovery and visible task state, but not a broad prevalence estimate.

### Subscription limits are hard to plan around

**Severity: Medium.** One user reports that five or six simple messages exhausted a five-hour Gemini Argon quota and that 20-30 minutes of coding used roughly a third of a weekly allowance, while they preferred other providers for stronger models or more usable access. ([@jan_volad](https://x.com/jan_volad) [compared plans](https://x.com/jan_volad/status/2119513284399223188): 20 likes, 9 replies, 1,660 views.) Another developer frames ChatGPT Plus, OpenCode Go, and Claude Pro as different purchases for general-purpose work, inexpensive inference, and coding planning/review rather than direct substitutes. ([@yuhasbeentaken](https://x.com/yuhasbeentaken) [compared the products](https://x.com/yuhasbeentaken/status/2119721665898647898): 6 likes, 2 replies, 848 views.)

These are individual accounts, not a measure of average quota or value. Still, the reports show why users compare usable task capacity, not only subscription price. More predictable per-model usage and clearer plan boundaries are worth exploring, although the evidence is limited to a small number of posts.

### Review queues can outgrow maintainer capacity

**Severity: Medium for the team described; prevalence is unclear.** [@dani_avila7](https://x.com/dani_avila7) [reported](https://x.com/dani_avila7/status/2119616979229171986) that a project with almost 200 contributors had more than 350 pull requests waiting for review (3 likes, 3 replies, 373 views). A reply proposed building a triage agent, but no measured result or follow-up was included. This is a concrete maintainer problem and a plausible niche for review triage, provided a human remains responsible for approvals.

## 3. What People Wish Existed

### Reviewable plans with team-specific guardrails

**Need:** A coding agent that learns repository conventions, proposes a plan before changing files, and leaves architectural decisions and approval with a person. A GitHub Dev Days speaker describes layering always-on instructions, on-demand skills, and narrow agents; EGM offers a public plan-and-review workflow. ([@nisalrenuja](https://x.com/nisalrenuja) [outlined the layers](https://x.com/nisalrenuja/status/2119491264014135433): 12 likes, 4 replies, 294 views; [EGM repository](https://github.com/google/elephant-goldfish-model).)

This is a practical need with **Medium urgency** in the evidence: it appears in concrete workflows rather than an explicit broad request. Existing tools partially address it, but EGM’s documentation still assigns trade-offs and approval to the developer. **Opportunity: Direct.**

### Recoverable work with transparent state and machine-level control

**Need:** When an agent moves between devices or continues in the background, users want to see what happened, recover context, and know which machine an approval affects. Replies to [@_samirism](https://x.com/_samirism)’s [multi-computer post](https://x.com/_samirism/status/2119884573190545726) (376 likes, 71 replies, 13,984 views) specifically ask for the target computer to be identified before approvals; a reply to [@github](https://x.com/github)’s [Copilot handoff post](https://x.com/github/status/2119529896296722931) (96 likes, 30 replies, 21,257 views) says retry behavior hid what went wrong.

This is a practical, **Medium urgency** need. Session handoff, remote agents, and Cloudflare’s experimental persistence example are partial solutions, but the threads show that continuity alone does not ensure visible failures or clear control. **Opportunity: Direct.**

### Predictable model usage and plan boundaries

**Need:** Clear limits and usable capacity that match the model and task being paid for. One subscriber reports fast quota depletion, while another says the best choice depends on whether the user needs general assistance, cheaper coding inference, or a stronger planner/reviewer. ([@jan_volad](https://x.com/jan_volad) [reported](https://x.com/jan_volad/status/2119513284399223188): 20 likes, 9 replies, 1,660 views; [@yuhasbeentaken](https://x.com/yuhasbeentaken) [compared plans](https://x.com/yuhasbeentaken/status/2119721665898647898): 6 likes, 2 replies, 848 views.)

This is a practical, **Medium urgency** need for heavy users, but the sample is small and the reports are account-specific. Local Qwen inference and explicit model/provider choices are partial workarounds, with GPU requirements or quality trade-offs. **Opportunity: Competitive.**

## 7. Where the Opportunities Are

**[+++] Human-approved plans and review gates** — EGM separates project-context drafting from fresh-context review, while a GitHub Dev Days speaker describes repo instructions, task-specific skills, and narrow agents; another practitioner keeps tasks small and reviews diffs before commits. These are multiple concrete approaches to making agent output auditable without handing off final judgment. ([@GoogleCloudTech](https://x.com/GoogleCloudTech) [announced EGM](https://x.com/GoogleCloudTech/status/2119203243054023129), 426 likes, 22 replies, 23,738 views; [@nisalrenuja](https://x.com/nisalrenuja) [described team context](https://x.com/nisalrenuja/status/2119491264014135433), 12 likes, 4 replies, 294 views; [@esrtweet](https://x.com/esrtweet) [described manual review](https://x.com/esrtweet/status/2119843690403242404), 189 likes, 21 replies, 4,529 views.)

**[++] Recoverable agent sessions with transparent control** — Multi-device Codex and IDE handoff posts show demand for continuity, while their replies identify lost context, unclear failure state, and target-machine approval as gaps. Cloudflare’s experimental harness shows one implementation direction for persistence, but does not establish a general solution. ([@_samirism](https://x.com/_samirism) [reported multi-computer use](https://x.com/_samirism/status/2119884573190545726), 376 likes, 71 replies, 13,984 views; [@github](https://x.com/github) [showed session handoff](https://x.com/github/status/2119529896296722931), 96 likes, 30 replies, 21,257 views; [Cloudflare example](https://developers.cloudflare.com/changelog/post/2026-11-09-codex-harness/).)

**[++] Cost and quota controls matched to task type** — A subscriber reports sharp quota depletion, another separates products by whether they provide general work, cheap inference, or strong coding review, and Foundry Local presents local inference as an option for everyday tasks with cloud escalation for harder ones. The path is supported by user reports and a vendor article, but there is no comparative evidence that it lowers total cost for every workflow. ([@jan_volad](https://x.com/jan_volad) [reported quota use](https://x.com/jan_volad/status/2119513284399223188), 20 likes, 9 replies, 1,660 views; [@yuhasbeentaken](https://x.com/yuhasbeentaken) [compared plans](https://x.com/yuhasbeentaken/status/2119721665898647898), 6 likes, 2 replies, 848 views; [Microsoft Foundry article](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/).)

**[+] Codebase and session memory for onboarding** — Understand Anything maps unfamiliar repositories, while SessionPal indexes and backs up prior conversations across five agents. Both target context loss, but the available posts do not measure how much time either saves or how much ongoing maintenance the tools require. ## 8. Takeaways

1. **The highest-confidence workflow signal is to separate planning from approval.** EGM uses fresh-context reviewers, while another practitioner keeps tasks small and inspects diffs before committing. ([EGM repository](https://github.com/google/elephant-goldfish-model); [@esrtweet](https://x.com/esrtweet) [described the supervised workflow](https://x.com/esrtweet/status/2119843690403242404), 189 likes, 21 replies, 4,529 views.)
2. **Agent continuity is becoming a product feature, but users also ask for visible failures and clear controls.** Codex multi-computer use and Copilot-to-VS-Code handoff preserve more of the workflow; replies point to context loss and unclear retry state. ([@_samirism](https://x.com/_samirism) [reported](https://x.com/_samirism/status/2119884573190545726), 376 likes, 71 replies, 13,984 views; [@github](https://x.com/github) [demonstrated handoff](https://x.com/github/status/2119529896296722931), 96 likes, 30 replies, 21,257 views.)
3. **Reliability and quotas are still practical constraints in individual accounts.** One user reports long-task errors and slowdown; another reports fast Argon quota depletion. These are first-person cases, not prevalence estimates. ([@vipinxtwt](https://x.com/vipinxtwt) [reported task failures](https://x.com/vipinxtwt/status/2119754376696955210), 26 likes, 9 replies, 2,370 views; [@jan_volad](https://x.com/jan_volad) [reported quota use](https://x.com/jan_volad/status/2119513284399223188), 20 likes, 9 replies, 1,660 views.)
4. **Builds are trying to preserve different kinds of context.** Understand Anything maps code structure; SessionPal keeps conversations searchable and backed up; OpsDesk groups agent operations but is still an early concept. ([@balance0014](https://x.com/balance0014) [showed Understand Anything](https://x.com/balance0014/status/2119491500140880004), 5 likes, 6 replies, 259 views; [@essjaykay755](https://x.com/essjaykay755) [introduced SessionPal](https://x.com/essjaykay755/status/2119800789560660201), 2 likes, 3 replies, 21 views; [@lorenzor](https://x.com/lorenzor) [shared OpsDesk](https://x.com/lorenzor/status/2119542170193653933), 3 likes, 3 replies, 62 views.)
5. **Local inference and durable sessions solve different problems and carry explicit constraints.** Foundry Local requires substantial NVIDIA GPU memory for long context; Cloudflare’s Codex recovery example is explicitly experimental. ([Microsoft Foundry article](https://devblogs.microsoft.com/foundry/foundry-local-agentic-coding-qwen3-8-27b/); [Cloudflare Codex harness](https://developers.cloudflare.com/changelog/post/2026-11-09-codex-harness/).)
