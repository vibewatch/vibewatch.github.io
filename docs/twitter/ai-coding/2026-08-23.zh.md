# Twitter AI 编程 - 2026-08-23

## 1. 人们在讨论什么

### 1.1 Codex 限额排障演变成一场公开的逆向工程实验（🡕）

最热的讨论仍然是 Codex 使用限额，但重心已从昨天的信任之争，转向明确的根因分析、漏洞保留，以及突然出现的高效率案例。至少有五条高信号信息支撑这一判断：Tibo 对消耗来源的官方解释；一组截图线程，保留了人们如何让进行中的轮次在使用量超过 100% 后继续运行；一位实践者报告称，一个耗时一小时的系统项目只消耗了每周 Plus 限额的约 10%；一条把问题与需求激增联系起来的增长与压力讨论；以及一些信号较弱的失败报告，称 Codex 仍会产生幻觉，或无法上传反馈。相比 2026-08-22 当天争论的重点还主要是累计重置是否到账、后续帖子是否可信，2026-08-23 更关注的是：究竟是什么在消耗配额，以及这种行为如何被复现或利用。

[@thsottiaux](https://x.com/thsottiaux) [表示](https://x.com/thsottiaux/status/2091407991736332689)（2,591 个赞、373 条回复、126,414 次浏览、211 次收藏）称，OpenAI 已将 Codex 异常消耗追溯到三个具体来源：长会话中多次压缩时的低效图像处理、异常高的 Computer History 使用量，以及一个成本高于预期的对话标题功能。这条帖子之所以重要，是因为它不像泛泛的安抚，而是点明了运行层面的原因，承诺为付费订阅全面重置使用量，并引来不少重度图片用户回复，称自己很可能正好踩中了这个 bug。

[@ns123abc](https://x.com/ns123abc) [认为](https://x.com/ns123abc/status/2091639651480043809)（659 个赞、49 条回复、19,644 次浏览、88 次收藏）称，OpenAI 已修复该故障，而一些知名发帖者也悄悄删掉了不想再与自己绑定的证据。比起配文，附带截图更关键：其中一张保留了 maria_rcks 对 “Endless” 方案的解释——如何让 Codex 会话在使用量超过 100% 后，仍停留在同一个尚未完成的轮次里；另一张则保留了 Theo 转述 Angel Brodin 早先的说法，即 OpenAI 是有意选择不在达到限额时中途切断用户任务。信号最强的一条回复立即提出反驳：所谓修复之后，一项夜间任务仍然能从 1% 配额跑满六个小时。

![Endless Codex harness 的截图，说明当配额计量器达到 100% 后，一个仍在进行中的回合如何继续运行](https://pbs.twimg.com/media/HQb82X1XEAAaKHT.jpg)

[@TJeparskis](https://x.com/TJeparskis) [报道称](https://x.com/TJeparskis/status/2091589078449893739)（4 个赞、66 次浏览、4 次收藏）称，GPT-5.6 Sol Max 在大约一小时内构建出一个可在浏览器中运行的 x86 操作系统 AstraOS，同时只消耗了每周 Plus 限额的大约 10%。这条帖子之所以值得注意，是因为它把官方“效率提升”的说法从截图带到了一个具体成品上：一次长时间自主编程任务，最终产出了一个可以启动的结果。

**讨论洞察：** 回复大致分成两派：一派希望出于公平关闭这些漏洞，另一派则把整件事当作一种“运行框架工程”。团队一旦公布了具体消耗来源，社区立刻开始据此推演。

**与前一天对比：** 到了 2026-08-22，最有力的证据还集中在累计重置是否到账，以及官方帖子是否可信。到了 2026-08-23，最有力的证据则下探了一层，转向压缩、图像处理、进行中轮次的行为，以及某些真实任务上突然变好的效率。

### 1.2 Skills、追踪工具与可安装文档持续取代临时提示词（🡕）

第二个主题是，构建者持续把智能体行为封装成可复用、可安装的组件，而不是继续写更长的提示词或发一次性讨论串。至少有六条信息支撑这一点：一套热门的 28 项推理 skills 目录；一个精选的跨客户端 skills 索引；把书籍内容打包成 skill 的工具；一套面向图表的专用 skill 包；一个兼容 Copilot 的追踪查看器；以及一个互动量不高但非常具体的提议——用菜单栏徽章显示哪些 Claude Code 会话正在等待人工处理。相比 2026-08-22 当时这一外围层面还被更笼统地描述为记忆、搜索和审查工具，2026-08-23 则让同样的思路更具操作性：可安装的 skill 包、公开索引，以及会话检查界面。

## 2. 什么让人沮丧

### 配额、重置与“资源充足”说法依然让人难以信任

这是一个高严重度问题，因为即便最有力的官方解释，也没能消除不确定性。[@thsottiaux](https://x.com/thsottiaux) [表示](https://x.com/thsottiaux/status/2091407991736332689)（2,591 个赞、373 条回复、126,414 次浏览、211 次收藏）称，OpenAI 已识别出 Codex 的消耗来源，并会重置付费用户的使用量；但 [@ns123abc](https://x.com/ns123abc) [认为](https://x.com/ns123abc/status/2091639651480043809)（659 个赞、49 条回复、19,644 次浏览、88 次收藏）则显示，所谓漏洞的故事只是换了个形态，并没有消失。该线程中的截图和回复保留了一种明确的操作者担忧：如果一个长时间进行中的轮次在达到 100% 后还能继续跑，人们要么会利用它，要么会默认别人也在利用它。

横向对比也没有让局势更平静。[@TJeparskis](https://x.com/TJeparskis) [报道称](https://x.com/TJeparskis/status/2091589078449893739)（4 个赞、66 次浏览、4 次收藏）称，一个重负载 Codex 任务突然比最近类似工作便宜得多；与此同时，[@prayag_sonar](https://x.com/prayag_sonar) [表示](https://x.com/prayag_sonar/status/2091395546674299215)（7 个赞、448 次浏览）称，Antigravity 上的 Gemini 3.7 Flash 几乎像是没有上限。另一边，[@Presidentlin](https://x.com/Presidentlin) [表示](https://x.com/Presidentlin/status/2091394328040030320)（55 个赞、9 条回复、4,537 次浏览）则称，随着宽松限额催生出转售经济，Antigravity 1.0 的吸引力有所下降。人们现在的应对方式是囤重置、测试替代入口，或者在不同提供商之间来回切换。这看起来是个值得直接去做的方向。

### 智能体仍需要更好的状态、权限与结果回读控制平面

这同样属于高严重度问题，因为多个互不相关的构建者，都在独立修补同一个盲点。[@aacle_](https://x.com/aacle_) [表示](https://x.com/aacle_/status/2091546000951480830)（25 个赞、1,294 次浏览、13 次收藏）称，他们 fork 了 Burp 的官方 MCP 服务器，因为官方版本只能发请求，却不能读回响应、查看 Intruder 结果，或管理扫描。[@Siddhant_K_code](https://x.com/Siddhant_K_code) [宣布](https://x.com/Siddhant_K_code/status/2091242972222533953)（2 个赞、415 次浏览）则提到面向 Copilot CLI/Desktop 的 agent-trace 支持，让用户可以事后检查会话、工具调用、失败、成本和决策。

同样的需求也出现在会话管理层。[@sebwilgosz](https://x.com/sebwilgosz) [询问](https://x.com/sebwilgosz/status/2091533994290475213)（19 次浏览）询问人们是否愿意为一个简单的菜单栏徽章付费，因为四到六个 Claude Code 会话往往会有两条提示卡在屏幕外等待处理；与此同时，[@charliejhills](https://x.com/charliejhills) [分享了](https://x.com/charliejhills/status/2091533151076311432)（14 个赞、4 条回复、1,938 次浏览、9 次收藏）讨论了 Claude Code 的新功能，比如会话间打标签和 /design。人们正靠晨间简报命令、追踪查看器和自定义仪表盘来应对。这看起来同样值得直接构建。

### Vibe-coded 应用在 QA 环节仍会翻车，而付费收尾市场正被挤压

这是一个中高严重度问题，因为证据同时包含可见缺陷和可见的定价压力。[@Joe_brendan_](https://x.com/Joe_brendan_) [认为](https://x.com/Joe_brendan_/status/2091407125318598729)（4 个赞、2 条回复、1,257 次浏览、3 次收藏）称，一些 vibe-coded 应用真正的问题不在于 AI 参与了构建，而在于跳过了显而易见的工程检查；附带的结账截图显示，系统接受了纯数字全名，而且重试流程还会重置字段。在劳动力端，[@AREGames_Tweets](https://x.com/AREGames_Tweets) [报道称](https://x.com/AREGames_Tweets/status/2091592597030461831)（9 个赞、3 条回复、116 次浏览、5 次收藏）称，Roblox 脚本工作越来越多只剩收入分成，即便帖子明确要求接单者得真的会写代码，而且不能用 AI。

同一个故事的正面一面，反而让这种沮丧更可信，而不是更弱。[@jeremykauffman](https://x.com/jeremykauffman) [表示](https://x.com/jeremykauffman/status/2091339012443160713)（274 个赞、15 条回复、4,284 次浏览、10 次收藏）显示，一个七岁孩子已经可以通过自然语言指令迭代游戏；而 [@PinnacleCrypt](https://x.com/PinnacleCrypt) [表示](https://x.com/PinnacleCrypt/status/2091401434801512739)（15 个赞、14 条回复、244 次浏览）则称，vibe coding 已经帮助他们交付出一个产品和第一个客户网站。结果是，收尾市场变得更残酷了：做到“能用”更容易，于是信任、QA 和打磨承担了更多付费价值。这看起来也值得直接构建。

## 3. 人们希望存在什么

### 在长时间运行开始前就说清楚真实配额与路由逻辑的一层

这是最明确的实际需求。[@thsottiaux](https://x.com/thsottiaux) [解释了](https://x.com/thsottiaux/status/2091407991736332689)（2,591 个赞、373 条回复、126,414 次浏览、211 次收藏）解释了 Codex 为什么会比预期消耗得更快；但 [@ns123abc](https://x.com/ns123abc) [展示了](https://x.com/ns123abc/status/2091639651480043809)（659 个赞、49 条回复、19,644 次浏览、88 次收藏）表明，人们仍在保存漏洞行为的截图，并争论补丁是否真的改变了这种行为。在 Google 一侧，[@prayag_sonar](https://x.com/prayag_sonar) [表示](https://x.com/prayag_sonar/status/2091395546674299215)（7 个赞、448 次浏览）称 Antigravity 几乎没有上限，而 [@Presidentlin](https://x.com/Presidentlin) [警告](https://x.com/Presidentlin/status/2091394328040030320)（55 个赞、9 条回复、4,537 次浏览）则称，宽松限额会吸引滥用。需求非常直接：人们希望在提交一次长任务之前，就看到可靠计数器、明确权益规则和诚实的路由行为。机会：直接。

### 能显示哪些任务在等待、运行或受阻的多会话监管器

人们要的并不只是更强自主性，而是更好的方式来管理他们已经拥有的自主性。[@sebwilgosz](https://x.com/sebwilgosz) [表示](https://x.com/sebwilgosz/status/2091533994290475213)（19 次浏览）称，四到六个 Claude Code 会话经常会有几条提示卡在屏幕外等待，因此一个菜单栏徽章看起来都值得收费。[@Siddhant_K_code](https://x.com/Siddhant_K_code) [宣布](https://x.com/Siddhant_K_code/status/2091242972222533953)（2 个赞、415 次浏览）提到用于事后检查会话的 agent-trace，而 [@aacle_](https://x.com/aacle_) [构建了](https://x.com/aacle_/status/2091546000951480830)（25 个赞、1,294 次浏览、13 次收藏）则指向一个仪表盘，因为单向 MCP 操作并不够。需求既实际又紧迫：控制平面应当暴露等待中的提示、卡住的运行、决策历史和回读结果，而不是让用户在一堆标签页里来回翻找。机会：直接。

### 能跨客户端迁移、不中断的可移植 skill 与参考资料打包

这是一个实际需求，而且竞争压力正在上升。[@senthazalravi](https://x.com/senthazalravi) [强调了](https://x.com/senthazalravi/status/2091431173775933758)（57 个赞、3 条回复、2,411 次浏览、80 次收藏）是一套 28 项推理 skills 目录；[@7h3h4ckv157](https://x.com/7h3h4ckv157) [分享了](https://x.com/7h3h4ckv157/status/2091215642133516329)（9 个赞、1,263 次浏览、8 次收藏）是把源材料打包成 skill 的 book-to-skill；[@DanKornas](https://x.com/DanKornas) [展示了](https://x.com/DanKornas/status/2091523345762193613)（21 个赞、4 条回复、1,762 次浏览、25 次收藏）则是一个精选的跨客户端 skills 索引。这个需求不是情绪性的，而是运营层面的。团队希望在 Claude Code、GitHub Copilot、Codex、Cursor、OpenCode 或 Antigravity 之间切换时，知识、图表语法和工作流规则依然能保留下来。机会：竞争性。

### 面向 vibe-coded 应用的 QA 护栏与公平交接流程

这里未被满足的需求，不太像“替我做出来”，而更像“帮我相信做出来的东西”。[@Joe_brendan_](https://x.com/Joe_brendan_) [展示了](https://x.com/Joe_brendan_/status/2091407125318598729)（4 个赞、2 条回复、1,257 次浏览、3 次收藏）称，一个简单的结账流程仍然过不了基本校验；而 [@AREGames_Tweets](https://x.com/AREGames_Tweets) [介绍了](https://x.com/AREGames_Tweets/status/2091592597030461831)（9 个赞、3 条回复、116 次浏览、5 次收藏）则指向一个市场：编码协助正越来越多地被压缩成报酬偏低的收入分成式清尾工作。需求很实际：构建者想要的是帮助，把快速生成的 AI 输出变成可测试、可审查、也值得付费的东西。机会：直接。

## 4. 正在使用的工具与方法

| 工具 | 类别 | 情绪 | 优势 | 局限 |

## 7. 机会在哪里

**[+++] 配额真实性与路由智能** —— 最强证据同时来自多个入口。Codex 用户想知道为什么使用量会被烧得这么快，截图线程保留了官方解释之后的漏洞行为，而 Antigravity 用户则一边庆祝资源充足，一边警告这种宽松也可能被钻空子。若有产品能在任务开始前就展示权益、路由、中断规则和预期消耗，就能回应第 1、2、4 节中最明确的痛点。

**[+++] 多会话监管与结果回读** —— agent-trace、Burp MCP fork、sebwilgosz 的菜单栏构想、CanvasTTY，以及 Claude Code 自带的会话间消息功能，都指向同一个需求：人类需要更好地看清多个智能体正在做什么、在等什么，或者哪些结果根本没法读回。这一机会之所以强，是因为人们已经在通用编程和安全专用工作流中分别做出了应对方案。

**[++] 可移植的 skill 与参考资料打包** —— cc-thinking-skills、book-to-skill、Awesome Agent Skills 和 markdown-viewer/skills 之所以存在，是因为团队希望推理模式、源材料和输出语法在切换客户端后还能继续沿用。这个机会看起来属于中等强度，而不是完全空白，因为市场已经相当拥挤，但需求显然已被验证。

**[+] 面向 vibe-coded 产品的 QA 与收尾护栏** —— Joe_brendan 的结账案例和 AREGames 关于收入分成的抱怨表明，新出现的瓶颈已经不再是生成第一版，而是验证、打磨和可信交接。这仍是一个早期机会，但证据表明，随着越来越多人能交付“够用”的原型，这种痛点会继续增长。

## 8. 要点

1. **当天最大的讨论仍然是限额，但证据如今已经具体到足以让用户据此推演。** [@thsottiaux](https://x.com/thsottiaux) [表示](https://x.com/thsottiaux/status/2091407991736332689)（2,591 个赞、373 条回复、126,414 次浏览、211 次收藏）明确指出，究竟是哪些 Codex 行为在消耗使用量，而截图线程立刻把这些细节转化成了关于漏洞、公平性和预期消耗的推论。
2. **Skills 正在成为智能体知识的持久单位。** [@DanKornas](https://x.com/DanKornas) [分享了](https://x.com/DanKornas/status/2091523345762193613)（21 个赞、4 条回复、1,762 次浏览、25 次收藏）是一个跨客户端 skills 索引，而 [@7h3h4ckv157](https://x.com/7h3h4ckv157) [分享了](https://x.com/7h3h4ckv157/status/2091215642133516329)（9 个赞、1,263 次浏览、8 次收藏）则是把源材料转化为可安装智能体知识的 book-to-skill。
3. **开发者对任何单一模型或 shell 的忠诚度都很低。** [@vicky_grok](https://x.com/vicky_grok) [介绍了](https://x.com/vicky_grok/status/2091522508117991513)（74 个赞、12 条回复、2,721 次浏览、14 次收藏）把 OpenCode 作为与提供商无关的 shell，而当天其他证据则不断按成本、限额和榜单位置对比 Ox Alpha、FreeToken、Qwen3.8 Max、Kimi K3 与 Antigravity，而不是把某一种技术栈视为既定赢家。
4. **监督多个并发智能体，正在成为一个独立的产品问题。** [@sebwilgosz](https://x.com/sebwilgosz) [询问](https://x.com/sebwilgosz/status/2091533994290475213)（19 次浏览）询问人们是否愿意为一个显示哪些 Claude Code 会话在等待的菜单栏徽章付费，而 [@Siddhant_K_code](https://x.com/Siddhant_K_code) [宣布](https://x.com/Siddhant_K_code/status/2091242972222533953)（2 个赞、415 次浏览）则通过 agent-trace 让人看到智能体实际做了什么。
5. **Vibe coding 持续扩大可及性，但 QA 和付费收尾工作仍是最硬的一道坎。** [@Joe_brendan_](https://x.com/Joe_brendan_) [认为](https://x.com/Joe_brendan_/status/2091407125318598729)（4 个赞、2 条回复、1,257 次浏览、3 次收藏）通过一个可见的结账 bug 说明，上线仍需要工程纪律；而 [@AREGames_Tweets](https://x.com/AREGames_Tweets) [报道称](https://x.com/AREGames_Tweets/status/2091592597030461831)（9 个赞、3 条回复、116 次浏览、5 次收藏）则显示，脚本工作已经开始从现金报酬滑向收入分成。
