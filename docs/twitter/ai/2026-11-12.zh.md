# Twitter AI - 2026-11-12

## 1. 大家在讨论什么

### 1.1 工作台基准测试将本地文件与网络研究结合起来 🡕

一项新基准测试考察智能体能否将用户工作区中的证据与公开网络上的资料联系起来，而不是将文件读取和网络搜索分开评估。其作者发布了 100 项专业场景任务，并比较了 14 个模型；最高成绩为 pass³ 的 64%。这项指标要求每项任务的三次尝试都获得满分。这只是基准测试结果，不能衡量模型在一般职场中的表现。

[@AfterQuery](https://x.com/AfterQuery) [介绍](https://x.com/AfterQuery/status/2120985309865459936)（30 个赞、9 条回复、1,150 次浏览、15 次收藏）提及 CrossSearch，并称表现最好的模型是 Gemini 4 Argon。该基准的 [概览](https://www.afterquery.com/blog/crosssearch) 描述了这样一类任务：智能体必须先利用工作区文件确定研究方向，再将公开来源中的发现应用到这些文件中。

[@MaryamMiradi](https://x.com/MaryamMiradi) [映射](https://x.com/MaryamMiradi/status/2120977464180502722)（17 个赞、5 条回复、397 次浏览、14 次收藏）展示了一张涵盖 20 种工具的浏览器工作流全景图，涉及智能体导航、数据提取、确定性自动化、浏览器基础设施和评测。信息图区分了这些角色，并指出浏览器执行只是完整工作流的一部分；有回复提醒，演示流畅并不能证明它适合日常可靠运行。

**与前一日对比：** 11 月 11 日的报告讨论了智能体工作流和评测设计；CrossSearch 则新增了一组已发布的任务，专门考察如何结合私有工作区中的证据与公开来源。

### 1.2 模型能力说法涵盖小型智能体与尚未公布模型的 API 响应 🡕

两条帖子都反映出模型能力说法变化很快，但都不足以构成普遍的性能比较。一位用户称，一个拥有 17 亿参数的模型可以浏览网页、创建 HTML 文件，并在 Pi 中运行；另一个账号则表示，自己针对一个 Google 尚未公布、也未列入模型目录的模型标识符发起请求后，收到了成功响应。

[@0xSero](https://x.com/0xSero) [展示](https://x.com/0xSero/status/2120664334057750607)（273 个赞、14 条回复、8,655 次浏览、169 次收藏）展示了一个小型模型在 Pi 中执行浏览器和文件任务。回复提到了低内存设备和移动端使用，但帖子没有说出模型名称，也没有提供受控基准测试。

[@aitrackerbot](https://x.com/aitrackerbot) [报道](https://x.com/aitrackerbot/status/2120760491282698704)（285 个赞、19 条回复、42,319 次浏览、35 次收藏）称，`gemini-4-hydrogen` 从一个 Vertex AI 端点收到了 HTTP 200 响应，并在响应中识别了自身。作者明确表示，Google 尚未公布该模型，它也不在模型目录中；这只是该账号对端点响应的观察，并非官方发布。

**与前一日对比：** 11 月 11 日的重点是已发布的模型和运行时比较。今天的帖子则带来了一个非正式的小型模型演示，以及一则明确未经确认的 API 发现。

### 1.3 按 token 计量是否会左右智能体设计，正受到质疑 →

一位从业者认为，按 token 计费和设置用量上限会奖励活跃度，而非有用成果，并指出智能体可能反复陷入循环，上下文也会被未启用的技能和 MCP 填满。有回复询问，如果某些服务只能通过 MCP 接入，该如何处理；作者表示，他们倾向于按需加载所需内容。

[@sermakarevich](https://x.com/sermakarevich) [认为](https://x.com/sermakarevich/status/2120905810406527252)（24 个赞、20 条回复、884 次浏览、15 次收藏）认为，这种计费模式可能会助长低效的智能体团队，并让指令上下文过载。这是一位从业者的个人批评，并不能证明所有服务提供商都会受到同样的激励影响。

**与前一日对比：** 前一份报告讨论了推理和评测成本；这条帖子则明确指出产品设计层面的顾虑，将按用量计费与上下文和工作流选择联系起来。

## 2. 人们感到沮丧的地方

### 综合工作任务的满分表现仍不稳定

**严重程度：在基准测试环境中为中等；问题的普遍程度尚未确定。** CrossSearch 报告称，在 100 项文件与网络任务中，排名第一的模型有 64% 的任务在三次尝试中均获得满分。这意味着相当一部分任务未能在三次尝试中都获得满分，但这并不能说明同样的失败在实际生产环境中有多常见。（[基准测试公告](https://x.com/AfterQuery/status/2120985309865459936)（30 个赞、9 条回复、1,150 次浏览、15 次收藏）、[基准测试方法](https://www.afterquery.com/blog/crosssearch)）

### 按用量计费可能会促使上下文和工作量不必要地增加

**严重程度：低置信度， 单名从业者的报告。** 一位作者表示，词元计价和使用限额会促使智能体反复运行，也会让未使用的技能或 MCP 继续占据上下文。一条回复询问如何使用只提供 MCP 接口的服务，作者则倾向于按需加载所需工具。帖子没有量化这一问题的成本或发生频率。（[@sermakarevich](https://x.com/sermakarevich/status/2120905810406527252)（24 个赞，20 条回复，884 次浏览，15 次收藏））

### 浏览器智能体演示无法证明其能可靠地操作网站

**严重程度：中（依据仅为一条从业者讨论帖）。** 作者列举了页面变化、会话、身份验证、重试和信息提取质量等障碍；一条回复指出，完成演示流程不等于能日复一日地可靠执行任务。帖子没有提供可靠性对比数据。（[@MaryamMiradi](https://x.com/MaryamMiradi/status/2120977464180502722)（17 个赞，5 条回复，397 次浏览，14 次收藏））

## 3. 人们希望出现什么

### 定价更贴合智能体的实际成果

一位从业者明确表示，希望 AI 实验室的激励机制与产品是否真正发挥效用挂钩，而不是与词元消耗量和使用限额挂钩。按需加载工具被视为减少上下文杂乱的一种权宜之计，但讨论帖没有指出任何按结果定价的替代方案。**机会类型：竞争性。**（[来源](https://x.com/sermakarevich/status/2120905810406527252)（24 个赞，20 条回复，884 次浏览，15 次收藏））

### 在贴近现实的跨来源任务上进行评估

CrossSearch 发布了结合工作区文件与网络研究的任务，并由其作者提供排行榜和数据集，让这一差距变得可衡量。它在一定程度上满足了对任务匹配型证据的需求，但作者公布的结果并不能证明它在所有工作场景中都有效。**机会类型：直接。**（[基准测试](https://www.afterquery.com/blog/crosssearch)）

### 在不断变化的网站上可靠地完成浏览器任务

这份从业者绘制的图谱将智能体导航与信息提取、确定性浏览器控制、基础设施和测试区分开来。作者指出页面变化和重试问题，一条回复则提醒，成功的演示无法证明运行稳定。帖子提出未来进行比较，但没有提供结果。**机会类型：竞争性。**（[来源](https://x.com/MaryamMiradi/status/2120977464180502722)（17 个赞，5 条回复，397 次浏览，14 次收藏））

## 7. 机遇所在

**[+++] 评测涉及本地文件与公开信息源的任务** —— CrossSearch 通过已发布的 100 项任务集明确呈现了这类任务，其当前最佳成绩为 64% 的通过率³。更贴合任务特点的评测有望揭示智能体在哪些环节失效，同时避免将文件搜索、网络调研，以及把证据应用到工作区这几项任务混为一谈。（[基准测试](https://www.afterquery.com/blog/crosssearch)）

**[++] 减少上下文和 token 浪费** —— 一位从业者将按量计费与反复调用循环、未使用的工具留在上下文中联系起来，并建议只在需要时加载工具。这一观察很具体，但仅来自一位作者的经验。（[帖文](https://x.com/sermakarevich/status/2120905810406527252)（24 个赞、20 条回复、884 次浏览、15 次收藏））

**[+] 让模型可用性声明更易核实** —— Hydrogen 端点报告在官方目录出现相关条目之前就引发了关注。公开目录和可复现的访问检查有助于区分正式发布与孤立的端点响应。（[帖文](https://x.com/aitrackerbot/status/2120760491282698704)（285 个赞、19 条回复、42,319 次浏览、35 次收藏、34 条引用、17 次转发））

**[+] 提升浏览器任务在演示之外的可靠性** —— 一项从业者调查分别讨论了智能体导航、信息提取、确定性控制、基础设施和评测；一条回复则提醒，演示成功并不能证明其能在日常使用中可靠运行。（[帖文](https://x.com/MaryamMiradi/status/2120977464180502722)（17 个赞、5 条回复、397 次浏览、14 次收藏））

## 8. 要点

1. **评测正转向更贴近现实的工作区。** CrossSearch 将本地文件与网络调研结合起来，其当前最佳成绩是在已发布的 100 项任务中达到 64% 的通过率³。（[@AfterQuery](https://x.com/AfterQuery/status/2120985309865459936)（30 个赞、9 条回复、1,150 次浏览、15 次收藏））
2. **紧凑型模型的演示尚不能作为可比基准。** 一位用户展示了一个未透露名称的 1.7B 模型在 Pi 中浏览网页并创建 HTML，但没有提供受控的测试条件。（[@0xSero](https://x.com/0xSero/status/2120664334057750607)（273 个赞、14 条回复、8,655 次浏览、169 次收藏））
3. **上下文管理和使用成本也是智能体设计的一部分。** 一位从业者将 token 定价与反复调用循环、未使用的工具留在上下文中联系起来，并建议按需加载工具作为应对办法。 ([@sermakarevich](https://x.com/sermakarevich/status/2120905810406527252) (24 个赞，20 条回复，884 次浏览，15 次收藏))
4. **浏览器工作流不能止于演示成功。** 工具图谱及其回复强调，导航、提取、控制和测试各有不同职能；面对不断变化的任务，保持可靠同样重要。 ([@MaryamMiradi](https://x.com/MaryamMiradi/status/2120977464180502722) (17 个赞，5 条回复，397 次浏览，14 次收藏))
