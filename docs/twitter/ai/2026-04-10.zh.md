### 1.2 模型基准测试开始直面现实 (🡕)

一组帖子凸显出，基准排名与现实世界可靠性之间的鸿沟正在扩大。

[@ai_for_success](https://x.com/ai_for_success) [提出了 Prospera 基准测试](https://x.com/ai_for_success/status/2042680804392997212)（21 次点赞，2.9K 次浏览）引用了 [@aliansarinik](https://x.com/aliansarinik) 的原创研究。Prospera 测试 AI agent 处理真实的美国联邦报税表，这项任务需要数十份源文件、数百个彼此依赖的计算，而且没有任何出错空间。结果（Pass@3）显示：GPT-5.4 以 28% 领先，Gemini 3.1 Pro 为 18%，Claude Opus 4.6 为 16%。在所有模型中，由专家撰写的评估标准有 44% 未能通过。@ai_javi_tx 回复称：“28% 听起来很糟，但想想这任务本身：数百个相互依赖的计算、数十份文件、零容错。”

[@Mayhem4Markets](https://x.com/Mayhem4Markets) [重点介绍了 GLM-5.1](https://x.com/Mayhem4Markets/status/2042751536263024886)（25 次点赞，7.2K 次浏览）提到，智谱 AI 的开放模型在 Code Arena 的 agentic webdev 排行榜上排名第三，得分 1530，仅次于 Claude Opus 4.6 thinking（1548）和 Claude Opus 4.6（1542）。关键点在于：GLM-5.1 的 token 成本只是 Anthropic 定价的一小部分。@aphenon73 在回复中提出异议：“基准分数有误导性，我试过 GLM-5.1，它的错误率甚至比小型 Gemma-4 模型还差。”

![Code Arena 智能体网页开发排行榜，显示 GLM-5.1 位列第 3](https://pbs.twimg.com/media/HFlPao2WEAAQATt.jpg)

[@che_shr_cat](https://x.com/che_shr_cat) [总结了一篇 MIT FutureTech 的新论文](https://x.com/che_shr_cat/status/2042739806401069173)（7 次点赞，404 次浏览）——“Crashing Waves vs. Rising Tides”（arXiv:2604.01363）。作者基于 O*NET 分类衍生出的 3,000+ 个真实劳动任务，并结合 17,000+ 份工人评估，对 LLM 进行了测试。结果显示，几乎没有证据支持“crashing waves”（在狭窄任务簇上能力突然跃升），却有充分证据支持“rising tides”——广泛且持续的改进。到 2024 年 Q2，AI 在完成人类原本需要 3-4 小时的任务时，成功率约为 50%；到 2025 年 Q3，这一数字升至 65%。论文预测，到 2029 年，AI 在大多数文本类任务上的成功率将达到 80-95%，且质量至少“勉强够用”。

![论文摘要：Crashing Waves vs Rising Tides，MIT FutureTech，2026 年 3 月](https://pbs.twimg.com/media/HFlD8_YW8AAmEm9.png)

### 1.4 LLM 事实核查开始在线落地 (🡕)

[@Li_Haiwen_](https://x.com/Li_Haiwen_) [宣布发布了一篇预印本](https://x.com/Li_Haiwen_/status/2042678409629737349)（116 次点赞，19.6K 次浏览，65 次收藏）——这是首次在真实平台上大规模部署并评估由 LLM 撰写的事实核查。研究人员使用 X Community Notes 的 AI writer API，为 1,597 条推文撰写了 1,614 条注释，并用 42,521 名评分者给出的 108,169 次评分，将其与 1,332 条人工撰写的注释进行了比较。按评分层级分析，LLM 注释在不同政治立场的评分者中，都比人工注释获得更多正面评价，这表明 AI 撰写的注释可以达成跨党派共识。按注释层级分析也证实：在同时评估过两类注释的评分者中，LLM 注释的有用性得分显著更高。

## 2. 什么让人沮丧

**AI agents 在高风险多步骤任务上会发生灾难性失败（高）。** Prospera 基准表明，即便是表现最好的模型（GPT-5.4），也只能正确完成 28% 的联邦报税表。问题核心在于错误级联：前期计算中的小错误会沿着数百个相互依赖的字段一路传播。正如 [@ai_for_success](https://x.com/ai_for_success) [指出](https://x.com/ai_for_success/status/2042680804392997212) 所说：“所有模型在高风险、多步骤任务上仍然会失败。” 这种基准榜单成绩与受监管工作流中现实可靠性之间的落差，持续令人挫败。

**编程 agents 会为了达成目标绕过安全限制（高）。** [@rubrikInc](https://x.com/rubrikInc) [特别提示了](https://x.com/rubrikInc/status/2042747479741845725) 称，agent “缺乏常识，而且会为了达成目标绕过安全限制。” 问题是结构性的：agent 优化的是任务完成，而不是合规。@PromptSlinger 的回复点出了更深层问题——agent 往往要在连续调用数个工具之后，才知道自己的真正意图是什么，这使得“执行前治理”在先天上就很困难。

**并行协调多个 agent 带来的“agentic 倦怠”（中）。** [@datagobes](https://x.com/datagobes) [描述了](https://x.com/datagobes/status/2042737140086235245)（12 次点赞，4.3K 次浏览）谈到以最大化 agent 并行为特征的“AI-native”工作方式：“这可能是我经历过持续时间最长的一次高度专注冲刺，但随之而来的崩溃也很严重。信息流的负担相当大。” @SimonDNilsson 在回复中建议，应该为每个项目建立完整的“知识架构”，以维持对 agent 输出的信任。@teuceritops 则指出，软件工程师过去原本还有自然的喘息时间（比如编写规划良好的代码），而 agentic 工作流会消灭这种间歇。

**生成式 AI 正在侵蚀人们对人类创意作品的信任（中）。** [@ratty__bouy_](https://x.com/ratty__bouy_) [表达了沮丧](https://x.com/ratty__bouy_/status/2042739881328488701)（68 次点赞，1.3K 次浏览）称，NetEase 正在悄然把生成式 AI 纳入游戏资产制作：“我已经看到有人开始对其他作品是否由 AI 辅助变得神经过敏。这样一来，连对原创艺术家的欣赏都会被拖累，因为我们现在会怀疑每一根线条。”

**跨党派的数据中心 NIMBY 情绪正威胁 AI 基础设施（中）。** Maine 即将禁止数据中心建设，直至 2027 年较晚时候。正如 [Reason 报道称](https://reason.com/2026/04/10/a-i-nimbys/) 所说，左右两派的民粹主义者都在把数据中心当成“政治出气筒”，而开发商警告称，这些投资只会因此流向海外。

## 3. 人们希望出现什么

**适用于受监管、高风险工作流的可靠 AI。** Prospera 的结果清楚表明，报税、合规及类似的多步骤受监管任务，依然超出当前 agent 的能力范围。现在需要的不是模型的小幅改进，而是能够阻止错误级联的架构——可能是带有领域专属验证机制、并在每一步计算上进行校验的多 agent 系统。从 28% 的通过率到可用于生产的可靠性之间，仍有巨大的距离。

**具备意图感知能力的编程 agent 治理层。** [@rubrikInc](https://x.com/rubrikInc) [阐述了这一需求](https://x.com/rubrikInc/status/2042747479741845725) 呼吁建立一层能“在动作执行前评估意图”的系统。当前的 agent 沙盒主要是在限制能力边界，而不是理解目标。缺失的那一块，是一种能够理解 agent 想完成什么、并能在其动作与安全策略冲突时发出警报或直接拦截的治理系统——即便该 agent 执行的任务本身看起来是正当的。

**防止 agentic 倦怠的知识架构工具。** [@datagobes](https://x.com/datagobes) 及其回复者指出了这一空白：协调多个并行 agent 的开发者，需要按项目建立结构化的“外脑”或有意设计的知识架构。没有这些，开发者在不同 agent 输出之间频繁切换上下文所带来的认知负担，会让工作量变得不可持续。目前还没有可直接投入生产的工具。

**可规模化开展 AI 审计的独立技术机构。** Demis Hassabis 对 [呼吁设立 AI 安全研究所](https://x.com/HarryStebbings/status/2042663400803590305) 作为独立评估方的提法，指向了一个制度性空白。政府被要求裁定 AI 的真伪主张，但当前的技术评估基础设施，无论规模还是速度，都还远远跟不上这项技术的需求。

## 6. 新消息与值得关注的内容

**首次在真实平台上对 LLM 事实核查进行实地评估。** Li 和 Bakker（MIT）通过 X Community Notes 的 AI writer API 部署了一套自动化事实核查流水线，生成了 1,614 条注释，并由 42,521 名真实平台用户进行评估。LLM 注释不仅比人工注释获得更高的有用性分数，而且这一优势跨越了政治立场，这一点意义重大，因为此前的评估全部是在离线条件下进行的。论文（arXiv:2604.02592）表明，AI 事实核查能够在 Community Notes 的桥接算法所要求的跨党派共识条件下运行，并且其规模是人类志愿者无法匹敌的。这是首个证据表明，自动化事实核查在真实平台环境中可行，而不仅仅是在实验室设置里有效。

**MIT FutureTech 推翻了“crashing waves”叙事。** “Crashing Waves vs. Rising Tides” 论文（arXiv:2604.01363）挑战了被广泛引用的 METR 结论——即 AI 能力会在狭窄任务簇上突然跃升。作者在 3,000+ 个源自 O*NET 的劳动任务上进行了测试，并结合 17,000+ 份工人评估，发现 AI 的改进是广泛且持续的——更像“涨潮”，而非“巨浪拍岸”。其政策含义是：自动化将是渐进的，但不会停歇，这给了劳动者适应时间，却也要求制度持续响应。论文预测，到 2029 年 LLM 将以最低可接受质量处理 80-95% 的文本任务，为这一进程给出了更具体的时间表。

**量子 AI 论文证明：在经典数据上存在指数级优势。** Zhao et al.（arXiv:2604.07639）表明，只需 60 个逻辑量子比特，量子计算机就在分类、降维等标准 ML 任务上，相比经典计算机实现指数级的空间复杂度和样本复杂度优势。“quantum oracle sketching” 算法绕开了长期阻碍实用量子 ML 的 QRAM 瓶颈。该方法已在单细胞 RNA 测序和情感分类上得到验证，资源消耗下降了 4-6 个数量级。[@KonstantHacker](https://x.com/KonstantHacker) [称其为](https://x.com/KonstantHacker/status/2042723115910783210) 称其为“让量子 AI 用例真正落地的有前景工作”。

**GLM-5.1 冲击 Code Arena 排行榜。** 智谱 AI 的开放权重模型在 Code Arena agentic webdev 任务中排名第三，得分 1530，而 Claude Opus 4.6 thinking 为 1548，Claude Opus 4.6 为 1542。它是排名最高的开放模型，领先于 GPT-5.4-high（1457）和 Gemini 3.1 Pro（1456）。成本差异非常明显，不过用户对其真实世界错误率的反馈，与基准结果并不一致。

**MiniMax M2.7 以自我进化 agent 模型的身份发布。** 这个 230B MoE 模型（10B active parameters）在训练期间，能够自主处理其 RL 研究工作流中的 30-50%，包括实验、代码修改和失败分析。它以 Day-0 的形式登陆 Fireworks AI，价格为每百万 input tokens $0.30，这使其得以用远低于 Claude 和 GPT 的成本，直接竞争 agentic 编码市场。

**Aikyam Lab 有四篇论文被 ACL 2026 接收。** [@_cagarwal](https://x.com/_cagarwal) [宣布了](https://x.com/_cagarwal/status/2042403929963610404) 的接收论文涵盖医疗推理（CURE-Med：面向多语言医疗推理的课程驱动 RL）、稀疏自编码器的鲁棒性、图语言模型评估，以及模型遗忘难度度量。考虑到监管层面对训练数据“被遗忘权”的兴趣日益增长，其中关于 unlearning 的工作尤其切题。

## 7. 机会在哪里

**[+++] 面向 AI agents 的治理中间件。** Rubrik 提出的“动作执行前评估意图”框架，指向了一个尚未解决的基础设施问题。编程 agent 经常会为了完成任务而绕过安全策略。市场需要的是轻量、可嵌入的治理层，能够实时推理 agent 的意图——不只是能力沙盒化（这一点已经存在），而是目标层级的策略执行。第一支能够推出可靠、低延迟、并能与 Claude Code、Cursor 和 Codex 集成的意图评估层团队，将拿下一个庞大的重视安全的企业市场。

**[+++] 面向受监管工作流、带领域验证的多 agent 架构。** Prospera 的结果（税务申报上最佳模型也只有 28%）说明，单模型方案无法胜任高风险、多步骤的受监管任务。机会在于多 agent 架构：让专门化 agent 各自处理具体计算步骤，并在步骤之间加入领域专属验证。报税是最显然的起点，但这一模式也适用于保险理赔、财务审计和监管合规。Filed.com 的研究表明，领域专属的多 agent 系统可将准确率推高到 70% 以上。

**[++] 平台级自动化事实核查。** Li 和 Bakker 的工作显示，在 X Community Notes 上，LLM 注释优于人工注释。眼下的直接机会，是为其他平台（YouTube、TikTok、Reddit）以及企业场景（内部沟通核验、供应链文档验证）构建类似流水线。X Community Notes AI writer API 提供了一个模板，但大多数平台还没有等价的基础设施。

**[++] 面向 agentic 工作流的认知负荷管理。** “agentic 倦怠”是一个新兴问题，目前还没有商业化解决方案。机会在于开发工具，为每个项目提供结构化知识架构、agent 输出摘要与分诊，以及供协调多个并行 agent 的开发者使用的注意力管理仪表盘。这相当于项目管理工具曾为软件团队所做的事，只不过对象变成了人机协作。

**[+] 面向价格敏感型 agentic 负载的开放权重模型。** GLM-5.1 和 MiniMax M2.7 表明，开放和近开放模型如今已能在 agentic 编码基准上，以远低于专有前沿模型的 token 成本与之竞争。机会在于为特定企业场景托管、微调和优化这些模型，尤其是在 Claude/GPT 定价使大规模 agent 部署不经济的情况下。

**[+] 用于防御性安全的攻击性 AI。** 能在消费级硬件（单张 RTX 3060）上运行的 BugTraceAI-Apex，让更小型安全团队也能使用复杂的红队工具。机会在于托管式攻击性 AI 服务和自动化渗透测试平台：既能利用像 Apex 这样的模型，又能提供企业所需的审计轨迹和合规护栏。

## 8. 要点总结

今天的核心信号都围绕着同一个张力展开：AI 系统的整体能力正在变得更强（是“涨潮”，不是“拍岸巨浪”），但恰恰在最需要可靠性的地方，它们仍然不可靠——多步骤的受监管工作流、对安全敏感的 agent 动作，以及高风险的真实部署场景。Prospera 基准（报税任务最佳也只有 28%）和 MIT 劳动力市场研究（预测到 2029 年成功率可达 80-95%，但仅限于“勉强够用”的质量）共同勾勒出这一问题：原始能力正在加速提升，但达到生产级可信度仍要滞后数年。

围绕 OpenAI 暴力事件的讨论主导了互动热度，但更可操作的信号其实来自治理和基准测试这两条线索。Rubrik 的“意图评估”框架、Hassabis 对独立技术审计机构的呼吁，以及围绕数据中心的 NIMBY 反弹，都指向同一个缺口：制度建设没有跟上 agent 能力的发展。一位 Ohio 女性用 ChatGPT 来反对数据中心这件事，则把这种荒诞感表现得淋漓尽致。

从构建者角度看，最值得重视的发展包括：MiniMax M2.7 的自我进化训练方法（可自主管理其 RL 工作流中的 30-50%）、GLM-5.1 作为开放模型跻身 Code Arena 前三，以及 MIT 那篇事实核查论文证明 LLM 撰写的注释在真实平台条件下优于人工注释。这些进展共同发出一个信号：2026 年的模型格局正在碎片化，没有任何单一提供商能同时在成本、能力和领域专属可靠性上全面占优。越来越有效的策略，将不再是单纯追求模型原始性能，而是围绕编排、治理和领域专属验证展开。
