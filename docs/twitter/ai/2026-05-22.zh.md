## 1. 人们在讨论什么

### 1.1 代理式 AI 将经济分成两个层级——富人用代理，其他人用聊天机器人 🡕

5 月 22 日最突出的信号，是算力稀缺正在成为一种结构性分界。人们担心的并不是 AI 会不可用，而是最强大的 AI——能够自主执行多步骤工作的代理——会因为价格过高而超出大多数用户和组织的承受范围；与此同时，简单聊天机器人则会越来越便宜，最终甚至免费。

[@emollick](https://x.com/emollick) [指出](https://x.com/emollick/status/2057565824341127432)（273 个赞、17 次转发、43 条回复、14,456 次浏览、34 个书签）表示，即便单轮聊天机器人的价格持续下降，复杂的代理式工作流仍将维持高成本，并将其归结为一个 AI 普及公平问题：“地球上的每个人都将免费获得非常好的聊天机器人，这对 AI 的民主化是好事；但真正优秀、能完成复杂工作的代理，会消耗多出数千倍的 token，因此只会留给那些付得起钱的地方。”一条来自从业者 [@gotnerfedhq](https://x.com/gotnerfedhq) 的回复则反驳了“这是未来风险”的说法：“这种分层已经体现在厂商定价里了。过去 60 天里，每一次悄无声息的涨价都落在代理式套餐，而聊天机器人套餐要么持平，要么更便宜。”

[@IntuitMachine](https://x.com/IntuitMachine) [总结](https://x.com/IntuitMachine/status/2057930049471324548)（527 次浏览、7 个书签）分享了一项精确量化代理式工作成本的学术研究，并直接贴出了论文摘要：

![论文封面展示了 U Michigan、Stanford、Google DeepMind、MIT 和 Microsoft AI 的研究人员所著的《How Do AI Agents Spend Your Money?》](https://pbs.twimg.com/media/HI870WQWEAA5gCa.jpg)

这篇论文——《AI 代理如何花掉你的钱？分析并预测代理式编码任务中的 Token 消耗》（Longju Bai 等，密歇根大学 / Stanford / Google DeepMind / MIT / Microsoft AI）——分析了 SWE-bench Verified 上 8 个前沿模型的 16,000 次生产运行。主要发现包括：代理式任务消耗的 token 数量是代码聊天的 1,000 倍；同一任务的运行最多可相差 30 倍；成本主要由输入 token 而非输出 token 驱动；更高的 token 消耗并不会提升准确率——准确率在中等成本时达到峰值，在更高支出下趋于饱和。Kimi-K2 和 Claude-Sonnet-4.5 每个任务平均比 GPT-5 多消耗超过 150 万个 token。前沿模型也无法准确预测自身的 token 成本（r = 0.39），而且会持续低估。

[@cerebras](https://x.com/cerebras) [发布](https://x.com/cerebras/status/2057547738644898055)（46 个赞、7 次转发、4,595 次浏览、11 个书签）表示，在团队开始把 AI 融入日常工作后，速度“从根本上变得重要起来”，并引用 CEO Andrew Feldman 的话说：“Cerebras 的推理只是在特定用例里更快吗？不是，它是全面更快。大模型、小模型、美国模型、中国模型、万亿参数模型、十亿参数模型——全面都更快。”

**讨论洞察：** 对 Mollick 的回复并未否认这种“两层结构”，而是进一步把它说得更具体。争议点不在于会不会分层，而在于这种分化是即将到来，还是其实已经发生——从业者认为，它已经被写进当前的定价页面里了。

**与前一天的比较：** 5 月 21 日关注的是算力稀缺带来的机构准入问题（大学联合采购、本地设备）。到 5 月 22 日，讨论进一步上移到了结构性经济层面：学术界量化了代理成本，DeepSeek 与美国模型之间出现了持续性的价格不对称，而让代理昂贵的具体机制也被点明——不是输出生成，而是输入 token 的累积。

### 1.4 代理安全正在成为一个产品类别 🡕

5 月 22 日，一组面向开发者和构建者的信息把代理安全视为一个工程问题，而不是政策讨论：具体的解决方案已经在落地。

[@infisical](https://x.com/infisical) [发布](https://x.com/infisical/status/2057940093164539992)（8 个赞、2 次转发、123 次浏览、3 个书签）表示，凭据经纪是应对“提示注入导致凭据窃取”的正确架构方案：他们的开源 Agent Vault “位于代理与其所需 API 之间，持有真实凭据，并在网络层把凭据替换进去。代理看到的始终只是占位符。”

[@trishoolai](https://x.com/trishoolai) [介绍](https://x.com/trishoolai/status/2057820273202610365)（13 个赞、10 次转发、282 次浏览）介绍了一个基于 Bittensor、用于训练其 Halo 防护模型的对抗训练闭环：

![Trishool Flywheel 图示展示了一个包含四个步骤的循环：部署（Subnet 23 上的 Halo checkpoint）、攻击（矿工尝试新型越狱攻击，并受到经济激励）、验证（验证者为这些尝试评分，最佳者获得 emissions）、加固（攻击数据用于下一轮训练）。该循环每周重复一次。](https://pbs.twimg.com/media/HI7YR8iXoAApqWj.jpg)

这个飞轮运行在 Bittensor Subnet 23 上：部署 Halo 模型后，矿工竞争性地用新型越狱攻击去攻破它，验证者为每次攻击打分（0/1/2），最佳提交获得 emissions，形成的对抗数据集再用于训练下一版 checkpoint。新颖性过滤器会剔除复制来的提示词。每天向矿工分发 $1,500；默认情况下，当防护模型守住攻击时，50% 的 emissions 会被销毁。使用 OpenClaw、Claude Code、Codex、Cursor 或 LangChain 的团队，都可以把 Halo 作为一层安全防护。

**讨论洞察：** 这三个工具分别代表三种不同路径：网络层凭据隔离（Agent Vault）、基于对抗训练的防护模型（Trishool Halo），以及 API 层治理埋点（AutoHarness）。从不同方向同时收敛到同一个问题，说明代理安全层正在固化为一个独立产品类别。

**与前一天的比较：** 5 月 21 日讨论代理安全时，重点还是 Microsoft 的 RAMPART 和基于 CI 的安全流水线。到了 5 月 22 日，重心从企业工具转向开源、区块链激励，以及开发者可自助使用的解决方案。

## 2. 什么让人感到沮丧

### 代理成本不可预测、因模型而异，而且在结构上与任务难度脱节

最具体的挫败感来自 AI 代理的成本波动。1.1 节引用的论文把这个问题说得很清楚：同一任务、同一模型，不同运行之间的 token 消耗最多可相差 30 倍；人工评定的任务难度与实际 token 成本相关性很弱（r = 0.32）；而前沿模型在执行前也无法预测自己的成本（r = 0.39，而且是系统性低估）。实际含义是：在生产环境中运行代理的工程团队无法可靠地做预算——同一个任务，这次可能只花 $0.20，下次却可能花 $6.00，而且执行前没有可信信号。严重程度：高。[@IntuitMachine](https://x.com/IntuitMachine) [帖子串](https://x.com/IntuitMachine/status/2057930049471324548) 提到的应对办法，是追踪重复文件读取操作，并把任务路由给 token 效率更高的模型（对代理工作负载使用 GPT-5，而不是 Claude 或 Kimi 系列）。

### AI 推理没有可验证回执——团队正在为不可审计的公用能力付费

[@ambient_xyz](https://x.com/ambient_xyz) [写道](https://x.com/ambient_xyz/status/2057811465407807692)（10 个赞、1 次转发、225 次浏览）指出，AI 推理缺乏其他公用服务都有的可验证性：“用的是不是正确的模型？路由是否变了？安全策略是不是截断了你的响应？延迟飙升是不是因为你被降级塞进了拥挤队列？没有证据，只有账单。”其他公用服务——电力、物流、支付——都有可计量、可核验的凭证。AI 却成了“那个奇怪的例外”，导致团队“花几周时间和供应商争论，财务和工程互相扯皮，SRE 还得因为‘昨天明明还好好的’被叫醒”。严重程度：中高。现有应对方法是自行构建内部日志，但供应商侧的验证仍然缺失。

### AI 实验室的不透明让研究者和从业者感到沮丧

[@GaryMarcus](https://x.com/GaryMarcus) [发布](https://x.com/GaryMarcus/status/2057822495332262228)（20 个赞、619 次浏览）直接批评 OpenAI 在 Erdos 问题结果上的披露不足：没有说明一共尝试了多少道题，训练集是否包含那个新发现的反例，也没有说明用了多少算力。回复 [@rugbist_](https://x.com/rugbist_)（2 个赞）说：“erdos 问题这个例子比大多数人意识到的更有冲击力，那种透明度正是我们已经失去、而且不会再回来的东西。”严重程度：中等。应对办法是独立复现，但那需要获取实验室私下掌握的基准数据。

## 3. 人们希望存在什么

### 一个持久、理解上下文、无需反复解释就知道你在做什么的 AI

[@TakoTreba](https://x.com/TakoTreba) [介绍](https://x.com/TakoTreba/status/2057887423984799874)（21 个赞、512 次浏览、6 个书签）提出了数据中最具体的未满足需求：“我想要一只鸟，它知道我做的所有事，而且一直都在。我可以跟它说话，也可以给它写字，不用解释我在做什么，或者我需要什么。它就是知道。”这里的语境是营销工作，横跨邮件、研究、内容创作、新闻简报、活动和数据分析——这些环节现在都能借助 AI，但每次会话都得重新建立上下文。“我不要 integrations。我想要的是对我全部工作的鸟瞰视角。”来自 [@TechWithMatteo](https://x.com/TechWithMatteo) 的回复提到，他们的 newsletter AI 能把原本 6 小时的研究和初稿工作压缩到 30 分钟，可算部分解决方案。[@chasing_next](https://x.com/chasing_next) 则把“个人操作系统”（文件 + AI）描述为当前替代方案。但二者都没有解决“跨所有任务保持持久上下文”这个需求。机会类型：直接机会。目前似乎还没有产品能完整解决它。

### 一个真正可用的代理式工作流执行前成本估算器

1.1 节总结的论文已经直接暗示了这个需求：如果前沿模型对自身 token 成本的预测相关性只有 r = 0.39，而且还是系统性低估，那么市场上就存在一个空白——在执行前仅根据任务描述估算代理运行成本的工具。虽然没有哪条推文明说“我希望有这个”，但这正是整组代理成本挫败感在实践中的直接推论。机会类型：竞争型——面向代理的成本预测工具，与现有模型路由产品相邻。

### 可验证的推理回执——证明在什么策略下跑了什么模型

[@ambient_xyz](https://x.com/ambient_xyz) [阐述](https://x.com/ambient_xyz/status/2057811465407807692) 直接提出了这一点：“每次调用都附带一份可验证回执：跑了什么、在什么策略下、走了什么路由、最终交付了什么。”目前还没有主流 AI API 提供商提供这项能力。机会类型：直接机会。它与支付领域的 Stripe、物流领域的 FedEx tracking 之间的类比，让这个产品直觉非常清晰。

### 真正适用于 AI 代理的文档解析

[@llama_index](https://x.com/llama_index) [发布](https://x.com/llama_index/status/2057915081795485775)（6 个赞、755 次浏览、5 个书签）提到 ParseBench，称其为“首个面向 AI 代理的文档 OCR 基准”，并指出“现有基准没有覆盖 AI 代理真正需要的东西”。回复 [@Hershal0_0](https://x.com/Hershal0_0) 说：“文档解析是 AI 的最终 Boss。希望以后少受点表格带来的创伤。”这种具体表述——去测试代理真正需要的能力——说明面向生产环境的代理文档解析仍然没有被解决。机会类型：竞争型。

**值得关注的项目细节：**

Agent Vault（Infisical）解决了数据中最具体、最明确的代理安全缺口：提示注入导致的凭据窃取。它的架构简单且易于组合——经纪层持有凭据，并在网络层完成替换，这意味着即便代理被攻破，其遵循指令的过程也无法暴露机密。它兼容任何基于 API 的代理技术栈。

Trishool Halo 的飞轮设计很不寻常：它不是一次性构建对抗数据集，而是持续付费给矿工，每周寻找新的攻击方式，从而不断刷新数据集。新颖性过滤器会在评分前剔除复制提示词，因此数据集不容易被刷；而经济激励则意味着矿工会持续寻找新的攻击面。这个项目正被定位为 LangChain、Claude Code、Cursor 等代理框架的插件式安全层。

Kethic 是一个值得注意的信号：一位来自尼日利亚、16 岁的自学构建者，专门创造了一种编程语言，把 AI 编码代理的 token 消耗相较 TypeScript 降低了 96%。黑客松获奖和可运行编译器说明这并非玩具项目。如果代理成本真如 SWE-bench 研究所说主要由输入 token 驱动，那么面向 token 效率设计目标语言，确实能直接缓解成本问题。

**反复出现的构建模式：** 三个彼此独立的团队（Infisical、Trishool、aiming-lab/AutoHarness）都在没有明显协调的情况下，收敛到“代理安全/治理”这个产品类别。它们面对的是同一个问题——AI 代理已经在生产环境中运行，但监管和控制不足——只是路径不同：网络层隔离、对抗训练、API 层埋点。

## 7. 机会在哪里

**[+++] 代理成本监测与执行前估算** —— 关于代理 token 消耗的学术研究（第 1.1 节）量化了一个真实的生产问题：同一任务，成本可相差 30 倍，而执行前没有可靠信号。论文明确指出，执行前成本预测尚未解决（相关性 r = 0.39）。相关工具领域——成本归因、路由、预算预警——仍很早期。AutoHarness 把成本归因列为四项功能之一；但目前还没有产品专注于代理工作负载的执行前成本估算。证据来自：Mollick 的两层结构判断、SWE-bench 研究、代理式定价层级的观察，以及 IntuitMachine 对 16,000 次运行的分析。

**[+++] 代理安全层：凭据隔离、治理与对抗加固** —— 一天之内出现了三个彼此独立的工具（Agent Vault、Trishool Halo、AutoHarness），全都在解决同一个问题：代理已经在生产环境中运行，却缺乏足够的安全控制。提示注入 → 凭据窃取，是最具体的攻击路径；治理和审计日志，则是企业眼下就有需求的合规能力。证据来自：Infisical、Trishool、aiming-lab/AutoHarness，以及 Aptos Move Prover 的工作——它也在区块链场景中显示出同样模式。

**[++] Verifiable inference receipts / AI utility metering** — The gap [@ambient_xyz](https://x.com/ambient_xyz) 所描述的问题（无法证明实际运行的是什么模型、采用了什么策略、经历了什么延迟）是一个企业采购和 SRE 问题，而当前没有现成解法。其他所有公用服务都有这种能力。这个类比很强，市场也真实存在：那些已经因为和供应商扯皮而耗掉数周的团队，会愿意付费更快地解决争议。证据来自：ambient_xyz 的帖子，以及更广泛的推理成本挫败感信息。

**[++] 边缘 AI 部署工具与量化** —— Lux Capital 的信和 BitCPM-CANN 指向的是同一个缺口：模型需要能跑在“以瓦特计、而不是以吉瓦特计”的硬件上，同时保留生产级质量。BitCPM-CANN 证明，今天已经能做到在保留 95–97% 表现的同时，把内存需求降低 6 倍。瓶颈在工具、部署和硬件兼容性，而不是能力本身。证据来自：wolfejosh/Lux 帖子、BitCPM-CANN，以及 wolfejosh 关于“边缘将超过数据中心”的判断。

**[++] 面向知识工作者的跨会话持久上下文** —— @TakoTreba 的“鸟”帖子异常具体：一个能跨全部工作持续保留上下文、不需要每次重新解释、并且理解营销工作中各环节相互关联的系统。当前工具要么要求用户每次重建上下文，要么要求自己维护外部知识库。未满足需求是：一种无需显式管理、就能积累并应用持久工作上下文的个人 AI。证据来自：TakoTreba 的帖子、chasing_next 的个人 OS 变通方案，以及 Sonnet 4.5 社区对关系连续性的强调。

**[+] AI 初创公司指标透明度 / CARR 与 ARR 信号服务** —— TechCrunch 的报道证实，投资人和记者所依据的，往往是被系统性夸大的营收数据。无论是一项标准化并审计 AI 初创公司营收口径的服务，还是仅仅为主要 AI 公司同步公布 CARR 与 ARR，都会对分析师、竞品创始人和 LP 有价值。证据来自：TechCrunch 的 ARR 调查。

**[+] 面向 AI 代理的 token 高效编程语言** —— Kethic 项目（比 TypeScript 少 96% token）以及 SWE-bench 关于“驱动代理成本的是输入 token 累积而非输出”的发现，都表明语言层面的 token 效率是一个真实优化目标。一种专门面向 AI-to-AI 代码生成设计的语言或转译器——也就是代码读者是模型，而不是人——有可能实质性降低代理式编码成本。证据来自：Kethic 帖子、SWE-bench token 消耗研究。
