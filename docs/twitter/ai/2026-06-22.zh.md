# Twitter AI - 2026-06-22

## 1. 人们在讨论什么

### 1.1 上下文捕获和循环设计正在取代提示词润色（🡕）

当天信息量最高的工作流讨论，已经不再围绕如何把提示词写得更漂亮，而是转向如何把更丰富的上下文送入系统、让这些上下文在多个步骤中持续生效，以及如何设计能从错误中恢复的循环。四条不同内容都指向同一转变：语音听写是更好的意图外化方式、显式的智能体循环、关于长对话上下文衰减的提醒，以及用于编码工作的更具对抗性的审查提示词。

[@guinnesschen](https://x.com/guinnesschen) [表示](https://x.com/guinnesschen/status/2068744472528314811)（2,030 个赞、81 条回复、137,649 次浏览、610 次收藏）认为，人们应该停止手动改提示词，转而对着听写按钮自由表达，让模型从语言中重建“潜在意图”。回复区让这一点从理论走向实践：[@alexanderbenz](https://x.com/alexanderbenz) 表示，在播客准备中，这种方式比手打节目提纲更有效；[@SherbyJohn](https://x.com/SherbyJohn) 则说，ChatGPT 的听写模型在实际使用中特别好用。

[@neil_xbt](https://x.com/neil_xbt) [认为](https://x.com/neil_xbt/status/2068912865197850682)（51 个赞、7 条回复、2,320 次浏览、16 次收藏）认为，更好的提示词只能优化一个已经失灵系统中的单一环节，而无人值守的智能体需要一套“观察—思考—行动—反思”的循环。配图把这一建议从口号变成了可落地的架构。

![四步智能体循环示意图：观察、思考、行动、反思](https://pbs.twimg.com/media/HLYzlgNW4AAOriu.jpg)

[@S1TA10](https://x.com/S1TA10) [警告称](https://x.com/S1TA10/status/2068953885511999954)（35 个赞、14 条回复、1,051 次浏览、15 次收藏）指出，一个 40,000 token 的 Claude 对话可能会因为 “lost in the middle” 而忽略前文指令，并建议每项任务单开新对话、只延续简短摘要、使用更结构化的输入，而不是把完整历史一股脑塞进同一个对话。[@rohit4verse](https://x.com/rohit4verse) [分享了](https://x.com/rohit4verse/status/2069113407446700378)（10 个赞、4 条回复、585 次浏览、15 次收藏）则给出了一份 PR 审查提示词：它预设至少存在一个真实 bug，并强制分别检查正确性、安全性、并发、回归和测试。

**讨论洞察：** 最有价值的回复并没有夸奖提示词技巧，而是在肯定更好的输入捕获和上下文回灌。相关证据指向一种更偏运营的方法论：尽早捕获混杂的人类意图，只保留仍然重要的上下文，并强制模型走结构化循环，而不是寄希望于一条提示词始终管用。

**与前一天对比：** 在 2026-06-21，最热门的工作流帖子仍主要围绕语音听写；到了 2026-06-22，讨论已经扩展到循环设计、上下文衰减和显式审查流程。与前一周相比，关于智能体能力的讨论持续从提示词技巧转向系统设计。

### 1.2 编排正在成为产品层，而不只是研究概念（🡕）

当天最明确的架构主题是：多模型编排正被当作一种独立的前沿能力来销售。讨论不再只是“又有一个新模型发布”，而是：最终胜出的产品会是模型本身，还是那个知道该如何在多个模型之间路由的层。

[@testingcatalog](https://x.com/testingcatalog) [报道称](https://x.com/testingcatalog/status/2068967746638131301)（368 个赞、26 条回复、40,208 次浏览、136 次收藏）将 Sakana AI 的 Fugu 和 Fugu Ultra 描述为编排系统，称其在多个基准测试中的表现可与 Claude Fable 5 和 Mythos 5 比肩。那张基准测试图片之所以重要，在于它给出了具体数字，而不是含糊的“前沿能力”说法：Fugu Ultra 在 LiveCodeBench 上得分 93.2，在 GPQA-D 上得分 95.5，在 SWE-Bench Pro 上得分 73.7，在 Terminal Bench 2.1 上得分 82.1。

[@SakanaAILabs](https://x.com/SakanaAILabs) [宣布](https://x.com/SakanaAILabs/status/2068862070062485867)（118 个赞、4 条回复、10,575 次浏览、22 次收藏）转发了原始发布，并链接到一个公开产品页面。该页面将 Fugu 描述为一个由可替换智能体池支撑的单一 OpenAI 兼容 API。Sakana 的发布页称，该系统能在内部跨多个专家模型进行委派、验证和综合，并明确把这种架构定位为对冲出口管制和单一供应商依赖的方案。

![对比 Sakana Fugu 和 Fugu Ultra 与 Fable 5、Mythos Preview、Gemini 3.1 Pro、GPT-5.5 和 Opus 4.8 的基准测试图表](https://pbs.twimg.com/media/HLYTDMMaEAAEVZj.jpg)

[@amiruci](https://x.com/amiruci) [表示](https://x.com/amiruci/status/2069095112186196175)（254 个赞、24 条回复、25,191 次浏览、70 次收藏）表示，Together AI 的推理业务在一年内增长了 20 倍，因为企业越来越希望拥有自己的智能层，为自身场景对开放模型做后训练，并掌握持续学习，而不是完全依赖封闭 API。

**讨论洞察：** 质疑并不是针对编排本身，而是针对其优化难度。TestingCatalog 帖子下的一条回复称，人们已经听说其他多模型系统存在问题；TestingCatalog 的回应则是，优化仍然需要时间。兴趣是真实的，但实现债务同样真实。

**与前一天对比：** 在 2026-06-21，关于开放模型的讨论更多集中在 GLM-5.2 这类更易获得的前沿模型；到了 2026-06-22，重心上移了一层：问题从“哪个模型更强？”变成了“当供应商、价格或访问规则变化时，哪个编排层还能持续运转？”

### 1.3 评测和对抗性审查仍像是稀缺基础设施（🡕）

另一个反复出现的主题是：评测仍然是实用型 AI 工作中最难的部分之一。公开材料比泛泛的“评测很重要”更扎实：一篇帖子认为，实验室之所以收购评测团队，是因为这类工作依然难以自动化；另一篇指向一个覆盖面很广的新智能体基准；还有一篇则把这种稀缺性转化为具体的代码审查工作流。

[@abhijaymrana](https://x.com/abhijaymrana) [认为](https://x.com/abhijaymrana/status/2068843661975273940)（64 个赞、1 条回复、5,109 次浏览、43 次收藏）认为，实验室收购团队正是看中评测专长，因为长尾评测的编写仍然困难且有价值。引用的讨论提到 Harbor 和 HealthBench 风格的 rubric 工作是少见的公开案例，这进一步强化了“可复用评测资产依然稀缺”的判断。

[@tom_doerr](https://x.com/tom_doerr) [指出](https://x.com/tom_doerr/status/2068808545626141083)（19 个赞、2,422 次浏览、25 次收藏）介绍了 Agents' Last Exam。其公开仓库将其描述为一个开放评测框架，包含覆盖 55 个行业的 150 个参考任务、隐藏参考答案、确定性评分器，以及面向长时程智能体工作的真实 Windows 或 Linux 沙箱。

![Agents' Last Exam 的 GitHub 截图，展示其 README 和基准测试定位](https://pbs.twimg.com/media/HLXiaJ1WwAAWinc.jpg)

[@rohit4verse](https://x.com/rohit4verse) [分享了](https://x.com/rohit4verse/status/2069113407446700378)（10 个赞、4 条回复、585 次浏览、15 次收藏）分享了一份完整的对抗性 PR 审查提示词：它明确要求不要先夸赞，预设确实存在一个真实 bug，并强制分别检查逻辑、故障路径、安全性、并发、回归和测试质量。

**讨论洞察：** 共同模式是用结构化评判取代泛泛判断。无论任务是公开基准还是一次性的 PR 审查，构建者都在尝试明确自己关心的失效模式，而不是让模型给出一个模糊的“没问题”。

**与前一天对比：** 2026-06-21 已经通过 Human-on-the-Bridge 和 Agents' Last Exam 把评测前移；到了 2026-06-22，这一主题仍在延续，但呈现得更具操作性：评测人才并购、公开基准框架，以及用于日常工程的对抗性审查提示词。

## 2. 什么让人沮丧

### 上下文衰减与提示词脆弱性

严重程度：高。工作流相关帖子反复描述同一个问题：一旦工作变成长流程，一次性提示就会失效。[@S1TA10](https://x.com/S1TA10) [表示](https://x.com/S1TA10/status/2068953885511999954)（35 个赞、14 条回复、1,051 次浏览、15 次收藏）指出，长对话会陷入 “lost in the middle”，导致早期指令被忽略；[@neil_xbt](https://x.com/neil_xbt) [认为](https://x.com/neil_xbt/status/2068912865197850682)（51 个赞、7 条回复、2,320 次浏览、16 次收藏）则认为，更好的提示词只能优化一个已经失灵系统中的单一环节。就连当天最受欢迎、立场偏正面的 AI 工作流帖子，[@guinnesschen](https://x.com/guinnesschen) [暗示](https://x.com/guinnesschen/status/2068744472528314811)（2,030 个赞、81 条回复、137,649 次浏览、610 次收藏）也指出：手打并反复润色提示词，往往不是捕获意图的正确界面。

当前的应对方式虽然轻量，却很说明问题：每个任务单开新对话、只携带简短摘要、用听写捕获更丰富的上下文，并强制模型走“观察—思考—行动—反思”循环。之所以值得围绕这一方向构建产品，是因为多篇帖子从不同角度收敛到了同一个抱怨。

### 评测默认设置太弱，误报式审查太多

严重程度：高。[@abhijaymrana](https://x.com/abhijaymrana) [认为](https://x.com/abhijaymrana/status/2068843661975273940)（64 个赞、1 条回复、5,109 次浏览、43 次收藏）指出，长尾评测工作的价值高到实验室仍愿意为此收购团队。[@rohit4verse](https://x.com/rohit4verse) [表示](https://x.com/rohit4verse/status/2069113407446700378)（10 个赞、4 条回复、585 次浏览、15 次收藏）表示，现有 AI 审查器一直告诉他 PR 看起来没问题，直到一条对抗性提示词才挖出真实 bug。[@tom_doerr](https://x.com/tom_doerr) [指出](https://x.com/tom_doerr/status/2068808545626141083)（19 个赞、2,422 次浏览、25 次收藏）介绍 ALE，恰恰是因为基准覆盖、隐藏参考答案和确定性评分器依然稀缺到足以构成价值。

当前的变通办法，是把评判流程规定得非常具体：对抗性提示词、隐藏参考答案、结构化分阶段检查，以及定制评测资产。之所以值得围绕这一方向构建产品，是因为证据既显示出真实痛点，也显示出围绕这一缺失层的明确预算投入。

### 供应商依赖与机器可读数据债务

严重程度：中到高。[@SakanaAILabs](https://x.com/SakanaAILabs) [将其描述为](https://x.com/SakanaAILabs/status/2068862070062485867)（118 个赞、4 条回复、10,575 次浏览、22 次收藏）将编排视为对冲出口管制和单一供应商依赖的方案；[@amiruci](https://x.com/amiruci) [表示](https://x.com/amiruci/status/2069095112186196175)（254 个赞、24 条回复、25,191 次浏览、70 次收藏）则表示，客户越来越希望拥有自己的智能层，而不只是依赖封闭 API。在电商一侧，[@alexgroberman](https://x.com/alexgroberman) [总结道](https://x.com/alexgroberman/status/2069041576979079481)（38 个赞、37 次转发、3,908 次浏览）转述了 Microsoft 的观点：产品数据往往是有的，但并没有结构化、同步化，或可靠到足以让 AI 助手和智能体据此行动。

当前的应对模式，一边是可替换模型池，另一边是结构化目录、feed 和信任信号。之所以值得围绕这一方向构建产品，是因为眼下的痛点是运营层面的，不是愿景层面的：人们现在就需要保持访问连续性，并让智能体能在真实产品数据上可用。

## 3. 人们希望出现什么

### 更好地在长任务中保留意图的方法

最有说服力的工作流帖子表明，人们想要的是：系统能保留自己思考中真正有用的部分，而不必逼他们事无巨细地管理提示词。[@guinnesschen](https://x.com/guinnesschen) [推动了](https://x.com/guinnesschen/status/2068744472528314811)（2,030 个赞、81 条回复、137,649 次浏览、610 次收藏）把语音听写视为更好的细微意图捕获方式；[@S1TA10](https://x.com/S1TA10) [认为](https://x.com/S1TA10/status/2068953885511999954)（35 个赞、14 条回复、1,051 次浏览、15 次收藏）则建议只延续简短摘要，而不是没完没了的聊天历史。这是一项有直接需求的现实需要，因为这些建议描述的是当下的应对行为，而非未来想象。机会：直接。

### 在模型访问变化时仍能持续运转的编排层

Sakana 和 Together 的帖子暗示了一项很具体的需求：一个能够切换供应商、做模型专门化，并在供应商或政策冲击下继续存活的智能层。[@SakanaAILabs](https://x.com/SakanaAILabs) [将其定位为](https://x.com/SakanaAILabs/status/2068862070062485867) 将 Fugu 描述为可替换的编排系统；[@amiruci](https://x.com/amiruci) [表示](https://x.com/amiruci/status/2069095112186196175) 则表示，客户希望通过后训练开放模型来拥有自己的智能层。这是一项有直接需求的现实需要，但竞争正在迅速升温。机会：竞争性。

### AI 助手真正能信任并据此行动的产品数据

Microsoft 指南摘要强调了一项不如模型发布吸睛、但非常具体的需求：更好的机器可读目录、同步 feed、可信评论，以及可供智能体完成交易的网站。[@alexgroberman](https://x.com/alexgroberman) [总结道](https://x.com/alexgroberman/status/2069041576979079481) 转述了 Microsoft 的观点：如今 AI 可见度取决于助手是否能实时理解、解释并使用你的数据。这是一项现实需要，证据指向的问题不是市场缺乏兴趣，而是现有零售基础设施存在缺口。机会：直接。

### 不需要专家手工打造的评测资产和对抗性审查工具

评测相关帖子指向了一个市场：需要比通用模型测评更严格、且可复用的评判资产。[@abhijaymrana](https://x.com/abhijaymrana) [认为](https://x.com/abhijaymrana/status/2068843661975273940) 表示，评测专长仍然稀缺到值得被收购；[@rohit4verse](https://x.com/rohit4verse) [展示了](https://x.com/rohit4verse/status/2069113407446700378) 则展示了一种手工应对方式：把代码审查变成一个明确的对抗性流程。对于发布智能体或 AI 辅助工程工作流的团队来说，这是一项有直接需求的现实需要。机会：直接。

| 用于提示的语音听写 | 输入工作流 | (+) | 比手打和润色提示词更快地捕获限定条件、示例和潜在意图 | 依赖转录质量，后续仍需管理上下文 |
| 观察—思考—行动—反思循环 | 智能体方法 | (+) | 为长流程系统提供明确的恢复与学习周期 | 如果没有配套的具体记忆、工具和升级规则，仍然偏抽象 |
| 简短摘要式上下文延续 | 上下文管理 | (+) | 减少长对话噪声，避免 “lost in the middle” 失效 | 需要严格的任务边界和高质量摘要 |
| Sakana Fugu / Fugu Ultra | 编排 API | (+/-) | 单一 API、学习式委派、清晰的基准定位、可替换智能体池 | 回复和发布口径都暗示，优化与可靠性工作仍有不少要做 |
| 开放模型后训练 | 模型定制方法 | (+) | 让团队能为自身场景掌握专门化行为和持续学习 | Together 的帖子明确表示，后训练仍然更像艺术而非科学 |
| Agents' Last Exam | 评测框架 | (+) | 行业覆盖广、隐藏参考答案、确定性评分器、真实沙箱 | 公开任务集仍只是子集；运行真实沙箱会带来运营开销 |
| 对抗性 PR 审查提示词 | 工程工作流 | (+) | 强制围绕正确性、安全性、并发、回归和测试进行结构化检查 | 目前证据仍是从业者个案，而非广泛基准数据 |
| Midjourney Draft Mode + GPT Image 2 | 创意工作流 | (+) | 先快速探索概念，再生成一致的身份板 | 需要人工筛选和迭代修正；工作流证据来自单一从业者案例 |
| AEO/GEO 结构化产品数据 | 电商方法 | (+) | 对齐 feed、信任信号和实时站点数据，让助手能推荐并完成交易 | 需要内容、目录和站点运营协同，而不是靠单一工具解决 |

整体满意度分布是务实的，而不是意识形态化的。人们并不在寻找某个魔法模型，而是在组合更丰富的输入、更严格的上下文纪律、编排层、公开评测框架，以及面向具体领域的工作流策略。

共同的变通模式是“结构化”。提示词失效时，人们就加循环和摘要；模型依赖显得危险时，人们就加编排和后训练；AI 电商显得不可靠时，人们就强调 feed、schema 和实时站点一致性。因此，迁移压力正从对原始模型的迷恋，转向那些能够保留上下文、评估输出，并让 AI 持续连接真实数据的系统层。

## 7. 机会在哪里

**[+++] 上下文保真型智能体基础设施** — 证据来自当天互动最高的语音听写工作流帖子、“观察—思考—行动—反思”循环图，以及关于长对话 “lost in the middle” 的提醒。这一方向很强，因为同一个痛点同时出现在输入捕获、记忆管理和长任务执行中。

** 评测与审查基础设施 [+++] Evaluation and adversarial review tooling** — [@abhijaymrana](https://x.com/abhijaymrana) [认为](https://x.com/abhijaymrana/status/2068843661975273940) 表示评测专长仍然值得通过收购获取；ALE 提供了公开基准框架；[@rohit4verse](https://x.com/rohit4verse) [展示了](https://x.com/rohit4verse/status/2069113407446700378) 则给出了代码审查薄弱时的手工变通方案。这一方向很强，因为它同时连接了痛点、预算和正在发生的实现。

**[++] 与供应商无关的编排层** — Sakana Fugu 和 Together AI 都将未来描述为：企业应拥有或路由自己的智能层，而不是依赖单一供应商。这一方向潜力中等，因为需求明确，但赛道正迅速变得拥挤且技术要求高。

**[+] 面向 AI 的产品数据与交易界面** — Microsoft 的 AEO/GEO 材料显示，助手和智能体必须先拿到结构化目录、可信评论、同步 feed 和可用的结账流程，才能推荐或购买。这一方向正在浮现，因为运营需求是真实的，但当天证据规模仍小于上下文与评测主题。

## 8. 要点

1. **工作流讨论已从提示词质量转向上下文质量。** 语音听写、循环设计和长对话失效提醒都指向同一个结论：瓶颈在于跨步骤保留意图，而不是打磨一条提示词。（[来源](https://x.com/guinnesschen/status/2068744472528314811)）
2. **编排如今正被当作一种独立的前沿能力来推销。** Sakana Fugu 把学习式委派和可替换模型池本身当作产品，而 Together AI 则把业务增长与客户拥有自己的智能层联系起来。（[来源](https://x.com/SakanaAILabs/status/2068862070062485867)）
3. **评测仍然是技术栈中最不容易商品化的部分之一。** 关于评测人才并购、ALE 和对抗性 PR 审查的帖子，都把判断视为专门基础设施，而不是事后补丁。（[来源](https://x.com/abhijaymrana/status/2068843661975273940)）
4. **最可信的应用型 AI 案例，都保留了人工和结构化数据在环。** 无论是购物、角色设计还是罕见病诊断，成功案例都依赖结构化证据、人工选择或专家验证，而不是完全自主的“魔法”。（[来源](https://x.com/ABC/status/2068869764445860331)）
