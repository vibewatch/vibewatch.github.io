# Twitter AI - 2026-09-20

## 1. 人们在讨论什么

### 1.1 开放权重多模态发布与网关流量，开始像默认的流量主通道 🡕

在 328 位作者发布的 352 条原创推文里，最清晰的变化是：开放权重 AI 不再像爱好者小圈子的东西，而开始像主流供给。当天信号最强的发布是 Qwen-Image-2.1，但周边证据同样关键：人们晒出了精确的本地硬件实测数据，而一张 Vercel 网关快照显示，开放权重模型已经拿走了大部分 token 流量。

[@Alibaba_Qwen](https://x.com/Alibaba_Qwen) [宣布](https://x.com/Alibaba_Qwen/status/2101659302792679789) 了 Qwen-Image-2.1：这是一款开放权重的一体化图像生成与编辑模型，支持原生 RGBA 输出、最多 10 张参考图，并在肖像、信息图和商品编辑上保持较高保真度。公开的 [仓库](https://github.com/QwenLM/Qwen-Image-2.1) 把推文里只是略微提到的技术细节补全了：7B 视觉生成组件、原生 2K 输出，以及对 Diffusers、ComfyUI、vLLM-Omni 和 SGLang 的首日支持，这让这次发布更像一层基础设施，而不是一次性的演示。

[@TeksEdge](https://x.com/TeksEdge) [贴出](https://x.com/TeksEdge/status/2101431138384490764) 了部署侧的证据（32 点赞、13 回复、3,709 浏览量、19 收藏）：Qwen3.8-27B 在 Intel Arc Pro B70 上本地运行时，Q4 为 23.4 tok/s、Q8 为 15.9 tok/s，文生图和视频测试虽慢但能跑通。真正特别的点，不是 Intel 突然击败了 Nvidia，而是 32GB VRAM 配合远低于 RTX 5090 的入门价格，已经足以让一整套 27B 级本地栈变得可用。

[@Polymarket](https://x.com/Polymarket) [放大传播](https://x.com/Polymarket/status/2101488459982557425) 了一则标题（88 点赞、23 回复、20,221 浏览量）：开源模型已占到 Vercel AI Gateway token 量的 78.4%；而互动更低、但细节更多的 [@AGTPInsights](https://x.com/AGTPInsights) [则给出](https://x.com/AGTPInsights/status/2101730665553440778) 了更有用的趋势线（1 引用、68 浏览量）：2026 年 9 月 19 日为 78.4%，高于 2026 年 8 月的 56%，也远高于 2025 年 12 月的 7%；并声称 Moonshot AI、DeepSeek 和 Z.ai 现在在网关支出上已超过 OpenAI。后续的 [RuntimeWire 总结文章](https://runtimewire.com/article/vercel-ai-gateway-open-weight-models-78-percent-token-volume) 补上了一个必要前提：这只是 Vercel 网关的快照，并不等同于全市场份额，但它依然让“按成本做路由”这条方向变得难以忽视。

![趋势卡片，显示开放权重模型在 2026 年 9 月 19 日占到 Vercel AI Gateway token 量的 78.4%，高于 8 月的 56% 和 2025 年 12 月的 7%](https://pbs.twimg.com/media/HSrY4v3aIAAZL5S.jpg)

**讨论要点：** 最值得注意的细微之处是经济性，而不是意识形态。开放模型显然正在赢下日常 token 流量，但公开的网关文章仍显示，最难的工作上的支出依然偏向高价闭源模型。这说明团队是在按任务类型做路由，而不是宣布某一个体系通吃。

**与前日对比：** 相比 2026-09-18 对精确上下文窗口和 tok/s 实测数据的强调，2026-09-20 把这些实测数据连到了两个更大的信号上：一是旗舰级开放权重多模态发布，二是开放权重模型已经主导某个主要生产网关 token 流量的证据。

### 1.2 Jev 已从发布周的新鲜感，转向明确的决策层用法手册 🡕

围绕 Jev 的讨论声量依然很大，但重心再次变化。2026-09-18 的信息流里塞满了首批演示和开源复刻；到了 2026-09-19，重点转成这种原生面向决策的模型该放在代码的哪一层。到 2026-09-20，最强的帖子已经更具体：有带基准的评估器行为、成串列出的有边界用例，以及明确说明 Jev 不该用在哪些地方的警告。

[@LangChain](https://x.com/LangChain) [报告](https://x.com/LangChain/status/2101454284927959080) 说，它把 Jev 与 GPT-5.6 Luna、GPT-5.6 Terra 和 Claude Sonnet 4.6 放在固定的天气智能体轨迹上，拿来当智能体评估器测试（328 点赞、37 回复、26,550 浏览量、418 收藏）。链接的 [博客文章](https://www.langchain.com/blog/jev-agent-evals-langsmith) 称，Jev 在 500 次重复的通过 / 失败判断上与二元真值判定完全一致，相比 LLM 裁判，方差低 92 倍到 913 倍，且实验中单次调用成本约为 $0.00035。这样一来，“System One” 被重新定义成一种实用的裁判原语，而不是哲学上的新奇概念。

[@_raghavdixit_](https://x.com/_raghavdixit_) [把](https://x.com/_raghavdixit_/status/2101704858868793450) 下一个问题框成了一种反向拆解的纪律（20 点赞、5 回复、6,507 浏览量、17 收藏）：Jev 到底是什么、它该叠在现有组件的哪一层，以及它会在哪些地方失灵。最有用的回复不是宣传，而是运营规则——冻结选项列表、用留出轨迹而不是厂商基准来做校准、加入一个无效选项检验分数是否因为正确原因而变化，并把低置信度情况送去人工复核，而不是假装概率默认就值得信任。

[@Layton_Gott](https://x.com/Layton_Gott) [发布](https://x.com/Layton_Gott/status/2101525943818899811) 了一张最清楚的“它该放在哪里”图片版地图（5 点赞、4 回复、175 浏览量、4 收藏）：模型路由、重试逻辑、工具风险闸门、人工审核队列、动态权限、支出防火墙、内容审核、线索路由、事故分诊，以及合规检查。几乎同样重要的是，第二页明确给开放式写作、新颖创意、主观判断和早期探索划出边界，把它们归为“不是它的工作”。

![Jev 信息图，展示它的前十个核心用例，包括模型路由、重试逻辑、风险闸门、人工审核队列、动态权限、支出防火墙和输出检查](https://pbs.twimg.com/media/HSoc-4AWIAAbB3S.jpg)

![第二张 Jev 信息图，列出更多用例、Choice/Score/Noul 问题类型，以及“非常适合”与“不是它的工作”的划分](https://pbs.twimg.com/media/HSodC2sW8AAy5hT.jpg)

**讨论要点：** 真正的实务分歧已经不再是“这东西有意思吗？”，而是“怎样把廉价决策模型关进一个可验证的盒子里？” 校准、回放、冻结标签集和人工升级处理，占据了那些更认真回复的核心。

**与前日对比：** 相比 2026-09-19 更偏落地细节的 Jev 讨论，2026-09-20 看起来更像设计指南：公开的评估器基准、明确的用例分类，以及更清楚地说明哪些内容应留在决策层之外。

### 1.3 只要能减少格式混乱和转录抖动，输入管线就会得到关注 🡕

另一簇帖子让 AI 看起来不再主要是选模型的问题，而更像是整理输入的问题。最有说服力的例子不是“这里有个更聪明的模型”，而是“这里有种更干净的方式把证据交给模型”，无论这些证据起点是 PDF、扫描表格，还是实时语音。

[@duqaXxX](https://x.com/duqaXxX) [展示](https://x.com/duqaXxX/status/2101383616563458154) 了一个本地助手（35 点赞、17 回复、106,291 浏览量、10 收藏）：它能从 PDF、扫描文档和电子表格中回答问题，并在每个答案里标出来源文件。最能说明问题的细节在回复里：先跑 OCR，只有当 OCR 失败或表格结构被压平时才调用视觉模型；模型按需加载，因此整套工作流可以在 16GB Mac Mini 上运行，而不必让大模型常驻内存。

[@RituWithAI](https://x.com/RituWithAI) [带出](https://x.com/RituWithAI/status/2101544289847148886) 了 Docling（12 点赞、8 回复、136 浏览量、7 收藏），把它摆成“单一格式解析器”的反面：PDF、DOCX、PPTX、XLSX、HTML、EPUB、电子邮件、图像、音频、视频、LaTeX 和 XBRL，都能转成结构化 Markdown。公开的 [仓库](https://github.com/docling-project/docling) 证实了更大的重点——结构保留本身就是产品：版面、阅读顺序、表格、公式、OCR、本地执行、MCP server 和 API 接口，取代了又一条脆弱的 regex 链。

[@ModelScope2022](https://x.com/ModelScope2022) [宣布](https://x.com/ModelScope2022/status/2101605223726760191) 了 Confucius4-R2T2（15 点赞、1 回复、809 浏览量、7 收藏）：这是一款面向字幕、翻译和语音智能体的真流式 ASR 模型。关键主张不只是更低延迟，而是仅追加式解码：它能避免转录内容来回闪烁，让下游智能体接收到的是稳定文本，而不是一条不断被重写的候选转录流。

![Docling README 截图，展示其广泛的文档格式覆盖、集成方式，以及它作为生成式 AI 工作流统一结构化摄取层的定位](https://pbs.twimg.com/media/HSovY_gaoAATE6A.jpg)

**讨论要点：** 反复出现的诉求并不是抽象地“支持更多格式”，而是要保留结构、保留来源、让延迟可预测，并在出错时仍能轻松检查输出。

**与前日对比：** 相比 2026-09-18 更偏硬件和运行时的本地模型讨论，2026-09-20 更关注数据摄取和转录层，因为正是它们决定了更小或本地系统到底能不能用。

### 1.4 物理 AI 帖子更关心可用的空间真值和修复闭环，而不是原始数据量 🡕

物理 AI 的声量依然小于软件 AI，但留下来的帖子罕见地高度一致。它们把瓶颈看成一个数据物流问题：怎样低成本采集现实世界、尽早做隐私过滤、证明数据来自哪里、再以 API 形式提供出来，以及持续从机器人出错的具体瞬间学习。

[@0xdnll](https://x.com/0xdnll) [认为](https://x.com/0xdnll/status/2101536437933855204) Vangrid 真正有意思的层，不是 900 万美元融资，而是让日常使用的手机充当边缘节点，去采集那些卫星和旧式地图覆盖不好的环境（92 点赞、104 回复、311 浏览量）。那条推文把结果描述成一套由人驱动的空间数据集，配有链上证明、数据浏览器和贡献激励，而不是一个泛泛的加密故事。

[@0x_zoda](https://x.com/0x_zoda) [把](https://x.com/0x_zoda/status/2101524082491601259) 同一场讨论又往产品现实推近了一步（29 点赞、33 回复、185 浏览量），核心是 Vangrid 的 Spatial API。附图和公开的 [API 文档](https://docs.vangrid.io/api/overview) 把关键转变讲得很明白：先采集真实地点、再验证它们，然后让开发者为仓库、装卸码头和室内机器人等场景发现、请求、获取并集成空间数据。

[@CoderJunkie](https://x.com/CoderJunkie) [用](https://x.com/CoderJunkie/status/2101492154808029661) 一张 Vangrid Explorer 图片把规模和来源问题讲得更直观（3 点赞、2 回复、10 浏览量）：上面显示了网格事件、采集、证明、活跃节点，以及一个“开放世界模型 API”；与此同时，[@Aliba_79](https://x.com/Aliba_79) [认为](https://x.com/Aliba_79/status/2101567633275686921) 机器人不缺芯片，缺的是人类记忆（54 点赞、62 回复、345 浏览量）：用浏览器遥操作做预训练、在后训练阶段由人修复失败案例，并把这些修正作为一条不断增长的记忆链来拥有。

![架构图，展示手机采集如何流入 Vangrid Spatial API，再进入仓库、装卸码头和室内空间等物理 AI 用例](https://pbs.twimg.com/media/HSoc_HRWUAAEVgO.jpg)

![Vangrid Explorer 仪表盘，显示采集、证明、活跃节点，以及一个面向去中心化空间真值的“开放世界模型 API”](https://pbs.twimg.com/media/HSn_4uiaEAAYudL.png)

**讨论要点：** 真正有意思的分歧不在于更多现实世界数据是否重要，而在于什么让这些数据真正有用：来源证明、采集时的隐私保护、API 访问，以及把失败本身变成下一份训练资产的反馈闭环。

**与前日对比：** 相比 2026-09-17 和 2026-09-19，这个类别又往“采集市场”口号之外走了一步，更接近具体的 API 界面、来源机制，以及把修复纳入环路的数据复利。

## 2. 令人困扰的问题

### 微小的智能体决策仍在支付前沿模型的价格

反复出现最多的智能体设计挫败点，不在推理质量，而在于那些本该便宜、类型化、易审计的小决策，仍要支付前沿模型的成本。[@Layton_Gott](https://x.com/Layton_Gott) [列出](https://x.com/Layton_Gott/status/2101525943818899811) 了适合 Jev 的有边界任务（5 点赞、4 回复、175 浏览量、4 收藏）：路由、重试逻辑、风险闸门、人工审核队列、动态权限、支出防火墙和输出检查；[@LangChain](https://x.com/LangChain) [说明](https://x.com/LangChain/status/2101454284927959080) 了为什么人们想要这种分层（328 点赞、37 回复、26,550 浏览量、418 收藏）：它把 Jev 和 LLM 裁判放在准确率、方差、延迟和成本上做了基准对比；而 [@_raghavdixit_](https://x.com/_raghavdixit_/status/2101704858868793450)（20 点赞、5 回复、6,507 浏览量、17 收藏）及回复，则把这种挫败感进一步沉淀成围绕冻结标签集、留出校准、无效选项测试和人工升级处理的操作规则。

严重程度：高。团队现在靠在更大模型前插入决策层勉强应对，但围绕路由、闸门和单步成本的帖子量表明，这里仍是一个非常开放、值得构建的产品界面。

### 基准和演示的成功，仍在掩盖长时程脆弱性

第二个挫败点是，看起来很好的评估依然回答不了生产环境真正的问题。[@github](https://x.com/github) [认为](https://x.com/github/status/2101454543837929615)（50 点赞、12 回复、16,619 浏览量、25 收藏），一个模型可以在干净基准上拿高分，却仍会在生产里那些真正重要的含糊、不完整或被截断的输入上失败，所以评估必须从产品决策、安全约束和运营护栏出发。[@amodexbt](https://x.com/amodexbt) [带出](https://x.com/amodexbt/status/2101634330090942756) 了一段论文摘要（14 点赞、3 回复、305 浏览量、10 收藏），称在 10,664 条轨迹上的一项智能体任务里，成功率会在 16 步内从近乎完美坍塌到接近 0；而 [@DivyanshT91162](https://x.com/DivyanshT91162) [推介](https://x.com/DivyanshT91162/status/2101592987574874319) AgentCompass，恰恰因为团队现在想要的是轨迹、工具调用、失败、延迟和可复现工件，而不是一个混在一起的通过率（18 点赞、11 回复、527 浏览量）。

严重程度：高。权宜方案已经很清楚：回放固定轨迹、给提示词和数据集做版本管理、记录完整轨迹，并按步骤编制可靠性预算。这里显然值得围绕它构建产品，因为对基准的信任，如今已经是工程瓶颈，而不是边缘抱怨。

### 输入管线往往在模型质量变重要之前就先坏掉了

几条帖子都在暗示，输入层仍是那些本来不错的系统悄悄失效的地方。[@duqaXxX](https://x.com/duqaXxX) [展示](https://x.com/duqaXxX/status/2101383616563458154) 说明，对一套在普通硬件上运行的本地文档助手来说，真正让人信任的是带来源文件标注的回答和 OCR 优先路由（35 点赞、17 回复、106,291 浏览量、10 收藏）。[@RituWithAI](https://x.com/RituWithAI) [强调](https://x.com/RituWithAI/status/2101544289847148886) Docling，是因为现在一个解析器必须保住版面、表格、公式、邮件、音频、视频和图表结构，而不能把一切都剥成纯文本；紧接着就有一条回复追问来源信息和抽取可追踪性（12 点赞、8 回复、136 浏览量、7 收藏）。[@ModelScope2022](https://x.com/ModelScope2022) [把](https://x.com/ModelScope2022/status/2101605223726760191) 同一个问题换成语音形态（15 点赞、1 回复、809 浏览量、7 收藏）：转录闪烁会拖垮下游智能体，所以仅追加式流式 ASR 不再只是工程细节，而是功能本身。

严重程度：中高。构建者现在靠 OCR 优先管线、来源文件引用、保结构解析器和稳定解码来应对，但这些证据表明，输入规范化仍然值得构建，因为它决定了更小、更便宜的模型到底能不能用。

### 物理 AI 仍缺少可查询、来源信息丰富的真值数据

物理 AI 的挫败点发生在建模之前。[@0xdnll](https://x.com/0xdnll/status/2101536437933855204)（92 点赞、104 回复、311 浏览量）把缺口定义为：那些卫星和静态地图覆盖不好的地方，缺少来自现实世界的采集数据；[@0x_zoda](https://x.com/0x_zoda/status/2101524082491601259)（29 点赞、33 回复、185 浏览量）又把更难的后续问题往前推了一步：怎样把这些采集结果变成一个机器人团队真正能查询的 API；[@CoderJunkie](https://x.com/CoderJunkie/status/2101492154808029661)（3 点赞、2 回复、10 浏览量）则用 Explorer 统计和“采集证明”的说法，把来源和规模问题可视化了出来；而 [@Aliba_79](https://x.com/Aliba_79/status/2101567633275686921)（54 点赞、62 回复、345 浏览量）认为，真正稀缺的不是芯片，而是人工纠错数据。

严重程度：中高。人们现在靠贡献者网络、来源哈希和把修复纳入环路的数据采集来应对，但这个类别依然值得构建，因为这条数据轨本身还远未成熟，也谈不上可互换。

## 3. 人们期望的功能

### 面向有边界智能体工作的可审计决策层

最清晰的愿望清单条目，是一层位于代码和通用 LLM 之间、便宜且类型化的决策层。[@Layton_Gott](https://x.com/Layton_Gott/status/2101525943818899811)（5 点赞、4 回复、175 浏览量、4 收藏）为路由、重试逻辑、支出防火墙、权限和人工审核队列标出了明确插槽，而 [@LangChain](https://x.com/LangChain/status/2101454284927959080)（328 点赞、37 回复、26,550 浏览量、418 收藏）则用固定轨迹上更低成本、方差更小的裁判行为给出了经济动机。[@_raghavdixit_](https://x.com/_raghavdixit_/status/2101704858868793450)（20 点赞、5 回复、6,507 浏览量、17 收藏）及回复展示了仍然缺失的产品特质：校准回放、明确冻结标签、无效选项测试，以及安全的升级路径。机会：直接。

### 能感知时程跨度的评估栈，要追踪真实轨迹而不只是通过率

最强烈的评估愿望，不是再来一份基准清单，而是要一套可复用系统：能回放真实轨迹、衡量长工作流会在何处衰减，并保留足够多的工件来支持是否上线的决策。[@github](https://x.com/github/status/2101454543837929615)（50 点赞、12 回复、16,619 浏览量、25 收藏）希望评估与产品结果和护栏直接绑定，[@DivyanshT91162](https://x.com/DivyanshT91162/status/2101592987574874319)（18 点赞、11 回复、527 浏览量）希望有一个统一框架来管理模型、基准、测试框架和环境，而 [@amodexbt](https://x.com/amodexbt/status/2101634330090942756)（14 点赞、3 回复、305 浏览量、10 收藏）则希望按步骤数来做可靠性预算，而不是再演一场基准秀。这既紧迫又务实，但今天仍只被部分满足。机会：直接。

### 来源关联的摄取层，既保留结构、来源，也守住延迟预算

大家想要的显然不只是“更好的 RAG”。他们要的是一层统一的摄取层，能处理文档、扫描件、电子表格和语音，而不破坏结构，也不让来源核验变得痛苦。[@duqaXxX](https://x.com/duqaXxX/status/2101383616563458154)（35 点赞、17 回复、106,291 浏览量、10 收藏）把来源文件归因和 OCR 优先路由做成了本地文档问答的信任锚点。[@RituWithAI](https://x.com/RituWithAI/status/2101544289847148886)（12 点赞、8 回复、136 浏览量、7 收藏）把 Docling 讲成格式混乱下的“一库通吃”答案，而 [@ModelScope2022](https://x.com/ModelScope2022/status/2101605223726760191)（15 点赞、1 回复、809 浏览量、7 收藏）则把稳定的实时转录抬成了语音智能体的一等需求。这个需求务实且迫切，但赛道已经开始拥挤。机会：竞争型。

### 在采集时就保护隐私、默认带来源信息的空间真值 API

物理 AI 帖子暗示的愿望很清楚：一张空间数据网络，既更容易采购，也更容易信任。[@0xdnll](https://x.com/0xdnll/status/2101536437933855204)（92 点赞、104 回复、311 浏览量）想要更广的地面采集，[@0x_zoda](https://x.com/0x_zoda/status/2101524082491601259)（29 点赞、33 回复、185 浏览量）想要把这些采集结果做成可调用的 API，[@CoderJunkie](https://x.com/CoderJunkie/status/2101492154808029661)（3 点赞、2 回复、10 浏览量）想要看得见的采集证明和网络统计，而 [@Aliba_79](https://x.com/Aliba_79/status/2101567633275686921)（54 点赞、62 回复、345 浏览量）想要让纠错数据沉淀成一条归自己所有的记忆链。需求是真实的，但市场运营很重，而且很可能高度依赖网络效应。机会：竞争型。

当一款工具做的是收窄不确定性，而不是再套一层通用模型包装时，满意度最高。Jev 把“下一步该发生什么？”收窄成类型化决策。Docling 把文档混乱收窄成结构化输出。Confucius4-R2T2 把嘈杂语音收窄成稳定文本。Vangrid 则把物理 AI 的数据获取收窄成采集、验证和 API 交付。

权宜模式也很一致：把廉价、结构化的决策路由给决策模型，把昂贵的前沿模型留给开放式推理；能先跑 OCR 就先跑 OCR；本地模型按需加载，不要常驻；以及在大规模信任一条管线之前，先要到来源信息或回放工件。

最大的迁移信号还是经济性。开放权重模型正在吃下更多日常 token 流量；把 LLM 当裁判的配置，正受到“更便宜的决策优先评估器 + 选择性人工审核”的挑战；而本地或隔离网络环境中的解析栈，只要能保留结构而不是把一切压扁成文本，也在获得更多可信度。因此，主要竞争断层并不抽象地落在“开放还是闭源”上，而在于哪一层拥有路由、可观测性、来源信息，以及判断“此刻是否真的值得为更贵模型付费”的权利。

## 7. 机会在哪里

**[+++] 可靠性预算与评估控制平面** - 第 1、2、4 和 6 节都指向同一个缺口：基准分数远远不够，长时程任务会急剧衰减，而团队想要可回放的轨迹、步骤级护栏、校准检查和面向生产的工件。GitHub 的评估生命周期、AgentCompass，以及《How Fast Do Agents Rot?》都证明，这是一项强烈且眼下就存在的机会。

**[+++] 面向路由、权限和审核队列的决策层原语** - Jev 持续上升的势头，来自非常具体的放置想法：模型路由、重试逻辑、风险检查、支出防火墙、动态权限，以及人工审核队列。这里的机会，在于为更大推理模型之前的那一层，提供廉价、类型化、可审计的决策能力。

**[+++] 来源关联的摄取与稳定转录基础设施** - Docling、那台本地 Mac Mini 助手，以及 Confucius4-R2T2 都说明，大家对这类系统有真实胃口：它们能保留结构、让来源始终可见，并阻止转录内容把下游智能体来回拉扯。这很强，因为它提升的是其上每一种模型选择的可用性，包括更小和本地的模型。

**[++] 面向物理 AI 的来源感知型空间真值 API** - Vangrid 和 Axis 指向了一个有意义、但更沉重的类别：在带隐私保护的前提下收集现实世界数据，证明它来自哪里，再做成 API 提供出来，并持续从修复闭环中学习。证据是真实的，但它的市场推进和网络效应负担，看起来都比纯软件类别更重。

**[+] 低成本本地多模态部署套件** - Qwen-Image-2.1、Intel Arc B70 的实测数据，以及开放模型 token 份额的跃升，都说明市场会继续需要实用的本地或自托管栈。这个机会仍在浮现、还谈不上完全被验证，因为不同硬件和工作负载上的软件易用性看起来依然很不均衡。

## 8. 要点总结

1. **开放权重 AI 看起来不再像小众偏好，而更像日常工作的默认大流量通道。** [@Alibaba_Qwen](https://x.com/Alibaba_Qwen) [发布](https://x.com/Alibaba_Qwen/status/2101659302792679789) 了一款严肃的多模态图像模型，并附带即时可用的工具支持（1,002 点赞、52 回复、52,440 浏览量、352 收藏）；[@TeksEdge](https://x.com/TeksEdge) [贴出](https://x.com/TeksEdge/status/2101431138384490764) 了具体的本地硬件实测数据（32 点赞、13 回复、3,709 浏览量、19 收藏）；而 [@AGTPInsights](https://x.com/AGTPInsights) [分享](https://x.com/AGTPInsights/status/2101730665553440778) 了那张网关快照（1 引用、68 浏览量），显示开放权重模型已占到 78.4% 的 token 量。当天传出的信息，首先是经济性的，其次才是意识形态上的。 ([来源](https://x.com/Alibaba_Qwen/status/2101659302792679789))
2. **Jev 之所以仍处在中心，是因为构建者现在已经很清楚自己想把决策模型放在哪一层。** [@LangChain](https://x.com/LangChain) [把它作为评估器做了基准测试](https://x.com/LangChain/status/2101454284927959080)（328 点赞、37 回复、26,550 浏览量、418 收藏），[@Layton_Gott](https://x.com/Layton_Gott) [画出了](https://x.com/Layton_Gott/status/2101525943818899811) 那些有边界的用例（5 点赞、4 回复、175 浏览量、4 收藏），而 [@_raghavdixit_](https://x.com/_raghavdixit_) [补上了](https://x.com/_raghavdixit_/status/2101704858868793450) 校准层面的保留意见（20 点赞、5 回复、6,507 浏览量、17 收藏）。有意思的变化，是它已经从类别炒作走向操作纪律。 ([来源](https://x.com/LangChain/status/2101454284927959080))
3. **对评估的怀疑，已经成熟成了可靠性工程。** [@github](https://x.com/github) [认为](https://x.com/github/status/2101454543837929615)，离线评估必须从产品决策和护栏出发（50 点赞、12 回复、16,619 浏览量、25 收藏）；[@DivyanshT91162](https://x.com/DivyanshT91162) [带出](https://x.com/DivyanshT91162/status/2101592987574874319) 了一套用于管理基准 / 测试框架 / 环境的框架（18 点赞、11 回复、527 浏览量）；而 [@amodexbt](https://x.com/amodexbt) [放大了](https://x.com/amodexbt/status/2101634330090942756) 一篇关于长时程智能体衰减的论文（14 点赞、3 回复、305 浏览量、10 收藏）。这条信息流更少关心表面的总分，更关心系统会在什么地方随着时间推移而失效。 ([来源](https://x.com/github/status/2101454543837929615))
4. **输入质量持续显露出自己是决定模型可用性的隐藏变量。** [@duqaXxX](https://x.com/duqaXxX) [展示](https://x.com/duqaXxX/status/2101383616563458154) 了本地文档问答怎样在答案引用来源文件时才变得可信（35 点赞、17 回复、106,291 浏览量、10 收藏），[@RituWithAI](https://x.com/RituWithAI) [重点提到](https://x.com/RituWithAI/status/2101544289847148886) Docling 的保结构解析界面（12 点赞、8 回复、136 浏览量、7 收藏），而 [@ModelScope2022](https://x.com/ModelScope2022) [宣布](https://x.com/ModelScope2022/status/2101605223726760191) 了仅追加式流式 ASR（15 点赞、1 回复、809 浏览量、7 收藏）。真正的需求，是那种能让证据从头到尾都保持可读、可查的系统。 ([来源](https://x.com/duqaXxX/status/2101383616563458154))
5. **物理 AI 的讨论声量依然小于软件 AI，但它对缺失数据层应是什么样子，讲得更具体了。** [@0xdnll](https://x.com/0xdnll) [把](https://x.com/0xdnll/status/2101536437933855204) 手机采集框成一种新的空间真值来源（92 点赞、104 回复、311 浏览量），[@0x_zoda](https://x.com/0x_zoda) [把重点放在](https://x.com/0x_zoda/status/2101524082491601259) 如何通过 API 使用这层真值（29 点赞、33 回复、185 浏览量），而 [@Aliba_79](https://x.com/Aliba_79) [认为](https://x.com/Aliba_79/status/2101567633275686921) 修复数据才是真正会复利的资产（54 点赞、62 回复、345 浏览量）。这一天的主题不是“采更多画面”，而是“先采集、再验证、可查询，并从失败中学习”。 ([来源](https://x.com/0xdnll/status/2101536437933855204))
