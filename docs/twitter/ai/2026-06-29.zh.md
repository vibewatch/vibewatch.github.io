# Twitter AI - 2026-06-29

## 1. 人们在讨论什么

### 1.1 智能体运行时和评估业务，已从演示层面的讨论转向运行层主张（🡕）

信息流中最活跃的话题，已经不再只是聊天质量，而是智能体系统能否成为持久的工作运行层，以及评估平台能否将这一转变商业化。三个不同的帖子共同支撑了同一个观点：以基准测试驱动的智能体运行时、作为产品的部署后评估，以及面向代码仓库的多智能体交接流程层。

[@kimmonismus](https://x.com/kimmonismus) [认为](https://x.com/kimmonismus/status/2071668628261687352) (273 个赞、22 条回复、53,607 次浏览、260 次收藏) 表示，Matrix 是他见过的第一个不像提示词编排、而更像运行层的“AI 公司”产品；他还引用了一项 GDPval-Bench 结果：Matrix 得分 95.45%，Codex CLI 为 84.9%，Claude Opus 4.7 为 80.3%。

![Matrix GDPval-Bench 图表显示，Matrix GPT-5.5 以 95.45% 领先，Codex CLI GPT-5.5 为 84.9%，Claude Opus 4.7 为 80.3%，Gemini 3.1 Pro 为 67.3%](https://pbs.twimg.com/media/HMALo2VaoAAxut6.jpg)

[@arena](https://x.com/arena) [报道称](https://x.com/arena/status/2071630464583151727) (167 个赞、13 条回复、35,451 次浏览、61 次收藏) 表示，其评估产品在上线八个月后已达到 1 亿美元年化收入运行率；引用的 [@ml_angelopoulos](https://x.com/ml_angelopoulos/status/2071629882057228680) 帖子补充称，已有数百万用户在运行包含数百次工具调用的长时多轮智能体会话，并衡量任务完成率和幻觉率，而不只是偏好投票。

![Arena 增长图表显示，其在 8 个月内从 0 美元 ARR 攀升至 1 亿美元 ARR，与其他高速增长的软件公司对比](https://pbs.twimg.com/media/HL_lBvBasAI_Xrv.jpg)

[@Chrismccann](https://x.com/Chrismccann/status/2071635725666439559) [分享了](https://x.com/Chrismccann/status/2071635725666439559) (1 个赞、2 条回复、379 次浏览) 发布了一个面向 Claude Code、Codex 及类似智能体的 [Agent Bootstrap Kit](https://github.com/chrismccann-dev/agent-bootstrap-kit)。该仓库将项目本身定位为长期事实来源：通过根智能体索引、稳定文档和可复用技能，让工作能够在不同智能体之间流转，而无需反复解释上下文。

**讨论洞察：** 最强烈的质疑来自 [@VK_ROXy](https://x.com/VK_ROXy)。[回复道](https://x.com/VK_ROXy/status/2071669268366643229) 指出，当合成评估钩子遇上生产环境延迟和薄弱的状态持久化时，协作基准测试可能会失效。因此，今天的运行时叙事与其说是“智能体已经被解决”，不如说是“评估和记忆设计如今才是真正的竞争焦点”。

**与前一天比较：** 2026-06-26，智能体式 AI 的讨论主要围绕企业内部的跨职能采用。到了 2026-06-29，信息流进一步下沉到基础设施供应商和运行时产品，它们声称自己能够将这种采用真正落地。

### 1.2 验证成为科学研究和自我改进智能体的瓶颈（🡕）

第二个主题是：AI 生成已经不再稀缺，验证才是。当天最有力的证据来自科学评审工具和递归改进研究；二者都将评估质量视为限制因素。

[@dair_ai](https://x.com/dair_ai) [强调了](https://x.com/dair_ai/status/2071688411229094397) (63 个赞、6 条回复、4,838 次浏览、67 次收藏) 提到了 Google Research 关于自动化科学评审的论文，并强调 AI 辅助论文生成的速度已经超过人类评审能力。附带的论文图片将该系统称为 Paper Assistant Tool (PAT)，它能够读取完整论文，并评估理论、实验和潜在缺陷。

![Google Research 论文《Towards Automating Scientific Review with Google's Paper Assistant Tool》的第一页，将 PAT 描述为一个具备代理能力的审查与验证框架](https://pbs.twimg.com/media/HMAdoXCacAAbqtl.jpg)

论文指出，在 SPOT 基准测试中，PAT 对数学错误的零样本召回率提升了 34%，并已作为 STOC 和 ICML 的投稿前工具开展试点（[论文](https://arxiv.org/abs/2606.28277)）。

[@rohanpaul_ai](https://x.com/rohanpaul_ai) [概述了](https://x.com/rohanpaul_ai/status/2071459875570552852) (10 个赞、3 条回复、1,887 次浏览、4 次收藏) 提到了 [Red Queen Godel Machine 论文](https://arxiv.org/abs/2606.26294)，将其视为一种让智能体与评估器共同演化、而不是固定基准测试不变的方法。论文称，加入“智能体即评审者”的评估信号后，编码表现有所提升，同时 token 用量减少了 1.35x-1.72x；论文写作的接收率则提高了 1.78x-1.86x。

**讨论洞察：** dair_ai 的一条回复中，[@yagi_dsn](https://x.com/yagi_dsn/status/2071708743218221151) 简洁地概括了这一主题：没有验证的生成只是噪声。回复者并未否认这一瓶颈，而是在争论一旦评审基础设施成为必需，价值最终会流向哪里。

**与前一天比较：** 2026-06-26，验证基础设施还不是主要话题。到了 2026-06-29，验证问题被明确提出：Google Research 和递归智能体研究都将评估器质量视为新的约束。

### 1.3 开放权重和本地编码技术栈，比拼重点从推理深度转向速度、成本和自主性（🡕）

开放权重模型的讨论继续远离“哪个模型最聪明”，转向“哪个技术栈在实际运行中最便宜、最快”。最受关注的帖子聚焦于关闭冗长推理轨迹、提升模型服务速度，以及让更多工作留在本地。

[@KyleHessling1](https://x.com/KyleHessling1) [宣布](https://x.com/KyleHessling1/status/2071632413785194834) (140 个赞、19 条回复、6,264 次浏览、99 次收藏) 将 Qwopus-3.6-35B-A3B-MTP-Coder 描述为一款快速的本地 MoE 编码模型，关闭思考模式后表现尤其突出；该帖称，它在 RTX 5090 上可达到每秒 253 个 token，并且配合 opencode 处理冗长、详细的提示词效果良好。其后续回复还链接了一个由模型生成的幻灯片 deck 和一个 RTS 游戏演示，二者都被用来证明：即使没有昂贵的推理轨迹，该模型仍然实用。

[@iam_elias1](https://x.com/iam_elias1) [声称](https://x.com/iam_elias1/status/2071555697779839473) (40 个赞、12 条回复、1,384 次浏览、12 次收藏) 表示，DeepSeek 的 DSpark 让每位用户的服务速度提升了 57% 至 85%，并在更具代表性的运行条件下，将总体吞吐量提高约 51% 至 52%；同时，DeepSpec 还开放了实现路径。该帖明确指出，最引人注目的 400% 吞吐量数字来自最佳 SLA 场景，并不代表普遍的生产结果。

[@martechismktg](https://x.com/martechismktg) [认为](https://x.com/martechismktg/status/2071708081180819790) (3 个赞、126 次浏览、3 次收藏) 表示，由于工具调用不断将上下文重新喂回模型，智能体工作流正变得不合算。所链接的 [MarTech 文章](https://martech.org/agentic-ai-is-rewriting-martech-economics-and-infrastructure/) 将典型日常工作流量化为每次运行 4,000 至 5,000 个 token、每月超过 100,000 个 token，并声称使用自有上下文过滤后，token 成本可降低 60% 以上。

![MarTech 插图展示了 API 调用、文件读取、网页搜索和 CRM 拉取如何将代理式工作流的 token 计量表推向 98% 的使用率](https://pbs.twimg.com/media/HMAvXARWoAAZboT.jpg)

**讨论洞察：** 大家共同抱怨的并不是模型能力不足，而是计算资源浪费：成千上万个思考 token、反复重放上下文，以及工具密集型循环，都在输出质量提升之前推高了延迟和账单。

**与前一天比较：** 2026-06-26，人们对本地模型的热情主要集中在主权和可获得性。到了 2026-06-29，讨论变得更加务实：免思考编码模型、推测解码效率，以及上下文过滤带来的经济性。

### 1.4 中美 AI 竞争继续从模型发布转向基础设施和出口管制的反作用（🡕）

地缘政治仍是强势主题，但重点已从单个模型发布转向维持领先地位所需的基础设施。多个帖子将开源分发、能源容量和出口管制政策串联成一个整体论点。

[@Yuchenj_UW](https://x.com/Yuchenj_UW) [预测](https://x.com/Yuchenj_UW/status/2071636150750785769) (272 个赞、21 条回复、10,363 次浏览、11 次收藏) 表示，如果中国实验室在几个月内击败 Fable 5 和 GPT-5.6，那么当前对禁令的恐慌将显得目光短浅。回复进一步推进了这一观点：[@VibeCoderOfek](https://x.com/VibeCoderOfek/status/2071638938433366359) 认为，只有在能力本身稀缺的情况下，出口管制才能争取时间；另一条回复则担心，政府下一步可能会试图封锁推理服务商。

[@kimmonismus](https://x.com/kimmonismus) [认为](https://x.com/kimmonismus/status/2071524362012791114) (109 个赞、18 条回复、9,719 次浏览、38 次收藏) 表示，美国更大的脆弱点是基础设施，而不只是模型政策。他引用了中国推动开源、基于 Huawei 的技术栈自主化，以及美国在数据中心和电力容量方面的短缺。

![预测的 AI 数据中心电力图表显示，需求将从 2024 年的 11 GW 上升到 2030 年的 327 GW，远远超出当前州级规模的电力基线](https://pbs.twimg.com/media/HL-GjARXAAAbMYG.jpg)

**与前一天比较：** 2026-06-26，中美 AI 讨论更多围绕访问控制和转售商经济。到了 2026-06-29，重心转向电力、数据中心容量，以及出口管制是否会让开源替代方案更具吸引力。

## 2. 人们感到挫败的地方

### 长时间运行的智能体工作流消耗 token 的速度超过质量提升速度

严重程度：高。信息流中最明确的运营层面抱怨是：工具密集型智能体循环在变得可靠之前，就已经十分昂贵。[@martechismktg](https://x.com/martechismktg/status/2071708081180819790) 指出，某种工作流每月可能消耗超过 100,000 个 token；所链接的 MarTech 文章则称，单条日常流水线每次运行就可能消耗 4,000 至 5,000 个 token。[@KyleHessling1](https://x.com/KyleHessling1/status/2071632413785194834) 实际上也在从模型侧优化同一个痛点，称赞一款编码模型能够避免“在可执行的连贯输出出现前，先思考 8k 个 token”。这一领域值得投入，因为替代方案已经初现雏形：自有上下文存储、更小的草稿模型，以及本地免思考模型。

### AI 生成研究正跑在人类评审层之前

严重程度：高。[@dair_ai](https://x.com/dair_ai/status/2071688411229094397) 将评审描述为 AI 科学家工作流中的真正瓶颈；附带的 PAT 论文则将科学评估视为系统问题，而不是评审人手不足的问题。[@rohanpaul_ai](https://x.com/rohanpaul_ai/status/2071459875570552852) 从另一个角度强化了这一挫败感：固定评估器会过时、容易被钻空子，或能力太弱，无法让递归智能体保持诚实。目前的应对方式包括投稿前工具、评审智能体和人类参与检查点，但信息流表明，这些方案仍处于早期，尚未定型。

### 模型延续性和访问权限可能在没有有效用户救济的情况下消失

严重程度：高。Keep4o 的整份提交材料都建立在这一挫败感之上：一个有用的模型可能仅因供应商的选择而被退役、限制或降质。[@Blue_Beba_](https://x.com/Blue_Beba_/status/2071562445072572510) 引用了法律投诉、政策提交和同行评审证据，因为普通产品反馈渠道并不足够。之所以严重，正是因为一些用户将这些模型视为无障碍工具或心理健康支持工具，而不是可以随时丢弃的聊天产品。

### 出口管制无法解决基础设施缺口，反而可能加剧碎片化

严重程度：中到高。[@Yuchenj_UW](https://x.com/Yuchenj_UW/status/2071636150750785769) 和 [@kimmonismus](https://x.com/kimmonismus/status/2071524362012791114) 指向了相似的抱怨：政策讨论一味聚焦于禁止访问，而计算能力、电力和数据中心建设才是更难解决的瓶颈。kimmonismus 图片中的 327 GW 需求预测曲线，让这一痛点变得具体。人们反复提出的应对方式，是建立多模型、多地域的韧性，而不是依赖单一获准供应商。

## 3. 人们希望存在什么

### 对已退役前沿模型的持久访问

这是信息流中最明确的诉求。Keep4o 希望供应商将已弃用模型开源，作为数字公共基础设施，而不是直接移除。这个请求具有很强的现实性，而非象征意义：用户要求延续性、无障碍访问，以及某种防止模型被单方面退役的保障。机会：直接。

### 能够承受供应商切换的自有上下文、多模型智能体系统

多个条目从不同角度暗示了同一需求。MarTech 文章认为，团队应将原始上下文掌握在自己手中，以降低 token 成本；[Agent Bootstrap Kit](https://github.com/chrismccann-dev/agent-bootstrap-kit) 将代码仓库视为智能体的持久记忆；出口管制讨论则暗示，如今任何认真的团队都需要模型供应商冗余。市场缺口在于一种简洁的产品：结合上下文持久化、低成本检索和便捷模型切换，同时无需定制基础设施。机会：直接。

### 面向科学研究和自我改进智能体的验证基础设施

PAT 论文和 Red Queen Godel Machine 都假定，评估器质量必须与生成器质量同步提升。人们似乎想要的不是另一个内容生成器，而是评审智能体、基准维护工具、对抗性评判小组，以及可追溯的审计循环。这个领域仍具竞争性，因为研究实验室、前沿模型公司和基础设施初创企业都在同时进入。机会：竞争性。

总体来看，这些工具反映出一个明显趋势：人们正在远离“一个更大的模型就能解决一切”的思路，转而主动组合更便宜的本地模型、服务优化、基于代码仓库的记忆，以及部署后的评估。主要的应对模式是：将昂贵或脆弱的上下文移出模型会话，放入团队拥有的基础设施中。

## 7. 机会在哪里

**[+++] 面向智能体式工作的验证基础设施** — PAT、Red Queen Godel Machine，以及围绕“验证负债”的回复讨论，都指向同一个缺口：评估智能体、评审小组、基准维护和审计循环，用于在自主系统脱离玩具任务后继续维持其可信度。

**[+++] 面向团队的自有上下文、多模型运营** — token 膨胀、供应商碎片化和代码仓库记忆工具，都表明市场存在明显机会：让上下文留在模型之外，跨供应商路由，并在长期工作中保持连续性。

**[++] 模型延续性和退役保险** — Keep4o 向联合国提交材料，显示市场确实需要能够在供应商退役或限制有用模型时保留访问权限的产品或政策。这在无障碍和支持类使用场景中尤其明显。

**[++] 面向开放权重部署的推理效率工具** — Qwopus 和 DSpark 都表明，速度和硬件效率正成为首要采购标准。团队希望以更低成本获得本地或自托管性能，同时不牺牲输出质量。

**[+] 面向跨境 AI 韧性的基础设施规划** — 出口管制和电力容量的讨论表明，围绕多区域模型策略、本地托管和计算规划存在长期机会；这些方案需要假定政策碎片化将持续存在。
