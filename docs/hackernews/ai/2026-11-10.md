# HackerNews AI - 2026-11-10

## 1. What People Are Talking About

### 1.1 Agent guidance targets outdated web patterns (↗)

The leading story introduced a stable release of Modern Web Guidance, a set of agent skills and a CLI intended to steer coding agents toward current web-platform features and away from older JavaScript workarounds. The builder says its 200+ guides and paired evaluations improved agents' pass rate from 55% to 92% across 200 tasks and about 1,700 Playwright and AST assertions; these are project-reported results, not an independent benchmark. The story received 187 points and 56 comments. ([Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance); [Chrome 1.0 announcement](https://developer.chrome.com/blog/modern-web-guidance-v1); [HN story](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments))

**Discussion insight:** Commenters raised a concrete compatibility concern: some recommended APIs are not supported in both Firefox and Safari. Others warned against concentrating web guidance in Chrome's hands, while one commenter found a compatible subset after asking an agent to filter recommendations for Chrome, Firefox, and Safari. The project says it includes browser compatibility data and fallbacks; its evaluation dashboard also cautions that automated accessibility assertions are not a full WCAG audit. ([surround](https://news.ycombinator.com/user?id=surround) (score 0); [codepoet80](https://news.ycombinator.com/user?id=codepoet80) (score 0); [pyrolistical](https://news.ycombinator.com/user?id=pyrolistical) (score 0); [evaluation dashboard](https://googlechrome.github.io/modern-web-guidance-src/))

**Comparison to prior day:** November 9's leading discussion focused on what authority an agent should inherit from a user's environment. On November 10, the strongest discussion shifted to what domain knowledge and compatibility constraints should shape agent-written code. ([HN story](https://news.ycombinator.com/item?id=50422628) (197 points, 66 comments))

### 1.2 Vibe-coding raises concerns about maintainability (↗)

An Ask HN author said rapid AI-assisted feature work had increased codebase complexity without a central definition of behavior, making bugs feel like whack-a-mole and edge cases and UI regressions harder to review. The post received 15 points and 16 comments. ([nkcodes](https://news.ycombinator.com/user?id=nkcodes); [HN discussion](https://news.ycombinator.com/item?id=50444380) (15 points, 16 comments))

Replies suggested explicit plans and durable documentation, architecture-first work, automated tests and benchmarks, mutation testing, code audits, and independent review before pull requests. One commenter noted these practices were not based on a systematic ablation study; another warned that accumulated documentation can itself become bloated. The thread offers practitioner approaches, not comparative evidence that one process works best. ([sadilek](https://news.ycombinator.com/user?id=sadilek) (score 0); [mpd](https://news.ycombinator.com/user?id=mpd) (score 0); [Marco012](https://news.ycombinator.com/user?id=Marco012) (score 0))

### 1.3 Business returns from AI remain difficult to quantify (→)

An Ask HN discussion asked whether businesses are making money with AI. One reply described using AI for e-commerce categorization and spam detection, while another said developers were happier but the product did not launch faster. A third commenter said AI appeared to reduce costs without increasing revenue. These are individual reports; the 4-point, 11-comment thread does not establish a general return on investment. ([HN discussion](https://news.ycombinator.com/item?id=50435819) (4 points, 11 comments))

### 1.4 Agent orchestration and enterprise controls meet adoption questions (→)

Cosh, an open-source Rust orchestrator for tools such as Codex and Goose, received 6 points and 4 comments. Replies asked what it offers beyond agents' native orchestration and requested clearer comparisons with alternatives. ([Cosh](https://github.com/DiegoZaluski/co-sh); [HN story](https://news.ycombinator.com/item?id=50439141) (6 points, 4 comments))

Separately, Anthropic said JPMorganChase is expanding Claude Code use and described staged access, controlled environments on the bank's infrastructure, and automated tests and approval gates. A commenter questioned what information is sent to Anthropic and how it is retained. The story received 2 points and 3 comments; the announcement is the vendor's account, and the thread does not resolve the data-handling questions. ([Anthropic's account](https://claude.com/resources/articles/jpmorganchase-expands-claude-code); [HN story](https://news.ycombinator.com/item?id=50436993) (2 points, 3 comments); [ddxv](https://news.ycombinator.com/user?id=ddxv) (score 0))

## 2. What Frustrates People

### AI-generated changes can outpace a team's ability to reason about the code

**Severity: Medium; prevalence is unclear.** One developer said adding flows with an agent had made behavior harder to define and the resulting code harder to review, with bugs and UI edge cases recurring. Replies recommended plans, documentation, tests, and review gates, but the thread provides no measured comparison of those practices. This is worth addressing where teams are already experiencing the problem, though the post alone does not establish how widespread it is. ([HN discussion](https://news.ycombinator.com/item?id=50444380) (15 points, 16 comments))

### Modernization guidance can conflict with browser support requirements

**Severity: Medium; evidence is concentrated in one discussion.** Commenters on Modern Web Guidance listed APIs they said were not supported in both Firefox and Safari and questioned the risk of steering agents toward browser-specific features. A different commenter reported asking an agent to retain only features supported in Chrome, Firefox, and Safari. The project describes cross-browser data and fallbacks, but compatibility still depends on the target browsers chosen for a specific application. ([HN discussion](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments); [evaluation dashboard](https://googlechrome.github.io/modern-web-guidance-src/))

### AI productivity claims do not answer whether the business gained

**Severity: Medium; prevalence is unmeasured.** Replies to an Ask HN question distinguish saved labor and happier developers from faster launches, increased revenue, or profit after AI costs. Respondents offered anecdotes rather than comparable business metrics. This points to a measurement gap, not evidence that AI fails to produce returns. ([HN discussion](https://news.ycombinator.com/item?id=50435819) (4 points, 11 comments))

### Enterprise deployment leaves data boundaries open to interpretation

**Severity: Low-confidence, potentially high impact in regulated settings.** Anthropic's account says Claude Code runs in controlled environments on JPMorganChase infrastructure and that changes pass automated tests and approval gates. A commenter still asked what information leaves that environment and how conversation retention works. The thread contains a question, not evidence of a breach or of the actual data path. ([Anthropic's account](https://claude.com/resources/articles/jpmorganchase-expands-claude-code); [HN story](https://news.ycombinator.com/item?id=50436993) (2 points, 3 comments))

## 3. What People Wish Existed

### Quality controls that preserve product intent across agent-written changes

The Ask HN author wanted a central definition of behavior and a way to keep agent changes from creating more edge cases than the team can review. Replies proposed plans, durable decisions, test and review gates, and explicit rules for inspecting existing patterns. This is a practical need for teams seeing that failure mode; evidence of demand beyond the thread is limited. **Opportunity: direct, with prevalence unmeasured.** ([HN discussion](https://news.ycombinator.com/item?id=50444380) (15 points, 16 comments))

### Guidance that is searchable and respects each project's browser targets

Commenters asked for compatibility-aware recommendations and a way to retrieve guide content without installing a package. Modern Web Guidance already offers browser compatibility data and fallbacks, while the thread shows that developers still want clear control over which targets their agent should support. **Opportunity: competitive.** ([HN discussion](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments); [Modern Web Guidance](https://github.com/GoogleChrome/modern-web-guidance))

### Business reporting that separates time saved from financial return

The AI ROI discussion surfaced different measures: lower manual effort, developer satisfaction, launch speed, revenue, and profitability after infrastructure and model costs. Respondents wanted visible business numbers, but no common reporting baseline appeared in the thread. **Opportunity: competitive; the need is clear, but no specific product approach was validated.** ([HN discussion](https://news.ycombinator.com/item?id=50435819) (4 points, 11 comments))

### Verifiable training tasks with evidence of real-world transfer

TheoremSmith's author asked whether synthetic proof tasks improve performance on real proofs and how to prevent solvers from exploiting the verifier. Its pipeline uses Lean to check proofs, but the write-up distinguishes verifying a proof from ensuring that the problem specification captures intended behavior. **Opportunity: aspirational, pending evidence of transfer beyond generated tasks.** ([TheoremSmith write-up](https://charleshuang.me/2026/09/27/theoremsmith/); [HN story](https://news.ycombinator.com/item?id=50444276) (7 points, 0 comments))

## 6. New and Notable

### Formal proofs as a source of verifiable training tasks

TheoremSmith turns Lean 4 repositories into graded proof-completion tasks by removing a theorem's proof and checking a solver's replacement. Its author describes generating multi-hour tasks and asks whether they improve real proof performance or can be gamed. The project is technically specific, but its HN post received 7 points and no comments, so broader interest and transfer are unproven. ([TheoremSmith](https://github.com/abundant-ai/theoremsmith); [HN story](https://news.ycombinator.com/item?id=50444276) (7 points, 0 comments))

### Ternary training targets consumer GPU memory budgets

A builder described an optimizer that reduces reported training state from about 16 bytes to 1 byte or less per weight, with a claimed 27B-model training run on a 24 GB GPU. The same post notes unfinished conversion work and factual-knowledge loss in one converted model. These are early builder results, not independently replicated benchmarks; the story received 4 points and no comments. ([TTF repository](https://github.com/oguzeldereli/ttf-ternary); [HN story](https://news.ycombinator.com/item?id=50438889) (4 points, 0 comments))

## 7. Where the Opportunities Are

**[+++] Make agent changes easier to review and verify** — The most-discussed launch paired agent guidance with browser-based evaluations, while a separate developer described maintainability and review failures after AI-assisted feature growth. Together these point to demand for explicit behavior, compatibility-aware guidance, and repeatable checks; the discussions do not identify one proven workflow or product. ([HN story](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments); [HN discussion](https://news.ycombinator.com/item?id=50444380) (15 points, 16 comments))

**[++] Make browser targets an explicit part of agent instructions** — Commenters questioned when modern APIs are safe to use across browsers and asked for easier access to searchable guide content. Tools that take a project's target browsers as a constraint could reduce that uncertainty, although Modern Web Guidance already offers compatibility data and fallbacks. ([HN discussion](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments))

**[+] Publish comparable business outcomes for AI adoption** — The AI ROI thread distinguishes developer satisfaction and time savings from launch speed, revenue, and profitability, but provides only anecdotes. Transparent, comparable measurement could address the question; demand and willingness to pay are not established. ([HN discussion](https://news.ycombinator.com/item?id=50435819) (4 points, 11 comments))

**[+] Test whether generated proof tasks transfer to real work** — TheoremSmith offers a concrete verifier-backed pipeline, while its author openly asks whether synthetic tasks generalize and how to prevent verifier gaming. A reproducible transfer evaluation would strengthen this early research direction. ([TheoremSmith](https://github.com/abundant-ai/theoremsmith); [HN story](https://news.ycombinator.com/item?id=50444276) (7 points, 0 comments))

## 8. Takeaways

1. **Agent domain knowledge is the day's strongest signal.** Modern Web Guidance was the top story and pairs curated expertise with a measured browser-based evaluation, though its reported improvement is project-generated and compatibility questions remain. ([HN story](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments))
2. **Fast code generation does not remove software-design work.** One Ask HN author described growing complexity and review difficulty; replies emphasized specifications, architecture, tests, and independent review, without comparative proof of which process works best. ([HN discussion](https://news.ycombinator.com/item?id=50444380) (15 points, 16 comments))
3. **Compatibility is a key trust boundary for coding-agent guidance.** Commenters supported useful modern features but asked that target browsers and fallbacks remain explicit. ([HN discussion](https://news.ycombinator.com/item?id=50443812) (187 points, 56 comments))
4. **Business value remains less clear than productivity anecdotes.** Replies distinguished lower effort and developer satisfaction from faster launches, revenue, or profit, with no common metrics offered. ([HN discussion](https://news.ycombinator.com/item?id=50435819) (4 points, 11 comments))
5. **Formal-verification and memory-efficient training projects are early signals.** TheoremSmith and TTF share concrete methods and builder-reported results, but evidence of transfer, replication, or adoption is limited. ([TheoremSmith](https://github.com/abundant-ai/theoremsmith); [TTF](https://github.com/oguzeldereli/ttf-ternary); [TheoremSmith HN story](https://news.ycombinator.com/item?id=50444276) (7 points, 0 comments); [TTF HN story](https://news.ycombinator.com/item?id=50438889) (4 points, 0 comments))
