## 1. 大家在讨论什么

### 1.1 智能体从回答提示词转向持续承担工作 (🡕)

Perplexity 推出了 Teammates，称其智能体能够记住项目目标和文件，协调 Computer 会话或其他 Teammates，跟进不断变化的工作，并汇报进度或请求审批。发布介绍称，这些工作流适用于销售、营销、支持和运营等场景，并可集成 Slack、GitHub 和 Gmail。Perplexity 表示，每个 Teammate 都在独立环境中运行，用户可以检查其工作或调整方向；这些是公司的说法，并非独立的性能评估结果。([Perplexity 公告](https://www.perplexity.ai/en-GB/hub/blog/teammates-are-agents-for-complex-ongoing-work); [HN 帖子](https://news.ycombinator.com/item?id=50395866)（57 分，49 条评论）)

**讨论见解：** 多位评论者对这次发布反应强烈负面。[trnvll](https://news.ycombinator.com/user?id=trnvll)（得分 0）称，Perplexity 的用户体验和产品质量似乎有所下滑；[jwr](https://news.ycombinator.com/user?id=jwr)（得分 0）则描述了订阅期间系统从用户选定的更强模型切换到其他模型的经历。这些都是个人经历，不能代表整体客户评价。

**与前一日对比：** 11 月 5 日排名靠前的智能体帖子，聚焦于用于提示和批准工作的实体键盘，以及本地会话审计工具。11 月 6 日领跑的发布则主打能够跟进并推进持续开展的工作的智能体。这反映的是每日信息流的变化，并不能证明长期趋势。([Keypad 的 HN 帖子](https://news.ycombinator.com/item?id=50381302)（84 分，55 条评论）；[Stroq 的 HN 帖子](https://news.ycombinator.com/item?id=50380704)（48 分，10 条评论）)

### 1.2 智能体基础设施聚焦身份、隔离与空闲算力成本 (🡕)

Zalando 的 Agentic Identity Broker 是一个开源 OAuth2 中介，可为智能体访问 MCP 服务提供范围受限、可撤销的权限。作者称，它会加密委派令牌，并采用 RFC 8693 令牌交换，使智能体无需接收用户凭据；作者还报告称，v0.1 版本已部署在内部的数百个智能体上。该部署数据由作者提供。评论者询问，这款产品与单纯的 OAuth 委派有何不同，以及它如何处理传递式访问。([代码仓库](https://github.com/zalando-incubator/agentic-identity-broker); [HN 帖子](https://news.ycombinator.com/item?id=50393235)（18 分，3 条评论）；[tiffanyh](https://news.ycombinator.com/user?id=tiffanyh)（得分 0）；[yubblegum](https://news.ycombinator.com/user?id=yubblegum)（得分 0）)

Google 宣布向 CNCF 捐赠 Agent Substrate 和 gVisor，强调代理运行时既要隔离不可信代码，也要减少模型调用或人工审核期间闲置的计算资源。另一篇 Ask HN 帖子询问如何以较低成本让多智能体任务整夜运行。Botel 的开发者介绍了在智能体虚拟机不活跃时将其暂停的做法，同时指出，区分短期和长期任务仍然很困难。([Google Open Source 公告](https://opensource.googleblog.com/2026/11/sandboxing-untrusted-ai-agents-at-scale.html); [HN 帖子](https://news.ycombinator.com/item?id=50390509)（6 分，0 条评论）；[Ask HN 提问帖](https://news.ycombinator.com/item?id=50391647)（4 分，3 条评论）；[Botel](https://botel.dev); [Botel 的 HN 帖子](https://news.ycombinator.com/item?id=50393793)（3 分，3 条评论）)

### 1.3 AI 辅助工作让人重新思考计算与交互界面 (🡕)

另一篇 Ask HN 帖子以个人经历展现了同样的变化：作者称自己为电视遥控器、手机媒体计时器、家庭数码相框、用电监测和离线地图制作了小工具，并表示正在本地组织一门课程。一位评论者 [stevendeluth](https://news.ycombinator.com/user?id=stevendeluth)（得分 0）称，自己用 Raspberry Pi 上的定制程序取代了开票软件。这些只是个人案例，并非普及率估算。([关于被遗忘话题的 HN 帖子](https://news.ycombinator.com/item?id=50387483)（40 分，36 条评论）；[关于自制软件的 HN 帖子](https://news.ycombinator.com/item?id=50391446)（3 分，3 条评论）)

### 1.4 专用智能体强调证据和结构化成果 (🡒)

TinyFish 的 TinyResearch 文章介绍了一套研究流程：将问题拆解为子问题，按任务需求排列来源，实时读取网页，提取带有来源链接的论点，检查是否存在遗漏，再据此撰写内容。作者称，产品的评估维度包括事实准确性、可信度、可读性、全面性和遵循指令的能力；这些是开发者提出的设计目标和报告，并非独立评估结果。 ([TinyResearch 文章](https://www.tinyfish.ai/blog/inside-tinyresearch); [HN 帖子](https://news.ycombinator.com/item?id=50389479)（19 分，0 条评论）)

## 2. 人们感到困扰的问题

### 让持久运行的智能体既经济又可预测

** 严重程度：中；直接证据有限。** 一位 Ask HN 发帖者说，本地智能体到了夜里就会停止运行，并询问常驻或多智能体系统的订阅服务、API 和自托管成本。Botel 的开发者提供按实际运行时间计费的方案，但表示智能体运行环境提供的信息不足，无法可靠地区分短时任务和长时任务。尚待解决的不只是空闲时的计算成本，还有运行时如何判断任务何时可以安全暂停。（[Ask HN 提问帖](https://news.ycombinator.com/item?id=50391647)（4 分，3 条评论）；[Botel 的 HN 帖子](https://news.ycombinator.com/item?id=50393793)（3 分，3 条评论））

### 破坏性操作与不明确的执行边界

** 潜在严重程度：高；普遍程度：不明。** 一则链接到 HN 的 Reddit 帖子称，某个智能体删除了一台机器；这只是单个用户的说法，原因尚未得到独立证实。在 HN 讨论中，[marcduck](https://news.ycombinator.com/user?id=marcduck)（得分 0）询问 Docker 是否足以充当沙箱。另一个 Show HN 项目宣传一种零信任 POSIX 运行时，但 [spoaceman7777](https://news.ycombinator.com/user?id=spoaceman7777)（得分 0）质疑其代码仓库是否能支撑其所宣称的策略执行能力。这些证据表明，人们关注隔离和可验证的边界，但不足以据此判断任何产品的安全性。（[关联事件](https://old.reddit.com/r/google_antigravity/comments/1xpbc54/antigravity_ran_a_command_to_delete_my_entire/)；[HN 讨论帖](https://news.ycombinator.com/item?id=50395939)（5 分，9 条评论）；[AegisKernel 的 HN 帖子](https://news.ycombinator.com/item?id=50394991)（10 分，3 条评论））

### 智能体连接带来额外阻碍和令牌开销

** 严重程度：低至中；证据来自一次测试版发布。** GRID 的开发者表示，浏览器刷新后 MCP 重新连接可能失败，工具调用消耗的令牌也比预期多。他们还提到，内置本地模型难以遵循书面策略。这是对集成和模型局限的具体描述，并非对 MCP 或本地模型的普遍评估。（[GRID 的 HN 帖子](https://news.ycombinator.com/item?id=50392347)（4 分，3 条评论））

### 难以向用户解释委托访问

** 严重程度：低；普遍程度：仅有一场小规模讨论。** 在 Agentic Identity Broker 发布帖下，[tiffanyh](https://news.ycombinator.com/user?id=tiffanyh)（得分 0）询问该身份代理如何融入日常工作，以及它与现有 OAuth 委托有何不同；另一位评论者则询问传递授权的情形。这说明其使用场景和权限模型仍有待解释清楚，并非有人报告实现失败。（[HN 帖子](https://news.ycombinator.com/item?id=50393235)（18 分，3 条评论））

## 3. 人们希望出现什么

### 经济实惠、可常驻运行且能可靠暂停和恢复的智能体

Ask HN 发帖者希望让复杂任务整夜运行，并询问其他人如何控制推理成本。Botel 提供按使用量付费的虚拟机方案，并估算，按照其描述的使用方式，一个小型社区网站每月费用可能约为 $0.40；但其开发者也表示，如何识别任务生命周期仍未解决。实际需求是让任务持续执行，同时提供透明的计费方式和可靠的暂停、恢复功能。 **机会：竞争激烈**；已有相关服务，但工作负载检测和独立成本对比仍有待解决。（[Ask HN 提问帖](https://news.ycombinator.com/item?id=50391647)（4 分，3 条评论）；[Botel 的 HN 帖子](https://news.ycombinator.com/item?id=50393793)（3 分，3 条评论））

### 为智能体提供清晰、可撤销的授权

Agentic Identity Broker 的作者介绍了一种范围受限、可撤销的 OAuth 委托方式，以避免将用户令牌交给智能体。关于传递式访问和日常使用的问题表明，开发者还需要清楚了解智能体以何种身份行事、能够访问哪些内容，以及审批和撤销机制如何运作。**机会：竞争激烈**，因为已有实现方案，但讨论中仍有使用方式和授权边界有待说明。（[代码仓库](https://github.com/zalando-incubator/agentic-identity-broker)；[HN 帖子](https://news.ycombinator.com/item?id=50393235)（18 分，3 条评论））

### 让个人计算设备更易改造的工具

自己动手制作软件的作者介绍了如何借助 AI 修复硬件和软件上的小问题，并计划在当地教其他人。另一条讨论那些被忽视话题的长帖中，一位评论者呼吁重新思考人们熟悉的屏幕和键盘交互方式，而不只是加快现有界面中的工作。这些都是希望获得更多用户控制权的实际诉求，但目前的证据主要来自少数个人经历，还不足以说明需求普遍存在。**机会：正在浮现。**（[关于自制软件的 HN 帖子](https://news.ycombinator.com/item?id=50391446)（3 分，3 条评论）；[关于被遗忘话题的 HN 帖子](https://news.ycombinator.com/item?id=50387483)（40 分，36 条评论）；[codingdave](https://news.ycombinator.com/user?id=codingdave)（得分 0））

## 7. 机会所在

**[+++］ 具备生命周期感知能力且闲置成本可预测的智能体运行时** — Ask HN 帖子询问如何以较低成本让智能体整夜运行；Botel 的开发者指出，作业生命周期检测仍是一个尚未解决的集成问题；Google 的 Agent Substrate 公告则聚焦于智能体等待期间的隔离。若有产品能清晰呈现状态、暂停/恢复行为、隔离机制和计费方式，便能回应讨论帖和开发者帖中提出的问题。(［Ask HN](https://news.ycombinator.com/item?id=50391647)（4 分，3 条评论）；[Botel 的 HN 帖子](https://news.ycombinator.com/item?id=50393793)（3 分，3 条评论）；[Google Open Source](https://opensource.googleblog.com/2026/11/sandboxing-untrusted-ai-agents-at-scale.html)）

**[++］ 具备明确作用域且可强制执行的身份与操作边界** — 身份代理的发布展示了一种实现可撤销、限定权限凭证的方法；而相关的机器删除事件报告以及对 AegisKernel 的审视，则表明用户希望拥有清晰的控制手段和可验证的执行证据。该事件尚未得到证实，身份代理的用途也仍在厘清，因此需求信号确实存在，但目前尚未广泛显现，也未得到量化。(［Agentic Identity Broker 的 HN 帖子](https://news.ycombinator.com/item?id=50393235)（18 分，3 条评论）；[相关事件的 HN 帖子](https://news.ycombinator.com/item?id=50395939)（5 分，9 条评论）；[AegisKernel 的 HN 帖子](https://news.ycombinator.com/item?id=50394991)（10 分，3 条评论））

**[+)］ 以证据为先、面向特定领域的智能体** — TinyResearch 介绍了如何将论断与实时来源关联，并核查尚未解答的问题；LDraw Mecha 则展示了一条从结构化模型数据生成动画的垂直路径。两者都是开发者实践案例，并不能证明市场规模，但它们指出，在某些工作流中，明确呈现中间产物有助于检查智能体的输出。(［TinyResearch 的 HN 帖子](https://news.ycombinator.com/item?id=50389479)（19 分，0 条评论）；[LDraw Mecha 的 HN 帖子](https://news.ycombinator.com/item?id=50397325)（15 分，0 条评论））

## 8. 要点

1. **智能体产品正朝着持续接管任务的模式发展。** Perplexity 推出的 Teammates 成为当天讨论的焦点，持续监控与复核，以及多智能体协作，都受到关注。（[HN 帖子](https://news.ycombinator.com/item?id=50395866)（57 分，49 条评论））
2. **运行时生命周期管理和成本仍是实际设计中的问题。** 一位 Ask HN 用户询问，如何以较低成本让任务整夜运行；Botel 的开发者表示，判断任务何时可以暂停仍然很困难。（[Ask HN](https://news.ycombinator.com/item?id=50391647)（4 分，3 条评论）；[Botel 的 HN 帖子](https://news.ycombinator.com/item?id=50393793)（3 分，3 条评论））
3. **凭证委派和机器隔离是智能体管控的不同组成部分。**Agentic Identity Broker 侧重于按范围授予访问权限，而 Google 发布的 Agent Substrate 则聚焦于隔离执行；用户评论对适用场景和沙箱的可靠性提出了疑问。（[AIB 的 HN 帖子](https://news.ycombinator.com/item?id=50393235)（18 分，3 条评论）；[Google Open Source 公告](https://opensource.googleblog.com/2026/11/sandboxing-untrusted-ai-agents-at-scale.html)；[相关事件的 HN 帖子](https://news.ycombinator.com/item?id=50395939)（5 分，9 条评论））
4. **AI 辅助构建既出现在基础设施工作中，也出现在个人计算场景中。**LDraw Mecha 将智能体应用于一套结构化的、类似 CAD 的模型转动画工作流；一位 Ask HN 发帖者则介绍了如何开发家用实用工具并集成硬件。这些只是具体案例，不能据此估算其普及程度。（[LDraw Mecha 的 HN 帖子](https://news.ycombinator.com/item?id=50397325)（15 分，0 条评论）；[自制软件的 HN 帖子](https://news.ycombinator.com/item?id=50391446)（3 分，3 条评论））
